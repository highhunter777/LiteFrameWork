# 动手前:质量登记表查询

**为什么存在**:两份审计登记表登记了存量质量债(硬编码/重复/技术债/不统一路径/类设计,含 file:line 与修复状态)。改文件前不查 = 可能重复踩已登记的坑,或错失顺手修小债的机会。这是 `Docs/修改指南.md` §2.1"动手前"第 3 步。

## 步骤

1. 用要改的文件名(不必带路径)grep 两份登记表:
   - `Docs/代码质量审计-客户端.md`(Assets/Lite* 全域,约 450 源文件)
   - `Docs/代码质量审计-服务端.md`(`Assets/RoomServer`、`Server/`)
2. **命中已登记债**:同文件小债顺手修,记入当前批次;修完回写该条目到该文档"修复登记"表(状态 + 提交号,**不删除原条目**)。大债不动,至少本次改动不使其恶化。
3. **未命中**:正常动手,但新代码禁止产生 `Docs/修改指南.md` §1 红线的同型问题——每条红线都源自审计实锤反例,评审可见。
4. **改动过程中发现新问题**:按登记表格式追加登记(严重度 + file:line + 一句话),让债可见,而不是只口头提。
