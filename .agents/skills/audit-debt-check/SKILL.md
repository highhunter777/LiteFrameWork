# 动手前:质量登记表查询

**为什么存在**:审计台账按八类登记存量质量债(硬编码/重复实现/技术债/不统一路径/类设计/功能缺口/文档债/工具链,含 file:line 与修法)。改文件前不查 = 可能重复踩已登记的坑,或错失顺手修小债的机会。这是 `Docs/规范/02-代码与修改规范.md` §2.1"动手前"第 3 步。

## 步骤

1. 用要改的文件名(不必带路径)grep 登记目录:
   - `Docs/审计/客户端/登记/`(一类型一文件;Assets/Lite* 全域)
   - `Docs/审计/代码质量审计-服务端.md`(服务端,迁移中;完成后同形)
2. **命中已登记债**:同文件小债顺手修,记入当前批次;修完**从登记文件删去该行**,并在 `Docs/审计/客户端/归档/<类型>-01.md` 追加一行(问题 → 修法/批次;**单文件 ≤100 条**,满则开 `-02`)。大债不动,至少本次改动不使其恶化。
3. **未命中**:正常动手,但新代码禁止产生 `Docs/规范/02-代码与修改规范.md` §1 红线的同型问题——每条红线都源自审计实锤反例,评审可见。
4. **改动过程中发现新问题**:按八类落到 `Docs/审计/客户端/登记/<类型>.md`(严重度 + file:line + 一句话 + 修法),让债可见,而不是只口头提;**悬空设计路线直接删除、不进归档**。
