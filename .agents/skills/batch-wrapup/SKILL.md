# 代码批收尾(收尾必跑 + 文档回写)

**为什么存在**:`Docs/修改指南.md` §2.3/§2.4 把"收尾"定义为一等流程:验证基线、生成物同步、文档回写、审计登记四位一体;任何一步漏掉的代价都远超省下的时间(生成物漏跑 = 联机握手拒进房;登记不回写 = 债不可见、同型问题复发)。

## 1. 验证

| 情况 | 必跑 |
|---|---|
| 一切改动的基线 | Unity recompile 0 错误 + `pwsh scripts/gate/test.ps1 -Lane L1 -Profile PullRequest` |
| 动过共享源集 / .proto / 表 | 按 `build-hash-sync` skill 重生成,再跑 L1(内含 BuildHash 守卫与表守卫) |
| 目录搬动过 | 按 `directory-move-sync` skill 同步六面后跑 L1 |
| 出包前 | `python scripts/codegen/gen-build-hash.py --check` |
| 新增依赖 / 跨域接入 | `pwsh scripts/gate/l0-dep-scan.ps1`(PASS:个人绝对路径/浮动依赖/密钥模式) |

L2(EditMode/PlayMode)留夜间流水线,白天不跑。

## 2. [Diag] 清理检查

临时诊断必须带 `[Diag]` 前缀 + 摘除批次号;本批若产生过 [Diag] 哨位,收口时必须清零(热路径禁周期性 Warning)。对本批改动过的文件 grep `[Diag]` 确认。

## 3. 接线检查

- 注册进容器的服务必须有生产消费者;发现无消费者的功能面:接线或退役,二选一,不静默留着。
- "待接线"半成品必须挂施工进度批次号,注释只写"待"不算登记。

## 4. 文档回写(红线 12)

1. 设计变更 → 回写对应专项设计(设计文档只描述最新设计)。
2. 批次证据 → 记入 `Docs/施工进度/`(进度文档只保留最新进度)。
3. 修了质量登记表条目 → 回写该审计文档"修复登记"表(状态 + 提交号,**不删除条目**)。
4. 新发现的质量问题 → 按登记表格式追加(严重度 + file:line + 一句话),让债可见。
