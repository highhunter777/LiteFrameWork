# 文档新增与修改规范

**为什么存在**：文档体系分 5 类落点（设计/规范/说明/进度/审计）、2 条硬纪律（设计↔进度分离、索引零孤儿）、3 类易腐引用（相对链接 / 章节锚 / 跨文档"唯一权威"）。规则原文在 `Docs/规范/01-文档体系与写作.md`、`Docs/设计文档/README.md`、`Docs/施工进度/README.md` §2.4 与 AGENTS.md；本 skill 只做**动手顺序**与**自检清单**，冲突以原文为准。

## 1. 先定落点（写之前 30 秒）

| 你要写的是 | 去哪 | 判据 |
|---|---|---|
| 目标架构 / 契约 / 验收标准 | `Docs/设计文档/<域>/` | 裁决"应该怎样"；**不记完成状态** |
| 这批做了什么、证据是什么 | `Docs/施工进度/<线>线.md` **新增一章** | 记"实际怎样"；追加不新建文件 |
| 怎么跑、怎么验、环境怎么恢复、代码在哪 | `Docs/说明/` | 解释层，一章一文件、NN 编号 |
| 必须遵守的硬规则与流程 | `Docs/规范/` | 规范层，可就地被执行/门禁引用 |
| 环境复原、机器差异事实 | `Docs/说明/16-环境复原与机器差异.md` | 只答"怎么装回来" |
| 存量质量债登记 | `Docs/审计/代码质量审计-*.md` | 登记表格式（file:line + 状态） |
| 被取代 / 已吸收的旧稿 | `Docs/归档记录/<日期>/` + README | 不再参与裁决 |
| 全仓级入口 | `Docs/README.md`、根 `AGENTS.md` | 只放指针，不复制正文 |

> **`Docs/` 根目录只允许两份**：`README.md`（入口）、`待办总览.md`（进度权威）。规则入 `规范/`、解释入 `说明/`；其他 .md 不放根目录（D7 提醒）。

**判据一句话**：能在代码/测试里看到的"结果"→ 进度；在讨论"应该是什么"→ 设计。**两者同时需要 → 写两份并互相链接，绝不混写。**

## 2. 命名与元数据

- 禁用后缀：`最终版`/`最新版`/`新版`/`最终`/`具体方案`/`精简版`/`V2最新版` —— 版本、状态、日期写进**元数据头**，不写进文件名（D5 会拦）。
- **设计文档必须以 §3 认可的类型结尾**：`总设计` / `专项设计` / `层级设计` / `分层设计` / `策略选型` / `备选方案` / `规范` / `参考` / `演进路线图`。**裸 `设计` 后缀不合规**（无法判定归属，D5 拦）。
  - 归类自问「它裁决什么」：只需一句话限定的形态 → 层级/分层设计；要跑起来才算完整 → 专项设计；只在查表时被引用 → 参考。
- 设计文档必须带元数据头：版本/日期、**定位**（本文回答什么）、**不做的事**（边界，避免越权裁决）、**冲突裁决**、**关联**。
- 进度章必须可验证：代码路径、测试命令、产物位置。**不得用文档描述代替实现证据。**
- 进度卷用 `<线>线.md`；`Docs/` 下文件一律**中文名**，不中英混排。

## 3. 两条硬纪律

**纪律一：设计文档不记施工状态**
- 禁止在 `Docs/设计文档/**` 写「已实施 / 已交付 / 批A 完成 / 2026-10-15」这类流水；写**现行形态**即可，状态由进度卷承担。
- 现状叙述只能写"现在是什么"，不能写"什么时候变成这样"。日期只允许出现在"版本/落定"元数据里。
- 后批修正前批：在**后批章内**写「修正前批某结论」，**不回改前章**——前章是当时事实。

**纪律二：索引零孤儿**
- 新文档必须在**同一批**补进对应 README 索引（设计 → `设计文档/README.md`；进度 → `施工进度/README.md`）。
- 改名/移动/合并：同一批内改完全部引用（含设计文档、进度卷、`Docs/README.md`、`AGENTS.md`、审计表），否则 D4 报链接失效。
- 跨文档只引用唯一权威，不复制第二份（复制即未来分叉）。

## 4. 进度卷的追加方式

进度已按**一条线一卷**组织（22 卷，卷内一章＝原一次批次记录）：

1. 选线 → 打开 `<线>线.md`。
2. 卷首「章节索引」表补一行（章号顺延、标题、`原文件名` 留空或写 `—`）。
3. 文末按既有格式追加 `## 第N章 <标题>` + `<a id="chN-<slug>"></a>` + 内容。
4. **不新建单文件**；跨线的新主题才新开卷（并在 `施工进度/README.md` 卷索引加一行）。

## 5. 拆分 / 合并 / 归档

- **合并**：保留一份权威，另一份内容整段并入（标题降级），旧文件删除，全部引用改指新区位（章节锚）。
- **拆分**：拆出的部分若属于别的主题，**优先并入那份文档**，而不是新建第三份。
- **归档**：移入 `Docs/归档记录/<日期>/`，并在该目录 README 写「文件 → 被谁取代 → 现行权威」表；同时从现役索引移除、在 `Docs/README.md` 归档节登记。
- 任何搬动后，**相对链接深度会变**——按下节自检。

## 6. 自检（改完必跑）

```powershell
python scripts/gate/test.py --suite Doc      # 含 D1~D6：内嵌状态/索引孤儿/链接与锚/命名
# 或直跑
python scripts/gate/doc-lint.py
python scripts/gate/doc-lint.py --no-links   # 只看结构不查链接（大仓快跑）
```

| 门禁 | 拦什么 |
|---|---|
| D1/D6 | 设计文档表格行 / 正文内嵌批次状态（提醒级，人工复核） |
| D2 | 审计表裸「，待提交）」 |
| **D3** | 设计文档或进度卷**未入索引**（孤儿） |
| **D4** | 相对链接指向的 .md 不存在；`#锚` 在目标文件里找不到 |
| **D5** | 文件名含不可治理后缀；或设计文档不以 §3 认可类型结尾（裸「设计」） |
| **D7** | `Docs/` 根目录出现白名单外的文档（应入子目录） |

> D4 的锚支持两种：显式 `<a id="x"></a>` 与标题 slug。改标题 = 让所有指向旧 slug 的链接失效，**改标题时同批搜一遍全仓引用**。

## 7. 与其它 skill 的分工

- `batch-wrapup` §4：**代码批收尾时**的文档回写（设计→专项、证据→进度、债→登记表）。本 skill 管"怎么写"，它管"什么时候必须写"。
- `directory-move-sync`：`Assets/`、`Server/` 下**代码与资源**目录搬动。本 skill 只管 `Docs/` 下的搬动。
