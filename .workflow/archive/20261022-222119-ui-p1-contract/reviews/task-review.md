- 依赖顺序：T1 → T2/T3 → T4 → T5 → T6；T2 与 T3 可并行，符合方案。
- 可测试性：每个任务都有定向 Unity 用例或项目门禁作为验证命令。
- 范围控制：WidgetSpec、UiPageManifest、契约校验规则、CI 接线均未拆进本批任务。
- 风险处理：T3 明确要求既有 hash 用例回归；T2 只对含 `LTextKeyRef` 的页面生效，降低保留基座风险。

## 发现的问题与处理

1. T5 的位置在任务依赖上先于 T6，但测试代码需要在 T2/T3/T4 之前先写。处理：任务描述已写明“先行测试与负例覆盖”，执行时按 staged-delivery 的 tests-first 阶段先落测试骨架并取得红证，再实现 T2/T3/T4；任务依赖仅表示最终完成顺序。
2. 本批不包含 `UiPageManifest`，因此契约 `owner/designRef` 暂不生成。处理：方案已登记；T4 的 `UiPageMetadata` 保留可选字段作为 P1-3 接缝。
3. `cacheStrategy` 当前无表列。处理：T1 明确默认 `Lru` 并写入设计文档，避免生成器私设第二口径。
