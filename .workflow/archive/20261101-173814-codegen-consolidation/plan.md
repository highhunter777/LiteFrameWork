## 背景与目标

- 现状（2026-11-01 实测）：
  1. **统一入口已经存在**：`scripts/codegen/toolbox.py` 有 7 个子命令（`build-hash`/`proto`/`luban`/`sync-code`/`ui-page`/`ui-api`/`refresh-hash`）。
  2. 但文件头明写 "Direct per-script invocation stays valid"；门禁、配置、工具清单、编排、hook、单测仍直调单脚本（清单见「现状与约束」§3）⇒ 工具链没有单一入口的事实约束。
  3. `.workflow/config.json` 的 commands 没有任何 codegen 新鲜度检查 ⇒ "改了字段没重生成"不会被门禁发现。
  4. **腐烂 8 处**（比母本多 4 处，见「现状与约束」§2）：6 处路径腐烂（`gen_proto` 的 `proto_dir`、`gen_sync_code` 的 `OUT_FILE`、`SimTrigTableGenerator` 的 `OutputPath`、`refresh-hash`/`local-chain` 的客户端常量路径、hook 的源集旧前缀）+ 2 处注释腐烂（`gen-build-hash` 的 shared 模板、`gen_luban` 头注释）。`BakeTargets` 历史四条旧输出已由 B 改为 `.bin`/地图 JSON，本交付只验证其**现状**路径。
  5. 既有生成物署名契约已经存在：设计文档 §2 + `scripts/tests/test_generated_artifacts.py`（`// <auto-generated: <生成器路径> ...>`，以 `>` 闭合，≤3 行，无时间戳）。母本要求 `toolbox/<tool>` + 输入指纹，**本方案升级这份契约**（同步改设计文档与测试），不另立第二套。
- 目标（可观察）：
  - `python scripts/codegen/toolbox.py all` 一条命令按依赖序跑完全部生成器；`all --check` 是门禁。
  - `toolbox.py doctor` 静态体检所有生成器声明的输入/输出路径，腐烂路径当场红；并打印"可执行调用点清单"。
  - 门禁/配置/工具清单/编排/hook/单测不再直调单脚本；人工直调保留但打印 `[deprecated]`；`Luban/gen.bat` 保留为兼容别名。
  - toolbox 自产文本生成物统一署名（生成器 token + 输入指纹 + 重跑命令），重复生成逐字节一致。

## 需求澄清与假设

- 已确认答复：把 10 个生成器统一到单一 codegen 入口（用户原话）。
- 采用假设（与母本字面冲突处按此裁决，验收时请用户确认）：
  1. **头/指纹覆盖范围**：只覆盖 toolbox 自产文本产物——`BuildHash.g.cs`×2、`EntitySlot.Sync.g.cs`、`UiPageCatalog.g.cs`、5 个 UI API `.g.cs`、`LuaKeys.g.cs`（共 10 个）。`Battle.cs` 是 protoc 产物、`.bytes` 是二进制、Luban 模板 `.cs`/`.lua` 归第三方模板，按母本「不动 Battle.cs/.bytes」与设计文档既有豁免不写统一头；`Battle.cs` 的新鲜度用 **sidecar 戳**（`Generated/Battle.cs.input`，不在 BuildHash 闭包）覆盖。`SimTrigTables.cs` 也不改写头（它在 `LiteSim/Scripts` 的 BuildHash 闭包内，改注释=两端换号；`trig` 验收见假设 3 的行尾判定）。
  2. **proto 的 `--check`**：`protoc` 不在仓库内（本机 NuGet `Google.Protobuf.Tools/3.36.1`，`libprotoc 36.1` 重生成 `Battle.cs` 已实测逐字节一致）。`proto --check` 有 `--protoc` 时做「暂存生成 + 归一文本比对」，没有时读 sidecar 戳比对 `.proto` 的 sha256，判「输入变了但 Battle.cs 没重生成」。**行尾**：`battle.proto` 工作区是 CRLF、blob 是 LF，sidecar 摘要与重生成比对都必须先做行尾归一（复用 `_codegen.input_digest`/`normalize_eol`），否则 clean clone 跨机器假红。**sidecar 缺失 ⇒ 红**（提示先跑一次 `toolbox proto --protoc`）；本批提交 sidecar；它在 Assets 内，Unity 会生成 `.meta`，`.meta` 走 unity-pipeline 并一并提交（硬前置，不留“未生成则记录”的退路），保证 C4 首跑即绿。门禁走无 protoc 的戳模式，避免把机器路径写进仓库配置。
  3. **trig 路线**：选母本路线②「toolbox 转发 Unity 实现并校验产物一致」——保持设计文档 §5「生成器引运行时常量、同程序集」的单源前提；不把 Unity 生成器搬进 Python，`trig` 不进 `all`/门禁。已探针验证 `unity command eval 'return LiteSim.Editor.SimTrigTableGenerator.BuildContent().Length;'` 成功（63819）；`toolbox trig` 用同一 eval 通道：生成走 `LiteGame.Editor` 的 public CLI 入口 → `SimTrigToolActions.Run`（经 `ToolWriteScope`），`--check` 调新增的 `IsUpToDate()`（只读）；**不直接调 `SimTrigTableGenerator.Generate()` 写盘**。**行尾**：工作区 `SimTrigTables.cs` 是 CRLF（`core.autocrlf=true`），而 `BuildContent()` 产 LF；`IsUpToDate()` 比较必须做行尾归一（`\r\n`/`\r`→`\n`），写入保持 LF，避免"CRLF 工作区一跑就判 stale/重写"。母本 AC68 的「逐字节一致」按 **git blob/归一文本** 解释（工作区行尾随 autocrlf 变化，不能作判据）；C5 用 `git diff --ignore-cr-at-eol --exit-code` + 归一文本判定。顺带把 `SimTrigTableGenerator.TableSize` 改为引用 `SimTrig.TableSize`（消除同值双份），产物零 diff；不在闭包内的 `SimTrigTableGenerator` 注释同步改，`SimTrig.cs`/`SimTrigTables.cs` 的注释不改（在闭包内）。
  4. **直调守卫**：用 `scripts/tests/fixtures/codegen-call-sites.json` 对每处 `scripts/codegen/<script>.py` 字面量做分类（键 `(file, line, literal)`，同文件同字面量多处独立；`invocation`/`import`/`analysis`/`signature`/`doc`/`text`/`contract-test`/`compat`/`toolbox`）；路径分隔符归一（`\\`→`/`）并重建 `Path`/`join` 拼接后匹配；`invocation` 必须走 toolbox，未分类即红。注释不入 AST、不扫描；用法/帮助/模板字符串按**每条字面量**分类为 `doc`/`text`（不做文件级），同文件仍有 invocation 可独立分类、不会被 `doc` 豁免。显式例外：`scripts/tests/test_script_contracts_sb.py`（`contract-test`，只验 `--help`/`--bogus`）、`Luban/gen.bat`（`compat`，保持原样、会打印 deprecated）。守卫自身与 fixture 文件级豁免。`scripts/codegen/*` 内部互调改为经 toolbox（`refresh-hash` 的 build-hash 步）。
  5. **统一入口复用既有 `toolbox.py`**，不新建 CLI；既有 7 子命令保留名字，新增 `all`/`doctor`/`trig`。
  6. **路径单源**：`gen-build-hash.py` 暴露 `SHARED_OUT_REL` + `shared_out_file(root)` 函数；`refresh-hash`/`local-chain` 通过共享 loader 调函数（不再硬编码），`test_refresh_hash.py` 的 mock root 因此继续有效；`gen_proto` 用 `PROTO_REL` 推导 `proto_dir`；单测用生成器常量而不是手抄路径。
  7. **门禁载体**：`.workflow/config.json` 没有"PullRequest 档"这种分档字段；本方案把 `codegen-check` 加入其 `commands`（`wf verify` 会执行），并在 `Docs/说明/10-测试与门禁.md` 登记为出包/PR 前命令。既有的 `sync-and-sim-check-shared` 改走 toolbox，保留（与 codegen-check 的 build-hash 步有重复，成本可接受）。`all --check` 的 build-hash 步检查 **shared + meta 两个常量**；Meta stale 也会让门禁红（Meta 是仓库产物，有意覆盖；出包门禁仍只用 `--check-shared`）。
  8. **hook 源集前缀**：`shared-source-reminder.py` 的旧前缀（`assets/litesim/core/...` 等）本批修正；新前缀必须覆盖 `SHARED_TARGETS` 全部 10 个目录——`assets/litesim/scripts/`、`assets/litesim/systems/`、`assets/litenet/core/proto/`、`assets/litenet/core/protocol/`、`assets/litenet/core/transport/security/`、`assets/litesync/shared/`、`assets/litesync/snapshot/`、`assets/litesync/input/`、`assets/litesync/events/`、`assets/gamedata/generated/`。用测试把 hook 与 `gen-build-hash.SHARED_TARGETS` 联锁（每个源集路径必须触发提醒），不再用旧路径夹具把腐烂钉绿。
- 假设影响：若要求 Unity 烘焙器（5 个）也纳入 `all`（自动化烘焙），需要 Unity 批处理模式，属另一批；若拒绝 sidecar 戳，proto 门禁只能退化为「有 protoc 才检查」。

- 设计文档 §2：统一署名 = `// <auto-generated: <生成器路径> —— DO NOT EDIT。源：<单源>；重跑 <命令>。>`，≤3 行，**以 `>` 闭合**；§5 明确 SimTrig 留在 Unity 编辑器（引运行时常量）。
- `test_generated_artifacts.py`：断言生成物签名以 `// <auto-generated: ` 开头、含生成器路径 / `DO NOT EDIT` / `源：`、**以 `>` 收口**、≤3 行；当前覆盖 BuildHash×2、EntitySlot.Sync、LuaKeys。
- 母本 AC71 要求 `toolbox/<tool>` + 输入指纹；与本合同不同 ⇒ 本方案同步升级设计文档与测试（不是并存两套），范围按假设 1 收窄；新头的第 3 行保留 `>` 闭合符。

## 候选方案与取舍

| 方案 | 核心思路 | 优点 | 代价/风险 | 结论 |
|---|---|---|---|---|
| 复用并强制 | 在既有 `toolbox.py` 上补 `all`/`doctor`/`trig`，门禁改道 | 成本最低、不破坏既有调用 | 需同步门禁/文档/测试 | **采用** |
| 新建 `gen.py` 入口 | 重写统一 CLI，废弃 toolbox | 命名更"正统" | 需迁移全部文档与调用点，收益为零 | 否决 |
| 只修路径不统一 | 修腐烂即止 | 最快 | 门禁仍不检查产物新鲜度 | 否决 |

子决策：

| 子问题 | 取舍 | 理由 |
|---|---|---|
| 头/指纹覆盖 | 只覆盖 10 个 toolbox 自产文本产物；`Battle.cs` 用 sidecar 戳；`SimTrigTables.cs` 不动 | 母本「不动 Battle.cs」与「所有生成物」冲突；`SimTrigTables.cs` 在 BuildHash 闭包内，改注释会换号 |
| proto `--check` | 有 protoc 走重生成比对；无 protoc 走 input 戳；sidecar 缺失判红 | protoc 不在仓库；门禁不能依赖本机路径；首跑先提交 sidecar |
| trig | 转发 Unity 实现（路线②），不进 `all` | 保持「运行时同程序集常量」单源；已用 eval 探针验证可行；避免双实现漂移 |
| 直调守卫 | 收齐所有 `scripts/codegen/<script>.py` 字面量，逐条按 `codegen-call-sites.json` 分类；`invocation` 必须走 toolbox | 只按 `subprocess`/`run_gate` 函数名猜会漏 `_run` 类包装；分类清单可复核 |
| refresh-hash/local-chain 路径 | 改为 `gen-build-hash.shared_out_file(root)` 函数 | 消除第二份路径；兼容 `test_refresh_hash.py` 的 mock root |

## 设计要点

- `all` 严格序：`luban → ui-page → ui-api → sync-code → proto → build-hash`；任一步失败即中止，退出码归一为非零（1；用法错 2，`_common.normalize_exit` 既有约定）。生成模式要求 `--protoc`（缺失在开跑前 fail-fast，避免半写）；`--check` 不需要。
- `all --check`：逐 tool 传 `--check`；不写仓库；任一处过期即非零。
  - `luban --check`：生成到临时 staging（不在 Assets），先复用 `reorganize_bin_stage` 把 `*.bytes` 移入 Domain 子目录，再按 `publish` 的同一归一规则比对（文本按目标 CRLF/LF 归一，`.bytes` 逐字节），并判定 `prune_stale` 会删除的多余产物；不 publish、不 prune。
  - `proto --check`：有 protoc → 临时目录重生成 + **归一文本比对**（不做工作区逐字节），并校验 sidecar；无 protoc → 先检查 `Battle.cs` 存在，再校验 sidecar 与 `.proto` 摘要；缺失/不匹配 → 红。
  - `ui-api --check` 既有语义包含 MD 生成区块；`all --check` 因此覆盖该区块（有意耦合，文档注明：改生成区块而不重生成会红）。
  - `sync-code`/`ui-page`/`build-hash` 内存复算比对。
- `doctor`：每个 Python 生成器暴露 `path_report()`（用自己的 `*_REL`/`OUT_FILE`/`DEFAULT_*` 常量，不维护第二份清单）；`refresh-hash`/`local-chain` 作为只读路径消费者也注册 `path_report()`。`doctor` 逐个 `exists` 输入与输出父目录，并按 **git 跟踪状态分层**：tracked 输入缺失＝红；未入库第三方/大资源输入缺失＝提示（符合资源规范，clean clone 不红）；输出父目录缺失＝红。Unity 工具（`SimTrigTableGenerator.OutputPath`、`BakeTargets.cs` 的路径型字符串常量，含 `MapTarget` 内联 scene/output 字符串）用 C# 常量/字符串解析校验。`Battle.cs.input` 缺失只作提示（由 `proto --check` 判红）。`doctor` 同时打印"可执行调用点清单"（来自 `codegen-call-sites.json` 分类）供人工复核。
- `trig`：`toolbox.py trig [--check]` 经 `unity command eval`（JSON）调用：
  - 生成：`LiteGame.Toolchain.SimTrigCli.Run(dryRun:false); return "ok";`（public CLI 入口，内部调 `SimTrigToolActions.Run`，经 `ToolWriteScope`）
  - 校验：`return LiteSim.Editor.SimTrigTableGenerator.IsUpToDate();`（只读）或 `SimTrigCli.Run(dryRun:true)`（同一动作 dry-run）
  - `IsUpToDate()` 的比较做行尾归一（`\r\n`/`\r`→`\n`）；C5 用 `git diff --ignore-cr-at-eol --exit-code` + 归一文本判定，避免 CRLF 工作区假 stale。
  - 解析 eval 的 `success/result` 映射退出码；Pipeline 不在运行/编译失败给出明确错误；不进 `all`/门禁。
- 生成物头统一格式（≤3 行，不写时间戳，末行以 `>` 闭合）：
  ```
  // <auto-generated: toolbox/<tool> — DO NOT EDIT
  // input: <相对路径|N sources> sha256:<前 8 位>
  // regen: python scripts/codegen/toolbox.py <tool>[ args]>
  ```
  指纹 = 该工具声明的输入集按相对路径排序、行尾归一化后的 SHA-256 前 8 位（`_codegen` 新增 `normalize_eol()`/`input_digest()`；build-hash 复用其源集摘要，写 `input: shared source set sha256:<8>` / `meta source set`）。`sync-code` 的指纹不是 8 个整源文件，而是解析后的 `[StateLayer]` 字段模型（struct/field/type/layer/flatten/order 的规范化序列化）——非 `[StateLayer]` 编辑不改头，避免 `all --check` 假 stale；生成物比对按行尾归一后的文本（CRLF 契约）。`LuaKeys.g.cs` 的 token 归 `toolbox/luban`：`Luban/gen_lua_keys.py` 从自己的 `collect()`（注册表 xlsx 判定）计算指纹并写头——这是唯一扫描面，`gen_luban` 不重复扫描、不传指纹；非注册表 xlsx 变化不触发 LuaKeys 头变更。`ui-page` 输入为 table+manifest+contracts（含文件数）。设计文档 §2 与 `test_generated_artifacts.py` 同步升级。
- `trig` 的写盘契约：`toolbox trig` 复用 `SimTrigToolActions.Run`（走 `ToolWriteScope`，路径在 `toolchain.json` 的 outputs 内）；若 eval 访问 internal 受限，在 LiteGame.Editor 加一个 public CLI 入口，仍调同一 `Run`；不在生成器里绕过 `ToolWriteScope` 直写。仅当无法复用且在设计中登记豁免时才允许直写。
- `sync-code --check`：生成物是 CRLF，目标在不同 clone 可能是 LF/CRLF；比对按行尾归一，写入保持 CRLF（既有契约）。
- `proto` sidecar：`Assets/LiteNet/Core/Proto/Generated/Battle.cs.input`，内容 `battle.proto sha256:<8>`（`_codegen.input_digest` 行尾归一后计算；全量重生成比对也做归一文本比对）；`gen_proto` 成功后写，`--check` 无 protoc 时读（先查 `Battle.cs` 存在）；不进 BuildHash 闭包（`collect` 只收 `.cs`）；本批生成并提交。Unity 会为 Assets 内新文件生成 `.meta`，`.meta` 走 unity-pipeline 创建并一并提交（硬前置）。
- 门禁：`.workflow/config.json` 的 `commands` 增
  `{ "name": "codegen-check", "cmd": ["python","scripts/codegen/toolbox.py","all","--check"], "timeout": 900 }`；既有的 `sync-and-sim-check-shared` 改走 toolbox（保留，重复成本可接受）。`.workflow/config.json` 由主代理修改，施工子代理不得动。**改 `scripts/gate/toolchain.json` 的 command 后必须跑 `python scripts/toolchain.py docs` 再生 `Docs/说明/工具索引.md`**，否则 `toolchain-docs-check`/`test_toolchain` 必红。
- 直调策略：`toolbox.py` 头注释与无参索引文案由 "Direct per-script invocation stays valid" 改为 "门禁/CI/脚本内部一律经 toolbox；人工直调保留并打印 `[deprecated]`"；`toolbox.py` **不设模块级 env**（避免测试进程 import 后泄漏），只在转发子进程时显式传 `env={**os.environ,'CODEGEN_VIA_TOOLBOX':'1'}`；`_codegen.run_tool` 在未设该变量时打印 deprecated，并对 `TOOL=='toolbox'` 豁免；`gen-build-hash`/`ui-page`/`ui-api` 也转 `run_tool`，保证 7 个 toolbox 子命令生成器直调都有提示（`Luban/gen_lua_keys.py` 不是 toolbox 子命令，由 `gen_luban` 调用，不在此列）；`gen.bat` 保持原样，因此会打印，符合兼容别名定位；`ui-page`/`ui-api` 收口到 `_codegen` 输出/失败契约（`TOOL` 名改为 `ui-page`/`ui-api`，避免 `[codegen/codegen/...]` 双前缀）。
- 守卫（新，`scripts/tests/test_toolbox.py`）：用 AST/文本收齐 `.workflow/config.json`、`scripts/gate/toolchain.json`、`scripts/**/*.py`、`scripts/**/*.bat`、`Luban/*.bat` 中所有 `codegen/<script>.py` / `scripts/codegen/<script>.py` 字面量；路径分隔符归一（`\`→`/`）并用 AST 重建 `Path`/`join` 拼接（覆盖 `build-plan.py`/`test_refresh_hash.py` 的分段写法）。逐条要求 `scripts/tests/fixtures/codegen-call-sites.json` 分类（`invocation`/`import`/`analysis`/`signature`/`doc`/`text`/`contract-test`/`compat`/`toolbox`）；未分类或 `invocation` 未走 toolbox 即红；注释不入 AST，用法/帮助/模板字符串按**每条字面量**分类为 `doc`/`text`，不做文件级豁免（同文件 invocation 可独立分类）。这样 `_run`/`run_gate`/拼接/反斜杠都能覆盖，不按函数名猜。例外：`test_script_contracts_sb.py`=`contract-test`、`Luban/gen.bat`=`compat`；守卫自身与 fixture 文件级豁免；`doctor` 打印分类清单。另加 deprecated 用例（7 个 toolbox 子命令生成器直调有提示、经 toolbox 无提示）。
- 路径单源：`gen-build-hash.py` 增 `SHARED_OUT_REL` + `shared_out_file(root)`；`refresh-hash`/`local-chain` 通过共享 loader（`_codegen.load_module('gen-build-hash')`，新增）调函数；`gen_proto` 由 `PROTO_REL` 推导目录；`test_generated_artifacts.py` 用生成器常量；`LuaKeys` 指纹只由 `gen_lua_keys.collect()` 的注册表集计算（见上）。
- hook：`shared-source-reminder.py` 的源集前缀改为当前路径——`assets/litesim/scripts/`、`assets/litesim/systems/`、`assets/litenet/core/proto/`、`assets/litenet/core/protocol/`、`assets/litenet/core/transport/security/`、`assets/litesync/shared/`、`assets/litesync/snapshot/`、`assets/litesync/input/`、`assets/litesync/events/`、`assets/gamedata/generated/`；`test_hook_reminder.py` 用当前路径，断言改为 `toolbox.py build-hash`，并对 `gen-build-hash.SHARED_TARGETS` 的每个目录构造事件断言必触发。

## 通用性与扩展性

- 根因：生成器各自为政 + 无"产物新鲜度"门禁 ⇒ 目录重构后路径腐烂无人发现（8 处已实证），"改了字段没重生成"也不红。
- 扩展点：新增生成器只需在 `toolbox.TOOLS` 加一行 + 在 `all` 序里插入位置 + 实现 `--check` + 暴露 `path_report()`；`doctor`/守卫/门禁自动覆盖。
- 判据固化：**一个入口（toolbox）、一条序（all）、一套头（auto-generated + 输入指纹 + regen）、一个门禁（codegen-check）、一张守卫（可执行调用点直调）**。
- 防复发：路径从生成器常量/共享函数读取，禁止第二份手抄；单测断言"声明路径 = 实际路径"；hook 与源集联锁。

## 风险与回滚

- 风险：
  1. `all`（生成模式）会重写 `GameData/Generated`/`Config` 等（Luban）→ 若并行线改表，归属混淆；本交付要求**串行窗口**内执行，`--check` 只写临时 staging。
  2. `luban --check` 需要 Luban.exe/Excel 解析，耗时与依赖高于其他步；900s 超时内应完成，超时则拆到独立门禁命令并记录。
  3. `proto --check` 戳模式只证明"输入变了/没变"，不证明 protoc 版本匹配；文档注明"有 protoc 时以重生成比对为准"。`battle.proto` 工作区 CRLF/blob LF，摘要与重生成比对必须行尾归一，否则跨机器假红。
  4. `trig` 依赖运行中的 Unity Editor，不进 `all`/门禁；编辑器不在时只保证明确失败，不保证 CI 可跑；eval 通道已探针但 Unity 版本升级后需复验。`SimTrigTables.cs` 工作区是 CRLF（`core.autocrlf=true`）而 `BuildContent()` 是 LF：必须做行尾归一，否则 `IsUpToDate` 恒 false、`Generate` 重写行尾；C5 用 `git diff --ignore-cr-at-eol` 判定。
  5. 头契约升级会一次性改动 10 个生成物 + 设计文档 + 测试；需确认无 BuildHash 常量变化（头不在闭包）与无运行期语义变化。`LuaKeys` 指纹必须只跟注册表 xlsx 集（`gen_lua_keys.collect()`），否则任意表改动都会让 `luban --check` 假 stale。
  6. 守卫分类清单需随调用点变化维护；未分类即红；必须覆盖 `_run`/`run_gate`/`Path` 拼接/反斜杠，否则“新增直调即红”不成立。`doctor` 打印清单，施工时用真实命中校准。
  7. 修改 `.workflow/config.json` 会被后续 `wf verify` 执行；若 `codegen-check` 自身不稳定，会阻塞本运行的验证阶段——先让 doctor/all --check 在本地绿，再接门禁。
  8. `ui-api --check` 含 MD 区块：文档编辑可能触发 codegen 门禁；这是既有生成物的有意覆盖，文档注明；如需分离另立任务。
  9. `SimTrigTables.cs` 在 BuildHash 闭包内：本批不改其头/注释，`trig` 产物必须一致（按 git blob/归一文本）；若误改会强制两端换号。
  10. `doctor` 的 BakeTargets 输入含未入库第三方资源（prefab/controller）：必须按 git 跟踪状态分层，clean clone 不能红。
  11. sidecar 在 Assets 内会多一个 `.meta`（走 unity-pipeline）；漏提交会让 C4 的 `git status` 带 `??`；`.meta` 生成是硬前置，无退路。
  12. 改 `scripts/gate/toolchain.json` 的 command 后必须跑 `python scripts/toolchain.py docs` 再生 `Docs/说明/工具索引.md`；否则 `toolchain-docs-check`/`test_toolchain` 必红，C12/C13 无法通过。
  13. 文档/技能/`.cs` 提示仍有直调：本批以 **`Docs/**/*.md`（排除 `Docs/归档记录/**`）+ `AGENTS.md` + `.agents/skills/**/*.md` + `Assets/**/*.cs` 全量 grep 0 命中**为验收（说明 02/04/05/06/07/08/09/10/11/12/14/15/17、规范 02/03、设计文档命令表、skills、Baking/GM、`SimTrigToolActions.cs` 都在扫描面内）；`_combatgeom_row.py` 是 helper，不算生成器直调。
  14. `toolbox trig` 若直接调 `Generate()` 会绕过 `ToolWriteScope`；必须复用 `SimTrigToolActions.Run`（或 public CLI 入口），否则违反工具写盘契约。
  15. `protoc` 不在仓库，验收依赖本机 NuGet 路径；进度卷记录该路径与版本（`libprotoc 36.1`）。
- 监控：每次 `all --check` 后 `git status` 必须干净；`toolchain-tests` 覆盖 toolbox 行为；`codegen-check` 持续把关；`doctor` 打印调用点清单。
- 回滚：修改集中在 `scripts/codegen/**`、`scripts/tests/**`、`scripts/hooks/shared-source-reminder.py`、`scripts/local/local-chain.py`、`scripts/build/build-player.py`、`scripts/gate/sync-and-sim-e2e.py`、`scripts/gate/toolchain.json`、`Luban/gen_lua_keys.py`、`Assets/LiteSim/Editor/SimTrigTableGenerator.cs`、`Assets/LiteGame/Editor/Toolchain/Actions/SimTrigCli.cs`（新 public 入口）、`Assets/LiteNet/Core/Proto/Generated/Battle.cs.input`（含 `.meta`）、`.workflow/config.json` 与文档；生成物头变化可随同一批回滚；`gen.bat` 未改，无连带风险。
