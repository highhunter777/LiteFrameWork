## 3. 验证结果（2026-10-12 实测）

### 3.1 编译

`Unity.exe -batchmode -nographics -quit`：**`error CS` 0**。5 个 `Unity.Pipeline*` 程序集全部产出。

> **踩坑留档**：首轮自制的补丁 1 脚本用 `- .*\n` 抓 `defineConstraints`，要求列表项的 `-` 在第 0 列；而 Unity 自己写的 meta 里列表项**缩进两格**。正则落空走了兜底分支，产出 `defineConstraints:` 后跟一行裸 `  []`，Unity 解析器报 `Parser Failure at line 10`，**5 个 Roslyn DLL 根本没加载**——正是该补丁要修的问题本身。
> 教训：**"编译 0 错误"不等于"资源被正确加载"**，插件 meta 的解析失败不进 `error CS`。已修，见 `scripts/pipeline/patch_p1_plugin_metas.py`。

> **踩坑留档（同型第二例，2026-10-12 发现并修复）**：本工程自身也有 9 个**非 Unity 生成**（脚本/手写）的 `.cs.meta`，末行写成 `  assetBundleVariant:`——Unity 的写法是冒号后留一个空格、且文件以换行结尾。这类文件在**资产重读时**（新开编辑器、或 git 操作改动到该文件）报 `Unable to parse file … [Parser Failure at line 11: Expect ':' between key and value within mapping]`，同样**不进 `error CS`**，只在 Console 冒一条 error，破坏"Unity recompile 0 错误"基线。
> 判定实测：末行**既无值空格、文件又无结尾换行**才报错（`Packages/` 下第三方 meta 普遍"无值空格但有结尾换行"，不报错；`Plugins/` 下 Odin/UniTask 三件"有值空格但无结尾换行"，也不报错）。
> 修法：**让 Unity 自己重写**——`AssetDatabase.ForceReserializeAssets(paths)`（GUID 全保留、diff 仅空白）；`AssetImporter.SaveAndReimport()` 与 `ImportAsset(ForceUpdate)` 实测**都不会**触发重写。**禁止手改 meta**（红线 4 / `Unity操作规范.md` §2）。
