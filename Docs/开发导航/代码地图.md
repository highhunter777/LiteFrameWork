## 3. 程序集对照（asmdef = csproj 双轨）

FFA 对局规则入口：`LiteSim/Core/Scripts/MatchRules.cs` 与 `Systems/{ScoreSystem,RespawnSystem,MatchSystem}.cs`；`RoomRuntime` 装配/裁决，`RoomOutput.MatchResultSummary` 冻结结果，`ServerHost` 发送 `MatchEnded`，`SettlementOutbox` 保存逐玩家成绩。规则参数来自 `Config/roomserver.json` 房间模板，快照字段同时覆盖 checksum/差分/协议重建。验收证据见[对局规则闭环](../施工进度/对局规则闭环.md)。

> 全量引用图（双端宿主 + 测试 + 编辑器 + 外部依赖标注）→ [程序集引用图](程序集引用图.md)；本节为自研主线速览。

**自研主线**（asmdef 引用即依赖方向，无环）：

```
LiteFramework.Core（零引擎依赖，references:[]）
  ├─► LiteFramework.Async（UniTask 相关件——批④从 Core 外提）+ LiteFramework.Unity（引擎适配）
  ├─► LiteSim.Core（零引擎依赖，BuildHash 源集）
  │     └─► RoomServer.Runtime（服务端内核，只引 LiteSim.Core，noEngineReferences）
  │            └─► RoomServer.Application.Runtime（+LiteNet +Google.Protobuf vendor）
  ├─► LiteNet（协议/传输/KCP；Client 状态机）
  ├─► LiteView（SimView/插值/动画驱动/相机端口——引 Core+LiteNet）
  └─► LiteClient.* 客户端框架侧（物理根 Assets/LiteClient/）：
        Abstractions → Runtime（BattleContext/输入服务）
        + Network.Kcp / Platform.Unity / Content.YooAsset / Scripting.XLua / Serialization.Luban（适配器）
             ▲ 产品 → 框架（反向禁止：L1 纯度守卫）
  └─► LiteGame.* 产品侧（物理根 Assets/LiteGame/）：
        App（流程/装配）→ UI（框架代码）/ LuaBridge（Lua 桥）＋ Assets/UI（资产）＋ Lua（页面脚本）
        + DevLocalServer（进程内本地服，唯一可引服务端程序集的调试档位，D2 登记）
```

**双轨规则**：`Assets/{LiteFramework,LiteSim,LiteNet,LiteTesting,RoomServer}` 下 csproj 与 asmdef 编译**同一份源码**（dotnet 侧供 `Tests.slnx`/宿主/CI，Unity 侧供编辑器与 Player）；csproj 是手写文件在 gitignore 白名单里；产物重定向 `.dotnet/`，**绝不许在 Assets 下落 bin/obj**（Unity 会当插件导入，CS1704）。

**离线开发形态**（`DebugTuner.UseLocalServer` 勾选 + F9）：`ProcedureMatch.CreateTransport` 换 `LocalServerTransport`——进程内跑真 `RoomRuntime`（自动补位满员开局），release 恒真 KCP。
