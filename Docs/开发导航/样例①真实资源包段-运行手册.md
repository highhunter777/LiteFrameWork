# 样例①「真实资源包段」运行手册

定位：框架准入样例①「启动与内容」的最后一段——**真实资产包（bundle）候选**从启动进入健康入口
（[框架先行](../施工进度/框架先行.md) §3/§5；《热更与内容发布专项设计》§7/§8）。
代码侧已落地；Unity 侧与运行按本手册执行。

链路：真资产包候选（`bundle/**` = YooAsset 包根镜像）→ 本地 CDN → 验签/下载/校验/激活 →
Player 以**候选包根**初始化资源包 → 入口资源探针真加载标记素材 → 冒烟证据。

## 前置

- 签名私钥：`~/.unitylib-content-signing/release-key-2026-09-26.xml`（仓库外，已 provisioning）
- Unity 编辑器可用；本地 CDN 需 `python`（`serve-cdn.ps1` 用 `python -m http.server`）
- 入库口径：标记素材放**共享资源目录** `Assets/ShareResource/`（只收纳必要配套）；收集组整目录收集

## 一次性准备（Unity）

1. 菜单 `LiteGame/Resource/样例内容：生成标记素材与收集组`
   - 生成 `Assets/ShareResource/SampleContent/CandidateMarkerTexture.png`（2×2 纯色）
     + `CandidateMarker.prefab`（SpriteRenderer 引用该纹理；唯一依赖同目录纹理）
   - 登记收集组 `ShareResource`（CollectPath=`Assets/ShareResource` 整目录、PackSeparately）
   - 幂等：重复执行不产生重复素材/重复收集组；生成后把 `Assets/ShareResource/**`（含 `.meta`）提交入库
2. 菜单 `LiteGame/Resource/样例：构建候选 Bundle（不覆盖内置包）`
   - 记 Console：`[BuiltinBundle] 构建成功：… output=<目录>`（作为下节的 `-BundleSource`）
   - 该入口 `copy=None`：**不改 StreamingAssets** —— 内置包不含标记素材，样例证据因此成立
     （既有菜单「构建内置 Bundle 包（Offline）」语义不变，勿用错入口）

## 打包候选（PowerShell；在仓库根执行）

```powershell
# 1) 组 staging：真 config + 真 lua（bundle/ 由脚本从 -BundleSource 镜像）
$stage = "Builds/CandidateStaging/rel-sample-001"
Remove-Item $stage -Recurse -Force -ErrorAction SilentlyContinue
New-Item -ItemType Directory "$stage/config","$stage/lua" -Force | Out-Null
robocopy "Assets/GameData/Config" "$stage/config" *.bytes /NFL /NDL /NJH /NJS /NP
robocopy "Assets/LiteGame/Lua" "$stage/lua" *.lua /E /NFL /NDL /NJH /NJS /NP

# 2) 布局 + 签名信封（CDN 根/端口取 scripts/content/local-cdn.json）
pwsh -NoProfile -File scripts/content/publish-candidate.ps1 `
    -ContentDir "$stage" -ReleaseId rel-sample-001 -Revision 1 `
    -BundleSource "<第 2 步 output 目录>"
```

注意事项：

- `-CdnRoot` 参数目前按 `scripts/` 相对解析（脚本重组遗留）；**不要传它**，直接用 `local-cdn.json` 的目录
- 候选清单只收三类前缀（与 `ReleaseLayout` 同源）：`config/**`、`lua/**.lua`、`bundle/**`；其余文件被跳过并报告
- 重复发布同一 `ReleaseId` 会先清目录再重铺（内容变更请递增 `ReleaseId`/`Revision`，不覆盖已发布路径）

## 起服 + 构建 + 冒烟

# 3) 本地 CDN（保持运行的终端）

## 证据判据（Player.log）

冒烟脚本会打印 `Player.log` 实际路径；核对以下三行**同时成立**：

| # | 行 | 含义 |
| --- | --- | --- |
| 1 | `[Asset] ready … version=<候选构建时间戳版本> root=<persistentDataPath>/content/candidate/bundle` | 资源包以**候选包根**初始化（版本 = 候选构建时间戳，与内置包版本不同） |
| 2 | `[Content] entry-assets ok probe=entry-assets checked=1 skipped=0` | 入口探针真加载 `CandidateMarker.prefab` 成功——该 location **内置包没有**，即内容来自候选包（`checked=1` = 属于当前代次清单并实际加载校验） |
| 3 | 内容事务日志 `phase=Confirmed`（`内容事务：phase=…`） | 候选已走完 验签→下载→校验→激活→确认。**注意（2026-10-03 实测）**：非 dev（发布）构建下 `Log` 的 **Info 级不落盘**，该行在 Player.log 中不可见——以持久确认记录为准（更强证据）：重置目录下 `activation.json` 的 `ConfirmedReleaseId=rel-sample-001` / `ConfirmedRevision` / `PendingState=0` / `LastFailure=null` |

```powershell
Select-String -Path "<Player.log 路径>" -Pattern '\[Asset\] init begin','\[Asset\] ready','\[Content\] entry-assets ok','内容事务：phase=','内容通道：CDN'
```

## 反向证据（一次性；证明"加载的确实是候选包"）

```powershell
pwsh -NoProfile -File scripts/build/player-smoke.ps1 -TimeoutSec 60      # 不带 -content.cdnUrl
```

预期（**不失败、但证据对照**）：

- `[Asset] ready … root=builtin version=<内置版本>`（用的是内置包根）
- `[Content] entry-assets ok … checked=0 skipped=1`（标记素材**不属于内置代次清单** → 探针跳过；
  即内置包确实不含该 location —— 与上节 `checked=1` 互为对照）

> 探针判据（`AssetsHealthProbe`）：location 属于当前代次清单 → 必须加载成功（否则 Error）；
> 不属于 → 跳过。这样"内置启动"不会因候选专属入口而失败，而反向对照仍可读。
