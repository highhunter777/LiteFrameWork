# 文档中心

> **角色**：入口页只放指针，不复制正文。文档分四层：**说明**（是什么/怎么跑）、**规范**（必须遵守）、**设计文档**（应该怎样）、**施工进度**（实际怎样）；另有**待办总览**（关口与剩余面）与**审计**（存量债）。

## 2. 目录结构

```text
Docs/
├─ README.md            本页：入口
├─ 待办总览.md           进度与优先级权威（关口/剩余面）
├─ 说明/                 解释层：是什么、怎么跑、在哪（16 章 + 工具索引）
├─ 规范/                 规范层：必须遵守的硬规则与流程（8 章）
├─ 设计文档/             目标架构与专项设计（权威：应该怎样）
├─ 施工进度/             一条线一卷的实施证据（权威：实际怎样）
├─ 审计/                 质量债登记与归档（按类型一文件）
└─ 归档记录/<date>/      被取代的历史稿（仅追溯）
```

> **根目录只放两份**：入口（README）与进度权威（待办总览）。规则在 `规范/`，解释在 `说明/`，设计与证据各归其位。

## 6. 归档

被取代的历史稿原按日期存 `归档记录/<date>/`（每卷 README 写明「文件 → 退役原因 → 现行权威」）。

**`Docs/归档记录/` 已整体清空**：2026-09-20～2026-10-29 各卷不再在库内，历史稿的原文只保留在 git 历史里。现役文档里指向归档原文的地方已去掉链接、只留文档名；引用它们的批次结论仍按当时事实阅读。新的归档仍按 `归档记录/<date>/` 建立并在本节登记一行。

## 7. 维护

- 新增/改文档先读 [规范 01](规范/01-文档体系与写作.md)；改完必跑 `--suite Doc`。
- 说明/规范按两位数连续编号，一章一文件；新增章整段重排（D9 把守）。
- 不保留重定向壳：旧路径退役时把映射写进对应目录 README，全仓入链同批改指。
