## 1. 前置决策（开工前定案）

| # | 决策 | 结论 | 理由 |
| --- | --- | --- | --- |
| 1 | **`LiteSim.View` 程序集** | 新建 `Assets/LiteSim/View/`（asmdef `LiteSim.View`，`noEngineReferences: **false**`，引用 `LiteSim.Core` + `LiteFramework.Unity` + UniTask + YooAsset + Cinemachine + Unity.InputSystem + 业务侧由 `LiteGame` 反向引用它） | 表现层**必须**能用引擎（§6.3：`Mathf`/粒子/`Animator`/DOTween 全可用）；与 `LiteSim.Core` 的零依赖红线互不矛盾——**判定零引擎、表现全引擎** |
| 2 | **`SimView` 驱动接缝** | `SimView : ITickable`（`GameEntry` 统一驱动），内部包 `FrameDriver`（M8 决策 14 既定）；**不吃 `IGameClock`** | 逻辑帧恒 60Hz；渲染帧只做插值/表现 |
| 3 | **镜像与池化** | `slotIndex → GameObject` 视图表；按 **location 分桶池**（同 `EntityService` 形态）；实体 Id 作稳定键（64 位，防重绕） | 复用既有池化与订阅袋纪律（§7.2 生命周期归属） |
| 4 | **远端插值** | `cur/prev` 双快照 + `alpha = accumulator / SimConfig.Dt`；插值延迟 = **2×快照间隔**（`SimConfig.InterpFrames`）；位移 >2m / 新增 / 消失 **直接 snap** | §6.1 既定 |
| 5 | **和解重对齐** | `Realign(simFrame)`：snap 当前逻辑态 + 清 `prev/cur` + 重置累加器 + **`silenceUntilFrame = 回滚前已渲染帧号`**；**本地玩家不 snap → residual 偏移 ~100ms 衰减**；远端 snap（被插值吸收） | §6.2；本地直接 snap 会持续微抖 |
| 6 | **表现触发只有两个来源** | ①**状态差分**（`cur.Hp < prev.Hp` → 受击；存活位变化 → 死亡/复活）②**`FrameEventBuffer`**（Fire/Hit/Crit/Death，每逻辑帧末消费——M8 §2.3 语义）；两者都受 `silenceUntilFrame` 保护 | §6.1；帧事件承载"差分推不出来的离散事件" |
| 7 | **开火 0 延迟** | 本地按键 → **立即**播枪口火焰 + 音效（纯 View，不碰 Sim）；**命中**特效等 Sim 该帧判定 | 手感与逻辑正确性的分工线（§6.2） |
| 8 | **输入三件** | `IIntentSource`（**键鼠 + 触屏双实现**）+ Input System Action Maps + 键位重绑（`InputActionRebindingExtensions` + 控件库 `Dialog` 重绑界面） | 设计 §4.1/§6-C1；触屏实现留接缝、真机验收归 M12 |
| 9 | **`PlayerController` 不做位移**（关键） | 只组装 `SimInputFrame` 并驱动 `RollbackSim`；**位移/碰撞/朝向全部由 Sim 权威** | 设计 §5 交付表原文；设计方案 §8.2 的 `CharacterController` 是**单机形态**——联机下双位移源必然撕裂，本里程碑明确不用 |
| 10 | **三个"门"** | ①**上下文门**（UI/菜单打开 → 战斗意图置零）②**帧边界门**（渲染帧只刷新"待用意图"，**逻辑帧才消费一次**——追帧不产生输入）③**重放静默门**（`silenceUntilFrame` 防事件重播 + 参数外插防动画倒带） | 设计 §4.1：缺一个就出 bug |
| 11 | **`InputDelay = 1` 不改** | 本地输入延迟 1 帧提交，配合 `InputHistory` 与和解判定 | 既有设计，勿动 |
| 12 | **相机服务** | `ICameraService`（`LiteSim.View` 内，**不进框架**）+ Cinemachine 承接；跟**预测位置**；和解期跟**衰减后表现位置**；震屏走 **Impulse** 且受 `silenceUntilFrame` 防重播；挂 `IWorldClock`（时停即冻结）；UI 用 Overlay（不依赖相机） | 设计 §3.1 定案逐条 |
| 13 | **地图装配分两半** | **视觉** = `Map_v1` 场景正式装配（View 侧）；**判定** = 新写 `MapExtractor`（Editor 工具：`Collider` → `SimMapData` 障碍/出生点，**生成物入库**） | 视觉与判定不共用几何（美术可改视觉、判定数据由工具重导）；一致性靠**随机采样点对照**用例守 |
| 14 | **地图 64 障碍上限的处理** | 超出按**面积降序取前 64** + 报告被丢弃清单（Editor 弹窗/日志）；**不静默截断** | `SimMapData.MaxObstacles = 64` 是定容事实；静默丢弃会导致"能穿过墙"这类不可解释现象 |
| 15 | **角色与动画** | `Erika` → **Humanoid** + 自建 `AnimatorController`（idle/run/aim/fire/hit/death，复用 `Kazuko.controller` 结构做模板）；Animator **参数单向驱动**（速度/开火/受击/死亡） | 美术链 P0"没它角色不播"；《美术资源清单》§0-1/2 |
| 16 | **HUD 三件（本里程碑）** | 血条（`HpBar`）+ 延迟/丢包指示 + 击杀提示（`Toast`/`FlyText`）；**技能栏 + 冷却环留技能批**（C3 之后） | 消费控件库模板；Lua 逻辑 + C# 壳（纪律：界面逻辑在 Lua） |
| 17 | **网络装配** | `KcpNetworkService : INetworkService`（LiteGame 桥）+ 流程三阶段 `ProcedureMatch/Battle/Result` + `ProcedureArgs` 的 `roomId/frameNo/BattleContext` 字段位（M10 遗留，建议不晚于本里程碑） | §7.2 三点接法 + §8.3 生命周期归属；`BattleContext` 由流程创建销毁 |
| 18 | **VFX 服务** | 独立实施：见**《VFX服务实施指导》**（本里程碑执行）；与 View 的接缝 = 观察层在静默门外调 `IVFXService.Play` | 设计已在《动作与特效设计》§2；**服务不调其他服务**（音效由编排方分别调） |
| 19 | **本里程碑不做** | 技能/Timeline 编排（`tb_action`/自定义轨/导出器——C3 之后）· AOI 调优 · 8 人压测 · 真机触屏/机型适配（M12）· 多房间/MatchMaker · Mod | 验收只要求"4 人移动/射击 + 视觉平滑 + 开火 0 延迟"，技能不在线 |

## 2. 分步实施（逐件施工图）

**批次划分（C1–C5 沿用设计 §6，另加 P 前置与 W 网络批）**：

| 批 | 内容 | 验收 |
| --- | --- | --- |
| **P（前置，先做）** | 地图提取器 + 角色/动画接入 | `Map_v1` → `SimMapData` 一致；角色能播 idle/run/fire |
| **C1 输入** | `IIntentSource`（键鼠 + 触屏）+ Action Maps + 键位重绑 | 重绑立即生效；两种实现产出同一意图面 |
| **C2 控制器** | `PlayerController` + 输入对齐逻辑帧 + 三个门 | 本地 0 延迟手感；追帧不产生额外输入 |
| **C3 表现核心** | `LiteSim.View` + `SimView`（镜像/插值/静默门）+ `ICameraService` | 远端插值不抖、本地修正不微抖；和解不重播 |
| **C4 战斗表现** | VFX 服务（独立指导）+ 开火/命中/死亡表现 + HUD 三件 | 开火 0 延迟；命中特效与判定一致 |
| **C5 联调验收** | `KcpNetworkService` 桥 + 流程三阶段 + 4 人对跑 + 150ms/带宽实测 | §9 M11 验收全组 |

### 2.1 P：地图与角色（~450 行）

```
Assets/LiteSim/View/Editor/MapExtractor.cs        # Map_v1 Collider → SimMapData（障碍/出生点，生成物入库）
Assets/LiteSim/View/Editor/MapConsistencyTests?   # 一致性用例（EditMode）：随机采样点 Sim 判定 vs 场景几何
Assets/Animation/Erika.controller                 # Humanoid + idle/run/aim/fire/hit/death（2026-09-19：资源目录口径改用顶层 Assets/Animation/）
```

- 提取规则：`BoxCollider` → `HalfX/HalfZ/Height`；`SphereCollider` → `Radius`；`MeshCollider` **不提取**（报告）；出生点用场景内命名标记（`spawn_00..`）。
- 上限处理：面积降序取 64 + 报告（决策 14）。
- 验收：一致性用例（在障碍内外各采样 N 点，Sim 的碰撞判定与场景几何一致——**不允许"视觉能穿、判定挡住"**）。

### 2.2 C1：输入采集与重绑（~500 行）

```
Assets/LiteSim/View/Input/IIntentSource.cs        # 设备无关意图面（MoveX/MoveZ/AimX/AimZ/Buttons）
Assets/LiteSim/View/Input/KeyboardMouseIntentSource.cs
Assets/LiteSim/View/Input/TouchIntentSource.cs    # 留接缝（真机验收 M12）
Assets/LiteGame/Scripts/Runtime/Shell/Input/InputService.cs   # 采集 + 重绑 + 上下文门（UI 开 → 意图零）
Assets/LiteGame/Assets/Input/PlayerActions.inputactions     # Action Maps（战斗/UI 双 Map）
```

- 相机相关换算（WASD → 世界 MoveX/MoveZ；鼠标屏幕射线 → 地面 AimX/AimZ）在 View 侧用 `Mathf` 无妨——**输入是数据**（进 `InputHistory` 与传输），换算确定性不影响 Sim（设计 §4.1 明示）。
- 重绑：`InputActionRebindingExtensions` + 控件库 `Dialog` 界面；重绑结果落 `SettingService`（既有）。

### 2.3 C2：`PlayerController`（~250 行）

- 职责：每渲染帧刷新"待用意图"；**逻辑帧边界消费一次**（`RollbackSim.Tick` 内）；`InputDelay=1` 提交；不产生位移。
- 上下文门：UI/菜单/重连提示打开 → 意图置零（含 `Buttons` 清零）。
- 用例：追帧 5 帧时输入只消费 5 次且同值；UI 打开时 Sim 收到零意图；捏造非法输入被 clamp（传输层已挡 + Sim 内 clamp）。

### 2.4 C3：`SimView` + 相机（~850 行）

```
Assets/LiteSim/View/SimView.cs          # ITickable：FrameDriver + 镜像 + 插值 + 静默门 + Realign
Assets/LiteSim/View/ViewTransformMath.cs# 纯函数：alpha 插值 / residual 衰减 / snap 判据（可 L1 覆盖）
Assets/LiteSim/View/CameraService.cs    # ICameraService（模式档位吃策略包参数）
Assets/LiteSim/View/EntityViewMap.cs    # slotIndex → GameObject 视图表 + 池
```

- **插值/衰减抽成纯函数**（`ViewTransformMath`，无引擎依赖）→ 进 `Tests/LiteSim.Core.Tests`（L1 覆盖），避免"表现数学只能靠肉眼验"。
- 相机模式档位（俯角/距离/FOV/夹取）来自策略包参数面（`INetGameStrategy` 的 ViewRule），相机不认识"模式"。

### 2.5 C4：战斗表现 + HUD（~900 行，VFX 服务另计）

- 开火：本地立即（枪口火焰 + `sfx_gun_fire` + 后坐力）；命中：等 Sim 帧事件（`fx_hit_default`/`fx_hit_flesh`）；死亡：状态差分触发。
- HUD：`HpBar`（本地 + 远端头顶）、延迟/丢包（Ops → 事件 → UI）、击杀提示（`Toast`/`FlyText`）。
- 纪律：界面逻辑在 Lua（`UI.*` 逻辑表），C# 只做壳；控件驱动走受控 API。

### 2.6 C5：网络装配与联调（~750 行）

```
Assets/LiteGame/Scripts/Runtime/Shell/Network/KcpNetworkService.cs   # INetworkService 桥（LiteNet ↔ 框架契约）
Assets/LiteGame/Scripts/Runtime/Procedure/ProcedureMatch.cs / ProcedureBattle.cs / ProcedureResult.cs
Assets/LiteGame/Scripts/Runtime/Match/ProcedureArgs 字段位（roomId/frameNo/BattleContext）
```

- `BattleContext` 生命周期：流程 `OnEnter` 创建（`new BattleContext`：SimWorld/RollbackSim/Ring/InputHistory 全预分配）、`OnLeave` 销毁（§3.2 既定，**不经容器**）。
- 联调形态：服务器 + **4 个有头客户端**（同机）+ 无头 4 客户端（自动化）；测试脚本 `scripts/m11-*.ps1` 留档。

## 6. 决策记录（本轮定案）

| # | 决策 | 备注 |
| --- | --- | --- |
| ① | `LiteSim.View` 是**独立程序集**且**允许引擎依赖**（判定零引擎、表现全引擎） | 与 Core 红线不冲突 |
| ② | **`PlayerController` 不做位移**——位移/碰撞/朝向全归 Sim | 联机下双位移源必然撕裂；设计方案 §8.2 的 `CharacterController` 属单机形态 |
| ③ | 插值/衰减等**表现数学抽纯函数**进 L1 | 避免"表现只能肉眼验" |
| ④ | 地图**视觉与判定分离**，靠提取器 + 一致性用例守 | 美术改视觉不必动判定数据 |
| ⑤ | 地图超 64 障碍**报告不静默** | 静默截断会变成"能穿墙"的不可解释 bug |
| ⑥ | `silenceUntilFrame` 住 View（观察层），**服务不知静默** | VFX/音频服务保持无状态可并行 |
| ⑦ | 表现触发只有两个来源（状态差分 + 帧事件缓冲） | 单一真相：Sim |
| ⑧ | 技能/Timeline 不做 | 本里程碑验收不含技能 |

## 7. 边界与风险

- **不越界**：不回写 Sim（§6.3 唯一红线）· 技能编排留后续 · 真机适配留 M12 · 框架层不放 VFX/相机（只放契约）
- **风险 1（最凶）：双位移源**——若有人让 `PlayerController`/`CharacterController` 也推位置，Sim 与表现立刻分裂（症状：本地看着对、别人看你瞬移）。对策：决策 ② 写死 + 评审把关；表现侧只允许"**residual 偏移**"这一种位置修正（且必须衰减到零）
- **风险 2：地图提取与视觉不一致**——视觉能穿、判定挡住（或反之）会让玩家完全失去信任。对策：一致性采样用例（决策 ⑤ 同上）
- **风险 3：Erika 动画缺动作**（`fire`/`hit` 可能有，`death` 未必）——缺的用**占位动作 + 日志**，不要静默播 idle（否则"死了还在跑"）。对策：接线时逐动作核对并记录缺口清单
- **风险 4：插值延迟与手感**——`InterpFrames=4`（66ms）是远端平滑与命中的折中；改了要同步 `SimConfig` 与延迟补偿口径（§3.4.1 共用旋钮）
- **风险 5：4 人对跑的机器压力**——有头 4 客户端 + 服务器同机跑，Profiler 会互相干扰。对策：验收用无头 4 客户端跑行为、有头跑观感
- **风险 6：和解率未达标**——若 4 人实测和解率偏高，先看是否"预测输入与权威输入链不一致"（`InputDelay`/上下文门），再考虑降低 `InterpFrames`；**跨运行时已逐位一致**，底噪不再是嫌疑（M7/§5-33 已排除）
