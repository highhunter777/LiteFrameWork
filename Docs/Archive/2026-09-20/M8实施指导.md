> 依据：《状态同步实施方案》**§3.1–3.9**（Sim 层结构：槽位数组 / 60Hz / 系统顺序 / 2.5D / 全量校验 / 命令缓冲+帧事件缓冲 / 声明式边界 / 判定住址）、**§9 里程碑（M8 定义与验收）**、**§11 开工前检查清单**（第 3 项常量、第 8 项与 M9 的接口）、**§5.1**（`Step` 纯函数）；范式轴依据《联机同步策略设计》§1（数值层是唯一整层差异 → **Sim 结构两范式同构**）。

## 1. 前置决策（开工前定案）

| # | 决策 | 结论 | 理由 |
| --- | --- | --- | --- |
| 1 | **整块拷贝的实现方式** | **定长托管数组 + `Array.Copy`**，`allowUnsafeCode` 保持 `false` | 设计原文写 `unsafe struct` + `fixed byte[]` + `UnsafeUtility.MemCpy`，但 **`UnsafeUtility` 属 Unity 程序集**（`LiteSim.Core` 零引擎依赖 → 不可用）；`Array.Copy` 内部即 memcpy 级，且纯托管、可 dotnet 侧跑 |
| 2 | **`Custom`/`Globals` 的落法** | **平面数组**：`byte[] Globals`（256）、`byte[] CustomData`（`MaxEntities*32`，`slot*32+offset` 寻址） | struct 内**不能**放数组字段（引用类型 → `Array.Copy` 只拷引用 → 快照会共享同一块 ✗ 回滚必错） |
| 3 | `EntitySlot` 组成 | 纯值类型：`long Id` / `SimVector3 Pos, Vel` / `float Yaw` / `int Hp` / `uint Flags`（+ 平面数组的自定义态） | 必须 **blittable** 才能整块拷贝；`EntitySlot[]` 与 `CustomData` 一并快照。**2026-09-18 对账**：字段组成不变；`Yaw` 自 Aim 改造起降为 **Sim 内派生量**（由 `SimInputFrame.AimX/AimZ` 经 `SimTrig.Atan2` 算出，仍进快照与 checksum）——见《角色状态与动作实现设计》§7-1 |
| 4 | **世界状态的容器形态** | `sealed class SimWorldState { int Frame; ulong RngState; EntitySlot[] Entities; uint[] AliveBitmap; byte[] Globals; byte[] CustomData; CommandBuffer Cmds; FrameEventBuffer Events; }` | 类持有**定长数组**（构造期一次分配，运行期零 new）；`EntitySlot[]` 是值类型数组 → `Array.Copy` 深拷内容 ✓ |
| 5 | **快照可拷贝性为硬约束** | 世界状态内**禁止引用类型字段**（无 `List`/`Dictionary`/`class` 成员） | M9 的 `SnapshotRing` = 逐数组 `Array.Copy`；M8 就把这条钉死（自检：反射断言字段皆为值类型/数组） |
| 6 | **常量集中** | 新建 `SimConfig`（§11-3）：`TickRate=60`、`Dt = SimMath.Dt`、`MaxEntities=256`、`InputDelay=1`、`MaxCatchUp=5`、`MaxRollbackFrames=8`（M9 用）、`InterpFrames=4`、`LagCompHistory=16`（M10 用） | §11 开工前检查第 3 项；常量一处定义，禁止散落魔数 |
| 7 | **实体 Id 编码** | `long Id`：高 48 位 version + 低 16 位 slotIndex；**跨帧引用必须 `TryResolve(id) → ref slot`**（校验 version 一致，失败 = 引用失效） | §3.1 注释：16 位 version 在弹幕密集时约 20 分钟耗尽 → **64 位防重绕**；成本 4B/实体可忽略 |
| 8 | **槽位分配/释放** | 线性找空槽（从 `_nextFree` 起环形扫描）+ 版本递增；**不做 swap-remove**（打乱遍历顺序 = 破确定性） | §3.1 |
| 9 | **遍历** | 一律 `for (i = 0; i < MaxEntities; i++)` 跳空槽；提供 `EntityIt`（`ref struct` + `ref return`，零分配）消除手写样板 | §3.1/§3.8-借鉴2（**不长为查询语言**） |
| 10 | **System 签名窄化** | 按域取参：`CollisionSystem.Run(ref state.Entities, state.AliveBitmap, ...)`；**只有该碰随机数的系统**才拿 `ref RngState` | §3.8-借鉴1：确定性审计写在签名上（"谁能动 RngState"从口头约定变类型约束） |
| 11 | **系统注册与顺序** | 显式注册表 + `Step` 内固定顺序：`输入 → 移动/重力 → （碰撞）→ 射击判定 → 投射物 → 伤害结算 → 冷却/Buff → 清理`；**不用自动扫描**；同帧多请求按 `playerId` 升序 | §3.3；本里程碑**实际实现**：输入/移动/重力/射击(hitscan)/伤害结算/清理；**碰撞与投射物留空位**（见 #12） |
| 12 | **M8 的系统范围（明确不做）** | 做：输入应用、移动+重力（2.5D）、hitscan 射击判定、伤害结算（经 CommandBuffer）、清理（死亡回收）；**不做**：静态障碍碰撞分桶、投射物实体、Buff/动作/属性（后续里程碑按其设计插入固定顺序位） | 验收（§9 M8）只要求确定性/可重放；把系统集合压到"能证明顺序与重放"的最小链，**顺序位一次摆好，加系统 = 插一行** |
| 13 | **Sim 不用事件中心** | 三种需求分去处：跨帧状态 → 世界状态；当帧延迟 → `CommandBuffer`（Capacity 512，**固定轮次最多 3 轮**，非 while 到稳定）；告知表现 → `FrameEventBuffer`（Capacity 256，**每逻辑帧末立即消费并清空**） | §3.7（事件中心的动态订阅/队列/闭包在确定性边界内全是负资产） |
| 14 | **FrameDriver 归属与接缝** | `FrameDriver` 在 `LiteSim.Core`（零依赖，**不实现 `ITickable`**）：累加器 + 追帧（`MaxCatchUp=5`）+ 固定 `dt`；M8 阶段由**测试直接驱动**，M11 由 `SimView` 包装（`SimView.Tick` 内跑累加器→`Step`→消费帧事件），**不吃 `IGameClock`** | §3.2：GameClock 可变速/暂停（服务表现层），逻辑帧必须恒 60Hz |
| 15 | **校验算法** | FNV-1a 32 位，遍历顺序恒定，覆盖 `Frame`/`RngState`/全部槽位逻辑字段/`Globals`/`CustomData`；**开发期每帧算，release 每 10 帧** | §3.6；v3 定位：**本地调试与离线重放裁判**（不上服务器对账） |
| 16 | **范式无关性** | 存储与系统层**不得出现任何状态同步专属假设**（无"客户端/服务器"字样、无网络类型）| 《联机同步策略设计》§1：两范式只有数值层整层替换，Sim 结构与机制库同构（M10′ 只重做网络层） |
| 17 | **输入与地图的"数据结构"并入 M8**（系统实现可留空） | `InputFrame`/`SimInputFrame`（输入面）+ `SimMapData`（判定用地图：**定长数组**的静态障碍（圆/AABB）+ 地面 + 出生点 + 尺寸）在 M8 定下并冻结 | 二者都是后续系统的参数面，**接口先定、消费者后写**；`SimMapData` 必须定长可拷（同 #5），视觉地图与它无关（§18） |
| 18 | **"可见性"用灰盒沙盒满足，不用产品件** | 新增 `SimSandbox`（Unity 侧**一次性调试件**）：`Map_v1` 当视觉底 + 灰盒胶囊 + 键盘 WASD→直接喂 `InputFrame` + Gizmos 画活体/朝向/hitscan 线/伤害；**不做控制器抽象、不做相机、不做动画** | 目的仅是"让 Sim 肉眼可见以便早期验证"；标注"不承担产品职责"，M11 的 `SimView`/控制器上线后即可删 |
| 19 | **PlayerController 与地图正式装配不在 M8 之前做** | 均留在 **M11**（§9 M11 行已含"输入采集 + 相机"，另补"地图装配"） | ①M8 验收（固定输入序列 3000 帧 / 逐字节一致）**不需要**控制器，接真实输入反而破坏可复现性 ②控制器是 `InputFrame` 的消费者，接口未定就写必返工 ③地图视觉半属 View（M11）、判定半属 Sim（#17） |

### 2.2 `SimConfig` + `SimWorldState`（~250 行）

```csharp
public static class SimConfig {
    public const int  TickRate = 60;
    public const float Dt = SimMath.Dt;              // 与 M7 同源，禁止第二处定义
    public const int  MaxEntities = 256;
    public const int  InputDelay = 1, MaxCatchUp = 5, MaxRollbackFrames = 8;
    public const int  InterpFrames = 4, LagCompHistory = 16;
    public const int  CustomBytesPerEntity = 32, GlobalsBytes = 256;
}

public sealed class SimWorldState {
    public int Frame;  public ulong RngState;
    public readonly EntitySlot[] Entities;           // 定长
    public readonly uint[] AliveBitmap;              // MaxEntities/32
    public readonly byte[] Globals;                  // 256
    public readonly byte[] CustomData;               // MaxEntities*32（平面）
    public readonly CommandBuffer Cmds;  public readonly FrameEventBuffer Events;
    ushort[] _versions;  int _nextFree;

    public long Spawn(in EntitySlot slot, out int slotIndex);   // 找空槽 + version++ → 组装 Id
    public bool TryResolve(long id, out int slotIndex);         // 校验 version（跨帧引用唯一入口）
    public void Despawn(long id);
    public void CopyTo(SimWorldState dst);                      // 逐数组 Array.Copy（M9 快照原语）
}
```

**要点**：`Id = (long)version << 16 | (ushort)slotIndex`（version 48 位）；`TryResolve` 失败必须返回 false 而**不是抛**（引用失效是正常路径：目标已死）。

### 2.3 两个缓冲（~160 行）

`CommandBuffer`：`Write(...)` 满则丢弃并记 `Log.Warning`（**不扩容**——扩容=运行期分配）；`FlushCommands` 由 `SimStep` 按固定顺序分批调用，**最多 3 轮迭代**。
`FrameEventBuffer`：`Write(...)` 同款；**消费方是 `SimView`**（M11）——M8 里 `SimStep` 只负责"每帧末交付 + 清空"。

### 2.4 系统链（~400 行）

| 系统 | 域参数（窄化签名） | 行为（M8 最小版） |
| --- | --- | --- |
| `InputSystem` | `ref Entities, AliveBitmap, inputs` | 应用 `InputFrame`（移动向量、朝向、开火位） |
| `MovementSystem` | `ref Entities, AliveBitmap` | `pos += vel*dt`；跳跃重力；**地面钳制**（2.5D） |
| `ShootingSystem` | `ref Entities, ref RngState, inputs, ref Cmds` | hitscan：对活体做**圆柱求交**（半径 + y 区间），按距离取最近；命中 → `Cmds.Write(Damage…)`；开火 → `Events.Write(Fire…)` |
| `DamageSystem` | `ref Entities, AliveBitmap, ref Cmds, ref Events` | 结算 `Damage` 命令 → 扣血 → `Hp<=0` 写 `Kill` 命令 + `Events.Write(Death…)`（**命令的二次产生走固定轮次**） |
| `CleanupSystem` | `ref Entities, AliveBitmap` | 回收死亡实体槽位（`Despawn`） |

**顺序依赖**：`Shooting → Damage → Cleanup` 必须成立（用例断言：伤害结算必须看到同帧射击结果；清理必须看到同帧死亡）。

## 3. 测试与自测策略

| 组 | 用例 |
| --- | --- |
| **布局契约** | 反射断言：`SimWorldState` 无引用类型**字段**（`EntitySlot[]`/`byte[]` 合法）；`EntitySlot` 仅值类型；`SimConfig` 常量值对账 §11-3 |
| **槽位与 Id** | 分配/释放/Double-free 忽略；同槽位复用 65536 次后 **Id 不复用**（version 递增）；`TryResolve` 对已死 Id 返回 false |
| **确定性（§9 验收①）** | 固定输入序列跑 **3000 帧**：两次运行 `CopyTo` 快照**逐字节一致**（`Array.Copy` 后逐元素比 + checksum 比） |
| **校验基线（§9 验收②/③）** | 3000 帧 checksum 序列写入 `Baselines/SimChecksum.txt`；重跑逐值一致（同款 M7 基线机制） |
| **系统顺序** | 构造"伤害必须晚于射击""清理必须晚于伤害"的可观测用例（去掉顺序即失败） |
| **同帧多请求顺序** | 乱序输入（playerId 3,1,2）→ 结果与升序一致（**顺序确定**，不是"平均正确"） |
| **命令缓冲轮次** | 三级连锁（伤害→击杀→掉落）在 3 轮内收敛；第 4 轮不再产生（丢弃并告警） |
| **帧事件语义** | 每帧末消费清空；追帧 5 帧时**5 帧事件都交付**（不只剩最后一帧） |
| **FrameDriver** | 累加器：0.5 帧输入 → 不推进；2.5 帧输入 → 推进 2 帧；积压 100 帧 → 单次 Tick 最多追 `MaxCatchUp=5` |
| **纪律** | 扫描器 0 违规（R1–R5 对 `Assets/LiteSim` 全开） |
| **跨运行时（降级为保障）** | 复用 M7 对账法：`Baselines/` 在 .NET 与 Unity 双跑逐位比（§9 注：v3 下已非正确性前提，而是**预测质量**保障） |

## 6. 决策记录（本轮定案）

| # | 决策 | 备注 |
| --- | --- | --- |
| ① | **整块拷贝用 `Array.Copy`（纯托管）**，不引入 `unsafe`/`UnsafeUtility` | Core 零引擎依赖的必然推论；`Array.Copy` 即 memcpy 级 |
| ② | **平面数组承载 `Globals`/`Custom`**（struct 内不放数组） | 否则 `Array.Copy` 浅拷引用 → 快照共享 → 回滚必错 |
| ③ | **64 位 Id（48 version + 16 slot）** + `TryResolve` 唯一入口 | §3.1 防重绕 |
| ④ | **M8 系统集合 = 输入/移动/射击/伤害/清理**；碰撞分桶与投射物留后续 | 顺序位一次摆好，加系统 = 插一行 |
| ⑤ | **FrameDriver 不吃 `IGameClock`**；M8 由测试驱动，M11 由 `SimView` 包装 | §3.2 固定 60Hz |
| ⑥ | **帧事件每逻辑帧末交付 + 清空**（不在 `Step` 内清） | §3.7：追帧不丢事件、不必进快照、回滚天然正确 |
| ⑦ | **命令缓冲固定 3 轮**（非 while 到稳定） | 轮次固定才确定 |
| ⑧ | **checksum = 本地调试/重放裁判**（不上服务器对账） | v3 定位（权威快照覆盖兜底） |
| ⑨ | **`InputFrame`/`SimMapData` 并入 M8 先定结构**（系统实现可空） | 接口先定、消费者后写；地图"判定半"属 Sim |

## 7. 边界与风险

- **不越界**：不建 `SnapshotRing`/回滚（M9）、不建网络（M10）、不建 `SimView`（M11）、不做帧同步专属假设（两范式同构）
- **不提前做 M11 的产品件**（2026-09-15 定，§1-#19）：`PlayerController`（走位/瞄准/相机/键位重绑，§8.2）与**地图正式装配**（`Map_v1` 视觉半）一律留 M11；M8 只交付 `InputFrame`/`SimMapData` **结构**与"一次性沙盒"。三条理由：①M8 验收用合成输入，真实控制器无助且破坏可复现性 ②控制器吃 `InputFrame`，接口未定先写必返工 ③地图视觉半属 View、判定半属 Sim，混做必然二次返工
- **风险 1：整块拷贝的隐蔽共享**——只要有人往世界状态里加引用类型字段，M9 的快照就会静默共享同一块内存（表现为"回滚后状态没退回去，且偶发"）。**对策**：反射自检用例 + `CopyTo` 用例（含 `CustomData` 改一字节后两态必须不同）
- **风险 2：`EntityIt` 的 `ref struct` 约束**——`ref struct` 不能装箱/进闭包/做字段；若后续需要"存起来慢慢遍历"会撞墙（正确做法是就地遍历）
- **风险 3：系统顺序被"顺手"打乱**——顺序是确定性的第一因，靠用例钉死（#3 组）
- **风险 4：命令缓冲溢出静默丢**——满即丢弃 + 告警；若真实需求超 512，**改容量常量**而不是扩容（扩容=运行期分配）
- **风险 5：跨运行时一致性降级被误读**——v3 下它不是正确性前提（快照覆盖兜底），但仍决定**预测准确率**（和解率）；基线对账仍要做，但失败不阻断发版
- **无 git 无关**（仓库已有版本控制）；`.dotnet/` 产物重定向已在 M7 就位

**跨运行时双跑对账结论**（v3 定位：预测质量保障，非阻断）：

- 同运行时：.NET 两次运行 3000 帧逐字节一致（验收①②不变）；Unity（Mono/2022.3）忠实重放与 .NET 基线**帧 0–2 逐位一致，帧 3 起分叉**（2951/3000 帧失配）。
- 根因（位级转储 + 双精度复算定位，非猜测）：**Unity Mono 对 `pos += vel * dt` 类乘加链执行 FMA 融合（单次舍入），.NET 8 保持 C# 语义的两次舍入**——特定操作数组合下差 1 ULP（帧 3 slot0 pos.Z：Mono=`BC8F3759`=融合值，.NET=`BC8F375A`=分离值）。分叉自首个 ULP 起雪崩至全序列失配，属预期内跨运行时底噪。
- 处置（依 v3 不阻断发版）：状态同步主路线以**服务器权威 + 权威快照覆盖**兜底正确性（§3.6/§12）；该 ULP 底噪由 M10 的"和解触发率可观测"吸收为预测质量指标。**同运行时重放不受影响——M9 回滚/重放的"同一运行时内逐位一致"前提成立**；M9 起重放/对账必须与被预测方同运行时。
- 对账过程顺带发现并修复：`SimChecksumBaselineSpec.MakeInputs` 原按值传 `SimRng`（可变 struct）→ 调用方输入流永不推进，基线实为"同一帧输入重复 3000 次"，与头注释"随机脚本输入"意图相悖。已改 `ref` 并重记录基线（L1 全量复验通过；该缺陷不推翻既有验收——冻结输入下 3000 帧稳定/重跑一致同样成立，受损的是场景丰富度）。**教训两条**：① 可变 struct 作参数必须 `ref`；② 双跑对账先证伪重放器本身——首轮"全分叉"是重放器与规格输入流不一致的误报。
