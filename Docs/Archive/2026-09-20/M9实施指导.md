# M9 实施指导：快照与回滚（先于网络）

> 依据：《状态同步实施方案》**§5.1–5.5**（机制库：`Step` 纯函数前提 / `SnapshotRing` / 输入预测策略 / 回滚触发与执行 / `InputHistory`）、**§9 里程碑 M9 行**（验收定义）、**§10-3/7**（纯函数红线 / 防雪崩）、**§11-3/8**（常量与预分配对账）；M10 复用面依据 **§3.4.1/L141**（服务端回溯快照环 = 本里程碑 `SnapshotRing` 同类异容）与 **§5.6**（重连补发吃 `InputHistory`）。
> 前置：**M8 已交付**（`SimWorldState.CopyTo` 深拷原语 / `SimStep` 纯函数 / `SimChecksum` / `FrameDriver` / `SimConfig` 常量 / 3000 帧基线机制）+ M8 收口批对账结论（**同运行时红线**，见下）。
> 定位：把 M8 的"可整块拷贝、可逐帧重放"升级为"**可回滚校正**"——M10 网络层（客户端预测/和解 + 服务端回溯）的机制地基。**顺序纪律（§9）：M8 → M9 → M10，快照回滚必须在联网前验收**——否则预测/和解 bug 与网络 bug 混在一起，定位成本翻十倍。
> 工期估算：**2–3 天**；预算 ~920 行（含测试 ~450）。

## 1. 前置决策（开工前定案）

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | **`SnapshotRing` 内部形态**：`SimWorldState[]`（每槽**独立实例**）+ `int[]` 帧号标记；`Capture`/`TryRestore` 全走 `CopyTo` | M8 决策①延续：纯托管 `Array.Copy`，不引 unsafe/memcpy；设计稿 §5.2 的 `stateSize` 参数取消（状态尺寸自述），签名落为 `SnapshotRing(int capacity)` |
| 2 | **帧号语义**：`Capture` 在每帧 `Step` **后**调用，标记"该帧执行后状态"；`TryRestore(F-1)` = "F 帧执行前状态" | 与 §5.4 伪码无缝：`target = F-1` → 重放 `f = F..lastSimulatedFrame`。两种帧号约定（Step 前/后）必须定死一种，取与伪码自洽者 |
| 3 | **容量 ctor 参数化**：客户端回滚环 = `MaxRollbackFrames + 1` = 9；M10 服务端回溯环 = 同类、容量 `LagCompHistory` = 16 | §5.2/§3.4.1："SnapshotRing 本体是 M9 交付物的复用"——不做第二个实现 |
| 4 | **越界语义（超出深度正确退化）**：`ContainsFrame` 不在环内 → **停止预测前进**（`_halted`，等真实输入追上——退化 lockstep 卡顿）+ 溢出计数告警；不做"最老快照 + 全量重放"（输入历史仅 32 帧，越界即不可重放，不假装可行） | §5.4："超出则强制等待……正确性优先的兜底" |
| 5 | **`InputHistory` 形态**：环形数组存最近 32 帧**全体输入**（每帧 `SimInputFrame[PlayerCount]` + `IsPredicted[PlayerCount]`，每帧独立数组）；容量 = 新常量 `SimConfig.MaxInputHistory = 32` | §5.5；真实输入到达**就地覆盖**并清预测位；32 帧为 M11 重连补发（§5.6）留余量 |
| 6 | **预测策略**（§5.3 表落 M8 输入面）：`MoveX`/`MoveZ`/`AimX`/`AimZ` 沿用上一逻辑帧值；**`Buttons` 不预测**（预测帧置 0——离散事件猜错代价极大） | §5.3；`IsPredicted` 标记进 `InputHistory`，回滚判定只看它。**2026-09-18 对账**：原文写 `Yaw`，随《角色状态与动作实现设计》§7-1 的 Aim 改造已改为 `AimX/AimZ`；实现上**无需改码**——`RollbackSim.PrepareNext` 沿用走的是**整结构拷贝**（`Array.Copy` / `TryGet` 取回整份 `SimInputFrame`），字段增删自动跟随 |
| 7 | **回滚执行器落名 `RollbackSim`**（LiteSim.Core，组合 `FrameDriver` + `SnapshotRing` + `InputHistory`；**`FrameDriver` 保持不动**——M8 已验收件，组合优于修改） | 设计稿机制库未给执行器命名；M11 由 `BattleContext` 组装（§8.3），M10 网络层喂 `OnRealInput` |
| 8 | **单渲染帧回滚上限 2**：超出只处理最早一次，其余留给后续渲染帧 | §5.4 防雪崩 |
| 9 | **回滚自检**：回滚后每帧 `ComputeChecksum` 应与"全程真实输入"直跑序列一致——**逐帧对齐**而非只比终态 | §5.4"绝佳自检"；开发期每帧算（M8 实测 3000 帧全程 checksum 秒级，成本可忽略） |
| 10 | **同运行时红线**：回滚/重放/对账必须与被预测方同运行时；L1 全部 .NET 闭环，Unity 不做验收 | M8 收口批实测：Mono FMA 1-ULP 底噪（快照覆盖兜底、和解率吸收——跨运行时是 M10 观测指标，不是 M9 验收线） |
| 11 | **可变 struct 传参纪律**：`SimRng`/`SimInputFrame[]` 等可变 struct 作参数一律显式 `ref`/`in` | M8 收口批教训（`MakeInputs` 按值传 `SimRng` 冻结输入流）；编码约定入评审清单 |
| 12 | **重放期事件缓冲**：重放每帧后由 `RollbackSim` 清空 `Events`（复用 FrameDriver 的"消费后清"约定）；M9 测试不消费事件，M11 接 `silenceUntilFrame` | §3.7 决策⑥：回滚重放天然正确的前提是事件是帧内瞬态 |

### 2.2 `SnapshotRing`（~120 行）

```csharp
public sealed class SnapshotRing {
    public SnapshotRing(int capacity);                       // 预分配 capacity 个独立 SimWorldState（§11-8：零 new）
    public void Capture(int frame, in SimWorldState s);      // Step 后调用（帧号语义 = 决策 #2）
    public bool TryRestore(int frame, SimWorldState s);      // 环内 CopyTo 恢复；越界 false（决策 #4）

}
```

要点：槽位 `frame % capacity` 覆写；`int[] _frames` 初始 -1；`ContainsFrame` 判 `[最老..最新]` 窗口。

### 2.3 `InputHistory`（~100 行）

```csharp
public sealed class InputHistory {
    public InputHistory(int capacity, int playerCount);                  // 每帧独立数组，预分配
    public void Record(int frame, SimInputFrame[] inputs, bool[] predicted);
    public void Overwrite(int frame, SimInputFrame[] realInputs);       // 真实到达：就地覆盖 + 清预测位
    public bool TryGet(int frame, out SimInputFrame[] inputs, out bool[] predicted);
}
```

### 2.4 机制件用例（~150 行）

环覆写与窗口判定；`TryRestore` 越界 false；**防共享用例**（`Restore` 后改活状态，再 `Restore` 同帧仍逐字节一致——钉死槽位独立实例）；`Overwrite` 覆盖语义与预测位清除。

### 2.5 预测策略 + `RollbackSim`（~250 行）

- `Tick(realDelta, map)`：`FrameDriver` 同款累加器；每逻辑帧 `Capture → 生成预测输入（沿用上一帧，Buttons=0）→ Step → Record(预测)`。
- `OnRealInput(int frame, SimInputFrame[] real)`：`Overwrite` 历史 → 判定（`F < simFrame && 该帧 IsPredicted && 不符`）→ `Restore(F-1)` → `for f = F..lastSimulatedFrame: Step(history[f])`（重放期每帧清 Events，决策 #12）→ `OnRollback?.Invoke(depth)`（M11 View 重对齐接口预留）。
- 越界（决策 #4）：`_halted = true` 停预测前进 + `OverflowCount++`；真实输入追上后恢复续跑（从最新真实帧 `Step` 续）。
- 单渲染帧上限 2（决策 #8）。

## 7. 边界与风险

- **不越界**：不做网络（M10：kcp2k/RoomServer/和解率观测）、不做 View 重对齐（M11：`Realign`/`silenceUntilFrame`/误差衰减——本里程碑只留 `OnRollback` 回调）、不做重连补发（M11，§5.6——`InputHistory` 容量已留足）、不做服务端回溯判定（M10，环已参数化就绪）
- **风险 1：快照槽位实例共享**（M8 风险延续）——环内实例若与活状态同引用，回滚后"状态没退回去且偶发"。**对策**：构造期独立实例 + `CopyTo` 双向 + 防共享用例（改恢复态后再 Restore 同帧仍一致）
- **风险 2：重放期事件缓冲无人清**——重放每帧重新产生帧事件，若不清则 256 容量溢出告警淹没诊断。**对策**：`RollbackSim` 重放每帧后清空（决策 #12）；M9 测试不消费事件
- **风险 3：停预测后的恢复语义**——`_halted` 期间帧号/快照/历史的对齐错误会表现为"恢复后永久偏差"。**对策**：恢复续跑用例与真值直跑对齐
- **风险 4：预测位覆盖遗漏**——真实输入到达未清 `IsPredicted`，会重复触发回滚判定。**对策**：`Overwrite` 原子覆盖 + 重复到达用例（同帧两次 `OnRealInput` 幂等）
- **风险 5：跨运行时误用**——任何"Unity 里重放 .NET 基线"式验收都是错的（M8 实测 FMA 1-ULP 底噪）。**对策**：同运行时红线（决策 #⑩）；跨运行时指标归 M10 和解率观测

**实现期修订（对 §2 施工图的偏差）**：

1. **帧号语义落地**：`SimStep.Step` 末尾 `Frame++` → **帧号 = 已执行步数，"第 k 步消费输入 k"**。据此 `RollbackSim` 构造期把初始状态锚定为帧 0——第 1 步的回滚（`Restore(0)`）天然可用；否则帧前状态不存在、首步错误不可恢复。§5.4 伪码的 `target = F-1` 语义不变。
2. **身份模板入参**：构造器第三参由 `playerCount` 改为 `SimInputFrame[] inputTemplate`（EntityId 必带、控制量零值）——冷启动预测基线。缺此基线时预测 `EntityId=0` 与真实输入**永不相等**，"预测正确→零回滚"场景不可构造（实现期实测发现；M10 客户端本地玩家身份已知，喂法一致）。
3. `MaxRollbacksPerFrame=2` 落 `SimConfig`（§2.1 未列——§11-3 常量集中纪律）。
4. `InputHistory` 增 `IsAnyPredicted` / `Differs` 判定辅助（回滚判定的材料读取，须在 `Overwrite` 覆盖前取）。
5. §2.7 `SimSandbox` 回滚可视化**裁掉**（可选非验收线；M11 `SimView` 的 Realign/silence 覆盖该需求）。

**验收对账（§4 完成判定）**：
