## 1. 决策记录：时机断言与 DI Validate 的删除（2026-09-10）

M1 施工中途用户决策：**删除两套诊断机制，均已从代码与测试中移除**——

1. **注册表填充期/解析期断言**（原设计方案 §2.3 的机制化：LuaRegistryTiming 全局时序 + Fill/Get 阶段断言 + AllowRefill 豁免窗口）。LuaRegistry.cs 回归纯字典语义。
2. **DI `Validate()` 全量预检**（原 M0 指导 §10 要点 5"本件最值的 100 行"，含孤儿注册告警与 `Referenced` 追踪字段）。

**删除后的诊断口径**：错误在 **Resolve 时点当场抛**——未注册（含构造依赖未注册）、循环依赖（报错含 `A → B → C → A` 依赖链）、构造抛异常（解包 TargetInvocationException 报真因）、重复注册（注册期当场抛）。xUnit 用例已全部改写为 Resolve 时点语义，语义覆盖不缩水。

**同步降级的纪律**（机制没了，约定还在）：
- §2.3 填充期/解析期降级为**流程顺序纪律**：ProcedurePreload 尾部填充、ProcedureMain 后解析，靠流程结构保证，无 Debug 断言兜底。M3 DevReload / M6 热更重填不再需要豁免窗口。
- 装配自检降级为 **Resolve 冒烟**：流程装配后对关键服务各 Resolve 一次即等价于原 Validate 的实解析扫描（M2 ProcedureLaunch 落地时如需要，是几行流程代码而非容器机制）。
- **M0 验收线第 2 条（DI Validate 四类问题用例）就此作废**——M0 指导按"不回写旧文档"惯例不改，以本节为准。
