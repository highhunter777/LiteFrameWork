# 模组系统设计（单机 · 按需件 · 永不进 Sim）

> 制订日期：2026-09-15
> 关系：复用《自研框架设计方案》§4.3 服务桥白名单纪律、资源唯一入口；复用《框架实施手册》的 xLua 导出清单与程序集分层；受《状态同步实施方案》Sim 红线约束。
> 一句话定位：**把模组当成"框架上的一个受控数据 / 资源 / 脚本来源"，而不是给游戏打补丁**——用 `Bridge.*` 白名单当沙箱、YooAsset 当资源入口、Luban 当数据层，再补 `ModManifest / ModLoader / ModHost` 三个新件。
> 状态：设计定稿（单机侧）。

---

## 0. 定位与三条硬红线

| # | 红线 | 含义 |
| --- | --- | --- |
| **M1** | **模组永不进 Sim** | 不得读写 `SimWorldState` / `SimRng` / `ComputeChecksum`，不得参与 60Hz 权威步进、回滚重放、`MatchArchive` 归档。模组只作用于 **View 层 + 内容 + 配置表 + 非 Sim 的 Lua 玩法规则** |
| **M2** | **资源唯一入口** | 模组资源必须经框架资源层（YooAsset 额外包 / 注册 Provider）加载，**禁 `Resources.Load`、禁裸 `File.Read`** |
| **M3** | **框架机制不可被改写** | 生命周期、容器（DI）、资源、网络、流程**不开放给模组**；模组只能消费门面，不能注册服务、不能挂钩子改机制 |

> **M1 的红利**：正因为模组进不了 Sim，「种子 + 输入 = 整场」的回放/归档天然对模组**免疫**——同一份归档在任何模组组合下重放结果一致，不需要把模组集合写进协议。

## 1. 能力边界（模组能做什么 / 不能做什么）

| 类型 | 模组能做 | 不能做 | 阶段 |
| --- | --- | --- | --- |
| **A 数据模组** | 覆盖 / 追加 Luban 表（数值、掉落、关卡参数、文案） | 改表结构、改主包表 | 先做 |
| **B 内容模组** | 新贴图 / 模型 / 音效 / 材质 / 新关卡场景 | 绕开资源层加载、注入引擎内部对象 | 第二 |
| **C 逻辑模组** | Lua 新玩法 / 新 UI 行为 / 新系统（走受限门面） | 进 Sim、注册框架服务、绕过白名单、访问文件系统 / 网络 | 最后 |

**明确不做**：改 Sim 数值参与权威判定、替换框架机制、注入原生库、任意文件 / 网络访问。

## 2. 按需件形态（本文核心）

模组系统**不是**主流程的常驻件，三层"按需"：

### 2.1 编译期按需 —— 独立程序集 + `defineConstraints`

```
Assets/LiteMod/                       ← 独立 asmdef，核心不引用它
├── LiteMod.asmdef                    # references: [LiteFramework.Core]
│                                     # defineConstraints: ["LITEMOD_ENABLED"]
├── Scripts/
│   ├── ModManifest.cs / ModLoader.cs / ModHost.cs
│   ├── Content/  ModContentProvider.cs      （数据：Luban 覆盖）
│   ├── Assets/   ModAssetProvider.cs        （资源：YooAsset 额外包）
│   ├── Scripts/  ModScriptSandbox.cs        （逻辑：Lua 沙箱）
│   └── ModApi/   （版本化创作接口面）
└── Editor/        打包器 / 校验器
```

- **不开 `LITEMOD_ENABLED` 宏 → 整个 asmdef 不参与编译**：零代码、零加载、零攻击面。「按需件」的第一层含义。
- 主流程只认一个 **~10 行契约** `IModHost`（`bool Enabled` / `void Boot()` / `void Shutdown()`），实现由 `#if LITEMOD_ENABLED` 条件编译挂在启动点；核心**不依赖**模组程序集（依赖倒置）。

### 2.2 运行期按需 —— 三类能力独立开关

| 开关 | 关掉时 | 打开时 |
| --- | --- | --- |
| 数据模组 | 主表照旧 | 加载模组表并做覆盖合并 |
| 内容模组 | 不注册额外资源包 | 注册 YooAsset 模组包 |
| 逻辑模组 | **不创建 Lua 沙箱、不加载任何模组 Lua** | 起沙箱 + 受限门面 |

只装数据模组的玩家**不付**逻辑沙箱与资源包的代价。

### 2.3 内容按需 —— 惰性加载

模组资源与脚本**用到才加载**：资源走框架异步加载（引用计数 / 卸载复用现成机制）；模组 Lua 按入口声明惰性 `require`，不预载全部模组。

**未启用时的成本清单**：不扫描目录、不解析 manifest、不注册资源包、不建 Lua 环境、不占常驻内存。做到"**装了才付钱，没装是零**"。

## 3. 子系统清单（最小集合）

| 件 | 职责 | 关键点 |
| --- | --- | --- |
| `ModManifest` | 声明：`id / name / version / author / type / entry / dependencies / apiVersion / priority` | `type` 决定走哪条能力通道；`apiVersion` 做兼容判定 |
| `ModLoader` | 发现 → 依赖解析 → 拓扑排序 → 冲突检测 → 按序加载 → **失败隔离** | 同 id 冲突、资源覆盖冲突要报错而非静默 |
| `ModContentProvider` | 数据覆盖层（键级 override 语义） | 主表只读；模组层可叠加，**可整体卸载** |
| `ModAssetProvider` | 注册模组资源包 / 目录 Provider | 接进框架资源唯一入口；卸载时随包释放 |
| `ModScriptSandbox` | Lua 环境 + 受限 `Bridge` 子集 + 执行预算 | 见 §4 |
| `ModApi` | **版本化**创作接口面 + 文档 + 示例模组 | 生态成败点；先开极小面 |
| `ModHost` | 生命周期、错误隔离、日志、启用清单 | 一个 mod 崩 → 定位到具体 mod + 可一键禁用，**不污染存档** |

---

## 4. 沙箱与隔离（逻辑模组）

**复用现成的白名单强制手段**——项目已有"业务 Lua 不出现 `CS.`、未导出类型运行期直接报错（关反射 fallback）"。模组直接用同一套：

1. **门面收窄**：模组 Lua 只能调 `ModApi`（`Bridge.*` 的一个**受控子集**，例如只给 `data / ui / log / event` 四类，**不给** `content` 这种能驱动流程的面）。新增面按《自研框架设计方案》§4.3 白名单纪律登记。
2. **禁危险库**：`io / os / loadfile / dofile / package` 一律不绑；`require` 只能解析模组自身包内路径。
3. **执行预算**：单次调用时间上限 + 每帧调用次数上限，超限即**熔断该 mod**（不是崩游戏）。
4. **错误隔离**：模组回调统一走 `SafeCall`（Core 已有，异常落地 Log 且调用方存活）；崩溃计数达阈值 → 自动禁用并提示。
5. **归属可读**：日志与堆栈必须**归属到具体 mod id**，否则没人愿意写模组。

> **注意单机的风险重定位**：单机没有作弊问题，风险是"**模组把游戏/存档搞崩**"。所以重点全在**稳定性隔离**，不在防作弊。

## 5. 与现有机制的接法（不新造轮子）

| 现有机制 | 模组系统怎么用 |
| --- | --- |
| **xLua + `Bridge.*` 白名单** | 就是沙箱本体：受限门面 + 运行期报错，物理上碰不到引擎内部 |
| **YooAsset 资源唯一入口** | 模组资源注册成额外包，白拿引用计数 / 卸载 / 依赖分析 |
| **Luban 配置表** | 模组表作为**额外来源**叠加到主表之上，不改生成管线与主包 |
| **生命周期归属（《状态同步实施方案》§8）** | 模组对象归 `ModHost` 显式管理，**不经容器**；模组不得注册框架服务 |
| **HybridCLR 热更** | **热更 ≠ 模组**：热更是官方代码更新（红线：禁碰 Sim 与 Net），模组是玩家内容（红线 M1）。二者纪律同源、边界互斥 |
| **MatchArchive / 回放** | 因 M1 而**天然免疫**：不需把模组集合写进归档 |

## 6. 存档与生命周期

- **存档记录模组清单 + 版本**（用于提示"此存档启用了哪些模组"，**不用于校验**）。
- **模组数据与主数据分集合存储**：模组缺失 / 版本不符时，按"**忽略模组字段、降级读取**"处理，**不拒绝加载存档**。
- **模组移除 / 升级**：不删玩家主数据；模组自有数据随模组启停决定去留。
- **启用清单可导出**：便于玩家排障（"关掉哪个 mod 就不崩了"）。

## 7. 工具链（决定模组作者体验，别省）

1. **模组项目模板**（manifest + 目录骨架 + 示例）
2. **打包器**（Editor 菜单：校验 → 打 mod 包 → 产出发布物）
3. **本地调试**：热重载 + 日志按 mod 分文件 + 崩溃归属
4. **校验器**：manifest 合法性、依赖闭环、白名单越界扫描（可复用 M7 的纪律扫描器思路）
5. **文档 + 至少 2 个示例模组**（一个纯数据、一个含 Lua 逻辑）

## 8. 决策记录（2026-09-15 定稿）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | **模组永不进 Sim**（红线 M1） | 保确定性 / 回滚 / 归档重放；回放免疫是白拿的红利 |
| D2 | **模组系统是按需件**：独立 asmdef + `defineConstraints`，默认不编译 | 零攻击面、零常驻成本；"装了才付钱" |
| D3 | **复用 `Bridge` 白名单当沙箱**，不新造脚本沙箱 | 已有强制手段（关反射 fallback + 运行期报错） |
| D4 | **复用 YooAsset 做资源入口**，注册额外包 | 白拿引用计数 / 卸载 / 依赖 |
| D5 | **复用 Luban 做数据层**，模组表叠加不覆盖生成管线 | 主包不受污染，模组层可整体卸载 |
| D6 | **API 先开极小面**（四类门面），版本化后扩 | 公开即背兼容债 |
| D7 | 模组对象**不经容器**管理，归 `ModHost` | 与框架"流程创建销毁、不经容器"的既有纪律一致 |
| D8 | 单机风险重定位为**稳定性隔离**，不设反作弊 | 单机无作弊面 |

## 9. 落地顺序（递增，每步可独立交付）

| 步 | 内容 | 前置 |
| --- | --- | --- |
| **1** | 数据模组：`ModManifest` + `ModLoader` + `ModContentProvider`（零安全风险，最快见效） | 无 |
| **2** | 内容模组：`ModAssetProvider` 接进 YooAsset | 1 |
| **3** | 工具链：模板 + 打包器 + 调试（**决定生态成败**） | 1–2 |
| **4** | 逻辑模组：Lua 沙箱 + 受限 `Bridge` 子集 + `ModApi` 版本化 | 3 |
| **5** | 分发（工坊 / 订阅 / 版本管理） | 4 |

## 10. 风险与边界

1. **API 兼容债**：门面一旦公开就要维护——先小面、后扩，宁可晚开不可乱开。
2. **性能**：模组逻辑禁入每帧热路径；只允许"事件点 / 低频"介入（并与 §4-3 的执行预算配套）。
3. **不要把模组做成热更**：热更管线（HybridCLR）覆盖官方代码，模组是玩家内容——混用会让"禁碰 Sim/Net"的纪律失效。
4. **不预做**：分发平台、模组市场、依赖版本求解器（semver 范围）都不在首版。
5. **调试体验是生态生死线**：没有"崩了能定位到哪个 mod + 一键禁用"，就没有人写第二个模组。
