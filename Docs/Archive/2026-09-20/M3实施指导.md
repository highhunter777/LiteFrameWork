## 1. 前置决策（开工前定案）

### 1a. Lua 收集方案（**定案，2026-09-10：自定义 `IIgnoreRule`**）

`.lua` 是 Unity DefaultAsset，被包级 `NormalIgnoreRule` 拒绝收集（M2 实测："Default asset cannot be packed"）。**定案：自定义 `IIgnoreRule`（~15 行）**——按路径放行：仅 `/LiteGame/Lua/` 下的 DefaultAsset 允许收集，其余沿用 `DefaultAssetIgnoreRule` 全部逻辑；包级 `IgnoreRuleName` 切换为它。**不改后缀**，保持 §4.4 目录约定（main.lua/UIMain.lua）不动。影响面核对：其余收集目录（Config=.bytes、Scenes=.unity、GameMain/Configs）无 DefaultAsset，放行无副作用——实施时复核一遍各收集目录。

### 1b. 预载清单来源：tag 枚举 vs 目录枚举

手册 §4.2 定死"收集器打 tag `lua` → `GetAssetInfosByTag` 枚举"。**M2 教训：YooAsset 3.0.5 模拟模式 API 与文档有出入**（RawFileObject 事件），tag 枚举在 EditorSimulateMode 下的实际 API 需实测——fallback 是经收集清单按 CollectPath 枚举。**先实测 tag 路径，不通再用 fallback，两条路都只写一处**（`LuaPreloader` 内部）。

### 1c. LuaKeys 生成（**定案，2026-09-10：做生成**——用户推翻"推迟手写"建议）

注册表 Lua路径 → **`LuaKeys.g.cs` 生成常量**，纳入 M3 交付。设计方案 §277"已落地先例"由本里程碑兑现。

**生成方案**：
- **来源**：注册表三件套 xlsx（TbUIForm/TbContentEntry/TbStrategy）的 `Lua路径` 列
- **工具**：`Luban/gen_lua_keys.py`（openpyxl，按 Luban 表头约定定位字段名行；无该列/空表跳过）
- **接线**：`gen.bat` 追加第三步（bat 注释 ASCII 纪律不变）
- **产物**：`Assets/LiteGame/Scripts/Runtime/Bridge/Generated/LuaKeys.g.cs`（namespace `LiteGame`，归属 LiteGame.Runtime 程序集；文件头标 `// generated`）

```csharp
// 生成形态（按根分段，段内按名字排序，幂等覆盖）：
public static class LuaKeys
{
    public static class UI         { public const string UIMain = "UI.UIMain"; }
    public static class Content    { /* …行驱动… */ }
    public static class Strategies { /* …行驱动… */ }
}
```

- **约束**：路径约定两段式（`根.名字`，§4.4 三个固定根）——未知根 **生成器直接抛**（fail the build，不静默落平铺）；重名即抛；**排序输出保证 diff 干净**
- **消费点**：RegistryFiller（填充与校验）、事件桥映射表、DevReload 校验——**禁止散落字符串路径**（收口模式判据，设计方案 §277）
- 编码 UTF-8；生成物入库（与 Luban 产物同策略）

### 1d. cfg/*.lua 不消费（重申）

`Bridge.data` 内部把 C# 强类型行转 LuaTable（xLua 生成代码），Lua **不触碰 Luban 类型**（`Luban.Tables` 不进白名单）；Luban 的 lua 输出维持"生成备用"。

- **asmdef 已就位**（核对实证：vendor 自带 `Src/xLua.asmdef`，其 `"name"` 字段已是 **`xLuaMain`**——文件名旧、程序集名对，LiteGame.Runtime 的引用早已咬合；名字避开原生 `xlua.dll` 的纪律满足）。新增 `Src/Editor/xLuaMain.Editor.asmdef`（Editor-only，引用 xLuaMain）——把生成器（5 个 cs）从运行时程序集剥离

### 2.2 Lua 全量预载（手册步骤 3）——**代码交付，Play 验证因 Unity 重导入未完成（待续）**

- 收集组 `LiteGameLua`（CollectPath: Assets/LiteGame/Lua，PackDirectory + 1a 的 ignore rule）+ 收集器 **`AssetTags: lua`（字符串字段，分号分隔——写成 YAML 序列反序列化必空，实测坑）**
- `LuaPreloader`（业务件，`Runtime/Lua/LuaPreloader.cs`）：Preload 锚点处全量 `LoadRawFileBytesAsync` → `Dictionary<string, byte[]>`（key = require 路径，如 `ui/UIMain`）；DevReload 重入 = 先 Clear
- **loader 是同步签名，任何"运行时再异步加载"的念头都是错的**——一切靠启动期预载；未命中 = 校验漏项直接抛（带路径）
- **本轮实证的三个坑（均已修复/落位）**：
  1. **清单 API**：3.0.5 无 `GetAssetInfosByTag`、无目录枚举——`GetAssetInfos(string)` 即 **tag 查询重载**（§1b fallback 路线不存在，tag 是唯一清单来源）
  2. **`.lua` 是 DefaultAsset**：`LoadAssetAsync<TextAsset>` 恒 null → 新增 `LuaTextAssetImporter`（ScriptedImporter，把 .lua 主对象声明为 TextAsset，EditorSimulateMode 与真机形态一致）
  3. **空文件 = 构建失败**：`main.lua` 曾为 0 字节 → PackDirectory 包体积为零 → `ErrorCode403 Bundle temporary size is zero` → 整个模拟构建失败停机。**Lua 目录禁止空文件**（已写入真实 main.lua）
- 待验证：Play 下 `LuaPreloader.PreloadAllAsync` 的 count/keys（ScriptedImporter 触发全工程 .lua 重导入期间 MCP 会话掉线，未完成）
