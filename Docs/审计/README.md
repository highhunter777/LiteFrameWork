# 审计流程（客户端 / 服务端通用）

> **定位**：存量质量债的**登记**与**归档**规则。回答三件事：问题在哪、修没修、修完的一行摘要放哪。
> **不做的事**：不记录施工过程（进度归 `Docs/施工进度/`）；不保留修复取证细节（取证在提交、测试与进度卷）。
> **冲突裁决**：与 [修改指南](../修改指南.md) §2 冲突时，验证/回写纪律以修改指南为准；本文件只管审计台账的形态与落点。
> **迁移状态（2026-10-27）**：客户端已按本流程拆分（登记 8 类型 + 归档 8 类型）；服务端 `登记/` 已启用——**2026-10-27 起新登记按八类直接落 `服务端/登记/`**（首批＝模块化审阅批 27 条），[旧单体表](代码质量审计-服务端.md) 存量条目继续有效、整体迁移归 [服务端批次计划](服务端/批次计划.md) 的 S1 迁移批。
> **迁移基线**：客户端此前单体表的**未结清条目已全部迁入** `客户端/登记/`；已修复的明细按"一行一条"收拢进 `客户端/归档/`（长论证不再搬运，取证留在 git 历史与施工进度）。此后逐批追加。

## 1. 目录与文件

```
Docs/审计/
├── README.md                 # 本文件（流程权威）
├── 客户端/
│   ├── 批次计划.md            # 路线图驱动条目池（A4–A10 独立批 + M0–M3 阶段施工批，只排范围/退出条件，不登记条目）
│   ├── 登记/<类型>.md         # 只放未结清条目（一类型一文件）
│   └── 归档/<类型>-01.md      # 已修复条目的摘要（一行一条；满 100 条开 -02）
└── 服务端/
    ├── 批次计划.md            # S1–S8 修复编排（只排范围/退出条件，不登记条目）
    ├── 登记/<类型>.md
    └── 归档/<类型>-01.md
```

**一个类型一个文件**：新增问题只进对应类型的登记文件，不再新建"综合表"。类型之间不合并、不新增子类型；确实不属八类时归 `技术债`。

## 2. 八种类型（判据）

| 类型 | 判据（问题是什么） | 典型 |
|---|---|---|
| 硬编码 | 魔法数字/字符串、缺省值、路径约定写死在代码里；应有配置/常量/表 | 池上限、超时、默认动效时长 |
| 重复实现 | 同一逻辑两份以上（复制、镜像、手抄），改一处漏一处 | FSM 双内核、字段清单手抄 |
| 技术债 | 死代码、未接线、临时诊断、半成品、测试专用 API 混生产 | 零消费者服务、`[Diag]` 哨位 |
| 不统一路径 | 同一件事两种以上做法/契约并存 | 关闭语义三种、计时三种轨 |
| 类设计 | 职责过载、状态口袋、公开可变字段、边界/端口缺失、耦合 | god class、public 字段状态袋 |
| 功能缺口 | 明确该有而缺的能力/入口（未实现，不是"坏了"） | 无退出入口、昵称为占位 |
| 文档债 | 文档与代码不符、索引/死链/权威分裂 | 符号名过时、三处默认值 |
| 工具链 | 编辑器/生成器/门禁/管线自身的缺陷（含工具写盘与预览） | 契约 fail-open、生成器覆盖手写 |

## 3. 登记规则

1. **只登未结清**。修好即从登记**删除该行**，不保留"已修复"批注——归档里有摘要。
2. 每条一行起：`- [严重度] \`file:line\` — 问题。修法：……`。够定位、够复现即可；不写长论证。
3. 严重度用 `高/中/低` 三档，只作排序参考，不绑定批次。
4. **悬空设计路线的条目直接删除**（见 §5）。

## 4. 归档规则

1. 一行一条：`- 问题 → 修法（批次/提交）`。**不保留**堆栈、完整判定过程、逐文件清单。
2. **每个归档文件最多 100 条记录**；满则新建 `<类型>-02.md`、`-03.md`……编号递增，不合并、不改名。
3. 序号文件内记录数写在头部元数据（`记录：N/100`）。
4. 状态只由 git 事实回填：`已提交 <hash>` 或 `工作区未提交`；**禁"待提交"**。
5. 归档是历史事实，不回改；后批修正前批时，在归档追加新行，不改旧行。

## 5. 删除判据（抛弃的设计路线）

满足任一即**直接删除**条目，**不进归档**：
- 设计文档已归档/被取代，且功能面已退役；
- 代码已整体删除（整文件/整程序集）；
- 用户已裁决放弃该路线。

批次记录里写一行：`删除 N 条（路线废弃：<路线名>）`，便于审计追溯。

## 6. 每批怎么走

> 分批编排与批次状态见 [客户端批次计划](客户端/批次计划.md)（A1/A2/A3 完成；M0/M1/M2 已完成，M3 进行中（M3-0/M3-1 完成）；v2 起按 [架构重构演进路线图](../设计文档/架构/客户端架构重构演进路线图.md) 驱动——A4–A10 独立批 + M0–M3 阶段施工批；A2 遗留按 2026-10-27 裁决跳过）与 [服务端批次计划](服务端/批次计划.md)（S1–S8 待开工；S7 含 1 项待裁决）。

1. **动手前查**：按要改的文件名 grep `登记/`，命中即顺手修小债；新代码禁止产生同型问题。
2. **修**：同批把修好的条目从登记删除。
3. **归档**：在对应 `归档/<类型>-0N.md` 追加一行（问题 → 修法/批次）；满 100 条先开新文件。
4. **新登记**：过程中发现的新问题，按八类落到对应登记文件。
5. **门禁**：
   - `python scripts/gate/test.py --suite Doc`（D4 链接 / D2 状态 / D8 归档上限）
   - `python scripts/gate/doc-lint.py`

## 7. 门禁说明

| 规则 | 拦什么 |
|---|---|
| D2 | 审计文件出现未按 git 事实回填的「待提交」状态（须写「已提交 hash」或「工作区未提交」） |
| D4 | 登记/归档/索引里的相对链接或锚失效 |
| D8 | 任一归档文件记录数 > 100（必须先开新编号文件） |

> 审计目录的**索引**：`Docs/README.md` 的"质量登记表"行指向 `Docs/审计/README.md`；各类型文件不再单独进索引（避免每加一类就改索引）。
