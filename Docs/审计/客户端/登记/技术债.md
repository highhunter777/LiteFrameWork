## TakeContainer 消费清单

`GameEntry.TakeContainer()` 是**唯一**允许从外部取"已装配根容器"的口（容器语义不进业务流程）。消费面封闭，新增一行即等于放行一处运行期服务定位——须在评审里说明它为什么不是流程代码：

| 消费点 | 性质 | 说明 |
|---|---|---|
| `LiteGame/Editor/Gm/GMEditorResolve.cs` | 编辑器工具 | GM 工具箱页件的运行态取件单源 |
| `Assets/Tests/UI/PlayMode/BattleSmokePlayModeTests.cs` | PlayMode 冒烟 | 流程机/工厂/服务观测（A12）——测试面允许 |

约束：**产品运行期与流程阶段不得调用**（`Modules/**` 的段与阶段只消费构造注入的能力）；`GameEntry` 的 XML 注释与本表同源维护。

## 机制缺口 / 半成品

- [中] Assets/LiteGame/Modules/Meta/Client/Account/AccountDomain.cs — Account 服务域当前只登记 IMetaAccountSession；Profile/RemoteConfig 尚无实现（待接线，批次 B2-ACCOUNT-PROFILE）。修法：实现后登记进 Account 服务域并补生命周期用例。
- [高] `LiteFramework/Runtime/Adapters/Unity/App/AppLifetime.cs:68-83,98-109` — 退出/销毁用 `Thread.Sleep(1)` 循环等 UniTask 关闭；主线程被阻塞，UniTask 续体无法推进，异步关闭/刷新钩子必空转满 3s。`LiteFramework/Runtime/Modules/Hosting/ClientHost.cs:191-204` — `ShutdownAsync` 收到取消令牌即抛 OCE 并置 `_state=4`，跳过 `DisposeRoot`，且 `_shutdownRequested` 使后续调用直接返回。修法：关闭链改可泵的协程/UniTask 等待；无论令牌是否取消都进 `finally` 释放根 Scope；补取消路径用例。
- [中] `LiteGame/Modules/Composition/ContentSegment.cs:102-112` — `PlayerCapabilities` 五项版本全 0、AppVersion/Channel 为空，而 `LiteFramework/Runtime/Modules/Content/Abstractions/ReleaseManifestValidator.cs:217-231` 仍逐轴比较；兼容检查实际半关闭，任何非 0 下限清单会被拒。修法：由 `BuildIdentity` 生成真实能力，或显式 `CompatibilityMode.Off` 并加“现有清单接受/拒绝结果不变”对照测试。
- [中] `LiteFramework/Runtime/Core/Logging/Log.cs:35-37,150-162` — 静态环形缓冲 `_ring/_start/_count` 无锁；`LiteGame/Modules/Battle/BattleContext.cs:191` 订阅 `Application.logMessageReceivedThreaded` 后经 `LiteFramework/Runtime/Modules/Diagnostics/ClientDiagnosticsBundle.cs:49-52` 读 `Log.Recent`，与主线程写入并发。修法：加锁/原子快照，或回调只投递到主线程后再取日志。
- [低] `LiteGame/Editor/UITools/Widgets/UIWidgetManifestGenerator.cs` — WidgetSpec 只校验结构，"声明状态/尺寸与实现不匹配"无机制。2026-10-27 探测：30 个模板根均无 LayoutElement/ContentSizeFitter/LayoutGroup，SizeBehavior 是"放置意图"而非模板内实现；模板级机械校验会误报 19/30，须先裁布局契约或改在页面使用点校验。
- [低] `Assets/ThirdParty/Plugins/Android/AndroidManifest.xml` — 本清单是**手写还原** Unity 默认主清单（**该版本安装目录内无 AndroidManifest.xml 模板文件可对照**，`PlaybackEngines/AndroidPlayer` 全树 0 命中）：activity 的 `configChanges`/`launchMode`/`hardwareAccelerated` 等与引擎实际生成值的偏差没有任何机制会报，只在真机行为（旋转重建 Activity、返回键、启动模式）上暴露。修法：T8 首包后从 `Temp/StagingArea/AndroidManifest.xml`（脚本用 manifest，非合并结果）取引擎生成版本与本文件逐项对账，把差异收敛回本文件。
- [中] `LiteGame/Modules/UI/Pages/Screens/Hub/Page_LobbyLogic.cs:309-314` — 大厅气泡 `Tap` 先算 `_line = _line % _lines.Count + 1` 再索引 `_lines[_line]`：三条文本时第三次点击得到 `_line == Count`，直接越界。与进房/离房链路无关，本批不修。修法：改为 `_line = (_line + 1) % _lines.Count`，并补三击/页面池化重入用例。
