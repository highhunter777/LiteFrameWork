## 机制缺口 / 半成品

- [高] `LiteFramework/Runtime/Adapters/Unity/App/AppLifetime.cs:68-83,98-109` — 退出/销毁用 `Thread.Sleep(1)` 循环等 UniTask 关闭；主线程被阻塞，UniTask 续体无法推进，异步关闭/刷新钩子必空转满 3s。`LiteFramework/Runtime/Modules/Hosting/ClientHost.cs:191-204` — `ShutdownAsync` 收到取消令牌即抛 OCE 并置 `_state=4`，跳过 `DisposeRoot`，且 `_shutdownRequested` 使后续调用直接返回。修法：关闭链改可泵的协程/UniTask 等待；无论令牌是否取消都进 `finally` 释放根 Scope；补取消路径用例。
- [中] `LiteGame/Modules/Framework/ContentComposition.cs:102-112` — `PlayerCapabilities` 五项版本全 0、AppVersion/Channel 为空，而 `LiteFramework/Runtime/Modules/Content/Abstractions/ReleaseManifestValidator.cs:217-231` 仍逐轴比较；兼容检查实际半关闭，任何非 0 下限清单会被拒。修法：由 `BuildIdentity` 生成真实能力，或显式 `CompatibilityMode.Off` 并加“现有清单接受/拒绝结果不变”对照测试。
- [中] `LiteFramework/Runtime/Core/Logging/Log.cs:35-37,150-162` — 静态环形缓冲 `_ring/_start/_count` 无锁；`LiteGame/Modules/Battle/BattleContext.cs:174` 订阅 `Application.logMessageReceivedThreaded` 后经 `LiteFramework/Runtime/Modules/Diagnostics/ClientDiagnosticsBundle.cs:49-52` 读 `Log.Recent`，与主线程写入并发。修法：加锁/原子快照，或回调只投递到主线程后再取日志。
- [低] `LiteGame/Editor/UiTools/Widgets/UiWidgetManifestGenerator.cs` — WidgetSpec 只校验结构，"声明状态/尺寸与实现不匹配"无机制。2026-10-27 探测：30 个模板根均无 LayoutElement/ContentSizeFitter/LayoutGroup，SizeBehavior 是"放置意图"而非模板内实现；模板级机械校验会误报 19/30，须先裁布局契约或改在页面使用点校验。
- [低] `Assets/Plugins/Android/AndroidManifest.xml` — 本清单是**手写还原** Unity 默认主清单（**该版本安装目录内无 AndroidManifest.xml 模板文件可对照**，`PlaybackEngines/AndroidPlayer` 全树 0 命中）：activity 的 `configChanges`/`launchMode`/`hardwareAccelerated` 等与引擎实际生成值的偏差没有任何机制会报，只在真机行为（旋转重建 Activity、返回键、启动模式）上暴露。修法：T8 首包后从 `Temp/StagingArea/AndroidManifest.xml`（脚本用 manifest，非合并结果）取引擎生成版本与本文件逐项对账，把差异收敛回本文件。

## 架构边界

- [中] `LiteGame/App/UiServiceModule.cs`、`LiteGame/App/ProcedureComposition.cs` — 两个装配段仍住 `App/` 而非 `Modules/**`（批 4 A15 的"18 段全住 Modules"未达成）：两段都要用 `Adapters.LuaBridge` 的注册表件（`RegistryFiller`/`UiLuaRegistry`/`LuaBehaviourAdapter`），业务模块程序集不得引适配器。批 5 已把其余 16 段就地归位；修法＝把注册表装订面下沉为端口/独立程序集后再迁，迁时同步 `DomainBoundaryTests`/`ModuleDependencyDeclTests` 扫描面与 `ClientAsmdefAllowlistTests`。
- [中] `LiteFramework/Runtime/Modules/Content/ContentHealthProbes.cs:85`、`LiteFramework/Runtime/Modules/Content/TrustedKeyStore.cs:61` — **全限定名**直接使用 `Newtonsoft.Json.Linq`（`JToken.Parse` / `JObject.Parse`），绕过 `IJsonSerializer`/`IJsonCodec` 端口；且 R12 正则只匹配 `using` 行，故扫描不报（同批已把 `Newtonsoft` 纳入 R12 边界表，但这两处属于规则盲区内的现存实例）。修法：改走 `IJsonCodec`（结构判定/字段读取）或 `IJsonSerializer`，把 Newtonsoft 收敛回 `Adapters/Newtonsoft/`；修好后顺带评估 R12 是否要覆盖全限定名（见工具链登记）。
