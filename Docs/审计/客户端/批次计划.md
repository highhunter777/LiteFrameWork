## 1. 编排原则

- **批次按“共享根因 / 同验证面”切**，类型只是归档维度：同一批可以跨类型，但必须有同一个收口判据。
- **每批独立可收口**：Unity 重编译 0 错 + L1 + 定向 EditMode（涉及 UI/资产时）+ doc-lint；动到构建闭包再加 gen-build-hash。
- **先清死代码，再拆结构，再去重**：避免给即将删除的能力做拆分/去重。
- **A2 遗留先跳过（2026-10-27 用户裁决）**：框架无消费者面（ClientErrorRecovery / CollectionPool 门面 / ConfigSnapshotPublishExtensions / EventCenter 队列与拦截器）不排；依赖它的 CommandCenter 类设计拆分、CommandCenter Send/SendAsync 去重、EventCenter 队列/拦截器统一同步不排。
- **完工回填**：本表只改“状态”列；证据写 [客户端审计线](../../施工进度/客户端审计线.md) 新章；修好的登记条目删除、对应归档追加一行。
