## 1. 编排原则

- **批次按“共享根因 / 同验证面”切**，类型只是归档维度：同一批可以跨类型，但必须有同一个收口判据。
- **每批独立可收口**：Unity 重编译 0 错 + L1 + 定向 EditMode（涉及 UI/资产时）+ doc-lint；动到构建闭包再加 gen-build-hash。
- **先清死代码，再拆结构，再去重**：避免给即将删除的能力做拆分/去重。
- **路线图驱动（v2）**：登记条目两类去处——
  1. **阶段施工批**：修法本身就是路线图机制（六接缝/不变量/目标形态）的条目，随 M0～M3 施工一并收口；销账走同一套“删登记行 + 归档一行 + 审计线一章”。
  2. **独立 A 批**：不依赖阶段的条目，可穿插开工；与 M 阶段**不并行开工同一文件**（路线图 §5），撞期时 A 批让路。
- **顺带边界**：只有“同一文件 + 同一根因 + 同一验证面”才能顺带修；跨批顺带破坏“每件独立提交可回退”。
- **路线图 §7 是硬前置**：所有权/作用域/协调统一前不新开 `RoomClient`/`UIService`/`BattleContext` 拆分（三件自 A4 移入 M2）；`UiApiSpec` 单源自 A7 移入 M3（制品收敛），不做会被 `PageDefinition` 覆盖的临时去重。
- **A2 遗留（2026-10-27 用户裁决先跳过；M3-7 起按路线图 §4.5 收口）**：框架无消费者面——`ClientErrorRecovery` 旧骨架已删（前批）、`CollectionPool` 三静态门面与 `ConfigSnapshotPublishExtensions` 已删（M3-7 §4.5 首刀）；`EventBus` 队列与拦截器、`CommandCenter` 拦截器仍待裁（下一刀）。
- **完工回填**：本表只改“状态”列；证据写 [客户端审计线](../../施工进度/客户端审计线.md) 新章；修好的登记条目删除、对应归档追加一行。
