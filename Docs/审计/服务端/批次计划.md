## 1. 编排原则

- **批次按“共享根因 / 同验证面”切**，类型只是归档维度：同一批可以跨类型，但必须有同一个收口判据。
- **每批独立可收口**：服务端构建 0 错 + L1 + 定向（LiteNet.Tests / MetaServer.Tests）；触 Meta 端点/持久化/结算/分配链加 L3（真 Mongo）；动 `Assets/RoomServer`、`Assets/LiteGame/DevLocalServer` 加 Unity 重编译 0 错；动共享源集/源链接件加 `gen-build-hash.py --check`；文档批跑 Doc 套件。
- **先清死代码，再拆结构，再去重**：避免给即将删除的能力做拆分/去重。
- **迁移先行**：旧单体表仍是服务端存量条目的合法登记面（代码 33 行 + 文档 12 行）。S1 完成前，本文件 §4 只给范围，不把旧表字面当逐条清单；S1 迁移时逐条复核——已发现若干“零调用”前提失效（如 `HasTemplate` 现有生产调用、`RoomInstance` 构造有 2 个生产调用），不得照旧表字面直接删。
- **不排项封闭**：归属已定的（`HostLog` area 词表归 R4）、设计已接受的（三套席位表示、`ServerTableLoader`→`LiteFramework`）不排；需裁决的（旧 journal 无账号条目）在 S7 内单列，不混入“跳过”。
- **完工回填**：本表只改“状态”列；证据写 [服务端审计线](../../施工进度/服务端审计线.md) 新章；修好的登记条目删除、对应归档追加一行。
