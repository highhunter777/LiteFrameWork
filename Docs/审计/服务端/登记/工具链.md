# 登记：工具链（服务端）

> 更新：2026-11-11　范围：服务端生成器/门禁/管线（`scripts/` 内服务端相关件）
> 规则：只登未结清条目；修好后**不删行**，在该行标注状态与理由（[规范 07](../../../规范/07-审计与债登记.md) §3.1），并在 `../归档/工具链-01.md`（首修时创建）追加一行。格式见 [审计流程](../../../规范/07-审计与债登记.md)。

- [中] `scripts/codegen/toolbox.py build-hash`（内部 `gen-build-hash.py` 的 `collect()`） — `collect()` 对 `META_EXTRA_FILES`/`SHARED_LINK_FILES` 中**不存在的文件静默跳过**（`if os.path.isfile` 为假即丢弃）：登记条目路径漂移或源文件搬走时生成器不报错、源集静默缩水（hash 变一次后稳定，无人察觉少算一件）。修法：文件缺失 fail-fast 报错，与「csproj 每加一条出树链接必须同批登记」规则配成双向机制。**实证（2026-11-11）**：`gen-build-hash.py:106` 的 `META_EXTRA_FILES` 仍登记 `Assets/LiteGame/Modules/Meta/WireSubModule/Join/JoinTicketInfo.cs`，实际在 `Assets/LiteGame/Modules/Meta/Abstractions/Room/JoinTicketInfo.cs`（`WireSubModule/Join/` 下只剩 `JoinTicketRequest.cs`）；`toolbox.py build-hash --check` 仍报 meta `f695a07d…`（61 files）全绿、无告警，而 `toolbox.py doctor` 已在该地址报 `input MISSING`（4 条 path problem 之一）——doctor 有信号、build-hash 不消费。后果：这个与服务器共享的 wire DTO 改动**不改变 Meta 构建身份**（Meta 常量只进启动日志、不进 Join 准入，故不阻塞准入）。修法：路径改指 `Abstractions/Room/JoinTicketInfo.cs` → 重跑 `toolbox.py build-hash` → `--check` 复核（meta 源集应回到 62 files）；并把「登记文件不存在即 fail」落进 `collect()`（与 doctor 的 declared-path 校验共用同一份清单），让两处口径不再分叉。
- [中] `Assets/LiteGame/Modules/Config/Table/MapTableProjection.cs` 是两端**出树共编件**（`Server/RoomServer/RoomServer.csproj:40` 的 `<Compile Include>`），但**未登记进 `scripts/codegen/gen-build-hash.py` 的 `SHARED_LINK_FILES`**（该表只有 `SimConfigMapper.cs` / `BattleStrategyTableReader.cs` / `TableLayout.cs` 三条）。后果：改地图→表的投影逻辑，两端 `BuildHash` 都不变，可在握手通过的前提下静默分叉。`Docs/说明/17-全项目数据流.md:204` 早已记为缺口，但一直未修。修法：`SHARED_LINK_FILES` 增一条 + 跑 `build-hash`（shared 常量会变，**需两端同批发布**）+ 更新 `说明/17:205` 的当前握手哈希值。
- [低] **MetaWire 类型清单与两份 csproj 出树链接清单没有守卫校验** — `namespace MetaWire`（17 个类型）的边界目前由三个手维护清单共同描述：`Server/MetaServer/MetaServer.csproj`(17 条)、`Server/RoomServer/RoomServer.csproj`(16 条)、`scripts/codegen/gen-build-hash.py` 的 `META_EXTRA_FILES`(17 条)。三者靠人保持一致，且 `collect()` 的 fail-fast 只校验**清单里写的文件存在**，不校验**csproj 里新增的出树链接是否同步进了清单**。后果：新增一个 MetaWire 文件并加进 csproj 但忘记加 META_EXTRA_FILES，Meta 构建身份会少算它，而两个 csproj 都能正常编译（不报错）。修法：加一条测试/守卫，断言「`META_EXTRA_FILES` 的 MetaWire 子集 == 两份 csproj 的对应出树链接集」。（2026-11-11 裁决保留 MetaWire 扁平命名空间时一并登记，作为「搬动前先补守卫」的前置项。）
