## 5. 发现与处置

### F1（真缺陷·本批已修复）：确认写盘失败时 ProcedurePatch 未达确定错误态

- **复现**（M8）：`Confirm` 的 `File.Replace` 抛 `UnauthorizedAccessException` → `ProcedurePatch` catch 内 `_activations.RecordFailure(...)` **二次写盘同败并抛出** → 异常逃逸 catch → UniTask 未观测异常落日志、FSM 卡在 Patch，**45s 无 `[BootstrapError]`、无错误 UI**。违反类注释自述契约"失败 = RecordFailure + Error 流程（确定错误态）"与 G1 退出条件"启动中断可进入确定错误态"。
- **物证**：遗留 `activation.json.tmp`（内含 catch 曾尝试留档的 `LastFailure="Patch 阶段失败：Access to the path is denied."` seq=30）；Player.log `UnauthorizedAccessException` 经 `UniTaskScheduler.PublishUnobservedTaskException` 落日志。
- **修复**（最小面）：`ProcedurePatch.RunAsyncCore` catch 内对 `RecordFailure` 包 try/catch——留档自身失败仅落错误日志（`内容失败留档未落盘：…`），原始失败仍走 `Fail` + Error 流程。上游各写点（PatchRunner/编排器）的写盘失败统一被此 catch 收口。
- **验证**：Unity recompile **0 错误**（pipeline `recompile_status`: completed/failed=false）；Player 重建（IL2CPP，`GameAssembly.dll @ 14:31`）；**同款注入复跑 M8R**——`[BootstrapError]` 可达、二次失败有日志、记录保持未确认；L1 门禁（纪律扫描/BuildHash 守卫）随批核证（数字见 §7）。

### F2（登记·待拍板）：候选根残留无法自愈——修复依赖"修复缓存"入口未建

- **形态一**（M3b）：同长篡改的坏字节**先落盘后校验**（FetchOneAsync 提交在 Verify 之前——§7"完成后全文件校验"的既定次序），而幂等跳过只看长度 → CDN 已修复、本地坏件留存 → **重跑永远 DigestMismatch**，直到手工删除本地件（M3c 证明清场即愈）。
- **形态二**（M6a-pre）：换发布（文件集变化）时，候选根残留旧发布文件 → `UnexpectedFile` 拒绝 → 新发布无法验签通过，需先清场。
- **定性**：非校验失效（fail-closed 全部正确——坏内容被拒、Confirmed 不动）；缺的是**修复路径**：§12 错误类别表"候选损坏 → 隔离该候选、保留旧版本、**按策略修复**"与总设计 §7.2 ErrorRecovery 的"**修复缓存**"动作均已有设计占位、未接线。候选根清场/坏件隔离策略（如 Verifying 失败时删除失配文件、或换发布时按清单清根）属设计裁决，随 G3 ErrorRecovery 接线批实施，不在本批硬改。
- **风险面**：生产上 CDN 修复后客户端无法自动恢复（反复 Verify 失败进错误态），需要用户清数据或等待"修复缓存"入口。

### F3（观察·不构成缺口）

1. **成功确认后 `.tmp` 空目录树残留**：成功路径不调清理（`CleanupTempAsync` 只在恢复/失败收尾两处），空目录树无害——与 §8 行 5"延后清理无引用目录"同语义。
2. **恢复尝试计数跨事务累计**：`RecoveryAttempts` 不随 Confirm 归零——累计超限后每次带在途的恢复都走"超限"分支；行为等价（放弃在途、以 Confirmed 继续、不阻断新候选），仅 LastFailure 措辞不同。是否按事务归零属可选优化。
3. **超限分支/恢复的诊断依赖 DiagSink**：生产组合根未接线 `IDiagRecordSink`（`DiagTrace` 适配一行未接）——超限消息只能经记录字段短暂可见，与「可诊断」批登记的"内容/事务面生产组合根接线随 L2 核证批"是同一遗留。
4. **传输中途断网无增量落盘可观察**：FetchOneAsync 全内存缓冲（整文件下载后才写盘），故"杀进程/断网于传输中"不留半截临时件——`.tmp` 的半截形态只在"下载完成→提交前"的极窄窗口存在。§7 断点续传（Range 续取）落地后此观察点才会展开。
