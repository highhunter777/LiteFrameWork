## 发现与处置

| # | 级别 | 发现 | 处置 |
| --- | --- | --- | --- |
| ① | 高 | **Worker 执行形态·在途 Join 断线 → 孤儿席位永久泄漏**：`ApplyWorkerOutput` 的 PlayerAdmitted 特判不查 `Disconnected`——Join 已由 Worker 执行、PlayerAdmitted 在 Outbound lane 未应用时传输断线，会话 `RoomId` 尚未绑定 ⇒ 断线命令无处路由，回传照常落席 ⇒ 席位永无 Disconnect（Runtime 视为在线）：未开局房永驻、`Running` 全员离场收尾失效。宿主 owner 延迟形态无此洞（`IsCurrentEnvelope` 查 `!Disconnected`） | **已修**：断线会话并入迟到 Join 分支（`ApplyStaleWorkerJoin` 释放席位 + 回滚动态预留 + 清 `JoinPending/Principal/BuildHash`）。红证：新用例 `Worker执行_在途Join遇断线_孤儿席位释放_房间收尾销毁` 修前 8s 超时不销毁 |
| ② | 中 | **owner 位迁移相位盲区 → 未开局死局**：`TransferOwner` 无视相位转最低号，未开局断线席位不可恢复（App 重连要求已开局）⇒ 在座玩家永远无法开局。"任何相位也转"的注释理由只对 Running 成立 | **已修**：两轮遍历——在线席位（Active/Restoring）优先、全断线退回最低号（既有钉子语义不变）。红证：新用例 `房主离席_优先转在线席位_断线席位不得挡开局` 修前 Expected 2/Actual 1；`旧房主重连不夺回` 按新契约重钉（其原钉恰是盲区形态） |
| ③ | 中 | **房间等待人数批漏重钉**：`MultiRoomTransportTests.真实传输_断线只影响本房间` 仍按旧语义断言（该批只跑定向 25 例，全量首跑即红——本审查的基线全量跑出） | **已修**：按新契约重钉（A 房未开局全员离场 → Abort+销毁；B 房隔离判据不变）。**教训**：内核语义批收尾必须跑全量 LiteNet 车道 |
| ④ | 低 | `PlayerSession.IsOwner` 注释漂移（"此后不变"与 TransferOwner 实迁矛盾） | **已修**（纯注释） |
| ⑤ | 中 | **未开局断线席位不可回收 → 部分离场容量慢性泄漏**：坐满后走一人即恒答"房间已满"直到全员散尽；同面 `RoomSummaries().Players = NextPlayerId` 上报虚高 | **登记不修**——需裁决席位复用语义（空位扫描 vs 顺延），见登记表 |
| ⑥ | 低 | `RoomRuntime` 构造不校验 `SpawnPointCount >= 1`（直构形态开局除零；装载侧已有校验兜底） | **登记不修**——下次触碰该文件顺手修 |

**正面结论**（审查通过面）：准入链序/fail-closed、票据验签与重放窗、SettlementOutbox 并发锁与崩溃自愈、输入闸门判定序与 Ack 四道闸、快照背压滞回、重连 peek/consume-in-lock 与 Restoring 抑制、排空链（BeginDrain→DrainComplete→Flush→Dispose + SIGTERM）、终态销毁静默前提与会话路由清理、buildHash 闭包（本批改动件均不在闭包内，`--check` 复算双 OK）——均与契约一致。
