### 8.4 Meta 错误体形状 —— **已统一**（本机 Mongo 可用后重做，L3 实证）

批一已把 Auth/Lobby/Settlement 三家归 `MetaResults` 单源；批二把**样例端点的错误体**也并了进来（`MetaResults.Disabled / InvalidRequest / StoreUnconfirmed`，错误码与 `SettlementEndpoints` 用**同一张 `ProfileErrorCodes` 表**——样例操作的本就是同一张结算账本）。审计点名的"同一 503『存储未配置』三处三种体"从此是**一个体**：

| 场景 | 批二前（样例端点） | 批二后 |
|---|---|---|
| 存储未配置 503 | `{code:"store-not-configured"}` | `{code:"profile.disabled", messageKey:"meta.profile.unavailable", args:[]}` |
| 载荷非法 400 | `{code:"invalid-json"}` | `{code:"profile.invalid-request", messageKey:…, args:[]}` |
| 字段违规 400 | `{code:"invalid-command", errors:[…]}` | `{code:"profile.invalid-request", messageKey:…, args:[…]}`（违规清单进 `args`） |
| 存储未确认 503 | `{code:"store-unavailable", reason:"…内部原因…"}` | `{code:"profile.store-unconfirmed", messageKey:…}`（内部原因**不出响应体**） |

**一处刻意不并、并给了判据**：`409 revision-conflict` 走 `SampleConflict` **领域体**（形如业务侧 409 的 `MatchSettlementResponse`——冲突项必须携带 expected/actual **数字**供调用方修正修订号，压进 `args` 字符串会**降**契约质量）。判据写进代码注释：
**协议级错误（请求未被受理）→ `{code,messageKey,args}`；领域结果（含 409 冲突）→ 领域 DTO；探针端点 → `text/plain`（编排器消费）。**

**过程更正（如实登记）**：本批初稿曾以"L3 本机不可执行，不在盲态下改对外契约"为由**裁决不改**；用户指出本机有 docker mongo 后复核——`litegame-mongo`（单节点副本集 `mongo:8.0`）可起，**L3 可跑**。前提失效即重做，没把"跑不了"当结论留着。断言同步钉死统一体（`503→code=profile.disabled`、`400→code=profile.invalid-request` + `messageKey` 在场、409 补钉 `expected`/`actual` **双数字**）。
**过程中的一次真红**：409 断言我先写成 `"expected":0`（实际是请求带来的 `9`）——L3 当场失败并指名用例，改回后全绿。这正是"能跑就必须跑"的价值：该断言在 L1 不可能暴露。
