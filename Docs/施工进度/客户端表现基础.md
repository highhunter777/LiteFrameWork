### 2026-09-25 · 表现壳生命周期收敛（提交 `a850bcb`）

> 依据：《框架先行》§7 队列第 4 项余部 + §6 样例三失败清单（**加载后 Owner 已退出、重复归还、世界/UI 暂停**）+ §5 接缝 1。

**修掉的两个真实缺陷**：

- **SceneService 迟到加载回写**（`Shell/SceneService.cs`）：原实现在 `await` 之后**无条件回写** `_single`——等待期间宿主 `ReleaseAll()` 后，加载完成仍把**活句柄**写回已释放的服务，后续无人释放 = 租约泄漏。现改为**代次检查**：`ReleaseAll` 递增代次并使在途加载过期，迟到结果**就地释放自己的租约**并计数（`DiscardedLateLoads`），不回写——落实 §9"无法取消的底层加载仍须在完成时检查代次；迟到结果释放自己的租约，不能回写已回收对象"。叠加加载同样处理；`ReleaseAll` 幂等 + 取消宿主代次令牌（`LifetimeToken` 供调用方链接）；释放后拒绝新加载（fail-fast）。
- **AudioService 分域时钟**（`Shell/Audio/AudioService.cs`）：原 `FadeAsync` 读 `Time.deltaTime`，注释声称"世界轨：时停即停"——但本工程 `Time.timeScale` **恒为 1**（`GameClock` 纪律：单一缩放源），读它等于**永不暂停**，注释所称语义从未成立。现按组取时钟域：Effect/Voice 走 `IWorldClock`（世界暂停/变速），Ui/Bgm 走 `IUIClock`；暂停期间 dt 为 0 → 淡变原地保持（不推进也不误判完成）。未绑定时退化为真实帧步进（编辑器/测试兜底）。`BindClocks` 在 `GameModules.Presentation` 注入。

**所有权与释放面**：

- **EntityService**（`Shell/Entity/EntityService.cs`）：`EntityHandle.Scope`（`ClientScope`）作为实体的**取消源与资源登记面**——宿主作用域注入时建子作用域，宿主退出（离场）级联取消实体上的全部工作；回收点先 Dispose 作用域再归还池（§5 接缝 1）。新增 `Shutdown()`：取消在途加载（链接生命周期令牌）→ 连锁回收全部活体 → 清空竞态表 → 排空实例池。重复归还/未知句柄由 Warning 改为**幂等 no-op + `DuplicateReturns` 计数**（清理路径抛异常会断在半路，静默又埋掉纪律问题）。新增诊断面 `PooledTotal`/`ActiveCount`/`InFlightCount`。
- **GameObjectPool**（`LiteFramework/Scripts/Unity/Pool/GameObjectPool.cs`）：新增 `Clear()`（排空闲置件）与 `Dispose()`（Clear + 销毁**自建**池根；注入的 root 归注入方）。`ObjectPool.Clear()` 已存在（Trim(0)），不重复造。`DestroyAtRuntime` 统一销毁口径：**编辑态 `DestroyImmediate` / 运行态 `Destroy`**——EditMode 无延迟销毁帧，直调 `Destroy` 会报错（本批编辑态用例实测踩到）。`DontDestroyOnLoad` 补 `Application.isPlaying` 门禁（与 UIService/AudioService 同口径）。

**开发中被用例揪出的真实缺陷**：`Shutdown` 按 `_active` 快照遍历时，**级联回收会带走子件**——不检查"是否仍在 `_active`"会对已回收句柄再走一次 `HideInternal` 并抛键不存在。已补检查并用**带挂接链的关闭用例**钉死。

**已知边界（登记）**：

- `VfxService` 在途加载仍用 `CancellationToken.None` + `Cancelled` 标志（**惰性取消**：结果丢弃但不真取消底层）；其预算/池/租约治理随表现壳后续批统一收敛。
- `SceneService` 仍是进程级单例（**非 SceneScope 子作用域**）；SceneScope 与真场景资源验收归 U2/场景批。
- 本仓多个第三方资产目录缺 `.meta`（GameFramework/FX/Suriken 等，**预先存在**）——不在本批范围。

### 2026-09-25 · 动画 UI 接缝半部（提交 `914fb19`）

> 依据：《动画模块专项设计》§15 首批 UI 接缝半部、§10"UI 的播放终态与 UI 操作结果分层映射"；《UI框架总设计》§6.3 复位契约；动画 §2 登记的"OnKill 不当完成信号"缺陷。

**修掉三个实测发现的真实缺陷**（本仓 DOTween 1.3.030，反射 + 行为双向实测）：

1. **`Kill(true)` 不复位** —— §6.3 复位契约**从未兑现**。原实现注释称 "Kill(complete=true) 跳终值即复位"，实测**在裸 Tweener 与 Sequence 上都不跳终值**且不派发任何回调。后果：超时/取消时 Tween 停在途中，页面留在半透明/偏移状态。正确复位 = 先 `Complete()`（跳终值并触发回调）再 `Kill(false)`（清理）。
2. **`OnKill` 被当作完成信号**（§2 登记缺陷；实测**比记录更严重**）：本仓 DOTween 的 **OnKill 根本不触发**——显式 `Kill(false)` 与 `KillOnDisable` 均实测无回调。后果：页面在转场中被回收（缓存淘汰/Destroy/低内存）时，任务**悬着直到 2s 超时**才收。修法两层：策略层 `OnComplete` 记 Completed、`OnKill` 只兜底让任务不悬（迟到回调不覆盖已写终态）；壳层 `UITransitionRunner` 感知事务锁定页面进入 `Recycled/Disposed` → 主动取消并立即收尾（`TransitionContext.OwnerGone`）。Cover/Pause/Closing **不作**取消依据——那些仍会收尾，避免把正常流程误判成丢失。
3. **无播放终态出口**：调用方无法区分"播完"与"被杀"。新增 `MotionOutcome`/`MotionPlayback`/`MotionHandle`（`Shell/UI/Anim/MotionOutcome.cs`，零引擎依赖）；`OutcomeOf` 分类改为"超时/丢弃两种事务级事实优先，其余交给播放终态"。`ITransitionStrategy`/`IReplaceTransition` 增带终态的**可选实现位**（默认接口实现转发旧签名）——既有策略零改动、语义不变。

**另修：player-smoke 标记过宽的假通过**。标记集里的裸词 `'AssetService'` 会匹配 `[Asset] init begin` 的**栈帧行**（`LiteGame.AssetService:InitAsync(...)`）——即应用仍在启动中就判通过。本轮实测撞到：一次运行卡在 `BFS step=CheckPlatform`（120s 未就绪）却因该裸词被判 PASSED。已移除该标记（只保留完成态证据），并在脚本注释登记为与 C1-11 正则缺陷同类的问题。收紧后复跑：真标记 `[Asset] ready` 命中，PASSED。

**验证**：Unity 编译 0 错误；EditMode **112/112**（+5：策略 Completed/Cancelled 分类、超时优先且已复位、真实策略正常完成 alpha 到目标、**真实策略取消复位回归卡**、**页面被回收主动取消回归卡**）；L1 **550/550**；Player 构建 PASSED + 冒烟 PASSED。

### 2026-09-25 · VFX 所有权收敛（关闭释放面 + 真取消）

> 依据：《框架先行建设与业务接入专项设计》§3"Scene/Entity/Audio/VFX 所有权"（四类中 VFX 是唯一未收敛项）、§5 接缝 1（谁创建、谁取消、谁释放）、§6 样例三失败清单（加载后 Owner 已退出）。VFX 预算/降级（`VfxBudget`：MaxActive/Overflow/低端跳过）与租约通道（C2 批①已把加载口接 `PrefabLeaseCache.GetAsync`）此前已就位，本批不动。

**背景**：VFX 是表现壳四类生命周期中唯一未收敛的——缺的是**服务本体的关闭面**：`LoadAndMaterializeAsync` 传 `CancellationToken.None`（宿主关闭无法取消在途）、迟到加载结果会写进已死服务（`_prefabs` 缓存 + 实例化进将被销毁的世界容器）、无 `Shutdown()`（活体不归池、池不排空、自建 `[VfxWorld]` 不销毁）。

**修正**（对齐 EntityService/AudioService 的宿主关闭语义）：

- **真取消**：内部 `_lifetime` CTS；加载改传 `LifetimeToken`——宿主关闭即真取消（经 `PrefabLeaseCache`→`SharedLoadCoordinator` 链路，最后一个等待者退出会撤销共享加载）。**单实例 Stop 仍走 `Cancelled` 丢弃**——prefab 加载是共享缓存，不因单个调用者退出而撤（§5.1"共享工作与单个调用者取消区分"，代码注释钉死）。
- **迟到不复活**：续体在 `inst.Cancelled || IsShutdown` 时**不写 `_prefabs` 缓存、不实例化**，计数"迟弃"（`Snapshot` 新键）——此前只挡了"宿主回收"路径，"服务关闭"路径会把迟到 prefab 写进已死服务。
- **关闭释放面 `Shutdown()`**（幂等）：先行取消在途 → 快照遍历 `Stop` 全部活体（与正常回收同一路径，不留第二套语义）→ 清挂点表 → `_pool.Dispose()`（排空闲置 + 销毁自建池根；注入的 root 归注入方）→ 清 `_prefabs` 引用（**租约释放归装配层** `PrefabLeaseCache.ReleaseAll`——本服务只持引用）→ 销毁自建 `[VfxWorld]`（编辑态 `DestroyImmediate` / 运行态 `Destroy`，与 GameObjectPool 同口径）。关闭后 `Play` **fail-fast** 拒绝。
- **DontDestroyOnLoad 补 `Application.isPlaying` 门禁**（自建世界容器分支——表现基础批修 UIService/AudioService/GameObjectPool 时漏了 VFX 这处，EditMode 直调会抛）。
- **装配关闭序修正**：`Presentation.ShutdownAsync` 现为 **Entity → Audio → VFX → `PrefabLeaseCache.ReleaseAll`**（先收使用者、再放租约——VFX 缓存的 prefab 引用先清，租约最后归零）。
- `VfxHandleTable` 补 `CollectAll`（Shutdown 快照遍历，避免边 Stop 边枚举）。

### 2026-09-27 · 缺陷修复：基础层权重未落地（武器脱手悬空）

> 触发：用户真机截图报"**武器与手脱离/悬空**"。排查结论——**不是循环播放问题**（循环回绕正常：缺陷态实测 `t=0.58s` 于 0.667s 片段内、`loop=True`，时间在回绕），而是**基础层（层 0）姿态从未送到角色**：通道在播、时间在走、`IsChannelActive` 全绿，角色却停在默认姿势，非映射的武器挂点骨骼 `add_weapon_r` 一直停在绑定值 → 视觉上就是"武器浮在身外"。

**根因（引擎行为，实测取证）**：`AnimationLayerMixerPlayable` **层 0 的输入权重默认为 0，不会被自动置 1**。本后端建图时只把 1..5 层清零，注释写的是"层 0 权重恒 1、不可改"（照 Unity 文档口径），于是**基础层整体不输出**。取证：缺陷态 `GetInputWeight(0)` 读回 `0.00`，修复后读回 `1.00`。

**探针实测**（真角色 prefab、播 `Run`、30 帧 × 0.05s；观测量 = 非映射骨骼 `add_weapon_r.localPosition`）：

| 配置 | `add_weapon_r.localPosition` | 判定 |
|---|---|---|
| 绑定姿势（无任何驱动） | `(0.4703, 1.0418, -0.0261)` | 基准（= prefab 序列化值） |
| 原生 `Animator.Play("Run")` + `Update` | `(0.1545, 1.0139, 0.3135)` | 骨骼被驱动 ✓ |
| `AnimationClipPlayable` 经 `mixer(1)` | `(0.1619, 1.0048, 0.3146)` | ✓（单输入时层 0 仍生效） |
| `AnimationClipPlayable` 经 `mixer(6)`，**层 0 未显式设权重** | **停在绑定值** | ✗ **缺陷复现** |
| 同图 + 层 0 显式 `SetInputWeight(0, 1f)` | `(0.1619, 1.0048, 0.3146)` | ✓ 修复成立 |

### 2026-09-27 · 普通混合器（同通道多片段）与显式混合时长

> 需求（用户裁决三项）：① 动画后端**添加普通混合器的 API**——用途定为"**通道内多片段按权重混合**"（如 Walk↔Run 按速度连续混合）；② **BlendSeconds 改为后端构造参数并在每处显式传递**（不再写死常量）；③ "view 的 tick 要不要写成状态机"——**结论：不改**（理由见末）。

**① 普通混合器路径（`TryPlayBlend`）**

> **同日后续修正（见下节 ④）**：下面两条的**类型与签名已收敛**——View 层 `AnimationClipBlend` 类型与"按名字列表提交"的裸入口已删除，**唯一混合入口**是 `IAnimationBackend.TryPlayBlend(in AnimationResolvedBlend)`（Core 侧等长 `Bindings[]/Weights[]`，零分配路径）。本节其余结论（原子性、按循环对待、共用 `Node` 机制、能力位、显式淡化时长）仍然成立。

- 新增 `AnimationClipBlend`（View 层纯值：`Binding` 片段名 + `Weight` 相对权重）——**后端只认绑定**，语义 ID → 绑定的解析仍归 Profile/消费者（§4 单源不变）。
- `AnimatorAnimationBackend.TryPlayBlend(channel, blends, startNormalized, speed)`：建普通 `AnimationMixerPlayable`（输入数上限 `MaxBlendInputs = 4`）、**权重按总和归一化**（集合内部恒为 1；通道自身的层权重另行表达）、输入片段**共用同一 `speed`、起点按 `startNormalized × 自身时长` 对齐**。
- **原子性**（§6"不能只占一半"）：通道未知 / UpperBody 无 Mask / 条目数 0 或超上限 / 起点或速度非法 / 任一绑定未知（并计入 `UnknownBindings`）/ 任一权重非有限或为负 / 权重和为 0 → **整组拒绝，通道保持原播放、不建任何节点**。
- **语义**：混合节点**按循环对待、不产生 `Completed`**（混合集合没有单一结束边界，§5）；与单片段节点可互相打断，共用同一套"当前 + 至多一条尾部"机制（§12 节点有界）。
- **实现要点（上一批职责收敛的直接收益）**：把通道的"当前/尾部"抽象成内部 `Node`（单片段或混合节点），让位/淡入淡出/回收对两种形态一视同仁——普通混合器**不需要第二套通道状态**；**回收必须显式级联**（Unity 不会替你销毁 mixer 的输入片段）：`DestroyNode` 先销毁全部输入片段再销毁 mixer。
- 能力位新增 `AnimationBackendCapabilities.ClipBlending`（§4 诚实声明）；诊断 `Source` 报 `mixer(N)`（含输入数），`Weight` 仍报**混合器实际权重**。

**② 混合时长显式化**

- `AnimatorAnimationBackend(Animator, float blendSeconds = DefaultBlendSeconds)`：`DefaultBlendSeconds = 0.12f` **只是默认值的兜底**；淡化数学不再读任何常量，改读**每通道持有的** `ChannelState.BlendSeconds`（构造时分发，构造点显式传）。`0` = **瞬时落位**（测试与"直接切"）；负值/NaN/Inf → `ArgumentOutOfRangeException` **显性失败**（不静默夹取）。
- 副作用即收益：per-channel / per-action 不同手感（拦截要快、受击沉降要慢）已只差"多传一个值"。

**③ view 的 tick 是否状态机 —— 结论：不改（用户裁决）**

`SimView.Tick` 是"每实体数值收敛 + 帧门"（视图增删 → 远端插值 → 本地衰减 → 相机），**没有真正的全局模式**；`CharacterLocomotionDriver` 的状态已显式在 `SlotAnim`（Player/Backend/Current/LastPos）里。改成 FSM 只会多一层间接、不增加可观测性。**若未来出现档位抖动/优先级混乱**，正确切口是把"速度 → 语义（含迟滞）"抽成一个**小状态核**，而不是把整个 Tick 状态机化。
