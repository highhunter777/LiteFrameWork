# 命名空间对齐（LiteClient）

> 范围：命名空间与程序集名一致性修复——《开发导航/程序集引用图》评审第 3 项（命名空间与程序集名脱节）。批次类型：重构，行为零变更。
> 状态：已完成（附验证证据，2026-10-03）

## 改动

**归属**：`LiteClient.*` 七程序集（Abstractions / Runtime / 五适配器）此前 rootNamespace 与全部类型命名空间沿用产品侧裸 `namespace LiteGame`（《共享代码范围》批⑥框架侧划分收口时的历史残留），与《模块拆分》确立的"**本仓命名空间每程序集一个**（`LiteGame` / `LiteGame.UI` / `LiteSim.View`…）"约定不符，也阻碍 C5 可提取方向（提取出的框架不应冠产品命名空间）。本批归位为 `LiteClient`。产品侧 `LiteGame.*` 保持不动。

明细（脚本实测执行）：

- 40 个 .cs 命名空间声明 `namespace LiteGame` → `namespace LiteClient`（`Assets/LiteClient/` 物理根内全部文件，裸命名空间无子级）；
- 7 个 asmdef `rootNamespace: "LiteGame"` → `"LiteClient"`；
- 限定名引用 9 处 / 6 文件：`LiteGame.<类型>` → `LiteClient.<类型>`（DevReload ×4、WidgetDemoMenu、LiteGameIgnoreRule 为代码；SafeCall / Setting / SimInputFrame 为注释 cref）；
- 消费方插入 `using LiteClient;` 53 文件——严格限定在 asmdef 可引用 LiteClient 的程序集目录（`LiteGame/{App,LuaBridge,DevHUD,DevLocalServer,Editor}`、`Assets/Tests/{EditMode,UI/PlayMode}`、`Tests/LiteSim.Core.Tests`），防把 using 插进 LiteFramework.Core 这类禁引它的程序集；
- dotnet 侧 2 文件删除失效的 `using LiteGame;`（`LiteSim.Core.Tests` 引用闭包内已无该命名空间）。

**无影响面（实测零命中）**：Lua 脚本 0 处；序列化资产（.asset/.prefab/.unity）0 处；反射字符串 0 处（仅有的 2 处字符串字面量为产品侧 `LiteGame.GameEntry` 反射与 GM 面板 Pref 键，不在改名面）。LiteClient 68 个类型名与产品/测试侧零重名冲突。
