# 施工进度

本目录记录施工进度与批次执行状态。全项目先后、并行关系和关口见 [总体施工路径](../待办总览.md)，本目录保存其引用的实施证据，与设计文档严格分离：

- 设计、契约、验收标准只写入 `Docs/设计文档/`，本目录不裁决任何设计问题。
- 每条进度记录必须可验证：代码路径、测试命令、产物位置；不得以文档描述代替实现证据。
- 批次状态只用：`未开始 / 进行中 / 已完成（附验证证据）/ 阻塞（附原因）`。

## 组织方式：一条线一卷

本目录按**施工线**成卷（2026-10-18 归并）：一卷＝一条线，卷内**一章＝原一次批次记录**（标题、正文、证据原样并入，仅降一级标题；章首保留 `原文件` 行供旧引用查证）。
旧版「一批一文件」的 118 份记录已全部并入下列 22 卷，**找不到旧文件名时就按线查卷**（如 `服务端R3-Lobby.md` → 《服务端R线》第 7 章）。

> **为什么这样组织**：同一线的批次前后强耦合（后批常修正前批结论），分散成文件时读者会读到互相矛盾的孤立片段；成卷后按章顺序读即得该线的完整演进，章索引保证可跳转。

## 查法

| 想找什么 | 去哪 |
|---|---|
| 某批交付了什么、证据是什么 | 按线找卷 → 卷首「章节索引」按标题定位 |
| 当前还有哪些挂账/未做 | 卷内搜 `挂账`/`未开始`/`待做`；跨线汇总见 [待办总览](../待办总览.md) |
| 某条设计对应的施工证据 | 设计文档正文里的链接已指向「卷 + 章节锚」 |
| 某次改动的影响面 | 卷内按日期搜 `20xx-xx-xx` |

## 维护规则

- **写新记录前先按 `doc-authoring` skill**（落点决策 → 卷内追加章 → 索引登记 → `-Lane Doc` 自检）。
- 新批次记录**追加为该线卷的新章**（章号顺延、章节索引补一行），不再新建单文件；跨线的新主题才新开卷，并在本页「卷索引」补一行（**未入索引即 D3 违规**）。
- 批次结论被后批修正时，**在后批章内写明「修正前批某结论」**，不要回改前章——前章是当时事实。
- 每章必须可验证：代码路径、测试命令、产物位置；不得以文档描述代替实现证据。
- 状态只由 git 事实回填，不由批次作者自述（口径见 [修改指南 §2.4](../修改指南.md)）。
