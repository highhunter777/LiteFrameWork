# 事件中心高级化：施工进度

> 依据：[《事件中心专项设计》](../设计文档/architecture/事件中心专项设计.md)（目标契约与验收以设计为准，本文件只记录施工状态与证据，不在此重复定义）。
> 背景（2026-10-03 检查）：`EventCenter`/`EventChannel<T>` 核心 192 行，快照派发（防重入/嵌套隔离/稳态零 GC）、异常隔离、StrictMode、池化事件回收、`SubscriptionBag` 生命周期分工均已就位并有 7 例 L1 直测；**业务层尚无真实发布调用**（唯一活跃消费者 = Lua `EventBridge`，`EntityService`/`UIForm` 仅登记订阅范式）——先行基建，升级定位是"业务铺开前把机制做完整"：优先级派发、有界队列、延迟派发、重复订阅告警与诊断面。

## 批次规划

| 批 | 范围 | 状态 |
|---|---|---|
| 批1 派发与队列升级 | 优先级订阅 `Subscribe<T>(handler, priority=0)`（小值先派发、同优先级稳定序）；重复订阅 Debug 告警（不抛）；有界队列 `MaxQueued`（默认 256）+ 溢出丢弃计数 + **丢弃路径池化事件回收**；延迟派发 `PublishQueued<T>(e, delayFrames=1)`（默认参数=现状语义） | **规划中** |
| 批2 统计与诊断面 | 中心级 `IModuleStats` 追加（QueuedPeak/QueuedDropped/DispatchErrors/Recycled/StrictWarnings/DelayedCount）；通道级 `EventChannelInfo` + `GetChannelInfos()`（Debug 三宏）；L1 测试增强（既有七例回归 + 新契约用例） | **规划中** |

## 边界（登记，非本专项范围）

- 跨线程发布（主线程 only 框架约定）；值类型事件（class 约束已声明，引用上转零装箱）；事件拦截/过滤链与异步派发（无场景）；弱引用订阅者（生命周期归 `SubscriptionBag`/`ClientScope`）。
- `FrameEvent`（Sim 帧内瞬态事件）不经事件中心——域不同，见设计 §1 分工表。
