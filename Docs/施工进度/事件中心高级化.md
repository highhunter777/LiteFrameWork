# 事件中心高级化：施工进度

> 依据：[《事件中心专项设计》](../设计文档/architecture/事件中心专项设计.md)（目标契约与验收以设计为准，本文件只记录施工状态与证据，不在此重复定义）。
> 背景（2026-10-03 检查）：`EventCenter`/`EventChannel<T>` 核心 192 行，快照派发（防重入/嵌套隔离/稳态零 GC）、异常隔离、StrictMode、池化事件回收、`SubscriptionBag` 生命周期分工均已就位并有 7 例 L1 直测；**业务层尚无真实发布调用**（唯一活跃消费者 = Lua `EventBridge`，`EntityService`/`UIForm` 仅登记订阅范式）——先行基建，升级定位是"业务铺开前把机制做完整"：优先级派发、有界队列、延迟派发、重复订阅告警与诊断面。

## 边界（登记，非本专项范围）

- 跨线程发布（主线程 only 框架约定）；值类型事件（class 约束已声明，引用上转零装箱）；~~事件拦截/过滤链~~ **已由批3 转正交付（§3.5）**、异步派发（无场景）；弱引用订阅者（生命周期归 `SubscriptionBag`/`ClientScope`）。
- `FrameEvent`（Sim 帧内瞬态事件）不经事件中心——域不同，见设计 §1 分工表。

## 施工记录（2026-10-03，批1+批2 同一工作面一次交付——同文件交叠，代码单提交、本节分批记录）

### 批1 派发与队列升级

- `EventChannel<T>`：订阅表改 `List<Sub>`（`Sub{Handler, Priority}`），按（priority 升序，注册序升序）**有序插入**——小值先派发、同优先级稳定序（§3.1）；订阅为低频边界操作，O(n) 插入可接受，**快照派发机制（嵌套隔离/缓冲复用/稳态零 GC）形态不变**；Debug 三宏下同一委托重复订阅 `Log.Warning` 不抛（§3.4——多实例复用同一委托合法；重复订阅 = 双计次，注销一条余一）。
- `EventCenter`：`Subscribe<T>(handler, priority=0)`（接口签名加默认参，既有调用点零改动）；`MaxQueued`（默认 256）溢出丢弃 + `QueuedDroppedCount` + `Log.Error` + **丢弃路径池化事件回收**（与"无订阅者路径同样回收"同纪律，§3.2）；`PublishQueued<T>(e, delayFrames=1)` 延迟派发（§3.3——`PendingEvent` 加 `DueTick`，中心 `_tickCount` 帧计数，到期按入队序经同一派发核心；未到期条目 Tick 内出队再回队，相对序保持；默认参 = 现状语义，`delayFrames<1` 钳到 1）。
- 直测 +4：优先级序（含同优先级稳定序）/重复订阅告警与计次/有界溢出（丢弃计数 + Error + 池化回收断言）/延迟时序（当帧队列先行、到期帧入队序、与当帧队列先后分明）。

### 批2 统计与诊断面

- 通道级（镜像 `ReferencePoolInfo`）：`EventChannel<T>` 增 `PublishedCount`/`DispatchErrors`/`EventType`，`IEventChannel` 扩诊断成员；`EventChannelInfo` readonly struct + `GetChannelInfos()`（Debug 三宏——"哪个事件被谁订阅了几次、有没有空转"）。
- 中心级 `Snapshot` 追加键（既有键不动，HUD 兼容）：`QueuedPeak`/`QueuedDropped`/`DispatchErrors`（通道求和）/`Recycled`/`StrictWarnings`/`DelayedCount`（队列扫描，HUD 低频可接受）。
- 直测 +3：Snapshot 追加键与健康度计数（Strict/异常/在途/峰值跨两轮 Tick 断言）/池化回收计数（含订阅者路径）/通道级诊断（订阅数、派发累计、空转可见、异常可见）。

### 批3 发布拦截链（2026-10-03，设计 §3.5——并行线批次行落笔，契约正文本批补全后执行）

- 设计修订：原 §3.6 非目标"事件拦截/过滤链"被推翻（同对象池 §7.4 续命模式）；契约补全为 §3.5（注册序管线/否决丢弃/fail-open/否决路径池化回收/IEventCenter 不扩面），原 §3.5/3.6 顺移为 §3.6/§3.7。
- 实现：`IEventInterceptor`（新文件，一类一文件）+ `EventCenter.RegisterInterceptor`（返回注销委托，幂等）+ `RunInterceptors` 管线（派发前注册序运行；否决 = 不派发不告警 + `InterceptedCount` + 池化事件回收；**拦截器异常记日志跳过继续——fail-open，观测性缺陷不阻断业务流**；零拦截器一次计数判断不伤零 GC 热路径）；Snapshot 追加 `Intercepted` 键；队列/延迟路径经同一 Publish 核零特例适用。
- 直测 +6：观测放行/否决丢弃含池化回收/注册序与注销幂等/异常隔离 fail-open/否决计数入 Snapshot/队列路径零特例。
