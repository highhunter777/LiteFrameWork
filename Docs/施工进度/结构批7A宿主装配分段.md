# 结构批 7A：MetaHost 装配分段（MetaHostOptions ＋ MetaServiceRegistration）

> **来源**：《服务端宿主结构拆分专项设计》§2 批 7A / §4。
> **状态**：**已完成（已提交 d2d3eece；附验证证据）**。

## 交付

| 面 | 落点 |
| --- | --- |
| 选项接线段 | 新 `Host/MetaHostOptions.cs`（internal static）：日志出口（控制台；EventLog 显式移除及其理由）、配置来源与优先级（内联默认值 → `appsettings.json` → `META_` 环境变量 → `overrides`）、Options 管线（`IValidateOptions<MetaConfig>` + 绑定 `Meta` 节 + `ValidateOnStart` + Kestrel/表单层入站上限 + 关闭时限）、功能门读（`ReadBootConfig` 绑同一节的普通实例）、监听地址落位（`ApplyListenAddress` 经 `IOptions<MetaConfig>`）；`MetaConfigValidator` 随段迁入 |
| 模块注册段 | 新 `Host/MetaServiceRegistration.cs`（internal static）：`Ops` 恒注册；`Auth`（签名密钥门 + `AccessTokenService`）、`Lobby`（两密钥成对门 + 注册表/票据签发/用例/开房用例）、`Persistence`（Mongo 连接串门 + 客户端/库/账本/账号/迁移/归档/结算用例 + 样例链路门 + 迁移托管服务 + 游客登录用例）各一处私有方法——**功能门随块走**，宿主不再持有一张横跨三模块的装配清单 |
| 宿主编排 | `MetaHost.Build` 172 → **28** 行（含文档注释）：建 builder → 选项段 → 门读 → 注册段 → `Build()` → 监听地址 → 中间件/端点挂载序；`CountRequestsAsync`、`WireGracefulShutdown`、`ParseCliOverrides`、`BuildIdentity`/`ConfigSection` 留宿主 |
| 装配顺序 | 逐条不变：日志 → 配置来源 → Options 管线 → 门读 → `Ops` → Auth → Lobby → 持久化（样例门/迁移/游客登录同嵌套关系）→ `Build()` → `Urls.Add` → `Use(CountRequestsAsync)` → `Map(Health → Sample〔门〕 → Auth → Lobby → Settlement)` |
| 行为零变化 | 配置单一来源不变（消费方仍一律 `IOptions<MetaConfig>`；门读仍是普通实例、只决定是否注册）；功能门的启用条件、DI 生命周期、路由可见性（样例端点缺省 404）、启动失败语义（ValidateOnStart / 迁移 fail-closed）逐条保持；**公共 API 零变化**（`Build`/`WireGracefulShutdown`/`ParseCliOverrides`/`BuildIdentity`/`ConfigSection`） |

## 如实说明（边界）

| 项 | 说明 |
| --- | --- |
| 零新用例 | 结构面本批不新增用例：`MetaHostTests`/`MetaConfigTests`/`MetaPage*` 夹具全部走 `MetaHost.Build`，覆盖装配可用性、ValidateOnStart 拒绝启动、配置覆盖生效三面；Options 段与注册段的搬运未改判据，新增测试只会重复同一断言 |
| `MetaHostOptions` 命名 | 沿用专项设计裁决名。它与 `IOptions<T>` 无继承/别名关系，是"宿主选项接线"的容器名；类注释已写明职责边界 |
| 未搬项 | 请求计数中间件、优雅关闭、CLI 解析、端点挂载序按设计"宿主保留"——它们依赖运行时 `WebApplication` 实例，属运行时挂载而非装配 |
| `META_TARGETS` 覆盖面 | 新增文件落 `Server/MetaServer/**` 通配，故 meta 构建身份必变；该身份只进启动日志、不参与准入判定（P1④ 口径），仍按红线 1 重录 |
