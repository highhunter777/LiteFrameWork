## 第1章 模块拆分施工进度：GameModules 按件拆到 App/Bootstrap

<a id="ch1-模块拆分"></a>

> **原文件**：`Docs/施工进度/模块拆分.md`（归并前独立成文，内容整段并入本章）

> 依据：《客户端总设计》§5.1（"只在隔离外部 IO、平台 API、所有权或存在真实替代实现时增加接口；
> 禁止为每个类机械创建接口"同一段的**启动模块命名**约定——本次新增）、§6.1（按依赖顺序初始化、
> 失败只关已成功者、关闭逆序）、§5.1 逻辑边界（流程不认识 UI/适配器运行时）。
> 本文件只记录施工状态与证据；目标与验收以设计为准，不在此重复定义。

### 起因

`App/GameModules.cs` 515 行，11 个 `IClientModule` 实现全嵌在一个 `internal static class GameModules` 里。
**它不是被设计成这样的，是搬家的落点**：`c74e78b`（第三刀）把 `GameEntry` 与 `GameModules` 从
`Main/` 整体迁进 `App/`，当时目的是量"Runtime 里除装配根还有没有适配器依赖"（用编译器量，
只报 2 个错、全在两行 `new`）。之后该文件只被改过 5 次，没人回头拆。

体量分布：9 个叶子模块 15–73 行，`Container` 160 行（占 31%），外层壳 2 行。

### 裁决（2026-09-26）

用户裁决**全拆**（不是只拆 Container）。拆出后新增一条**命名约定并写入设计**（§5.1）：

> 装配根注册的 `IClientModule` 实现一律 `<能力>Module`，一件一文件、顶层类，住 `App/Bootstrap/`。

**为什么必须有后缀**（这不是风格偏好，是可裁决的技术约束）：模块类名取自领域通用词——
`Content`/`Config`/`Settings`/`Input`/`Clocks`/`Container`。放顶层会与**既有类型或引擎 API 争名**：
本批实测，`Input` 作为顶层类会劫持 `using UnityEngine` 文件里 `Input.GetKey` 的解析（CS0117）。
加 `<能力>Module` 后缀，才使"每件一文件 + 顶层类"这条路成立。

## 第2章 目录收敛施工进度：DevHUD 并入 Editor、Luban 生成物归拢 GameData

<a id="ch2-目录收敛"></a>

> **原文件**：`Docs/施工进度/目录收敛.md`（归并前独立成文，内容整段并入本章）

> 依据：《客户端总设计》§5 顶层框图（LiteGame 下应是分层代码目录）、§14.1（可重复依赖与生成物）、
> §22 禁止的重构方式（不做大爆炸式搬迁，分层边界要有名有姓）；`ScanTargets.LiteGameTopLevelDirs`
> 的既定纪律"新增顶层目录必须登记并说明属哪一层，未登记即报红——目录一变就红"。
> 本文件只记录施工状态与证据；目标与验收以设计为准，不在此重复定义。

### 起因

两处顶层目录长期是"历次拆分自然长出来的"，不是分层决策的结果：

1. **`Assets/LiteGame/DevHUD/`**——独立的 `LiteGame.DevHUD` 程序集（全平台 + 三宏 `#if`），
   里面只有两个开发面工具（`DevHUD` 全屏 stats、`SimSandbox` 灰盒沙盒）。
2. **`Assets/LiteGame/RawFile/Config/`**——Luban `gen.bat` Pass 1 的 bin 产物落地处，
   同时也是 YooAsset 收集组路径与两端 buildHash 的客户端表数据源。名字还与引擎概念撞车：
   `RawFileObject`/`LoadRawFileBytesAsync` 是 **YooAsset 的 raw file 容器**，与本目录不是一回事。

### 裁决（2026-09-26）

| 项 | 裁决 | 后果（明确知情） |
|---|---|---|
| DevHUD | **并入 `LiteGame.Editor`**（Editor-only 程序集），删 `LiteGame.DevHUD.asmdef` | **构建 Player 时整程序集不进包**——dev 包/冒烟里不再有 HUD 与 SimSandbox；真机上验不了 Sim（需要时再单独拆运行时程序集） |
| RawFile | **移到 `Assets/GameData/Config/`**（与代码侧产物 `Generated/` 同域），LiteGame 回归纯代码层 | 路径参与 buildHash → **hash 必变**（两端握手常量同步更新）；YooAsset 收集组需重收资源包 |

### 改动

**归属**：`LiteClient.*` 七程序集（Abstractions / Runtime / 五适配器）此前 rootNamespace 与全部类型命名空间沿用产品侧裸 `namespace LiteGame`（《共享代码范围》批⑥框架侧划分收口时的历史残留），与《模块拆分》确立的"**本仓命名空间每程序集一个**（`LiteGame` / `LiteGame.UI` / `LiteSim.View`…）"约定不符，也阻碍 C5 可提取方向（提取出的框架不应冠产品命名空间）。本批归位为 `LiteClient`。产品侧 `LiteGame.*` 保持不动。

- 40 个 .cs 命名空间声明 `namespace LiteGame` → `namespace LiteClient`（`Assets/LiteClient/` 物理根内全部文件，裸命名空间无子级）；
- 7 个 asmdef `rootNamespace: "LiteGame"` → `"LiteClient"`；
- 限定名引用 9 处 / 6 文件：`LiteGame.<类型>` → `LiteClient.<类型>`（DevReload ×4、WidgetDemoMenu、LiteGameIgnoreRule 为代码；SafeCall / Setting / SimInputFrame 为注释 cref）；

- dotnet 侧 2 文件删除失效的 `using LiteGame;`（`LiteSim.Core.Tests` 引用闭包内已无该命名空间）。

**无影响面（实测零命中）**：Lua 脚本 0 处；序列化资产（.asset/.prefab/.unity）0 处；反射字符串 0 处（仅有的 2 处字符串字面量为产品侧 `LiteGame.GameEntry` 反射与 GM 面板 Pref 键，不在改名面）。LiteClient 68 个类型名与产品/测试侧零重名冲突。

### 批②（2026-10-01）· 方向反转收口

#### 起因（§7-1，🔴）

`LiteClient.Runtime.asmdef` **无条件**引用 `RoomServer.Runtime` + `RoomServer.Application.Runtime`；
唯一消费者是 `Assets/LiteGame/Runtime/Net/LocalServerTransport.cs`（离线隔离开发）。
`ProcedureMatch.cs:116-126` 有 `#if UNITY_EDITOR || DEVELOPMENT_BUILD || LITEFRAMEWORK_DEBUG`
**但 asmdef 引用是程序集级的，`#if` 只挡调用点、挡不住引用** → 两个服务端程序集进**所有**
Player 构建，并被 `LiteClient.Runtime` 的全部引用方传递性带上（含测试）。

#### 三条路逐一收窄（实测，非推断）

| 路 | 判定 | 依据 |
|---|---|---|
| (a) 独立程序集 + 构建配置排除 | **否** | `DevHUD.cs` 记录的真实回归：「**Player 里的剥离由三宏负责，不需要也不应该靠程序集边界**」——DevHUD 曾用 asmdef 边界替代宏、结果 HUD 静默消失；且 `DevHUD` 的 asmdef 用 `autoReferenced:false` 也没挡住出包。asmdef 的真正"排除"手段只有 `includePlatforms:[Editor]`（会让 play 模式失效）或 `defineConstraints` |
| (b) 在装配处分档声明 | **采纳** | 设计 §3 D2 原文"必须在装配处分档声明——它是**调试宿主**关系"。且实测 `LocalServerTransport` **零依赖 `LiteClient.Runtime` 其它件**（只用 LiteNet/LiteSim/RoomServer），同程序集纯属偶然 → 可机械落地、无环 |
| (c) 条件剥离（`#if` + 宏） | 部分 | 调用点已有三宏门禁；但其**载重开关**实测不在 asmdef 可达范围内 |

**关于 (c) 的实测**：`LITEFRAMEWORK_DEBUG` **只在 dotnet 侧定义**
（`Assets/LiteFramework/LiteFramework.Core.csproj` 的 `DefineConstants`），
`ProjectSettings/ProjectSettings.asset` 的 `scriptingDefineSymbols` 与任何 asmdef
都**不含**它 → Unity 里本地服的实权开关是 `UNITY_EDITOR || DEVELOPMENT_BUILD`。

**规范文本**（两端同源，单源在本类）：基摘要 = `gameplay-digest-v1` + 逐表一行 `<相对路径> <表字节 SHA-256 全量 hex>`（顺序 = `TableLayout.JudgmentFiles` 声明序）；终值 = `gameplay-rules-v1` + 基摘要 8 hex + 两行规则位；取 SHA-256 低 32 位 = proto `uint32`。表字节按**原始字节**喂哈希（`.bytes` 由 git 判为 binary（`-text`），跨机器 checkout 逐字节一致）。**文本里不含浮点**（避免跨运行时 `"R"` 格式差异）——数值全走表字节/hex。
