# 结构批 6C：Mailbox 路由族门控评估

> **来源**：《服务端宿主结构拆分专项设计》§2 批 6C / §4。
> **状态**：**已完成（已提交 52bc4753；纯评估，无代码改动）**。

## 裁决

**不做**——Mailbox 路由族（`SubmitCommandTo`/`TrySubmitCommandTo`/`DrainRoomMailbox`/`DrainRoomControlMailbox`）保持 `ServerHost` 现形态，不另立组件。

## 证据（P4 §9.1「块内互调 grep ＋ 新消费者」判据）

| 判据 | 结果 |
| --- | --- |
| 外部触点 | `SubmitCommandTo`/`TrySubmitCommandTo` 共 **7 个宿主调用点**（传输断线、PendingDisconnectQueue、Worker Tick、排空超时、宿主 Tick）＋ 6B 入站 `IRoomGateway` 的 Submit/TrySubmit；`DrainRoomMailbox`/`DrainRoomControlMailbox` **6 个调用点**（CompleteAndDrainAllRooms、提交即时排空、Pump 三路径、入站 gateway） |
| 块内互调 | 路由族与 `ApplyOutput`/`ApplySignal`/`ApplyOutboundEnvelope`/`ExecuteCommandTo` 互锁（回传应用/当前房间/输出缓冲）；Apply 族已由 P4 判例明确留宿主，搬路由族会把 Apply 族一起拖进端口或复制其状态 |
| 状态面 | `_mailboxRouting`/`_workerExecution`/`_drainMailboxesImmediately`/`_pendingDisconnects` **36 处引用全部在 `ServerHost`**——没有可独立搬走的房间表式状态本体 |
| 新消费者 | 6B 入站处理器只经 `IRoomGateway` 的 Submit/TrySubmit/DrainMailbox/SchedulePump 四个入口消费，不构成新的独立组件边界 |

## 结论

外提会把 Apply 族、宿主状态、Worker 唤醒与 PendingDisconnect 一起塞进参数表（P2 HttpWorker 判例：收益递减），端口规模超过 >12 阈值却换不到独立职责——**不切**。6C 关闭，后续只剩 7A（MetaHost 装配分段）。
