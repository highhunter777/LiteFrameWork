# 步幅对齐（混合速率＋相位）

《动画模块专项设计》混合面跟进批（2026-10-15，用户点单"先做速率＋相位对齐"）：移动动画是**权重混合**（MoveBlend{Idle,Walk,Run}）——此前各片段整体 1×（无速率换算）、且各片段时长差异大（**实采：Idle 3.000s / Walk 1.133s / Run 0.667s**），混合区间出现"步态踩乱拍 + 脚不打滑对不上"的观感问题。本批落**相位锁定 + 脚程匹配**的最小档（纯表现，不动判定/权威根）。

> 本记录只保留最新进度与证据；设计裁决在各自设计文档，本文件不裁决设计。

## 交付

| 面 | 落点 |
| --- | --- |
| 数学（LiteView 纯计算面） | `LocomotionBlendMath.BuildMoveSpeeds(speed, weights, durations, out speeds)`：公共相位速率 **Φ = 速度 ÷ Σ(权重ᵢ·时长ᵢ·脚程ᵢ)**，步态槽净速率 = Φ×时长（同 Φ ⇒ 归一化相位同步）；**Idle 豁免恒 1×**（无步态）；退化（Σ≤ε/零权重）→ 全 1×；**钳制在 Φ 上**（各槽同乘时长，锁定不被逐槽钳制破坏）。常量单源：`WalkNaturalMps=2.5`/`RunNaturalMps=5`/`PhaseRateMin/Max`（**手测定档**） |
| 接口（Core 播放面） | `IAnimationBackend.TrySetBlendInputSpeeds(channel, speeds)` + `AnimationPlayer.TrySetBlendInputSpeeds(handle, speeds)`：**逐输入净速率**——各输入 `SetSpeed`、混合器节点归 1（调用方给出的即最终速率）；校验（数/有限/>0）整组前置、失败不改现状；同 `TrySetBlendWeights` 就地调参纪律（不换句柄/不重建/相位不重置） |
| 后端实现与诊断 | `AnimatorAnimationBackend.TrySetBlendInputSpeeds`；`AnimationChannelDebug` 增**逐输入倍率**读数（`InputSpeedCount`/`InputSpeed0..3`——引擎真值，零分配） |
| 装配与驱动 | `LocomotionRootStage` 逐帧落对齐速率（权重更新成功后；提交成功也当帧落）；MoveBlend 三槽时长经 `CharacterLocomotionDriver` 从后端 `TryGetClipSeconds` 解析（清单缺件/缺片段引用 → null 降级 1×，不阻断装配）；`CombatAnimMachine.Build(ctx, moveDurations)` 传入 |

## 裁决与边界（如实）

- **相位锁定优先于逐片段精确脚程**：两步态槽"各按自己脚程"会相位漂移（双脚踩乱拍）比轻微滑步更差——取**同 Φ**（锁定）＋Σ 加权脚程守恒；残差（两片段脚程不相等时）由观感手测承受。
- **Idle 豁免**：Idle 无步态；若随 Φ 缩放，低速混合区会按权重放大"呼吸"频率（实测模型：0.75 权重时不豁免可达 ~4×）——恒 1×。
- **AimMoveBlend 不改口径**：四向片段等长（1.133s）天然同相；沿用整体倍率（限速走路档恒 ≈1）。若未来换非等长 strafe 片段集，应换用逐输入净速率口径（同数学）。
- **脚程常量为手测定档初始值**（Walk=2.5/Run=5=设计速度；片段为原地动画、无从烘焙数据反推——`RootMotionCatalog` 覆盖动作片段，走跑不受影响）——实机复核后调常量即可，不动结构。
- **不触判定**：纯表现；权威位移/网络零改动。
