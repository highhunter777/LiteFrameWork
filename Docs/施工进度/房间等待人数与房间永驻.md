# 房间等待人数口径 + 开局前全员离场房间收尾

> **来源**：用户报告（2026-10-17）——「房主没显示等待玩家／满人了成员看到还是未满人」与「房间什么时候会销毁」两问的排查结论落修。
> **状态**：**已完成（附验证证据）**——已提交 735a4398。

## 如实说明（边界）

| 项 | 说明 |
| --- | --- |
| 真机双端未实测 | 房间页"等待玩家 N/M"的联机观感（房主开房即有数、第二人进房即刷）与开局钮链路需真 Meta + 多端进房；本批证据面 = L1 + 定向 EditMode（页面/门面语义由桩驱动），真机端到端归手测 |
| L2/L3 未跑 | 按节律留夜间流水线；本批未触 Meta 侧代码与协议，L3 面无改动 |
| 大厅列表保持投影口径（有意） | `Page_Lobby` 的"未进的房"列表只能来自 Meta 投影，未改；其新鲜度上限 = `Config/roomserver.json` 的 `heartbeat_interval_ms`（10s）+ 列表页 OnShow 一次性查询——如需更鲜，杠杆是调小心跳或让 RoomServer 变更即上报（另开批次） |
| 等待超时仍未配 | `rooms.*.waiting_timeout_ms` 缺省 0（不限时）。本批修的是"全员离开"这一常见形态；"房主在场但始终不开局"仍是**房间有位占用者**的正常状态，要自动散场属模板配置面（未改） |
| 中局离开的行为未改 | 单席位离席在中局不改相位（缺席按空输入沿用、实体照常复活），只有"全员离场"才收尾——本批未触碰该语义 |
