## 1. `RoomInstance` 同步协议字段封装（④，完成）

**前**：9 个 public 可变字段承载宿主↔Worker 同步协议，部分 `Interlocked`、部分裸读写——
审计点名的实例是 `OutboundSequence` 裸 `++`；`DriveAction` 可被静默覆盖；`WorkerOutputs`（List）
暴露给宿主任意 Clear/Execute；排空截止的"只前移"规则散在 `ServerHost.BeginDrain` 里。

**后**：全部私有，只经意图命名的方法访问——**同步原语与状态绑死，编译器替注释把关**：

| 语义 | 新 API | 关键点 |
|---|---|---|
| 驱动登记 | `TrySchedulePump` / `ClearPumpScheduled` / `EnterWorkerDrive` / `CompletePump` | CAS 收进类内；`CompletePump` 把"登记位 + 在途计数"一并归零（原先分散两处，漏一个房间就永不静默） |
| 静默判据 | `HasPendingWork` | 两个值**一起读**（原先调用方各读各的，漏一个即误判可销毁） |
| Tick 合并节流 | `TryQueueTick` / `ClearPendingTick` | 去重语义（"本 Pump 至多一条"）不再靠调用方先读后写 |
| 命令执行 + 产出缓冲 | `ExecuteCommand(cmd)` → `IReadOnlyList<RoomOutput>` | `Clear`+`Execute` 成对收进类内；**宿主不再持有 List**，`EnqueueWorkerOutputs` 也不再回写 `Clear`——"谁拥有缓冲"从口头约定变成类型约定 |
| 出站序号/拒绝 | `NextOutboundSequence` / `NoteOutboundRejected` / `OutboundRejectedCount` | 裸 `++` → `Interlocked.Increment`；**并给出读口**（原先只增不读，见下） |
| 迟到 Join 回收 | `MarkStaleJoinRollback` / `StaleJoinRollbackPending` / `ClearStaleJoinRollback` | 三态语义（置位/判据/清位）从裸字段变方法名 |
| 排空 | `SetDrainDeadline`（只前移规则在内）/ `DrainDeadlineMs` / `TryIssueDrainTimeout` | 原 `if (room.DrainDeadlineMs < 0 \|\| deadline < room.DrainDeadlineMs) room.DrainDeadlineMs = deadline;` 与"读-判-写"式的超时投递判据各自收进一处 |
| 驱动绑定 | `BindDriveAction` | 重复绑定**直接抛**（原 public 字段会静默丢弃旧委托） |

**顺带发现（登记）**：`OutboundRejected`（Outbound lane 满/关闭的回传拒绝数）此前**只增不读**——
全仓无任何消费者（审计未列）。本批给出口 `OutboundRejectedCount`；**接进 Ops 行**归 §4 的计数面封装批
（一起做才不用改两遍输出格式）。

## 2. 重连票据消费单一入口（①，完成一半）

**完成**：审计指"同一段重连票据消费写了三处（:818 直驱、:912 worker 工厂、:973 host-owner 工厂）"。
抽出两个入口后只剩一处实现：

- `TryConsumeReconnectTicket(request, out playerId, out roomId)`——票据字段名与"一次性"语义的唯一出处（直驱路径用）；
- `ConsumeTicketInLock(instance, session, request, playerId, roomId, command, expectRebindResponse)`——
  **两条 Mailbox 形态共用**：在容量锁内消费 + 绑定校验（peek 出的席位/房间 ≠ 真正消费到的即抛竞态异常）
  + 信封构造。此前这段在两条路径上逐字重复，漏写校验的那份会让"绑了别处的票据静默通过"。

### 2.2 Worker 驱动体整块外提（已完成，209 行 → `RoomWorkerDriver.cs`）

**按线程归属切分**（这条线就是外提依据，不是"能搬就搬"）：

| 归属 | 内容 | 落点 |
|---|---|---|
| **Worker 线程上跑的** | 驱动核心（清登记→消费两 lane→复检重登记）、命令执行（控制/重连换绑/输入）、席位侧效应、回传入盒 | **新 `RoomWorkerDriver.cs`**（261 行含端口与文档） |
| 宿主的**生产侧** | `ScheduleRoomPump` / `SubmitWorkerTick`（先入盒再登记唤醒——被 Join/输入/重连/排空等多条宿主路径调用） | 留 `ServerHost` |
| 宿主的**回传应用侧** | `ApplyOutboundEnvelope` 族（宿主线程解析会话、编码并经 Transport 发送） | 留 `ServerHost` |

**窄端口**（`IRoomWorkerHost`，8 个成员，由 `ServerHost` **显式实现**——不扩大其公共面）：
`Pool` / `Ops` / `NowMs` / `BuildHash` / `NoteWorkerCommand` / `NoteWorkerPump` / `NoteWorkerFailure` / `NoteMailboxStale`。
契约窄到什么程度算够：本批的标准是"**驱动体需要的每一样都在这里，且这里没有第二样**"——
审计担心的"拿新 god class 换旧 god class"就卡在这条线上。

**可安全整块搬移的判据（本批实测）**：先 grep 目标方法的**全部调用点**——若都在块内
（本例 12 个方法只互调，外界只碰两个入口），就是一次干净的外提；反之（有宿主侧分散引用）
必须先裁定边界，不能边搬边改。**公共面收成两个入口**：`Drive(room)`（装配到 `DriveAction`）
与 `Send(seat,…)`（装配到管线 `SendTo`）。
**行为零变化**：逐行搬移，只把宿主成员改为经端口调用；`ServerHost` 从 **2039**（HEAD 基线）→ **1868** 行。

## 3. 宿主结构化日志层（③，完成）

新增 `Server/RoomServer/HostLog.cs`：`Info/Warn/Error(area, message)` + 可替换 `Sink`
（测试/嵌入式宿主接管即可把日志变成断言面）；缺省落 Console，形如 `[WARN][Reject] conn 3: ...`。

**替换 16 处宿主逻辑直落**（按级别分类，不是无脑平移）：

| 位置 | 级别 / 区域 |
|---|---|
| `ServerHost` 工作项异常、帧体异常（`HostAssembly`） | `Error` / Worker、Loop |
| Outbox 写入失败（介质） | `Error` / Settle |
| 连接拒绝 ×2、建房被拒、Outbox 容量满拒 | `Warn` / Reject ×2、Room、Settle |
| Match 迁移、结算就绪、排空开始、终态销毁、Ops 行、玩法表装载 ×2、Lobby/Settle 客户端日志 | `Info` / Match、Settle、Drain、Room、Ops、Tables、Lobby |

**边界（写进类注释）**：`Program` 的 14 处 CLI/启动打印**有意保留 Console**——那是控制台程序自身的 UI
（用法提示、参数错误、启动回执），不是服务日志。收口后 `Server/RoomServer` 内 `Console.WriteLine`
只存在于 Program（CLI）与 HostLog（缺省 sink）两处。

**不引日志框架**：本层只要"级别 + 区域 + 一行文本"；结构化字段/采样/异步落盘归 R4 的 OTel 接线
（服务端总设计 §11.2 已明列），此处不预置半个框架。

## 4. Ops / BroadcastAccount 计数面封装（②，完成）

**Ops（`RoomServer/Application`，34 个 public 可变字段 → 只读属性 + 20 个方法）**：

- **读面同名不变**（`Ops.Format`、`/metrics`、测试断言 `host.Ops.Rejects` 等**零改动**）；
- 递增一律经方法：`NoteReject / NoteReconnectServed / NoteRoomRejected{AtCapacity,BadConfig} / NoteRoomDestroyed /
  NoteRejectWhileDraining / NoteRoomDrainTimedOut / NoteTickCoalesced / NoteTicketRejected / NoteSessionRejected /
  NoteSessionsCleaned(int) / NoteMatchStateChanged / NoteSettlement{Ready,Journaled} / NoteSettlementOutbox{Duplicate,Rejected,Failed} /
  NoteRestoreCompleted / NotePacket{Rejected,Oversized}`——**原子性在定义处一次定死**（原先 25 处调用点各写各的裸 `++`）；
- 读面改 `Interlocked.Read`：周期行不再可能读到撕裂的 64 位值（本类计数**确实跨线程**：输入/ACK 由房间 Worker 累加）；
- **三处收编**：① 票据"总数 + 分类"映射从宿主 `switch` 收进 `NoteTicketRejection(枚举)`（新增分类不再要改枚举/宿主/Ops 三处）；
  ② 周期打印节流从宿主收进 `TryBeginPrint(nowMs, intervalMs)`；③ 和解"记最大帧"的**读-比-写三步**收进 `NoteMismatch(frame)`
  （多线程下原先会丢最大值）；
- **顺带闭环**：`RoomInstance.OutboundRejectedCount`（§1 给的口）接进 Ops 行 `outRej=`——**只增不读的计数等于没计数**；
- 唯一保留的可写状态 = `PrintEnabled`（输出开关，不是计数；测试与 `--quiet` 用它）。

**BroadcastAccount（共享源集 `Assets/RoomServer/Application`，8 个 public 可变字段 → 只读属性 + 意图方法）**：

- 写面收成**事件级**方法：`RaiseBackpressureTier()`（档位 +1 封顶 / 降级计数 / **退出恢复观察**——原先管线连写三处字段，
  漏第三处就是"档位升了却还在观察恢复"）、`LowerBackpressureTier()`、`MarkRecoverObservation(frame)`、
  `ClearRecoverObservation()`、`ForceBackpressureTier(tier)`（测试用档位起点，区间由类内夹在 0..3——原先直赋字段可写出非法档位）；
  `RecordSnapshotSend` / `TryAcceptAck` / `Reset` 原样；
- `Session` 的**转发面**：原先 8 个转发属性**每个都带 setter**（等于把刚私有化的状态重新打开，审计点名的"转发属性放大面积"）
  ——**删除 7 个无人调用的 setter**，只留 `BackpressureTier`（用例需要"从指定档位起跑"）转 `ForceBackpressureTier`；
- **ACK 安全链一动未动**：`TryAcceptAck` 的四道闸（非负单调 / 不超前 / 命中 ledger / 验证后才更新 `LastAckSnapshot`）
  原样保留——P0-4 的红线是"ack 只能释放真实发送过的量"，本批不碰。

**顺带收编（审计 §五 Meta [中]）**：`MetaServer/Host/Ops.cs` 的 `public volatile bool Draining`
（同文件其余状态早已方法化，独留这一处裸字段）→ 只读属性 + `BeginDrain()`；写点两处（宿主
`ApplicationStopping`、`MetaHostTests`）随之改调。**

**兼容面（实测）**：读面同名（测试与 `Format` 零改动）；测试**只写** `PrintEnabled`（11 个用例，核实过）；
`Session.BackpressureTier = 3` 经 setter 转发仍可用。

### 4.1 同款计数面补齐（审计原文点了 `InputGate.Dropped*`，一处不收等于没收）

| 面 | 处理 | 备注 |
|---|---|---|
| `InputGate`（共享源集，11 个只增计数） | 私有 + 只读属性 + 11 个 `Note*` 方法；`LastClampedAckSnapshot` 改只读，**钳位与计数合成一个入口** `NoteAckSnapshotClamped(int)`（两件事必须同一步发生，原先是两行可各自漏） | 闸门单线程（权威循环内），故**不引 `Interlocked`**——那只会让人误判它跨线程 |
| `RateLimiter`（6 个拒绝/清理计数） | 私有 + 只读属性；写点全在本类锁内；**原先以 `ref` 把 public 字段传进 `TryAcquire`**——等于把计数写权限交给任何拿到 limiter 的代码，收口后消失 | `BucketCount` 早已是只读属性，未动 |
| `ServerLoop.LoopStats`（4 个节拍计数 + `LastPumpError`） | 私有 + 只读属性 + 三个写入方法；`NoteCatchUpAbandoned(debtMs)` 把"丢债 + 放弃追帧"合成一次记账（同一事件，原先是两行）；`NotePumpFailure(desc)` **返回累计次数**供上报节流判断 | 其中 `PumpFailures` 是 P0 批我自己加的——自己新增的字段同样过"只读属性"这道闸，不给自己开口子 |

**顺带发现并处置：`DroppedIllegalFrame` 是恒零死计数**——声明了、`Ops` 行读了、测试诊断串也打了，
但**全仓无递增点**：源头是一次分类合并（`frame <= 0` 已并入 `DroppedOutOfRange`，代码注释明写"与窗口不含所需帧同归类"），
字段没跟着清。结果是 Ops 行 `drop(...)` 首位**永远打印一个看起来像测量值的 0**——
"打印一个假指标"比不打印更坏（运维会以为该项确实测过且为 0）。
处置：**删字段**（不重连写点——当前分类是有意合并的，凭空加递增点等于发明语义），
Ops 行该槽改列**活的** `DroppedStaleFrame`，标签随之改为 `drop(dup/range/stale/ack/btn)`，测试诊断串同步。
