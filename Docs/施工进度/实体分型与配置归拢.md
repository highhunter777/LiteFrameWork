**设计要点**：

1. **脊柱不动、分型表平行展开**（设计 §1 裁决的落地）：分型行跟槽位同生共死（Spawn 置 kind 位、Despawn 清行），迭代序 = 槽位升序——确定性免费；快照/回滚/SlotDelta/Checksum 基线全部保持有效。
2. **三个确定性面缺一不可**（设计 §2）：CopyTo 深拷、双口径 Checksum、Despawn 清行——`EntityKindTablesTests` 逐面钉住（含"清行后 checksum 与空槽恒定"的隐形分叉守卫）。
3. **重力双表位（债 #2）的过渡态**：`MovementConfig.Gravity` 是表位镜像，**消费单源**在 `CombatConfig.Gravity`（MovementSystem 只读那边），一致性由 `ConfigService.ValidateCandidate` 闸门卡死——迁列随机制消费批，不提前动 digest。
4. **双端同源**：服务端与客户端读同一份 `.bytes`，表数据进 buildHash——roomserver.json combat 内联分区从"可选来源"变为"出现即拒"。
