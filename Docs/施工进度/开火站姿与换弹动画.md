## 施工中发现（本批真缺陷）

**①换弹进入路径缺失（首轮全量 EditMode 抓出）**：进入裁决只写在战斗根 OnUpdate——从**移动根**（Idle/Moving，即"未开火未瞄准时按 R"的最常见路径）没有进入者，事实置位后状态机停在移动层不动。修法：移动根 OnUpdate 增加换弹入口（与瞄准入口同款、优先于瞄准），战斗根内的保持/出场仍由根裁决——与 `SimView.IsDead` 的"事件沿（驱动器）+ 轮询（各根入口）"双路径先例一致。修复后过滤面 29/29。

**②持帧句柄的通道未交还（推演 + 通道数断言抓出）**：`HoldOnFinish`（帧锁定）完成时"不停机不停用"——句柄已终态、通道仍以权重 1 占位；换弹叶播完持帧后退根（战斗根 OnLeave 的 `Stop`）被**终态守门静默吞掉**（旧语义：已终态句柄再 Stop 一律 no-op）⇒ FullBody 层冻在换弹末帧、Locomotion 在下面白跑（角色卡死姿态、只在换弹这一条路出现——死亡叶恒驻不退根所以此前无感）。修法：`CharacterAnimationPlayer.Stop` 对**持帧完成的句柄**语义扩为"**释放通道**"（停用占位 + 清槽位，**不产生第二次终态**、返回值仍 false）；框架契约用例 + 视图侧"退根后 channels==1"断言双钉。

## 2026-10-10 · 换弹改上半身叠加（消解移动滑步）

**用户报告**：换弹时脚不动，出现滑步。

**根因（不是"缺移动换弹资产"）**：换弹原为战斗根 `Reloading` 叶 → **Override 全身接管**，而进战斗根会先停移动根的 Base `MoveBlend`——Base 停 ⇒ 腿冻结在当前帧，世界位移照旧 ⇒ 滑步。换弹片段本身是全身动画（含下肢曲线），但腿根本不该由它管。

**裁决**：换弹改走 **Overlay 上半身叠加层**，不进战斗根、不发起根迁移、不停 Base。
- 表（`Luban/Data/#animationprofile.xlsx`）`Combat.Reload` 行 `channel` 由 `override` 改为 `overlay`（重跑 `scripts/codegen/gen-luban.ps1`，重生成 `tbanimationprofile.bytes`/`.lua`）；`Overlay` 本就是表列合法值，翻译边界无需改；
- `SlotAnimContext` 新增换弹叠加层形状：`UpdateReloadUpper(isReloading, isDead)`（事实真且未死 → 提交一次性 `Reload` 到 Overlay，同一事实期不重发；被拒不记已提交、下帧自愈重试）与 `ReleaseReloadUpper()`（事实清除/死亡 → `Stop`；**播完持帧占位走播放器的"释放通道"路径**，权重淡出露下方姿态）；
- 驱动器每帧在机 `Tick` 之后调一次；死亡到达（帧事件路径与状态轮询路径）**立即**释放叠加层——死亡是全身 Override，压过一切；
- 状态机收口：删 `CharacterAnimId.Reloading` 枚举、`ReloadStage`、`CombatRootStage` 的换弹裁决段与相关转换、`LocomotionRootStage` 的换弹入口；战斗根形态在换弹前后**完全不变**（换弹不抢占 Override，射击窗也不被换弹打断——叠加层权重 1 天然压住上半身）；
- 装配期形状校验随之改口径：换弹语义**必须**登记为 `Overlay`（Override 全身接管＝停 Base＝滑步），错误信息直述该因果；
- 诊断新增 `TryGetReloadUpper(slot)` / `TryGetReloadHandle(slot)`（换弹态不再能从 `TryGetCurrent` 形态面读到——它不占根）。

**为什么 Overlay 的 Mask 够用**：`OverlayMaskFactory` 本就关 Root 位与双腿（含腿子树补插骨）、开 Body/Head/双臂/手指——即"上半身"，且对无其曲线的骨惰性。换弹片段的下肢曲线被 Mask 挡在叠加层外，腿完全归 Base 的 `MoveBlend`。

**测试面变更**（`CharacterLocomotionEditModeTests`，真路径 StartReload）：
| 用例 | 变更 |
|---|---|
| `驱动_换弹事实_上半身叠加层接管_腿继续走Base_事实清除释放`（改名自"Reload叶全身接管"） | 断言改为：叠加层在场 + **形态仍是 MoveBlend**（不迁根）+ `channels==2`（Base+Overlay）；移动期同句柄不重提交、Base 侧进 Moving 叶；播完持末帧仍 2 通道；事实清除后叠加层释放、`channels==1` |

**遗留**：上半身叠加后的观感（换弹上半身姿态与持枪 `AimIdle` 的衔接、慢放 0.5× 的末段持帧）需真机手测；包内无移动换弹资产这件事本身仍未解决（现在表现为"移动时播站姿换弹动作"，但腿在正常出步）。

## 2026-10-10 · 换弹期持枪约束（枪随持枪手）

**用户报告**：换弹时"左手握不住枪、右手拉枪栓位置错位"。

**排查（真 prefab + 真片段逐帧采样，全部为实测值）**：

| 观测 | 结果 |
|---|---|
| 枪骨 `add_weapon_r` | 位于 `root/add_weapon_r`——**根骨**，与 `pelvis` 同级，不随手 |
| 枪骨世界位 vs `hand_r` 世界位 | `(0.47, 1.04, -0.03)` **完全相同**（右手是枪的挂点父级） |
| Reload 片段 `hand_r → 枪` 距离 | 0.6 mm → **21 cm** → 0.6 mm（右手离开枪去拉栓） |
| Reload 片段 `hand_l → 枪` 距离 | 恒 **33.6 cm**（片段里左手并未握枪） |
| 枪骨片段内自身运动幅度 | 位移 6.4 cm / 旋转 22.5°（远小于手部 21 cm / 70°） |

**根因**：片段做的是"右手持枪 + 右手去拉栓"的**自相矛盾动作**——枪挂在右手骨上（模型侧），但动画让右手离开枪。故枪在片段里与两只手都分离；把枪挂在躯干上只会让分离更明显（拉栓时枪不随父级动）。

**裁决（用户确认 B 方案）**：换弹叠加层在场期间，武器骨位姿**锁定到持枪手**（`hand_r`）× 烘焙偏移——"枪永远在手里"是结构上唯一能让手枪不分离的解。

**实现**
- `WeaponGripOffset`（新，`Assets/LiteView/Animation/Profiles/`）：纯表现参数资产——跟随骨路径 / 武器骨路径 / 局部位置 / 局部欧拉 / **幅度缩放 0..1**（真机可调，0 = 等于不约束，1 = 完全锁定）；
- `WeaponGripConstraint`（新，`Assets/LiteView/Animation/Drivers/`）：换弹叠加层在场时按"跟随骨变换 × 偏移"覆写武器骨，并按幅度缩放与**本帧动画值**插值（写前先读，故权重 0 时写回等值）；写序在**播放器 Tick 之后**（动画 Evaluate 完成后），单一写者、退出即停写；
- `WeaponGripBaker`（新，`Assets/LiteGame/Editor/`）：菜单 `LiteGame/烘焙持枪偏移`（**2026-10-10 起并入 `LiteGame/烘焙工具箱`**——见《烘焙工具箱专项设计》），参考姿态 `AimIdle t=0` 采样生成资产；
- `LiteAnimator` 新增可选 `gripOffset` 配置面（空 = 不启用）；`CharacterLocomotionDriver` 建槽时建约束、每帧尾部启停、诊断日志带 `持枪约束=on/off`；`LiteGame.Editor.asmdef` 补 `LiteView` 引用；
- 资产 `Assets/Prefab/WeaponGripOffset.asset`：跟随骨 `…/hand_r`、武器骨 `root/add_weapon_r`，重烘偏移 `localPos ≈ (-0.0006, 0.0002, -0.0001)`（≈ 0，印证枪骨坐在右手上）、`localEuler Y = 270°`。

**施工中修正的两个真缺陷**（均由实测抓出，非推演）：

1. **坐标换算踩 Unity 延迟矩阵坑**（首版表现为"枪跑到角色原点"）：首版用 `follow.localToWorldMatrix * Vector4` 手工搭矩阵，而烘焙侧用 `InverseTransformPoint`——`localToWorldMatrix`/`.position` 在动画写入 Transform 后**同帧读取可能是旧值**（延迟刷新），两边各差一次，叠加后枪被算到原点附近（实测期望世界位 `(0.01, 0.18, 0.22)` vs 真实 `(0.47, 1.04, -0.03)`，差 1 米级）。**修法**：两边统一 `TransformPoint`/`InverseTransformPoint`，烘焙前显式 `Physics.SyncTransforms()`。**同时暴露测试自身的盲区**——原用例的期望值算法与实现共用同一个错误公式，3/3 全绿却放行缺陷；修后期望值改为独立解析式。
2. **首次跟随骨选错**（胸椎 → 右手）：首版按"手部动作幅度大、跟手会把枪甩走"的推断选了躯干，但逐帧距离分析显示**枪骨与右手骨世界位完全重合**——跟手才是结构正解。教训：**跟随目标应由"挂点父级链"的数据决定，不由幅度推断决定**。
