## 第2章 快照全量 AOI 缺席判死修复

<a id="ch2-快照全量AOI修复"></a>

> **原文件**：`Docs/施工进度/快照全量AOI修复.md`（归并前独立成文，内容整段并入本章）

> 状态：**已完成（附验证证据）**
> 范围：《状态同步专项设计》§5.2/§6.2/§8（AOI 只影响广播不影响判定——红线）；缺陷由 2026-10-01 用户问询触发（"现在 bot 是不是会消失；按 F9 瞬间移动玩家会有什么问题"）
> 证据时点：2026-10-01

### 缺陷（真缺陷，非设计意图）

**机制链**（每一环均有代码事实）：

1. `SnapshotDiffer.BuildFor` 对**全量帧**也做 AOI 过滤（半径 30m、格 10m）——视野外实体不进全量包；
2. `SnapshotReassembler.Apply` 对全量的语义是"**缺席槽位一律判死**"（清整个 AliveBitmap 只回填包内槽位）——该语义以**全图**为前提，与 ① 矛盾；
3. `RollbackSim.OnAuthoritativeSnapshot` 任何一次失配/超前覆盖都把镜像整体 `CopyTo` 进本地预测 Sim；
4. `SimView.SyncViews` 按 `_sim.IsAlive` 回收视图 → **视野外实体被无声杀死**（死亡事件在和解静默门内，无任何死亡表现）。

**触发条件**：实体出视野后 ≤1s 必有一帧全量（`ProtocolConstants.FullEveryFrames=60`）把它在镜像里判死；随后任一次和解采纳即落地。离线 F9 形态的触发源＝开局首包超前覆盖 / 开火换枪（不预测的公共面变化）/ >83ms 卡顿帧（客户端追帧上限 5 < 服务端 8 → 快照超前直接采纳）；真联机下丢包/远端输入即常发 → **视野外实体基本必然消失**。消失后服务端(活)↔客户端(死)每快照失配 → 30Hz 和解风暴 + `SendMismatch` 每帧上报；走回视野内还要等下一帧全量（≤1s）才无声冒回。

### 修复内容

| 文件 | 改动 |
|---|---|
| `Assets/LiteNet/Protocol/SnapshotDiffer.cs` | `BuildFor` 全量分支绕过 AOI——全图活体直发（槽位升序）；AOI 只保留在增量分支；类注释钉死"全量缺席=死只对全图成立" |
| `Assets/RoomServer/Application/SnapshotPipeline.cs` | 背压档 3 `TrimFarthest` 豁免全量帧（缺席判死语义同一条红线）；裁剪只作用于增量帧 |
| `Assets/LiteSim/View/SimView.cs` | `TryInterpolate` 补**远端硬切**：前后快照位置差超 `SnapDistance` 直接对齐新快照（§6.2"远端必要时 snap"落地——消除传送/复活被插值播成 33ms 横穿地图的"飞人"） |

带宽代价：全量 ≤1Hz 且 ≤ 活体数，整帧可付；AOI 的收益全在 30Hz 增量上，不受影响。重连路径（`ServerHost.HandleReconnect` → `SnapshotCodec.PackFull`）本就全图整帧，未受影响、无需改。

### 用例

### F9（瞬间移动玩家）处置结论

用户问询的第二问按下列口径落档：

1. **已随本批消除**：AOI 连锁消失（瞬移 >~30m 不再把 bot/远端"裁死"——它只是冻结，增量不更新、全量 ≤1s 兜底刷新）；远端"飞人"（远端 snap 落地）。
2. **属设计允许、无需处理**：瞬移自造一次和解+硬切（`SnapDistance=3m`，§6.2 复活/传送允许硬切）；本地预测在快照到达前于原地多跑 ≤1 个快照间隔。
3. **真要做传送类功能（调试热键/复活/传送技能）时的前置件**，本批不做：输入帧表达不了位置跳变——需新增服务端 `RoomCommand`（权威帧边界写位置，客户端不预测）；落点必须过与出生点同款的"清障"校验（客户端 `CharacterController.Move` 收敛会被墙挡住 → 表现/判定持续分叉）；调试热键按 F9/F10 同款三宏门禁（`UNITY_EDITOR || DEVELOPMENT_BUILD || LITEFRAMEWORK_DEBUG`）。

### 遗留登记

- **checksum 全图口径 × AOI 增量裁剪的失配波**：线上 checksum（`SimChecksum.ComputePublicChecksum`，随每份快照）按**全图**算，视野外实体的变化不进增量 → 实体在视野外移动期间客户端每快照失配和解（每帧全量 ≤1s 自愈收敛；当前 1v1 站桩 bot 无感）。根治需把 checksum 比对口径按视点可见集裁剪（两端同源可见性判定，避免视点位置竞态）——**协议/设计级决策，归状态同步专项后续批**，不以表现修补替代。

> 证据时点：2026-10-09

### 缺陷（真缺陷，非设计意图）

**锁死主链**（每一环均有代码事实与 [Diag] 哨位实测）：

1. 客户端 `RoomClient.SendInput` 冗余窗＝**固定"最近 ≤4 帧"**（`_recentCount` 只看环内连续可用段）；
2. 预测领先（本地帧 − 权威帧）在本形态是**常态**——领先 >4 后，服务器要消费的 `serverFrame+1` 永远不在窗内；
3. 服务端 `InputGate.Store` 旧口径主帧取"窗内最大 ≤ serverFrame+1"——取不到即整包按越界丢弃（`DroppedOutOfRange` 按包增长、`AcceptedCount` 冻结）；且包内未来帧（> serverFrame+1）一律不预存；
4. 权威收不到输入 → 本地预测每份快照失配 → **按快照频率持续和解回滚**（橡皮筋/锁死，不可自愈）。

**伴生缺陷三处**（同批根治）：

- **多步渲染帧空输入分叉**：一渲染帧走 2+ 逻辑帧时，进程内权威与客户端共用累加器且**先**步进——客户端输入三件在 `TickOutgoing` 之后才做，多出的帧被权威按空输入兜底执行，与本地沿用逐位分叉 → 每份受影响快照都和解（低帧率下成快照频率橡皮筋）。
- **追帧补发按下标读错行**：`TryGetExecutedInput(frame, playerIndex)` 按数组下标读回，但历史数组由 SimStep **就地按 EntityId 排序**、远端槽位常携带零身份（排在最前挤位）——下标口径会取到别人的输入发出。
- **和解重放终点无上限**：卡顿帧"同步采纳 + 本地步进"逐次把领先顶高——越过输入冗余覆盖范围后服务器再也找不到所需帧号，锁死形态不可自愈。

### 施工记录

#### 2026-09-26 · 平台适配批

**新增程序集 `LiteClient.Platform.Unity`**（`Assets/LiteClient/Adapters/Platform.Unity/`）：
`IIntentSource`（New Input System 实现）+ `ICameraService`（Cinemachine 实现）。
依赖只向下：`Abstractions` / `Runtime` / `Core` / `LiteSim.View` + `Unity.InputSystem` + `Cinemachine`。

**输入侧**：

- `NewInputIntentSource`（新）——读 `PlayerInputActions` 的 `GamePlay/Fire|Move`；移动向量归一 ≤1、
  鼠标屏幕点 → 地面平面解算瞄准方向（与旧实现同口径）。角色：**只出连续意图**（Move/Aim/Fire），
  离散意图（Reload/Switch/Skill/Pickup/UseItem）需按键沿 + 单调 `action_seq`，随武器/Action 消费者（G2）。
- **`IntentSample`（新类型）**：`Sample()` 返回"意图 + 是否真的采到"。**非空语义显性化**——
  "没采到"（设备未就绪）与"采到空意图"（用户真的没按键）必须可分辨，否则前者会被当成后者，
  玩家松手/设备抖动时意图塌缩成零。用 `default(SimInputFrame)` 表达前者会让两种语义不可分。
- `KeyboardMouseIntentSource`（**删除**）与 `LiteSim.View.Input` 目录。

**相机侧**：

- `ICameraService`（新端口）住 **`LiteSim.View`**（带 `UnityEngine.Vector3`；`LiteFramework.Core` 开

## 第5章 联机死亡/血量/动画同步修复（P0+P1）

<a id="ch5-联机死亡血量动画同步修复"></a>

> **原文件**：—（本批新增章节）
> **状态**：已完成（工作区未提交；L1 1749 PASS，Unity 全量 EditMode 647/648——唯一红为并行线 Meta 模板断言，与本章改动无关）

### 5.1 缺陷与根因

用户联机实测症状：**一边打死了、另一边没死；人物动画同步不连续**。静态检查确认快照字段链路（Hp/Kills/Deaths → SlotDelta/FromDelta/差分摘要/公共 checksum/CopyTo）本身完整，问题集中在来源与时序：

1. **客户端把自身开火结果当权威**：`BattleInputPipeline` 把含 `ButtonFire` 的真实输入喂本地 `RollbackSim`，本地 `ShootingSystem → DamageSystem` 结算伤害/跨死线；`SimView` 把预测 `Death` 事件交给动画，`DeadSeen` 只由 `LifeStartFrame` 变化清除——服务端回溯判 miss 时，开火方会看到预测死亡/尸体（甚至本地 `RespawnSystem` 到点“复活”），受害方全程满血。
2. **快照无帧号单调守卫**：快照走 Unreliable，旧包/重复包可覆盖 `LastSnapshotFrame` 与镜像，Hp/死亡/比分可回退；远端插值窗口随包到达重置，丢包冻结再跳、乱序倒退。
3. **视点帧口径抵消**：客户端发 `LastSnapshotFrame + InterpFrames`、服务端再减 `InterpFrames`，实际回溯到最新快照帧；而 `SimView` 渲染的是插值窗口（落后最新快照），且回溯把射手也恢复到历史位——移动交火下客户端判中、服务端判不中。
4. **命中/死亡反馈只有预测源**：客户端 `Hit/Crit/Death` 只来自本地帧事件，受害方（本地不模拟敌方开火）永远收不到自己阵亡的归属/音效；排行榜读本地预测 `Kills`，预测击杀先上板、权威再回退。
5. **关键状态单次增量**：非致命掉血/复活等变化通常只在一份不可靠增量里；丢包后要等周期全量（或 ack 兜底）才收敛。AOI 增量 × 全图 checksum 的失配波仍按既有债务处理（P2）。
