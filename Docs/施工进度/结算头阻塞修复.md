# 结算头阻塞修复（确定性拒绝的终态处置）

> **批次**：服务端审计"顺带登记·确定性拒绝的头阻塞"（[审计修复登记行](../代码质量审计-服务端.md)）　**日期**：2026-10-12　**状态**：完成（未提交）
> **来源**：审计登记——`SettlementSubmitService` 对非 2xx 一律"保持待提交 + 重投"，而 `TrySubmitNext` 只取 `ListPending()` 头部：Meta 返 409（台账冲突）/400（载荷非法）时该条目**永不收敛且阻塞其后全部条目**。
> **前置要求（已履行）**：审计明示"改拓扑须先改该设计再改代码"——**设计先改**。

## 1. 设计先行（《上云测试专项设计》§2 新增裁定）

新增"**提交失败处置分级（2026-10-12 裁定）**"：

- **可重试失败**（网络/超时、401·403·404 凭据·部署面、408·429、5xx）→ 维持原口径：保持待提交 + 指数退避（那些是运维可修复状态，弃置会把"修好后本可收敛"的结算静默丢账）；
- **确定性拒绝**（**载荷级 4xx**：400 载荷非法 / 409 台账冲突 / 413 / 422）→ **不无限重投**：Outbox 追加**弃置标记行**（`Kind="x"`，含原因）退出待提交面并**让位**后续条目，计数 `Abandoned` + 警告日志；
- 弃置标记写介质失败 → 按可重试失败处理（事实不丢）。

## 2. 实现

| 层 | 改动 |
|---|---|
| `ISettlementOutbox` | 新增 `bool TryAbandon(string matchId, string reason)`（终态处置口；线程/幂等/介质失败口径同 `TryMarkCompleted`，注释写明） |
| `FileSettlementOutbox` | ①`TryAbandon`：**标记行写先行**（崩溃自愈口径同完成标记）→ 写失败内存不动（保持待提交）；②装载把 `Kind="x"` 与 `"c"` 同路处理（退出待提交面）并计数；③新 `Abandoned` 属性（装载重建 + 运行时累加）；④journal `JournalEntry` 追加 `Reason` 字段（追加字段，旧行兼容；线格式注释同步 `x`） |
| `SettlementSubmitService` | ①新步 `SettlementSubmitStep.Abandoned`（Loop `continue` = 立即让位）；②`IsDeterministicRejection` 判据（**400/409/413/422**；401/403/404/408/429/5xx **保持可重试**——判据与理由写进注释）；③失败分支：确定性 → `TryAbandon` 成功则计 `Abandoned` + 清 `_consecutiveFailures`（弃置≠端点不健康，不推退避）+ 警告日志；写失败回落可重试失败；④`Abandoned` 计数读口；⑤类注释与 §2 引文同步 |

**已知遗留（不冒充）**：`Abandoned` 目前只有服务计数 + 日志面；汇入 Ops 行 / `/metrics` 随 R4 后续批（RoomServer 的 metrics 只从 Ops 取数，接口面不在本批扩张）。

## 3. 测试（+4，全绿）

| 用例 | 钉住 |
|---|---|
| `确定性拒绝400_弃置并让位_后续条目照常提交_重开不复活` | 队首 400 → 步=Abandoned、计数=1、Failed=0（不推退避）、容量释放、`ListPending[0]`=后一条；**让位**后第二条照常 Submitted；重启面："x" 行重建计数、**不复活不重投**（handler 调用数=2 封死） |
