## 第9章 控制台编码修复（服务器两端 UTF-8）

<a id="ch9-控制台编码修复"></a>

> **原文件**：`Docs/施工进度/控制台编码修复.md`（归并前独立成文，内容整段并入本章）

**范围**：GM 本地联测页（第五页）实机联测发现的服务器日志乱码——`deploy/logs/*.log` 与页内尾随视图中文全乱、丢字。

**根因（字节级实证）**：服务器子进程控制台输出随系统 OEM 码页（中文机 = GBK），而重定向捕获方（GM 本地联测页，Unity/Mono 侧）按 **UTF-8** 解码——`票据验签` 的 GBK 字节（C6 B1 BE DD D1 E9 C7 A9）按 UTF-8 解码恰好还原为观察到的 `Ʊ…ǩ` 混合乱码；`meta.log`/`room.log` 合计 261 处 U+FFFD（不可逆丢失）。仅"重定向捕获"路径受害；控制台窗口路径（local-chain.ps1）不经重定向、无损。

**修法**（`Server/RoomServer/Program.cs`、`Server/MetaServer/Host/Program.cs` 入口各一段）：

- 有控制台宿主：`Console.OutputEncoding = UTF8`（切控制台码页 65001 + 托管写出流）。
- 无控制台宿主（detached/服务化形态——setter 实测抛 `IOException: 句柄无效`）：降级直换托管写出流（`Console.SetOut/SetError` + UTF-8 `StreamWriter`，`AutoFlush`），两种宿主同得 UTF-8 输出。

**验证**：

- 三拓扑字节级实测（`CreateNoWindow`+管道＝GM 面板同款 / `CreateNoWindow`+文件 / detached+文件＝服务化形态）：原始输出字节均为合法 UTF-8、0 替换符、中文行完整可读。
- L1 **[PASS] 1700**；两端 Debug bin 重编（bin 侧 appsettings 密钥未被覆盖，mtime/内容实测）；BuildHash 不涉及（`Server/` 不在共享源集）。
- 两实例已按 GM 面板同款姿态重启运行（apphost、工作目录＝仓库根、日志续写 `deploy/logs`，面板探针按进程名可见可管）。

**顺带发现（同日续修——页件侧）**：GM 本地联测页 `GmLocalChainPage.UdpBound()` 的"绑得动 = 空闲"判据在 Windows 不成立——Unity 运行时实测：RoomServer 已占用 17777 时 `new UdpClient(17777)` 仍 `BIND_OK`（Windows UDP 默认允许多重绑定，Mono 未设排他）。后果：Room 行恒显 `[--] process alive, port not bound`（进程在跑却报"端口未绑定"）。候选修法：`System.Net.NetworkInformation.IPGlobalProperties.GetActiveUdpListeners()`（同运行时实测 `has17777=True / has19999=False`，可用）。**已随联测两修修复**（改枚举 `IPGlobalProperties.GetActiveUdpListeners()` 判端口占用；同批修"日志区滚不动"——见 [GM与调试工具分层](GM与调试线.md#ch1-GM与调试工具分层) 续记与客户端审计修复登记）。

**边界（如实）**：页件 `LaunchCaptured` 显式钉解码端（`StandardOutputEncoding/StandardErrorEncoding = UTF8`）可作双保险——服务端输出已固定，未加亦正确（现有编辑器运行时默认即按 UTF-8 解码）。

### 边界（如实）

- **Unity recompile 与 EditMode 编译未验证**（Pipeline 不可达）——下次编辑器可达时先 `unity command recompile` 再进任何测试。
