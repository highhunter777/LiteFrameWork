# 平台适配施工进度：New Input System 设备源与 Cinemachine 相机服务

> 依据：《角色状态与动作专项设计》§3（输入三件：设备源/上下文门/帧边界门）；《联机战斗演示专项设计》

> 本文件只记录施工状态与证据；目标与验收以设计为准，不在此重复定义。

## 起因

`Player.inputactions`（New Input System 的 Action 资产）与 `com.unity.cinemachine` / `com.unity.inputsystem`
两个包**都早已在仓库里**（`Packages/manifest.json`），但代码侧一处没用：输入还是 legacy
`UnityEngine.Input` 的键位直读（`KeyboardMouseIntentSource`），相机还是自算的 `BattleCameraRig`。
本批把两者接上，并把实现收进设计里预留但一直空着的 `Adapters/Platform.Unity` 槽位。

## 裁决（2026-09-26，用户）

| 项 | 裁决 |
|---|---|
| 实现落哪 | **`Adapters/Platform.Unity`**（§5 框图预留槽）——`Runtime` 不直接依赖 InputSystem/Cinemachine |
| 旧实现 | **直接替换、不保留双路**（`KeyboardMouseIntentSource` / `BattleCameraRig` 删除） |
| 生成类 | 资产移入适配器、生成类改名 `PlayerInputActions` + 命名空间 `LiteGame` |
| 相机初始设置 | **归场景/预制配置**——代码不设档位（俯角/距离/FOV/阻尼/优先级一律不写） |

## 施工记录

### 2026-09-26 · 平台适配批

**新增程序集 `LiteClient.Platform.Unity`**（`Assets/LiteGame/Adapters/Platform.Unity/`）：
`IIntentSource`（New Input System 实现）+ `ICameraService`（Cinemachine 实现）。
依赖只向下：`Abstractions` / `Runtime` / `Core` / `LiteSim.View` + `Unity.InputSystem` + `Cinemachine`。

**输入侧**：

- `NewInputIntentSource`（新）——读 `PlayerInputActions` 的 `GamePlay/Fire|Move`；移动向量归一 ≤1、
  鼠标屏幕点 → 地面平面解算瞄准方向（与旧实现同口径）。角色：**只出连续意图**（Move/Aim/Fire），
  离散意图（Reload/Switch/Skill/Pickup/UseItem）需按键沿 + 单调 `action_seq`，随武器/Action 消费者（G2）。
- **`IntentSample`（新类型）**：`Sample()` 返回"意图 + 是否真的采到"。**非空语义显性化**——
  "没采到"（设备未就绪）与"采到空意图"（用户真的没按键）必须可分辨，否则前者会被当成后者，
  玩家松手/设备抖动时意图塌缩成零。用 `default(SimInputFrame)` 表达前者会让两种语义不可分。
- `KeyboardMouseIntentSource`（**删除**）与 `LiteSim.View.Input` 目录。

**相机侧**：

- `ICameraService`（新端口）住 **`LiteSim.View`**（带 `UnityEngine.Vector3`；`LiteFramework.Core` 开
  `noEngineReferences`，引擎类型进不去——初稿放 Core 被编译当场拦下，见下"踩坑"）。
- `CinemachineCameraService`（新实现）——取**场景里已配置好的** `CinemachineVirtualCamera`，
  只把表现层给的位置写给它的 Follow 目标。**不创建 vcam、不写任何档位常量**
  （构图归美术配置；代码再写一份会导致"编辑器里改了没用"）。场景无 vcam = 装配缺口，
  `TryCreateFromScene` 返回 false 并给原因，由调用方决定。
- `BattleCameraRig`（**删除**）——自算的指数平滑与档位常量全部退场；平滑口径归 Cinemachine 的 vcam 配置。
- `SimView` 的相机字段由 `BattleCameraRig` 改为 `ICameraService`（只调 `Follow`）。

**装配与守卫**：

- `PresentationModule`（⑨）建/取主相机 + 建相机服务，并把主相机 Put 进 `ClientContext`；
  `InputModule`（⑩）取该相机设给设备源（注册序即依赖序，无需回填钩子）。
- `ContainerModule`：**没相机服务就不进对局**——`ProcedureBattle(..., requireCamera: true)` 在
  `RunAsyncCore` 开头抛（进 `ProcedureError`）。理由：没虚拟相机的包里，对局会"跑得动、看不见"，
  属最难查的静默失效。**当前 `BuildProfile` 只构建无 vcam 的 `Test.unity`，故这是预期会命中的守卫**
  （用户配置场景 vcam 后自然转为正常路径）。
- `DisciplineScanner` R12 边界表 + 正则各补两条：`UnityEngine.InputSystem` / `Cinemachine`
  只允许 `Adapters/Platform.Unity/` 使用。

**踩坑（两条，都是"编辑器/编译器当场拦下"而非事后发现）**：

1. **`ICameraService` 初稿放 `LiteFramework.Core`** → Unity 报 `ICameraService.cs(1,7) error CS0246:
   UnityEngine 找不到`。Core 的 asmdef 是 `noEngineReferences: true`（核心机制不依赖引擎）。
   改放 `LiteSim.View`（与 `IVFXService` 同层同理由）。
2. **`LiteGame.Editor.csproj` 等生成物与 asmdef 有漂移**（本批新加的 asmdef 引用与源文件不在生成物里）——
   靠 `unity command recompile`（真编辑器）而非 `dotnet build` 生成物验证，避免被过期生成物误导。

**未做与边界**：

1. **触屏/手柄**：Action 资产目前只有 `GamePlay`（键鼠绑定）与空壳 `UI` 映射；触屏沿用同一 Move/Aim/Buttons
   的绑定与设备切换随移动端批（`IIntentSource` 抽象已就位，加绑定即可，不动代码）。
2. **重绑**：Action Maps + 重绑落 `GameSettings` 仍归 U2 余部；本批只把输入从硬编码 KeyCode 换成
   Action 资产（重绑的前置条件已具备）。
3. **相机行为回归**：原 `BattleCameraRig` 的"首帧落位、和解期跟衰减后位置"语义由 Cinemachine 阻尼
   与 `ICameraService.Reset` 承接；**实际观感需真机/PlayMode 验收**（本批无 vcam 场景，未跑）。
4. **`BuildProfiles/windows-x64.json` 仍只构建 `Test.unity`**：配置 vcam 后应把该场景加入
   `scenes`（或改用含 vcam 的场景）——属配置，不在代码批。
