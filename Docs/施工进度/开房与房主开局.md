## 交付

- **Runtime**（`Assets/RoomServer/Runtime/`）：
  - `RoomCommandKind.StartEarly` + `RoomCommand.StartEarly(playerId)` 工厂；`PlayerSession.IsOwner`
    （首入座者置位，断线重连不迁移）；`PlayerAdmitted.IsOwner`（随就位信号，宿主填 JoinAck）；
    `StartRejectedOutput`（拒绝原因输出 → App 映射 StartMatchResponse）。
  - `ExecuteStartEarly`：仅 WaitingForPlayers 有效、仅 owner 可触发 → 复用 `StartMatch`（reason=
    "owner-start"——审计与满员 "full" 可辨）；Running 后幂等忽略；非 owner/无效席位 → 拒绝输出。
  - `ExecuteJoin` 收口对局中拒加入：Starting/Running/Finishing/Settling → `JoinRejectedOutput("对局进行中，无法加入")`。
- **协议**（`battle.proto`，**只增不改**）：`JoinAck.is_owner=7`；`StartMatchRequest{}`（C→S Reliable）；
  `StartMatchResponse{ok,reason}`（S→C Reliable，仅拒绝时回）。`PacketType` 追加 13/14；`PacketCodec` 登记两型。
  ★ `gen_proto.py`（protoc 3.36.1 自 nuget Google.Protobuf.Tools）+ ★ BuildHash 重生成：
  shared `3c07d038aadb1e81`→**`e92b22d72b589a0a`**（meta 恒 `ff8b78bb…`；中途一次 `b3ce…` 因
  顺序反例被注释卫生批的源改动作废——**先改源后重生成**纪律的现场教训，如实登记）。
- **宿主**（`ServerHost.cs`）：分发 `StartMatchRequest` → `HandleStartMatchRequest`（会话→席位→房间→
  `RoomCommand.StartEarly`）；`ApplyOutput` 映射 `StartRejectedOutput` → 回发起者 StartMatchResponse；
  `JoinAck.IsOwner` 填充。
- **客户端**（`RoomClient`/`BattleClient`）：`SendStartMatchRequest()`（Connected 相位守卫）+
  `OnStartMatchResponse` 事件；`BattleClient` 转发。**UI 按钮接线挂账 Unity**（Page_Room.lua 挂账注释

## 续批：房主迁移 + 房间明细投影（同日）

**房主迁移**（房主退房转移裁决——**并行会话外部编辑为主**，本会话补宿主 wire 用例与二义性修复）：
- `ExecuteDisconnect` 房主离席 → `TransferOwner`：owner 位转给**最低 playerId 的其余席位**（任何相位——
  全断线也转，防"回来的人都不是房主"死局）；只剩房主一人则保持（他重连仍是房主）；旧房主重连**不夺回**
  （确定性优先）。`OwnerChanged` 信号 → 宿主可靠广播 → 客户端 `OnOwnerChanged` 事件（UI 换按钮归属）。
- 协议只增：`OwnerChanged{player_id}` + `PacketType.OwnerChanged=15`；BuildHash **两常量**都要重生成——shared
  `d392d83ced326411`（外部已按序重跑）、meta `2b9ab6789263c071`（**快进后会话 `--check` 查出 meta 侧未随批重算**＝心跳构建身份过期，补跑 `gen-build-hash.py` 写齐；出包门禁只盯 shared，故这类漂移不会被拦）。
- 本会话补：`ServerHost` 二义性限定修复（裸 `OwnerChanged` 在 Proto/Runtime 两命名空间二义——编译红）、
  宿主级 wire 用例（房主 Leave → 在座者收 `OwnerChanged` + 新房主开局全链）。
- 用例：Runtime 8/8（外部）· 宿主 4/4（含新增）· LiteNet 未过滤 533/533 · **L1 1626/1626**（快进后会话复核，含 `LobbyRoomDetails` 3 例）。
- 边界：**独房主离席后新加入者不获房主**（"只剩房主一人则保持"的推论——房间死胡同时新玩家可另开
  新房 roomId；如需"owner 永离后新加入者继承"另立批）。
