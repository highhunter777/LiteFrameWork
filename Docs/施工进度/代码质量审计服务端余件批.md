## 1. 房间明细 phase 闸缺陷（必做，①）

**缺陷链**（三处，开工前逐一复核）：
1. `Server/RoomServer/ServerHost.cs:307-318` `RoomSummaries()` 只跳 `Runtime==null`、**不滤终态**；
   而终态（`Transition(Closed)`）到销毁（`TryDestroyTerminalRoom`，`_rooms.Remove` 在随后的 Pump）之间
   房间仍在册——心跳线程读快照可报出 phase=6/7；
2. 契约本来就写"终态房间（已销毁）不报"（`Server/MetaServer/Contracts/Lobby/LobbyContracts.cs:78`）——读面违背自家契约；
3. Meta `InstanceRegistry.cs:139` 硬闸写成 `0..5`（与内核 8 值枚举只靠注释绑）→ 任一行非法**整次注册**
   `InvalidFields` → 一行终态房间毒死整条心跳（实例被清扫出可分配集合）。

**修法（路线1：同源枚举 + 读面过滤；分级 = (a) 维持整次拒绝）**：

| 层 | 改动 | 文件 |
|---|---|---|
| 读面 | `if (room?.Runtime == null \|\| room.Runtime.Closed) continue;`（判据 = 内核 `RoomRuntime.Closed`/`IsTerminal`）+ 文档注释写明契约与竞态窗 | `Server/RoomServer/ServerHost.cs` |
| 相位词汇 | `MatchPhase` 枚举自 `RoomOutput.cs` 移入 `MatchStateMachine.cs`（相位词汇与状态机同文件；该文件纯 BCL 无 using，可被源链接共编） | `Assets/RoomServer/Runtime/{RoomOutput,MatchStateMachine}.cs` |
| 单源链接 | MetaServer.csproj 增 `<Compile Include=…MatchStateMachine.cs>`（与 JoinTicketFormat/Base64Url 同款惯例） | `Server/MetaServer/MetaServer.csproj` |
| 校验闸 | `0..5` 字面量 → 枚举派生：`r.Phase < (int)MatchPhase.Created \|\| r.Phase > (int)MatchPhase.Aborted \|\| MatchStateMachine.IsTerminal((MatchPhase)r.Phase)`——内核新增相位时本闸自动跟随 | `Server/MetaServer/Modules/Lobby/InstanceRegistry.cs` |
| 契约注释 | `RoomReport.Phase` 口径改为"值域与终态判据两端同源、终态不报" | `Server/MetaServer/Contracts/Lobby/LobbyContracts.cs` |
| 生成物 | `gen-build-hash.py`：`META_EXTRA_FILES` 补登 `MatchStateMachine.cs` **与 `Base64Url.cs`**（后者自 P2 引入链接起漏登——见 §3） | `scripts/codegen/gen-build-hash.py` |

**测试**：

  先在册 Running 正证（过滤非误杀）→ Leave 后 `Closed` 且 `RoomCount==1`（销毁前窗口）断言

## 2. GuestLogin catch 分级（②）

**前**：`GuestLoginUseCase.cs:103-107` `catch (Exception)` 全归 `StoreUnavailable`（503）——编程错误与存储故障同形，掩盖 bug
（对照同模块 `ApplyMatchResultUseCase.cs:101-108` 按异常类分捕）。

**后**（三件）：
1. `Contracts/Persistence/AccountStore.cs` 新增 `AccountStoreUnavailableException`（与 `SettlementStoreUnavailableException`
   同款"未确认语义、重试安全"契约；端口注释同步写明"基础设施故障抛本类"）；
2. `MongoAccountStore` 两方法把 `MongoException` 归包为本类（含撞键重读仍不存在分支——原先裸 `throw;` 靠上层 catch-all 兜底）；
3. 用例分捕：`catch (AccountStoreUnavailableException) → StoreUnavailable`、`catch (OperationCanceledException) throw`、
   **其余异常如实上抛**（不冒充 503）。

**测试**：存储故障用例改注入 `AccountStoreUnavailableException`（行为不变）；新增"编程错误如实上抛_不冒充存储故障"。

## 3. 新发现：`META_EXTRA_FILES` 漏登源链接件（本批登记并修复）

`Server/MetaServer/Host/BuildHash.g.cs` = Meta 编译输入摘要，规则要求"csproj 每条出树 `<Compile Include>` 链接
都必须在 `gen-build-hash.py` 的 `META_EXTRA_FILES` 登记"。复核发现 **`Base64Url.cs` 自 P2 引入链接起漏登**
（改它 Meta 身份不动 = 静默失联）；本批把 `Base64Url.cs` 与新链 `MatchStateMachine.cs` 一并补登，并把
"每加一条链接必须同批登记"写进该表注释。Meta 常量因源集变化重录：`121083349e678189 → 6e1192067dc37716`。
