### 9. M1 收尾债：模块资源作用域接入（2026-10-28）

> **债**：M1 建了 `IModuleScope`（Host 每模块建独立 scope、失败/关闭时释放），但产品模块 0 处登记——模块仍各自在 `ShutdownAsync` 手工释放，初始化中途失败的资源无兜底。本批补齐。

- **接入模块**：`InputModule`（设备源 + 输入服务状态）、`ContainerModule`（命令注册 → 根容器 → 场景租约）、`UiServiceModule`（红点登记 + 主题租约；`UIService` 异步关闭仍在 `ShutdownAsync`）、`PresentationModule`（相机/实体/音频/VFX/租约）、`LuaHostModule`（Lua env）。
- **写法**：装配期第一行 `context.Scope.Register(new DelegatedDisposable(DisposeModuleResources))`——初始化失败时 Host 释放该模块 scope 即回收（不再依赖"成功才调用"的 `ShutdownAsync`）；`ShutdownAsync` 只保留异步关闭面（当前仅 `UiServiceModule`）或空实现。
- **顺序保持**：释放序仍是 命令注销 → 容器 → 场景；设备源 → 服务状态；相机 → 实体 → 音频 → VFX → 租约。`ContainerModule` 的原 `catch` 手工清理删除（与 scope 路径重复）。
- **行为差异（有意）**：`UiServiceModule` 的主题租约由 scope 在 `ShutdownAsync`（页面全关）之后释放——页面先销毁、主题引用后归还。
- **守卫**：`ModuleScopeAdoptionTests`（L1）按文件检查五个模块保留 `context.Scope.Register`；删除登记或新增同类漏登记即红。
