## 1. 档位定义（三档）

| 档 | 判据 | 手段 | 生效窗口 | 守卫 |
| --- | --- | --- | --- | --- |
| **热更面** | 单端可变（表现/内容/流程/局外），无每帧或确定性刚需 | 资源/文案/表值（内容候选）；Lua 脚本整套激活；**新增页面/内容/策略**走表登记 + Lua 注册表 + 资源收集组；既有 C# 方法体走 `xLua hotfix` 预埋面 | `NextLaunch`/`SafeWindow`（对局中不换 Match 配置） | 候选校验/签名/健康探针（已有链）；文案键守卫；预埋面"清单 + 签名快照"（本件 §4） |
| **数据面** | 改动两端必须同值（判定数值） | 表 bytes 双端发布（服务端换表重启 + 客户端内容候选） | `NextLaunch` + **新房间固定新快照**、旧房排空 | **已落（批 E）**：`CombatConfigDigest` 覆盖**判定面表字节 + 本局规则位**（覆盖面单源 = `TableLayout.JudgmentDomains`）+ 客户端 `StartGame.ConfigHash` 复算比对（不等拒局）；判定数值已移出 buildHash 编译期闭包 |
| **永不出面（AOT 稳定层）** | 双端共源（服务端也编）／确定性（浮点/整数基线）／引擎直连／所有面的底座 | 出包（应用发布） | — | buildHash 闭包（代码 + 协议 + 生成读码面 + 源链接共编件）+ IL2CPP AOT 确定性 |

**边界原则**：能改行为、能加内容，**不能加 C# 结构**；宿主 API 签名变更 = 应用发布。

## 3. 首批 hotfix 预埋候选（判据 + 示例）

**预埋判据**（四条全满足才入面）：① **同步、非泛型、非 `async`** 方法（xLua hotfix 已知限制面）；② 事件/低频驱动（**无每帧 tick**）；③ 常改或预期常改；④ 边界清晰（只吃显式参数、不长持引擎句柄）。

**首批示例**（具体名单待执行步逐方法核对——判据先于名单）：`BattleHudDriver` 显示规则、`DamageNumberStyleResolver`/`BattleDamageNumberDriver` 样式与阈值、`HitFeedbackDispatcher` 路由规则、`LaserSightPolicy` 武器支持位、`App/Meta` 的失败处置策略。

**明确不入预埋面**：`Procedure*` 的 `RunAsyncCore` 族（async）、Sim/协议、框架核心、任何每帧方法。

## 4. 守卫机制（预埋清单 + 签名快照）——设计要点

- **生成物**：扫描预埋 attribute → 产出「清单 + 每方法签名快照」（类型/方法名/参数与返回类型），进版本库；
- **比对门禁**：清单缺失、签名漂移、方法被删或改名 → **L1/纪律扫描红**（`xlua.hotfix` 找不到方法只 warning——**静默失效**必须被机制挡）；
- **同族先例**：`ScanTargets.cs`（纪律目标清单）、`gen_lua_keys.py`（登记表 → 常量）、`BridgeCapabilitySet`（能力声明 + 探针）；
- **IL2CPP**：预埋面 `link.xml` 保留；hotfix 生成代码随包（AOT 侧）；
- **补丁交付**：补丁脚本走 Lua 内容通道（候选校验/签名/安全窗口激活同链，§7/§8）。
