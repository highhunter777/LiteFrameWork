# 对象池高级化：施工进度

> 依据：[《对象池专项设计》](../设计文档/architecture/对象池专项设计.md)（目标契约与收编清单以设计为准，本文件只记录施工状态与证据，不在此重复定义）。
> 背景：LiteFramework 池内核 `ObjectPool<T>` 的 §2 基线直测自初始提交随库（`ObjectPoolTests` 20 例——设计 v1.0"此前零直测"系笔误，2026-10-03 执行时实测发现并已修正设计 §6 表述）；`ReferencePool`/`GameObjectPool` 零直测属实；内核缺淘汰策略、空闲过期收缩、借出验证与命中率统计；`EntityViewMap`/`FlyTextPool`/`Toast` 各写各的 Stack 池不走内核（无上限/无统计/无生命周期接口）；`EntityService.ShowAsync` 首建路径 `OnSpawn` 双调用（池已驱动又手动调一次，池命中路径只有一次——潜伏缺陷，全仓尚无 `IPoolLifecycle` 实现类故未显性化）。
引用池（`ReferencePool`）现状（2026-10-03 检查）：统计全在 Debug 三宏内（与内核"计数器不做条件编译"裁决不一致）、无命中率/淘汰策略/整体清空；消费者是 `EventCenter`（派发完对实现 `IReference` 的事件 `Release`，可选实现）。基线直测 6 例已在库（`ReferencePoolTests`——同日执行核证，"零直测"表述系笔误，与内核同型错误，已修正设计 §7 口径）；批4 扩充至 12 例。

## 边界（登记，非本专项范围）

- kcp2k vendor `Pool<T>`（Vendor 隔离，不互染）；`GameFramework` 第三方池套件（无引用死资产，清理另行）。
- 定容环家族（`PendingInputRing`/`InputHistory`/`SnapshotRing`）是槽位复用存储非对象池，不收编。
- `UIService` 表单缓存策略层（Recycled 原位停用 + LRU 淘汰 + 租约语义）保持自有。
- 集合池的既有"调用方持实例 Clear 复用"点（如 `RoomRuntime.Execute` outputs）不强制迁移，新代码优先走池。
- `EntityViewMap.Release` 的 `[Diag] 视图回收` LogWarning 为既有临时诊断哨位，本批未动（去留另行）。

## 施工记录（2026-10-03，四批交付；批1–3 见下，批4 附后）

### 批1 内核升级

- `ObjectPool<T>`（`Assets/LiteFramework/Scripts/Core/Pool/ObjectPool.cs`）：
  - `PoolEviction` 枚举（`DropNewest` 默认 / `EvictOldest` 满池淘汰队首最旧 + `EvictedCount`，与 `DroppedCount` 不混用）；
  - 平行时刻队列（`_idleAtMs`，与空闲队列同进出序；`Release(obj, nowMs = 0)` / `Preload(count, nowMs = 0)` 时刻由消费方传入）+ `TrimExpired(nowMs, maxIdleMs)` 按龄收缩（消费方驱动，内核零时钟；边界为严格大于）；
  - `validateOnAcquire` 借出验证（失效即销毁计 `InvalidatedCount`、继续取下一件、池空转 create；**先于 onGet/OnSpawn**；验证回调抛异常记日志销毁后继续）；
  - 统计追加 `PoolHits`/`EvictedCount`/`InvalidatedCount` 进 `IModuleStats.Snapshot`（Misses = Acquired − PoolHits 不另建键）；
  - 新增契约：create 返回 null = 工厂拒绝（不回调不计账，调用方按 null 处理）——收编 `EntityViewMap` 可空工厂必需（产出必须经 Acquire 登记，否则 Debug 重复归还检测误伤）；
  - §3.5 兼容红线：默认参数逐位一致（源兼容：新参数全部为可选尾参，`GameObjectPool` 等既有调用点零改动）。
- 直测：`ObjectPoolAdvancedTests`（21 例：淘汰两策略/过期收缩含边界与预热/验证回调含先序与全失效/统计口径/回调顺序/异常回滚/重复归还）。

### 批3 收编与缺陷修复

- `EntityViewMap`：`Dictionary<string, ObjectPool<GameObject>>` 每 location 一池（onGet=激活、onRelease=停用+挂回战斗域 _root、onDestroy=编辑 Immediate/Play 延迟口径、`validateOnAcquire: go != null` fake-null 防御、`statsName = EntityViewMap.{location}`、`poolMaxIdle` 可配默认 32）；**recycler 两态语义不变**（外部回收方接管时不入本地池）；`ClearPool` 走各池 Clear（原零调用面死 API，保留为排空入口）。
- `FlyTextPool`：`Stack<TMP_Text>` → 懒建 `ObjectPool<TMP_Text>`（maxIdle=PoolDepth 语义保留；复位 alpha/停用进 onRelease；模板 CanvasGroup 随 prefab 序列化红线原样保留）；`Show` 激活移入 onGet。
- `Toast`：`Stack<RectTransform>` 无上限 → 懒建 `ObjectPool<RectTransform>`（maxIdle=MaxVisible；Retire 复位进 onRelease；新增 `PooledCount` 诊断面）。懒池在首次 Show 定型——`MaxVisible` 运行期变更不追溯已定型池（"调容量是配置不是运行时行为"同 §2 口径）。
- **缺陷修复（§5.1）**：`EntityService.ShowAsync` 首建路径删除手动 `OnSpawn`（`GameObjectPool.Get` 已驱动——两路径对齐为各恰一次）。

### 批4 引用池升级（2026-10-03，设计 §7 契约）

- `ReferencePool`（`Assets/LiteFramework/Scripts/Core/Pool/ReferencePool.cs`）：
  - **统计无条件化**（§7.1）：桶计数（Created/Acquired/Released/PoolHits/PeakUnused/Dropped/Evicted）移出条件编译；**保持 Debug-only 两处**——`Using` 哈希集（重复归还检测，"release 信任 Debug 全绿"契约不变）与 `GetAllInfos()`/`ReferencePoolInfo`（HUD 面）；`ReferencePoolInfo` 追加 `CreatedCount`/`EvictedCount`/`PoolHits` 字段（可选尾参，HUD 消费方兼容）；
  - **per-type 淘汰策略**（§7.2）：`SetEviction<T>(PoolEviction)`（与 `SetMaxSize<T>` 同型；默认 `DropNewest` = 现状；`EvictOldest` 淘汰队首最旧、新归还件入池——`EvictedCount` 记账，与 `DroppedCount` 不混用，同内核 §3.1 口径）；
  - **整体清空**（§7.3）：`Clear<T>()`（未注册类型 no-op 不建桶）与 `ClearAll()`——被清件只丢弃不走第二次 Clear（与 Trim 同口径），在途件不受影响，幂等；
  - **非目标登记**（§7.4）：validateOnAcquire（纯 C# 数据无 fake-null 场景）、TrimExpired（MaxSize 已兜内存，无消费方驱动场景）——代码注释同步登记。

### 过程实测（踩坑登记）

- **执行中覆盖了随库基线测试**：批1 初版把新直测写进既有 `ObjectPoolTests.cs`（20 例，初始提交随库）导致整文件被覆盖、基线用例消失——L1 计数异常（+28 只 +8）暴露，trx 名单 diff 定位后**从 HEAD 原样还原基线文件**，高级化用例拆分至 `ObjectPoolAdvancedTests.cs`，零净损失。
- xunit 2.9.2 的 `Assert.Equal/Same/Empty` 无 message 第三参（v3 特性）——L1 直测断言统一改为两参 + 消息挂 `Assert.True`。
- 测试替身的故障注入标志需按**故障类型分离**（OnDespawn 故障与验证失效共用一个标志 → OnDespawn 先炸导致用例永远走不到被测路径，Invalidated 恒 0）。
- 单对象"取-还"循环不积累空闲（每轮净 1）——TrimExpired 多件断言须先取多件独立在用再逐件归还。
