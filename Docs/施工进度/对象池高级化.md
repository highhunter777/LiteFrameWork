# 对象池高级化：施工进度

> 依据：[《对象池专项设计》](../设计文档/architecture/对象池专项设计.md)（目标契约与收编清单以设计为准，本文件只记录施工状态与证据，不在此重复定义）。
> 背景：LiteFramework 池内核（`ObjectPool<T>`/`ReferencePool`/`GameObjectPool`）此前零直测；`EntityViewMap`/`FlyTextPool`/`Toast` 各写各的 Stack 池不走内核（无上限/无统计/无生命周期接口）；内核缺淘汰策略、空闲过期收缩、借出验证与命中率统计；`EntityService.ShowAsync` 首建路径 `OnSpawn` 双调用（池已驱动又手动调一次，池命中路径只有一次——潜伏缺陷，全仓尚无 `IPoolLifecycle` 实现类故未显性化）。

## 批次规划

| 批 | 范围 | 状态 |
|---|---|---|
| 批1 内核升级 | `ObjectPool<T>`：淘汰策略 `PoolEviction { DropNewest 默认, EvictOldest }`、空闲过期收缩 `TrimExpired(nowMs, maxIdleMs)`（消费方驱动）、借出验证 `validateOnAcquire`、统计追加（PoolHits/Evicted/Invalidated）；`Tests/LiteFramework.Core.Tests/ObjectPoolTests.cs` 直测补缺（默认行为兼容断言钉死） | **规划中** |
| 批2 集合池家族 | `CollectionPool<TCollection,TItem>` 内核 + `ListPool<T>`/`DictionaryPool<K,V>`/`HashSetPool<T>` 静态门面（maxIdle 默认 8）；L1 测试；不迁移既有业务点 | **规划中** |
| 批3 收编与缺陷修复 | `EntityViewMap`（Stack→每 location `ObjectPool<GameObject>`，validateOnAcquire 防御，recycler 两态不变）、`FlyTextPool`（depth16→maxIdle）、`Toast`（maxIdle=MaxVisible）、删 `EntityService.ShowAsync` 首建手动 OnSpawn；EditMode 回归 + 容量/统计新断言 | **规划中** |

## 边界（登记，非本专项范围）

- kcp2k vendor `Pool<T>`（Vendor 隔离，不互染）；`GameFramework` 第三方池套件（无引用死资产，清理另行）。
- 定容环家族（`PendingInputRing`/`InputHistory`/`SnapshotRing`）是槽位复用存储非对象池，不收编。
- `UIService` 表单缓存策略层（Recycled 原位停用 + LRU 淘汰 + 租约语义）保持自有。
- 集合池的既有"调用方持实例 Clear 复用"点（如 `RoomRuntime.Execute` outputs）不强制迁移，新代码优先走池。
