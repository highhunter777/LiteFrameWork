**⑤ 广播/重组/重连路径（LiteNet.Protocol + RoomServer）**

- `SnapshotCodec`：`PackMatch`/`PackPrivate`/`ApplyPrivate` 单源；`PackFull` 附 Match + 公共口径 checksum；`ToDelta/FromDelta` 扩公共战斗面与主动作摘要。
- `SnapshotDiffer`：摘要基线扩至公共面全字段（漏一个 = 差分漏发静默分叉）；`BuildFor` 按会话附本人 PrivateState；移除 `BeginFrame` 中无消费者的全量 checksum 死计算（P0 后每帧多算全部运行态，纯浪费）。
- `SnapshotReassembler`：**持久镜像语义**（增量只在常驻镜像上累积才完整——每包新建镜像会把未携带槽位清零）；全量清零扩展到新数组；`OverlayPrivateAndMatch` 原语（预测正确、不和解时仍刷新本人私有面/比赛状态——这些量客户端不预测、只能来自快照）。
- `ServerHost.HandleReconnect`：重连响应 = 公共全量 + 比赛状态 + **本人私有状态** + 输入历史（§5.6 顺序）；`RoomClient` 新增 `OnReconnectResponse` 事件（此前该包被静默丢弃）。

**审查修复（实施中定位的真缺陷）**

- `SnapshotReassembler.Apply`：分配器重建（`SetAllocatorIdleSlot`）必须先于私有面应用——`ApplyPrivate` 经 `TryResolve` 定位本人槽位，顺序颠倒则解析必失败、私有面静默不落地（用例当场抓获）。
- `RoomServer.InputGate._pending`：帧号单键会让多玩家同帧输入互相顶替（先到者被后到者覆盖，`TryConsume` 只有一人拿到输入）——改为 `(playerId, frame)` 复合键（回归用例：`多玩家同帧输入_互不顶替_各取各的`）。
- `SnapshotDiffer` 变化集条件一次误反（`!Matches`）——被"静止场景增量恒 2 / 增量重建镜像停更"两处用例夹击定位，已修正并有既有用例看守。
