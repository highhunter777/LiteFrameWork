# 目录收敛施工进度：DevHUD 并入 Editor、Luban 生成物归拢 GameData

> 依据：《客户端总设计》§5 顶层框图（LiteGame 下应是分层代码目录）、§14.1（可重复依赖与生成物）、
> §22 禁止的重构方式（不做大爆炸式搬迁，分层边界要有名有姓）；`ScanTargets.LiteGameTopLevelDirs`
> 的既定纪律"新增顶层目录必须登记并说明属哪一层，未登记即报红——目录一变就红"。
> 本文件只记录施工状态与证据；目标与验收以设计为准，不在此重复定义。

## 起因

两处顶层目录长期是"历次拆分自然长出来的"，不是分层决策的结果：

1. **`Assets/LiteGame/DevHUD/`**——独立的 `LiteGame.DevHUD` 程序集（全平台 + 三宏 `#if`），
   里面只有两个开发面工具（`DevHUD` 全屏 stats、`SimSandbox` 灰盒沙盒）。
2. **`Assets/LiteGame/RawFile/Config/`**——Luban `gen.bat` Pass 1 的 bin 产物落地处，
   同时也是 YooAsset 收集组路径与两端 buildHash 的客户端表数据源。名字还与引擎概念撞车：
   `RawFileObject`/`LoadRawFileBytesAsync` 是 **YooAsset 的 raw file 容器**，与本目录不是一回事。

## 裁决（2026-09-26）

| 项 | 裁决 | 后果（明确知情） |
|---|---|---|
| DevHUD | **并入 `LiteGame.Editor`**（Editor-only 程序集），删 `LiteGame.DevHUD.asmdef` | **构建 Player 时整程序集不进包**——dev 包/冒烟里不再有 HUD 与 SimSandbox；真机上验不了 Sim（需要时再单独拆运行时程序集） |
| RawFile | **移到 `Assets/GameData/Config/`**（与代码侧产物 `Generated/` 同域），LiteGame 回归纯代码层 | 路径参与 buildHash → **hash 必变**（两端握手常量同步更新）；YooAsset 收集组需重收资源包 |

**过程中被守卫抓到的一处漏改**：第一次只改了 `BuildHashTests`，漏了 `CombatNumbersTests` 里
同样硬编码的 bin 路径——`客户端bin产物存在` 当场红。这正是 §14.1"生成物/路径单源"想要的效果：
路径不是文档约定，是**可执行断言**。

**未做与边界**：

1. **`Assets/BundleCollectorSetting.asset` 改了但资源包未重收**——`Bundles/` 里仍是旧路径的产物。
   重收属发布动作（`gen-candidate` / 构建流程），不在本批；**在重收之前，Player 的 Offline 包
   仍按旧路径取表**（编辑器内走 EditorSimulateMode 不受影响）。留作下一批或随下次构建自然更新。
2. **服务端 json 产物位置未动**（`RoomServer/Data`）——那是 RoomServer 的部署产物，不在 Assets 下，
   本次裁决范围只到客户端侧。若日后要"三份产物同域"，那是独立裁决（会把服务端数据拉进 Assets）。
3. **`Assets/LiteGame/Lua/Cfg/` 未动**——它是 Lua 侧产物 + 业务脚本的混合目录，挪动会牵动
   LuaPreloader 的 `LuaDir` 单源与收集规则的放行分支，收益与风险不成比例。
