## 外接模式（进程级验证，2026-10-13）

同一条链**在真 OS 进程上跑通**（不止同进程托管）：用例内新增 `上云回环_外接进程_真链跑通`（env 门控），指向已起的 `MetaServer` + `RoomServer` 进程。

- **启用**：`LITELOOP_META_URL=http://127.0.0.1:5055`、`LITELOOP_ROOM_PORT=17888`（可选 `LITELOOP_KILL_LIMIT=3`，须与外部房间配置一致）。
- **与同进程用例的差别**：外部进程内权威态**不可读** → **唯一可观测面＝客户端镜像**（镜像驱动开火：目标位取镜像、帧号取镜像最新帧+2）；对账降为**两面**（客户端观测 ↔ Meta 落库），权威面由外部服务器日志/指标印证。同进程用例保持三面对账、未改动。
- **本机起进程**：`dotnet Server/MetaServer/bin/Release/net8.0/MetaServer.dll`（`:5055`，`META_Meta__*` 注入回环密钥 + 宿主 Mongo）+ `dotnet Server/RoomServer/bin/Release/net8.0/RoomServer.dll --config <回环配置>`（`:17888`，2 人 / `kill_limit=3` / 无出生保护；`LITENET_*` 注入与用例同值的四把回环密钥）。回环配置与密钥落在 `TestResults/extloop/`（本机联调，不入库）。
- **结果**：外接测试 **1/1 通过**（61s）。服务器侧证据：Room→Meta `POST /lobby/instances/register → 200`；房间服 Ops `room=loop-ffa … players=2 … match transitions=3`；`[Match] … Finishing->Settling reason=settle`；Meta `POST /matches/result → 200` + 随后多次 `GET /matches`；`Outbox/settlements.journal` 落盘。

**附注**：`deploy/` 容器制品同链可跑，但其 `standard` 模板是 20 杀 + 出生保护（不适合快回环），故本机整链走**本地进程 + 回环专用配置**；另外启动时发现容器镜像偏旧（`buildHash=d392d83ced326411` ≠ 当前 `ccc7cdb85bc51cba`），已 `--build` 重建。
