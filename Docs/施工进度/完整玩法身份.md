## 2. 口径（三档输入各归其守卫）

| 输入 | 守卫 |
|---|---|
| 代码侧判定常量（烘焙导出/算法常量）、协议、生成读码面、源链接共编件 | buildHash 闭包 + Join 握手（AOT 稳定层，永不出面） |
| 判定面**表字节** + 本局规则位（免死/无限子弹） | `CombatConfigDigest` 运行期摘要 + 客户端 `StartGame.ConfigHash` 复算比对 |
| 表现/内容表（UI/Content/Strategy/Animation） | 内容发布链（候选校验/签名/健康探针）；不换联机身份 |

**规范文本**（两端同源，单源在本类）：基摘要 = `gameplay-digest-v1` + 逐表一行 `<相对路径> <表字节 SHA-256 全量 hex>`（顺序 = `TableLayout.JudgmentFiles` 声明序）；终值 = `gameplay-rules-v1` + 基摘要 8 hex + 两行规则位；取 SHA-256 低 32 位 = proto `uint32`。表字节按**原始字节**喂哈希（`.bytes` 由 git 判为 binary（`-text`），跨机器 checkout 逐字节一致）。**文本里不含浮点**（避免跨运行时 `"R"` 格式差异）——数值全走表字节/hex。

## 5. 未验前提（如实）

- **两端真发布复验未做**：本批验的是"装载后摘要复算 + 拒局路径"（L1/EditMode 覆盖）与"闭包重划后出包门禁口径"；真环境走一遍 §11 发布顺序（服务端换 `.bytes` 重启 → 客户端内容候选 → 新房间固定新快照）仍须真 CDN/真签名候选环境——文档口径：**不把"能热更"当"已发布验证"**。
