## 定位与范围

本批交付的是**开发形态**而非产品能力：客户端动战斗代码不再必须先起 `RoomServer` 进程
（此前端点硬编码 127.0.0.1:17777，起不来则 `ProcedureMatch` 十秒超时根本进不了对局），
DebugTuner 打开开关即自带权威端跑完整闭环。

**真实边界（别把"本地绿"当"联机绿"）**：真 Sim 判定 / `InputGate` 校验 / 快照差分与 AOI /
协议编解码 / 会话相位机；假 Socket（无丢包/乱序/延迟/MTU）/ 假票据（非空即可）/ 单房间 /
**自动补位**（站桩对手）/ 无多房间、排空、Ops、持久化 / 时间轴自走。弱网、断线重连真实性、
多房间隔离与**真实多人交互**仍须在**真服务器**验（L3 与两房用例覆盖）。

  - **真内核**：`RoomRuntime` + `SnapshotPipeline` + `InputGate` 与服务端宿主**同一份源码**；
    映射只有 `Join → JoinAck`、`MatchStarted → StartGame`、`Tick → 快照广播`——对应

    `ServerHost.HandleInput` 同口径——不接 ACK 闸则差分基线不前推、每帧全量；
  - **OnConnected 泵补发**：真 KCP 的连接完成是 Tick 驱动异步过程；本地若在 `Connect()` 内同步发，
    Join→JoinAck 全链会在 `BattleClient` 构造内跑完，客户端 JoinAck 边缘事件在订阅者
    （`WaitJoined`）挂好之前就发掉——本地模式必超时。挂起至 `TickIncoming` 补发，时序对齐真传输；
  - **自动补位**（用户裁决）：真客户端进房后剩余席位由假连接补满（`FillRoomWithBots`），满员即
    `MatchStarted`；补位者永不发包＝权威循环空输入站桩、不占本地号位、不出进房事件包、快照管线
