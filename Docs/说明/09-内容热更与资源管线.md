## 1. 三条互不替代的事实链

内容正确性由三条互不替代的链构成：

```text
代码一致性 → BuildHash（共享源集摘要）        → Join 握手
数据一致性 → CombatConfigDigest（判定面表字节）  → StartGame.ConfigHash
内容可信性 → 清单签名（描述）+ 逐文件摘要（字节）→ 候选校验 + 激活事务
```

- **代码**：改 `Assets/LiteSim/{Scripts,Systems}`、`Assets/LiteNet/Core/{Proto,Protocol,Transport/Security}`、`Assets/GameData/Generated`（生成读码面）或共享链接件，必须重跑 `python scripts/codegen/gen-build-hash.py`；该脚本一次写两个常量——`Assets/LiteNet/Core/Protocol/BuildHash.g.cs`（共享源集）与 `Server/MetaServer/Host/BuildHash.g.cs`（Meta 构建身份，不参与准入）。出包门禁复算用 `--check-shared`，发布 Meta 前用 `--check`。
- **数据**：判定面表**数值**可两端热更、不必出包；客户端装载后按 `StartGame.ConfigHash` 复算比对，不等拒局。
- **内容**：签名只保"清单描述没被篡改"，逐文件摘要只保"字节与清单一致"；两门都过才允许激活。

混为一谈会误判："签名过＝内容对""哈希没变＝表没改"。握手与对局侧的细节见 [06-联机同步与网络协议](06-联机同步与网络协议.md)。

## 2. 内容访问模型：租约 + 代次 + 共享加载

### 2.1 端口与租约

`IContentService`（`Assets/LiteFramework/Runtime/Modules/Content/Abstractions/ContentServiceContract.cs`）是内容访问唯一入口：`AcquireAsync(location, type)` 返回 `AssetLease<T>`（带引用计数）。`AssetLease<T>` 落在 Core（`ContentContracts.cs`，零引擎依赖，故 L1 可直接测）：`Dispose` 幂等且只首次回调，引用计数由 Host 维护，末位释放才允许卸载底层，释放后资产对象不得再使用。

### 2.2 代次是缓存键的一部分

`ContentGeneration`＝`(ReleaseId, 单调 Value)`，内置代次 `("builtin", 0)`（`ContentGeneration.Default` / `BuiltinReleaseId`）。加载与缓存键包含代次，因此旧代次租约继续有效、不被热更抽走；新获取走新代次，自然命中新内容；不需要"全局卸载再重载"这种会打断对局的操作。代次推进由 `PatchCoordinator` 在确认提交后经 `IGenerationSink`（`YooAssetContentService.Advise`）执行。

### 2.3 共享加载

`SharedLoadCoordinator`（`Modules/Content/SharedLoadCoordinator.cs`）处理同一 location 的并发请求：

| 场景 | 行为 |
|---|---|
| 同键并发 | 只加载一次，等待者共享结果 |
| 等待者取消 | 只退本人；全员退出才弃置并尽力取消底层 |
| **迟到结果** | 就地卸载，**不发出租约**（避免没人要的资产泄漏） |
| 引用归零 | 卸载恰好一次 |

### 2.4 YooAsset 适配与页面级缓存

`YooAssetContentService`（`Assets/LiteFramework/Runtime/Adapters/YooAsset/`）把 `(代次, location, Type)` 映射为 YooAsset 句柄：类型不符先归还句柄再抛（不留半截引用）；`LiveEntries` 供泄漏断言。`PrefabLeaseCache` 是另一种语义：同 location 共享一份租约、常驻到 `ReleaseAll`，按 location 归零卸载尚未实现——适合页面级复用，不适合临时对象。

## 3. 配置表：从 xlsx 到两端同一份字节

### 3.1 生成链与布局单源

```text
Luban/Data/#*.xlsx + Map/*.json
  → Luban/gen.bat（= scripts/codegen/gen_luban.py）
      ├─ Assets/GameData/Generated/*.cs       读码面（进 BuildHash）
      ├─ Assets/GameData/Config/{域}/*.bytes  表数据（两端同读）
      └─ Lua Cfg + LuaKeys（Luban/gen_lua_keys.py）
```

`TableLayout`（`Assets/LiteGame/Modules/Config/TableLayout.cs`，客户端与服务端源链接共编）是布局单源：`DataDir = Assets/GameData/Config/`；`Files` 声明 12 张表——`Item/tbitemconfig`、`Movement/tbmovementconfig`、`Entity/tbentityconfig`、`UI/tbuiform`、`UI/tbltext`、`UI/tbcrosshair`、`Content/tbcontententry`、`Strategy/tbstrategy`、`Combat/tbcombatnum`、`Combat/tbweapon`、`Animation/tbanimationprofile`、`Map/tbmap`，共 9 个域（Item、Movement、Entity、UI、Content、Strategy、Combat、Animation、Map）。新增表＝在 `Files` 加一行"领域/表名"，再跑 `Luban/gen.bat` 与 `gen-build-hash.py`；`TableDataPath(file)`、`TableName(file)`（裸表名，装载缓存键）是拼接与取键的单源。

### 3.2 装载与原子发布

`ConfigService`（`LiteGame/Adapters/Luban/ConfigService.cs`）三段式：① 候选字节预取（缺表 fail-fast，报错带完整 location）→ ② 候选建表（Luban 同步解析，失败不触碰已发布状态）→ ③ 校验（`tbcombatnum` 单行表等全表约束）+ 玩法数值回填 + `ConfigSnapshotService` 原子发布。发布先 validate 再 lock 替换，`Version` 单调 +1；失败抛且 `Current` 不动——不会出现"半张新表"。`Loaded`/`CurrentSnapshot`/`GameplayDigestBase` 是对外读数。

两端共读同一份 `.bytes`：客户端经 `IContentService` 租约取字节，服务端 `ServerTableLoader` 直读盘，`TableLayout` 与 `SimConfigMapper` 源链接共编，故同一份文件必得同一摘要。配置装载在 `ProcedurePreload` 首步，早于 Lua 预载（见 [08](08-UI与Lua脚本层.md)）。

### 3.3 玩法数据身份

`TableLayout.JudgmentDomains = Combat / Movement / Entity / Item / Map`（**5 域**，UI/Content/Strategy/Animation 属单端热更面，不进身份），由 `Files` 声明序派生 `JudgmentFiles`（6 张表：`tbcombatnum`、`tbweapon`、`tbmovementconfig`、`tbentityconfig`、`tbitemconfig`、`tbmap`）。`ComputeGameplayDigestBase(bytesByTableName)` 缺字节直接抛（清单与取数口径漂移是静默退化入口，宁 fail-fast）；算法单源在 `LiteSim.CombatConfigDigest`。

## 5. 热更事务

### 5.1 分工

| 件 | 角色 |
|---|---|
| `ProcedurePatch` | 主链：调编排 → 失败进 Error → 资源包初始化 → 入口探针 → 进 Preload |
| `PatchRunner` | **薄编排**：取候选 → 无候选也走一次恢复 → 信任门 → 生效窗口 → 交协调器 |
| `PatchCoordinator` | **阶段状态机**：10 个 `PatchPhase`、顺序不变量、失败留档与回退 |
| `ActivationTransactionStore` | 激活记录：三态、事务 ID、恢复计数、完整性盖章 |

`ProcedurePatch` 的实际顺序：① `PatchRunner.RunAsync`（无 runner 时退化为只跑 `RecoverOnStartup` 并打状态日志）→ ② `IContentService.InitializeAsync`（当前 Confirmed 代）→ ③ 入口资源探针（`AssetsHealthProbe`，走与运行时同一条租约通道，入口取 `LiteGame.View.SimView.DefaultEntityPrefab`）→ ④ `Request(Preload)`。

### 5.2 十阶段与顺序不变量

```text
Idle → Recovering → PrecheckingSpace → Fetching → Verifying
     → PendingActivation → Activating → HealthChecking → Confirmed
任一阶段失败 → Failed（保留已确认版本）
```

三条顺序不变量（每一步都落盘，崩溃后可判断"走到哪"）：

1. **`BeginCandidate` 先于下载**：先把候选事务写盘再拉文件，中途崩溃即能识别"有一个未完成候选"。
2. **`MarkPendingActivation` 先于激活**：激活前落盘，崩溃后可判断"是否已切过"。
3. **`Confirm`+`Advise` 最后**：健康检查通过才推进代次、清理 Pending。

失败一律保留允许版本：① `RecordFailure` 留档 → ② 重建已确认代次 → ③ 返回 `PatchRunResult.Failed`（`FinalPhase`＝失败发生的那一阶段，是定位依据；`NoWork` 表示无候选、按已确认版本继续启动，不算失败）。

### 5.3 失败恢复与记录 IO

- 只有 **HealthChecking 失败** 才 `RebuildConfirmedAsync`（Shutdown + Initialize，经 `ContentActivator`），其它阶段失败保留 Confirmed。
- `ActivationTransactionStore`：`MaxRecoveryAttempts = 3`，启动 `RecoverOnStartup` 发现在途即回退到 Confirmed，超限放弃并留档；每次写盘 `RecordSequence++` 并做完整性盖章，用于识别旧记录/回填。恢复语义是**放弃在途、以 Confirmed 继续**（远程重取尚未接线）。
- `FileActivationRecordIO`：缺文件/解析失败/结构版本不符/完整性不符 → 返回 null（回 builtin）；Save 走 `FileSystem.WriteJson`。注意 `ActivationRecord.ConfirmedRevision` **未并入完整性摘要**——反回退只提高门槛，不是安全边界。

## 6. 信任：签名与摘要两门分离

| 门 | 时机 | 保什么 | 失败 |
|---|---|---|---|
| **签名**（RSA-2048 + PKCS#1 v1.5 + SHA-256） | 下载**前**验清单 | 清单描述（版本、条目、摘要、平台、过期、撤销） | keyId 未登记/已撤销或签名不符 → 拒候选 |
| **摘要**（逐文件 SHA-256） | 下载**后** | 文件字节与清单一致 | 长度/摘要/多余文件/重复路径 → 拒候选 |

### 6.1 校验顺序

`ReleaseManifestValidator.Validate` 的十步**顺序即安全**：① 结构/schema（`ReleaseManifest.CurrentSchemaVersion = 1`）→ ② releaseId → ③ 路径与预算 → ④ 条目字段（长度非负、摘要 64 位小写 hex）→ ⑤ 过期 → ⑥ 撤销 → ⑦ 签名 → ⑧ 反回退 → ⑨ 平台 → ⑩ 兼容。签名在路径/预算之后（先拒廉价畸形输入），但**在依据描述做任何下载之前**。签名对象是清单**原始字节**（`signedBytes` 不做换行归一化）。

### 6.2 预算、锚点与生效窗口

- `ReleaseBudget` 默认：`MaxFileCount=4096`、`MaxFileBytes=512 MB`、`MaxTotalBytes=4 GB`、`MaxPathDepth=16`、`MaxPathSegmentLength=128`。
- 公钥来源：编入应用本体的锚表 `ContentTrustAnchors`（1 条 `release-key-2026-09-26`，RSA-2048，e=65537），经 `ApplyTo(TrustedKeyStore)` 登记；未登记/已撤销 → null → fail-closed。撤销只能随下一版内置表体现（写可写存储的撤销清单会被篡改）。
- 私钥：签名机用户目录 `~/.unitylib-content-signing/...xml`，仓库外、绝不入包；签发后用内置锚点 modulus 自校验。
- 反回退：`Revision < ConfirmedRevision` 拒，基线取 `ActivationRecord.ConfirmedRevision`。
- 生效窗口 `ReleaseEffectWindow` 三值，但 `ValidateEffectWindow` 当前只放行 `NextLaunch`；`SafeWindow`/`NextMatch` 与 LiveRefresh 未实现。

### 6.3 Lua 候选沙箱

`CandidateLuaValidator`（`Assets/LiteFramework/Runtime/Adapters/XLua/Lua/`）用**独立 `LuaEnv`** + 每脚本新建 fenv：回收 `CS`/`require`/`io`/`os`/`debug`/`package`/`loadlib`/`dofile`/`loadfile`/`load`，白名单只留基础函数与 `table/string/math/coroutine/bit/utf8`；`log` 是无副作用桩；受限 `require` 只认本批候选集合、遇环即拒、标准库按 `package.loaded` 语义放行。**不执行 main**，只做语法与模块级加载验证。边界：无 `debug` 加固、无指令计数/超时——防误用，不防恶意脚本。

## 7. 候选包工具链

### 7.1 脚本

| 脚本（`scripts/content/`） | 输入 | 输出 |
|---|---|---|
| `gen-candidate.py` | `--content-dir`（只收 `config/**`、`lua/**.lua`、`bundle/**`）+ `--release-id` + `--revision` + 私钥 + `--anchors-cs` | 紧凑 JSON 清单 + 签名信封 `{"manifest":…,"signature":"<base64>"}`，默认落 `content/candidate.json` |
| `publish-candidate.py` | 内容目录 + `--cdn-root`（缺省读 `local-cdn.json` 的 `directory`）+ 可选 `--bundle-source` | `{cdn}/{releaseId}/**`、bundle 段镜像、`{cdn}/candidate.json` |
| `serve-cdn.py` | 同一配置 | 本地 HTTP 服务（Ctrl+C/130 视为正常停止） |
| `_local_cdn.py` | `scripts/content/local-cdn.json` | 配置装载：`directory=LocalCDN`、`bind=127.0.0.1`、`port=18090` |

`gen-candidate.py` 其它参数：`--expires-in-days`（默认 30）、`--platform`、`--key-path`（默认 `~/.unitylib-content-signing/release-key-2026-09-26.xml`）、`--key-id`（默认 `release-key-2026-09-26`）。`publish-candidate.py` 默认 `--release-id rel-local-001`、`--revision 1`。

### 7.2 内置包与候选包

- **内置包**：`BuiltinBundleBuildInvoker`（`Assets/LiteGame/Editor/Resource/`）用 SBP 构建 `DefaultPackage`，版本号 `1.0-yyyyMMddHHmmss`（每构建唯一化），`ClearAndCopyAll` 复制到 `StreamingAssets/yoo`。工具 id `content.bundle-builtin`；Player 构建前必须先跑，否则缺 `BuiltinCatalog` 会在 Preload 失败进错误 UI。
- **候选包**：工具 id `content.bundle-candidate` → `RunForCandidateFromMenu` → `RunForCandidate`（`EBundledCopyOption.None`，**不覆盖内置包**），产物目录经 `LastOutputDirectory` 记录，再经 `publish-candidate --bundle-source` 打成候选 `bundle/` 段。异步入口 `RunCandidateAsync` 当前无调用者。

### 7.3 运行期包根二选一

`AssetService.InitAsync(builtinPackageRoot)`：编辑器走 `EditorSimulateMode`（模拟构建 + 编辑器文件系统），Player 走 `OfflinePlayMode`（Host/Web 模式与网络下载流程未实现）。包根选择 `CandidateBundleRootResolver.IsCandidateBundleReady`，两条同时成立才用候选根 `{persistentDataPath}/content/candidate/bundle`：① 激活记录的已确认 `ReleaseId` 不是 `builtin`；② `<候选根>/bundle/DefaultPackage.version` 存在。缺一退回 `StreamingAssets/yoo`（fail-safe，包不完整时宁可退内置也不让初始化裸失败）。

候选根布局单源 `ReleaseLayout`：`content/candidate` 下 `config/`（表字节）、`lua/`（热更脚本）、`bundle/`（YooAsset 包根镜像）；Lua 模块名＝require 点分名（剥 `lua/` 前缀与 `.lua`、`/` 归一化为 `.`），与 `LuaPreloader` 的斜杠缓存键区分。

## 8. 现状：兑现、未接线、未验证

- **健康确认实际装配**：编排内挂 `CompositeHealthCheck`（`candidate-config` 查清单声明的配置文件存在/非空与 JSON 根形态，`lua-scripts` 走候选脚本集合 + 沙箱验证）；`entry-assets` 由 `ProcedurePatch` 在包初始化后单独执行。
- **已兑现且有证据**：候选校验、十阶段编排、反回退、真实 HTTP 下载与本地通道、Lua 沙箱、两版本对照、真实资产包段（Windows Player：候选包根初始化 + `entry-assets` 的 checked/skipped 证据行）。
- **未接线**：`CandidateEntryFilesHealthProbe`、`BridgeCapabilityHealthProbe` 只有定义无装配点；`BuiltinBundleBuildInvoker.RunCandidateAsync` 无调用者。
- **未实现/未验证**：断点续传（`HttpCandidateFetcher` 无 `Range` 请求，临时文件按 Release 隔离但已有长度只用于"超长即弃"，失败仍整文件重下）；"原子提交"是 temp 写完 → 读回 → 再写 target（不是 rename）；真云 CDN、移动端磁盘余量、Android IL2CPP 密码学后端、掉电/杀进程矩阵（`File.Replace` 的 fsync 行为未覆盖）；运行态重发布、Release 归属、对局固定快照、`SafeWindow`/`NextMatch` 激活。

## 9. 核对与排障

改热更/资源面时以这几处为口径：`TableLayout.Files`/`JudgmentDomains`（表与判定面）、`BundleCollectorSetting.asset`（收集组）、`ReleaseLayout`（候选根布局）、`ReleaseManifestValidator`（校验顺序与预算）、`PatchCoordinator`（阶段）。脚本一律 `.py`（`scripts/` 已全量 Python），日志标签 `[Patch]`/`[Content]`。

| 现象 | 原因/处置 |
|---|---|
| 出包门禁提示 BuildHash 不一致 | 共享源集/生成读码面改动后漏跑 `gen-build-hash.py`；重跑后提交 `BuildHash.g.cs` |
| 进房被拒、提示配置哈希不等 | 两端判定面表字节不一致（`CombatConfigDigest`）；核对 `JudgmentFiles` 6 张表与 `StartGame.ConfigHash` |
| 候选被拒（签名/撤销/过期） | 看 `ReleaseRejectReason`：keyId 未登记或撤销、`signedBytes` 被改动、`expiresAt` 已过 |
| 候选被拒（预算/路径） | 文件数 >4096、单文件 >512 MB、总字节 >4 GB、路径段 >16 或段长 >128 |
| 候选被拒（反回退） | `revision` 不高于 `ActivationRecord.ConfirmedRevision`；提高 revision 重新签发 |
| 候选激活后仍跑旧内容 | `ReleaseEffectWindow` 只支持 `NextLaunch`，需重启；代次未推进时看 `PatchCoordinator.Phase` 是否停在 `HealthChecking` |
| Player 启动用了内置包而非候选 | `CandidateBundleRootResolver` 两条件未同时成立（`ReleaseId` 仍为 builtin，或 `bundle/DefaultPackage.version` 缺失） |
| 候选 Lua 验证报"越出候选集合" | 依赖未打进本批 `lua/**`，或 require 了被回收的 `io/os/debug` |
| 表装载失败 | `ConfigService` fail-fast：定位缺表的 location；确认 `TableLayout.Files` 与生成产物、收集组一致 |

内置包与客户端的构建流程见 [11-构建与本地联测](11-构建与本地联测.md)，工具入口全表见 [15-工具链手册](15-工具链手册.md)。
