# 架构单元模型（arch/units.json）

> **定位**：回答“客户端有哪些程序集单元、各自在哪一层、允许引谁、资源归哪个收集组、由哪个测试桶覆盖、owner 是谁”。
> **单源**：`arch/units.json`；本文件只解释读法与维护流程，不复制第二份清单。
> **关联**：[客户端架构重构演进路线图](../设计文档/架构/客户端架构重构演进路线图.md) · [模块发行矩阵](19-模块发行矩阵.md) · [域间引用矩阵](18-域间引用矩阵.md) · [规范 09 §6](../规范/09-分层与命名.md#6-程序集分层与命名)

## 1. 为什么有这张模型

B5 之前，同一套结构事实散在五处：`ClientAsmdefAllowlistTests` 的手写允许边、`module-tiers.json` 的 tier/收集组、`ScanTargets.Default` 的扫描根、`DomainBoundaryTests` 的域清单、`domain-matrix.py` 的允许边。新增一个模块要同时改多处，漏一处不会立刻红。

现在这些事实只有一个作者面：`arch/units.json`。其余表要么读它，要么由它生成；`scripts/gate/arch-check.py --check` 只能做只读诊断（模型与真实仓库是否一致），**不是守卫、不在 L1**；现行架构守卫是 AR1/AR2/AR3（见 §4）。

## 2. 模型结构

| 字段 | 内容 |
|---|---|
| `version` | 模型版本（当前 1） |
| `layers` | 语义层：`kernel` / `framework` / `shell` / `product` / `app` / `editor`，各带 `rank` 下限 |
| `tiers` | 发行 tier：`base` / `script` / `data` |
| `testBuckets` | 测试桶：`kind`（dotnet/unity）、`path`、`lane`（L1/L2/L3） |
| `externalAssemblies` | 允许被引用的第三方/外部程序集与理由 |
| `units` | 程序集单元：`id`/`assembly`/`path`/`asmdef`/`layer`/`rank`/`owner`/`tier`/`collectGroups`/`tests`/`noEngine`/`defineConstraints`/`references`/`friends`/`notes` |
| `collectPathExceptions` | 收集组路径顶层例外：组 → 归属模块 + 依据 |
| `changeMatrix` | 「改什么 → 发什么」矩阵 |
| `domains` / `domainEdges` | Modules 顶层域清单与角色、跨域允许边（当前 12 域 / 31 条允许边）。**描述性数据，不构成门禁**：`domain-matrix.py` 已删除（2026-11-10），无脚本、无 C# 用例读这两个字段，不得据此宣称有强制力 |
| `scanTargets` | 纪律扫描根：`root`/`rules`/`exclude`/`includeEditor`（规则集本身仍在 `ScanTargets.cs`） |
| `topLevel` | `Assets` 与 `Assets/LiteGame` 顶层目录登记/忽略面 |

`rank` 是**依赖深度**，不是业务重要性：依赖边必须指向严格更小的 `rank`。同一语义层内可以有多个 rank（例如产品域的 Config=30、Battle=40、Procedure=55），这样“上层只能引下层”可以被机械判定，而不必给每个模块硬造一个并列层号。

## 4. 门禁与模型诊断

```powershell
python scripts/gate/namespace-path.py        # AR1 路径=命名空间（对基线棘轮）
python scripts/gate/change-unit.py           # AR2 改动单元上限（对基线棘轮）
python scripts/gate/hot-boundary-check.py    # AR3 AOT 不引 hot（默认 warning，--strict 升 error）
python scripts/gate/arch-check.py --check    # 只读诊断：模型/投影/仓库一致性（非守卫、不在 L1）
python scripts/gate/arch-check.py --write    # 从模型重写两个投影
# 域间矩阵与零使用边门禁已废弃（2026-11-10）：domain-matrix.py / zero-use-edges.py / port-lint.py 均已删除
python scripts/gate/test.py --suite L1 --profile PullRequest  # L1 只跑 dir-flat-lint + dotnet 用例
```

`ModuleFriendAllowlistTests`（L1）读 9 个 `Modules/*/AssemblyInfo.cs` 的 `InternalsVisibleTo`，与 `units[].friends` 逐条比对（当前 55 条；未登记/数量变化即红）；零使用边门禁（`zero-use-edges.py --check`，基线 `arch/zero-use-edges.json`）**已废弃**（2026-11-10：脚本与基线均已删除），不再校验。

`arch-check.py --check`（只读诊断，非守卫、不在 L1）当前校验：

1. 客户端根（框架 / LiteGame / Sim / Net / Sync / LiteCodeGen）下每个 asmdef 都已登记，且模型引用与实际 asmdef **逐条相等**（漏登记、旧登记、新边都红）。
2. 内部依赖 `rank` 严格递减；外部引用必须在 `externalAssemblies` 且有理由。
3. 收集组 ↔ 模块 100% 有主；路径落在归属模块 `Content/` 下，顶层例外必须带依据。
4. 测试桶存在；dotnet 桶必须登记在 `Tests/Tests.slnx`。
5. `Assets` / `Assets/LiteGame` 顶层目录与模型一致。
6. 扫描根存在，规则集/排除集在 `ScanTargets.cs` 中真实定义。
7. 两个生成投影与模型逐字节一致；生成物 `.meta` 合法。

## 5. 新增一个模块只改一处

1. 建模块目录与 asmdef（目录、程序集名、命名空间按[规范 09 §6](../规范/09-分层与命名.md#6-程序集分层与命名)）。
2. 在 `arch/units.json` 的 `units` 增加一条：`id`=程序集名、`asmdef`/`path`、`layer`、`rank`（大于所有依赖的 rank）、`owner`、`tier`、`collectGroups`、`tests`、`references`；有 `InternalsVisibleTo` 的模块另登记 `friends`（程序集名，未登记即红）。
3. 跑 `python scripts/gate/arch-check.py --write` 重写投影。
4. 若新增收集组，先在 `Assets/BundleCollectorSetting.asset` 建组，再在单元 `collectGroups` 登记；路径不在 `<模块>/Content/` 下时补 `collectPathExceptions` 并写依据。
5. 重编译并跑定向用例 + L1；新增引用边会被 `ClientAsmdefAllowlistTests` 与 `arch-check.py` 同时看到。

## 6. 旧表生命周期

`scripts/content/module-tiers.json` 仍保留，但已是模型生成的只读镜像（文件内 `generatedFrom` 指向 `arch/units.json`）。保留一个版本周期用于回滚/对照；周期结束后删除，届时 `ModuleTierMatrixTests` 与文档已只读模型。

## 7. 边界

- 模型只覆盖客户端 6 个根；服务端宿主（`Server/`、`Assets/RoomServer/`）的档位表仍在 `ScanTargets`/共享代码专项设计中，不并入本模型。
- 规则集内容（`LintRule[]`）与校验逻辑仍是 C# 代码；模型只决定“哪个根用哪套规则”。
- 模型是**结构登记**，不裁决设计目标；目标架构仍归设计文档，施工证据归进度卷。
