## 1. 全栈轮廓

### 1.1 三个进程

- **客户端**：`Assets/LiteGame`（流程/UI/Meta 入口/本地服）、`Assets/LiteFramework`（对局编排）、`Assets/LiteNet`（协议/传输/会话）；渲染帧驱动、逻辑帧追 60Hz；KCP over UDP + AES-256-GCM 信封。
- **RoomServer**：宿主 `Server/RoomServer` + 内核 `Assets/RoomServer/Core` + 应用 `Assets/RoomServer/Modules`；`ServerLoop` 60Hz；对外 UDP `port`（云上 17777）、`/metrics`、`/gm/*`。
- **MetaServer**：`Server/MetaServer`（ASP.NET Core Minimal API）；请求驱动 + Mongo；HTTP 5000 的 `/auth` `/lobby` `/matches` `/live` `/ready` `/metrics`。

## 2. 链路与客户端

### 2.1 进房到开局

`GuestLoginAsync` → `POST /auth/guest`（deviceId 幂等建号、600s 令牌）→ `/lobby/rooms/public` → `/lobby/create-room` 或 `/lobby/join-ticket`（出号 → 选实例 → 签 v4 票据）→ `ProcedureMatch` 取 `ticket`+`address` → `KcpTransportClient.Connect` + 信封三段握手 → `RoomClient.SendJoin(roomId,token,BuildHash.Value)` → `JoinAdmissionGate` → 建房/复用 → `RoomCommand.Join` → `PlayerAdmitted` 签票据 + `BuildJoinAck` → 房主 `StartEarly(owner)` → 收 `StartGame` **复算 ConfigHash**（不等 `SessionFailed`）→ `SimWorldState`+`RollbackSim` → `ProcedureBattle`。满员不自动开局，`Running` 后进房一律拒（`RoomRuntime.cs`）。

### 2.2 五件套、相位机与上下行约束

`BattleClient`（持传输 + `RoomClient`，`Idle` 时首发 Join）· `RoomClient`（`LiteNet/Core/Client`：相位机/收发/冗余窗/重连/RTT 探针）· `BattleContext`（网络事件 → 镜像 → 预测和解 → 视图 → 输入上行）· `BattleInputPipeline`（入史/上行/沿用帧预发/追帧补发）· `BattleSnapshotMirror`（镜像重建/和解/插值源 16 份环形）。

`Idle` → `Connected`（JoinAck 或 `CompleteRestore`）→ `SuspectedLost`（传输断、席位在重连窗）→ `Reconnecting`（已重拨并发 `ReconnectRequest`）→ `Restoring`（验票 + 版本确认）→ `Connected`；票据空/耗尽/版本不符/超时进 `Failed`。超时 `ReconnectTimeoutMs=10_000`（连接建立后重置）；**不自动重试**，由 `BattleContext` → `End(SessionFailed)`；版本确认三项 = `Seed`、`ConfigHash`（仅已收 `StartGame`）、`BuildHash`。

- 冗余窗 16；下界 `LastSnapshotFrame+1`（锚快照）；上界 `min(环内连续可用,16)`，跳帧即断连续。`ack_snapshot`=已收最新快照帧号；`view_frame`=`SimView.RenderFrame`；单渲染帧跑 ≥2 逻辑帧时多出的帧逐帧各发一包。
- 下行只收严格新于已应用帧的快照；全量=缺席槽位判死并清运行态数组，增量=只覆盖指到槽位；和解按校验锚比对，不符则权威覆盖+重放；插值环 16 份须大于 jitter buffer(8)。`OnStartGame` 是一次性边缘事件，晚订阅读 `StartGame` 属性；`OnReconnectResponse` 只在 `Restoring` 可应用且**必须**随后 `CompleteRestore()`。
- 路径 A：`CreateTransport(testRoom:true, rules)` → `LocalServerTransport.ForRoom`，真内核、无 Socket/验票、自动补位、代房主开局，在 `UNITY_EDITOR || DEVELOPMENT_BUILD || LITEFRAMEWORK_DEBUG` 内；路径 B：Meta 票据 → 真 KCP，端点单源 `MetaEndpoints`，缺 PSK 构造即抛。
- 注入优先级：`-meta.url=`/`-envelope.key=`/`-device.id=` > `Assets/StreamingAssets/deploy.args` > 默认；`deploy.args` 由 `BuildProfiles/*.json` 的 `endpoints` 生成，为空会**删除**旧文件；同机多客户端须各给不同 `-device.id`。

### 3.3 快照三层与校验锚

公共层 `SlotDelta` 25 字段逐槽；比赛层 `MatchStateDelta` 每份快照全量；私有层 `PrivateStateDelta` 只发本人（武器 2 槽 / 技能 3 槽 / 状态 4 槽 / 背包 12 格 / 资源）。三个锚：全量帧 `checksum`=`ComputePublicChecksum`；增量帧 `checksum` 填 0，改比 `visible_checksum`（本条实际携带槽位集合）与 `match_checksum`，不一致再逐槽比 `SlotDelta.checksum`。战斗事件独立成包（按 `(kind,a,b,frame)` 去重、1s 窗口全量重发），因快照曾被顶到 1531B 超过 KCP 不可靠上限被静默丢；Unreliable 单包明文上限约 1194B，超限由 kcp2k 丢、应用层只记账。

## 4. 房间内核（`Assets/RoomServer`）

### 4.1 三层与每帧步序

| 层 | 目录 / 程序集 | 纪律 |
|---|---|---|
| 纯内核 | `Core` / `RoomServer.Runtime` | 只引 `LiteSim.Core`；`noEngineReferences`；**R11**：禁 Console/系统时钟/文件 IO/proto/LiteNet |
| 无 IO 应用子集 | `Modules` / `RoomServer.Application.Runtime` | +LiteNet +vendor `Google.Protobuf`；可用 proto、无 IO |
| 可执行宿主 | `Server/RoomServer` | Socket/HTTP/文件 + MS DI 组合根 |

`Events.Clear()` → `frame=Frame+1` → 逐席位 `Gate.TryConsume`（缺席空输入、pending 开火打 `ButtonDeferHit`）→ `SimStep.Step(advanceMatch:false, rules)` → 核验本帧**真产** `Fire`（武器门放行才算）→ `CaptureEvents(fireOnly:true)` → `SnapshotHistory.Capture` → `_recentInputs.Record` → `LagComp.RecordInputs` → `ConsumePendingFire`（逐射手回溯 + `FlushCommands` + 再 `CaptureEvents`）→ `MatchSystem.Tick`（含回溯后才判胜）→ `SnapshotHistory.Capture` 覆盖最终计分 → 诊断录制。同帧 `Capture` 两次（后者覆盖），环成本 ×2；快照不走输出事件，`SnapshotPipeline` 步进后拉 `AuthSim`/`Gate` 自建。

命令入 8 种（`AuthenticatedJoin/ClientInput/Disconnect/Rebind/Tick/Shutdown/RestoreAck/StartEarly`）；事件出 6 族（`Signal/JoinRejected/MatchStateChanged/SettlementReady/RoomAborted/StartRejected`）；信令 5 种（`PlayerAdmitted/MatchStarted/SeatRestored/OwnerChanged/SeatsChanged`）。

### 4.2 输入闸门（14 项，顺序即语义）

1. 形状：`Count>16` 整条丢；空包/装载不足；`batch.Frame > serverFrame+8` 整条丢。
2. 定帧：从 `serverFrame+1` 倒退最多 16 帧找主帧；主帧 `≤0` 或越界丢；`frame ≤ serverFrame` 拒。
3. 语义：按键白名单；切枪槽位 `[0,2)`；离散 seq 非零且单调（同帧同 seq 才可重入）。
4. 数值：浮点有限性；Move 单分量 `|v|≤1`；Move 平方长 `≤1`；Fire/Skill1-3 帧 AimPoint 全零非法；距离闸 `dist² ≤ (HitscanRange×1.1)²`。

同帧去重"后到生效"（只计数不丢）；`EntityId` 一律覆写为会话实体；`ackSnapshot` 越界只钳位；未来帧 `(serverFrame+2 .. +8]` 同口径校验后入 `PendingInputRing`（32 槽、`slot=frame&31`、换代整槽清空）。十类丢弃计数中 `IllegalActionSeq/IllegalWeaponSlot/NonFinite/IllegalVector/OversizedMessage` **不进 Ops 行**。

### 4.3 回溯、同帧互杀与状态机

目标帧 = `view_frame`（不再减插值），clamp `[auth.Frame-16, auth.Frame]`；退化：历史窗为 0、目标帧 ≥ 当前帧、环内无该帧、取不到历史输入。目标取历史位、**射手取当前位**（Pos/Vel/Yaw/Flags/SelectedWeapon/SemiFireArmed），仅当前 `Hp>0` 才拷武器行；只跑 `ShootingSystem`，结果须过 `CanApplyHistoricalHit`（当前 Hp>0、`LifeStartFrame≤targetFrame`、当前帧 ≥ `InvulnerableUntilFrame`）。同帧互杀时后结算者取历史态，活着则用当前武器行覆盖；`Outcome` 四态 `NoFire/Compensated/DegradedFire/InvalidShooter` 进 Ops；`clientAckSnapshot` 形参当前未使用。

`Created(0)→WaitingForPlayers(1)→Starting(2)→Running(3)→Finishing(4)→Settling(5)→Closed(6)`，另 `Aborted(7)`；`IsAllowed` 是唯一真值来源，非法迁移输出 `Reason="Rejected:"+reason`，不改状态不抛。进房相位闸：`Starting/Running/Finishing/Settling` 一律拒；空位取最低、满员拒、`NextPlayerId` 只升不降；**未开局断线即释放席位**，对局中断线保留席位；owner = 首个入座者，离席迁最低在线席位，旧房主重连**不夺回**。

## 5. 宿主（`Server/RoomServer`）

### 5.1 装配、一帧与路由

`HostAssembly.Register/Build`（`ValidateOnBuild`+`ValidateScopes` 常开）；容器只在装配层、**运行期零解析**、per-room 对象不进容器；`CombatValues`/`Weapons`/`Map` 缺即拒装配；生产形态 `mailboxRouting:true`+`drainMailboxesImmediately:false`+`workerExecution:true`；解析序 outbox→transport→host，容器逆序释放。

一帧：取 `_nowMs` → `TickIncoming()` → `_pendingDisconnects.Flush()` → `FlushGmActions()` → 逐房间（超时兜底 → 投 Tick + 排 Control/Input/Outbound → 广播 → 销毁终态房）→ 周期清理（600 tick）→ `TickOutgoing()` → `MaybePrintOps()`（缺省 5s）。owner 形态必须**先排输入再投 Tick**，否则同批 `frame+1` 输入被判 stale。

入站：`Join`→`InboundJoinHandlers`；`Input`/`MismatchReport`/`RestoreComplete`/`Leave`/`StartMatchRequest`/`Heartbeat`→`InboundHandlers`；`ReconnectRequest`→`InboundReconnectHandlers`；坏包记 `Ops.NotePacketRejected`。每包三前置闸：包长 >4096 记 `PacketOversized`；Session 包限流**静默丢弃**；会话已 `Disconnected` 丢。出站：`JoinAck`、`StartGame`、`StateSnapshot`+`CombatEvents`、`ReconnectResponse`、`MatchEnded`、`StartMatchResponse`（仅拒绝）、`OwnerChanged`、`RoomSeats`、`Heartbeat` 回显。

### 5.2 准入与限流

① IP 入场频率 → ② 字段 UTF-8 字节边界 → ③ token 非空 → ④ **buildHash 逐字比对**（`DiagStage.Build`）→ ⑤ 票据验签（**先于建房**）→ ⑥ 账号入场频率（验签后才知 AccountId）；顺序不可交换。之后才是排空红线、控制 lane 容量、建房/复用、`RoomCommand.Join`；nonce 窗 `DefaultNonceWindow=4096`，窗口满即**拒新票**。

限流四 lane：`IpConnect` 32/4s、`IpEntry` 32/8s、`AccountEntry` 16/2s、`SessionPackets` 256/128s；桶表 8192（每 lane 独立、满则拒新键不淘汰）、空闲 TTL 120000ms；探测不到远端地址跳过该维度。

### 5.3 重连、排空与结算

重连：签票（Join 成功；128bit CSPRNG base64url、TTL 300s、容量 256 超限淘汰最老、**一次性**）→ 入站（IP 限流 → `TryPeek` → 找房 → 队列容量 → 容量锁内消费票据 → `Rebind`）→ 席位 `Restoring`、旧连接映射失效 → 管线按 `seatBroadcastable(=Active)` 在**两个环**都跳过该席位 → 响应含 Seed/ConfigHash/BuildHash + 全量快照 + 私有面 + 战斗事件窗 + 最近 32 帧输入历史 → `RestoreComplete` 触发 `Restoring→Active` + `SeatRestored`（幂等）→ `RequestFullSnapshot()` 整帧重锚。仅 `Running` 可重连；断线会话 TTL = 票据 TTL，未进房静默 60s。

排空：① `Draining=true` 随心跳上报让 Lobby 停分配（无独立 readiness 面）→ ② 停新 Join、逐房 `SetDrainDeadline`（只可前移）→ ③ `Pump` 查 deadline，CAS 只投一次 `Shutdown(DrainTimeout)` → ④ `FlushSettlementOutbox()` → ⑤ `Dispose`：Worker `Stop(drain:true)` → 房间收尾 → Transport → Outbox。判据 `DrainComplete` = 在排空且全部在册房间 `Runtime.Closed`；`Program` 以 `BeginDrain(now+5000)` + 轮询（上限 7000ms）→ `loop.Stop()`；Ctrl+C 与 SIGTERM 同链。

结算：冻结 `SettlementReadyOutput` → 广播 `MatchEnded` → 入盒四态 `Appended/Duplicate/RejectedFull/Failed`（容量按**待提交**数计）→ JSONL + `WriteThrough` 逐行 Flush（`Kind`=`s`/`c`/`x`）→ 后台线程取 `ListPending()[0]` POST `submit_url`+Bearer，**2xx** 即 `TryMarkCompleted`；可重试（传输异常/401·403·404/408·429/5xx）按 `min(base<<min(n-1,16), max)` 退避，确定性 4xx 弃置；完成标记满 1024 重写日志；幂等键 `matchId = RoomId + ":" + Guid`；奖励 `NoEconomyRewardPolicy` 恒 0（占位）。

### 5.4 GM 与诊断面

`POST /gm/rooms`（读，`RoomSummaries(includeHidden:true)`）、`/gm/start`（`StartEarly(owner)`，取真实 owner 代发）、`/gm/abort`（`Shutdown(Operator)`，走完 Finishing/Settling）、`/gm/kick`（需 `player`，`Disconnect` + 传输层断开）、`/gm/rules`（`flags` 或 `noDeath`/`infiniteAmmo` → `SetTestRules`，**只对云端测试房**）、`/gm/settle-flush`、`/gm/diag-list`/`/gm/diag-fetch`（现场包，`diagnostics.enabled` 才装配）。鉴权头 `X-GM-Key`：长度先比 + 恒定时间比较，密钥取 `LITENET_GM_KEY`（空则端点不创建）；仅 POST、body ≤4096B、绑定面**不得为通配地址**（装载期拒）；HTTP 线程只鉴权+入队，动作在 `FlushGmActions` 执行。

## 6. Meta 与持久化（`Server/MetaServer`）

### 6.1 端点

| 方法 | 路径 | 鉴权 | 成功 / 主要失败 |
|---|---|---|---|
| POST | `/auth/guest` | 无 | `{accountId,accessToken,tokenType,expiresAtMs}`；`auth.invalid-request/disabled/store-unavailable` |
| POST | `/lobby/instances/register` | Lobby 实例密钥 | `{heartbeatTtlMs}`；`lobby.instance-unauthorized/registry-full/disabled` |
| POST | `/lobby/join-ticket`、`/lobby/create-room` | 访问令牌 | `{instanceId,address,roomId,ticket,expiresAtMs}`；`version-mismatch`(409)、`forbidden`(403)、`no-capacity`(503) |
| GET | `/lobby/rooms`（实例密钥）、`/lobby/rooms/public`（玩家令牌） | 见左 | 同一投影 `{rooms[]}`；401/503 |
| POST | `/matches/result` | **结算实例密钥**（与注册分权） | `{matchId,duplicate,results[]}`；任一 conflict → 409 |
| GET | `/matches?limit=N` | 访问令牌 | `{matches[]}`；400（越界）/401/503 |
| GET | `/live` `/ready` `/metrics` | 无 | `ready` 或 503 `draining`/`store-unreachable`；Prometheus 文本 |
| POST | `/sample/settlement` | 无 | 仅 `EnableSampleEndpoints=true` 挂载，缺省 404 |

统一错误体 `{code,messageKey,args[]}`，`args` 只放字段名/上限，不回显字段值。

### 6.2 登录、大厅与签票

- 游客登录：`requestId`/`deviceId` 各 ≤128 UTF-8 字节；`deviceId` 唯一索引做幂等裁判；`accountId="a"+20 hex`（CSPRNG）；按源 IP 限流（缺省 30 次/分钟）。
- 令牌 `v1.kid.accountId.jti.audience.purpose.iatMs.expMs.sig`（**9 段**，签名覆盖前 8 段，HMAC-SHA256，TTL 600s）；校验 fail-closed 不抛：kid → 签名（恒时）→ 声明 → 时效 → audience → purpose。
- 建房出号 `R-`+6 位随机（去 `I/1/O/0`），保留窗 120000ms、重试 16；分配只选"未 drain 且 `PlayerCount<MaxPlayers`"且 buildHash 同值；排序 = 玩家少 → 房间少 → `Ordinal`。
- 云端测试房授权（唯一校验点）：`template` 文法 `[a-z0-9_-]{1,32}` + 恒定时间比对 `LITEGAME_GM_ROOM_KEY`（空则一律 403）。
- 签票 v4 共 16 段（含 `template`）、覆盖前 15 段、nonce 128bit hex、TTL 300s；客户端**不解析票据**只透传。
- 注册即心跳（同 `InstanceId` 重复注册=更新并刷 `LastSeenMs`），心跳时限 30s；摘除是**惰性清扫**；表满拒新实例不淘汰旧条目；地址形状 `host:port`（无 IPv6 面）。

### 6.3 结算与配置

先归档（幂等 `matchId`）再账本（逐玩家 fan-out）。账本幂等双维度 = `operationId`（缺省 `match:{matchId}:{playerId}`）+ 唯一索引 `(playerId,matchId,settlementType)`；`expectedRevision` 缺省 -1（不做 CAS），≥0 走 CAS，不符 → conflict（整包 409 可重试收敛）。上界：单提交 ≤64 玩家、`delta` ≤1,000,000、同 `playerId` 不重复；`GET /matches` 按令牌账号、`limit` 1..100（缺省 20）、内存排序；迁移 `LatestVersion=4`，失败逆序回滚并拒启。

`Meta` 节 / `META_` 前缀覆盖；`MetaConfig` **必须是属性而非字段**（`ConfigurationBinder` 只绑属性）；缺省 `BindAddress`=`http://127.0.0.1:5000`、`AllowNonLoopbackHttp`=false、`MaxInboundBytes`=65536、`ShutdownTimeoutSeconds`=15、`AuthTokenTtlSeconds`=600、`LobbyTicketTtlSeconds`=300、`LobbyHeartbeatTtlSeconds`=30、`LobbyRegistryCapacity`=64、结算查询 20/100；Mongo 连接串与库名成对（空=持久化关）。指标 9 项无高基数标签：`meta_http_request_total`、`meta_http_rejected_total`、`meta_lobby_instance_register_total`、`meta_ticket_issue_total`、`meta_room_create_total`、`meta_match_result_store_total`、`meta_match_result_duplicate_total`、`meta_draining`、`meta_uptime_seconds`。

## 7. 功能边界

### 7.1 已闭环

确定性 Sim（固定系统序、整数随机、逐位基线）· 服务器权威 + 预测/回滚/和解 · 快照三层 + 校验锚 · 30Hz 差分 + AOI + 三级背压 + 全量兜底 · 输入冗余窗 + 未来帧预存 + 14 项闸门 · 延迟补偿回溯 · 一次性重连票据 + 整帧重锚 · 多房间/Worker 池/有界 Mailbox · 优雅排空 · 安全信封 + 分层限流 + 票据验签 · 结算 Outbox · Meta 四模块 + 分权凭据 · GM 写面门禁 · 房主开局/迁移 + 席位实时面。

### 7.2 已实现但无生产调用方

| 件 | 事实 |
|---|---|
| `Leave`（包与 proto） | 服务端受理（转 `Disconnect`），客户端**无发送方**（离场走 `Disconnect()`） |
| `PurgeExpiredNonces` | 只有定义与"宿主应周期调用"注释，**零调用点**；`NoncesPurged`/`RejectedWindowFull` 无读面 |
| `InputGate` 五类丢弃计数 | 不进 Ops 行（见 §4.2） |
| `BroadcastAccount.BackpressureDrops` | 有计数、无输出 |
| `RoomInstance` Mailbox 三段计数 | `MailboxRejectedFull/Accepted/Dequeued` 无外部读 |
| Meta `IOutboxStore`/`MongoOutboxStore` | 端口与实现就绪，装配显式退役 ⇒ `OutboxCapacity` 是死配置 |

### 7.3 已知缺口与债

| # | 缺口 | 影响 |
|---:|---|---|
| 1 | 观战/回放未实现（proto 与房间服均无 `Spectator`/`Replay`；`SimReplayRunner` 只是 Sim 诊断重放） | 只能直播参与 |
