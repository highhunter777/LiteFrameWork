## 1. 全栈轮廓

### 1.1 三个进程

- **客户端**：`Assets/LiteGame`（流程/UI）、`Assets/LiteFramework`（对局编排）、`Assets/LiteNet`（协议/传输/会话）；渲染帧驱动、逻辑帧追 60Hz；KCP over UDP + AES-256-GCM 信封；进房链 `GuestLoginAsync` → `/auth/guest` → `/lobby/rooms/public` → `/lobby/create-room` 或 `/lobby/join-ticket` → `ProcedureMatch` 取 `ticket`+`address` → `BattleClient` → 信封三段握手 → `RoomClient.SendJoin(roomId,token,BuildHash.Value)` → `JoinAck` → 房主 `StartEarly(owner)` → `StartGame`（**复算 ConfigHash**，不等 `SessionFailed`）。
- **RoomServer**：宿主 `Server/RoomServer` + 内核 `Assets/RoomServer/Core` + 应用 `Assets/RoomServer/Modules`；`ServerLoop` 60Hz；对外 UDP `port`（云上 17777）、`/metrics`、`/gm/*`。
- **MetaServer**：`Server/MetaServer`（ASP.NET Core Minimal API）；请求驱动 + Mongo；HTTP 5000 的 `/auth` `/lobby` `/matches` `/live` `/ready` `/metrics`。

### 1.2 源集与硬边界

- **判定/协议闭包 `SHARED_TARGETS`**：`LiteSim/{Scripts,Systems}`、`LiteNet/Core/{Proto,Protocol,Transport/Security}`、`GameData/Generated`；守卫 = `JoinRequest.build_hash` 逐字比对 + `gen-build-hash.py --check-shared`。
- **源链接共编件 `SHARED_LINK_FILES`**：`Adapters/Luban/{SimConfigMapper,TableLayout}.cs`（csproj `<Compile Include>` 出树链接，两端同一份源码）。**不在闭包内**：`Assets/RoomServer/{Core,Modules}`（只服务端编译）；`JoinTicketFormat.cs`/`Base64Url.cs`/`MatchStateMachine.cs` 另进 Meta 构建身份。
- **数据面**：表数值 `GameData/Config/*.bytes` 不进闭包，改由 `CombatConfigDigest` → `StartGame.ConfigHash` 客户端复算，不等拒局。
- **三层**：纯内核 `Core`/`RoomServer.Runtime`（只引 `LiteSim.Core`、`noEngineReferences`、**R11** 禁 Console/系统时钟/文件 IO/proto/LiteNet）→ 无 IO 应用子集 `Modules`/`RoomServer.Application.Runtime`（+LiteNet +vendor `Google.Protobuf`）→ 宿主 `Server/RoomServer`（Socket/HTTP/文件 + MS DI，容器只在装配层、运行期零解析）。

### 1.3 关键常量

| 项 | 值 |
|---|---|
| 逻辑帧 / 快照 | 60Hz / 30Hz（`stride=2`，计数器先自增后取模 ⇒ **首帧不广播**）；追帧 5、预测领先 6；全量每 60 帧、ack 落后 30 帧 |
| 输入 / 回溯 | 延迟 1、冗余窗 16、预存环 32 槽、未来帧 8；回溯窗 16、回滚深 8、单帧 2 次、输入历史 32 |

| hash / 票据 / 宿主 | `48fa22580c3a03c4`、Meta `599c06a554f3710a`（不参与准入）；300s、256 条、v4 16 段签 15 段；清理 600 tick、入包 4096B、排空 5000+2000ms；KCP MTU 1200 / 10ms / 10s |

### 2.3 快照三层与校验锚

公共层 `SlotDelta` 25 字段逐槽；比赛层 `MatchStateDelta` 每份快照全量；私有层 `PrivateStateDelta` 只发本人（武器 2 槽 / 技能 3 槽 / 状态 4 槽 / 背包 12 格 / 资源）。三个锚：全量帧 `checksum`=`ComputePublicChecksum`；增量帧 `checksum` 填 0，改比 `visible_checksum`（本条实际携带槽位集合）与 `match_checksum`，不一致再逐槽比 `SlotDelta.checksum`。战斗事件独立成包（`(kind,a,b,frame)` 去重、1s 窗口全量重发）；Unreliable 单包明文上限约 1194B。

## 3. 内核与宿主

### 3.1 输入闸门（14 项，顺序即语义）

1. 形状：`Count>16` 整条丢；空包/装载不足；`batch.Frame > serverFrame+8` 整条丢。
2. 定帧：从 `serverFrame+1` 倒退最多 16 帧找主帧；主帧 `≤0` 或越界丢；`frame ≤ serverFrame` 拒。
3. 语义：按键白名单；切枪槽位 `[0,2)`；离散 seq 非零且单调（同帧同 seq 才可重入）。
4. 数值：浮点有限性；Move 单分量 `|v|≤1`；Move 平方长 `≤1`；Fire/Skill1-3 帧 AimPoint 全零非法；距离闸 `dist² ≤ (HitscanRange×1.1)²`。

同帧去重"后到生效"；`EntityId` 一律覆写为会话实体；`ackSnapshot` 越界只钳位；未来帧 `(serverFrame+2 .. +8]` 同口径校验后入 `PendingInputRing`（32 槽、`slot=frame&31`）。十类丢弃计数中 `IllegalActionSeq/IllegalWeaponSlot/NonFinite/IllegalVector/OversizedMessage` **不进 Ops 行**。逐帧步序、回溯与同帧互杀见 [04](04-服务端与房间内核.md)。

### 3.2 状态机与席位

`Created(0)→WaitingForPlayers(1)→Starting(2)→Running(3)→Finishing(4)→Settling(5)→Closed(6)`，另 `Aborted(7)`；`IsAllowed` 是唯一真值来源。进房相位闸：`Starting/Running/Finishing/Settling` 一律拒；空位取最低、满员拒、`NextPlayerId` 只升不降；**未开局断线即释放席位**，对局中断线保留席位；owner = 首个入座者，离席迁最低在线席位，旧房主重连**不夺回**。

### 3.3 准入、限流与重连

① IP 入场频率 → ② 字段 UTF-8 字节边界 → ③ token 非空 → ④ **buildHash 逐字比对**（`DiagStage.Build`）→ ⑤ 票据验签（**先于建房**）→ ⑥ 账号入场频率（验签后才知 AccountId）；顺序不可交换。之后才是排空红线、控制 lane 容量、建房/复用、`RoomCommand.Join`；nonce 窗 `DefaultNonceWindow=4096`，窗口满即**拒新票**。限流四 lane：`IpConnect` 32/4s、`IpEntry` 32/8s、`AccountEntry` 16/2s、`SessionPackets` 256/128s；桶表 8192（满则拒新键不淘汰）、空闲 TTL 120000ms。

重连：票据 128bit CSPRNG base64url、TTL 300s、容量 256 超限淘汰最老、**一次性**；席位 `Restoring` 期间管线在两个环都跳过该席位；响应含 Seed/ConfigHash/BuildHash + 全量快照 + 私有面 + 战斗事件窗 + 最近 32 帧输入历史；`RestoreComplete` 触发 `Restoring→Active` + `SeatRestored`（幂等），随后 `RequestFullSnapshot()` 整帧重锚。仅 `Running` 可重连；断线会话 TTL = 票据 TTL，未进房静默 60s。

### 3.4 排空、结算与 GM

排空：`Draining=true` 随心跳让 Lobby 停分配 → 停新 Join、逐房 `SetDrainDeadline`（只可前移）→ `Pump` 查 deadline，CAS 只投一次 `Shutdown(DrainTimeout)` → `FlushSettlementOutbox()` → `Dispose`；判据 `DrainComplete` = 在排空且全部在册房间 `Runtime.Closed`。

结算：`SettlementReadyOutput` → 广播 `MatchEnded` → 入盒四态 `Appended/Duplicate/RejectedFull/Failed` → JSONL + `WriteThrough`（`Kind`=`s`/`c`/`x`）→ 后台取 `ListPending()[0]` POST `submit_url`+Bearer，**2xx** 即完成；可重试项按 `min(base<<min(n-1,16),max)` 退避、确定性 4xx 弃置；幂等键 `matchId = RoomId + ":" + Guid`；奖励 `NoEconomyRewardPolicy` 恒 0（占位）。

GM：`POST /gm/rooms`、`/gm/start`（`StartEarly(owner)`，取真实 owner 代发）、`/gm/abort`（`Shutdown(Operator)`）、`/gm/kick`（需 `player`）、`/gm/rules`（`flags` 或 `noDeath`/`infiniteAmmo` → `SetTestRules`，**只对云端测试房**）、`/gm/settle-flush`、`/gm/diag-list`/`/gm/diag-fetch`。鉴权头 `X-GM-Key`（长度先比 + 恒定时间比较，密钥取 `LITENET_GM_KEY`，空则端点不创建）；仅 POST、body ≤4096B、绑定面**不得为通配地址**。

## 4. Meta 与持久化（`Server/MetaServer`）

### 4.1 端点

| 方法 | 路径 | 鉴权 | 成功 / 主要失败 |
|---|---|---|---|
| POST | `/auth/guest` | 无 | `{accountId,accessToken,tokenType,expiresAtMs}`；`auth.invalid-request/disabled/store-unavailable` |
| POST | `/lobby/instances/register` | Lobby 实例密钥 | `{heartbeatTtlMs}`；`lobby.instance-unauthorized/registry-full/disabled` |
| POST | `/lobby/join-ticket`、`/lobby/create-room` | 访问令牌 | `{instanceId,address,roomId,ticket,expiresAtMs}`；`version-mismatch`(409)、`forbidden`(403)、`no-capacity`(503) |
| GET | `/lobby/rooms`（实例密钥）、`/lobby/rooms/public`（玩家令牌） | 见左 | 同一投影 `{rooms[]}`；401/503 |
| POST | `/matches/result` | **结算实例密钥**（与注册分权） | `{matchId,duplicate,results[]}`；任一 conflict → 409 |
| GET | `/matches?limit=N` | 访问令牌 | `{matches[]}`；400（越界）/401/503 |
| GET | `/live` `/ready` `/metrics` | 无 | `ready` 或 503 `draining`/`store-unreachable` |
| POST | `/sample/settlement` | 无 | 仅 `EnableSampleEndpoints=true` 挂载，缺省 404 |

### 4.2 登录、大厅与签票

游客登录：`requestId`/`deviceId` 各 ≤128 UTF-8 字节；`deviceId` 唯一索引做幂等裁判；`accountId="a"+20 hex`。令牌 `v1.kid.accountId.jti.audience.purpose.iatMs.expMs.sig`（**9 段**，签名覆盖前 8 段，HMAC-SHA256，TTL 600s）。建房出号 `R-`+6 位随机（去 `I/1/O/0`），保留窗 120000ms。云端测试房授权（唯一校验点）：`template` 文法 `[a-z0-9_-]{1,32}` + 恒定时间比对 `LITEGAME_GM_ROOM_KEY`（空则一律 403）。签票 v4 共 16 段（含 `template`）、覆盖前 15 段、nonce 128bit hex、TTL 300s，客户端**不解析票据**只透传。

### 4.3 结算与配置

先归档（幂等 `matchId`）再账本（逐玩家 fan-out）。账本幂等双维度 = `operationId`（缺省 `match:{matchId}:{playerId}`）+ 唯一索引 `(playerId,matchId,settlementType)`；`expectedRevision` 缺省 -1（不做 CAS），≥0 走 CAS，不符 → conflict（整包 409）。单提交 ≤64 玩家、`delta` ≤1,000,000、同 `playerId` 不重复；`GET /matches` 按令牌账号、`limit` 1..100（缺省 20）、内存排序；迁移 `LatestVersion=4`，失败逆序回滚并拒启。

`Meta` 节 / `META_` 前缀覆盖；`MetaConfig` **必须是属性而非字段**（`ConfigurationBinder` 只绑属性）；缺省 `BindAddress`=`http://127.0.0.1:5000`、`MaxInboundBytes`=65536、`AuthTokenTtlSeconds`=600、`LobbyTicketTtlSeconds`=300、`LobbyHeartbeatTtlSeconds`=30、`LobbyRegistryCapacity`=64、结算查询 20/100；Mongo 连接串与库名成对（空=持久化关）。指标 `meta_*` 无高基数标签。

## 5. 功能边界

### 5.1 已实现但无生产调用方

- `Leave`（包与 proto）：服务端受理（转 `Disconnect`），客户端**无发送方**（离场走 `Disconnect()`）。
- `PurgeExpiredNonces`：只有定义与"宿主应周期调用"注释，**零调用点**；`NoncesPurged`/`RejectedWindowFull` 无读面。
- 有计数无读面：`BroadcastAccount.BackpressureDrops`、`RoomInstance` Mailbox 三段计数。

### 5.2 已知缺口与债

| # | 缺口 |
|---:|---|
| 1 | 观战/回放未实现（proto 与房间服均无 `Spectator`/`Replay`；`SimReplayRunner` 只是 Sim 诊断重放） |
| 2 | `Running` 后不可进房，掉线只能靠重连票据回原席位 |
| 3 | 云端测试房不产结算；`sandbox` 的 `match_duration_frames=0` 永不自然结束 |
| 4 | 经济口径占位（`NoEconomyRewardPolicy` 恒 0），账本 revision 推进但余额不变 |
| 5 | Meta 多实例不支持（注册表/出号保留集驻进程内存） |
| 6 | 访问令牌无吊销面（`jti` 只是未来锚点），只能等 TTL |
| 7 | Unreliable 单包明文约 1158B，超限静默丢（实体多/全量帧有风险） |
| 8 | `JoinTicketFormat` 类注释漂移：写 v3/15 段/覆盖 14 段（另处"前 13 段"），实际 v4/`PartCount=16`/覆盖前 15 段 |
| 9 | `InputMessage.frames` 注释写"≤4 帧"，实际 `MaxRedundancy=16`（注释漂移，以代码为准） |
| 10 | GM 审计走裸 `Console.WriteLine`，与统一日志纪律不一致 |
| 11 | `/metrics` 缺省绑全接口，GM 强制非通配（两 HTTP 面口径不一） |
| 12 | `scripts/deploy/{gm,deploy-room,wg-peer}.py` 硬编码路径与端口（`gm.py` 改用 19101） |
| 13 | Room UDP 实际绑 `0.0.0.0:17777`（配置无对局 bind 字段），可达性靠安全组/防火墙 |
| 14 | 基包 `deploy.args` 含 `-envelope.key`（PSK），"基包不含私钥"只对 `.conf` 成立 |

## 6. 配置与观测

### 6.1 房间服配置（整份启动期快照，改配置必须重启）

| 分区 | 键与缺省 |
|---|---|
| 根 | `port`（**必填**）、`max_rooms`（**必填**）、`audience`、`worker_count`/`mailbox_capacity`（1/1024）、`default_template`、`metrics_port`/`gm_port`（0=关）、`gm_bind`（`127.0.0.1`，禁通配）、`settlement_journal`（**强制 `.journal` 后缀**）、`settlement_outbox_capacity`（10000） |
| `rooms.<模板>` | `expected_players`（**必填**，1..32）、`seed`/`map_id`、`match_time_limit_ms`/`waiting_timeout_ms`（0=不限）、`match_duration_frames`/`kill_limit`/`respawn_delay_frames`（**须 ≥1**）/`spawn_protection_frames` |
| `rate_limit` / `lobby` | 四组 burst/补充见 §3.3、`buckets` 8192、`idle_ms` 120000；`url`（空=不注册）、`instance_id`、`advertise_host`、`heartbeat_interval_ms` |
| `settlement` / `diagnostics` / `host_tuning` | `submit_url`（空=关闭）、5000、60000、5000；`enabled`/`directory`/`max_files`/`max_total_mb`/`max_commands`/`max_steps`/`log_tail_lines`；10 项部署调参（排空宽限与看门狗、Ops 间隔、入包上限、会话清理节拍、未进房静默 TTL、Lobby 超时、重连票据 TTL/容量、Outbox 压实阈值） |

### 6.2 云上现行值与环境变量
