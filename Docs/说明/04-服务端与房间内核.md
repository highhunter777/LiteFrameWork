## 1. 三个宿主与两层内核

| 工程 | 形态 | 职责 |
|---|---|---|
| `Server/RoomServer` | net8.0 控制台 | 60Hz 权威节拍 + 多房间：连接/会话/房间表、权威仿真驱动、快照与事件广播、重连、结算入盒、`/metrics` 与 GM 端点 |
| `Server/MetaServer` | ASP.NET Core Minimal API + Kestrel（Web 框架走 `FrameworkReference`）；外部包 `MongoDB.Driver` + `Newtonsoft.Json`（契约序列化，与客户端同库同设置） | 访客登录与访问令牌、实例注册心跳、Join 票据签发、战绩结算落库 |
| `Server/ReplayTool` | 仅引用 RoomServer | 回放权威输入流逐帧对账：退出码 0=一致 / 2=首分歧 / 3=身份或格式 / 4=IO / 5=记录截断 |

拓扑：Meta 签发 Join 票据（HMAC）→ 客户端持票经 KCP + 安全信封连房间 → 房间验签准入 → 房间 Mailbox → `RoomRuntime` 权威步进 → 快照 30Hz 下发 + 回溯判定 → 终局 `SettlementOutbox` POST 回 Meta（`matchId` 幂等）。

### 1.1 分层与纯度边界

纯逻辑不碰 IO，带 IO 的半边留在宿主：`Assets/RoomServer/Core`（`RoomServer.Runtime`）只依赖 `LiteSim.Core`，**R11** 禁 Transport/Socket、系统时钟、Console、文件 IO、proto、LiteNet，装权威运行时/输入闸门/回溯补偿/比赛状态机；`Assets/RoomServer/Modules`（`RoomServer.Application.Runtime`）可引用 LiteNet/proto，仍禁 IO、墙钟、Console、kcp，装快照/事件流水线、会话与准入编排；宿主 `Server/RoomServer` 全开。

asmdef 与 csproj 成对双编、LangVersion 锁死（Runtime/Application 为 9.0）防双轨漂移，Runtime 纯化由 L1 纪律扫描打红兜底；Application 在 Unity 侧 `autoReferenced:false`，只有开发档 `LiteGame.Dev` 引用，不进正式客户端运行链。

### 1.2 源链接共编与 BuildHash

服务端不复制共享代码，而是 csproj `<Compile Include>` 直编客户端仓库内的源文件——单源，漂移即 wire 不兼容：RoomServer 共编 Luban Runtime、`Assets/GameData/Generated/**`（表读码面）、`Serialization.Luban/{SimConfigMapper,TableLayout,MapTableProjection}.cs`；MetaServer 共编 `Assets/RoomServer/Modules/{JoinTicketFormat,Base64Url}.cs` 与 `Assets/RoomServer/Core/MatchStateMachine.cs`。改共享源集或共编件后必须跑 `python scripts/codegen/gen-build-hash.py`（一次写两个常量）；表**数值**改动不进闭包，走数据面摘要（见 §8）。

## 2. 房间服进程与线程模型

权威仿真单线程，其余只入队/只读：

| 线程 | 驱动 | 纪律 |
|---|---|---|
| `RoomServer.Loop` | `ServerLoop`：60Hz 权威节拍，专用线程 + 绝对锚点（`Anchor = start + n×freq/tickRate`）防漂移；落后有界追赶至多 5 帧，超限丢时间债 | 只跑 `ServerHost.Pump` |
| `RoomServer.Worker.N` | 固定 Worker 池，每线程一个有界 mailbox；按 roomId 哈希取模路由——同一房间永远落同一 Worker | 消费房间三 lane，驱动 Runtime 并广播 |
| GM / metrics 监听 | HTTP listener 线程 | 只入队/只读；GM 动作只在权威循环内执行 |
| 后台 HTTP ×2 | Lobby 心跳、结算提交（专用线程、单在途、有界停止） | 失败只影响分配/落库，不影响对局 |

房间与线程的交接面收敛在两处：**`RoomMailbox` 三 lane**（Input/Control/Outbound；有界，满/关闭显式返回；出队 Control → Input → Outbound，lane 内 FIFO）与 **`RoomInstance`**（单房间宿主侧状态，跨线程同步收进 Interlocked，单线程约束由结构保证）。生产装配是 Worker 执行形态（`workerExecution + mailboxRouting`），宿主直驱形态保留作退化路径。

一帧 `Pump`：

```text
TickIncoming（收包）→ 补投暂存断线 → FlushGmActions（GM 只在此执行）
→ 逐房间（插入序）：排空期超时兜底（到期未终态投一次 Shutdown）
   Worker 形态：Tick 入 Control lane → 应用 Worker 回传 → 销毁终态房间
   宿主形态：先排 Control → Input → Outbound，再投 RoomCommand.Tick → 快照 BroadcastIfDue
→ 周期清理（每 600 tick ≈ 10s：会话 TTL / 重连票据 / 限流桶）
→ TickOutgoing → Ops 周期行（5s）
```

宿主形态必须先排输入再投 Tick：否则 Tick 先推进帧号，同批里对 `frame+1` 合法的输入会被判 stale。权威 Sim 步进发生在房间 `Tick` 命令内部（`ExecuteTick`）：时限判定 → `StepFrame` → Sim 终局则 `Finish` 冻结结算。优雅关闭：信号（Ctrl+C/SIGTERM）→ 停收新会话 → 逐房间排空（超期兜底投 `Shutdown`）→ Outbox Flush → 退出。

## 3. 权威步进与裁决

### 3.1 `StepFrame` 的固定顺序（13 步）

`Assets/RoomServer/Core/RoomRuntime.cs`：

```text
1  AuthSim.Events.Clear()                     事件是帧内瞬态
2  frame = AuthSim.Frame + 1                  inputDelay=1 语义
3  逐席位 Gate.TryConsume(frame, i)            缺席用空输入；有 pending 开火打 ButtonDeferHit
4  SimStep.Step(..., advanceMatch:false)      权威步进
5  StepsCount++                               诊断
6  逐席位核验本帧真产 Fire（武器门放行）→ 清 ButtonDeferHit   空仓/冷却/死亡不能旁路资源门
7  CaptureEvents(frame, fireOnly:true)        必须在回溯清缓冲之前
8  SnapshotHistory.Capture（第 1 次）          回溯基料
9  _recentInputs.Record                       重连补发基料
10 LagComp.RecordInputs                       回溯历史输入
11 ConsumePendingFire                         逐个射手回溯判定 + FlushCommands + 事件捕获
12 MatchSystem.Tick                           整帧含回溯之后才判胜
13 SnapshotHistory.Capture（第 2 次）          覆盖最终计分/比赛态
```

两个易误解点：生产形态的 Match 不在 `SimStep` 内（生产形态在回溯判定之后才判胜）；同帧 Capture 两次（第一次供回溯、第二次覆盖最终状态），环成本 ×2 换回溯与计分的一致。

### 3.2 输入闸门

`InputGate` 是纯校验器（不持世界状态），单帧逐项检查，违规按原因计数并丢：

- **消息形状**：`Count > MaxFrames(16)`、`Frames == null` 或越界。
- **帧号**：上限 `serverFrame+8`（`FutureFrameTolerance`）、`frame<=0`、已消费帧 `frame<=serverFrame`。
- **意图**：按键白名单；切枪槽位 `[0,2)`；离散 seq 非零且严格递增（同帧同 seq 例外）。
- **数值**：Move/AimPoint 有限；Move 分量 ≤1、长度²≤1；Fire/Skill 帧 AimPoint 非零；**瞄准点距离闸** `dist² ≤ (射程×1.1)²`（`AimPointRangeTolerance`）。

补充语义：同帧去重"后到生效"（未消费前允许覆盖，只计数不丢）；EntityId 一律覆写为会话实体（防伪）；`ackSnapshot` 越界只钳位计数、不丢输入；未来帧 `(serverFrame+2 .. serverFrame+8]` 逐帧同口径校验后入库。存储环 `PendingInputRing`：容量 32 槽、玩家上限 32、`slot = frame & 31`、换代即整槽清空。距离闸把"打得到"变成可验证约束。

### 3.3 回溯补偿

以"玩家看到的过去"为裁判（`LagCompensator.CompensateFire`）：目标帧 `targetFrame = viewFrame`（客户端渲染帧）；窗口 clamp 到 `[auth.Frame-16, auth.Frame]`；窗口关闭/目标帧不在环/取不到输入 → 退化路径，按当前帧判定；射手取**当前**位/朝向/武器，仅当 Hp>0 才拷武器行；判定是暂存当前态 → 恢复到目标帧 → 单跑 `ShootingSystem`（带 `ButtonFireFlag`）→ 过滤历史命中；结果写回**当前帧**并 `FlushCommands`。同帧互杀时后结算射手取历史 Hp/武器行，活着的射手用当前武器行覆盖。结果四态 `NoFire / Compensated / DegradedFire / InvalidShooter`，计数进 Ops。

### 3.4 比赛生命周期与席位

`Created → WaitingForPlayers → Starting → Running → Finishing → Settling → Closed`，任意阶段可 → `Aborted`。开局只认房主 `StartEarly`（满员不自动开局），进房闸在 `Starting/Running/Finishing/Settling` 一律拒；席位取最低空位、满员拒，`NextPlayerId` 高水位只升不降（`AllocatedSeats` 才是在册人数口径）；未开局断线即释放席位，对局中断线保留席位；owner 是首个入座者、离席迁给最低在线席位、旧房主重连不夺回；非法迁移由 `IsAllowed` 裁决，输出 `Rejected:`，不改状态不抛。

## 4. 内核契约与入站

### 4.1 命令进、事件出、快照拉

命令入 8 种（`AuthenticatedJoin / ClientInput / Disconnect / Rebind / Tick / Shutdown / RestoreAck / StartEarly`，struct 联合、零分配）；事件出为 `PlayerAdmitted / MatchStarted / SeatRestored / OwnerChanged / SeatsChanged / JoinRejected / MatchStateChanged / SettlementReady / RoomAborted / StartRejected`，`TargetPlayerId=-1` 表示全体；快照不走输出事件——`SnapshotPipeline` 在步进后**拉取** `AuthSim`/`Gate` 构建下发。

Runtime 信任 App 层已验证的命令（校验只发生在闸门，不进内核）；proto 编码与发送归 App 层，握手/开局/终局经 `HandshakePacker`、输入解包经 `InputPacker`，真服与本地本服共用同一映射单源。

### 4.2 入站路由与准入

包级路由：`Join` → `InboundJoinHandlers`；`Input` → `InboundHandlers.HandleInput`；`MismatchReport` 只计 `Ops.NoteMismatch`；`ReconnectRequest` → `InboundReconnectHandlers`；`RestoreComplete` 转 `RestoreAck`（`Restoring → Active`）；`Leave` 转 `Disconnect`；`StartMatchRequest` 房主提前开局；`Heartbeat` 原样回显。每包前置：包长 > 4096 → `PacketOversized`；Session 包速率限流静默丢弃；会话 `Disconnected` 丢。KCP 收包 → 安全信封解包（握手未建立期间的包静默丢弃）→ proto 解码 → 准入链 → 会话映射/`RoomCommand` 构造 → 房间 Mailbox。

`JoinAdmissionGate` 六步顺序不可交换：① IP 入场频率（先于验签与建房）→ ② 字段 UTF-8 字节边界（RoomId/Token/BuildHash）→ ③ token 非空红线 → ④ buildHash 逐字比对 → ⑤ **票据验签（先于建房）**——垃圾票据不能撑大房间表 → ⑥ 账号入场频率（验签通过后才有 AccountId）。之后才是排空红线、既存房间控制 lane 容量、建房/复用。

限流四 lane：`IpConnect`（IP·连接，32 突发 4/s）、`IpEntry`（IP·入场，32/8）、`AccountEntry`（账号·入场，16/2）、`SessionPackets`（Session·包速率，256/128）。桶表每 lane 8192 条，满则拒新键（安全优先），空闲 TTL 120s；探测不到远端地址则跳过该维度。

## 5. 会话、重连、排空与结算

### 5.1 会话两级

身份事实在席位，连接只是载体：`Session`（连接级）断线即弃，持 ConnectionId/Epoch、路由缓存、票据身份，实现 `IBroadcastSeat`；`PlayerSession`（席位级）断线保留、重连复活，持 PlayerId/EntityId、Phase（Active/Disconnected/Restoring）、IsOwner、输入去重水位。会话表构造期定容（默认 4×房间容量）；未进房静默 60s 回收；断线保留期＝重连票据 TTL。

### 5.2 重连

签发在 Join 成功时（`ReconnectService.Issue` → `JoinAck.reconnect_token`）：CSPRNG 128 bit 不透明 token（base64url 22 字符）、TTL 300s、容量 256 超限淘汰最老、**一次性**（无论是否过期先 Remove）。入站：IP 限流 → Peek → 找房 → 队列容量 → 容量锁内消费票据 → `Rebind`（置 `Restoring`、`RebindGeneration++`、旧连接映射失效）→ 下发 Seed/ConfigHash/BuildHash + 全量快照 + 私有面 + 事件窗 + 最近 32 帧输入历史；恢复 ACK 前抑制该席位增量广播；`RestoreComplete` → `RestoreAck` 置回 Active 并产 `SeatRestored`（幂等）。重连只在 `Running` 有效。

### 5.3 排空五步

① 停止分配（`Draining=true` 随心跳上报，Lobby 停止分配）；② 停新 Join + 逐房 `SetDrainDeadline`（只可前移）；③ 限时完成或超时 Abort（`Pump` 检查 deadline，CAS 只投一次 `Shutdown(DrainTimeout)`）；④ 刷 Outbox（本就 write-through，此处收口 + 压实）；⑤ 停 Worker/Transport/Host（`Stop(drain:true)` → 房间收尾 → Transport → Outbox）。收敛判据 `DrainComplete` = 在排空且所有在册房间 `Runtime.Closed`。

### 5.4 结算

`Finish` 产 `SettlementReadyOutput(MatchResultSummary)` 并广播 `MatchEnded`；测试房（隐藏房）不入盒，仍发 `MatchEnded`。入盒四态 `Appended / Duplicate / RejectedFull / Failed`；JSONL 日志 `FileOptions.WriteThrough` + 每行 Flush；幂等键 `matchId = RoomId + ":" + Guid`；容量按**待提交**数计，满则显式 `RejectedFull`；完成标记累计 1024 条自动压实。提交线程取最老待提交 → POST Meta `/matches/result`（结算实例密钥）→ 2xx（含 duplicate）即完成；可重试失败（传输异常/401/403/404/408/429/5xx）保持待提交并指数退避，确定性 4xx（400/409/413/422）弃置；重启从日志待提交面重建。奖励由 `ISettlementRewardPolicy` 单点决定，当前 `NoEconomyRewardPolicy` 恒 0。

## 6. 安全模型

- **传输加密**：`SecureEnvelopeRoomTransport` 装饰传输层，三段握手（ClientHello/双 nonce/proof）→ `SecureEnvelopeSession`（AES-256-GCM、HKDF-SHA256 派生、64 位重放窗）；无密钥且未 `--allow-insecure-local` 拒启。
- **进房授权**：Meta 签发 Join 票据（HMAC-SHA256 盖章、nonce CSPRNG）→ 房间 `HmacJoinTicketValidator` 六步验签：kid 查表 → 常量时间比对 → 解字段 → 服务端时钟时效 → 绑定项（audience/roomId/buildHash/simVersion）→ nonce 一次性窗口（4096）；未知 kid/篡改/过期/重放/绑定不符全拒。
- **运维通道**：GM 端点只绑运维网（云端只绑隧道地址）、仅 POST + `X-GM-Key` 头、动作只在权威循环执行、全量审计，契约单源 `gm-contract.json`；路由有 `/gm/rooms`（读）、`/gm/start`、`/gm/abort`、`/gm/kick`、`/gm/settle-flush`、`/gm/rules`、`/gm/diag-list`、`/gm/diag-fetch`。

票据线格式 `JoinTicketFormat`（`v4` 共 16 段，签名覆盖除 sig 外全部段）以源链接同时编进签发方与验签方。

## 7. Meta 服务

### 7.1 分层与条件装配

分层为 `Contracts/`（端口 + DTO，零驱动依赖）、`Modules/`（用例：Auth/Lobby/Profile）、`Host/`（端点、鉴权、限流、迁移 HostedService）、`Infrastructure/Persistence/`（Mongo 适配器 + `SchemaMigrationRunner`）。装配是条件式的：密钥非空才注册对应模块，Mongo 连接串非空才注册持久化与迁移——缺配置等于功能降级不崩溃，唯一例外是启动迁移 fail-closed（配了 Mongo 而迁移失败，服务拒绝就绪）。配置链：内联默认 → `appsettings.json` → `META_` 环境变量 → CLI 覆盖。

### 7.2 端点与鉴权

| 方法 | 路径 | 鉴权 |
|---|---|---|
| GET | `/live` · `/metrics` | 无 |
| GET | `/ready` | 无；draining=503；Mongo 不可达=503 |
| POST | `/auth/guest` | 无凭据，每 IP 限流 |
| POST | `/lobby/instances/register` | Lobby 实例密钥 |
| POST | `/lobby/join-ticket` · `/lobby/create-room` | 访问令牌（版本不符 409） |
| GET | `/lobby/rooms` · `/lobby/rooms/public` | 实例密钥 / 访问令牌 |
| POST | `/matches/result` | **结算实例密钥**（与 Lobby 分权） |

统一错误体 `{code, messageKey, args[]}`，`args` 只放字段名/上限，不回显字段值。

### 7.3 身份、票据与持久化

- **游客登录**：`deviceId` 唯一索引做幂等裁判；`accountId = "a" + 20 hex`（CSPRNG）。
- **访问令牌**：9 段线格式 `v1.kid.accountId.jti.audience.purpose.iatMs.expMs.sig`，HMAC-SHA256 覆盖前 8 段，TTL 600s，校验 fail-closed（kid→签名→声明→时效→audience→purpose）。
- **建房**：前缀 `R-` + 6 位随机（去 `I/1/O/0`）+ 保留窗 120s + 重试 16 次；保留集上限 4096，满则拒出号；实例分配只选"未 drain 且未满"、声明 buildHash 时只选同值，排序确定（玩家少→房间少→实例标识序）。
- **签票**：`v4` 16 段、签名覆盖前 15 段；`matchId/simVersion` 置空、`nbfMs=0`；nonce 128 bit；TTL 300s；与房间端物理同一份（类注释仍写 v3/15 段，属注释漂移）；客户端只透传不解析。
- **持久化**：一条提交、双侧落库（归档面 `matchId` 幂等 + 账本面逐玩家 fan-out），归档先落；账本幂等双维度（`operationId` + 复合唯一索引 `(playerId, matchId, settlementType)`）；追加默认 `expectedRevision=-1`，≥0 走 CAS、不符整包 409；原子边界是副本集事务内"账目写 + revision 推进"，撞键回滚后读回首条返回 duplicate；单提交 ≤64 玩家、`delta` 绝对值 ≤1,000,000、同 `playerId` 不得重复；迁移 `LatestVersion=4`，失败逆序回滚并拒绝启动。

## 8. 表与地图、边界与已知缺口

**表与地图（fail-fast）**：`ServerTableLoader` 直读 `Assets/GameData/Config/*.bytes`——与客户端同一份字节，无服务端专属表；按 `TableLayout.Files` 清单装载 → `SimConfigMapper` 投影出 `CombatValues` 实例 → 经装配入参显式传入（缺表即拒装配）。数据面守卫是运行期摘要：`TableLayout.ComputeGameplayDigestBase` 算判定面摘要 → 随 `StartGame.ConfigHash` 下发 → 客户端装载后复算比对，不等拒局——表数值可两端各自热更、不必同步出包。地图经 `ServerMapCatalog` 做多图映射（行键→判定图），缺行 fail-closed。

**边界**：改 Sim 源码/proto/表源必跑 `python scripts/codegen/gen-build-hash.py`（漏跑＝Join 握手全员拒进房）；R11 禁项时间只从 `Tick.nowMs` 进；监听线程不得动房间状态（GM/metrics 只入队/只读）；配置是启动期快照（`roomserver.json`/`META_` 改后必须重启进程）；密钥一律环境变量（`LITENET_*` 五把），开发本地无密钥必须显式 `--allow-insecure-local`。

**已知缺口（现状，不是待办清单）**：

1. `PurgeExpiredNonces` 无生产调用点：nonce 窗口满时的策略是**拒新票**，不是清理。
2. `CompensateFire` 的 `clientAckSnapshot` 形参未使用——对齐已改为直接信任 `viewFrame`，调用处仍传值。
3. 测试房不产结算：`sandbox` 模板不限时/不按击杀结束，隐藏房也不入盒，"打半天没战绩"通常是预期行为。
4. 奖励恒 0：`NoEconomyRewardPolicy` 有意为之，经济系统未接入。
5. Meta 单实例：实例注册表与出号保留集驻进程内存，不支持多实例。
6. 容量与阶段限制：部署配置 `max_rooms=8`、席位上限 32、`Running` 后不可中途加入，观战/回放无实现。
7. 输入丢弃原因只暴露 5/10：`InputGate` 有 10 个计数（重复/越界/过期/ack/按键/seq/槽位/非有限/向量/超长），Ops 只输出其中 5 个。
