## 1. 三条本地路径

| 路径 | 开什么 | 适用 | 不适用 |
|---|---|---|---|
| **A 本地测试模式**（进程内，最快回路） | 只开编辑器 | 表现/玩法手感迭代、动画/HUD/准心、GM 调参 | 真实网络、多客户端、弱网/重连 |
| **B 本地全链**（Meta + RoomServer） | Mongo + MetaServer + RoomServer + 客户端 | 登录/大厅/创房/票据/结算全链、真网络链路、多客户端 | 日常快速迭代（起链重） |

直连测试身份（`Room-A` / `c2-dev-token`）已退役：`request direct`、`TestToken` 与 `UseLocalServer` 全局回退都已删除（有 EditMode 用例钉住"字段不存在"）。本地真 KCP 只剩 B 一条路径，快速回路走 A。

## 2. 两个决定成败的机制

### 2.1 BuildHash 握手门

共享源集被编进两端程序集，两侧算出同一个常量：`Assets/LiteSim/Scripts`、`Assets/LiteSim/Systems`、`Assets/LiteNet/Core/Proto`、`Assets/LiteNet/Core/Protocol`、`Assets/LiteNet/Core/Transport/Security`、`Assets/GameData/Generated`，加上 `SHARED_LINK_FILES` 两条源链接件（`Assets/LiteFramework/Runtime/Adapters/Luban/SimConfigMapper.cs`、`TableLayout.cs`）。权威清单是 `gen-build-hash.py` 的 `SHARED_TARGETS` 与 `SHARED_LINK_FILES`，不在文档里。

改这些内容后必须跑 `python scripts/codegen/gen-build-hash.py`，重新编译/打包两端。漏跑的后果不是报错，而是 **Join 握手直接拒进房**（客户端表现：`JoinAck` 永不到，10s 超时进错误态）。生成物两处：`Assets/LiteNet/Core/Protocol/BuildHash.g.cs`（客户端+房间，握手红线）与 `Server/MetaServer/Host/BuildHash.g.cs`（Meta 构建身份，只进启动日志 `build=`，不参与准入）。`--check` 复算两个常量，`--check-shared` 只复算握手那个——出包门禁用的是后者。**表数据（`.bytes` 数值）不在闭包内**，表值可两端热更；但改表源后生成读码面变了，仍要重跑。

### 2.2 安全信封 PSK

真实 KCP 通道强制加密（AES-256-GCM / HKDF-SHA256 / 64 位重放窗口）。服务端没给密钥**直接拒绝启动**（fail-closed，`--allow-insecure-local` 仅用于服务端单机自测，没有任何客户端能连上它）；客户端没给密钥直接抛错。三处（RoomServer、编辑器、exe）必须是同一把 Base64 32 字节 PSK。

## 3. 环境前置

- Unity **2022.3.55f1c1**（中国版，revision `06b99830297d`）+ Pipeline（`unity` CLI 在 PATH）；`.NET 8 SDK`；打 exe 只支持 Windows。
- B 路径额外需要：本机 MongoDB（Meta 持久层；连接串空 = 持久化关，能起但账本不落）。
- 生成密钥（PowerShell，32 字节 → Base64）：

```powershell
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))
```

一次性 `init` 会生成**五把**：`ENVELOPE_PSK`、`AUTH_SIGNING_KEY`、`LOBBY_INSTANCE_KEY`、`LOBBY_TICKET_KEY`、`SETTLEMENT_KEY`。手动配 Meta 时只涉后四把；信封 PSK 归传输层。密钥不入库、不进文档、不回显。

## 5. 路径 B：本地全链（Meta + RoomServer + 大厅/票据）

### 5.1 一键操作（推荐）

```powershell
python scripts/local/local-chain.py init    # 生成 deploy/.env（五把密钥）+ Assets/StreamingAssets/deploy.args
python scripts/local/local-chain.py up      # 起 Meta + RoomServer（各开一个日志窗口）
```

- 子命令：`init` / `meta` / `room` / `up` / `status` / `keys`；`init` 已存在不覆盖，`--force` 重生成。
- `deploy/.env`（gitignore 内）含五把密钥加端点/路径：`META_BIND`、`META_URL`、`MONGO_CONNECTION`、`MONGO_DB`、`ROOM_CONFIG`、`ROOM_PORT`、`LOBBY_DEFAULT_ROOM_ID`（客户端「快速进入」的落点房号，缺省 `lobby-default`；留空则该钮被 Meta 拒 400）。
- `init` 同时写 `Assets/StreamingAssets/deploy.args`（`-envelope.key=` + `-meta.url=` 两行）——编辑器 Play 后直接走登录页/大厅，exe 也能零参数启动。
- `status` 一屏总览：BuildHash、Meta 进程与 `/live`、Mongo 可达性、RoomServer 进程与 UDP 端口、信封/票据门禁状态、客户端烙入内容、密钥脱敏汇总。
- 图形界面：`LiteGame/工具链` → 「本地联测」页（工具 `debug.local-chain`），同一份 `deploy/.env` 驱动；Start/Stop 两端，输出重定向到 `deploy/logs/meta.log` / `room.log` 并在页内尾随，探针 1s 节流、只读。

### 5.2 手动起 Meta

填 `Server/MetaServer/appsettings.json` 的 `Meta` 节：`BindAddress`、`MongoConnectionString` + `MongoDatabaseName`（**成对**填，只填一半启动即拒）、`AuthSigningKeyBase64`、`LobbyInstanceKeyBase64`、`LobbyTicketKeyBase64`（`LobbyTicketKeyId` 默认 `l1`、`LobbyTicketAudience` 默认 `lobby`）、`LobbyDefaultRoomId`、`SettlementInstanceKeyBase64`；`EnableSampleEndpoints` 保持 false。

```powershell
dotnet run --project Server/MetaServer -- --bind http://127.0.0.1:5000
```

`ValidateOnStart` 一次报齐所有配置违规；成功横幅含监听地址与 `/live` `/ready` `/metrics`。`/live` 只证事件循环在响应，`/ready` 含存储探测且 drain 期间必须未就绪。房间侧另用 `POST /lobby/instances/register`（注册）与 `POST /matches/result`（结算，凭 `SettlementInstanceKeyBase64`，与 Lobby 注册分权）。

### 5.3 手动起 RoomServer

```powershell
dotnet run --project Server/RoomServer -- --config Config/roomserver.json --port 17777 `
  --envelope-key <ENVELOPE_PSK> `
  --ticket-key "l1:<LOBBY_TICKET_KEY>" `
  --lobby-instance-key <LOBBY_INSTANCE_KEY> `
  --settlement-instance-key <SETTLEMENT_KEY>
```

密钥也可走环境变量：`LITENET_SECURE_ENVELOPE_KEY` / `LITENET_TICKET_KEY` / `LITENET_LOBBY_INSTANCE_KEY` / `LITENET_SETTLEMENT_INSTANCE_KEY`（`--ticket-key` 可多次给多个 kid）。成功标志：`安全信封已启用`、`票据验签已启用（kid: l1 / audience: lobby）`、`Lobby 注册已启用：url=…`、`结算提交管道已启用：url=…`。**同机开第二个实例**必须换工作目录或换 journal 路径（结算 journal 是 CWD 相对的独占文件，双实例同 CWD 撞文件锁）。

### 5.4 配置键位（`Config/roomserver.json`，严格 JSON、禁注释）

| 键 | 必填 | 语义 |
|---|---|---|
| `port` | 是 | KCP 监听端口 0..65535（0 = 系统分配，实际端口从横幅回读；仓库值 17777） |
| `max_rooms` | 是 | 房间数上限 1..65535，满则拒新建（仓库值 16） |
| `rooms.<模板>` | 是 ≥1 | `expected_players` 必填 1..32（满员开局依赖它）；可选 `map_id`（0/缺省 = 宿主默认图；模板与票据盖章行键各持非 0 且不等 → 拒绝建房）、`seed`、`match_time_limit_ms`、`waiting_timeout_ms`、`match_duration_frames`、`kill_limit`、`respawn_delay_frames`、`spawn_protection_frames` |
| `default_template` | — | 缺省模板名，必须存在于 `rooms`（缺省 `default`） |
| `audience` | — | 票据受众比对（空 = 不校验；与 Meta `LobbyTicketAudience` 同值） |
| `worker_count` / `mailbox_capacity` | — | 1..256（缺省 1）/ 1..1000000（缺省 1024） |
| `settlement_journal` | — | **必须 `.journal` 结尾**（`.json`/`.bytes` 进 buildHash 闭包，落错处 = 握手全拒）；缺省 `Outbox/settlements.journal` |
| `settlement_outbox_capacity` | — | 1..1000000，缺省 10000 |
| `rate_limit` | — | 分层限流 `{ip,entry,account,session}_burst/_per_sec` + `buckets`（缺省 8192）+ `idle_ms`（缺省 120000）；整段缺省 = 内置，给了就逐字段校验 |
| `lobby` | — | `url` 加必随的 `instance_id`（≤64B）/ `advertise_host`（≤128B）/ `heartbeat_interval_ms`（1000..300000）；`url` 空时不许配其余字段（半段配置拒启） |
| `settlement` | — | `submit_url` 加可选 `submit_interval_ms`（5000）/ `submit_max_backoff_ms`（60000）/ `submit_timeout_ms`（5000）；`url` 空时不许配其余 |
| `host_tuning` | — | 运维调参：`drain_grace_ms`、`drain_watchdog_extra_ms`、`ops_interval_ms`、`max_inbound_packet_bytes`、`session_cleanup_interval_ticks`、`session_unseated_idle_ttl_ms`、`lobby_request_timeout_ms`、`reconnect_ticket_ttl_ms`、`reconnect_capacity`、`outbox_compact_threshold_marks`（逐字段范围校验） |
| `metrics_port` | — | `/metrics` 出口（0 = 关，缺省）；Windows 非管理员绑 `+` 前缀需 urlacl，失败告警降级不断服务 |
| `gm_port` / `gm_bind` | — | 运维写端点（0 = 关，缺省）；`gm_bind` 缺省 `127.0.0.1`，通配地址装载期即拒 |
| `combat` | **禁** | 玩法数值只走 `.bytes` 表，配了装载即拒 |

### 5.5 客户端接入

```powershell
& "Builds\StandaloneWindows64\Test.exe" -envelope.key "<同一把 PSK>" -meta.url "http://127.0.0.1:5000"
```

参数键（剥前导 `-` 后大小写不敏感）：`meta.url`、`meta.timeout`、`envelope.key`、`device.id`、`room.template`、`room.gmkey`、`gm.url`、`gm.key`。合并序：**命令行 > 包内 `deploy.args` 烙入 > 字段默认**；信封另有环境变量 `LITENET_SECURE_ENVELOPE_KEY` 兜底（命令行/烙入皆空时才回落）。`device.id` 空则落机器标识——同机的编辑器与 player 会算同一账号，同机多客户端要各自身份时显式给不同值。`meta.url` 空 = 未配置，登录页显性拒绝，不悄悄回退本地。

## 6. exe（IL2CPP Player）

### 6.1 出包链

```powershell
python scripts/build/build-player.py                  # 编辑器开着执行，不需要第二个实例
python scripts/build/build-player.py --skip-restore-check   # CI 用（已单独跑过环境校验）
python scripts/build/build-player.py --skip-bundles         # 仅纯代码迭代，内容可能旧
```

Profile `BuildProfiles/windows-x64.json`：`StandaloneWindows64` / IL2CPP / x86_64 / `channel=development`（带 `Development`+`DetailedBuildReport`，exe 里 F3 开发控制台可用）/ 场景 `Assets/Scenes/Boot.unity` / `contentMode=OfflineBundles` / 产物 `Builds/StandaloneWindows64`。

链上步骤（任一失败即中止）：`restore-check.py` → `l0-dep-scan.py` → `gen-build-hash.py --check-shared` → 对齐 `activeBuildTarget` 与 `scriptingBackend`（切后端后 25s 复读校验）→ 场景集合与 profile 双向同步 → 端点烙入 → 内置内容包 → dry-run → `build --confirm` → 每 20s 轮询 `build_status`（45 min 上限）→ 产物存在性 + 新鲜度（产物目录里有比构建开始更晚的文件，否则判"没产出"）。

### 6.2 内置内容包

包由 `LiteGame.EditorTools.BuiltinBundleBuildInvoker` 构到 `Assets/StreamingAssets/yoo`（`DefaultPackage`，版本号 `1.0-<UTC 时间戳>`，每次唯一），随包分发供 Offline 文件系统应答。`build-player.py` 自动调它（10s 轮询、20 min 上限），编辑器 Play 中构建会失败——先停 Play 再重试。手工入口是 Hub 动作 `content.bundle-builtin`（`LiteGame/工具链`）。内置包已接线的平台见 `build-player.py` 的 `BUNDLE_PLATFORMS`（当前 `StandaloneWindows64` 与 `Android`）；平台不在清单内时 profile 必须显式 `--skip-bundles`。Windows 上它只建议用于纯代码迭代，漏跑这步等于把上一版内容打进包，症状是 exe 启动即 `BOOT FAILED 配置文件加载失败:…bytes`（`Player.log` 里是 Preload 失败）。成功行形如 `[Asset] ready package=DefaultPackage version=1.0-<时间戳> root=builtin`。

### 6.3 端点烙入（零参数分发）

`BuildProfile.endpoints` 写 `{"meta.url": "...", "envelope.key": "...", "content.cdnUrl": "..."}`。打包时按行写成 `StreamingAssets/deploy.args`（`-key=value`）：值**不得含空格**（token 形态，含空格直接拒绝烘焙）；`endpoints` 为空/缺省时**删除残留的 deploy.args**，换渠道重打不会带上一个包的密钥。玩家双击即玩，运维仍可用命令行临时覆盖；编辑器里手放一份 `deploy.args` 同样生效。信任边界不因烙入改变：PSK 与基址本来就在客户端二进制里可提取（防窃听篡改，不承担客户端身份），CDN 内容另有 RSA 验签。

### 6.4 启动冒烟

```powershell
python scripts/build/player-smoke.py --timeout-sec 30
```

先 `taskkill` 同名进程、删 `Player.log`，再起 `Builds/StandaloneWindows64/Test.exe`（默认 exe 名 = `productName`），在超时内命中两个**定义态标记**之一即通过：`BootstrapError`（预载失败并显示内建错误 UI）、`[Asset] ready`（离线包就绪）；早退或无标记判失败。不得用裸标识符当标记——旧版拿 `AssetService` 当标记，命中的只是启动栈帧那一行。可选模式：`--mem-loop`（校验 `[MemLoop] cycle=…` 行数、常驻数不漂移、后 5 轮均值相对前 5 轮增长 ≤ 8MB）、`--input-modal`（校验五段 `[InputModal]` 相位行）。

**安卓通道**（`--platform android`）：

```powershell
python scripts/build/player-smoke.py --platform android `
  --apk-path Builds/android/Test.apk `
  --adb-path E:/unity3d/2022.3.55f1c1/Editor/Data/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb.exe `
  --adb-serial 127.0.0.1:7555
```

流程：ARM 翻译预检（`getprop ro.product.cpu.abilist` 必须含 `arm64-v8a`——xLua 只发 arm64/x86，x86_64 模拟器靠翻译层时会带出该项；无此项当场 fail-fast，可用 `--skip-arm-preflight` 跳过）→ `install -t -r` → **`logcat -c` 清缓冲**（防上一局残留标记造成假绿）→ `am force-stop` + `am start -n <包名>/com.unity3d.player.UnityPlayerActivity` → 每 2s `logcat -d` 轮询同一份定义态标记表 → 会话日志导出 `TestResults/android-smoke/android-smoke-<时间戳>.log`（`--log-artifact` 可改路径，AC5/AC6 共用该工件）→ `uninstall` 清理（`--keep-installed` 可保留）。包名默认读 `ProjectSettings` 的 `applicationIdentifier`，可用 `--package-name` 覆盖。**与桌面通道的判定差异**：安卓的 `BootstrapError` 判失败（包内容是内置的，出现错误 UI 就是真问题），只有 `[Asset] ready` 判通过。

## 7. 改完代码后的操作序

`Gen` = 生成物命令，`服` = 停服后重起，`编` = 编辑器重编译，`包` = exe 重新打包。

| 改动面 | Gen | 服务器 | 编辑器 | exe |
|---|---|---|---|---|
| 纯表现（`LiteGame` App/UI、`LiteView` 动画、场景/prefab/美术/音效） | — | 不动 | 编（即改即生效） | 包才生效 |
| 玩法判定共享源（`LiteSim`、协议/信封、`GameData/Generated`） | `gen-build-hash.py` | 停服 → 重起 | 编 | **必须包**（旧 exe 握手必拒） |
| 表源（`Luban/Data/*.xlsx`，含文案/准心手感/武器数值） | `Luban/gen.bat` → `gen-build-hash.py` | 停服 → 重起 | 编 | 包 |
| `.proto`（`Assets/LiteNet/Core/Proto/battle.proto`） | `gen_proto.py` → `gen-build-hash.py` | 停服 → 重起 | 编 | 包 |
| 服务端宿主（`Server/RoomServer`、`Server/MetaServer` 的 .cs） | — | 停服 → 重起 | 不影响 | 不影响 |
| Lua/文案脚本（`Assets/LiteGame/Lua`） | — | 不动 | Play 重进（随 Preload 装载） | 包 |

口诀：改表现=编辑器即改即玩；改判定=两端同步加 exe 重打；改数据=Gen+双端；改宿主=只重启服务器。三个高频坑：改服务端/共享代码**前先停服**（活进程锁 `Server/*/bin` 的 DLL，不停服跑 L1 或 dotnet 编译会报 `MSB3027`）；编辑器侧改信封/协议后**忘了等重编译**就开测，两端哈希不一致 Join 被拒；exe 测试用 Development 档（当前唯一档），才有 F3 开发控制台。

## 8. 排障速查

| 症状 | 大概率原因 | 处置 |
|---|---|---|
| `JoinAck` 永不到 / 握手即断 | BuildHash 两端不一致（共享源没双端同步，或 exe 是旧包） | 看服务端哈希比对行 → 跑 `gen-build-hash.py` → 双端重启 → exe 重打 |
| 信封握手失败断开 | PSK 两端不一致或客户端没拿到 | 核对 `LITENET_SECURE_ENVELOPE_KEY`（服务/编辑器/exe 三处同值） |
| RoomServer 起不来 | 缺信封键（fail-closed）或配置半段/越界 | 看启动异常文本（装载期逐项列出） |
| 编辑器进对局抛信封错 | 启动 Unity 前没设环境变量，也没有 `deploy.args` | 跑 `python scripts/local/local-chain.py init` 或退出 Unity 设变量后重开 |
| 端口不通 | KCP 是 **UDP**（17777），不是 TCP | `netstat -ano -p udp` 查占用；本机回环一般无碍 |
| L1 或 dotnet 编译报 `MSB3027` | 本机活服进程锁 DLL | 停服再跑 |
| exe 行为与编辑器不一致 | exe 内容是打包时内置的（表/场景/prefab 旧） | 重打包；对照 §7 |
| Meta 登录/大厅/创房失败 | Mongo 未起、几把键不同值、票据键不匹配 | 按 §5.2/§5.3 逐项核对键值 |

成功标志：客户端日志 `[Battle] joined (JoinAck)`；服务端横幅出现房间创建/进房行。

## 9. 已知缺口

- **Hub「本地联测」页的 init 按钮调的是 `scripts/local/local-chain.ps1`**，而仓库已无任何 `.ps1`（脚本全量 Python）。当前只能用 `python scripts/local/local-chain.py init`；页内 Start/Stop/探针不受影响。
- **`local-chain.py status` 与 `scripts/codegen/refresh-hash.py` 仍读 `Assets/LiteNet/Protocol/BuildHash.g.cs`**，生成物实际在 `Assets/LiteNet/Core/Protocol/`。表现是 status 的 BuildHash 行显示 "(missing)"、refresh-hash 直接抛文件不存在；改哈希请直接跑 `gen-build-hash.py`，再分别重建服务端与触发 Unity 重编译。
- `scripts/gate/toolchain.json` 里 `content.bundle-builtin` 的 `menu` 字段仍记 `LiteGame/Resource/构建内置 Bundle 包（Offline）`，但编辑器侧已无该 `MenuItem`：入口按 `handler` 分发到 Hub 动作，`check` 只校验 `menu` 唯一性、不校验其存在。
