## 1. 程序形态：一个组合根

客户端只有一个入口，没有第二条引导路径：

```text
Boot.unity
  └─ GameEntry（唯一 MonoBehaviour 引导适配器，ExecutionOrder -1000，s_booted 幂等）
       ├─ ClientHost（启动/关闭持有者，纯 C#，不依赖 UnityEngine）
       ├─ AppLifetime（平台桥：Pause/Focus/LowMemory/Quit）
       └─ 13 个 IClientModule（注册序 = 初始化序 = 关闭逆序）
```

- `GameEntry`（`Assets/LiteGame/App/GameEntry.cs`）：建 Host、注册模块、喂帧与生命周期事件；`Update` 单点把 `Time.unscaledDeltaTime` 交给容器 `Tickables`。
- `ClientHost`（`Assets/LiteFramework/Runtime/Modules/Hosting/ClientHost.cs`）：真正的启动/关闭持有者，持根作用域、模块表、刷新钩子、平台事件回调。
- `AppLifetime`（`Adapters/Unity/App/AppLifetime.cs`）：唯一把平台消息翻译成 Host 订阅；`Quit` 是意图，由流程放行。
- `ModuleContext`/`ClientContext`：模块装配窗口与产物注册表。

宿主的四条硬语义：注册序即初始化序与关闭逆序（启动后 `AddModule` 抛 `InvalidOperationException`）；失败只回滚已成功部分（按 `_initializedCount`）；单模块关闭失败不阻断其余（异常聚合上报）；退出前按登记序跑 `AddPreShutdownFlush`。初始化前先做图校验（重名/缺依赖/依赖环）在副作用之前 fail-fast。静态状态只留 `s_booted` 与 UI 动效时钟两个复位点，由 `ResetForEditorReload` 处理 Domain Reload Off 的二次 Play 死锁。

## 2. 模块链：注册序就是依赖图

### 2.1 模块与产物

① `PlatformInfrastructureModule`：持久化 + 日志（先于一切 IO）；② `IdentityModule`：`IdentityContext`；③ `DevSessionModule`：`IDevSession`（设备源构造即消费，须早于 ⑫）；④ `ContentModule`：`IContentService`、`ActivationTransactionStore`、`PatchRunner`、`AssetsHealthProbe`；⑤ `SettingsModule`：`SettingService` + `GameSettings`；⑥ `ClocksModule`：World/UI 双轨时钟 + `EventBus`；⑦ `SchedulersModule`：`GameTimelineRunner`（依赖 ⑥）；⑧ `LuaHostModule`：`LuaComponent`；⑨ `ConfigModule`：`ConfigService`（表字节走 ④ 的租约通道）；⑩ `UiServiceModule`：三注册表、`RedDotRegistry`、`UIService`、`UINavigationController`；⑪ `PresentationModule`：`EntityService`、`AudioService`、`VfxService`、主相机；⑫ `InputModule`：`IInputService`；⑬ `ContainerModule`：消费以上全部 → 容器 + 流程机。

插入一个模块等于声明"它依赖前面全部、被后面依赖"，顺序不是风格。

### 2.2 装配窗口与产物交换

`ModuleContext` 是 `IClientModule.InitializeAsync` 唯一的登记面：

**`Put<T>` 只在本模块初始化返回前的窗口内合法**（返回/抛出/取消/异步续体晚到再 Put 一律抛）；**`Require<T>` 缺失即抛**（fail-fast），`Get<T>` 缺失返回 null；**同型同引用可重复暴露，换引用当场拒绝**；全部模块成功后装配面密封（`IsAssemblySealed`），运行期不得新增注册。产物最终登记在同一来源的 `ServiceContainer` 上。

### 2.3 装配末段：`ContainerModule`

读完这一个文件就知道客户端有什么服务，它按五组收敛：① 引擎服务键（场景、派发器、时钟驱动、别名注册、判定图投影 `IMapProvider`）；② 命令与调试（`CommandCenter` 与 `ICommandCenter` 指向同一实例；GM 命令/弱网预设/`DebugKernel` 只在开发三宏）；③ 会话与联机（`MetaDeployConfig` 三源快照 命令行 > 包内烙入 > 默认、摘要提供者惰性求值、传输工厂委托、两半会话工厂、`MetaEntryService` 未配置基址即置空）；④ 反馈与页面流（`DialogService`/`ToastTicker`、`Bridge` 绑定、`ui.modal` 拦截源、`PageFlow`；模态登记只留不依赖表的 Error/Confirm，设置页 id 随 Preload 放行闸口登记——此处查表必抛）；⑤ 帧驱动序 + `Seal()` + 流程机。

## 3. 容器、帧驱动与作用域

### 3.1 容器能做什么、拦什么

`Assets/LiteFramework/Runtime/Core/DI/ServiceContainer.cs`：构造注入（按构造函数递归解析）；`Validate()` 只遍历声明图、不执行构造与工厂，缺依赖与循环依赖当场抛；生命周期越域即拒（Singleton 依赖 Scoped、根容器注册 Scoped、Transient 实现 `ITickable` 都抛）；`Seal()` = `Validate()` + 置 `_sealed`，之后注册一律抛；子容器向父域读 Singleton、只持本域实例（Account/Match 两级各挂一个）；`ServiceOwnership.Borrowed`/`ContainerOwned` 决定是否随容器释放；自动发现 `IModuleStats` 供 DevHUD 拉取。

### 3.2 帧驱动序（13 件）

`SetTickOrder` 在装配根显式声明，`GameEntry.Update` 按索引遍历调用（接口枚举器每帧箱化，故不用 foreach）：

```text
MainThreadDispatcher → WorldClock → UIClock → DotweenUiClockDriver → UIService
→ LogicScheduler → UIScheduler → TimelineRunner → VfxService
→ DialogService → ToastTicker → CommandCenter → StageMachine
```

三个排序决策：派发器最前（后台完成先切回主线程）；时钟先于一切时间消费者；命令中心在流程机之前（排队/延迟命令当帧到期即可被流程应用）。`EventBus` 不在链上——它已无内部队列，不再实现 `ITickable`。容器 Seal 后对局期零注册，对局能力来自阶段生命周期与构造注入。

### 3.3 作用域树与租约

`Assets/LiteFramework/Runtime/Core/Scope/ClientScope.cs` 是取消、释放与租约的底座，五层树为 Root → Account（登录会话）→ Match（一局匹配/房间连接）→ Scene（对局场景组）/ UI（页面资源）。

取消级联（子令牌链接父令牌）；LIFO 释放（按登记逆序，单项失败不阻断，异常收集在 `DisposeFailures`）；释放后再 `Register` 会就地释放并抛 `ObjectDisposedException`（错误契约的一部分）；资源以 `AssetLease<T>` 归还，视图侧 `PrefabLeaseCache` 按作用域缓存同一 prefab。

运行时时间线：引导期由 `ClientHost` 建 Root 作用域与根容器；进房时 `AccountSessionFactory.Create` 建 Account 作用域 + 子容器 + `BattleClient`（构造即发 Join，失败就地回滚重抛）；会话建立时 `BattleContext` 构造期建 Match 作用域并把 RoomClient 订阅登记进去；对局中 Scene/UI 子作用域按需；离场按"视图与驱动 → Match 服务域 → Account 作用域 →（非宿主关闭时）卸场景组"拆。离开一个域 = 冻结它的一切，不存在逐件手工清理清单。

## 4. 基础设施：时钟、事件、命令、状态机、池

**时钟**（`Core/Clock/GameClock.cs`）是全项目唯一的缩放实现：

```csharp
ScaledDelta = Paused ? 0 : realDelta * TimeScale;   // realDelta 先被 MaxDelta=0.1 钳制
```

World/UI 两个实例分别驱动逻辑调度与表现时间轴（`UiAnimationClock`）；Unity `Time.timeScale` 恒为 1，避免"0.2 × 0.2"的双缩放事故；单帧 delta 钳到 0.1s。**边界**：流程机与对局推进不消费 `ScaledDelta`（`StageMachine` 吃 unscaled、`RollbackSim` 用真实帧间隔）——暂停 WorldClock 只冻结走 `IGameClock` 的消费者。

**事件与命令**：`EventBus` 是通知（优先级派发、延迟派发、有界队列、发布拦截链），`CommandCenter` 是意图（类型化注册-执行-结果、排队/异步、拦截器、权限门、撤销重做、审计环 32 条）。事件不承担"必须成功"，命令不用于广播；UI 开关走导航，帧事件走事件中心。

**状态机**（`Core/Fsm/`）：`StageMachine` 扁平 + 显式迁移表跑启动流程；`HierarchicalStageMachine` 父子状态、子继承父迁移；配套 `TransitionTable`、`FsmCapture`、`StageGraphDiagnostics`、`FsmAudit`。抢占/恢复机体已删除（无消费者），`StageSpec` 的优先级/可打断字段仅作表数据兼容保留。

**池、IO、日志与错误契约**：`ObjectPool<T>`/`ReferencePoolService`/`CollectionPool<,>` 服务高频创建与热路径零分配；`FileSystem` 是唯一 IO 门面（禁旁路 `File.*`）；`Log`/`LogTag`/`ILogSink` 是统一日志门面（禁 `Console.WriteLine`/`Debug.Log` 直写）。错误契约：已关闭服务抛 `ObjectDisposedException`、程序员错误 fail-fast、内容问题 `Log.Warning` + 默认值。

## 5. 流程机：七个阶段与放行闸口

`Launch → Patch → Preload → Main → Match → Battle`，再加 `Error` 终态，由一台扁平状态机 + 显式迁移表驱动——启动不需要抢占/层级状态机的表达力，显式表让流程可被静态检查与审计。

**Launch** 引导收尾；**Patch** 热更候选（`PatchRunner` 取候选过信任锚，阶段状态机与激活事务归协调器）；**Preload** 配置装载 + Lua 填表（放行闸口，五步序任一失败即阻断进 Main）；**Main** 启动入口决策（不加载对局场景，联机入口未配置时页面显性拒绝）；**Match** 建 Account 会话（类型化工厂把进房参数变成可移交的 `AccountSession`）；**Battle** 对局全程（独占对局场景组进出场与会话生命周期）；**Error** 终态。

`ProcedurePreload` 五步序不可换：① Lua 全量预载 → ② Init env + 执行 main.lua → ③ `RegistryFiller` 读三件套逐行填充 → ④ 整批统一判定（不遇错即停，一次拿全部问题）→ ⑤ 放行（模态登记已就位）。

进房参数链：正式构建走 `MetaJoin`（Meta 签发的 Join 票据 Host/Port/RoomId/Ticket，服务端验签）——开发与正式构建同一条链，测试房只是传输决策的一个分支。会话装配拆两半工厂：`AccountSessionFactory` 零引擎依赖、行为可在 L1 直测；`MatchSessionFactory` 是 Unity 面（`BattleContext` 依赖 SimView），从 Account 服务域派生 Match 子域。两半都是类型化工厂，拼装错误在工厂内就地回滚，不泄漏半个建好的域。

## 6. 一次帧的三层驱动

第一层是 §3.2 的常驻 tick 链（13 件），变速只在 `IGameClock` 内部发生。第二层是流程机：`StageMachine.OnUpdate` 是 tick 链末件，对局期它就是 `ProcedureBattle.OnUpdate`。第三层是对局帧序，序不可换：

```text
① 渲染采样前：rig.TickPreSample()（诊断件先动）
   瞄准世界注入 → SampleOnRenderFrame（上下文门裁决：任一拦截源成立＝本帧输入为空）
② context.Tick(realDelta)：对局唯一驱动入口
③ rig.Tick(realDelta)：视图消费者——本帧权威已应用后才动
```

`BattleContext.Tick`（`Assets/LiteFramework/Runtime/Modules/Battle/BattleContext.cs`）内部五段：

```text
TickIncoming（收泵）
→ 输入三件：采样入史 → 同一份上行 → 沿用帧预发（必须先于本地服步进）
→ TickOutgoing（本地测试形态在此步进真房间内核）
→ Sim.Tick（固定步长预测推进；Log.SetFrame 帧轴随之推进）
→ ResendCarriedFrames（未确认段冗余重发）
→ View.Tick（表现视图）
```

输入上行帧号 = `Sim.Frame + InputLeadFrames`，`InputLeadFrames = 3`（覆盖 RTT + 抖动，代价约 2 帧本地输入延迟）；回溯锚点 `viewFrame` 取视图当前渲染帧，即"玩家看到的过去"。收尾是同步的：`Leave()` 在调用栈内走完 `Ended` → 流程 finally（上下文被拆空），`OnUpdate` 顶门检过后本帧仍可能被拆空，余下驱动面前必须复检空引用。

## 7. 对局编排与视图装配

### 7.1 `ProcedureBattle` 全序

全序：① 建 `BattleViewRig` → `LoadAsync` 八段取件（资源先备、会话后建）；② `MatchSessionFactory.Create` → `BattleContext` → `RoomBridge.BindSession`（页面经 `Bridge.room` 读房主事实，收尾必摘）；③ 双信号竞速等开局：`StartGame` 与 `MatchEnded` 先到先得（等待期被中止不悬挂，胜者败者一并退订）；④ 散场/开局/拒局三分支（`ConfigHash` 不符按会话失败收尾，不变成错误态）；⑤ `WaitEnded` 单源单事件等待并冻结 `MatchEnded`；⑥ finally：摘会话门面 → 摘对局菜单 Back → 清输入派发 → `rig.Dispose` → Match 服务域 → Account 作用域 → 卸场景组；⑦ 页面流在 finally 之后（正常结束进结算页，失败/离场回大厅）。

开局分支四个设计点：① 对局场景组在 StartGame 之后、本阶段内叠加加载（避免"未开局即付费"与跨阶段所有权分叉），全程"正在进入对局…"加载遮罩，视图建成才收；② 场景行键取 JoinAck 权威事实（`RoomClient.MapId`，0 = 服务器未标注 → 首图口径）再查地图表 `scene` 列，缺表即 fail-fast；③ 相机硬门在场景就位之后（vcam 随 Rig 场景走）；④ 先收 System 加载面、再关 Bottom 房间页——反序会让房间页卡在被加载面挡住的模态队列里，整局留着全屏阻断。

离场卸载只跳过宿主关闭，判据取**根令牌**而非本阶段令牌：主动离场也会取消本阶段令牌，但那不是关闭，场景必须照卸，否则残留在大厅画面里（换图重进还会累积）。卸载按地图表枚举全部地图场景 + Rig，幂等，失败只记日志、不阻塞离场。

### 7.2 视图装配与降级边界

表现侧由 `Assets/LiteGame/App/Presentation/Battle/BattleViewRig.cs` 收拢（五个协作件）。四段合同：`LoadAsync` 八段取件（角色 prefab → 激光束 → HUD → 保护壳 → 飘字底件 → 逐档材质 → 片段清单 → 音效，逐项独立降级）；`Attach` 按依赖序接线（视图装配 → 命中分发器 → HUD 族 → 激光 → 保护壳 → 阵亡面板 → 视角/指针 → 反馈消费者 → 输入接线）；`Tick`/`TickPreSample` 按相位驱动（判定之后表现、诊断件在采样前落位）；`Dispose` 按相位逆序（动画 → 排行榜/击杀/远端火光/网络件 → HUD 面板 → 阵亡 → 准心 → 激光 → 保护壳 → HUD 根件 → 伤害数字），消费者先于生产者、视图先于上下文。
降级边界是设计出来的：缺角色 prefab → 无角色视图（工厂拒绝 = 无实体可见，不造占位替身）；缺 HUD/激光/飘字/音效 → 该项静默降级；相机这类结构前提缺失 → 显性失败（`requireCamera: true`）。"跑得动但看不见"不是可接受态。

## 8. 相机、表现与输入

**相机**由 `ICameraService`（Cinemachine 适配器）承担：装配根创建、跨场景常驻、跨对局复用，服务对象恒非 null，"此刻有没有接上 vcam"由 `requireCamera` 在开打前判定。构图/档位/阻尼/FOV 全归 vcam 场景配置，每局只做 `Reset`。端口语义：`Follow` 写位姿，`AddLookDelta` 收视角增量，`SetAiming` 收瞄准语义态，`SetAimPoint` 收瞄准点。基础灵敏度是机制常量单源 `0.0025` 弧度/像素，ADS 档按 `AdsLookSensitivityScale = 0.6` 收敛；瞄准态走 `AimHoldGate`：上升沿立即生效，下降沿按最小保持 0.3s 分治。AimPoint 单一口径：设备源把准心射线与**预测世界**求交解出目标点，朝向与弹道自该点派生；设备源不缓存权威状态，本地实体未对齐时按无效槽位注入。

**表现域**（`Assets/LiteGame/App/Presentation/`，程序集 `LiteGame.Presentation`，Hud/Fx/Battle/Audio 四组；与 `Assets/LiteView`）守四条规则：① 只读判定——只消费预测态与公共快照，禁回写 Sim，这是"回滚不闪、和解不抖"的结构前提；② 事件消费制——`SimView` 静默门放行帧事件 → `HitFeedbackDispatcher` 并列订阅 → 消费者各自过滤；③ 服务不互调——动画不认识 VFX、VFX 不认识音频，跨域由流程/编排件接线；④ 预算与句柄制——VFX 同屏预算（`VfxBudget.Default()` = 64，超限 `RecycleOldest`/`Reject` 二选一）、挂点隔离停止，音频句柄 + 优先级抢占 + 分组并按分域时钟（对局暂停/离场即停）。关键驱动件：`CharacterLocomotionDriver`（动画状态决策收进单机双根状态机）、`BattleCrosshairDriver`（Hip/ADS 双形态，被模态拦截时藏准心还系统光标）、`BattleLaserDriver`（端点 = 逻辑枪口 → 瞄准点经 `SimRaycast` 截停，与子弹同终点）。

**输入三件**：设备源 `IIntentSource` 把键鼠/触屏同面输出为意图（Move/Aim/Fire），Action 资产是进程级资源、驻留装配根；拦截裁决 `IntentGate` 用具名拦截源统一决策并报出"是谁拦的"，生产装配登记 `ui.modal`（模态 UI 开 = 拦游戏意图）；协调者 `InputService` 渲染帧只采样、逻辑帧经 `TryTakeForPrediction` 唯一消费、同一份输入经 `TryTakeForSend` 上行。对局内由 `BattleInputPipeline` 收拢：输入帧数组按房间规模定容复用（零分配），先于本地服步进消费——预测、上行、本地服三处吃同一份输入。

## 9. 本地联测与开发面

本地测试模式 = 进程内本地服：`Assets/LiteGame/Dev/LocalServer/LocalServerTransport.cs` 持**真 `RoomRuntime`** 与真快照管线（不复制票据/多房间/排空这些带 IO 的 Application 半边），单连接、热路径零分配。本地真服与云端测试房走真 KCP，传输决策点在流程的传输工厂。

调试能力的边界是**编译期的**：`UNITY_EDITOR || DEVELOPMENT_BUILD || LITEFRAMEWORK_DEBUG`（开发三宏）之内才有 GM 命令、调试内核、弱网预设、自瞄验证件——release 里这些类型整体不存在（条件编译剔除），不是"藏在 release 里关掉"。

- **一张开关表**：`Assets/LiteGame/Dev/Debug/TestModeOptions.cs` 是面板渲染、运行时快照、`DevStartupConfig` 初值三处的同源表，现有 9 个开关（NoDeath / InfiniteAmmo / LaserSight / DamageNumbers / AutoHeadshot / DrawHeadshotDebug / TeleportEnabled / BotFrozen / BotInfiniteHp），分 Startup 与 Live 两组。
- **一条命令链**：玩家操作与 GM 动作都走 `CommandCenter`（权限门 → 拦截器 → 审计环 32 条）；GM 命令注册点在装配期，dev 构建恒可发现，不依赖场景里是否挂了 `DevStartupConfig`；测试热键（T = 传送到准心）入队命令。
- **一个调试内核**：`DebugKernel` 是调试面唯一门面，编辑器页/HUD/控制台三个只读投影只消费它；`IModuleStats` 由容器自动发现，对局诊断读口随对局挂接、离场注销；`-memloop` 与 `-inputmodal` 两类探针靠命令行参数门控，未带参数时一次查找后零开销。

> **待核**：相机 FOV 档位与地图表 `scene` 列取值属场景/表数据，不在代码内，以资产与表为准。
