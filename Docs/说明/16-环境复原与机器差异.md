# 16 环境复原与机器差异

> **定位**：干净克隆或换机后，把工程恢复到"能编译、能跑 L1/L3、能进 Unity"要做什么；以及哪些差异是设计如此、哪些是真缺陷。
> **权威边界**：不裁决目标架构（归 [设计文档](../设计文档/README.md)）、不记批次（归 [施工进度](../施工进度/README.md)）；入库范围的裁决在 [规范 08](../规范/08-资源入库与第三方引用.md)。
> **来源**：合并自《环境恢复指南》与《非作者机恢复与验证记录》，重复的入库/缺件表只留一份（以脚本实测为准）；验证数字取最近一次非作者机实测（旧目录已删，映射见 [说明索引](README.md)）。
> **关联**：[10-测试与门禁](10-测试与门禁.md)、[11-构建与本地联测](11-构建与本地联测.md)、[15-工具链手册](15-工具链手册.md)、[客户端质量登记](../审计/代码质量审计-客户端.md)、[施工进度·资源与工具链线](../施工进度/资源与工具链线.md)。

## 1. 一条命令复原

```powershell
git clone <repo>
cd <repo>
python scripts/gate/restore-check.py
```

退出码 **0** = 环境就绪（可直接用 Unity 打开，包解析完后跑 `scripts/gate/l2-unity-gate.py`）；**1** = 有 blocking 缺件，按 `[MISS]` 清单逐项补齐后重跑，**不允许带缺件继续**。输出分三档：`[OK]` 通过、`[WARN]` 不阻塞、`[MISS]` 阻塞。

### 1.1 校验面（`scripts/gate/restore-check.py`）

| 检查 | 判据 | 级别 |
|---|---|---|
| Unity 版本身份 | `toolchain.json` 的 `unity.version`/`unity.revision` 对上 `ProjectVersion.txt` 的 `m_EditorVersion`/`m_EditorVersionWithRevision` | MISS |
| 工程设置完整 | `ProjectSettings/ProjectSettings.asset` 在位 | MISS |
| 依赖可复现 | `Packages/manifest.json` 无个人绝对路径（`file:[A-Za-z]:`）、无浮动 git 依赖 | MISS |
| lock 文件 | `packages-lock.json` 在位 | WARN |
| vendored 包 | `Packages/com.tuyoogame.yooasset`、`Packages/com.code-philosophy.luban` | MISS |
| .NET | `dotnet --version` 为 8.x | 缺失 MISS；9.x WARN |
| Python | ≥3.10 且装 `openpyxl`、`cryptography` | MISS |
| git | `git` 在 PATH | MISS |
| Odin Inspector | `Assets/Plugins/Sirenix/**/Sirenix.OdinInspector.Attributes.dll` | MISS |
| DOTween / UniTask / xLua | `Assets/Plugins/Demigiant/DOTween`、`Assets/Plugins/UniTask`、`Assets/Plugins/xlua.bundle` | MISS |
| 入库视觉资源 | `Assets/ShareResource/Fonts/NotoSansSC-Regular SDF.asset`、`Assets/Settings/URP-Balanced.asset` | MISS |
| 场景 | `Boot.unity` 或 `TrainingGround.unity` 任一在位 | WARN |
| JDK | `java` 在 PATH（Android IL2CPP 前置） | WARN |
| 注册面 | 跑 `python scripts/toolchain.py check` | WARN |

版本以 `scripts/gate/toolchain.json` 为准：Unity `2022.3.55f1c1`、revision `06b99830297d`、`edition: Unity China`、`source: unity.cn/download`。**revision 也校验**——同版本号的另一支构建（社区版）会被拦下，因为序列化行为可能不同（§5.1）。

### 1.2 典型输出

```text
[env/restore] Restore check | project: <repo>
  [OK]   Unity 2022.3.55f1c1 (matches toolchain.json)
  [OK]   Unity revision 06b99830297d (matches toolchain.json)
  [OK]   manifest.json reproducible (56 deps, zero personal paths)
  [WARN] .NET SDK 9.0.308 (L1/L3 target net8.0; prefer 8.x)
[env/restore] Restore check PASSED: workspace can open / run L1,L3 / proceed to build
```

有 `[MISS]` 时会逐条打印并在末尾给出 `Restore check FAILED: N blocking item(s)`。

## 4. 非作者机的必然缺件

### 4.1 未解析 GUID 的机制与度量

序列化资产按 GUID 互相引用；实体缺失时引用悬空——**这是"不入库"策略的必然结果，不是仓库损坏**。度量用：

```powershell
python scripts/content/scan-missing-guids.py
# => [quality/scan-missing-guids] assets with a guid: 25392
#    [quality/scan-missing-guids] UNRESOLVED GUID references: 187
```

脚本把 `Assets/`、`Packages/`、`Library/PackageCache/` 下所有 `.meta` 视为"存在"，再从 `Assets/` 的序列化资产与整个 `ProjectSettings/` 收集引用。本机全量 187 条里绝大多数是三方 demo 面（Synty HUD、DamageNumbersPro、MagicaCloth 示例）引用了未入库素材；**自有 prefab/scene 的缺口另算**，见 §4.2。

### 4.2 占位策略

非作者机首次排查时，对自有 prefab/scene 缺的那批做过程序生成占位：预置**原 GUID**、落在 `Assets/Art/_Placeholder/`（`.gitignore` 覆盖，不入库），已入库的 prefab/scene 零改动即自动接回。规模：Sprite 13（九宫格/面板/按钮/图标/暗角）、Material 9（FX 粒子）、Mesh 4（含 `4300002`/`4300010` 子 fileID）、Prefab 3（`TrainingGround` 的 `Dome`/`Figure_Base_EditNormal`/`Grid_Plane`）。

**有意不占位**的：6 个 KriptoFX 运行时脚本（属代码不属美术，stub 会静默丢序列化数据并往程序集塞死类）、1 个字体源 TTF（两个 SDF 的 `m_SourceFontFileGUID` 都指向它；处于 Dynamic 档时运行时无法新增字形，但已烘 7189 字形仍可渲染）。另有 1 条不是缺素材、而是工程设置写错（见 §6 第 1 条）。

占位件**没有生成脚本**：那次是一次性程序，仓库里不复现。换机要么整目录拷贝，要么按同一 GUID 重建。

### 4.3 缺件的表现

| 缺件 | 表现 |
|---|---|
| UI/特效/模型/音效/地图 | UI 空白、特效不播、场景缺件但能进 |
| 角色包 | 对局实体回灰盒；`CharacterAsset`/`CharacterLocomotion` 用例跳过（既有分流逻辑，非回归） |
| 字体 | TMP 中文缺字；即使字体资产入库，fallback 没挂也一样缺（§6 第 2 条） |
| `Player(Rifle).prefab` | 烘焙工具箱 ABORT（有前置断言） |
| URP 资产 | 渲染退化到 Built-in 兜底，画面不可信 |

## 5. 机器差异（不是缺陷）

### 5.1 编辑器是 Unity 中国版构建

`Editor.log` 自述 `Built from '2022.3/china_unity/release' branch`，版本仍是 `2022.3.55f1c1 (06b99830297d)`。同版本号的社区版构建在序列化行为上可能有差别；历史观察到 `ProjectSettings/GraphicsSettings.asset` 被编辑器重写为 `serializedVersion: 15`、增删 Unity 6 字段（`m_BrgStripping`、`m_LightProbeOutsideHullStrategy`、`m_CameraRelativeLightCulling`）、并改写 `m_SRPDefaultSettings` 的 URP GUID。

这类 diff 是编辑器产物、不是业务改动：提交前先看 `git status ProjectSettings`，只提交有意的配置变更；误入的用 `git checkout -- ProjectSettings` 还原后重开确认。（当前仓库里该文件是 `serializedVersion: 14`、工作区干净——是否重写随编辑器与导入状态而变，别把"没复现"当"不会发生"。）

### 5.2 出包模块与真机前置

两份 BuildProfile 都写 `backend: IL2CPP`（`windows-x64.json`、`android-il2cpp.json`），所以**模块不是仓库状态**：`PlaybackEngines/` 要有目标平台（Windows 的 IL2CPP 变体在 `windowsstandalonesupport/Variations/`，Android 需 `AndroidPlayer` + JDK 11 + SDK/NDK）。本机实测两类模块都在；缺 JDK 时 `restore-check` 只发 WARN，不阻塞 Windows 开发。换机后先自查模块，再判断"构建失败"是不是仓库问题。

### 5.3 客户端注入面

联机入口的四项配置走三源装载：**命令行参数 > 包内烙入 `StreamingAssets/deploy.args` > 字段默认**，PSK 为空时再回落环境变量 `LITENET_SECURE_ENVELOPE_KEY`。

- 键名：`-meta.url`、`-meta.timeout`、`-envelope.key`、`-device.id`、`-room.template`、`-room.gmkey`（两种写法等价：`-key=value` 或 `-key value`）。
- 本地测试路径用常量：`ProcedureMatch.TestHost = 127.0.0.1`、`TestPort = 17777`。
- `GmUrl` 未显式给时由 `MetaUrl` 推同 host + `9101`；`GmKey`/测试房口令只在本机配、不入库。
- 干净克隆**没有** `deploy.args` 属正常：未配置时联机入口显性拒绝（fail-closed），不悄悄回退本地。

### 5.4 门禁的本机噪声

- `.NET SDK 9.x` 只告警：测试目标 `net8.0`，8.x 才是基线。
- `toolchain.py check` 的告警分两类：注册面漂移（未登记脚本/文档缺失）与索引过期；`restore-check` 把它降为 WARN，不阻塞复原。
- Console 里的历史 error 计数不等于编译失败：以 `console_status` 的 `groundTruth.compilationFailed` 为准。

## 7. 验证基线（非作者机实测）

### 7.1 编译

```powershell
Unity.exe -batchmode -nographics -quit -projectPath <repo> -logFile Temp/compile.log
# 判据：error CS 0；5 个 Unity.Pipeline* 程序集全部产出
```

"编译 0 错误"**不等于**资源被正确加载：插件 meta 解析失败只在 Console 冒 error，不进 `error CS`。判 meta 是否合法看 `Parser Failure` 与 `GetCompatibleWithEditor`，不要只看编译结果。

### 7.2 EditMode

| 项 | 数值 |
|---|---|
| 总数 | 416 |
| 通过 | 364 |
| 失败 | 17 |
| 跳过 | 35 |

失败归因：缺字体 10（`UiFontFamily`×3、`LTextTypewriter`×6、`BattleHud`×1）、缺美术/角色包 1（`BodyBake`）、已入库 prefab 缺节点 2（`SafeArea` 读 `UIMain.prefab`、`UiU0`）、**未定因 3**（`BattleLaser` 端点数值偏差 `-0.8057`）。35 个跳过集中在 `CharacterAsset`/`CharacterLocomotion`，是缺角色包时的分流逻辑，不是回归。

### 7.3 占位没有引入回归（A/B 实测）

把 `Assets/Art/_Placeholder` 整个移开 → 重导入 → 重跑 → 移回 → 重跑，逐条比对失败集合：

```text
WITHOUT placeholders: 416 / 364 passed / 17 failed / 35 skipped
WITH    placeholders: 416 / 364 passed / 17 failed / 35 skipped
失败集合 diff: IDENTICAL（逐条一致）
```

### 7.4 复现步骤

```powershell
python scripts/gate/restore-check.py         # 基线自检
python scripts/content/scan-missing-guids.py # 看缺哪些引用
Unity.exe -batchmode -nographics -quit -projectPath <repo> -logFile Temp/compile.log
python scripts/gate/test.py --suite L1 --profile PullRequest
```

### 7.5 未跑的部分

**PlayMode 未跑**：它要进 Play 模式，画面/文本状态受缺件影响，结论不可信。资源侧已无阻塞，缺的是复跑动作。
