## 1. 五层验证

| 层 | 回答的问题 | 入口 | 平台 | CI |
|---|---|---|---|---|
| **L0** 静态门禁 | 依赖可复现吗？有没有个人路径、浮动 git 依赖、密钥？工具注册面漂移吗？ | `python scripts/gate/l0-dep-scan.py` | 任意（不需 Unity/.NET） | 仅 windows step 跑一次 |
| **L1** 纯逻辑 | 判定、协议、房间内核、框架语义对不对？ | `python scripts/gate/test.py --suite L1 --profile PullRequest` | win + ubuntu | 已接入（job 触发条件见 §7） |
| **L2** Unity | 工程编得过吗？EditMode/PlayMode 真跑了吗？`.meta` 合法吗？ | `python scripts/gate/l2-unity-gate.py`（= `test.py --suite L2`） | 仅 Windows，需编辑器或 batchmode | 条件式（自托管 + `L2_ENABLED`） |
| **L3** 集成/端到端 | 真 IO、真网络、真进程内服务端跑得通吗？ | `python scripts/gate/test.py --suite L3 --profile PullRequest` | win + ubuntu | 已接入 |
| **L4** 真机/性能 | 目标设备帧率、内存、生命周期达标吗？ | **无脚本、无套件** | 真机 | 无 |

`--suite` 合法值只有 `L1 / L2 / L3 / All / Doc`：L0 是独立脚本，L4 未纳入脚本；`All` 顺序跑 L1 → L3 → L2，因此也要求 Windows。每层都对着一种历史假绿：旧程序集（L2 新鲜度）、测试没编进来（`Total<=0`）、构建没产物（产物与新鲜度校验）、基线被随手改（CI 防篡改）。

### 1.1 L0 查什么

`l0-dep-scan.py` 六项，任一命中 exit 1：`Packages/manifest.json` 与 `packages-lock.json` 无个人绝对路径（`file:[A-Za-z]:`）；git 依赖固定 commit（`.git#<40-hex>`）；已入库 vendored 包（`Packages/*/package.json`）必须带 LICENSE；git 跟踪文本文件无密钥特征（私钥头、AWS key、GitHub token、硬编码凭据；扫描器自身与两个测试文件已登记豁免）；`python scripts/toolchain.py check` 通过；GM HTTP 契约在三处一致（服务端路由、编辑器 GM 页、CLI）。git 不可用时密钥扫描降级为 warning。

## 2. 统一入口 `scripts/gate/test.py`

### 2.1 执行契约

- **工程发现**只认 `Tests/**/*.Tests.csproj`；`Tests/` 下出现其它命名的 csproj 直接抛错（否则新工程会被静默跳过）。当前 6 个：`LiteTesting.Core.Tests`、`LiteFramework.Core.Tests`、`LiteSim.Core.Tests`、`LiteNet.Tests`、`MetaServer.Tests`、`MetaServer.Integration.Tests`（真 Mongo）。
- **顺序**：逐工程 `dotnet restore --disable-parallel --ignore-failed-sources -m:1 -p:BuildInParallel=false -p:NuGetAudit=false` → `dotnet build Tests/Tests.slnx -c Release --no-restore -m:1` → 逐工程 `dotnet test --no-build --no-restore --blame-hang-timeout <5m|12m> --filter …`。
- **环境**：导出 `LITETEST_RUN_ID`（`<profile>-<UTC 时间戳>`）、`LITETEST_ARTIFACTS`（`TestResults/artifacts`）、`DOTNET_PROCESSOR_COUNT=4`、`DOTNET_CLI_HOME=.dotnet-cli`，结束后还原。

### 2.2 过滤与档位

| 套件 | 默认过滤 | 档位差异 |
|---|---|---|
| L1 | `Category!=Integration&Category!=EndToEnd&Category!=Performance&Category!=Quarantine&Duration!=LongRunning` | 两个档位同过滤；挂死超时 5m |
| L3 | `(Category=Integration\|Category=EndToEnd)&Category!=Quarantine` | PR 档再加 `Duration!=LongRunning`、超时 5m；非 PR 档置 `M10_LONGRUN=1`、超时 12m |

`--filter <expr>` 覆盖该套件的默认分类表达式，但外层恒加 `Category!=Quarantine`。

### 2.3 判红

任一工程失败仍跑完其余工程再汇总；**`Total<=0` 判红**（防测试程序集没编进来）；`dotnet` 不在 PATH 直接失败并落摘要。失败也会写 `status=fail` 的摘要，不靠退出码推断。

### 2.4 产物与机器可读摘要

每个工程一份 TRX（`TestResults/<suite>-<工程>-<runId>.trx`）加一份 `summary-<suite>.json`。摘要 schema 版本为 **2**，字段：`schemaVersion / suite / profile / status(pass|fail) / runId / total / passed / failed / skipped / artifacts[]`，失败附 `error`，Nightly 另有 `suites[]`（v1 的 `lane/lanes` 已更名）。单一写者：`test.py` 写 L1/L3/Doc，`l2-unity-gate.py` 写 L2，`nightly-gate.py` 写 Nightly；CI、夜间日志、人读输出消费同一份，不再各自解析控制台。

## 3. L2 Unity 门禁

### 3.1 路径判定

`Library/Pipeline/.unity-pipeline-port` 存在且未传 `--run-editmode-tests` → **路径 A**（编辑器在跑，经 Unity Pipeline，不用关编辑器）；否则解析 Unity 可执行文件（`--unity-exe` > `UNITY_EXE` > LocalNotes > Hub 探测）走 **路径 B**（batchmode）。另有 `--meta-scan-only` 只跑 meta 扫描。

### 3.2 路径 A 步骤

1. `set_autotick --enable true`，保证后台编译/测试期间编辑器继续 tick。
2. **新鲜度守卫**：写 `Temp/l2-freshness-request.cs`（`AssetDatabase.Refresh(ForceSynchronousImport)` + `CompilationPipeline.RequestScriptCompilation()`）→ `eval_file` 执行 → 轮询 `Temp/l2-freshness-status.cs` 的 `isCompiling`，上限 90s（3s 间隔）。外部改 `.cs` 后 Unity 不会自动导入，`recompile_status` 会误报 `up_to_date`，用例跑的是旧程序集——这是最隐蔽的假绿。mtime 比较（`Assets/**/*.cs` 对 `Library/ScriptAssemblies/*.dll`）只作第二道辅助判据。
3. `recompile_status`：`compilationFailed`/`failed` 为 true 判红；`console` 只对 `error CS####` 判红，其它 error 级条目计数并提示。
4. `run_tests --mode editor|playmode --async_tests true`，每 5s 轮询 `test_status`（单模式 900s 上限）；两模式各自判红，`Total<=0` 判红。

### 3.3 路径 B

先用 `tasklist` 确认没有 `Unity.exe` 占用同一工程（占用即判红），再 `unity test <工程> -e <UnityExe> --mode EditMode|PlayMode --output TestResults/{editmode,playmode}-results.xml --timeout 1800`；两段独立判定，不因前一段失败短路。

### 3.4 meta GUID 扫描（两路径共有）

扫 `Assets` + `Packages` 全部 `.meta` 前 8 行内的 `guid:`，必须是 32 位 hex。历史事故：非法 GUID 的 `.meta` 被 Unity 拒收 → 资源与类型静默消失，而 L1 全绿。L2 摘要写 `summary-l2.json`（`profile` 为空串，`total/passed/failed` 汇总两模式，artifacts 为两份 xml）。

## 4. 纪律扫描（`Assets/Tools/DisciplineScanner`）

### 4.1 规则 R1–R14

| 规则 | 拦什么 | 为什么 |
|---|---|---|
| R1 | 超越函数（Sin/Cos/Tan/Atan2/Exp/Log/Pow） | 跨平台 libm 结果可能不同，判定层走 `SimTrig` |
| R2 | 显式 FMA | 融合乘加在不同 CPU/编译器下结果可能不同 |
| R3 | float `==`/`!=`（0/null/default 字面量豁免） | 浮点等值比较不可靠 |
| R4 | LINQ 与不稳定遍历（判定层） | 顺序不确定即结果不确定 |
| R5 | 裸 `UNITY_EDITOR` | 应走开发三宏或适配器，避免 release 残留 |
| R6 | 原生协程（`IEnumerator`/`StartCoroutine`/`yield return`） | 统一 UniTask，生命周期可控 |
| R7 | 非法 `.meta` GUID（仓库级） | 资源静默消失 |
| R8 | `Resources.Load/LoadAsync` | 资源必须走内容服务/租约 |
| R9 | Mod 类型进入 Sim | 判定面不得被模组污染 |
| R10 | UI 服务装配直接发业务包 | UI 不认识网络业务 |
| R11 | 运行时纯化：Console／`DateTime.Now`／`Stopwatch`／`Thread.Sleep`／`System.Net`/`Socket`／`Kcp*`／文件 IO／proto 与 LiteNet 引用／`new Random()`（`Assets/RoomServer/Core` 全根；`Server/MetaServer` 除 `Host/`） | 房间内核必须可确定性测试，宿主层才合法用 IO |
| R12 | 适配器边界：`YooAsset`／`XLua`／`UnityEngine.InputSystem`／`Cinemachine`／`DG.Tweening` 只在各自登记边界目录 import；框架侧 `LiteFramework.*` 禁反向引 `LiteGame.*` | 防止第三方 API 与产品依赖泄漏进框架 |
| R13 | 机制面禁读静态数值读口：`CombatConfig` 装载面 + `AimMoveSpeed` + `Loaded/Publish`、`MovementConfig` 全类、`WeaponConfig` 的 `Default/TryGet/Loaded/Publish`；常量面豁免 | 值必须经 `CombatValues`/`MovementValues`/`WeaponTable` 实例传递 |
| R14 | 投影禁直调调试源：`Assets/LiteGame/Dev/Projection` 与 `Assets/LiteGame/Editor/Gm` 只经 `DebugKernel` 门面读数/写动作/发现 | 豁免＝契约类型、纯格式化助手、`Log` 门面；例外行 `lint-allow R14` 须写理由 |

### 4.2 作用域与豁免

规则一处分发、多根适用：`ScanTargets.Default` 22 个目标，每个只启用相关子集（`LiteSim` 扫 R1–R5+R9，`LiteNet` 与 `LiteFramework/Runtime/Core` 只扫 R5，`Assets/LiteGame` 扫 R8+R12，`RoomServer/Core` 扫 R11+R13，`Server/MetaServer` 除 `Host/` 扫 R11，两个投影根扫 R14）。豁免三层：路径级（`/Editor/`、`/Vendor/`、规则表自身）、目标级（`ExcludeRoots`、读口定义文件）、行级（`lint-allow`，可只豁免某条规则）。违规即 **L1 红**，由 `DisciplineScannerTests` 的"真实源码_全部目标_零违规"与各规则正负例执行，不是建议。

### 4.3 结构守卫（同为 L1 红）

七类：`Assets/LiteGame` 顶层目录白名单（`App/Editor/Dev/Lua/LuaBridge`）；注释卫生（禁日期戳与批次号）；共享档位成员 asmdef 零引擎（`SharedAssemblyDefs` 三条 S1 件）；S2 契约层零第三方实现依赖（登记表当前为空，S2 义务实际由 `ClientAsmdefAllowlistTests` 的目录级用例守）；`Assets/` 下禁 `bin`/`obj`（须用 `Directory.Build.props` 重定向 `.dotnet/`）；依赖方向（D1 服务端宿主不引客户端面；D2 客户端引服务端程序集只许 `Assets/LiteGame/Dev`，且登记目录必须真实存在）；框架侧 asmdef 禁引 `LiteGame`。

### 4.4 视觉单一来源（独立扫描器）

`Assets/LiteGame/Editor/Core/VisualConstructionScanner.cs` 与 R1–R14 独立：用户可见视觉必须来自 `Assets/ShareResource/UI/Screens` 与 `Widgets` 模板；命中 `typeof(T)` 参数或 `AddComponent<T>`/`GetOrAddComponent<T>` 即违规，类型表 `VisualComponentTypes` 共 **23** 个视觉/交互类型名。例外按**文件名**登记（非路径，目录迁移不失效）：`ProcedureError.cs`（引导期错误界面）、`UiInput.cs`（输入底座）；层容器骨架 `[UIRoot]` 与各层节点按"是否构造视觉组件"判定，不按 `new GameObject` 判定。`ScanSource(text)` 是纯函数便于喂合成负例，`ScanDirectory` 跳过含 `/Editor/` 的目录与自身文件；正/负例由 EditMode 用例 `VisualSingleSourceEditModeTests` 执行，并被 `ui.validate` 工具复用。

## 5. 测试基础设施

| 位置 | 内容 |
|---|---|
| `Assets/LiteTesting/Core` | 与 Unity 无关：`TestTrait`/`TestCategory`/`TestDuration`/`TestPriority`、`TestScope`、`Eventually`、`DeterministicRandom`、`TestRunSettings`；**双轨**（同一份源码进 `LiteTesting.Core.csproj`，dotnet 测试可直接用） |
| `Assets/LiteTesting/Runtime` | PlayMode 用：`PlayModeTicker`、`PlayModeTestScope`（不引 `UnityEditor`） |
| `Assets/LiteTesting/Editor` | EditMode 用：`UnityTestBase`、`UnityTestScope`（对象与 AssetDatabase 的所有权/回收） |

- **标签单源**：`Category`/`Duration`/`Priority`/`Owner` 四个键，NUnit 与 dotnet filter 共用同一批字符串。`Category` 取 `Unit`/`Contract`/`Integration`/`Asset`/`Smoke`/`EndToEnd`/`Performance`/`Quarantine`；`Duration` 取 `Fast`/`Medium`/`LongRunning`；`Priority` 取 `P0`–`P3`。
- **`Eventually`**：有界轮询，`timeout`/`pollInterval` 必填且 >0，超时抛 `TimeoutException` 并附 `Last state`。
- **`DeterministicRandom`**：SplitMix64 定序，种子来自环境变量 `LITETEST_SEED`（缺省固定值）按测试 ID 做 FNV-1a 派生。
- **逐位基线**：`Tests/LiteSim.Core.Tests/Baselines/IeeeBaseline.txt` 与 `SimChecksum.txt`，靠跨平台 L1 矩阵比对（基线改动受 §7.3 防篡改约束）。

**Quarantine 现状**：制度要求"必须关联缺陷、责任团队、≤7 天到期，禁用重试掩盖不稳定"，代码侧只有常量与各套件过滤（默认排除），没有到期日/缺陷关联的机械校验；当前登记 0 个 Quarantine 用例。

## 6. 文档与工具清单门禁

### 6.1 Doc 套件

`python scripts/gate/test.py --suite Doc` 不碰 dotnet：先 `scripts/gate/doc-lint.py --root <repo>`，再 `python scripts/toolchain.py docs --check`，写 `summary-doc.json`。doc-lint 规则：D1/D6 设计文档内嵌施工状态（提醒）、D2 审计文件裸"待提交"（违规）、D3 索引覆盖（设计文档与施工进度全部入索引）、D4 相对链接与 `#锚` 失效、D5 不可治理文件名后缀、D7 `Docs/` 根目录白名单、D8 审计归档单文件 ≤100 条、D9 `说明/` 与 `规范/` 章号两位数且连续无跳号。

### 6.2 工具清单（`scripts/gate/toolchain.json`，schema v6）

唯一清单：**71 个工具、9 个 category、5 个 surface**（`ci` 工作流、`nightly-task` 计划任务、`zcode-hook`、`claude-hook`、`unity-pipeline` 路径）。每个工具声明 `kind`（action/cli/gate/page/docs/content/window/build/hud/…）、`plane`（external/editor/runtime/none）、`purpose`（dev/delivery/debug）、`requires`（play/player/unity-batch）与 `destructive`。四个消费面：编辑器 Hub（唯一菜单 `LiteGame/工具链`，按 `kind` 选适配器）、CLI（`scripts/toolchain.py` 的 list/check/docs/open/run/generate/verify/build/doctor）、生成索引 `Docs/说明/工具索引.md`（`docs --check` 逐字节比对）、外部注册面（CI/hook/计划任务引用的脚本是否存在）。

`check` 校验清单结构与路径、surface 引用、索引新鲜度、**孤儿可执行脚本**（无 `main` 且未豁免）、编码与行尾（`.ps1` 一律报"P5 后不允许新增"、`.py` 禁 BOM、脚本全禁 CRLF）、域形态三规则（同义参数同名 / 文档权威唯一 / 一域一个输出前缀）。后三类默认 warning，`--strict` 升 error。`doctor` = `check` + `restore-check` + Pipeline 端口状态。

## 7. CI 与本机夜间

### 7.1 触发现状

`.github/workflows/ci.yml` 当前只开 `workflow_dispatch`（手动）：`push` / `pull_request` / `schedule` 三段已注释保留，恢复时原样加回。因此下面的 job 触发矩阵以文件里的 `if` 为准，不要按历史文档假设"提交即跑"。

### 7.2 四个 job

| Job | 触发条件 | 超时 | 做什么 |
|---|---|---|---|
| `l1-dotnet-test` | `if: push \|\| pull_request` → **纯手动 dispatch 不执行** | 20 min | win+ubuntu 矩阵：基线防篡改（仅 ubuntu）+ L0（仅 windows）+ L1 |
| `l3-network-test` | 同上 → 纯手动 dispatch 不执行 | 25 min | 同矩阵跑 L3 |
| `l2-unity-gate` | `vars.L2_ENABLED == 'true'` 且 dispatch/schedule | 60 min | 自托管 Windows：L2 + `build-player.py --skip-restore-check` + `player-smoke.py --timeout-sec 30` |
| `nightly-longrun` | dispatch/schedule | 45 min | `test.py --suite L1/L3 --profile Nightly`（含 `M10_LONGRUN` 长跑） |

### 7.3 基线防篡改

只在 ubuntu 跑一次：`git diff BASE..HEAD -- 'Tests/**/Baselines/**'` 有变更时，必须在 PR 标题/正文或提交信息里带 `[baseline]`，否则失败；BASE 依次取 PR 基分支、push 前 SHA、`HEAD~1`，都取不到则跳过（浅历史可绕过）。

### 7.4 本机夜间任务

计划任务 `LiteGame-Nightly-Gate`（由 `scripts/gate/install-nightly-task.py` 重注册，`--dry-run` 干跑，`--what-if` 为兼容别名）跑 `scripts/gate/nightly-gate.py`：L1（Nightly 档）→ L2 → L3 只跑 `FullyQualifiedName~WeakNet` 子集；日志落 `TestResults/nightly/L2-<stamp>.log` 与 `L3-<stamp>.log`，摘要写 `summary-nightly.json`（`suites[]` 逐段记 status/exitCode），末尾单列"PlayMode 本次是否执行"。`--skip-l1`/`--skip-l3` 可裁段。它与 CI 的 `l2-unity-gate` 目的重叠，二选一。

## 8. 出包链里的门禁位

`build-player.py` 把门禁串进出包链：`restore-check.py` → `l0-dep-scan.py` → `gen-build-hash.py --check-shared`（不可跳过）→ … → 产物与新鲜度校验；`player-smoke.py` 只认 `BootstrapError` 与 `[Asset] ready` 两个定义态标记。链条细节与本地三端操作见 [说明 11](11-构建与本地联测.md)。

## 9. 现状缺口

1. **L4 完全缺失**：无套件、无脚本、无设备/性能基线，真机与内存证据只能手工。
2. **L2 只能在自托管 Windows 跑**：需完整工程与中国版编辑器授权，GitHub-hosted 不可用。
3. **L2 有"绿而未跑"分支**：路径 A 找不到 `unity` CLI 时只记 note 后 return，最终仍判 pass，且不经过 `Total<=0`；需人工确认输出。
4. **Doc 套件未进 CI**：四个 job 都不跑 Doc，文档索引/链接/章号只在本地或手动跑。
5. **Quarantine 未机械化**：无到期日与缺陷关联校验，容易退化成永久豁免。
6. **手动 dispatch 跑不到 L1/L3**：两个 job 的 `if` 只认 push/PR，因此 CI 当前实际只剩 L2 与夜间长跑可手动执行。
