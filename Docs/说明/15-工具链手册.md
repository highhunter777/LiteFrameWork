## 1. 统一入口

**唯一注册源**是 `scripts/gate/toolchain.json`（schemaVersion 6，updatedAt 2026-10-25）：编辑器 Hub、`scripts/toolchain.py`、工具索引生成、注册面检查、`restore-check` 的环境字段都读它。当前登记 **71 件工具**、9 个分类（内容烘焙 6、UI 16、调试 9、代码生成 12、质量门禁 9、构建 3、内容发布 5、环境与索引 7、部署与云运维 4）；按平面分 `editor` 27、`runtime` 9、`external` 31、`none` 4。注册面 5 个：CI、夜间任务、ZCode/Claude hook、pipeline 包路径。

```powershell
python scripts/toolchain.py check --strict                # 清单/文档/注册面
python scripts/toolchain.py docs --check                  # 工具索引新鲜度
python scripts/toolchain.py verify --suite L1 --profile PullRequest
python scripts/toolchain.py generate build-hash --check    # = codegen/toolbox.py
```

| 子命令 | 作用 | 关键参数 |
|---|---|---|
| `list` | 按清单列工具 | `--json`、`--plane/--kind/--purpose`（可重复，并集） |
| `check` | 清单/路径/文档/注册面，外加孤儿脚本、编码与 EOL | `--json`、`--strict`（可选注册面告警升 error） |
| `docs` | 生成或校验工具索引 | `--check`（只比新鲜度，Doc 车道也调它） |
| `open <id>` / `run <id> -- <args>` | 在 Hub 打开工具 / 跑 CLI·门禁·构建·内容工具 | `--` 之后原样透传 |
| `generate <tool> [args]` | 转发到生成器工具箱 | 等价 `scripts/codegen/toolbox.py` |
| `verify --suite ...` | 跑门禁套件 | `--suite L0\|L1\|L2\|L3\|Doc\|All`、`--profile PullRequest\|Nightly\|Release` |
| `build [--profile]` / `doctor` | 转发 `build-player.py` / 清单+环境+注册面巡检 | 默认 profile `windows-x64.json`；`doctor` 另有 `--strict`、`--fix-nightly` |

编辑器内入口是菜单 **`LiteGame/工具链`**（`Assets/LiteGame/Editor/Toolchain/Window/LiteGameToolboxWindow.cs`）：清单驱动列出可打开的工具。新增工具的最低要求是**同批登记清单 + 文档 + 注册面**，否则 `check` 报漂移、`docs --check` 报索引过期。

## 6. Unity 侧操作边界

序列化内容不能靠改文件保证一致（GUID、导入设置、组件引用都由编辑器维护），因此按内容类型分三档。

### 6.1 可直接编辑

普通 `.cs`；Shader、CSV、JSON、Markdown 等纯文本。多文件先批量改完再统一刷新/编译，避免重复编译与域重载。**Pipeline 不可达时只允许改这些纯文本**，且结论里要写明"序列化资源未验证"。

### 6.2 必须走 Pipeline

- 场景、Prefab、Material、ScriptableObject、AnimationClip、AnimatorController、Timeline 的创建与修改；
- `Assets/` 下既有文件/目录的移动、重命名、复制、删除；外部资源的导入与导入设置（可先把源文件拷进目标目录再让 Unity 导入）；
- 场景对象操作：GameObject 的创建/删除/层级/Transform/组件及序列化字段；
- 工程设置：Build Settings、Tags/Layers、Input、Quality、Graphics、Player Settings；
- 场景/Prefab/材质/视觉效果在编辑器里做并持久化，**不得以运行时代码临时创建替代资产制作**。

### 6.3 禁止直接操作

- 手改或删除 `.meta`，或把某个 GUID 复用到别的资源；
- 手改 `.unity/.prefab/.mat/.asset/.controller/.anim` 等序列化文件；
- 手改 `Library/`、`Temp/`、`Logs/`、`UserSettings/`、根级 `*.csproj`/`*.sln`；
- 以字节方式改写二进制资产。

### 6.4 批量与收尾

- 同类目标批量查询、修改、统一验证；改序列化字段/组件类/程序集结构时维护资源兼容与脚本绑定；大范围重导入、切构建目标、出包、批量改写资源先取得明确授权；
- 优先命令目录里的专用操作，无合适操作才 `eval`；`eval` 只写最小代码并处理 Undo、脏标记与保存；
- 验证按改动匹配，非必要不跑全量；视觉改动按批截图、区分本轮新增与历史日志；
- 场景/Prefab 编辑或 Play Mode 结束后保存有意义的修改、丢弃临时变更，**不得擅自保存或丢弃用户已有的未保存内容**。

## 7. Pipeline 兼容层（跑在 2022.3 上）

### 7.1 为什么有补丁

上游 `com.unity.pipeline` 只声明支持 Unity 6000.0（registry 里所有版本都写 `"unity": "6000.0"`），本工程是 2022.3.55f1c1，因此以 **embedded 包** `Packages/com.unity.pipeline/`（`0.7.0-exp.1`）落位并打兼容补丁。包**不入库**（与 `MCPForUnity/` 同策略），换机按 §7.3 重建；升级到 Unity 6 后应还原上游原包（补丁均带 `#if` 守门或可逆）。

UPM 依赖：`com.unity.nuget.mono-cecil 1.11.6`、`com.unity.nuget.newtonsoft-json 3.2.1`、`com.unity.test-framework 1.1.33`、`com.unity.inputsystem 1.11.2`。

### 7.2 九条补丁（重抓后逐条重放）

| # | 文件 | 改动 | 原因 |
|---|---|---|---|
| 1 | `Runtime/Plugins/CodeAnalysis/*.dll.meta`（5 个） | 转 v2：`serializedVersion: 2` + **列表式** `platformData`（Editor/Standalone 启用） | 上游 v3 的 map 式被读成"全平台禁用"→ `IlInterpreter` 找不到命名空间；`defineConstraints` 原样保留 |

### 7.3 重抓与重放

包体来源 `https://packages.unity.com/com.unity.pipeline`（registry 直连可达）。**先关编辑器**，再：

```bash
curl -s https://packages.unity.com/com.unity.pipeline \
  | python -c "import json,sys; d=json.load(sys.stdin); print(d['dist-tags']); print(list(d['versions']))"
mkdir -p Temp/pipeline_dl Packages/com.unity.pipeline
curl -sL -o Temp/pipeline_dl/com.unity.pipeline-0.7.0-exp.1.tgz \
  https://download.packages.unity.com/com.unity.pipeline/-/com.unity.pipeline-0.7.0-exp.1.tgz
tar -xzf Temp/pipeline_dl/com.unity.pipeline-0.7.0-exp.1.tgz \
  -C Packages/com.unity.pipeline --strip-components=1
# 再按 §7.2 重放 9 条补丁，然后重开编辑器（UPM 解析 → 编译 → 起服务）
```

校验：`package.json` 的 `version` 为 `0.7.0-exp.1`；文件数量级约 820（上游 tarball 821，补丁增删少量文件）；程序集产出 5 个（`Unity.Pipeline`/`Unity.Pipeline.Editor`/`IlInterpreter`/`Attributes`/`CodeGen`）；`error CS` 为 0。**上游 latest 会前进**（实测已是 `0.8.0-exp.1`），换版本必须逐处核对锚点，不能照搬。

### 7.4 驱动通道：CLI 与 HTTP

服务在编辑器侧由 `[InitializeOnLoad]`（`PipelineServerStartup`）自动启动，**新增 embedded 包后必须重启编辑器**才会解析、编译并起服务；描述符 `Library/Pipeline/.unity-pipeline-port`（`pid`/`port`/`evalToken`/`mode`）是唯一发现通道，关闭编辑器时删除，`.gitignore` 覆盖。

- **CLI**（现行 `1.0.0-beta.2`，装在 `%LOCALAPPDATA%\Unity\bin\unity.exe`）：`unity status` 列已连编辑器（端口/状态/工程/版本/PID）；`unity list --project-path <repo>` 列命令（本机 **151 条**）；`unity command <cmd> --project-path <repo>` 执行；多实例时必须显式给 `--project-path`。
- **HTTP**（CLI 只是壳，打同一服务）：`GET /api/commands` 取命令目录（每条带完整 JSON Schema），`POST /api/exec` 执行；另有 `/api/status`、`/api/editor_status`、`/api/dialog`、`/api/test-status`、`/api/progress`。

```bash
cat Library/Pipeline/.unity-pipeline-port
curl -s -H "Authorization: Bearer <evalToken>" http://127.0.0.1:<port>/api/commands
curl -s -X POST http://127.0.0.1:<port>/api/exec \
  -H "Authorization: Bearer <evalToken>" -H "Content-Type: application/json" \
  -d '{"command":"editor_status","parameters":{}}'
```

| 连接约束 | 说明 |
|---|---|
| 必须 `127.0.0.1` | Mono 的 `HttpListener` 对 IPv6 回环回 400；`localhost` 可能落 `::1`，表现为间歇连不上 |
| 必须 `Authorization: Bearer <evalToken>` | 每请求校验、常量时间比较；缺失/错误回 401 |
| 不能带 `Origin` 头 | 服务端拒收（挡浏览器页）；curl/脚本默认不带 |
| 端口 | 编辑器 `7800-7849`，测试实例 `7850-7899`，取首个空闲 |
| Token 生命周期 | 存 `SessionState`：跨域重载存活、编辑器重启才换 |

**请求体与对象引用**（踩过的坑）：参数键名是 `parameters` 不是 `args`（用 `args` 会得到 400 `Required parameter 'path' is missing or empty`），先读 `/api/commands` 的 schema；`add_component`/`set_tag`/`set_transform` 的 `target` 用 **globalId**（`GlobalObjectId_V1-2-<sceneGuid>-<fileId>-0`），传 `/MainCamera` 会被当文件系统路径解析；改工程设置的命令（`add_scene_to_build`、`set_tags_layers`）**只改内存**，返回成功但文件不动，必须补一条 `save_all` 才落盘。

### 7.5 常见故障

| 现象 | 原因 | 处置 |
|---|---|---|
| 编辑器卡在模态对话框 | 非自动化模式启动 | 无人值守用 `unity open` |
| 新包导入后无服务 | 没重启编辑器，UPM 未解析 | 重开编辑器再看描述符 |
| 插件 DLL"未加载"但 `error CS` 为 0 | meta 解析失败不进编译错误 | 看 Console 的 `Parser Failure`；插件 meta 必须是 v2 列表式 |
| `build-player.py` 卡在 dry_run | 补丁 9 未重放 | 补 `public` 后重新编译 |

## 8. 排障速查

| 症状 | 先查 | 处置 |
|---|---|---|
| Join 被拒/握手失败 | `toolbox.py build-hash --check` | stale → `build-hash` + `refresh-hash` 全链（漏 RoomServer 重建/Unity 重编译同样拒进房） |
| 改了表但行为没变 | Luban 产物时间戳 | `toolbox.py luban` + Unity 导入（`refresh-hash` 可编排） |
| checksum 红/假和解 | sync-code 产物 vs `[StateLayer]` 标注 | `toolbox.py sync-code` + `build-hash` |
| 爆头/枪位/身位手感漂 | prefab 是否被美术动过 | 烘焙对应页重烘（write-if-changed，值不变零触碰） |
| L2 全绿但行为不对 | 新鲜度守卫（见 [10-测试与门禁](10-测试与门禁.md)） | 外部改码后强制 Refresh + 编译收敛再跑 |
| 出包被 `--check` 拦 | buildHash stale | `toolbox.py build-hash` 后再出包 |
| 克隆后缺 prefab/资产 | `.gitignore` 白名单 | 派发渠道还原（烘焙前提），见 [16-环境复原与机器差异](16-环境复原与机器差异.md) |
