# 模块发行矩阵（tier / 收集组 / 改什么发什么）

> **定位**：回答"改一个模块或一类内容，应该发应用基包、脚本包还是数据包"。
> **单源**：`arch/units.json`（模块 tier / 收集组 / 「改什么→发什么」）；`scripts/content/module-tiers.json` 是模型生成的只读镜像（旧表保留一个版本周期）。L1 守卫 `ModuleTierMatrixTests` 读模型，`scripts/gate/arch-check.py` 校验模块路径、tier 取值、收集组与 `Assets/BundleCollectorSetting.asset` 双向覆盖。本文是给人看的投影，数值/清单以模型为准；模型结构与维护流程见[说明 20](20-架构单元模型.md)。

## 1. 层级口径

| tier | 含义 | 发布形态 |
|---|---|---|
| `base` | AOT 代码/程序集（含 Bootstrap、App、Modules、Adapters） | 应用基包（重新出 Player）；内容包不能替换 |
| `script` | Lua 脚本（`Assets/LiteGame/Lua`） | 脚本内容包（候选/热更） |
| `data` | 配置表、prefab、字体、场景、角色/特效等资源 | 数据内容包（按收集组） |

一个模块可同时拥有多个 tier：代码是 `base`，它拥有的资源/表分别落 `data`/`script`。

## 4. 改什么 → 发什么

| 改什么 | 路径面 | 发什么 | 说明 |
|---|---|---|---|
| C# 代码/程序集 | `Assets/LiteGame/**/*.cs` | base | 改 AOT = 应用发布；内容包不能替换代码 |
| Lua 脚本 | `Assets/LiteGame/Lua/**` | script | 走 Lua 收集组与候选校验链 |
| 配置表/表源 | `Assets/GameData/Config/**`、`Luban/Data/**` | data | 表值可热更；表源改动需重跑 Luban/摘要链 |
| UI/角色/特效/音效/场景资源 | `Assets/LiteGame/Modules/*/Content/**`、`Assets/ShareResource/**`、`Assets/Scenes/**` | data | 按收集组发内容包 |

## 5. 门禁

```powershell
python scripts/gate/test.py --suite L1 --profile PullRequest
```

`ModuleTierMatrixTests` 会拦住：模块目录未登记、tier 不在枚举、收集组登记不存在、真实收集组未被覆盖、
矩阵行缺路径或 ship 不是 tier。新增模块/收集组时先改 JSON，再同步本文。
