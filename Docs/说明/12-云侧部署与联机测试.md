## 1. 形态与地址面

### 1.1 为什么是 Windows 原生

对局与隧道都要 UDP 入站（`17777`、`51820`），而 Windows 的 `netsh interface portproxy` 只转发 TCP、WSL2 里接不了公网 UDP；现行形态让 .NET 进程与隧道服务直接监听主机，隧道把报文投递到 `10.8.0.1` 即到位。

### 1.2 主机与安全组

| 项 | 现行值 |
|---|---|
| 系统 | Windows Server 2025 Datacenter，**Server Core（无图形桌面）**，build 26100 |
| 规格 / 时区 | 2 vCPU / 3.9 GB / C: 40 GB（可用 26 GB）；China Standard Time，服务内部一律 UTC |
| 地址与账号 | 公网 IP、管理员账号、密钥路径只记 `LocalNotes/cloud-host.md`（不入库）；本文不回显 |
| 门禁 | 主机防火墙三档默认关闭，唯一门禁是**云安全组**：`UDP 51820` 全来源开放，`22/tcp` 已撤出入方向，`5000`/`17777`/`9100`/`9101` 不开公网 |

Server Core 缺两个件：**OpenSSH Server**（`Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0`，装后 `Set-Service sshd -StartupType Automatic`、公钥写 `%ProgramData%\ssh\administrators_authorized_keys`）与 **VC++ 2015–2022 x64**（`vc_redist.x64.exe /install /quiet`）——不装后者 `mongod` 起不来（缺 `vcruntime140.dll` / `msvcp140.dll`）。

### 1.3 地址与端口

| 角色 | 监听面 | 绑定来源 |
|---|---|---|
| Meta（登录/大厅/票据/战绩） | `http://10.8.0.1:5000` | `META_Meta__BindAddress` |
| Room（KCP 对局） | `UDP 17777`，kcp2k 绑 `0.0.0.0` | `roomserver.json` 的 `port` |
| 指标 / 运维（GM） | `TCP 0.0.0.0:9100` / `TCP 10.8.0.1:9101` | `metrics_port` / `gm_port` + `gm_bind` |
| MongoDB / WireGuard | `127.0.0.1:27017`（副本集 `rs0`）/ `UDP 51820`（接口 `10.8.0.1/24`） | `mongod.cfg` 的 `net.bindIp` / `wg0.conf` |

**`17777` 的绑定面不等于可达面**：它绑 `0.0.0.0`，对外可达由安全组与主机防火墙决定（只放行隧道网段），核验按实际监听面查。客户端只认隧道内地址（Meta `:5000`、Room `:17777`、指标 `:9100`、GM `:9101`），换机换 IP 不变。Meta 端点：`/live`、`/ready`、`/auth/guest`、`/lobby/rooms/public`、`/lobby/instances/register`、`/matches/result`。

### 1.4 运维通道：隧道优先，公网 22 关闭

日常 SSH 走隧道入口 `10.8.0.1:22`，本机 `~/.ssh/config` 别名 `litegame-cloud-tunnel`（`HostName 10.8.0.1`、`IdentitiesOnly yes`、`StrictHostKeyChecking accept-new`、`ServerAliveInterval 30`）：公网 22 的白名单按**来源 IP** 放行而出口 IP 会变，隧道内的 22 由 WireGuard 公钥 + SSH 公钥识别身份。**脚本默认只走隧道**：`scripts/deploy/` 的 `deploy-room.py` / `gm.py` / `wg-peer.py` 共用 `_ssh_host.py`，`10.8.0.1:22` 可达且别名已配才继续，否则 fail-fast、**不自动回退公网**；破窗用 `--ssh-host litegame-cloud` 或 `LITEGAME_SSH_HOST`，或走云控制台 VNC。本机隧道服务 `WireGuardTunnel$wg-dev`（自启）；首次接入核对 host key。

## 2. 目录布局与发布方式

云上根目录 `C:\litegame\`：`meta\`（MetaServer.exe + appsettings.json + run.cmd + 日志）、`room\`（RoomServer.exe + roomserver.json + run.cmd + 日志）、`GameData\Config\`（玩法表 .bytes，与客户端同一份，`--combat-table` 指这里）、`wg\`、`python\`（embedded Python 3.12 + `remote_runner.py`，不写 PATH）、`mongo\`（bin/data/log/mongod.cfg）。服务器只收产物，不装 SDK：

```powershell
dotnet publish Server/MetaServer/MetaServer.csproj -c Release -r win-x64 --self-contained true -o Builds/win-server/meta
dotnet publish Server/RoomServer/RoomServer.csproj -c Release -r win-x64 --self-contained true -o Builds/win-server/room
```

自包含产物百 MB 级（`meta` 约 105 MB、`room` 约 73 MB），服务器不装 SDK。**玩法表必须与二进制同批**：`deploy-room.py` 默认同传 `Assets/GameData/Config`（`--skip-tables` 可跳过）；只换二进制不传表时客户端会在 `StartGame` 以「玩法数据身份不符（ConfigHash）」拒整局——这是数据面守卫。判据：Room 日志 `[Tables] 玩法数据身份基摘要:0x…` 与客户端「本地基摘要」同值。

云上动作由 `deploy/remote_runner.py`（stdlib-only，上传为 `C:\litegame\remote_runner.py`）执行：`room-stop` / `room-start` / `room-status` / `wg-peer`。运行时默认 `C:\litegame\python\python.exe`（改系统 Python 设 `LITEGAME_REMOTE_PYTHON=python`），pin 为 Python 3.12.9 + 固定 SHA256；缺失时脚本在停服/上传**之前** fail-fast。首次/换机跑 `python scripts/deploy/bootstrap-cloud-python.py`（`--dry-run` 只看计划，`--force` 重装）。

## 3. 依赖件与托管

**依赖件**：MongoDB 官方 zip 解到 `C:\litegame\mongo\bin`，`mongod.cfg` 配 `storage.dbPath`、`systemLog.path`、`net.bindIp 127.0.0.1:27017`、`replication.replSetName rs0`（事务依赖），装服务后 `rs.initiate`（期望 `1 PRIMARY`）；WireGuard 用官方 MSI + `wg.exe genkey/pubkey` + `/installtunnelservice wg0.conf`（服务 `WireGuardTunnel$wg0`，换配置先卸后装），`wg0.conf` 的 `[Interface]` 为 `Address 10.8.0.1/24` + `ListenPort 51820`，每个测试者一条 `[Peer]`（`AllowedIPs 10.8.0.2/32`）。

**托管**：两个应用由任务计划 `LiteGame-Meta` / `LiteGame-Room` 托管（`SYSTEM` + `AtStartup`，Action = `cmd.exe` + `/c "…run.cmd"`，直接给 `.cmd` 会返回 `0x1` 且无日志）；**禁止在 SSH 会话里 `Start-Process` 起常驻进程**（子进程随会话回收）。配置是**启动期快照**，改 `roomserver.json` 或环境变量后必须重启对应任务。

## 4. 应用配置

### 4.1 Meta：以机器级环境变量为准

配置优先级：代码默认值 → `appsettings.json` → `META_` 环境变量 → 命令行/测试覆盖。实测 `appsettings.json` 放 exe 同目录**没有被采用**（仍绑 `http://127.0.0.1:5000`），改用机器级环境变量一次就对，故现行以环境变量为准（每条 `[Environment]::SetEnvironmentVariable('<变量名>','<值>','Machine')`，密钥值来自开发机 `deploy/.env`）。

- Meta 12 项（前缀 `META_Meta__`）：`BindAddress`、`MongoConnectionString`（`mongodb://127.0.0.1:27017/?replicaSet=rs0`）、`MongoDatabaseName`（`litegame`）、`AuthSigningKeyBase64`、`LobbyInstanceKeyBase64`、`LobbyTicketKeyBase64`、`LobbyTicketKeyId`（`l1`）、`LobbyTicketAudience`（`lobby`）、`LobbyDefaultRoomId`（`lobby-default`）、`SettlementInstanceKeyBase64`、`AllowNonLoopbackHttp`（`true`）、`EnableSampleEndpoints`（`false`）。
- Room 4 项：`LITENET_SECURE_ENVELOPE_KEY`、`LITENET_LOBBY_INSTANCE_KEY`、`LITENET_SETTLEMENT_INSTANCE_KEY`、`LITENET_TICKET_KEY`（`l1:<LOBBY_TICKET_KEY>`）。

密钥只经环境变量注入，不进仓库、不回显（代价是机器上其他管理员可读，封闭测试接受）。

### 4.2 Room：`deploy/roomserver.windows.json`

仓库这份就是成品（纯 ASCII、无 `_comment`），直接传成 `C:\litegame\room\roomserver.json`（复杂命令别在 ssh 里拼引号：scp 传 `.ps1` + `powershell -File` 执行）。

| 字段 | 值 / 说明 |
|---|---|
| `port` / `max_rooms` / `worker_count` / `mailbox_capacity` | `17777` / `8` / `1` / `1024` |
| `audience` / `default_template` / `metrics_port` / `gm_port` / `gm_bind` | `lobby` / `standard` / `9100` / `9101` / `10.8.0.1` |
| `lobby.url` / `advertise_host` / `instance_id` / `heartbeat_interval_ms` | `http://10.8.0.1:5000/lobby/instances/register` / `10.8.0.1` / `room-1` / `1000` |
| `settlement.submit_url` | `http://10.8.0.1:5000/matches/result` |
| `diagnostics` / `rate_limit` | `enabled:true`、`C:/litegame/room/diagnostics`、`max_files 100`、`max_total_mb 512`；限流 `buckets 8192`、`idle_ms 120000`（其余见文件） |

启动横幅判据：`rooms=[standard,four,eight,sandbox] default=standard`；仍是 `default=sandbox` 说明配置没上传或任务没重启。

### 4.3 模板：规则集，不是地图

| 模板 | `expected_players` | `match_duration_frames` | `kill_limit` | `respawn_delay_frames` | `spawn_protection_frames` |
|---|---|---|---|---|---|
| `standard` / `four` / `eight` | 2 / 4 / 8 | 10800（60 fps 下 180 s） | 20 | 180 | 120 |
| `sandbox` | 2 | 0（不限时） | 0（不按击杀结束） | 60（1 s） | 120 |

- **普通房**：大厅选图 + 人数建房，走 `default_template=standard`，自然结束并产出结算。
- **云端测试房**：只能由编辑器 GM 页「创建并进入云端测试房」按 `template=sandbox` 建（隐藏、不进大厅；地图随建房票据盖章）。`respawn_delay_frames` **必须 ≥ 1**；`spawn_protection_frames=0` 表示无出生保护，且开火即清零；客户端选人数会覆盖模板的 `expected_players`（票据盖章 `0 = 按模板`）。
- **代价**：测试房不产结算——服务端对隐藏房跳过结算入盒，客户端仍收 `MatchEnded`，结算页按「无结果」展示。模板/端口/心跳改动只改配置并重启任务（`buildHash` 不变、客户端不动）。

## 5. 运维（GM）端点

真 KCP 独立进程形态下客户端 GM 面板够不到权威侧，故房间服另起**只绑隧道地址的写端点** `http://10.8.0.1:9101/gm/*`。门禁五条（缺一不开）：**仅 POST**（其余 404）；头 `X-GM-Key` **恒定时间比对**；body ≤ **4096 B**；密钥只走机器级 `LITENET_GM_KEY`，**空 ⇒ 端点不创建**；`gm_bind` **不得为通配地址**（装载期拒）。权威契约是 `Server/RoomServer/gm-contract.json`（动作、路径、必填字段、状态码都以它为准，`gm.py` 的动作清单由它派生）。

| 动作 | 路径 | 语义 |
|---|---|---|
| `rooms` / `diag-list` / `diag-fetch`（读） | `POST /gm/rooms` · `/gm/diag-list` · `/gm/diag-fetch` | 在册房间（`room/phase/players/expected/map`，含隐藏房）；诊断产物清单（名/字节/时刻）与按名下载（目录直下，64 MB 上限） |
| `start` / `abort` / `kick` | `POST /gm/start` · `/gm/abort` · `/gm/kick` | 强制开局（取真实 owner 代发）/ 运维终止（走完 Finishing/Settling）/ 踢席位（需 `player`） |
| `rules` | `POST /gm/rules` | `1`=免死 / `2`=无限弹药 / `0`=关闭，或 `{noDeath,infiniteAmmo}`，**只对隐藏测试房生效**，普通房 409 |
| `settle-flush` | `POST /gm/settle-flush` | 立刻回灌结算 Outbox |

状态码与字段以 `Server/RoomServer/gm-contract.json` 为准（`400` 坏 JSON、`401` 密钥不符、`404` 未知动作、`409` 房间状态拒绝、`413` 下载超限）。调用经 `python scripts/deploy/gm.py --action <动作>`；脚本自动起/关 SSH 隧道，本机端口默认 **19101**，**别用 9101/9100 作本机转发端口**（落在 Windows TCP 排除区间 9014–9113）。密钥取 `LITEGAME_GM_KEY`，缺失回退 `LocalNotes/cloud-host.md`；手拼 curl 必须带 body（否则 `HttpListener` 回 411）。

## 6. 发版矩阵

| 改了什么 | 云上 | 客户端 |
|---|---|---|
| 纯表现 / Lua / prefab / 美术 | 不动 | 编辑器重编译；需要时重出包 |
| 服务端宿主 `.cs`（`Server/RoomServer`、`Server/MetaServer`） | **重新 publish 并上传**（只重启任务无效） | 不动 |
| 共享源集（`LiteSim/{Scripts,Systems}`、`LiteNet/{Proto,Protocol,Transport/Security}`、`GameData/Generated`、`SHARED_LINK_FILES` 源链接件） | `python scripts/codegen/gen-build-hash.py` → 重新 publish 上传 | **必须重打包**（旧包握手拒） |
| 房间内核 `Assets/RoomServer/{Runtime,Application}`（不在共享闭包内，改它不动 buildHash） | 重新 publish 上传 | 不动（编辑器重编译即可） |
| 表源 `Luban/Data/*.xlsx` / 只改 `roomserver.json` | `Luban/gen.bat` → 重建产物；配置改动传配置后重启任务 | 表源改则重编译 + 重打包（摘要同源）；配置改动不动 |

判据永远是两端 `buildHash` 同值；不一致的表现是签票 **`409 version-mismatch`**，不是「连不上」。出包前可跑只读 preflight：`python scripts/build/build-plan.py --base origin/main`。

## 7. 一键部署与判据

```powershell
python scripts/deploy/deploy-room.py                    # 发布 → 打包 → 停服 → 上传 → 解压 → 起服 → 回读
python scripts/deploy/deploy-room.py --skip-publish --with-config   # 只上传现有产物并同时上传 roomserver.windows.json
```

执行序（脚本内固化）：`dotnet publish` → `tar` 打 `room.tgz` 与 `GameData-Config.tgz` → `ensure_remote_ready`（云上 Python 探测，缺失即 fail-fast）→ `room-stop` → `scp` 上传 → `room-start`（解压 + 起任务）。**两个已固化的坑**：**先停服再解压**（运行中的 DLL 被占用会 `Can't unlink already-existing object`）；**停/起分两次 ssh**。判据：`process=RUNNING`、`task=Running`、`buildHash=…` 与客户端包内常量同值。

## 8. 测试者接入

**游戏基包只发一次，conf 一人一份**（WireGuard 密钥/隧道地址必须唯一）。测试者包必须用 **release 通道**产物：`BuildProfiles/windows-x64-release.local.json`（`channel: release`，输出 `Builds/StandaloneWindows64-release`，与 closedtest 档同 endpoints，但不含开发面）。

命令：`pwsh -NoProfile -File Dist/New-Package.ps1 -Tester LiteGame-base -Base -Zip -GameBuild Builds/StandaloneWindows64-release` 出基包；`python scripts/deploy/wg-peer.py --name alice`（`--dry-run` 只生成不改云上，`--ip 10.8.0.9` 指定地址）出每人 conf；`pwsh -NoProfile -File Dist/New-Packages.ps1 -Testers alice,bob,carol -Overlay -Zip -Force` 批量出叠加包（`-DryRun` 只校验，省略 `-Testers` 则扫 `Dist/out/*.conf`）。

测试者侧：解压基包 → 把自己那份 `.conf` 放到与 `加入联机环境.cmd` 同目录（只能放一份）→ 双击该脚本（装 WireGuard → 装隧道 → `/live` 自检）→ 双击游戏。一人一份 `.conf`（内含私钥），不能共用/回传/截图；换机或换公网 IP 时全部作废（只需重生成 `Endpoint` 与 `PublicKey`）。基包不含私钥，可重复分发；换网络**不用重新加白**。

### 9.2 一轮对局

| 步 | 操作 | 期望 |

| 1 | 编辑器 Play / 双击 exe（零参数）→「游客一键登录」 | 登录页版本行 = 云上 `buildHash`；进大厅、显示短号 |

| 5 | 正常打完（standard：20 杀或 180 s） | 结算页 → 大厅「战绩」有行 |

### 9.3 云端测试房（开发者路径）

本机以开发者配置启动（`deploy.args` 或命令行带 `-room.gmkey=<口令>`），登录进大厅 → 编辑器 Hub → 调试分类「本地测试模式」页 →「云端测试房（sandbox）」→ 选地图 →「创建并进入云端测试房」→ 隐藏房建成、房号回填；需要免死/无限弹药时同页下发 `/gm/rules`。每次加入都需要 `template=sandbox` + `room.gmkey` ⇒ 开发者专属；口令来自 Meta 侧 `LITEGAME_GM_ROOM_KEY`，为空 ⇒ 功能关闭、签票一律 `403 forbidden`。兜底：`gm.py --action rooms / start / kick`。

## 10. 观测、收尾与排障

### 10.1 观测与验收

观测面：`C:\litegame\room\out.log`（Lobby 横幅 / `[GM]` 审计 / 结算 / `[Ops]` 周期行）、`/metrics`（经 `ssh -N -L 19100:10.8.0.1:9100 litegame-cloud-tunnel` 看）、客户端 `Player.log`（release 无 DevHUD，见 [13](13-调试面与排障.md)）。验收用**普通房**（`standard`）打完一局 → 结算页 → 大厅「战绩」有行；测试房（`sandbox`）不结算。横幅仍是 `default=sandbox` 就先重传配置并重启 `LiteGame-Room`；也可 `gm.py --action settle-flush` 回灌 Outbox。

### 10.2 高频坑

| 症状 | 根因 / 处置 |
|---|---|
| `mongod` 起不来 / 隧道装不上 | Server Core 缺 VC++ 运行库 → 装 `vc_redist.x64.exe`；同名隧道服务存在时重装失败 → 先 `uninstalltunnelservice` |

| 登录 `Insecure connection not allowed` / 同机同账号 | 包不是用当前 profile 出的；各给不同 `-device.id` |
| `ssh` 突然 `Connection timed out` | 出口 IP 变了或 sshd 停了 → 控制台核对；`ping` 通不代表 22 通 |

### 10.3 红线与容量

1. 私钥（`~/.ssh/id_ed25519_litegame`）、`deploy/.env` 密钥、测试者 `.conf`、`LITENET_GM_KEY` **不入库、不回显、不截图**；IP 与用户名可以入库。
2. 这是**封闭测试环境**：不得公开/宣传，**不得作为「可发布」判据**。
3. 云上应用一律任务计划托管，禁 SSH 会话里 `Start-Process`；云上脚本保持**纯 ASCII**。
4. 换机/换公网 IP ⇒ 已发出的测试者 `.conf` 全部作废；客户端与游戏包不动。
5. 容量 2 核 / 3.9 GB，**不做容量承诺**；数据在 `C:\litegame\mongo\data`、结算在 `room\Outbox`、诊断在 `room\diagnostics`，**无定时备份**。
