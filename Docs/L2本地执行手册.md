# L2 本地执行手册

本文用于在 Windows 本机收口 Unity L2 门禁。所有 Unity 交互均通过 Unity CLI/Pipeline 完成；不得直接删除 `Assets/` 下的文件、文件夹或 `.meta`。

## 1. 本次目标

完成以下验收：

1. Unity Editor Pipeline 可连接。
2. 通过 `AssetDatabase` 删除误导入的 `Assets/LiteTesting/bin`、`obj` 及其 `.meta`。
3. Unity 脚本重新编译成功，不再出现 `LiteTesting.Core.dll` 同名程序集警告。
4. `LiteTestingFrameworkEditModeTests` 两个框架冒烟用例通过。
5. 完整 L2 门禁退出码为 `0`。

## 2. 执行前检查

打开 Windows PowerShell，进入工程根目录：

```powershell
Set-Location 'E:\unityProject\Test'
$ProjectPath = (Get-Location).Path
```

确认：

- Unity Editor 已打开本工程，且不在 Play Mode。
- Editor 没有正在编译、导入资源或执行测试。
- 没有模态对话框挡住 Editor。
- `unity` CLI 可用：

```powershell
unity --version
```

不要启动第二个 Unity Editor 打开同一工程，也不要运行以下命令：

```powershell
# 禁止：会绕过 Unity AssetDatabase，并可能留下错误的 GUID/导入状态。
Remove-Item -Recurse Assets\LiteTesting\bin
Remove-Item -Recurse Assets\LiteTesting\obj
```

## 3. 恢复并确认 Pipeline

先查看实例：

```powershell
unity pipeline list
unity status --format json
```

正常状态应满足：

- 工程为 `E:\unityProject\Test`。
- Editor 实例为 `running` 或 `ready`。
- `Server Reachable` 为 `true`，或 `state` 为 `ready`。

如果显示 `Server Reachable=false` 或 `state=unreachable`：

1. 切回 Unity Editor。
2. 执行菜单 `Window > Pipeline > Start Server`。
3. 等待 5 秒，再重复 `unity pipeline list`。
4. 若存在模态对话框，先人工处理对话框，再重试。
5. 仍不可达时，先保存自己的未保存内容，再自行决定是否重启 Editor；不要直接结束 Unity 进程。

连接恢复后执行：

```powershell
unity command editor_status --project-path "$ProjectPath"
unity command set_autotick --enable true --project-path "$ProjectPath"
unity command --project-path "$ProjectPath"
```

`editor_status` 应返回可服务状态；最后一条命令应列出当前实例支持的命令，其中至少应包含：

- `run_script`
- `recompile`
- `recompile_status`
- `run_tests`
- `set_autotick`

如果 `editor_status` 返回 `blocked_by_dialog`，按返回的 `dialog` 信息在 Editor 中处理，不要持续重试。

## 4. 清理旧构建产物

`Assets/LiteTesting/bin` 与 `Assets/LiteTesting/obj` 是 dotnet 构建产物，会以插件 DLL 形式与 `LiteTesting.Core.asmdef` 同名告警。用 Pipeline 的 `delete_asset` 删除（走 Unity 的 AssetDatabase，`.meta` 一并清除）：

```powershell
foreach ($folder in 'Assets/LiteTesting/bin', 'Assets/LiteTesting/obj') {
  if (Test-Path -LiteralPath $folder) {
    unity command delete_asset --asset $folder --confirm true --project-path "$ProjectPath"
  }
}
```

目录不存在时跳过对应项即可（幂等）。

只读验证目录和 `.meta` 已由 Unity 一并删除：

```powershell
@(
  'Assets/LiteTesting/bin',
  'Assets/LiteTesting/bin.meta',
  'Assets/LiteTesting/obj',
  'Assets/LiteTesting/obj.meta'
) | ForEach-Object {
  [pscustomobject]@{ Path = $_; Exists = Test-Path -LiteralPath $_ }
} | Format-Table -AutoSize
```

四项都应为 `False`。如果清理命令失败，不要改用文件系统强删，应先处理 Pipeline 或 Unity 报出的错误。

## 5. 重新编译并检查状态

触发编译：

```powershell
unity command recompile --project-path "$ProjectPath"
```

编译会触发域重载，短暂连接失败属于正常现象。每隔 2 至 3 秒重复查询：

```powershell
unity command recompile_status --project-path "$ProjectPath"
```

直到状态为以下任一终态：

- `completed`
- `up_to_date`

验收要求：

- `failed` 或 `compilationFailed` 不得为 `true`。
- `errors` 为空。
- Unity Console 中不再出现以下同名程序集警告：

```text
Plugin 'Assets/LiteTesting/bin/Release/netstandard2.1/LiteTesting.Core.dll'
has the same filename as Assembly Definition File
'Assets/LiteTesting/Core/LiteTesting.Core.asmdef'
```

可通过 Pipeline 查看控制台：

```powershell
unity command console --project-path "$ProjectPath"
```

如果看到 `error CS####`，先修复编译错误，不要继续跑测试。

## 6. 运行框架冒烟测试

先确认测试可发现：

```powershell
unity command list_tests --mode editor --project-path "$ProjectPath"
```

运行 LiteTesting 框架自身的 EditMode 用例：

```powershell
unity command run_tests `
  --mode editor `
  --filter LiteGame.Tests.EditMode.LiteTestingFrameworkEditModeTests `
  --project-path "$ProjectPath"
```

预期结果：

```text
Total=2 Passed=2 Failed=0
```

若结果只显示失败但没有详细堆栈，分别缩小到单个用例重跑，或查看 Unity Test Runner / Console：

```powershell
unity command run_tests --mode editor --filter TrackedGameObjectIsDestroyedWithScope --project-path "$ProjectPath"
unity command run_tests --mode editor --filter TemporaryAssetFolderIsDeletedWithScope --project-path "$ProjectPath"
```

## 7. 运行完整 L2 门禁

框架冒烟通过后执行：

```powershell
powershell -NoProfile -File scripts\test.ps1 -Lane L2 -Profile PullRequest
```

最终应同时看到：

- `.meta` GUID 扫描通过。
- Unity 编译状态正常。
- Console 无 `error CS####`。
- EditMode 用例数大于 `0`，且失败数为 `0`。
- 汇总显示 `L2 通过`。
- PowerShell 进程退出码为 `0`。

可立即检查退出码：

```powershell
$LASTEXITCODE
```

## 8. 常见故障

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| CLI 退出码 `2` | 命令参数错误，操作没有执行 | 按错误提示修正参数，不要原样重试 |
| CLI 退出码 `6` | Editor 或命令执行失败 | 阅读完整错误；先处理连接、编译、对话框或测试失败 |
| `state=unreachable` | 找到了实例描述符，但 HTTP 服务不可达 | 在 Editor 执行 `Window > Pipeline > Start Server` |
| `blocked_by_dialog` | 模态对话框阻塞主线程 | 在 Editor 中人工关闭或确认对话框 |
| 域重载期间连接失败 | 编译过程中服务正在重启 | 等 2 至 3 秒后只重试状态查询 |
| `Total=0` | 测试程序集未编入或过滤条件错误 | 检查编译状态、asmdef 和 `UNITY_INCLUDE_TESTS` |
| 仍有同名 DLL 警告 | 旧 `bin/obj` 未被 Unity 完整删除 | 重新执行清理脚本并验证四个路径均不存在 |

## 9. 最终验收清单

- [ ] `unity pipeline list` 显示服务可达。
- [ ] `set_autotick` 成功。
- [ ] `Assets/LiteTesting/bin`、`obj` 及两个 `.meta` 均不存在。
- [ ] `recompile_status` 为 `completed` 或 `up_to_date`，无编译失败。
- [ ] Console 无 `LiteTesting.Core.dll` 同名警告和 `error CS####`。
- [ ] `LiteTestingFrameworkEditModeTests` 为 `2/2` 通过。
- [ ] 完整 L2 门禁退出码为 `0`。
