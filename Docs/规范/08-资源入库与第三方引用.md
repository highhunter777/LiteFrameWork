# 规范 08 · 资源入库与第三方引用

> **定位**：什么资源进版本库、放哪、第三方资源怎么引用。回答「这个文件该不该提交、放哪个目录」。
> **权威边界**：收集目录/分包规划归[资源收集目录专项设计](../设计文档/客户端/内容/资源收集目录专项设计.md)；运行时加载归[说明/09](../说明/09-内容热更与资源管线.md)。
> **来源**：合并自 AGENTS.md「资源规范」节与 2026-10-11 / 2026-10-13 两次用户裁决。
> **关联**：[01 文档体系与写作](01-文档体系与写作.md) · [02 代码与修改规范](02-代码与修改规范.md)

## 1. 入库判定（只看类型，不看目录）

**只有三类资源入库**：

| 类别 | 例 |
|---|---|
| 配置资源 | ScriptableObject、.asset 配置、管线设置 |
| 预制体模板资源 | UI 模板 prefab、HUD prefab |
| 场景资源 | `Assets/Scenes/*.unity` |

- **判定不看所在目录**：这三类落在共享目录或模块目录同样入库；非这三类落在同样位置同样**不入库**（收集目录是「进包来源」，不是「入库理由」）。
- 代码与脚本资源（.cs/.py/.shader 等）可纳入版本管理。
- 其他资源（美术原始素材、音频、第三方包）不纳入版本管理，由打包机本地还原。
- 最终裁决以根 `.gitignore`（其分段注释即理由）为准；本规范是导航视图，两者冲突以 `.gitignore` 为准。

## 2. 已裁决的例外（封闭名单）

| 例外 | 范围 | 理由 |
|---|---|---|
| TMP 中文字体 NotoSansSC SDF | `Assets/ShareResource/Fonts/`（含 OFL 许可） | 75 处文本引用的视觉单一来源；7 个 EditMode 用例按真实字体资产加载 |
| URP 管线资产 | `Assets/Settings/`、`UniversalRenderPipelineGlobalSettings.asset` | ScriptableObject 配置资源；已入库的 `ProjectSettings/GraphicsSettings.asset` 按 GUID 引用 |

金楷系列字体（约 110MB、全仓零引用、再分发许可未核实）与其余素材**维持不入库**。新增例外必须用户裁决并同批登记本节。

## 3. 第三方资源引用

- 产品资产**不得直接引用第三方资源**；先把要用的件**复制进我们自己的收集目录**（模块内使用资源目录，或 `Assets/ShareResource` 下的分类目录），再引用复制件。
- 复制件按类型判定：第三方付费资源不入库 → 其复制件也不入库（随打包机本地还原）。
- 第三方原始库（如 `Assets/Synty/`）只作**可复制的来源**，不被产品直接消费。
- 第三方付费资源不纳入版本管理。

## 4. 目录分层（2026-10-11 裁决）

```text
Assets/ 顶层           原始资源（Art/Model/Sound/Animation/Map…）——只被引用、不被直接寻址
模块目录/<资源子目录>   仅本模块使用、需进包的资源（模块聚合，样板 LiteGame/Lua）
Assets/ShareResource/   跨模块共享、需进包的资源（其下自建顶层子目录）
```

- 进包资源只放后两类；顶层只放原始资源。
- 新增/搬动收集目录 = collector ＋ 代码常量 ＋ 设计文档三面同批，改后重跑资源包构建核对清单。
- 迁移与分包方法论见[资源收集目录专项设计](../设计文档/客户端/内容/资源收集目录专项设计.md) §2/§5。

## 5. 检查清单

- [ ] 新增资源是否属「配置/预制体模板/场景」三类？否 → 不入库。
- [ ] 是否直接引用了第三方路径？是 → 先复制再引用。
- [ ] 是否落在顶层而非收集目录？是 → 按 §4 分层归位。
- [ ] 是否为已登记例外？否 → 不得扩例。
