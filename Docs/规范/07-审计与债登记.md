# 规范 07 · 审计与债登记

> **定位**：存量质量债的登记、修复与归档规则——问题在哪、修没修、修完的一行摘要放哪。
> **权威边界**：不记施工过程（归 [施工进度](../施工进度/README.md)）；不保留修复取证细节（取证在提交、测试与进度卷）。
> **来源**：合并自旧 `审计/README.md`（流程部分；登记表与归档目录原位保留）。
> **关联**：[02 代码与修改规范](02-代码与修改规范.md) · [说明索引](../说明/README.md)

## 1. 落点与目录

```text
Docs/审计/
├── 客户端/{登记,归档}/<类型>.md   # 未结清条目 / 已修复摘要
├── 服务端/{登记,归档}/<类型>.md
├── 客户端/批次计划.md             # 只排范围/退出条件，不登记条目
├── 服务端/批次计划.md
└── 代码质量审计-服务端.md         # 旧单体表存量（迁移中，S1 批收口）
```

- **一个类型一个文件**；新增问题只进对应类型的登记文件，不新建"综合表"，不合并类型；确实不属八类时归「技术债」。
- 本规范是流程权威；台账本身在各 `登记/`、`归档/` 文件里。

## 2. 八种类型（判据）

| 类型 | 判据 | 典型 |
|---|---|---|
| 硬编码 | 魔法数字/字符串、缺省值、路径约定写死；应有配置/常量/表 | 池上限、超时、默认动效时长 |
| 重复实现 | 同一逻辑两份以上，改一处漏一处 | FSM 双内核、字段清单手抄 |
| 技术债 | 死代码、未接线、临时诊断、半成品、测试专用 API 混生产 | 零消费者服务、`[Diag]` 哨位 |
| 不统一路径 | 同一件事两种以上做法/契约并存 | 关闭语义三种、计时三种轨 |
| 类设计 | 职责过载、状态口袋、公开可变字段、边界/端口缺失 | god class、public 字段状态袋 |
| 功能缺口 | 明确该有而缺的能力/入口（未实现，不是"坏了"） | 无退出入口、昵称为占位 |
| 文档债 | 文档与代码不符、索引/死链/权威分裂 | 符号名过时、三处默认值 |
| 工具链 | 编辑器/生成器/门禁/管线自身缺陷 | 契约 fail-open、生成器覆盖手写 |

## 3. 登记规则

1. **只登未结清**；修好即从登记**删行**（不留"已修复"批注，归档里有摘要）。
2. 每条一行起：`- [严重度] file:line — 问题。修法：……`；够定位、够复现即可。
3. 严重度 `高/中/低` 只作排序参考，不绑定批次。
4. **悬空设计路线的条目直接删除**（见 §5）。

## 4. 归档规则

1. 一行一条：`- 问题 → 修法（批次/提交）`；不保留堆栈、判定过程、逐文件清单。
2. 每个归档文件最多 100 条；满则开 `<类型>-02.md`、`-03.md`……编号递增，不合并、不改名（**D8 把守**）。
3. 序号与记录数写头部元数据（`记录：N/100`）。
4. 状态只由 git 事实回填：`已提交 <hash>` 或 `工作区未提交`；**禁"待提交"**（**D2 把守**）。
5. 归档是历史事实，不回改；后批修正前批时追加新行，不改旧行。

## 5. 删除判据（抛弃的设计路线）

满足任一即**直接删除**条目、**不进归档**：设计已归档/被取代且功能面退役；代码已整体删除；用户已裁决放弃。批次记录写一行：`删除 N 条（路线废弃：<路线名>）`。

## 6. 每批怎么走

1. **动手前查**：按要改的文件名 grep `登记/`；命中即顺手修小债，新代码禁止产生同型问题。
2. **修**：同批把修好的条目从登记删除。
3. **归档**：在对应 `归档/<类型>-0N.md` 追加一行；满 100 条先开新文件。
4. **新登记**：过程中发现的新问题按八类落到对应文件。
5. **门禁**：`python scripts/gate/test.py --suite Doc`（D2 状态 / D4 链接 / D8 上限）。

## 7. 批次编排

分批与状态见 `审计/客户端/批次计划.md` 与 `审计/服务端/批次计划.md`（只排范围/退出条件）；阶段目标以[客户端架构重构演进路线图](../设计文档/架构/客户端架构重构演进路线图.md)为准。
