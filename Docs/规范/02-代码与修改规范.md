### 1.1 常量与硬编码

- **逻辑中禁魔法数字/魔法字符串**：数值参数进 Luban 表或带名常量；资源路径、场景对象名、协议词表、页面 id（`PageIds.g.cs`）与文案 key 收口到所在系统的常量类/生成物。
- **跨层共享的"同一常量"必须单源，C# 侧是权威**：页面逻辑（`Page_<Name>Logic`）、编辑器工具、运行期服务引用同一份（经受控 API 生成或常量类导出），不允许两份字面量并存。动效默认值单源在 `UIFxDefaults`，页面逻辑与工具均引用它；新增参数不得再写第二份。〔反例：Pulse/Flash/Slide/Bubble 默认值曾在三处并存，`UIWidget.cs:42` 的 0.08 即漏网产物〕
- **生成器与运行时共享常量时，生成器必须引用运行时定义**（同工程源链接或代码生成），禁"注释对齐"。〔反例：`SimTrigTableGenerator.TableSize` 与 `SimTrig.TableSize` 各写一份〕
- **按名解析场景对象必须常量化 + 失败可见**：`GameObject.Find`/`transform.Find` 的路径字面量收口常量，解析失败必须留下诊断，静默 no-op 视为 bug。〔反例：`ProcedureBattle` 6 条场景路径与 `"Aim Camera"` 字符串约定〕
- **新路径字面量禁含中文**（跨平台打包风险）。〔反例：曾用 `"训练场.unity"`，现为 `Assets/Scenes/TrainingGround.unity`；新增路径字面量仍一律禁中文〕

### 1.2 单源与同步面

- **任何"A 与 B 必须一致"的关系必须机制化**：单源引用、代码生成、守卫测试三选一。只靠注释或"记得同步"即违规——评审见到"必须与 X 保持一致"的新注释，应要求改成机制。〔反例：`SimChecksum` 分型表字段清单手抄两份、`SimWorldDiff` 覆盖面漂移，导致 checksum 报警但 diff 报不出原因〕
- **float 位级比较只走 `BitUtil.Equal`**（Sim 确定性唯一入口）；数学只走 `SimMath`/`SimTrig`。
- **新增实体状态字段＝同步链四处一起动**：`CopyTo` / `SimChecksum`（公共＋全量双口径）/ `SnapshotDiffer` / `SnapshotReassembler`，且优先推动进 StateLayer 生成器而非继续手抄。〔反例：Item/Projectile/Zone 分型表未进生成器〕

### 1.3 静态状态与依赖获取

- **禁新增 public static 可变字段/属性**。名义豁免名单封闭（`Log`；`FileSystem`/`ReferencePoolService` 已实例化退役），扩名单须在设计文档登记。静态只读配置快照须走 `ConfigSnapshotService` 式的版本化发布，禁裸 volatile 直赋值双轨。〔反例：`AnimationProfileConfig` 静态快照绕过配置服务；`CollectionPool` 静态池族出了豁免名单〕
- **确定性判定路径（伤害/弹药/移动/命中/checksum）禁读任何静态可变状态——包括 `#if UNITY_EDITOR` 内的**。GM 开关一律显式注入参数对象；不进 checksum 的可变全局＝静默分叉源。〔反例：历史上 `SimTestRules` 六个静态布尔被直读，现经 `ILocalTestHooks` 端口注入〕
- **服务获取统一构造注入/容器 Resolve**；禁反射取私有成员取服务（改名即静默断链）；禁新增静态服务定位器。除公开面外一律走 `GameEntry.TakeContainer()`。〔反例：原 `GmPanel` 反射 `"s_container"` 六区静默失效（历史名；按现行 04 §6.1 应为 `GMPanel`）〕

### 1.4 错误与日志契约

- **已关闭服务再调用统一抛 `ObjectDisposedException`**。同一层级的姊妹服务必须同契约——不许一个抛、一个警告降级、一个裸奔 KeyNotFound。〔反例：EntityService/SceneService 抛、VfxService 警告、AudioService 无守卫〕
- **程序员错误 fail-fast**（构造期校验、参数越界直接抛）；**内容降级**走 `Log.Warning`＋显式默认值；禁吞异常静默继续。
- **生产日志统一 `Log.*` 门面**；禁在非编辑器生产路径直落 `Debug.Log/LogWarning`。临时诊断必须带 `[Diag]` 前缀＋摘除批次号，批次收口时必须清；热路径禁放周期性 Warning。〔反例：`BattleContext` 曾把七个 `[Diag]` 哨位留在 Tick〕
- **`IModuleStats.Snapshot` 实现约定：实现负责 `into.Clear()` 后填入**（调用方复用 Dictionary 且不清；见接口注释与 DevHUD 消费端）。统计键为展示用短词，同一实现内键语言须自洽（存量中文词表与新英文词表并存，不新增同实现内混用）。

### 1.5 并发与异步

- **锁粒度一致性**：同一对象的状态读写要么全在锁内，要么有单一属主线程，禁混用。〔反例：`SecureEnvelopeRoomTransport` 锁外读改连接状态、锁内 Dispose〕
- **延迟执行按域选择**：按秒动作序列走注入相应时钟的 `ITimelineRunner`；帧级"下一拍"由调用方在自身帧驱动里排队，或走 `EventBus.PublishQueued`（帧域、随 `FrameSchedule`）；两者不混用。`PublishQueued` 当前**无产品消费者**，属登记在册的预留槽位——新增调用点必须同时点名消费者并更新登记。
- **UniTask 延迟/续帧统一经 `UnityAsync` 封装入口**；LiteNet 禁 UniTask 的纪律维持不变。
- **传输层所有权约定写进接口注释并全项目一致**（谁 Dispose 内层）。装饰器与 `RoomClient` 两种现状约定是登记债，新适配器禁止再加第三种。

### 1.6 类与接口设计

- **功能模块高内聚、低耦合**：一个功能的实现（数据、逻辑、装配、平台适配件）必须内聚在同一模块目录内，不得为"分层"把它拆成两处实现、各自演进；跨模块只经端口/契约通信。分层裁决的是能力归属（如纯机制 vs 平台适配），不是功能切分的理由；确因平台依赖必须外置的适配件，只做薄适配、语义仍由模块单源定义。
- **接口只在跨边界时引入**：接口必须满足其一——实现与声明分属不同 asmdef，或存在第二个实现（含测试替身）。同程序集单实现接口没有跨过任何边界，直接用具体类型（`internal` 可见性 + 方向守卫），不新增“模块自持接口”；存量基线 `arch/port-baseline.json` 与 `port-lint.py` 守卫**已废弃（2026-11-10）**——文件与脚本均已从仓库删除；端口准入判据即本节：接口只在实现与声明分属不同 asmdef、或存在第二实现时引入（背景见[路线图 §4.1](../设计文档/架构/客户端架构重构演进路线图.md)）。
- **单一职责**；一个类承担多项职责时，动手前先给拆分方案（不按行数判定）。现役 god class 清单以审计登记与拆分方案为准；改动这类文件时应顺手收敛自己那一域，禁止继续加职责。
- **拆分口径**：外提的协作件按变化原因成文件（协作件与它的契约可同文件）、公共 API 不变、行为零变化。已收敛先例：`ProcedureBattle`→`BattleViewRig`（按 04 §6.3 拟改 `BattleViewGroup`，待改名批）、`BattleContext`→`BattleInputPipeline`/`BattleSnapshotMirror`、`UIService`→`UIFormStore`/`UICoverageResolver`、`StageMachineCore`。
- **禁 public 可变字段状态袋**：上下文/实例对象用只读属性或 internal setter＋明确属主；上下文类不得反向引用宿主形成双向耦合。〔反例：`VfxInstance` 10 字段；`SlotAnimContext` 曾 14 个 public 可变字段＋Root 反向引用，现构造注入＋只读读口〕
- **禁把 `GetHashCode` 公式当身份键**（哈希相撞＝静默吞通知）。〔反例：`AnimationPlayer._terminals`〕
- **文件边界由变化原因决定（「一类一文件」已废除）**：一个文件＝**一个内聚职责**，允许 **2～4 个强相关类型**共存（典型：值类型/枚举 + 它的实现 + 它的常量）；接口与其实现**同文件**（除非实现与声明分属不同 asmdef）。唯一分合判据：**两个类型永远一起改 → 同一文件；从不一起改 → 不同文件**。〔反例：为每个小类型单开 20～30 行文件，是把一件内聚的事拆成多处的碎片化，**不算单一职责**〕
- **事件/回调必须上接口端口**，禁 `is 具体类` 突破抽象订阅实现。〔反例：装饰器 `is KcpTransportClient` 订阅 OnError〕
- **同一接口的多实现行为契约一致**（返回 Clone 与暴露内部引用不许混用）。〔反例：`RoomClient.MatchResult` Clone vs `StartGame` 裸引用〕

### 1.7 UI 通路纪律

- **产品 UI 打开/关闭唯一写者是 `UINavigationController`**：流程层、服务类（Feedback/Dialog）、页面逻辑一律经单写者队列，禁直调 `UIService.ShowAsync`。存量多通道是登记债，新代码必须走单写者。
- **UI 控件计时统一走 `UIAnimationClock`**（时停/变速联动），禁自驱 `Update` 用 `Time.unscaledDeltaTime`。〔反例：Countdown〕
- **动效参数一律走 `UIFx` 默认值或表**，页面转场参数收口到同一处，禁内联第三份。〔反例：`FadeSlideTransition` 内联 0.25s/0.2s/40f〕
- **UI 页面接入不动框架**：走生成页面目录（`UIPageCatalog.g.cs`）与构建器扩展点（见 [03](03-领域查询表.md) §10）。

### 1.8 确定性内核纪律

- **改 Sim 内核（`Packages/com.litegame.sim/{Scripts,Systems}`）＝BuildHash 重跑＋L1 全量**；系统顺序 Input→Movement→Shooting→Damage→Cleanup 即确定性契约（`SimStep.cs`）。
- **地图/出生点唯一来源**：`Map/tbmap` 表（烘焙产物）经共享投影 `MapTableProjection` 两端共用，禁另写第二份地图（改布局＝改场景重烘）。
- **客户端与服务端同读同一份 `.bytes` 表**，表值与代码默认值必须一致（L1 表守卫钉住）。
- **R11 房间内核纯度**：`Assets/RoomServer/Core/` 禁 Console/系统时钟/文件 IO/proto/LiteNet；纪律扫描随 L1。
- **R13 数值读口**：机制面禁读静态配置读口上的可变值，数值经实例参数传入（const 豁免）；表行→实例字段的装载在组合根完成。

### 1.9 接线纪律（禁静默半成品）

- **注册进容器的服务必须有生产消费者**，否则不得注册；发现无消费者的功能面：接线或退役，二选一，不许静默留着养 god class。
- **"待接线"半成品必须挂施工进度批次号**（可被追踪），注释只写"待"不算登记。
- **反射访问私有成员取服务＝违规**，一律走 `GameEntry.TakeContainer()` 等公开面。
- **预埋结构（数据先行机制缺席）必须在设计文档声明预期消费批次**，否则不进 checksum/快照这类有对账语义的面。〔反例：`EntityKindTables`〕

### 1.10 序列化资产与目录搬动

- **序列化资产走 pipeline**：场景/Prefab/Material/ScriptableObject/AnimationClip/AnimatorController/Timeline、`Assets/` 下文件/目录的移动改名删除、场景对象操作、工程设置，一律走 unity-pipeline CLI（三档边界见 [说明 15](../说明/15-工具链手册.md) §6）；禁手改序列化文件与 `.meta`，禁复用 GUID。Pipeline 不可达时只允许改纯文本，并在结论里写明"序列化资源未验证"。
- **目录搬动六面同步**：`ScanTargets.cs`（纪律目标）、YooAsset 收集组、`Tests.slnx`/csproj 引用、`.gitignore` 白名单、构建器路径、外部注册面（Windows 计划任务、CI workflow、`toolchain.json` 路径）；搬完跑 `python scripts/toolchain.py check`。
- **新增收集目录**＝collector＋收集组表＋文档三面同批，规划见[资源收集目录专项设计](../设计文档/客户端/内容/资源收集目录专项设计.md)。

### 1.11 注释预算

- **XML 文档注释 ≤4 行**（含 `<summary>`/`<param>`/`</summary>` 标签行）；**非 XML 块注释**（`//`、`/* */`）紧贴声明时：类型 ≤3 行、成员 ≤2 行。方法体内的行内说明不按块计，但一件事只说一句。
- **只写"做什么 + 调用方必须知道的约束"**；设计理由、历史、反例、权衡迁 `Docs/设计文档/`，代码里最多留一句"见《X》§N"。〔2026-11-06 批反例：`IInputService` 类注释 30 行、`ConfigService` 叠两个 `<summary>` 共 23 行，已按本规则压到 4 行〕
- **禁一个类型叠两个 `<summary>`**：XML 文档只取第一个，第二个等于没写，且编译无警告。
- **例外**：生成物（`*.g.cs`、`Generated/`、`*.Generated.cs`、`<auto-generated>` 文件）不适用；`<param>`/`<returns>`/`<exception>`/`<typeparam>` 各一行不计入正文预算；未挂声明的块（文件头、`using`/`namespace`/`#` 之前）不计；`[Obsolete]` 说明可附迁移指引。
- **守卫**：`python scripts/gate/comment-lint.py`（增量，默认 `--base HEAD`；PR 用 `--base origin/main`）；全量普查 `--all --json`。存量按[注释债登记](../审计/客户端/登记/注释债.md)分批清，**只减不增**。
- **动 `Packages/com.litegame.sim` / `com.litegame.net` 的注释也算改源码**：BuildHash 覆盖源文件字节（含注释），清这两处必须同批跑 `toolbox.py build-hash` 并同步两端。

### 1.12 目录平铺预算（改动单元口径）

- **一个改动单元 ≤5 个代码文件**：改动单元＝一个目录（＝一个命名空间），故机械面仍是"该目录直接存放的 `.cs` 计数 ≤5"，但判据变了——问的是"这 5 个文件是不是同一件事"，不是"目录还塞得下几个"。`.cs`/`.proto`/shader/`.asmdef` 计入，`.meta`、`.json` 与美术资源不计；"文件都很小"不构成豁免，已进子目录的文件不重复计。
- **改动单元＝一个"能说出口的意图"＝一个目录＝一个命名空间**：单元总行数 **≤600**；**入口文件唯一且与目录同名**（`Arena/Arena.cs`）；单元之间 **0 个跨单元接口**——直接引用类型，接口只在实际跨 asmdef 或存在第二实现时引入（§1.6）。
- **禁止按技术层拆（仅产品侧改动单元）**：`Assets/LiteGame/**` 下的域/单元目录不得以 `Abstractions/`、`SubModules/`、`Impl/`、`Interfaces/`、`Services/`、`Common/`、`Utils/` 作为目录名，也不得新开 `Core/` 目录——技术层不是变化原因；存量 `Assets/LiteGame/Core/` 按守卫基线棘轮并回单元，本批不搬。
- **上述禁令不适用于三类另有权威的目录**：① 框架四件层目录 `Core/`/`Services/`/`Adapters/`/`Hosting/`（AOT 侧保留，见 §1.14）；② 内核与红线目录 `Packages/com.litegame.net/Core/`、`Packages/com.litegame.sim/`、`Assets/RoomServer/Core/`（R11）；③ `LiteGame.Core` 程序集（阶段 4 前仍存在）。
- **作用域＝客户端代码 + 共享包；AR1 与 AR2 同一作用域**：`Assets/{LiteGame,LiteCodeGen,LiteTesting,Tests}` 与 `Packages/com.litegame.{framework,sim,net,sync}`。`Server/`、根 `Tests/`、`Assets/RoomServer/` **不归本规则管**——AR1（`namespace-path.py` 的 `CODE_ROOTS`）与 AR2（`change-unit.py` 的 `UNIT_ROOTS`）按同一份代码根清单维护；扩面＝两处同批改，再 `--update` 收紧平铺基线。
- **例外**：生成物（`Generated/`、`*.g.cs`、`*.Generated.cs`、`*.Designer.cs`）、随包第三方（`Adapters/kcp2k`）、`obj`/`bin`。
- **与切子包的分工**：[09-分层与命名 §1.1](09-分层与命名.md) 的「文件 >20 或顶层类型 >30」判据回答"要不要新开子包"；本规则回答"一个改动单元里放几个文件、多少行"。未到 20 门槛也须先按 ≤5 收进已有子目录。
- **守卫**：AR2 `scripts/gate/change-unit.py`（改动单元 ≤5 文件 / ≤600 行 / 入口文件唯一且与目录同名 / 0 个跨单元接口；**与本文同批落地**）＋ `python scripts/gate/dir-flat-lint.py`（存量平铺计数，已挂 L1 套件）。存量按[目录平铺债登记](../审计/客户端/登记/目录平铺债.md)棘轮：`--update` 只许收紧，基线回涨直接红；与他人并行开发时用 `--update --shrink-only`——只登记本批已解决的目录、保留他人在途增长（仍红），不用 `--allow-growth` 吞掉。
- **守卫已随规则更新（2026-11-11）**：「`public interface` 必须住 `Abstractions/`」与「跨模块类型必须住 `Abstractions/` 或 `LiteGame.Core`」两条旧约束废除，改由本条「禁技术层目录名」＋「跨模块类型必须显式登记理由」承担；`ModuleInterfaceOwnershipTests`／`CrossModuleContractLocationTests`／`DomainBoundaryTests` 三条守卫已同步，登记与存量豁免只减不增。

### 1.13 路径 = 命名空间

- **代码目录路径与命名空间路径逐段相等，零例外**：`Assets/LiteGame/Battle/Arena/` ↔ `namespace LiteGame.Battle.Arena`；一个目录只有一个命名空间，目录内类型不另写第二命名空间。
- **改目录＝同批改命名空间与 `using`**：目录搬动仍按 §1.10 六面同步，命名空间是同批的第七面。
- **守卫脚本见 `scripts/gate/namespace-path.py`**（与本文同批落地；AR1，棘轮只减不增——存量漂移进基线，新增即红）。
- **已裁决的单一例外（2026-11-11）：`namespace MetaWire` 保持扁平，不按路径对齐。** 该命名空间承载两端共编的 Meta HTTP 线形状（`Packages/com.litegame.shared/Runtime/MetaWire/**`，17 个类型；2026-11-12 P1a 从 `Assets/LiteGame/Modules/Meta/WireSubModule/**` + `Abstractions/Room/JoinTicketInfo.cs` 整体迁出到 UPM 包 `LiteGame.MetaWire`，命名空间与类型名不变，物理路径/程序集归属变更），其边界已由**三个显式登记点**钉住：`Server/MetaServer/MetaServer.csproj`（17 条出树链接）、`Server/RoomServer/RoomServer.csproj`（16 条）、`scripts/codegen/gen-build-hash.py` 的 `META_EXTRA_FILES`（17 条）。把它对齐成目录路径只换取 AR1 计数变小，代价是 33 条 csproj 链接 + 17 条哈希清单同步漂移一次，而该清单刚因一处路径写错「静默漏算」了一个 wire DTO。**AR1 里这 17 条属"有意保留"，不是债，不得当债去修。** 若确要搬动，先补一条守卫使「MetaWire 类型清单 == 两份 csproj 出树链接清单」逐条一致，再谈路径。 **按命名空间判定，不按目录判定**：这 17 个类型同属一个两端共编面，P1a 后同住 `Runtime/MetaWire/`（`JoinTicketInfo.cs` 在包根，其余按 Core/Login/Join/Lobby/Match/Instance 分格）——按目录直觉把它当"待平的客户端平铺面"去动、或按包目录再拆 asmdef，会当场改坏 meta 常量并破两端构建。**迁出后取源面不变**：两份 csproj 出树链接 + `META_EXTRA_FILES` 仍逐条登记，改动这些 DTO 照旧重跑 `toolbox.py build-hash`（只动 meta 常量，`--check-shared` 不变——该源集不进握手闭包）。

### 1.14 AOT/hot 是唯一硬边界

- 热更沿用 HybridCLR（`AOT | hot` 边界见[客户端架构重构演进路线图](../设计文档/架构/客户端架构重构演进路线图.md) §2；热更分界与接入见[热更与内容发布专项设计](../设计文档/客户端/内容/热更与内容发布专项设计.md) §3）。**`AOT | hot` 是唯一的编译期硬边界**：AOT 程序集不得引用 hot 程序集（AR3），AOT 只认 `IHotEntry` 与框架端口。
- **AOT 侧（随包）**＝`LiteFramework`（含原 `Core` / `Services` / `Adapters` / `Hosting`；**时态**：目标形态＝**一个程序集**（内部 `Core`/`Services`/`Adapters`/`Hosting` 四层目录与命名空间；编辑器件 `LiteFramework.Editor` 另计，不计入运行时程序集数）；**阶段 4 程序集合并前，现仍为四件程序集**；**目标吸收 `LiteCodeGen.Runtime`**）＋ `LiteNet` ＋ `LiteGame.Bootstrap`（即引导程序集）＋ `LiteCodeGen.Runtime`（**现役**独立 AOT 件；被 `LiteFramework.Services` 编译期引用；AOT 不能引 hot，故只能落 AOT）。
- **hot 侧（玩家侧热更面）**＝`LiteGame`（产品全域；**目标吸收 `Luban.Tables`**）＋ `LiteSim` ＋ `LiteSync` ＋ `Luban.Tables`（`Assets/GameData/Generated`；**现役**独立 hot 件；表值可热更，见 AGENTS 红线 1 现行口径）。
- **非玩家侧（不参与 AOT|hot 分区）**＝`RoomServer*`、`MetaServer*`、`LiteTesting*`、`LiteCodeGen.Editor`、`DisciplineScanner*`、`ReplayTool`、测试工程、`Unity.Pipeline*`、`MCPForUnity*`。
- **计数口径**：玩家侧运行时＝**6 + `Dev`**（AOT 三件 `LiteFramework` / `LiteNet` / `LiteGame.Bootstrap`；hot 三件 `LiteGame` / `LiteSim` / `LiteSync`；`Dev` 不进发布包、不参与分区）；编辑器程序件 `LiteFramework.Editor` / `LiteGame.Editor` / `LiteCodeGen.Editor` **不打包、不计入运行时程序集数**；现役的 `LiteCodeGen.Runtime`（AOT）与 `Luban.Tables`（hot）待各被吸收，故不计入这 6 件。
- **只检验 AOT → hot 一条边**：AOT → 非玩家侧、非玩家侧 → 任意，都不报。`LiteGame.Adapters.Dev` → `RoomServer.*` 是**设计允许的**（Dev 承载本地服、不进发布包）——AR3 不覆盖 hot → 非玩家侧，该边不报**不属于漏洞**。
- **原有"框架不得引产品""模块不得引适配器""Services 不得引 Adapters"等多条重叠边界作废**，由这一条取代；精确到文件的集合由引用图算出（`ProjectSettings/HybridCLRSettings.asset`），本条只给程序集分区，不抄文件清单。
- **守卫**：AR3 `python scripts/gate/hot-boundary-check.py`（AOT 程序集出现对 hot 程序集的引用即红；三类分区表见脚本 `PARTITION`）。

### 1.15 例外裁决：本轮规则先行

- **例外**：在**架构收敛线**（[客户端架构重构演进路线图](../设计文档/架构/客户端架构重构演进路线图.md) v2.0）覆盖到的规则范围内，本轮**规则先行、代码服从文档**。理由：规则要供 AI 子代理读取并执行；若先改代码，子代理仍按旧规则施工。

### 2.1 动手前

1. **查领域表**：[03 领域查询表](03-领域查询表.md) 定位改动文件与"改完必跑"；查不到的领域先补表再动手。

### 2.2 改动中

- **一个改动一个关注点**：流程接线、数值调参、结构拆分分开；同一提交内不混"顺手重构"与行为变化。
- **同步面逐项过**：改共享源（Sim/协议/生成读码面/源链接共编件）→ BuildHash；改目录 → `ScanTargets.cs`/收集组/csproj/外部注册面；改 UI API 规格（`UIApiSpec.json`）→ `toolbox.py ui-api` 重生成三件（声明/转发/清单）；改表**数值**（`.bytes`）→ 数据面走运行期摘要，两端发布同批（[03](03-领域查询表.md) §9）。
- **自我检查闸门**：要写"必须与 X 一致"的注释 → 停下，改成机制（§1.2）；要加 static 可变字段 → 停下，走注入（§1.3）；要 `Debug.Log` 临时排查 → 带 `[Diag]`＋批次号，当天登记摘除批次（§1.4）。

**人类操作模拟验证**（强制）：凡"用户点得到/按得到"的面（页面按钮、列表行、输入控件、热键、入口编排），真机/Play 验证必须按真实操作路径驱动，禁以结构探针、EditMode 桩或直调 API 冒充"操作过"。手法（编辑器 Play 参考实现，`unity-pipeline`）：①**可点性自检**——对当前界面所有 `Button` 做 `EventSystem.RaycastAll`，命中为空即红；②**操作模拟**——`ExecuteEvents` 派发 pointer click 或按键注入，驱动入口→操作→副作用全链；③**副作用断言**——网络请求（服务端日志/端点）、页面流转（console `[Nav]`）、落库等必须真实发生；④**截图存证**——`capture_game_view` 留档。口径：结论只覆盖实际走到的路径；未走真操作路径的检查不得表述为"可操作/可玩"。反例：页面 Canvas 缺 `GraphicRaycaster` 时，结构探针/EditMode 桩/自动化全绿，首个真点即全灭。

### 2.4 文档回写与登记

- **代码完成后回写**：设计变更回写对应专项设计；批次证据记入[施工进度](../施工进度/README.md)——一线一卷，新批次追加为该卷新章（章号顺延＋章节索引补一行），不新建单文件；跨线新主题才新开卷。
- **设计文档不记进度**：设计文档写完成状态/批次状态即违规（权威＝[`设计文档/README.md`](../设计文档/README.md)）。已内嵌的施工状态剥离为指向施工进度的指针（批次内容先并入进度卷，再剥离）。
- **后批修正前批结论时，在后批章内写"修正前批某结论"，不回改前章**——前章是当时事实。
- **修了质量登记表的条目** → 回写该审计文档的"修复登记"表（状态＋提交号），不删除条目。
- **新发现的质量问题** → 按审计文档格式追加登记（严重度＋`file:line`＋一句话），让债可见。
- **状态只由 git 事实回填**：`已提交 <hash>` 或 `工作区未提交`，禁裸"待提交"（D2 拦）。

### 2.5 提交

- **一个关注点一个提交**：流程接线、数值调参、结构拆分分开；行为变化与纯格式化/重命名分开。
- **生成物与源同批提交**：`BuildHash.g.cs`、proto 生成物、Luban 生成物、UiApi 派生物、`UIPageCatalog.g.cs` 等不留到"下次再生成"；`git status` 里生成物与触发它的源在同一批。
- **文档与代码同批**：§2.4 的设计/进度/审计回写是提交的一部分，不是提交后的补记。
- **声明**：改了 `Tests/**/Baselines/**` → PR 标题/正文或提交信息必须带 `[baseline]`，否则 CI 失败（判据见 [说明 10](../说明/10-测试与门禁.md) §7.3）；临时 `[Diag]` 与摘除批次号不得留在提交里。
- **不入库件不得进暂存**：私钥、`deploy/.env`、测试者 `.conf`、`LocalNotes/`（见 [AGENTS.md](../../AGENTS.md) 云侧红线）。
- **状态回填**：审计/进度状态按提交后的实际 hash 回填，不预填；同一批多次提交时写最后一个覆盖该条目的 hash，并在进度章注明拆分。
