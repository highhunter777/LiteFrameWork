### 1.1 常量与硬编码

- **逻辑中禁魔法数字/魔法字符串**：数值参数进 Luban 表或带名常量；资源路径、场景对象名、协议词表、Lua 注册 key 收口到所在系统的常量类。
- **跨层共享的"同一常量"必须单源，C# 侧是权威**：Lua shim、编辑器工具、Lua 页面引用同一份（经桥接导出或生成），不允许两份字面量并存。动效默认值单源在 `UiFxDefaults`，shim 经占位符注入；新增参数不得再写第三份。〔反例：Pulse/Flash/Slide/Bubble 默认值曾在 `UiFx.cs`、`LuaBehaviourAdapter` shim、`UIMain.lua` 三处并存，`UIWidget.cs:42` 的 0.08 即漏网产物〕
- **生成器与运行时共享常量时，生成器必须引用运行时定义**（同工程源链接或代码生成），禁"注释对齐"。〔反例：`SimTrigTableGenerator.TableSize` 与 `SimTrig.TableSize` 各写一份〕
- **按名解析场景对象必须常量化 + 失败可见**：`GameObject.Find`/`transform.Find` 的路径字面量收口常量，解析失败必须留下诊断，静默 no-op 视为 bug。〔反例：`ProcedureBattle` 6 条场景路径与 `"Aim Camera"` 字符串约定〕
- **新路径字面量禁含中文**（跨平台打包风险）。〔反例：曾用 `"训练场.unity"`，现为 `Assets/Scenes/TrainingGround.unity`；新增路径字面量仍一律禁中文〕

### 1.2 单源与同步面

- **任何"A 与 B 必须一致"的关系必须机制化**：单源引用、代码生成、守卫测试三选一。只靠注释或"记得同步"即违规——评审见到"必须与 X 保持一致"的新注释，应要求改成机制。〔反例：`SimChecksum` 分型表字段清单手抄两份、`SimWorldDiff` 覆盖面漂移，导致 checksum 报警但 diff 报不出原因〕
- **float 位级比较只走 `BitUtil.Equal`**（Sim 确定性唯一入口）；数学只走 `SimMath`/`SimTrig`。
- **新增实体状态字段＝同步链四处一起动**：`CopyTo` / `SimChecksum`（公共＋全量双口径）/ `SnapshotDiffer` / `SnapshotReassembler`，且优先推动进 StateLayer 生成器而非继续手抄。〔反例：Item/Projectile/Zone 分型表未进生成器〕

### 1.3 静态状态与依赖获取

- **禁新增 public static 可变字段/属性**。名义豁免名单封闭（`Log`；`FileSystem`/`ReferencePoolService` 已实例化退役），扩名单须在设计文档登记。静态只读配置快照须走 `ConfigSnapshotService` 式的版本化发布，禁裸 volatile 直赋值双轨。〔反例：`AnimationProfileConfig` 静态快照绕过配置服务；`CollectionPool` 静态池族出了豁免名单〕
- **确定性判定路径（伤害/弹药/移动/命中/checksum）禁读任何静态可变状态——包括 `#if UNITY_EDITOR` 内的**。GM 开关一律显式注入参数对象；不进 checksum 的可变全局＝静默分叉源。〔反例：历史上 `SimTestRules` 六个静态布尔被直读，现经 `ILocalTestHooks` 端口注入〕
- **服务获取统一构造注入/容器 Resolve**；禁反射取私有成员取服务（改名即静默断链）；禁新增静态服务定位器。除公开面外一律走 `GameEntry.TakeContainer()`。〔反例：原 `GmPanel` 反射 `"s_container"` 六区静默失效（历史名；按现行 04 §6.1 应为 `GMPanel`）；`Bridge.Data` 静态定位器是受控存量债〕

### 1.4 错误与日志契约

- **已关闭服务再调用统一抛 `ObjectDisposedException`**。同一层级的姊妹服务必须同契约——不许一个抛、一个警告降级、一个裸奔 KeyNotFound。〔反例：EntityService/SceneService 抛、VfxService 警告、AudioService 无守卫〕
- **程序员错误 fail-fast**（构造期校验、参数越界直接抛）；**内容降级**走 `Log.Warning`＋显式默认值；禁吞异常静默继续。
- **生产日志统一 `Log.*` 门面**；禁在非编辑器生产路径直落 `Debug.Log/LogWarning`。临时诊断必须带 `[Diag]` 前缀＋摘除批次号，批次收口时必须清；热路径禁放周期性 Warning。〔反例：`BattleContext` 曾把七个 `[Diag]` 哨位留在 Tick〕
- **`IModuleStats.Snapshot` 实现约定：实现负责 `into.Clear()` 后填入**（调用方复用 Dictionary 且不清；见接口注释与 DevHUD 消费端）。统计键为展示用短词，同一实现内键语言须自洽（存量中文词表与新英文词表并存，不新增同实现内混用）。

### 1.5 并发与异步

- **锁粒度一致性**：同一对象的状态读写要么全在锁内，要么有单一属主线程，禁混用。〔反例：`SecureEnvelopeRoomTransport` 锁外读改连接状态、锁内 Dispose〕
- **延迟执行按域选择**：按秒延迟走 `GameScheduler`；帧级"下一拍"由调用方在自身帧驱动里排队；`EventBus` 不内置延迟队列，两者不混用。
- **UniTask 延迟/续帧统一经 `UnityAsync` 封装入口**；LiteNet 禁 UniTask 的纪律维持不变。
- **传输层所有权约定写进接口注释并全项目一致**（谁 Dispose 内层）。装饰器与 `RoomClient` 两种现状约定是登记债，新适配器禁止再加第三种。

### 1.6 类与接口设计

- **功能模块高内聚、低耦合**：一个功能的实现（数据、逻辑、装配、平台适配件）必须内聚在同一模块目录内，不得为"分层"把它拆成两处实现、各自演进；跨模块只经端口/契约通信。分层裁决的是能力归属（如纯机制 vs 平台适配），不是功能切分的理由；确因平台依赖必须外置的适配件，只做薄适配、语义仍由模块单源定义。
- **单一职责**；单类 >400 行且多职责，动手前先给拆分方案。现役 god class 清单以审计登记与拆分方案为准；改动这类文件时应顺手收敛自己那一域，禁止继续加职责。
- **拆分口径**：外提的协作件一类一文件、公共 API 不变、行为零变化。已收敛先例：`ProcedureBattle`→`BattleViewRig`（按 04 §6.3 拟改 `BattleViewGroup`，待改名批）、`BattleContext`→`BattleInputPipeline`/`BattleSnapshotMirror`、`UIService`→`UIFormStore`/`UICoverageResolver`、`StageMachineCore`。
- **禁 public 可变字段状态袋**：上下文/实例对象用只读属性或 internal setter＋明确属主；上下文类不得反向引用宿主形成双向耦合。〔反例：`VfxInstance` 10 字段；`SlotAnimContext` 曾 14 个 public 可变字段＋Root 反向引用，现构造注入＋只读读口〕
- **禁把 `GetHashCode` 公式当身份键**（哈希相撞＝静默吞通知）。〔反例：`AnimationPlayer._terminals`〕
- **一类一文件；接口与实现分文件**（同文件需注释豁免理由，如 `ISceneService` 先例）。
- **事件/回调必须上接口端口**，禁 `is 具体类` 突破抽象订阅实现。〔反例：装饰器 `is KcpTransportClient` 订阅 OnError〕
- **同一接口的多实现行为契约一致**（返回 Clone 与暴露内部引用不许混用）。〔反例：`RoomClient.MatchResult` Clone vs `StartGame` 裸引用〕

### 1.7 UI 通路纪律

- **产品 UI 打开/关闭唯一写者是 `UINavigationController`**：流程层、服务类（Feedback/Dialog）、Lua 桥一律经单写者队列，禁直调 `UIService.ShowAsync`。存量多通道是登记债，新代码必须走单写者。
- **UI 控件计时统一走 `UiAnimationClock`**（时停/变速联动），禁自驱 `Update` 用 `Time.unscaledDeltaTime`。〔反例：Countdown〕
- **动效参数一律走 `UiFx` 默认值或表**，页面转场参数收口到同一处，禁内联第三份。〔反例：`FadeSlideTransition` 内联 0.25s/0.2s/40f〕
- **UI 页面接入不动框架**：走生成页面目录（`UiPageCatalog.g.cs`）与构建器扩展点（见 [03](03-领域查询表.md) §10）。

### 1.8 确定性内核纪律

- **改 Sim 内核（`Assets/LiteSim/{Scripts,Systems}`）＝BuildHash 重跑＋L1 全量**；系统顺序 Input→Movement→Shooting→Damage→Cleanup 即确定性契约（`SimStep.cs`）。
- **地图/出生点唯一来源**：`Map/tbmap` 表（烘焙产物）经共享投影 `MapTableProjection` 两端共用，禁另写第二份地图（改布局＝改场景重烘）。
- **客户端与服务端同读同一份 `.bytes` 表**，表值与代码默认值必须一致（L1 表守卫钉住）。
- **R11 房间内核纯度**：`Assets/RoomServer/Core/` 禁 Console/系统时钟/文件 IO/proto/LiteNet；纪律扫描随 L1。
- **R13 数值读口**：机制面禁读静态配置读口上的可变值，数值经实例参数传入（const 豁免）；表行→实例字段的装载在组合根完成。

### 1.9 接线纪律（禁静默半成品）

- **注册进容器的服务必须有生产消费者**，否则不得注册；发现无消费者的功能面：接线或退役，二选一，不许静默留着养 god class。
- **"待接线"半成品必须挂施工进度批次号**（可被追踪），注释只写"待"不算登记。
- **反射访问私有成员取服务＝违规**，一律走 `GameEntry.TakeContainer()` 等公开面。
- **预埋结构（数据先行机制缺席）必须在设计文档声明预期消费批次**，否则不进 checksum/快照这类有对账语义的面。〔反例：`EntityKindTables`〕

### 1.10 序列化资产与目录搬动

- **序列化资产走 pipeline**：场景/Prefab/Material/ScriptableObject/AnimationClip/AnimatorController/Timeline、`Assets/` 下文件/目录的移动改名删除、场景对象操作、工程设置，一律走 unity-pipeline CLI（三档边界见 [说明 15](../说明/15-工具链手册.md) §6）；禁手改序列化文件与 `.meta`，禁复用 GUID。Pipeline 不可达时只允许改纯文本，并在结论里写明"序列化资源未验证"。
- **目录搬动六面同步**：`ScanTargets.cs`（纪律目标）、YooAsset 收集组、`Tests.slnx`/csproj 引用、`.gitignore` 白名单、构建器路径、外部注册面（Windows 计划任务、CI workflow、hook 配置、`toolchain.json` 路径）；搬完跑 `python scripts/toolchain.py check`。
- **新增收集目录**＝collector＋收集组表＋文档三面同批，规划见[资源收集目录专项设计](../设计文档/客户端/内容/资源收集目录专项设计.md)。

## 2. 修改规范（流程）

### 2.1 动手前

1. **查领域表**：[03 领域查询表](03-领域查询表.md) 定位改动文件与"改完必跑"；查不到的领域先补表再动手。
2. **查专项设计**（[设计文档索引](../设计文档/README.md)）：领域设计裁决目标架构，本规范不替代它。
3. **查质量登记**（[审计流程](07-审计与债登记.md)：客户端 `审计/客户端/登记/`，服务端 `审计/服务端/登记/`；服务端旧单体表存量仍有效）：要改的文件里有没有已登记债——同文件小债顺手修（记入批次），禁止新增同型问题（§1 红线）。
4. **查扩展成本**：确认这次变体的多点同步面（BuildHash 源集、ScanTargets、两端装载、C#/Lua shim……），见 [03](03-领域查询表.md) §10.3；漏一处即静默漂移。

### 2.2 改动中

- **一个改动一个关注点**：流程接线、数值调参、结构拆分分开；同一提交内不混"顺手重构"与行为变化。
- **同步面逐项过**：改共享源（Sim/协议/生成读码面/源链接共编件）→ BuildHash；改目录 → `ScanTargets.cs`/收集组/csproj/外部注册面；改 Lua shim 对面 → C# Dispatch 同步（反之亦然）；改表**数值**（`.bytes`）→ 数据面走运行期摘要，两端发布同批（[03](03-领域查询表.md) §9）。
- **自我检查闸门**：要写"必须与 X 一致"的注释 → 停下，改成机制（§1.2）；要加 static 可变字段 → 停下，走注入（§1.3）；要 `Debug.Log` 临时排查 → 带 `[Diag]`＋批次号，当天登记摘除批次（§1.4）。

| 改了真机/Play 里可交互面（按钮/列表/输入/入口编排） | 人类操作模拟验证（下文，强制） |

> 工具形态与失败语义见[生成器工具箱专项设计](../设计文档/架构/生成器工具箱专项设计.md)；统一入口 `python scripts/codegen/toolbox.py <tool> [args...]` 与单脚本直调等价，上表保留红线最小命令形态。

**人类操作模拟验证**（强制）：凡"用户点得到/按得到"的面（页面按钮、列表行、输入控件、热键、入口编排），真机/Play 验证必须按真实操作路径驱动，禁以结构探针、EditMode 桩或直调 API 冒充"操作过"。手法（编辑器 Play 参考实现，`unity-pipeline`）：①**可点性自检**——对当前界面所有 `Button` 做 `EventSystem.RaycastAll`，命中为空即红；②**操作模拟**——`ExecuteEvents` 派发 pointer click 或按键注入，驱动入口→操作→副作用全链；③**副作用断言**——网络请求（服务端日志/端点）、页面流转（console `[Nav]`）、落库等必须真实发生；④**截图存证**——`capture_game_view` 留档。口径：结论只覆盖实际走到的路径；未走真操作路径的检查不得表述为"可操作/可玩"。反例：页面 Canvas 缺 `GraphicRaycaster` 时，结构探针/EditMode 桩/自动化全绿，首个真点即全灭。

### 2.4 文档回写与登记

- **代码完成后回写**：设计变更回写对应专项设计；批次证据记入[施工进度](../施工进度/README.md)——一线一卷，新批次追加为该卷新章（章号顺延＋章节索引补一行），不新建单文件；跨线新主题才新开卷。
- **设计文档不记进度**：设计文档写完成状态/批次状态即违规（权威＝[`设计文档/README.md`](../设计文档/README.md)）。已内嵌的施工状态剥离为指向施工进度的指针（批次内容先并入进度卷，再剥离）。
- **后批修正前批结论时，在后批章内写"修正前批某结论"，不回改前章**——前章是当时事实。
- **修了质量登记表的条目** → 回写该审计文档的"修复登记"表（状态＋提交号），不删除条目。
- **新发现的质量问题** → 按审计文档格式追加登记（严重度＋`file:line`＋一句话），让债可见。
- **状态只由 git 事实回填**：`已提交 <hash>` 或 `工作区未提交`，禁裸"待提交"（D2 拦）。

### 2.5 提交

- **一个关注点一个提交**：流程接线、数值调参、结构拆分分开；行为变化与纯格式化/重命名分开。
- **生成物与源同批提交**：`BuildHash.g.cs`、proto 生成物、Luban 生成物、UiApi 派生物、`UiPageCatalog.g.cs` 等不留到"下次再生成"；`git status` 里生成物与触发它的源在同一批。
- **文档与代码同批**：§2.4 的设计/进度/审计回写是提交的一部分，不是提交后的补记。
- **声明**：改了 `Tests/**/Baselines/**` → PR 标题/正文或提交信息必须带 `[baseline]`，否则 CI 失败（判据见 [说明 10](../说明/10-测试与门禁.md) §7.3）；临时 `[Diag]` 与摘除批次号不得留在提交里。
- **不入库件不得进暂存**：私钥、`deploy/.env`、测试者 `.conf`、`LocalNotes/`（见 [AGENTS.md](../../AGENTS.md) 云侧红线）。
- **状态回填**：审计/进度状态按提交后的实际 hash 回填，不预填；同一批多次提交时写最后一个覆盖该条目的 hash，并在进度章注明拆分。
