## 1. 原则与判据

大型 UI 的返工很少来自「不会做」，而来自五类可预防的失效：美术改了节点名/结构而工程按旧名接线（运行时缺控件）；工程顺手改视觉/字号/间距（美术签收失效，下一轮被改回）；静态文案一半在 prefab、一半在 Lua（语言切换双源冲突）；契约未生成或无 diff（双方以为「看截图就对上了」）；同一 prefab 被两人同时编辑（覆盖、冲突、无法回溯）。本规范用**所有权＋契约＋评审门**把它们前移。

**三条原则**：

1. **一个 prefab，同一时间一个 Owner**：Owner 由页面清单记录；非 Owner 改动需评审。
2. **接口优先于截图**：契约是接口，截图是证据；没有契约不交接。
3. **变更可见**：契约 diff、节点改名、样式令牌变更都必须显式通知/评审，不允许「先合再补」。

**违规判据**：非 Owner 未经评审改同一 prefab；以截图代替契约交接；改名/令牌变更先合再补；同一文本节点双写；两人同时编辑同一 prefab 且无 Owner 记录。

## 2. 角色与责任

### 2.1 角色定义

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| **UI 美术** | 页面布局、视觉层级、切图/九宫格、静态文案 key、文字/颜色样式、暴露控件标记、契约生成、美术角色校验、视觉验收 | Lua/数据/导航、运行时生命周期、性能预算裁决 |
| **UI TA** | 设计令牌、字体、图集、材质/Shader、动效规范、控件模板、性能与资源预算、全量资源校验 | 业务逻辑、页面导航 |
| **客户端 UI 工程** | 页面登记、数据/逻辑/导航接线、契约消费与评审、绑定生成、行为验收、工具实现 | 视觉细节最终裁决、绕过美术直接改视觉 |
| **本地化** | key/文案落库、语言列、复数/占位符规则 | 页面布局、控件命名 |
| **QA** | 设备矩阵、可点性/安全区/长文本/性能验收、缺陷回归 | 视觉设计、逻辑实现 |

> 小团队可一人兼多角色，但**同一页面同一时间仍只设一个 Owner**；兼角色不取消评审门。

### 2.4 能力门槛

- **美术**：能在 Prefab Stage 独立完成页面布局、控件插入、命名/暴露、key、令牌应用、契约生成、增量校验与截图。
- **TA**：能定义令牌/图集/字体/控件模板，读懂校验报告与性能预算。
- **工程**：能读契约、生成/消费绑定、接线、跑全量校验与运行时调试。
- **共同**：理解「prefab 是唯一视觉真相」「同一控件只有一个写者」「契约 diff 是 API diff」。

### 2.5 禁止事项

- 美术不直接改 Lua/表源/运行时 C#。
- 工程不未经评审改视觉、字号、间距、切图、动效参数。
- 任何人不得手改契约/清单/生成代码。
- 不得用「先合再补」替代交接门。
- 不得把模板内部件暴露为页面控件（`Clone_` 条目、模板插槽内部）。
- 不得复制第三方资源到产品目录之外直接引用。

**违规判据**：越过所有权表直接改他人面；手改生成物；以「小改动」为由跳过评审门。

## 3. 页面契约

### 3.1 契约是唯一交接物

`UiPageContract` 是从 prefab ＋ `tbuiform` 行生成的只读接口描述，字段固定为 `page` / `controls[]` / `text[]` / `styles[]` / `templates[]` / `events[]` / `sourceHash`（schemaVersion 现行 `2.0`，生成器 `ui-contract` `1.0`）。

- **美术产出**：视觉、static key、BindNode/BindName、模板使用、样式角色。
- **工程消费**：`controls[]` 作为接线 API；`text[]` 作为静态文案；`templates[]` 作为模板依赖；`sourceHash` 作为基线。
- **CI 消费**：契约 diff、`sourceHash` 漂移、引用越界。
- **静态文案标记**：美术在文本节点挂 `LTextKeyRef`，只填 `Key`（参数/复数/富文本替换归工程动态文案）；运行时在页面打开/语言变更时写入，不重跑 `OnShow`，关闭即退订。
- **截图**只是验收证据，不替代契约。

字段模型与生成规则见[UI 编辑器工具链专项设计 §5](../设计文档/客户端/UI系统/UI编辑器工具链专项设计.md#ch-contract) 与 `Docs/设计文档/客户端/UI系统/UiPageContract.schema.json`。

**违规判据**：未生成契约即交付；以截图/口头确认替代契约；手改契约 JSON；`sourceHash` 与 prefab 不一致仍交接。

### 3.2 契约变更 = API 变更

| 变更 | 判定 | 处理 |
| --- | --- | --- |
| 新增控件/文本/模板 | 向后兼容（次版本） | 工程可直接消费；契约 diff 可见 |
| 删除/改名控件 | 破坏性 | 双方评审；工程先迁移引用；旧名至少保留一个版本别名（如可行） |
| 控件类型变化 | 破坏性 | 双方评审；确认绑定/调用兼容 |
| 静态文案 key 变化 | 破坏性（本地化） | 本地化 ＋ 工程 ＋ 美术三方确认 |
| 纯视觉属性变化 | 非契约 | 美术自测 ＋ 视觉签收；不进 `controls` |
| 层级/锚点变化 | 非契约 | 预览/截图矩阵验证；影响工程接线时升级为契约变更 |

破坏性变更必须在契约 diff 中显式标注；不能靠口头/截图放行。

**违规判据**：破坏性变更无 diff 标注即合并；改名不留迁移期别名也不先迁移引用。

### 3.3 静态文案所有权

- **静态文案**（标题/按钮/标签/说明/空态/固定提示）归美术：节点挂 `LTextKeyRef` 或填 key；工程不在 Lua 写同一节点。
- **动态文案**（数值/房间号/倒计时/账号/玩家名）归工程：走 `SetText`/`SetTextKeyArgs`/绑定。
- **混合文案**归工程；静态部分作为 key/模板参数由工程组合。
- 一个文本节点只能有一个写者；`ui.contract.text-double-write` 规则拦截双写。
- key 命名 `UI.<页面>.<语义>` / `Common.<语义>`；新 key 由美术提案，本地化/工程同批落库。

**违规判据**：同一节点 prefab 与 Lua 双写；静态文案走绑定、动态文案写成 key；新 key 未落库即合并。

### 3.4 控件暴露

- 只暴露逻辑需要操作的控件：按钮、输入、列表、需要显隐/状态/数值的节点。
- 装饰节点、分割线、背景、模板内部件不暴露。
- `BindName` 默认等于节点名；可为 API 稳定性独立命名。节点改名时：默认同批改 `BindName`；独立命名则只改节点名并重生成契约，引用仍按 `BindName`。
- 列表条目内部件不设 `BindName`；行数据按子节点名/字段协议绑定。

**违规判据**：装饰节点/模板内部件出现在 `controls[]`；工程引用契约外的名字（越界引用）。

## 4. 交接流程

### 4.1 主流程

```text
① 美术起页（复制视觉基线，仅 prefab）
   → ② 布局/控件插入/令牌/静态 key
   → ③ 命名 + BindNode 暴露
   → ④ 生成契约 + 增量校验
   → ⑤ 截图矩阵（中/英/长文本/安全区/设备档）
   → ⑥ 工程契约评审 + 页面登记（tbuiform/Lua/C#/hash）
   → ⑦ 工程接线 + 绑定生成 + 引用对账
   → ⑧ 全量校验 + 布局预览/数据档/真链路
   → ⑨ 美术视觉签收 + 工程行为签收
   → ⑩ 合并；契约成为该页基线
```

### 4.2 交接清单

**美术交付**：

- [ ] prefab 自包含、根组件完整、命名合规。
- [ ] 契约已生成且 `sourceHash` 与 prefab 一致。
- [ ] 增量校验全绿（Warning 已解释/登记）。
- [ ] 静态文案全部走 key，无 Lua 双写。
- [ ] 截图矩阵齐全（至少中/英/长文本/安全区）。
- [ ] 控件暴露清单与预期接线一致。
- [ ] 模板/图集/字体依赖通过资源检查。

**工程交付**：

- [ ] 页面登记完成（id/layer/full_screen/lua 路径/prefab 路径）。
- [ ] 绑定生成/hash 记录完成；生成物与 prefab 一致。
- [ ] 引用全部在契约 `controls[]` 子集内。
- [ ] 全量校验通过；PlayMode/Player 可开、可点、可返回。
- [ ] 关闭/复用/语言切换/取消无残留。
- [ ] 行为签收 ＋ 性能预算记录。

### 4.3 评审门

| 门 | 谁 | 判据 |
| --- | --- | --- |
| G1 视觉基线 | 美术 ＋ TA | 布局/令牌/切图/安全区符合规范 |
| G2 契约 | 美术 ＋ 工程 | 字段完整、命名唯一、类型可解析、无越界暴露 |
| G3 接线 | 工程 ＋ 美术 | 引用在契约内、数据流单向、无视觉改动 |
| G4 运行时 | 工程 ＋ QA | 可开/可点/可返回；复用/语言/取消/性能通过 |
| G5 签收 | 美术 ＋ 工程 | 视觉/行为双签；契约基线冻结 |

### 4.4 返工分流

- 视觉/布局/切图/字号/动效 → 美术。
- 数据/逻辑/导航/绑定/生命周期 → 工程。
- 令牌/图集/字体/控件模板/性能 → TA。
- 契约字段争议 → 工程主持、美术确认；以「逻辑是否需要操作该控件」为判据。
- 不以临时豁免合并；先修根因，再补验证。

**违规判据**：跳过 G1–G5 任一门即合并；返工改到非责任方；以临时豁免替代根因修复。

## 5. 变更管理

### 5.1 改名/移动

- 节点改名：默认同批改 `BindName`、契约、Lua/C# 引用点；`BindName` 独立命名时只改节点名并重生成契约。
- 文件/目录移动：同步收集组、场景引用、测试、文档、构建器（走目录搬动同步流程）。
- 模板改名：同步所有实例与契约 `templates[]`；影响面只读列表先行。
- 组件类型替换：视为契约破坏性变更，双方评审。

### 5.2 样式/令牌变更

- 令牌 ID 变更需迁移映射与旧 ID 别名；至少保留一个次版本。
- 令牌值变更影响所有引用页面；TA 需跑漂移报告 ＋ 视觉回归。
- 页面裸值整改：优先令牌化；确需例外则登记 Owner/原因/到期。

### 5.3 版本与基线

- 契约 `schemaVersion` 主.次；主版本不兼容，次版本只追加。
- 每页契约基线随页面版本冻结；破坏性变更需新基线。
- 页面清单记录状态，五态单源为 `Assets/LiteGame/Editor/UiTools/Page/Manifest/UiPageStatus.cs`（迁移表同源，词表见[工具链专项设计 §8.5](../设计文档/客户端/UI系统/UI编辑器工具链专项设计.md#ch-page-manifest)）；状态由工具与评审更新，不靠口头。

| 状态 | 含义 | 允许迁移 |
| --- | --- | --- |
| `Draft` 草案 | 起页已产出 prefab，尚未登记 `tbuiform` | → 评审 / 已登记 |
| `InReview` 评审 | Owner 提交评审，等待工程/TA 过目 | → 草案 / 已登记 / 冻结 |
| `Registered` 已登记 | `tbuiform` 有行、Lua/C# 骨架已建 | → 已接线 / 评审 / 冻结 |
| `Wired` 已接线 | 工程已按契约接线（导航/数据/反馈） | → 冻结 / 已登记 |
| `Frozen` 冻结 | 基线冻结，破坏性变更需新基线 | → 评审（解冻须回评审） |

**违规判据**：改名只改视觉不改引用；令牌 ID 直接删除无别名；破坏性变更不换基线；状态靠口头更新或跳过迁移表。

## 6. 度量

| 指标 | 目标口径 |
| --- | --- |
| 美术独立完成首版 | ≤1 个工作日（熟手 ≤4 小时） |
| 工程接线 | ≤0.5 个工作日 |
| 静态迭代 | <30s（编辑器布局/文案） |
| 运行时状态迭代 | <2min（数据档/真链路看到真实状态） |
| 美术改动导致首开失败 | 连续两周 0 起 |
| 契约漂移/手改 | 0 起 |
| 越界引用（Lua/C# 用契约外名字） | 0 起 |
| 裸样式新增 | 0 起（例外登记除外） |
| 页面首开/复用问题回归 | 0 起 |

度量只用于改进流程，不用于个人考核；数据来自工具报告与缺陷记录，不靠人工估算。
