# 联机动画与根位移专项设计

> 状态：方案草案；根位移烘焙、Sim 执行与足部补偿均未实现
> 版本：0.1
> 更新日期：2026-09-25
> 适用范围：服务器权威状态同步下的角色移动动画、短时动作位移、滑步控制和客户端表现恢复
> Owner：玩法/网络同步（权威位移与协议）；客户端表现（动画烘焙、姿态和足部补偿）；质量工程（回放与设备验收）
> 依赖：[状态同步专项设计](../../networking/状态同步专项设计.md)、[角色状态与动作专项设计](../../gameplay/角色状态与动作专项设计.md)、[动画模块专项设计](动画模块专项设计.md)、[动作与特效专项设计](../../gameplay/动作与特效专项设计.md)

本文细化联机动作的**位移来源、同步时钟和视觉补偿**。玩法事实仍以状态同步和动作专项为准；Animator、Playable 和动画资源不进入 `LiteSim.Core` 或 RoomServer。本文是设计，不表示根位移导出器、动作位移系统或足部 IK 已交付。

## 1. 决策与适用边界

| 动作 | 权威位移来源 | 客户端动画 | 当前预测策略 |
| --- | --- | --- | --- |
| 待机、普通走跑、自由转向 | Sim 输入速度、重力与边界 | 原地动画依实际水平速度调步频；需要时做视觉步幅匹配 | 沿用本地移动预测、远端插值 |
| 冲刺、翻滚、扑跃等短时强编排动作 | 离线烘焙、版本化的逐 tick 根位移，由 Sim 执行 | 同动作帧的姿态与表现标记；不再叠加根位移 | 若归类为技能，沿用现行“不预测技能”规则；要即时预测须单独扩展契约 |
| 受击硬直、击退 | 玩法参数或显式位移数据，按动作规则选其一 | 按权威动作阶段对齐姿态 | 不擅自预测受击结果 |
| 非对局演出 | 演出系统独占绑定 | 可按演出契约使用 Root Motion | 不作为对局角色权威位移 |

不追求所有走跑都用逐帧烘焙位移：方向和速度频繁变化时，速度驱动更适合现有预测与和解。烘焙曲线只用在需要精确轨迹和节奏的有限动作；曲线是**玩法配置**，不是在服务端播放动画的指令。

## 2. 现状和不可越界点

- 当前 [InputSystem](../../../../Assets/LiteSim/Core/Systems/InputSystem.cs) 根据输入写 `Vel.X/Z` 和朝向；[MovementSystem](../../../../Assets/LiteSim/Core/Systems/MovementSystem.cs) 按 `Vel * Dt` 推进 XZ、对 Y 积分重力、钳制地面和地图边界。固定编排见 [SimStep](../../../../Assets/LiteSim/Core/Scripts/SimStep.cs)。当前移动系统**没有静态障碍碰撞**，因此不能承诺根位移在障碍处已正确阻挡。
- [ActionRuntime](../../../../Assets/LiteSim/Core/Scripts/SimCombatRuntime.cs) 已有 `ActionId/StartFrame/Phase` 和内部 `CastToken`；[公共快照](../../../../Assets/LiteSim/Core/Scripts/SimWorldStateSnapshot.cs)含前三项，不含 `CastToken`。这些字段可作为固定帧进度的基础，但不表示动作曲线已接入 Sim；也不足以无条件重建暂停、变速或重复动作实例。
- 现行链路为 60Hz 权威 Sim、初始 30Hz 快照、本地移动预测与和解、远端插值。按[动画模块专项设计](动画模块专项设计.md#8-表现事件恢复与-root-motion)，联机权威根节点只受 Sim/预测呈现控制，表现侧不得通过 Root Motion 或 `OnAnimatorMove` 回写。
- 现行规则仅预测移动和朝向，不预测技能判定。若将冲刺或翻滚视为技能并要求按键后立即位移，需要另行设计可回滚的动作发起、拒绝、碰撞和事件去重；本文不默许技能预测已存在。

## 3. 位移数据契约和制作链

编辑器对**最终导入设置和角色适配后的动作**以 60Hz 采样，产出只读玩法数据；导出时检查原始根轨迹、坐标系、单位、根旋转、片段裁剪和导入选项。服务端不加载 `AnimationClip`、Avatar 或 Animator。动画换骨架、重定向或导入设置改变了轨迹时，必须重新烘焙和校验。

| 字段 | 目标语义 |
| --- | --- |
| `ActionId / MotionVersion` | 与玩法动作唯一绑定；版本、来源资产与生成器版本可追溯 |
| `TickRate / SampleCount` | 固定 60Hz；索引 `i = SimFrame - StartFrame`，有效范围 `[0, SampleCount)`；阶段帧数与样本数一致 |
| `DeltaLocalX / DeltaLocalZ` | 每 tick 的局部平面增量，而不是累计世界坐标；零位移也显式采样 |
| `DeltaYaw / DirectionPolicy` | 有转体需要时显式定义锁定起始方向、逐帧转向或有限输入修正；服务端和客户端一致 |
| `YPolicy` | 默认继续沿用 Sim 重力/地面规则；跃起需要权威 Y 轨迹时另定义碰撞和落地语义，不能把视觉抬升偷写进根节点 |
| `MovementPolicy / CancelPolicy` | 动作期间普通输入位移是禁用、叠加还是有限转向；允许取消的帧与取消后速度归属固定 |
| `ContentDigest` | 对规范化样本、动作帧数和全部影响判定的策略求摘要；在对局准入中两端校验并锁定版本 |

烘焙管线按“采样 -> 数值规范化/必要的量化 -> 校验 -> 生成两端共享产物 -> 摘要 -> 发布”运行。检查 NaN/Inf、非法采样数、越界速度/转角、阶段时长不匹配、重复 ID 和非预期的 Y 位移；对同一资产重复导出必须逐字节一致。若采用量化，单位、舍入规则和计算次序要在 Sim 侧定稿，不得让客户端用原始 float、服务端用另一套四舍五入。玩法时长由动作配置决定，不能被动画裁剪长度反向覆盖。

该产物属于玩法兼容数据，不只放在客户端美术包。发布与对局中途版本冻结遵循[动作与特效专项设计](../../gameplay/动作与特效专项设计.md)和[热更与内容发布专项设计](../content/热更与内容发布专项设计.md)；接入现有 `buildHash`/配置准入时需明确覆盖这份产物。现有 [CombatConfigDigest](../../../../Assets/LiteSim/Core/Scripts/CombatConfigDigest.cs)仅摘要已装载的战斗数值，**不能直接当作根位移产物摘要**。

## 4. 60Hz Sim 执行与同步

目标固定顺序为：读取本帧输入和动作请求 -> 推进权威动作阶段 -> **在同一帧选择唯一的 XZ 位移来源** -> 按起始/逐帧朝向旋转局部增量 -> 地图边界及后续碰撞解算 -> 更新实际位置/速度 -> 其他战斗判定。实现时必须与当前 `SimStep` 的输入、移动和射击顺序共同定稿，确保命中、取消与位移读到的是同一帧定义的位置；不能仅在 `MovementSystem` 后补一段位移。

```text
i = frame - action.StartFrame
delta = RotateYaw(actionDirection, motion[i].deltaLocalXZ)
requestedPosition = currentPosition + delta
actualPosition = ResolveMovement(requestedPosition, mapAndCollisions)
```

- 动作位移生效帧不再叠加 `Vel.X/Z * Dt`，除非动作配置明确规定可叠加且两端同规。动作结束、中断、死亡或传送时切换回普通移动，并定义输入是否保留、速度如何重建；不继续消费剩余样本。
- 实际位置由 Sim 边界/碰撞结果决定。导出曲线是**期望位移**，不是穿透障碍的特权；当前没有静态障碍碰撞时，先限制试点场景或补齐确定性的碰撞解算，不能把视觉侧 Physics 结果回写。
- 固定速度动作可由 `ActionId + StartFrame + 当前帧` 重建索引；暂停、变速、分支、非固定取消窗口则需新增可复制/可序列化的权威进度或阶段锚点。新字段必须同步更新快照差分、checksum、回滚、重连与协议用例。
- 服务端广播**解算后的实际位置**及可公开的动作摘要，不逐帧广播采样数组。客户端本地只预测现有契约允许的移动；扩展动作预测后才能以相同曲线和碰撞规则重放。远端以快照插值定位，以呈现帧和动作摘要采样姿态；迟到快照不从第零帧重播。
- 配置缺失、摘要不匹配或样本不合法：对局准入拒绝或动作配置加载失败，不能在权威侧静默回退成零位移。只有视觉资源缺失可以退化为保底姿态，而不影响 Sim 位移。

## 5. 滑步控制与网络表现

滑步主要来自姿态脚步速度与**实际**位移速度不符、权威修正造成模型突跳、碰撞停住而动画仍前进，以及 Animator 根运动被重复应用。处理次序如下：

1. 普通走跑用解算后的实际水平速度选择姿态和步频，起停有门槛与过渡；只在视觉子节点做受限的步幅修正/脚部锁定，不能改权威根节点。
2. 编排动作按权威动作帧采样姿态，不把 `Animator.deltaPosition` 叠加在 Sim 根节点。受阻后按实际位移调整姿态推进、转为受阻姿态或有限视觉补偿；若动作有命中帧，改姿态速度不得改变玩法生效帧。
3. 本地和解时根节点与表现节点分离：判定继续用修正后的 Sim 位置，视觉误差在有界窗口内衰减；瞬移、复活、越过阈值的大误差直接切换并复位脚锁/偏移。远端姿态随插值呈现帧推进，不盲目按本地壁钟重播动作。
4. 脚部 IK/足锁只解决视觉接触；坡面、台阶、边缘、长时间受阻、变向和低帧率要单独验收。绝对“零滑步”不是可由根位移烘焙保证的承诺。

## 6. 性能、测试与验收

每个动作的数据为有界只读数组，按动作 ID 加载和缓存；Sim 每帧只读取当前样本，不动态解码 Clip 或分配临时对象。首版以 8 人场景、动作频繁打断和目标 Player 记录 Sim 额外耗时、样本内存、稳定帧 GC、动画 CPU/GPU、插值误差与脚部接触滑移。单动作长度、内存上限和足部滑移阈值先在首批真实角色/设备基线中定稿，**未定阈值前不得宣称性能或视觉达标**；既有动画模块的稳定帧框架自有分配目标为 0 B GC/frame。

| 测试层级 | 必测内容 | 通过条件 |
| --- | --- | --- |
| L0 / L2 EditMode | 源资产/导入设置、重复导出、非法样本、缺失配置、阶段和摘要校验 | 两端共享产物逐字节相同；失败定位到动作和采样帧 |
| L1 纯 C# | 逐 tick 位移、方向、边界、取消、死亡、传送、缺席输入、重放及摘要 | 同输入/版本逐帧位置与 checksum 相同；不双重位移 |
| L2 PlayMode | 真实角色走跑、翻滚、冲刺、受阻、坡面、低帧率、混合/中断、脚锁复位 | 视觉根节点不回写 Sim；无重复播放或永久偏移 |
| L3 无头联机 | 跨进程服务器/客户端产物兼容、快照和解、迟到/丢包、重连、版本拒绝 | 权威位置和回放一致；重连进度正确；不重复表现事件 |
| L4 Player/设备 | 8 人动作密集、目标帧率、长稳、屏幕录像和 Profiler | 设备预算与足部滑移阈值经基线评审后达标，无持续内存增长 |

验收前需完成：烘焙格式与数值纪律定稿、动作占用 XZ 的规则、碰撞/受阻策略、内容版本准入、是否扩展动作预测，以及实际角色的脚步接触基线。缺少其中任何一项，先保留普通走跑速度驱动和现行不回写 Root Motion 的边界，不以视觉补偿替代权威规则。
