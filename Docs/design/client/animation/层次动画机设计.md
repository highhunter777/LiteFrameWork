## 0. 为什么重构（问题登记）

2026-09-27~28 的动画线连续批改暴露了驱动层的**结构性问题**：开火形态配对被实现成散布在 `CharacterLocomotionDriver.Tick/SubmitFire/OnFrameEvent` 里的布尔规则集——`s.IsAim` 合成（瞄准位 OR 射击驻留窗 OR 片段在途）、`AimMoving` 迟滞锁存（两分支手动刷新防陈旧）、移动门控（`if (s.AimMoving) return;`）、起跑终止叠加（moving && inFlight → Stop）、`FireStanceHoldSeconds` 驻留计时。每条规则都对，但**它们是同一件事的碎片**：一个隐式的、没有名字的状态机。

枚举登记面（`CharacterAnimationIds` + `AnimationProfile` + `FrameEventAnimationMap` 三处手工同步）在每加一个语义时都要动三个文件——"现在的枚举太麻烦了"（用户原话，2026-09-29）。三表一致性靠测试钉（映射表↔Profile 交叉校验），不靠结构。

**结论**：把隐式状态机升成显式层次状态机，用框架现成的 `HierarchicalStageMachine`（LiteFramework/Fsm，UnityLib 同步件——不是新造轮子）。

## 1. 分层（上层战斗层 / 下层移动层）

```
Combat（根）                        ← 战斗层：决定"正在干什么"
 ├── Idle（待机/腰射待机）
 ├── Firing（开火中：进 Fire 驻留窗）
 ├── Reloading（换弹中——随消费者接入再启用，批B-① 按"不预建无消费者"收缩）
 ├── Hit / Death / Evade（后续消费者接入时启用，批C）
Locomotion（根）                    ← 移动层：决定"腿和基础形态"
 ├── Idle（速度≈0）
 ├── Moving（速度轴 1D 混合 {Idle,Walk,Run}）
 ├── AimIdle（瞄准&静止）
 ├── AimMoving（瞄准&移动：4 向 strafe）
```

- **两台并列单根 HSM，不是一台双根机（v0.2 修正②）**：战斗层与移动层是**两台独立的 `HierarchicalStageMachine` 实例**（每槽各建两台，层间不直接引用——跨层事实由驱动器喂，见 §2）。不能用"一台机两棵根"承载：框架的多根是**互斥平级根**语义——单活动路径、跨根迁移 = 全退全进（LCA=0），设计给"同一时刻只在一个阶段"的流程形态（Launch/Preload/Main/Error）。而战斗层与移动层必须**同时活动**（Firing 叠加在走跑腿上正是上半身混合的本意）——双根机会造成"开火时腿停、跑动时枪收"。战斗层**不占有**移动层的通道，移动层独占 Locomotion 通道。两台机当前均为平面退化形态（无复合态），消费者需要复合结构时再生长；`CombatAnimMachine.Build` 注释"批B-② 移动层入树时长出第二根"随批B-② 修正为"建第二台"。
- **战斗层状态 → 通道映射**（替代 FrameEventAnimationMap 的手写枚举表）：
  - `Firing` → UpperBody 通道播 `AimIdle_Shoot`（Profile 语义绑定不变）
  - `Reloading` → UpperBody 通道播 `Reload`（G2 快照消费面接通时进树）
  - `Hit/Death/Evade` → FullBody 通道（整身接管，先 `Stop(Locomotion)` 的 §8 纪律不变）
- **移动层状态 → 通道映射**：全部落 Locomotion 通道（Blend/Single 由 Profile 定义照旧）。四态中 `Idle`/`Moving` **同形态**（`MoveBlend`，速度轴权重就地连续）——态界只服务诊断直读与转换表，跨越不重提交（见 §5）。
- **Profile 仍是绑定单源**：HSM 只持有**状态 ID**，不持有片段名——`AnimationProfile` 的 id→binding/loop/speed 登记面保留（它解决的是"哪个片段"，HSM 解决的是"什么时候播谁"）。枚举 `CharacterAnimationIds` 从"三处手工同步的词汇表"降为"Profile 登记用的 id 常量"，`FrameEventAnimationMap` 整个废弃（映射=状态机的转换条件，见 §2）。

## 2. 状态事实与转换（谁驱动状态机）

**输入事实**（每渲染帧采集，沿用现驱动器的来源，零新数据面）：
- `IsAiming`（SimView.IsAiming，Sim 权威）
- `Speed` / `MoveDir`（视图帧间位移）
- **`IsMoving` 锁存**——**迟滞公式单源**在 `LocomotionBlendMath`（进 0.6 / 出 0.3 m/s，比较符逐字沿用现锁存式，可直测）；**锁存值由驱动器每帧算**，是**原始速度的纯函数**（不依赖任何一台机的输出）
- 帧事件（Fire/Reload——经 SimView.EventSink 静默门，§8 接缝纪律不变）
- 片段完成终态（backend Tick 返回的 done mask）

**跨层事实的喂序（对拍不变量，v0.2 新增）**：驱动器每帧 **算锁存 → 喂 `CombatCtx.IsMoving` → 战斗层 Tick（窗尽回 Idle 的事务先应用）→ 读战斗层 Current 合成 `CombatFiring` 喂移动层 → 移动层 Tick → 播放器 Tick**。战斗层门控因此吃到**本帧**速度事实（与现驱动器同序）；移动层语境吃到**本帧**战斗层 Current（与现 `s.IsAim` 合成同序）。两层互为输入的循环（门控⇄语境）由"锁存=纯函数+驱动器单点喂"解开——任何一侧不吃陈旧值，公式无双写。

**转换表**（替代现在散布的布尔规则；每条都是既有手工规则的正名）：

| 层 | 从 | 到 | 条件 | 等价的旧补丁 |
| --- | --- | --- | --- | --- |
| 战斗 | Idle | Firing | Fire 事件到达 | SubmitFire 的"已在播不重提" |
| 战斗 | Firing | Firing | Fire 事件到达且驻留窗内 → 重起一轮（2× 速） | 连发重起策略 |
| 战斗 | Firing | Idle | 驻留计时归零（2.0s 常量，批B-① 原形；2026-09-30 曾改与 Sim 侧驻留窗同源派生，随驻留窗口径回退一并还原）且无新事件 | FireStanceHoldSeconds 衰减 |
| 战斗 | Firing | Firing | 移动事实为移动（`IsMoving` 锁存）→ 只停站姿后坐叠加、不退出 Firing（Firing 是移动腰射"持枪步态"配对的载体——退出即失去 AimWalk；Sim 驻留窗已撤销，本行为自 2026-09-30 起为**纯表现语义**） | "移动中不叠加"（原"起跑终止叠加"的退场语义废止） |
| 移动 | Idle | Moving | `IsMoving` 锁存置位 | 锁存本体（原 `SlotAnim.AimMoving` 字段的迁移位——非瞄准期同样刷新，状态成员 ≡ 锁存值） |
| 移动 | Moving | Idle | `IsMoving` 锁存清零 | 同上 |
| 移动 | AimIdle | AimMoving | `IsMoving` 锁存置位 | 迟滞进入（进 0.6） |
| 移动 | AimMoving | AimIdle | `IsMoving` 锁存清零 | 迟滞退出（出 0.3） |
| 移动 | Idle/Moving | AimIdle/AimMoving | `IsAiming ∨ 战斗层=Firing`（形态语境配对，规则收进状态机）——按锁存选目标：置位 → AimMoving、清零 → AimIdle；**AimMoving 时 AimMoveBlend 播放倍率随实际速度缩放（走 1× / 跑 2× 钳制——步频跟脚程，免"走姿配跑速"滑步；2026-09-30 步频同步批）** | IsAim 合成 + 迟滞锁存 + `TrySetBlendSpeed` |
| 移动 | Aim* | Idle/Moving | 退出瞄准且战斗层=Idle——按锁存选目标（置位 → Moving、清零 → Idle） | 形态回落 |

- **迟滞口径（v0.2 裁决③）**：驻留计时归**状态**持有（`FireStanceHold` 在 Firing 态内，批B-① 已落）；**瞄准双阈值迟滞不归态持有**——它被两侧同时消费（战斗层门控战前要、移动层转换要），改由某台机的状态承载会让另一侧吃一帧陈旧值或双写公式。解法=锁存作为**驱动器算的输入事实**（公式单源 `LocomotionBlendMath`），`SlotAnim` 上的散字段（`IsAim`/`AimMoving`）随批B-② 删除；移动层四态与锁存值由同一对阈值保持一致（对拍用例钉）。
- **每槽两台并列单根 HSM**（实例随视图创建销毁，Owner 代次语义由重建保证——同现驱动器）。
- 事件冒泡（⑤）：Hit/Death 从战斗层根拦截帧事件，优先级天然高于 Firing——死亡打断开火不再需要手写顺序（批C）。

## 3. 不动的东西（明确边界）

- `AnimatorAnimationBackend` / `AnimationLayerGraph` / 遮罩自动派生 / `UpperBodyMaskFactory` 排除面——**引擎机构零改动**（已验证的机构保持）。
- `AnimationProfile`/`AnimationDefinition`/Blend 数学（`LocomotionBlendMath`）——绑定与权重数学不动。
- 通道语义（Locomotion/UpperBody/FullBody）与淡化时长、截断策略、节点稳定用例。
- `IFrameEventAnimationConsumer` 接缝与 §8 静默门、合并规则——只换消费者内部实现。
- `[Anim][diag]` 诊断面升级为 HSM 状态直读（`TryGetCurrent` → `Current` 路径），IModuleStats 聚合照旧。

## 5. 风险与对策

- **HSM 是事务式（一帧一事务）**：战斗层高频重入 Firing 依赖"层内重起"不产生跨层事务——Firing 自转（进自己）按"驻留窗内重起"语义处理（态内合并口，不触发 LCA 退出，批B-① 已落）；移动层全部转换为单跳迁移（无多跳需求）。
- **跨层事实循环**（门控⇄语境互为输入）：锁存=原始速度的纯函数、由驱动器单点计算喂两侧（§2 喂序）——任何一侧不吃陈旧值、公式无双写。
- **同形态迟滞跨越不重提交**：Idle↔Moving 同为 `MoveBlend`，跨越只走 `UpdateBlendWeights` 就地调权重——重提交会给通道刷 `Interrupted` + 0.12s 淡化接缝（对拍用例钉死）。
- **确定性与表现层无涉**：HSM 全在 View 侧，不碰 Sim 事实、不进 checksum——回滚重放仍被静默门挡在门外。
- 平面机对拍用例已有（框架 §HSM 文档"flat 机 = 退化形态，两者有对拍用例"）——复用该测试基建。
