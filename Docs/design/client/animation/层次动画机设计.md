## 0. 为什么重构（问题登记）

2026-09-27~28 的动画线连续批改暴露了驱动层的**结构性问题**：开火形态配对被实现成散布在 `CharacterLocomotionDriver.Tick/SubmitFire/OnFrameEvent` 里的布尔规则集——`s.IsAim` 合成（瞄准位 OR 射击驻留窗 OR 片段在途）、`AimMoving` 迟滞锁存（两分支手动刷新防陈旧）、移动门控（`if (s.AimMoving) return;`）、起跑终止叠加（moving && inFlight → Stop）、`FireStanceHoldSeconds` 驻留计时。每条规则都对，但**它们是同一件事的碎片**：一个隐式的、没有名字的状态机。

枚举登记面（`CharacterAnimationIds` + `AnimationProfile` + `FrameEventAnimationMap` 三处手工同步）在每加一个语义时都要动三个文件——"现在的枚举太麻烦了"（用户原话，2026-09-29）。三表一致性靠测试钉（映射表↔Profile 交叉校验），不靠结构。

**结论**：把隐式状态机升成显式层次状态机，用框架现成的 `HierarchicalStageMachine`（LiteFramework/Fsm，UnityLib 同步件——不是新造轮子）。

## 1. 分层（上层战斗层 / 下层移动层）——互斥覆盖，单机双根

```
Combat（复合态，根①）               ← 战斗层（上层）：决定"正在干什么"——激活即覆盖移动层
 ├── AimIdle（瞄准·静止）
 ├── AimMoving（瞄准·移动：4 向 strafe + 步频倍率）
 ├── Firing（站定射击：AimIdle_Shoot 一轮 / 连发重起）
 ├── Reloading（随消费者接入再启用，批C）
 └── Hit / Death / Evade（后续消费者接入时启用，批C）
Locomotion（复合态，根②）            ← 移动层（下层）：默认移动——战斗根不活动时主导
 ├── Idle（速度≈0）
 └── Moving（速度轴 1D 混合 {Idle,Walk,Run}）
```

- **单机双根，互斥覆盖（v0.3 核心语义）**：每槽**一台** `HierarchicalStageMachine`、两棵根树。在战斗根任一态上=覆盖中（移动根整体不活动）；退回移动根=覆盖解除。框架多根=互斥平级根：单活动路径、跨根迁移=全退全进（LCA=0）——正是"覆盖/解除"的语义（设计给"同一时刻只在一个阶段"的流程形态）。**为什么双根重新成立**：v0.2 曾改"两台并列单根"，那是在半身叠加的正交同时活动语义下（腿走跑+上半身后坐）的必然；二次裁决取消半身，同时活动需求不复存在。
- **覆盖的机制面=通道接管（§8 纪律扩展）**：战斗动作全走 **FullBody 通道**（无 Mask 整身覆盖）。**各根自管本根通道**：移动根 OnLeave 收 Locomotion 通道（停 MoveBlend 句柄）、战斗根 OnEnter 播 FullBody；反向同构（战斗根 OnLeave 收 FullBody、移动根 OnEnter 重提交 MoveBlend 按当前速度权重）。HSM 事务序（LCA 下先深→浅退出、再浅→深进入）**结构性保证先停旧通道再开新通道**——同帧无两层写身体，§6 单一写入责任成立。
- **战斗根状态 → 通道映射**（全部 FullBody）：`AimIdle`→`AimIdle`；`AimMoving`→`AimMoveBlend`（4 向混合 + 播放倍率 1×..2× 钳制）；`Firing`→`AimIdle_Shoot`（2× 速）；批C：`Reloading`→`Reload`、`Hit/Death/Evade`→`Hit1/Die1/Evade`。
- **移动根状态 → 通道映射**：`Idle`/`Moving` 同形态 `MoveBlend`（Locomotion 通道，权重就地连续；态界只服务诊断直读与转换表，跨越不重提交）。
- **半身机构（UpperBody 通道）**：**保留不拆**（后端分层混合/AvatarMask/能力位与契约用例零改动），当前生产消费者为 0——未来需要半身叠加时按消费者重新启用。
- **Profile 仍是绑定单源**：HSM 只持有**状态 ID**，不持有片段名——`AnimationProfile` 的 id→binding/loop/speed 登记面保留（它解决的是"哪个片段"，HSM 解决的是"什么时候播谁"）。枚举 `CharacterAnimationIds` 从"三处手工同步的词汇表"降为"Profile 登记用的 id 常量"，`FrameEventAnimationMap` 整个废弃（映射=状态机的转换条件）。批B-② 随通道改绑重新登记（Fire/AimIdle/AimMoveBlend → FullBody；登记数据变、机制不变）。

## 2. 状态事实与转换（谁驱动状态机）

**输入事实**（每渲染帧采集，沿用现驱动器来源，零新数据面；**单机单上下文**——v0.2 的两上下文合一）：
- `IsAiming`（SimView.IsAiming，Sim 权威）
- `Speed` / `MoveDir` / `Rotation`（视图帧间位移与朝向）
- **`IsMoving` 锁存**——迟滞公式单源在 `LocomotionBlendMath`（进 0.6 / 出 0.3 m/s，比较符逐字沿用现锁存式，可直测）；**原始速度的纯函数**，由驱动器每帧算并喂入——战斗根的瞄准移动迟滞（AimIdle↔AimMoving）与射击提交门控（站定才提交）**同吃这一个锁存**，机内无迟滞散字段
- 帧事件（Fire——经 SimView.EventSink 静默门，§8 接缝纪律不变）
- 片段完成终态（backend Tick 返回的 done mask）

**覆盖语境（战斗根活跃判据）**：`IsAiming ∨ 射击窗在`。射击窗**归战斗根复合态持有**（stage 实例 OnUpdate 逐帧递减、Fire 事件刷新；HSM 的 OnUpdate 根→叶传播使复合态计时与子态并存）。**开火态（三次裁决定义）＝射击窗语境**——自开火判定起、最后一次开火后窗长内的整段；开火限速键于此，**不键于"站定射击片段是否在播"**（Firing 态只是语境中的站定射击段——移动腰射的限速不随 Firing→AimMoving 迁移消失）。窗现为 **Sim 权威 + View 同源镜像**（v0.4）：Sim 侧 `EntitySlot.FireStanceFrames`（帧计数，**私有面**——只进全量 checksum，远端开火输入不可重建）在 `ShootingSystem` 开火判定点置窗（与 `FrameEventKind.Fire` 事件**同点**⇒ 两层窗同触发同长度、逐帧一致由构造保证），每逻辑帧统一递减（整数计数 ⇒ 确定性；缺席/空输入帧与死亡实体照常推进）；窗长**单源** `CombatConfig.FireStanceFrames`（影响模拟行为 ⇒ 进 `CombatConfigDigest`），View 侧 `FiringHoldSeconds = FireStanceFrames / TickRate` 派生——**"改窗长只动一处"恢复**，"限速时间=开火态时间"由单源窗长结构性保证。窗尽且无 ADS → 退回移动根；**离开开火态即取消限速**：自然结束＝窗尽，被打断＝打断态落地时在其建立点清窗（死亡不特判——输入已丢弃、窗自然衰减；换弹/回避随批C 落地时**双端同批**补清窗纪律）。该判据即 v0.2 语境配对（aimCtx）的层间化——从"移动层选形态的语境"升格为"**哪一层主导**"。

**转换表**（每条都是既有手工规则的正名）：

| 根 | 从 | 到 | 条件 | 等价的旧补丁 |
| --- | --- | --- | --- | --- |
| 战斗 | AimIdle | AimMoving | `IsMoving` 锁存置位 | 迟滞进入（进 0.6） |
| 战斗 | AimMoving | AimIdle | `IsMoving` 锁存清零 | 迟滞退出（出 0.3） |
| 战斗 | AimIdle | Firing | Fire 事件 ∧ 站定（锁存清零）→ 提交一轮（2× 速） | 首发提交 / 静默后事件重入 |
| 战斗 | Firing | Firing | 事件 ∧ 上一轮已完 → **态内合并口重起**（不迁移）；在播吞 | 连发重起 / 不重提（重提会按第 0 帧并刷终态） |
| 战斗 | Firing | AimMoving | 起跑（锁存置位）→ 停 clip、**窗保持**；腿让 AimMoveBlend 承担 | "起跑只停叠加不退态"（全身化后停的是整段 clip） |
| 战斗 | Firing | AimIdle | clip 完成 ∧ 窗在——**先判窗再维持**（防窗尽帧的一帧闪现） | 播完回落 AimIdle 基础层 |
| 战斗 | Aim* / Firing | 移动根叶 | 语境解除（!IsAiming ∧ 窗尽）→ 按锁存 Request(Idle/Moving) | 窗尽回 Idle + 形态回落 |
| 移动 | Idle | Moving | `IsMoving` 锁存置位 | 锁存本体（原 SlotAnim.AimMoving 迁移位） |
| 移动 | Moving | Idle | `IsMoving` 锁存清零 | 同上 |
| 移动 | Idle/Moving | AimIdle/AimMoving | 瞄准建立（IsAiming）或 Fire 事件开窗——按锁存选目标；移动中事件只开窗（不播站姿射击） | IsAim 合成 + 移动形态视同瞄准态 |
| 移动 | Idle | Firing | 站定 Fire 事件——单跳跨根直接进 Firing | 站定开火提交 |

- **射击提交门控（保持批B-① 语义）**：**站定才提交**——`AimIdle_Shoot` 是站姿片段，整身覆盖会连腿一起定格；移动中开火只续窗（反馈由枪口特效承担；`AimWalk_Shoot` 家族缺资产，债 #5 登记）。
- **迟滞口径（一次裁决③维持）**：锁存=驱动器算的输入事实，公式单源；`SlotAnim` 上的散字段（`IsAim`/`AimMoving`）随批B-② 删除。
- **事件路径**（逻辑帧边界，Tick 之外）：Fire 事件路由到战斗根实例的**态内合并口**（批B-① 模式：续窗 / 在播吞 / 已完重起 / Request 迁移）——不绕过事务语义，不入队跨帧。
- **喂序（单机后简化）**：测速 → 算锁存 → 喂上下文 → 机.Tick（根→叶 OnUpdate，事务帧末应用）→ 播放器 Tick。v0.2 的"跨层事实喂序"（两机互喂的循环论证）随两机合一而消失——窗与门控同机同帧序。

## 3. 不动的东西（明确边界）

- `AnimatorAnimationBackend` / `AnimationLayerGraph` / `ChannelNode` / `ChannelBlendAdvance` / 遮罩机构 / `UpperBodyMaskFactory` 排除面——**引擎机构零改动**（UpperBody 通道当前零消费者，机构与契约用例保留）。
- `AnimationProfile`/`AnimationDefinition`/Blend 数学（`LocomotionBlendMath`）——绑定与权重数学不动（批B-② 只改登记的通道列）。
- 通道语义（Locomotion/UpperBody/FullBody）与淡化时长、截断策略、节点稳定用例。
- `IFrameEventAnimationConsumer` 接缝与 §8 静默门、合并规则——只换消费者内部实现。

## 5. 风险与对策

- **HSM 是事务式（一帧一事务）**：全部转换为单跳 Request（跨根全退全进=覆盖切换）；Firing 连发重起走态内合并口（不迁移、不触发 LCA）——批B-① 先例保持。
- **跨根切换频率**：ADS/射击窗每次翻转=全退全进+Stop/重提交 Locomotion——与今日"瞄准形态切换"**同频同本**（有界尾部/节点稳定用例已覆盖）；切换接缝的 0.12s 淡化观感归真机手测。
- **站定开火的视觉等价假设**：今日上半身叠加只在站定时出现（移动门控），`AimIdle_Shoot` 整身播与"AimIdle 基础+上半身叠加"预期近等价（同包瞄准姿态族）；真机验收归手测，不等价再议腰射专用片段（债 #5）。
- **同形态迟滞跨越不重提交**：Idle↔Moving 同为 `MoveBlend`、AimIdle↔AimMoving 同为瞄准语境内——跨越只走 `UpdateBlendWeights` 就地调权重（重提交会刷 `Interrupted` + 0.12s 淡化接缝），对拍用例钉死。
- **确定性边界（v0.4 修正）**：HSM 全在 View 侧、不碰 Sim 事实；唯一例外是**射击窗的 Sim 侧镜像**（`FireStanceFrames`）——它由开火判定（输入驱动）派生、回放可重建，只进全量 checksum；View 侧动画仍被静默门挡在门外（不播双份）。
- **和解 churn 边界（如实登记）**：`FireStanceFrames` 私有 ⇒ 和解基线早于开火帧时，窗内公共 `Vel` 逐快照纠偏至窗尽（有界 churn ≤ 窗长/次点射；远端视图走快照插值不受影响）。**根治＝协议加列**（`SlotDelta` 带窗计数、只增字段号——远端可重建），首版不做，登记在《角色状态与动作专项设计》§7。
