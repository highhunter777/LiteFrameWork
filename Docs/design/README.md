# 设计文档中心

本目录保存仍然有效的目标架构、专项设计、规范、参考和路线图。执行命令、环境恢复、本地补丁与历史稿不放在这里。

## 1. 权威层级

发生冲突时按以下顺序处理：

1. **当前实现事实**：以代码、版本化配置和可复现测试为准。
2. **总设计**：裁决目标架构、重构顺序和商业验收门槛；架构总设计负责跨域边界，领域总设计在该边界内裁决本领域契约。UI 的唯一领域入口为《UI框架总设计》，U0～U4 路线并入该文，不另维护 UI 路线图。
3. **专项设计/策略选型**：定义单一领域的协议、状态、数据流和实现约束，不得违反总设计。
4. **规范**：定义制作与提交硬规则，违规必须由工具或门禁发现。
5. **参考**：描述 API、映射和使用方式；与代码不一致时修正文档或代码契约。
6. **路线图**：记录交付状态、批次和缺口，不作为“已经实现”的证据。
7. **Archive**：仅用于历史追溯，不参与当前设计裁决。

## 2. 目录职责

| 目录 | 职责 |
| --- | --- |
| `architecture/` | 客户端、服务端跨域总设计，框架先行/业务准入与商业验收门槛 |

## 3. 命名规范

| 类型 | 命名格式 | 使用条件 |
| --- | --- | --- |
| 总设计 | `<领域>总设计.md` | 跨多个模块，能够裁决边界和优先级 |
| 专项设计 | `<能力>专项设计.md` | 单一领域的完整运行设计 |
| 策略选型 | `<主题>策略选型.md` | 比较候选并冻结当前选择 |
| 备选方案 | `<能力>备选方案.md` | 当前不实施、满足触发条件后再启动 |
| 规范 | `<对象>规范.md` | 必须遵守并应进入自动校验的规则 |
| 参考 | `<对象>参考.md` | API、字段、映射或使用查询表 |
| 路线图 | `<领域>演进路线图.md` | 当前状态、批次、依赖和退出条件 |

文件名禁止使用“最终版”“新版”“具体方案”“精简版”“V2最新版”等不可治理后缀。版本、状态和日期写入文档元数据，不写进文件名。

## 5. 维护规则

- 总设计必须写明状态、版本、适用范围、Current/Target 和冲突裁决规则。
- 专项设计必须写明 Owner、依赖、输入输出、失败语义、容量或性能预算和对应测试层级。
- 设计改名或移动时必须在同一变更中更新 `Docs/README.md`、本索引和全部现行引用。
- 已被完整吸收的文档移动到 `Docs/Archive/<date>/`，归档索引写明替代文档。
- 不复制第二份相同设计；跨文档只引用唯一权威来源。
- 目标能力不得描述为当前能力；路线图中的完成状态必须能由代码、测试或发布产物证明。
