## 1. 文档定位与冲突裁决

本文统一《自研框架设计方案》《框架流程说明手册》《框架实施手册》《待办总览》的客户端部分、《测试开发框架总设计》的客户端发布部分，以及当前代码审计结论，作为客户端商业化、通用化和重构工作的第一入口。

发生冲突时按以下顺序裁决：

1. 客户端目标架构、重构顺序、发布门槛和客户端测试门禁以本文为准。
2. 当前行为以代码和自动化测试为准；文档目标不能作为“已经实现”的证据。
3. 测试分类常量、`LiteTesting` API 和 `scripts/test.ps1` 执行契约继续以《测试开发框架总设计》为准；客户端覆盖范围和 Release 硬门禁以本文第 16～18 节为准。
4. UI 领域的生命周期、操作、导航、重构与验收细化到 [UI框架总设计](../client/ui/UI框架总设计.md)，与本文跨域 Scope/内容服务/发布门禁保持一致；制作、API 和工具遵循其配套文档。联机同步算法以《状态同步专项设计》为准，服务端边界以《商业级通用服务端框架总设计》为准。
5. 热更范围、版本/摘要、候选内容、激活恢复和发布验收细化到[热更与内容发布专项设计](../client/content/热更与内容发布专项设计.md)；本文已同步 2026-09-23 裁决，避免专项与总设计互相冲突。
6. 框架先建范围、最小验证样例和正式业务准入按[框架先行建设与业务接入专项设计](框架先行建设与业务接入专项设计.md)实施；C1 为主，必要 C2/U2 与质量基础提前用样例验证，不等于产品关口已完成。
7. 归档文档只用于追溯，不得覆盖本文结论。

本文作出的主要冲突裁决：

- 旧方案“不做作用域容器”只适用于早期根单例装配；商业客户端必须补 Root、Account、Match、Scene、UI 生命周期域。
- 旧里程碑将 Player 资源、热更和内容闭环后置；现改为商业客户端第一阶段硬门槛。
- `AssetService` 静态门面可在迁移期保留兼容入口，但最终所有权必须归 `IContentService` 和显式资源租约。
- Lua/UI 按平台能力与安全窗口发布；Sim 算法、协议语义、安全代码和原生插件走应用/服务端升级。已有 schema/指令集内的玩法参数可双端发布，仅新对局采用，不得局中热替换。
- L2 只有 EditMode 不足以证明客户端可发布；必须增加 PlayMode、Player 构建、真机和故障恢复门禁。

## 2. 目标与商业级定义

“商业级通用客户端框架”必须同时满足：

- **可复制**：干净机器能够从版本库和受控依赖源还原、构建和测试，不依赖个人绝对路径或口头步骤。
- **可发布**：目标平台 Player 能启动、更新、登录、进入主要流程并安全退出。
- **可恢复**：下载中断、资源损坏、登录过期、断线、存档损坏、前后台切换和低内存都有确定策略。
- **可运营**：版本、渠道、灰度、回滚、远程配置、崩溃、日志和性能数据可追踪。
- **可演进**：框架机制、第三方适配器和游戏业务边界明确，可替换资源、网络或脚本实现。
- **可验证**：每个关键承诺都有自动化门禁、性能预算或人工发布证据，不依赖“编辑器里看起来能跑”。

首个商业 Beta 不要求一次完成所有平台和所有 SDK，但必须完整支持一个声明的平台组合、一个内容分发链和一条真实用户主流程。

## 4. 不可违反的架构原则

1. `LiteSim.Core` 和 `LiteNet` 不依赖 Unity、Lua、客户端 Host 或第三方热更运行时。
2. Sim 判定不访问 `Transform`、`Time`、Animator、文件、网络、账号、数据库或 Lua。
3. UI/Lua 不直接操作 Transport、protobuf、SimWorld 或持久化文件，只调用白名单 UseCase/门面。
4. 所有长生命周期对象必须有唯一 Owner；所有跨帧异步必须绑定 CancellationToken。
5. 所有队列、缓存、池、历史、日志和下载重试都有容量、超时和清理策略。
6. 内容激活、配置切换和存档写入必须是事务式的：先验证，后原子提交，失败保留上一可用版本。
7. 客户端输入、时间、奖励和版本声明不作为服务端事实；服务端权威边界不因客户端框架便利而改变。
8. 不使用静态 Service Locator 扩散依赖；静态兼容门面不得拥有不可释放的真实生命周期。
9. 第三方依赖必须版本化、可审计并满足许可证要求；禁止提交个人绝对路径作为团队配置。
10. 新能力先建立契约和失败语义，再实现；关键失败不得静默回退到不兼容默认值。

## 6. ClientHost、生命周期与作用域

### 6.1 ClientHost

`GameEntry` 最终收敛为 Unity 引导适配器，真正的启动与关闭由 `ClientHost` 持有：

```csharp
public interface IClientModule
{
    UniTask InitializeAsync(ClientContext context, CancellationToken ct);
    UniTask ShutdownAsync(CancellationToken ct);
}
```

Host 责任：

- 建立根 CancellationTokenSource 和模块所有权图。
- 按依赖顺序初始化，失败时只关闭已经成功初始化的模块。
- 关闭时逆序执行，单模块失败不得阻断其余模块释放。
- 处理 `OnApplicationPause/Focus/Quit`、低内存、网络可达性变化和平台深链。
- 在关闭前刷新设置、存档、遥测和崩溃前最后日志。
- 使用 `RuntimeInitializeOnLoadMethod(SubsystemRegistration)` 清理静态兼容状态，支持关闭 Domain Reload 的编辑器场景。

### 6.2 作用域

| Scope | 生命周期 | 允许持有 | 退出动作 |
| --- | --- | --- | --- |
| Root | 进程 | Content、日志、平台、全局设置、遥测 | 逆序 Shutdown、静态重置 |
| Account | 登录到登出 | Token、Profile、RemoteConfig、Meta 会话 | 撤销请求、清敏感缓存 |
| Match | 匹配到结算完成 | BattleClient、BattleContext、FrameDriver、输入历史 | 断网、解绑、销毁战斗态 |
| Scene | 场景加载到卸载 | Scene Handle、场景资源、场景服务 | 卸场景、释放资源租约 |
| UI | 实例创建至销毁；每次展示另有子作用域 | 实例持逻辑/Prefab 租约；展示持订阅、临时资源、任务/Tween | 关闭清展示；缓存保实例依赖；销毁才释放长期租约 |

现有 `ServiceContainer` 继续承担 Root 装配，不强行改造成复杂 DI。新增轻量 `ClientScope` 负责 Cancellation、Disposable 和资源租约的 LIFO 释放；Account/Match 等短生命周期依赖不得注册进根容器。

## 7. 启动、主流程与错误恢复

### 7.1 标准流程

```text
Launch
→ Bootstrap          本地日志、平台、内置配置、最小错误 UI
→ Compliance         隐私同意、地区/年龄等可选策略
→ Patch              版本、下载、校验、激活、回滚
→ Preload            ConfigSnapshot、Lua、注册表和公共资源
→ Login              账号与短期凭据
→ Lobby              Profile、房间、活动入口
→ Match              分配、Join Ticket、建 MatchScope
→ Battle             BattleContext、FrameDriver、Sim/View
→ Result             冻结结果、展示、等待权威结算
→ Lobby              销毁 MatchScope 后返回
```

单机产品可以用 OfflineLogin/LocalLobby 替换网络阶段，但不得绕过 Scope、内容版本和错误恢复契约。

每个 Procedure 必须：

- 由状态机拥有独立 CancellationTokenSource，离开阶段立即取消。
- 只创建本阶段 Scope 内对象，不把 Match/Scene/UI 状态泄漏到 Root。
- 定义超时、重试、用户取消、失败目标状态和诊断上下文。
- 只请求状态迁移，不直接递归进入下一个流程。

### 7.2 错误分类

| 类型 | 示例 | 默认动作 |
| --- | --- | --- |
| Transient | DNS、超时、短暂 CDN/网关失败 | 有界退避重试，允许用户取消 |
| Recoverable | 缓存损坏、旧清单、Token 过期 | 清受控缓存、回滚或重新登录 |
| Compatibility | app/content/protocol 不兼容 | 阻止进入，提示更新客户端 |
| Security | 签名失败、票据篡改、重放 | 不重试，清敏感状态并上报 |
| Fatal | 内置资源缺失、初始化不变量破坏 | 导出诊断，安全退出/重启 |

`ProcedureError` 必须升级为 `ErrorRecovery`：提供重试、回滚内容、清缓存、重新登录、离线模式（产品允许时）、导出诊断和退出；不能只写日志后停机。

## 8. 内容更新与资源生命周期

### 8.1 ContentService

用可注入 IContentService 取代静态所有权，YooAsset 作为后端。发布描述/兼容策略、PatchCoordinator、ContentGeneration 和事务存储各有独立职责；完整契约见[热更与内容发布专项设计](../client/content/热更与内容发布专项设计.md)。

```text
内置启动与事务恢复
→ 验证发布描述/兼容性
→ 计划并下载候选
→ 文件、配置与脚本校验
→ 安全窗口激活（持久化 PendingActivation）
→ 健康检查
→ Confirmed / 恢复允许的上一可用版本 / ErrorRecovery
```

必须支持产品声明的 EditorSimulate、Offline、Host/平台模式，以及有界下载、多源切换、续传、空间预检、可信清单与文件验证。签名/能力限制在首次远程激活前完成，不等到 C3 才补。

候选与当前版本隔离；文件提交、运行时激活和健康确认分开记录。保留允许的上一可用版本，断电/杀进程后可从事务记录恢复；回退受安全撤销、App/Bridge/存档和服务端兼容限制，不能无条件回退。健康检查必须覆盖配置、Lua、注册表与关键入口，错误 UI 可达不是新版本健康。

发布描述、签名与版本维度由热更专项维护；私钥不进入客户端或仓库。版本、阶段、下载量、错误码、确认和回退结果接入统一观测。

### 8.2 资源租约

禁止返回无法表达所有权的裸资源作为唯一 API。目标接口返回：

```text
AssetLease<T>       单资源所有权，可 Dispose
SceneLease          场景句柄与资源依赖
ContentScope        一组 Lease 的 LIFO 所有者
SharedLoad<T>       同 generation/location/type 的并发请求合并
```

资源策略：

- Root 只持有真正全局且有预算的资源。
- UI、Scene、Match 的租约进入对应 Scope，退出自动释放；Scope 固定 ContentGeneration，加载与缓存键包含代次，旧使用者不从全局 Current 混取新内容。
- 缓存有字节/数量/时间预算，不以“字典里还在”作为缓存策略。
- 收到低内存事件时，先释放无引用缓存、池冗余和非关键预加载，再决定降级或退场。
- 资源泄漏测试必须比较 Scope 前后 Handle、实例、Bundle 和托管内存，不只调用 `UnloadUnusedAssets` 掩盖问题。

## 9. 配置、版本与热更边界

ConfigService 改为不可变 ConfigSnapshot：候选 bytes/清单验证 → 解析与全表/跨表校验 → 构建只读快照 → 安全窗口发布 → 旧读者退出后释放。失败不能先设置 Tables 或修改 CombatConfig 全局数值。表清单由 schema 生成。

配置发布、版本元组和摘要以[热更专项](../client/content/热更与内容发布专项设计.md)为唯一细化来源：沿用 BuildId/AppVersion/ContentVersion/ConfigSchema/ProtocolVersion/SimVersion/SaveSchema，并补 Release、Bridge 能力、资源构建兼容及玩法/脚本/目录身份。

- 文件完整性按原始字节计算摘要；双端 binary/JSON 的玩法一致性按规范化语义摘要验证，二进制不做换行归一化。
- 现有 buildHash 在迁移期继续严格校验；新版本维度、Join/重连/归档和双端测试完成后才允许代码、玩法数据、表现内容分离发布，不能只上报编译期常量代表热更后的数据。
- 对局/房间固定玩法快照，新旧房间独立持有；CombatConfig 可变静态值迁移为执行上下文依赖。对局内不得切换数值、动作、武器或技能规则。
- Lua、UI、文本、本地化和表现资源按平台策略与生效窗口更新；正式 Lua 首版采用启动或安全窗口整套环境重建。DevReload/UIPatch 是开发工具。
- 已有 schema/指令集内的玩法参数允许双端发布，仅新对局采用；Sim 算法、协议语义、安全代码、原生插件以及旧 Player 不支持的 Bridge/schema 能力走应用/服务端升级。

HybridCLR 或 xLua C# 方法热补丁不作为当前主线前置。确有消费者时单独设计目标程序集、生成/注入、AOT/裁剪、平台许可、资源生命周期和回退；宏或插件存在不代表该能力已交付。

## 10. 网络、会话与重连

### 10.1 分层

```text
MetaClient             HTTPS/JSON + WebSocket，登录、Profile、Lobby、社交
BattleClient           protobuf 业务协议、输入、快照、可靠命令
ReconnectCoordinator   断线检测、票据、重绑、恢复和超时
INetworkTransport      KCP/UDP 或其它传输实现
```

UI 只调用 UseCase/ViewModel，不直接发包。Transport 不解析游戏业务，BattleClient 不管理 UI。

### 10.2 Connect 契约

`ConnectAsync` 必须在以下任一条件完成：Connected、明确 Error、Disconnected、Timeout、Canceled。禁止 Error 后仍无限等待 Connected。

还必须补齐：

- DNS/IPv4/IPv6、网络切换和前后台恢复策略。
- 有界发送/接收队列、最大包、频率限制和背压指标。
- 热路径缓冲池或所有权明确的 Memory，不逐包 `ToArray/new byte[]`。
- 连接代次 generation；旧连接回调不能污染新会话。
- Meta 与 Battle 独立状态和错误码，不能用一个 bool 表达全部网络状态。
- HTTPS/WSS 必须验证证书链；公网 KCP 不能裸奔，须采用经过评审的安全传输或安全信封，提供身份、机密性、完整性、序号和重放窗口，禁止自创密码算法。

### 10.3 重连闭环

```text
Connected
→ SuspectedLost
→ Reconnecting
→ Authenticating
→ Restoring
→ CatchingUp
→ Connected
             └─拒绝/超时→ Failed → Result/Lobby
```

恢复顺序与服务端总设计一致：重绑 PlayerSession → 版本确认 → 公共全量快照 → Match 状态 → 本人私有状态 → 输入/事件水位 → 客户端恢复 ACK → 增量流。

重连必须处理票据一次性消费、重复 Response、旧连接迟到包、事件去重、输入历史裁剪、恢复时 UI 状态和最终超时退场。

## 11. 设置、存档与安全存储

三类数据必须分离：

| 类型 | 示例 | 存储策略 |
| --- | --- | --- |
| Setting | 音量、画质、语言、按键 | 宽容读取、版本迁移、脏写合并 |
| Save | 单机进度、本地缓存、草稿 | Envelope、迁移链、双备份、原子写、CRC/HMAC |
| Secret | Refresh Token、设备密钥 | Keychain/Keystore/平台安全存储，不写普通 JSON |

`SaveEnvelope` 至少包含 `schemaVersion/appVersion/contentVersion/createdAt/payloadHash/payload`。迁移必须逐版本、可重复、失败保留原文件，并覆盖最近两个正式版本升级路径。

设置在设置页关闭、`OnApplicationPause(true)` 和正常退出时 `SaveIfDirty`；应用被系统杀死不能成为唯一持久化时机。

## 12. Lua、UI、场景与表现服务

### 12.1 Lua

- Bridge 继续采用白名单，不导出 ServiceContainer、protobuf、SimWorld 或任意文件/网络 API。
- Release 环境移除调试库和 LuaPanda，限制 `CS/os/io/debug/package.cpath` 等能力。
- Lua 包必须随内容清单签名和版本化；执行异常包含脚本版本、chunk 和受控栈信息。
- 设置内存预算、GC 观测、单帧执行预算和异常熔断；重复错误不得每帧刷屏或卡死主循环。
- DevReload 与正式热更分离；正式环境不允许任意执行调试字符串。候选 Lua 验证不得绑定正式全局 Bridge 或产生业务副作用；跨 env 不复用 LuaTable。指令预算/中断能力需实际验证，异步等待超时不能中断 Lua 死循环。

### 12.2 UI

UI 的 Current/Target、缺陷登记、接口契约、U0～U4 施工顺序及测试矩阵统一见 [UI框架总设计](../client/ui/UI框架总设计.md)。本节保留跨域边界：

- 同一 form 的兼容并发打开共享实际操作，等待者取消与页面取消分开；不同数据不静默覆盖，拒绝/失败有结果，不能返回 null 表示加载中。首次与复用合流，初始化失败回滚。
- UI 生命周期拆分实例作用域与每次展示作用域。Prefab 租约覆盖缓存实例寿命；临时任务/订阅随关闭释放。Covered/Paused、加载中和缓存对象都纳入 ScopeExit/Reload/Shutdown 清理。
- `ShutdownAsync` 幂等取消操作、完成等待者、销毁页面和缓存、释放 Lua/资源引用与 DDoL Root；系统清理不能被页面关闭守卫无限阻断。
- Lua 注册表保存模块/工厂，页面持独立实例，生命周期显式传 self。初始化异常不能吞后宣告打开成功；环境重建不能复用旧 Lua 引用。
- 导航历史与显示栈分离；统一 Go/Back/Replace、Modal、Loading、Error 与 Dialog 结果。输入禁用、射线阻断和焦点分别处理，不能以 blocksRaycasts=false 代替模态遮罩。
- UI 只读 ViewModel；高频数据在 C# 按逻辑帧/快照聚合，视觉按 UIClock/渲染帧推进，Lua 只做低频编排。本地化与导航结果使用独立刷新/通知，不重复 OnShow。
- 本地化、字体 fallback、SafeArea、长文本、输入方式、可访问性和平台返回键进入通用能力。U0 正确性和 U1 所有权先于大规模模板/样式工具建设；Player 资源前置与 C0/C1 同期完成。

### 12.3 Scene、Entity、Audio、VFX

- SceneService 增加操作串行化、重复请求合并、失败回滚和 SceneScope。
- Entity/VFX/UI 池记录 in-use、容量、峰值和泄漏；退出 Match/Scene 后必须回到预算基线。
- Audio 区分音乐、UI、环境和战斗总线，支持焦点丢失、系统中断、混音和全局停止。
- 所有表现服务只消费 Sim/ViewModel 输出，不参与权威判定。

## 13. 可观测性、隐私与远程控制

### 13.1 日志和崩溃

结构化公共字段：

`appVersion/contentVersion/buildHash/sessionId/accountHash/platform/deviceTier/procedure/scene/matchId/errorCode/event/durationMs`。

要求：

- 本地日志按大小轮转，崩溃时保留最近关键事件和流程状态。
- 捕获 Unity 日志、未处理异常、未观察异步异常和原生崩溃平台报告。
- Token、票据、聊天原文、完整账号、设备广告标识和敏感 payload 禁止入日志。
- 上传必须尊重隐私同意、采样、网络和流量策略。

### 13.2 Metrics 与性能事件

最低指标：启动各阶段、Patch 下载/校验、资源加载、场景切换、登录、连接、重连、帧时间、GC、内存、池容量、Lua 内存、UI 打开和异常数。

远程配置/Feature Flag 必须：

- 带 schema、签名、过期时间、默认值和审计记录。
- 只控制预先声明的安全开关和参数，不远程注入代码。
- 失败时使用版本化本地快照，不使用未知空默认。
- Match 开始后冻结影响对局表现或规则的开关。

## 14. 构建、依赖与发布工程

### 14.1 可重复依赖

- `Packages/manifest.json` 和 lock 文件必须纳入版本控制。
- Git 依赖固定 commit，不跟随浮动分支；商业插件记录版本、来源、许可证和校验摘要。
- 付费插件不能再分发时，提供受控制品源或安装校验器；禁止要求从个人目录手工复制后才可构建。
- Unity、JDK、Android SDK/NDK、Xcode、.NET、Python 和生成器版本写入机器可读工具清单。
- 干净环境恢复脚本必须验证缺件并明确失败，不允许带缺依赖继续生成残缺工程。

### 14.2 BuildProfile

每个构建由版本化 Profile 描述：

`environment/channel/platform/backend/architecture/scenes/defines/contentMode/endpoints/signing/stripping/debugSymbols`。

要求：

- Dev、QA、Staging、Production 配置隔离，Secret 不入库。
- Build Settings 不永久混入 Test/Guide 场景；场景列表由 Profile 生成并校验。
- IL2CPP、裁剪、`link.xml`、xLua 生成代码和原生插件在目标平台实际构建验证。
- Player、内容包、Manifest、符号、SBOM、许可证清单和测试报告使用同一 Build ID。
- 发布支持灰度、暂停、回滚和强更；旧 Match/内容版本按兼容矩阵完成生命周期。

## 15. 通用化与版本治理

框架通用化不是把所有游戏功能塞进 Core，而是提供稳定扩展点和可选适配器：

- Core 包只包含跨项目稳定机制，不含本游戏表名、UI ID、场景路径或业务错误码。
- Game.App 通过 Composition Root 注册产品模块；缺少某模块时由 Capability 明确禁用，不放空实现假装成功。
- 内部 UPM 包使用 SemVer、CHANGELOG、升级说明、最低 Unity 版本和兼容矩阵。
- 至少维护一个 Minimal Sample 和一个 Network Sample，验证包不依赖当前项目隐式状态。
- 公共 API 废弃至少跨一个次版本，提供编译期提示和迁移文档。
- 生成器输出必须可重复；同一输入在支持的平台产生相同摘要。
- 登录、支付、推送、归因、客服、公告和平台成就等 SDK 通过可选 Adapter 接入，在隐私同意后按 Capability 初始化；SDK 类型、回调和静态单例不得进入 Core。
- 支付只在客户端发起平台流程，收据必须交服务端校验和幂等发货；客户端结果不作为到账事实。

## 16. 测试开发框架：现状缺口与补足

现有 L0～L4 分层方向正确，但距离商业客户端门禁仍有以下缺口：

| 缺口 | 风险 | 补足 |
| --- | --- | --- |
| L0 未拦截个人绝对包路径、浮动 Git 依赖和许可证缺失 | 干净环境无法还原 | 增加依赖可复制性、lock、Secret、许可证、生成物扫描 |
| L2 主要是编译和 EditMode | 无法证明生命周期、异步和 Player 行为 | 增加 PlayMode 子层和真实启动冒烟 |
| 没有 Player Build/Test Lane | Editor 绿但 IL2CPP、裁剪或原生插件失败 | 自动构建并运行声明平台 Player |
| L3 无 Unity 客户端 Host 联调 | 无头协议通过但客户端装配断裂 | 建立 Unity/Player Client E2E Harness |
| L4 只有设计，没有设备矩阵和执行器 | 性能、热更、后台恢复不可审计 | 建立设备池、预算文件、Profiler 和审批产物 |
| 缺 Patch/Save/生命周期故障注入 | 只测成功路径 | 提供下载、磁盘、损坏、杀进程和网络故障点 |
| 缺资源泄漏断言 | 长玩后内存增长 | 建立 Scope/Handle/对象/内存快照基线 |
| 缺升级兼容测试 | 老用户升级可能丢档或卡启动 | 保留最近正式版本样本，自动执行跨版本升级 |
| 覆盖率和变异测试未落地 | 断言质量无法量化 | 先记录基线，再启用关键模块只升不降和变异门禁 |
| L2 仍可通过变量整体跳过 | Unity 破坏可能进入主分支 | 受影响 PR 强制 L2，Release 一律不可跳过 |

### 17.2 故障注入

测试基础设施必须提供稳定故障点，而不是依赖随机拔网线：

- Content：指定文件损坏、下载到 N%、Manifest 过期、签名错误、CDN 5xx、磁盘空间不足。
- Network：延迟、丢包、乱序、重复、带宽、断网、DNS 失败、IP 切换和旧连接迟到包。
- Storage：读写异常、短写、坏 JSON/bytes、备份损坏、提交前杀进程。
- Lifecycle：每个启动阶段取消、Pause/Resume、低内存、重复初始化和退出超时。
- Backend：401/403/409/429/5xx、Token 过期、协议不兼容、重复命令和幂等重放。

每个故障用例必须断言最终状态、用户可见动作、资源清理和遥测事件，不能只断言“抛了异常”。

### 17.3 性能与泄漏预算

预算放入版本化 `Tests/Budgets/client-performance.json`，按平台和设备档配置。以下作为首个 Beta 默认门槛，项目可收紧；放宽必须有评审和基线证据：

| 指标 | 默认门槛 |
| --- | --- |
| 热启动到可交互 | 中档目标设备 p95 ≤ 3 秒，不含用户主动等待下载 |
| Patch UI 首次可见 | p95 ≤ 2 秒 |
| 60 FPS 对局帧时间 | CPU/GPU p99 各 ≤ 16.67ms，且无持续恶化趋势 |
| 战斗稳定热路径 GC | 0 B/帧；低频分配有事件和预算 |
| UI 主线程 | 常规页面 ≤ 2ms/帧；稳定态 0 B/帧 |
| 重连 | 网络恢复后 p95 ≤ 5 秒完成 Restore |
| Scope 循环 | Match/Scene/UI 100 次后 Handle/实例回到基线，无持续 retained memory 增长 |
| 长稳 | 24 小时无崩溃、无无界增长、无持续帧时退化 |

包体、峰值内存、功耗、温升和下载量必须由产品目标设备矩阵给出具体数值；没有基线时先测量，不伪造统一数字。

### 17.4 设备与升级矩阵

- 每个正式平台至少覆盖最低支持系统、主流中档和当前旗舰档；Android 至少覆盖 ARM64 和声明的 Graphics API。
- Release 使用非 Development、与生产一致的 IL2CPP、裁剪、签名和内容模式。
- 安装测试覆盖全新安装、覆盖安装、上一正式版升级、回滚限制、剩余空间不足和系统杀进程。
- WebGL、iOS、主机平台只有在产品声明支持时进入硬门禁；未声明的平台不得宣传为已支持。

### 17.5 覆盖率、变异与不稳定治理

- 关键状态机、版本兼容、签名验证、存档迁移、支付/库存和重连分支必须 100% 场景覆盖。
- Core 和纯逻辑变更行覆盖率初始门槛 80%，记录模块基线后只升不降。
- 对校验器、幂等、权限、版本和回滚算法运行变异测试；只统计覆盖率不足以证明断言有效。
- `Quarantine` 必须有缺陷、Owner 和不超过 7 天的到期日；Release 不得包含 P0/P1 隔离测试。
- PR 禁止自动重试掩盖失败；只有确认基础设施故障后才允许重跑整个 Lane。

失败产物至少包含：

- Build ID、Git SHA、App/Content/Config/Protocol 版本和依赖锁摘要。
- Lane/Profile/平台/设备、测试 ID、种子、首次失败阶段和退出码。
- 脱敏日志、截图/视频（适用时）、Profiler/Memory 快照和网络条件。
- Player、符号、Manifest、SBOM、许可证和测试报告之间的关联索引。

发布证据必须可从 Release 记录下载，不能只留在某台自托管机器的本地目录。

## 22. 禁止的重构方式

- 禁止大爆炸式重写 Core、Sim、协议后再补测试。
- 禁止把目标设计直接标记为“已完成”，或用接口/空实现伪装能力存在。
- 禁止把 Match、Scene、UI、Token 或下载任务放进永久根单例。
- 禁止继续增加不可重置的静态服务和 `.Forget()` 异步根任务。
- 禁止用 `Resources.Load`、裸 AssetBundle、直接文件路径绕过 ContentService。
- 禁止立即释放 Handle 后把裸对象交给未知生命周期的消费者。
- 禁止客户端自行热更 Sim/协议以绕过版本兼容和服务端发布。
- 禁止自创加密算法、把签名私钥/Secret 放进客户端或仓库。
- 禁止通过自动重试、`UnloadUnusedAssets` 或强制 GC 掩盖不稳定和泄漏。
- 禁止 Release 跳过 L2/Player/真机门禁，或只用 Editor 结果宣称平台支持。
- 禁止为了“通用”把游戏业务、支付、社交和所有平台 SDK 塞进 Core。

## 23. 完成定义

每个客户端框架项只有同时满足以下条件才算完成：

1. Current/Target 状态已更新，代码、文档和版本清单一致。
2. Owner、Scope、取消、超时、失败状态和释放顺序明确。
3. 正常、边界、非法输入、取消、失败恢复和升级路径有对应测试。
4. 日志、指标和错误码能定位失败，敏感数据已脱敏。
5. 资源、队列、缓存、池、历史和重试有显式预算。
6. 相关 L0/L1/L2/L3 全绿；影响 Player、平台或性能的改动同时通过 L4 对应门禁。
7. Build/Profile/Content/Config/Protocol/Save 兼容关系和回滚方式已记录。
8. 没有新增个人路径、未锁依赖、手工隐式步骤或第二套事实来源。
