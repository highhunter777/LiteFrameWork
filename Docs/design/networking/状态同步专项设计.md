# 状态同步专项设计

> 当前联机主路线：3D 俯视角、float、服务器权威、客户端移动预测、快照和解、远端插值、服务器回溯命中。帧同步只是独立预案，见《帧同步备选方案》。
> 状态：现行专项设计
> 版本：1.1
> 更新日期：2026-09-23
> 适用范围：客户端预测、服务器权威、快照、和解、插值和回溯
> 维护责任：网络同步

## 1. 不可让步的原则

1. `LiteSim.Core` 不引用 Unity、LiteFramework、Lua、网络或 IO。
2. `Step(state, input)` 是可重放的固定顺序函数；不得依赖 Dictionary 遍历、动态订阅、隐藏静态状态或可变 dt。
3. `View → Sim` 只有输入和读取；View 不回写位置、血量、伤害、库存或技能判定。
4. 服务器是战斗事实唯一来源；客户端预测只为手感，权威快照负责纠正。
5. 协议单源为 protobuf；框架网络层只提供字节管道，不认识帧号和房间语义。

## 2. 程序集和拓扑

```text
LiteSim.Core  ── 纯 C# Sim、固定布局、系统、快照、回滚
LiteNet       ── protobuf、KCP 双通道、RoomClient、协议纯函数
LiteSim.View  ── Unity 镜像/插值/输入/相机/VFX
LiteGame      ── 流程、Bridge、UI、Lua、BattleService
RoomServer    ── .NET 权威 Sim、广播、回溯、重连、归档
```

客户端战斗链路：`Input → LiteNet → RoomServer AuthSim → StateSnapshot → Rollback/SimView`。

## 3. 数值与布局

- 逻辑帧率 60Hz，`dt = 1/60`；快照初始 30Hz。
- 状态同步使用 float；超越函数通过生成查表，基础算术遵守 IEEE 纪律。
- `SimWorldState` 使用固定容量数组：`EntitySlot[]`、`AliveBitmap`、`Globals`、`CustomData` 和明确的 Weapon/Action/Status/Match 状态数组。
- 快照、checksum、回滚、重连必须覆盖所有影响判定的字段；帧内命令和帧事件不进快照，消费后清空。
- 实体 Id = 版本 + 槽位，禁止 swap-remove；遍历顺序固定。

## 4. Sim 系统顺序

```text
Input/边沿 → CharacterState/Movement/Aim
→ Weapon 装备/冷却/弹药
→ Action/Skill 阶段
→ Hitscan/Projectile
→ Status Tick
→ Damage/Heal/Resource 命令轮次
→ Death/Respawn/Score/Loot
→ Cleanup
```

同帧请求按 `EntityId` 升序。系统不使用通用事件中心，使用固定 `CommandBuffer` 和 `FrameEventBuffer`。

## 5. 协议

### 5.1 输入

`InputFrame` 包含 `EntityId/MoveX/MoveZ/AimX/AimZ/Buttons`，追加 `selected_weapon_slot/target_entity_id/action_seq`。按钮位覆盖 Fire、Reload、Switch、Skill1–3、Pickup、UseItem。

- Move/Aim/Fire/Skill：不可靠包 + 最近 4 帧冗余。
- 一次性 Pickup/Use/Drop：可靠命令，带 commandId。
- 服务端覆盖 EntityId，校验帧号、按钮、向量长度、频率和 seq 窗口。

### 5.2 快照分层

> **状态：前三层已交付（Sync-P0，2026-09-22，代码 `3839dac`）**——`PublicStateSnapshot`→`SlotDelta` 公共战斗面（含护盾/公开状态/动作摘要）、`MatchStateSnapshot`→`StateSnapshot.match`、`PrivateStateSnapshot`→`PrivateStateDelta`（只发本人）均已上线并随重连按序恢复；`CombatEvent` 层按 P1 战斗闭环落地（P0 未实现事实事件通道）。和解口径同步定案：线上 checksum 为公共可重建口径（`SimChecksum.ComputePublicChecksum`），私有面不进比对。[施工记录](../../施工进度/同步契约P0.md)。

原缺口（历史记录，现已修复）：旧协议不能把 `CustomData/Globals` 的变化自动恢复，因此必须显式增加：

- `PublicStateSnapshot`：可见实体的位置、速度、朝向、HP、护盾、公开状态、动作摘要。
- `MatchStateSnapshot`：阶段、倒计时、比分、回合和胜者。
- `PrivateStateSnapshot`：仅本人可见的弹药、技能 CD、资源、局内背包、私有状态。
- `CombatEvent`：Fire/Hit/Cast/Death/Respawn/Pickup 等事实，按 `frame + eventSeq` 去重。

重连顺序：公共全量 → 比赛状态 → 本人私有状态 → 输入历史（已落地）。所有新字段同步修改 `SnapshotCodec/Differ/Reassembler`、`CopyTo`、checksum 和协议测试——该纪律已被布局/校验/往返用例钉死，新增状态仍必须遵守。

## 6. 预测、和解和插值

### 6.1 客户端预测

- 预测移动和朝向；开火、技能、命中、拾取、奖励不预测。
- `InputHistory` 保存最近输入；权威快照到达后在对应帧校验，差异触发回滚重放。
- 回滚重放清空帧事件；`silenceUntilFrame` 防止特效、音效、震屏重复。

### 6.2 View

- 本地玩家跟预测位置；远端使用前后快照插值。
- 和解时本地误差衰减，远端必要时 snap；复活/传送允许硬切。
- 开火反馈可立即播放，但命中/受击/死亡只由状态差分或服务器帧事件触发。

## 7. 命中和延迟补偿

- hitscan 使用服务器快照环回溯到开火者视角帧；回溯窗口 clamp 到 `[当前帧-LagCompHistory, 当前帧]`。
- 回溯只读目标位置，不推进世界、不消费随机数；命中结论回写当前帧命令缓冲。
- 投射物作为 Sim 实体随快照推进，不走 hitscan 回溯。
- 客户端不自行决定命中和伤害。

## 8. RoomServer

- 每房间单线程 AuthSim，MVP 单循环；缺席输入使用空输入。
- 60Hz Step，30Hz 增量快照，AOI 只影响广播不影响判定。
- 每连接有发送队列上限；超限按降快照率、收缩 AOI、丢低优先级实体降级。
- Join 目标校验身份票据、房间 Protocol/Sim/Gameplay 契约和签名的 MatchStartSnapshot；RoomServer 不查 Profile 数据库。版本迁移前保留现有 buildHash 严格检查，新增维度按[热更专项](../client/content/热更与内容发布专项设计.md)补协议、准入和双端测试，不据本文宣称已上线。
- 结算只输出签名 `RewardDelta`，交给 ProfileService 幂等落库。

## 9. 重连和归档

- 重连票据一次性、短时有效；服务端返回公共/私有快照和输入历史。
- 归档至少包含 matchId、seed、Build/Protocol/Sim 身份、可找回原 ConfigSnapshot 的 ID 与完整 GameplayDigest、最终 checksum、输入历史和结算摘要；迁移期继续保留 buildHash。
- 对局固定配置和版本依赖，重连必须恢复原房间版本；发布新数据不能替换局中快照。新旧房间并存与内容准入遵循热更专项。
- 归档用于复查和反作弊，不作为客户端权威数据源。

## 11. 红线和验收

- 不把玩法判定放 View/Lua；不让 UI 直接发战斗包。
- 不把局外库存、聊天、公会完整状态放进战斗快照。
- 8 人 3 分钟稳定；150ms RTT、10% 丢包可收敛；重连 5 秒内恢复；重复输入不得重复伤害或奖励。
