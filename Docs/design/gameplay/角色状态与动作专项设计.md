# 角色状态与动作专项设计

> 状态：现行专项设计
> 版本：1.1
> 更新日期：2026-09-22
> 适用范围：角色 Sim 状态、输入控制、网络映射和表现状态
> 维护责任：角色与表现

## 1. 三层边界

| 层 | 职责 | 禁止 |
|---|---|---|
| Sim | 移动、朝向、动作阶段、状态效果、战斗判定 | Unity/Lua/框架引用 |
| 控制器/网络 | 采集设备意图、帧对齐、输入校验、发送 | 直接改 Transform 或权威状态 |
| View | 镜像、动画、特效、音效、相机、HUD | 回写 Sim 判定 |

## 2. 状态模型

- `ActionState`：`ActionId/StartFrame/Phase/SourceId`，阶段为 `None/Windup/Active/Recovery`。
- 每实体一个主动作槽；技能、冲刺、交互、死亡/复活可进入；移动、瞄准、连发射击不进入。
- `StatusSlot`：固定数量的 `EffectId/EndFrame/Param`；眩晕、护盾、无敌等限时状态住 Sim。
- 仲裁优先级：死亡 → 状态压制 → 主动作 → 移动/瞄准 → 表现过渡。

## 3. 输入三件

1. `IIntentSource`：键鼠和触屏输出相同的 Move/Aim/Buttons。
2. 上下文门：UI/菜单打开时输出零战斗意图。
3. 帧边界门：渲染帧只刷新待用意图，逻辑帧消费一次；追帧不产生额外输入。

服务器重新绑定 EntityId，并校验移动/瞄准向量、帧号、按钮白名单、动作频率和 `action_seq`。

## 4. 动作和武器的协作

- 连发 Fire 每帧由 `WeaponSystem` 处理，不占主动作槽。
- Reload/Switch 若有前后摇，使用 `category=reload/equip` 的 ActionState 参与仲裁。
- `ActionSlots.TryOccupy/Release` 统一处理冲刺、技能、交互和换弹冲突；同帧按优先级和 EntityId 决定。

## 5. View 驱动

角色动画的 Profile、CharacterAnimationDriver、播放器与后端按[动画模块专项设计](../client/animation/动画模块专项设计.md)实施。本文负责角色事实与输入边界；播放时钟、打断结果、资源和池化契约由动画专项维护。

- Animator 参数只由 Sim 快照/事件推导，单向写入；值不变不重复写。
- 本地相机跟预测位置，和解期间跟表现位置；远端插值。
- 开火枪口反馈可立即播；命中、受击、死亡和技能结果只由权威事件触发。
- `silenceUntilFrame` 防回滚重放重复特效、音效和震屏。

## 6. 验收

- UI 打开时角色不动；追帧输入次数准确；非法按钮被拒绝。
- 动作前摇/判定/后摇、状态持续、回滚重放两端一致。
- 本地移动无明显延迟，远端不抖，和解不重复播事件。
