# 动作与特效专项设计

> 状态：现行专项设计
> 版本：1.3
> 更新日期：2026-09-23
> 适用范围：ActionSystem、动作表现、世界空间 VFX 和预算
> 维护责任：战斗表现

## 1. ActionSystem

动作系统覆盖有前摇/持续/后摇的离散动作：技能、冲刺、蓄力、交互、死亡/复活；移动、瞄准、连发射击属于连续系统，不直接进入动作时序。

- 每实体一个主动作槽。
- `ActionState` 记录 id、起始帧、阶段和来源。
- 中断规则、优先级、消耗和效果由 Luban 表驱动。
- Timeline 只负责编辑和导出；Sim 只执行有限效果指令，不执行任意 Lua/MonoBehaviour。
- 联机判定走 Sim；表现轨由 View 序列执行器消费。

动画播放的 Profile/Driver/后端、时钟、句柄、终态和资源所有权遵循[动画模块专项设计](../client/animation/动画模块专项设计.md)。本文继续维护 Sim 动作规则、VFX 与 Timeline 制作/导出；动画结束或视觉标记不决定玩法生效。

## 2. VFX 服务

VFX 是表现服务，不是玩法系统：不保存判定状态、不修改 Sim、不调用音频服务。

```csharp
IVFXService.Play(defId, attach, follow, scale)
IVFXService.Stop(handle)
IVFXService.StopAll(attach)
```

内部负责 YooAsset 加载、Prefab 池化、挂点跟随、自动回收和基础预算；触发时机由 View 观察状态差分/帧事件决定。

## 3. 联机规则

- 回滚期间由 `silenceUntilFrame` 防重复播放。
- 特效不能携带命中、伤害、碰撞等事实。
- UI 动效走 `UiFx`，音频走独立 AudioService。
- 首版只做同屏数量上限和低端机降级；跨特效优先级/抢占后置。

## 4. 验收

播放/停止/跟随/回收正确；池化无异常实例增长；超预算按配置降级；回滚和重连不重复播关键事件。


## 5. Timeline 编辑与导出（从 UI 工具专项迁入）

> 状态：目标设计；已有运行时服务不代表编辑器/导出器已实现。
> Owner：玩法工具 / 战斗表现；依赖：游戏业务总设计、Luban 数值契约、序列执行器与绑定资源名册。

原 UI 工具专项中的时间轴内容在此维护，UI 总设计只引用此处。时间轴工具不阻塞 UI 生命周期、资源与输入修复。

### 5.1 编辑器与轨道

使用项目已引用的 Unity Timeline 编辑时序，Animator/Animation Track 承担骨骼和属性动画。新增范围是必要的自定义轨/Clip、导出器和验证器，不另造时间轴画布，不把估算代码行数当作交付承诺。

| 内容 | 承载与产物 |
| --- | --- |
| 判定/动作窗口、位移与效果时间点 | 自定义 Track/Clip；导出为 Sim 认可的有限、整数帧指令 |
| 特效/音效/震屏/飘字 | 表现 Track/Clip；引用受控名册/id，导出给 View 序列执行器 |
| 骨骼/属性动画 | 内置 Animation Track/Animator，资源按内容服务加载 |
| 编辑预览/非权威通知 | Signal 或受控事件轨；不能把任意脚本回调导入 Sim |

导出时使用当前业务主线 60Hz：`frame = round(seconds * 60)`，要求 `abs(seconds * 60 - frame) < 1e-4`。精度不满足即拒绝，不静默吸附改变判定时间；负帧、越界与非有限数值同时拒绝。

### 5.2 单源与数据流

沿用游戏业务总设计的 `tb_action/tb_action_num` 与版本化生成链。旧 UI 工具稿提出的额外 `tb_timeline.tracks` 紧凑串不自动成为新运行协议；若既有 Action 结构无法承载，先修改玩法数据契约和两端验证，再确定生成载体。

每个字段只有一个可写来源：`tb_action_num` 已声明的前摇/生效/后摇、冷却等数值和时间字段仍由表维护，Timeline 将其作为只读参考；Timeline 自有表现时间点/轨道结构由 TimelineAsset 维护并导出。两处发生重叠时校验失败，不允许策划改表、工具又从旧时间轴覆盖。决定将某个字段改为导出字段时，须在配置 schema 标明生成归属并取消手工写入源。

导出通过菜单/CI 显式执行，保存时可做增量验证；多资产导出使用内容 hash，重复执行无变化。输出写入暂存区、全部校验通过后发布，不在失败时留下半套表/生成物。玩法 schema/指令产物进入玩法兼容摘要，资源名册与生成版本进入对应发布身份；迁移期保留 buildHash 严格门禁，拆分及双端发布遵循[热更专项](../client/content/热更与内容发布专项设计.md)。

### 5.3 验证矩阵

每类至少一个负例：秒到帧对齐；时间点在合法范围；特效/动画/状态/数值 key 存在；必填参数完整；按动作类型校验窗口/冷却/取消关系；不允许的同帧同类冲突；数值表与时间轴单源对账。冷却是否覆盖整个动作窗口由动作规则决定，不能用一条固定大小关系误拒合法技能。

L1 验证纯导出数据/整数帧规则，L2 验证 Timeline 资产与引用/导出一致性，战斗用例验证两端读取同一结果。编辑器预览成功不能代替 Sim 指令与 View 重播/去重测试。

### 5.4 运行与热生效

- 联机动作由导出数据 + Sim/View 执行器消费，不让 PlayableDirector 执行权威判定；表现按快照/和解对齐，用项目的事件/代次去重规则避免重复特效。
- 非对局演出可直接使用 PlayableDirector，但同样具有 Scope 所有权、停止与资源释放路径。
- 对局内禁止热替换参与 Sim 的表和规则；新内容下一局采用。对局上下文持有一致的配置快照，不跨局缓存失效 Tables 引用。
- 配置重载采用候选加载/校验 → 发布 → 通知 → 放行新对局，失败保留当前可用版本。已有 schema/指令集内的数据允许双端发布，新旧房间各持不可变快照；新增指令语义走代码升级。旧稿“先清可用缓存再重建”废止，事务与恢复细节遵循热更专项。
- Lua DevReload、内容发布和 Action 配置采用不同生命周期入口，协调者在安全窗口编排，不互相伪装成同一重载按钮。
