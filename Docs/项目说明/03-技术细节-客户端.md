# 03 · 技术细节：客户端

> 客户端 = 宿主与装配（`Assets/LiteGame/App`）+ 框架（`Assets/LiteFramework`）+ 框架侧域层（`Assets/LiteClient/{Runtime,Adapters}`）+ 产品 UI（`Assets/LiteGame/UI`）+ 表现（`Assets/LiteView`）。
> 设计契约以 [客户端总设计](../设计文档/architecture/商业级通用客户端框架总设计.md)、[UI 框架总设计](../设计文档/client/ui/UI框架总设计.md)、[动画模块专项设计](../设计文档/client/animation/动画模块专项设计.md)、[热更与内容发布专项设计](../设计文档/client/content/热更与内容发布专项设计.md) 为准；本文只讲机制怎么落地。

## 1. 装配、容器与作用域

| 件 | 位置 | 机制 |
|---|---|---|
| `ClientHost` | `LiteFramework/Scripts/Async` | 宿主：按序初始化模块、聚合产物、**逆序关闭**、失败只回滚已成功部分（注册序=初始化序=关闭逆序） |
| `IClientModule` + `ClientContext` | `LiteGame/App/Bootstrap/*Module.cs` | 模块只经 `Put/Require` 交换产物（同型唯一、编译期可见）——**不用字典做服务定位**，装配错误显性失败 |
| `ServiceContainer` | `LiteFramework/Scripts/Core/DI` | `Seal()` 之后只读；自动发现 `ITickable`（帧驱动）与 `IModuleStats`（DevHUD 诊断面） |
| `AppLifetime` | `LiteFramework/Scripts/Unity/App` | Unity 平台桥：Pause/Focus/LowMemory/Quit + 优雅关闭（刷新钩子 → 逆序模块关闭 → 根 Scope 释放） |
| `ClientScope` | `LiteFramework/Scripts/Core/Hosting` | 层级所有权：**Root → Account → Match → Scene → UI 五层** Scope 树（根/账号/对局/场景/界面）；关闭即级联释放租约，**关闭序与创建序相反** |
| 框架内核（`Core`，零 Unity 依赖） | `LiteFramework/Scripts/Core` | 事件中心（`EventCenter`＋`EventChannel<T>`：优先级派发/延迟派发/有界队列/发布拦截链）、命令中心（`CommandCenter`：类型化意图注册-执行-结果，排队/异步/拦截器/撤销重做）、三机体状态机（`StageMachine`/`PreemptiveStageMachine`/`HierarchicalStageMachine`＋`PreemptiveHierarchicalStageMachine`，迁移表 `TransitionTable`、快照 `Capture`/`Restore`）、对象池（`ObjectPool<T>`/`ReferencePool`/`CollectionPool`）、`FileSys`（IO 唯一门面）、`SafeCall`/`SubscriptionBag`、`Localization*`、`GameClock`。**凡带 UniTask 的件都在 `Async/` 另立程序集**（`ClientHost`、`PatchCoordinator`、`SharedLoadCoordinator`、`IContentService` 端口）——`Core` 是 S2 契约层，义务是零第三方实现依赖 |

装配红线：**注册顺序即依赖图**（见 [02 §1.2](02-总体流程.md)）；对局期不再注册 Tickable——对局由**阶段生命周期**（`ProcedureBattle.OnUpdate`）驱动，天然随离场停止。

## 2. 时钟与暂停

| 概念 | 实现 | 谁消费 |
|---|---|---|
| `WorldClock` / `UIClock` / `SystemWallClock` | `LiteFramework/Scripts/Core/Clock/GameClock.cs`，`ClocksModule` 装配 | 逻辑调度（`LogicScheduler`）、时间轴（`TimelineRunner`）、DOTween Manual 轨（`UiAnimationClock.DotweenUiClockDriver`） |
| 暂停 / 变速 | `GameClock.Tick`：`ScaledDelta = Paused ? 0 : realDelta × TimeScale`（单帧 delta 上限钳制） | 同上（**写 `Paused` 的只有开发态 `DebugTuner`**） |
| 全局纪律 | Unity `Time.timeScale` **恒为 1**；`GameEntry.Update` 统一喂 `Time.unscaledDeltaTime` | —— |

**现状约定（重要）**：流程机与对局推进**不消费** `ScaledDelta` —— `StageMachine` 自身是 `ITickable`（被 `GameEntry.Update` 直接喂 unscaled delta），`RollbackSim`/`FrameDriver` 用的是传入的真实帧间隔。因此**把 WorldClock 置暂停只冻结走 `IGameClock` 的消费者，不冻结流程与对局推进**；若要"真冻结对局"，需要在流程/对局侧一并裁决（属设计决策，本文不擅自定义）。

## 3. UI 与 Lua

- **UIService**（`Assets/LiteGame/UI`）：壳件 `UIForm` 生命周期（**七态**：`Loading`/`Active`/`Covered`/`Paused`/`Closing`/`Recycled`/`Disposed`，枚举见 `UIFormState.cs`）+ 模态栈（最顶模态优先 Back、射线遮蔽）+ 输入锁职责分离；每个 form 一条**缓存策略**（`DestroyOnClose` / LRU 预算 / `Resident` 不参与淘汰）。
  - **语义层固定四项**：`GroupNames = { Bottom, Window, Top, System }`（索引即 `tbuiform.layer` 列；**无 Modal/Loading 层**）；缓存默认预算 `DefaultCacheBudget = 16`。
  - **prefab 加载口必填**：构造参数 `loadPrefab` 为 null 直接抛——生产绑 `ContentPrefabLease`（`AssetLease<GameObject>` 的 UI 适配），测试绑 `UIPrefabLeases.Unowned`（Release 为 no-op）。
  - 模态/Back 目标已抽为独立子域 `UIModalStack`（壳经其 `IUIFormQuery` 窄口转发，公共 API 不变）。
- **焦点**：`UIFocusCoordinator`（纯簿记类，非 MonoBehaviour）——焦点事实单源＝EventSystem 当前选择；遮盖/暂停时保存并清选择、恢复时**不抢占**；打开时聚焦首个可交互 `Selectable`；`Tick()` 轮询 `UiInput.BackPressedThisFrame()`（**桌面先行口径＝ESC**）。
- **输入底座**：`UiInput.EnsureEventSystem()` 幂等建位 `[UIEventSystem]`（EventSystem + `InputSystemUIInputModule.AssignDefaultActions()`）——属输入基础设施而非视觉结构，故在 `VisualConstructionScanner` 例外表登记。
- **默认策略**：`InstantTransition`（**零动效**，通用 UI 层不硬依赖 DOTween 适配器；生产装配显式注入 `FadeSlideTransition`）、`DefaultLayerStrategy`、`DefaultPopInterceptor`（全放行）。
- **导航**：`UINavigationController` 是**单写者**——`GoAsync/ReplaceAsync/BackAsync` 串行执行、队列有上限（`DefaultQueueCapacity=8`）、排队等待超时（`DefaultOpenTimeoutSeconds=10s`）、排队期可取消；UI 页面打开必须走导航（不直调 `ShowAsync`）。
- **Lua 页面**：`Assets/LiteGame/Lua/main.lua` require `UI.UIMain`（真页面），经 `LuaBehaviourAdapter` 挂到 prefab；控件与页面 API 见 [UI控件LuaAPI参考](../设计文档/client/ui/UI控件LuaAPI参考.md)。
  - **装配三段**：`UiShellModule` 建三注册表（`UiLuaRegistry`/`ContentLuaRegistry`/`StrategyLuaRegistry`，各自 `kind` 仅用于报错文案）→ `ContainerModule` 注入 `RegistryFiller` 给 `ProcedurePreload` → 启动期填表（五步序：Lua 预载 → `Init` env 执行 `main.lua` → 填表 → 报告统一判定 → 放行；**任一失败即 fail-fast 阻断进 Main**）。
  - **填充语义**：键为全路径字符串（`"UI.UIMain"`），值为 `LuaTable`；空路径行跳过且不计 Total；失败三分类——`路径非法`/`未注册(配置漏配)`/`注册失败(lua 异常)`。另有 `LuaKeys` 生成常量（**仅 2 个**：`UI.UIMain`/`Content.DemoEntry`）做编译期已知键的兜底校验。
  - **运行期增量重填**：`LuaRegistryRefillService`（`IModuleStats`，HUD 名 `LuaRefill`）**不重建 env**——打标 `MarkLogicStale` → 重预载 → 清 Bridge 的 Lua 缓存 → 清 require 缓存 → 三注册表 `Clear` → 同一条 `RegistryFiller` 重填 → `ApplyStaleLogic` 换表。与 Editor 期 `DevReload`（重建 env 的"重锤"）分工明确。
  - **`Generation` 只作读数不作判据**：`LuaRegistry<T>.Generation` 在每次 `Fill` 都递增（抖动），界面失效一律以 `UIService` 的显式打标为准。
  - **白名单纪律**：`Bridge` 只导出 `data`/`ui`/`content` 三个门面，`ILuaRegistry` 与玩法系统一律不导出；但**这三个门面当前在 `.lua` 侧零调用**，现有脚本只经 `self.ui` 受控面操作控件。
  - **未接线件**：`Lua/LuaPanda.lua`（第三方调试器）与 `Lua/Core/eventer.lua`（Lua 局部信号器）均已放置但无消费方。
- **模板与控件库**：`Assets/UI/Screens`（界面）、`Assets/UI/Widgets`（控件库，收集组 `UIWidgets`）；可用控件含虚拟列表 `VirtualList`（窗口复用/有界节点）、Toast、Dialog、ProgressBar、StarRating 等。
- **本地化/反馈面**：`LText`（语言服务 + 控件/Lua 面，切语言自动刷新已绑定文本）、`DialogService`（合并/互斥组/优先级）、`FeedbackService`（Loading 遮罩/Toast/错误弹窗统一出口，System 层 form，视觉单一来源）。
- **动效**：`UiFx` 原语（DOTween）+ `UiAnimationClock`（Manual 轨接 UIClock，暂停即停）+ 转场策略（`MotionOutcome`/`MotionPlayback`：区分"播完/被取消"，取消必须**先复位再降级**）。
- **生成物**：`LiteCodeGen`（UI/Lua 绑定代码生成），界面行由配置表 `tbuiform` 投影（`Assets/GameData/Config`），模板名与 location 对齐。

> 现状提醒：主流程**当前不打开** `UIMain`（`ProcedureMain` 里的打开调用被注释掉），可玩的 UI 面主要由 PlayMode 用例与冒烟标记覆盖；正式主菜单入口归 U2/G3。

### 3.1 控件库与投影层现状（2026-10-10 代码核对）

- **`UIFormCatalog`（`App/`）**：懒加载投影 `tbuiform` → `UIFormInfo`，仅 2 个方法（`Get`/`Reload`）。**`CacheStrategy` 字段在 `Reload()` 中未被赋值**，恒为枚举默认值 `Lru`——即 `UICacheStrategy` 的 `Resident`（常驻不淘汰）与 `DestroyOnClose`（关即销毁）两个枚举值**当前无配置来源、不可达**。表结构补列前，这两种缓存策略是**未兑现的目标**。
- **`UI/Widgets/` 32 件**：被 `UIBindIndex` 实际接线的只有 7 类——`ProgressBar`/`HpBar`/`Countdown`/`Toast`/`UIBubble`/`FlyTextPool`/`UIWidget`（后者覆盖 `StateButton`/`RedDot` 的可交互）；被服务层接线的有 `UIDialog`（`DialogService`）、`LoadingMask`（`FeedbackService`）、`VirtualList`（`ListScreen.prefab`/`SimSandbox`）。其余 `AvatarFrame`/`GuideHighlight`/`UIEventRelay`/`UISliderWrap`/`UIToggleWrap`/`UIDropdownWrap`/`UIInputFieldWrap`/`SimpleListView`/`AnimatedImage`/`StarRating`/`Stepper`/`BottomNav`/`TabGroup`/`SafeAreaReceiver`/`CountText` **无生产消费者**（仅控件模板 prefab、`UIDemoPage` 一页全展与测试）——不能宣称已接入业务。
- **红点链三件未接通**：`RedDotRegistry` 在 `UiShellModule` 建实例并 `context.Put`，但**C# 侧无任何 `Evaluate` 调用点**；`RedDot`/`RedDotTree` 只在 `UIDemoPage` 里被 new，且**未接入 `UIBindIndex`**（无 `BindRedDot` 受控口）。红点在 Lua 侧的 G4 入口同样是目标。
- **`BindLocale` 未接线**：语言服务唯一的生产消费口是 `UIBindIndex.BindLocale`，而**装配链无调用点**——因此 `SetTextKey`/`SetTextKeyPlural` 系列在真实界面上会抛（详见 [UI控件LuaAPI参考](../设计文档/client/ui/UI控件LuaAPI参考.md) §3 当前限制）。
- **转场编排层**：`UITransitionRunner`（`Transition/` 5 件）**不注册 `ITickable`**，由 `UIService` 在自身 Tick 帧末转发——避免双驱动，同时让界面 `OnUpdate` 内发起的请求同帧帧末可被推进。超时兜底 2s，队列容量 1，重复请求同一 Incoming 忽略并计数。
- **转场策略两实现、装配注入真实现**：`InstantTransition`（`UI/DefaultStrategies.cs`，零 DOTween 依赖，是 `UIService` 默认值）vs `FadeSlideTransition`（`UI/Anim/`，真实动效）；`UiShellModule` **显式注入 `FadeSlideTransition`**。不传 = 页面瞬时切换（功能正确、无动效）。

| `VfxService` | 编排方消费**静默门放行的帧事件** | 句柄制播放、按挂点隔离 StopAll、预算与回收、关闭面真取消 |

### 5.1 对局表现驱动（`Assets/LiteGame/App/Presentation/`，11 件）

纯 View 层——只读 Sim 事实（预测态/公共快照），**禁回写 Sim**；跨域一律由 `ProcedureBattle` 编排接线，各自 `Tick()` 不互调。

| 件 | 消费 | 关键口径 |
|---|---|---|
| `HitFeedbackDispatcher` | `SimView.EventSink` **并列订阅** | 帧事件 → `HitFeedbackContext`（槽位/命中点世界位/**本地角色**）→ 按注册序转发 `IHitFeedbackConsumer`；**不做本地过滤**（过滤归消费者，特效/音效对旁观同样可见） |
| `BattleDamageNumberDriver` | Hit/Crit | 只显本地造成/承受；**锚定受击点**（不随实体移动）；同屏预算 **24**，超限淘汰最旧并**记日志**；合并键含爆头档（爆头/普通各并各的） |
| `BattleImpactFxDriver` | Hit/Crit 且 `Caused` | 受击点世界位 `fx_impact_enemy`；爆头放大 **1.35** |
| `BattleMuzzleFlashDriver` | Fire | 武器挂点跟随 `fx_muzzle_flash`（缩放 1）；灰盒无挂点静默退化；**远端开火光待公共开火信号** |
| `BattleLaserDriver` | 射击语境 | 束挂武器 `Muzzle` 挂点、`useWorldSpace=false`；端点＝**逻辑枪口→瞄准点三维弹道**经 `SimRaycast` 截停（与子弹同终点） |
| `BattleCrosshairDriver` | 鼠标屏幕点 | Hip/Ads 双形态（`SimView.IsAiming`）；画布**无 `GraphicRaycaster`**；被拦/未建 → 藏准心**还系统光标** |
| `BattleHudDriver` | 预测态 | 场景 `/Battle HUD/Panel`；HP 文本+`fillAmount`、弹匣、换弹标签；**未装备显示 `--`**；技能栏为静态占位（技能系统未做）；值变化才重写 |
| `AutoHeadshotRig`／`BattleHeadshotDebugDrawer` | 测试模式诊断 | 前者**替换**输入源：锁最近非自身活体、AimPoint 压头部带中心、持续开火；**近于 2.5 m 跳过**（避免朝天打空）。后者画服务端判定几何（灰柱/黄下沿/红上沿，圆 20 段），只画活体 |

> 三个诊断件（`AutoHeadshotRig`/`BattleHeadshotDebugDrawer`/`LocalServerTransport` 哨位）与 GM 面板、测试模式开关同属开发三宏件，**release 整体剥离**。

### 5.2 测试模式与 GM 面板（开发面）

- **开关单一描述表** `TestModeOptions`（**8 个**）：`Startup` 组 3（免死/传送/冻结，进房由场景 `DebugTuner` 快照）＋ `Live` 组 **5**（无限子弹/激光/伤害数字/自动爆头/爆头可视化，GM 面板现场开合即时生效）；另 `BotCount`（int）不在开关表。面板渲染、运行时快照、`DebugTuner` 初值三处均经该表——**新增开关只改这张表**。
- **GM 面板**（菜单 `LiteGame/测试/GM 面板`，EditorWindow）：六大区（测试模式/命令与审计/运行状态/表查询/场景服务/产物核对），Play 中 0.5s 刷新、命令区 1s 刷新。命令区只执行**无参**命令（带参标注"需专面板"），走权限门→拦截器→审计全链；审计环最近 **32** 条。**当前实际注册的 GM 命令只有 1 条**（`GmResetClockCommand`，重置时钟）。
- 爆头区实时调：面板与 `HeadHitLineTuner` 共用同一导出口径；面板滑杆写 `HeadHitLineDevOverride`/`HeadshotRadiusDevOverride`（`-1`＝复位），判定与可视化同读 `*Live`；定型才导出 `HeadBake.g.cs`。
