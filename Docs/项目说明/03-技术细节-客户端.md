## 1. 设计目标：一句话与五条硬约束

一句话：**一个跑在"服务器权威（Server-Authoritative）＋客户端预测（Client-Side Prediction）"确定性对战模型上的 Unity 客户端，框架能力（宿主/作用域/内容/UI）压在同一条真实业务链上验证。**

五条硬约束（hard constraints）与各自的设计回答——本章后面每一节都是这五条的展开：

| # | 硬约束 | 设计回答 | 守卫（guard） |
|---|---|---|---|
| 1 | 判定必须两端逐位一致 | 判定代码单源共编（`LiteSim.Core`，客户端/服务端宿主/dotnet 测试三处编译）；客户端侧表现只读判定 | BuildHash 握手（version handshake）、R11 纯化扫描 |
| 2 | 服务器权威，客户端只预测连续位 | `BattleContext` 持 Sim 与上行，命中/死亡只认权威快照，公共校验和解（reconciliation on public checksum） | 公共/全量 checksum 双口径 |
| 3 | 生命周期不能靠自觉 | 五层作用域树（scoped lifetime tree）＋租约（lease）＋级联释放；模块注册序＝依赖图（dependency graph） | 装配期预检、LIFO 释放用例 |
| 4 | 多入口竞争是事故源 | 单写者（Single-Writer）决策面——导航、时钟暂停、系统光标、房间状态各只有一个写者 | 导航队列化、具名拦截源 |
| 5 | 表现永远不能欺骗判定 | 表现域只读 Sim 与事件、禁回写；权威事实（authoritative facts）优先于预测 | 事件静默门、公共事实读源 |

**结构篇 · 程序由什么组成**

## 2. 程序形态：一个组合根与它的产物流

客户端程序的骨架是**一个组合根（Composition Root）**——唯一知道全部服务如何拼装的地方，没有第二个入口：

```text
Boot.unity
  └─ GameEntry（唯一 MonoBehaviour 引导适配器（bootstrap adapter），ExecutionOrder -1000，幂等守卫）
       ├─ ClientHost（启动/关闭持有者，纯 C#，不依赖 UnityEngine——L1 可用假事件测完整启动/关闭/回滚）
       ├─ AppLifetime（平台抽象层（platform abstraction）：唯一把 Pause/Focus/LowMemory/Quit 翻译成宿主订阅的桥；
       │   退出是"意图（quit intent）"，由流程放行）
       └─ 11 个 IClientModule：注册序 = 初始化序 = 关闭逆序
```

### 2.1 模块链与产物流

模块间不共享内部状态，只经 `ClientContext.Put/Require` 交换**类型化产物**（typed products；同型唯一、缺产物启动期即抛）——模块初始化链（bootstrap sequence）就是依赖图（dependency graph）本身：

| # | 模块 | Put 进上下文的产物 |
|---|---|---|
| ① | `PlatformInfrastructureModule` | 本地持久化 + 日志设施（先于一切 IO，后续任何失败都有处留证） |
| ② | `ContentModule` | `IContentService`（租约来源）、`ActivationTransactionStore`（启动恢复决策）、`PatchRunner`/`PatchCoordinator`、`AssetsHealthProbe` |
| ③ | `SettingsModule` | `SettingService` + `GameSettings`（UI/音频注册时就要读偏好） |
| ④ | `ClocksModule` | World/UI 双轨时钟 + `EventCenter`（事件总线，event bus） |
| ⑤ | `SchedulersModule` | `GameTimelineRunner`（时间轴，依赖 ④） |
| ⑥ | `LuaHostModule` | `LuaComponent`（XLua 宿主，同 GameObject 组件） |
| ⑦ | `ConfigModule` | `ConfigService`（表字节经 ② 的租约通道装载） |
| ⑧ | `UiServiceModule` | UI/Lua/策略三注册表、`RedDotRegistry`、`UIService`、`UINavigationController` |
| ⑨ | `PresentationModule` | 租约缓存、实体服务、`AudioService`、`VfxService`、主相机（⑩ 做瞄准解算要用） |
| ⑩ | `InputModule` | `IInputService`（设备源驻留） |
| ⑪ | `ContainerModule` | 消费以上全部 → 容器 + 流程机（见 2.2） |

### 2.2 装配末段：`ContainerModule` 收敛什么

`ContainerModule` 是装配的**单一入口（Single Point of Entry）**——读完这一个文件就知道客户端有什么服务。它按五组收敛：

1. **引擎服务键**：`ISceneService`（对局场景组进出场）、`IMainThreadDispatcher`（主线程派发器，后台完成切回主线程）、DOTween 时钟驱动、配置/注册表的**别名注册（alias registration）**——接口键与具体键指向同一实例、`IMapProvider`（判定图投影（projection）——两端同代码同数据）。
2. **命令与调试**：`CommandCenter`——命令模式（Command Pattern：类型化意图、排队/异步派发、撤销/重做（undo/redo）、拦截器（interceptor）、权限门（permission gate）、审计踪迹（audit trail，环形缓冲 32 条））；具体键 + `ICommandCenter` 接口键指向**同一实例**；GM 场景命令、弱网预设命令、`DebugKernel` 只在开发三宏内装配。
3. **会话与联机**：`MetaDeployConfig` 三源快照（命令行 > 包内烙入 > 默认，单次读取）；玩法摘要**提供者**（惰性求值——装配点早于配置装载，取值点在进房，恒在装载后，见 §4.3）；传输工厂委托（本地测试/真 KCP 的决策留给 `ProcedureMatch`，工厂不认识测试开关语义）；`Account/MatchSessionFactory`；`MetaEntryService`（未配置 Meta 基址＝置空，页面显性拒绝，不造指向空址的客户端；设备标识 `-device.id` 优先、否则机器唯一标识；云端测试房模板/口令随部署注入——测试者包不带，建不了测试房）。
4. **反馈与页面流**：`DialogService`/`FeedbackService`/`ToastTicker`（容器拥有所有权，Container-Owned）；`Bridge` 系列绑定（Lua 门面的后端）；`ui.modal` 具名拦截源（模态开＝拦游戏意图）；模态登记只留不依赖表的 Error/Confirm 两 id（设置页 id 单源在表里，随 Preload 放行闸口（release gate）登记）；`PageFlow`（入口/开局关房/结算三处流程 × 页面接缝）。
5. **帧驱动序 + Seal + 流程机**——完整的一次帧三层驱动见 §5。

**错误语义**：引导失败 → `ProcedureError.ShowBootstrapError`（确定错误态，不半死不活）；模块初始化失败只回滚已成功部分（partial rollback）；编辑器 Domain Reload Off 的静态残留由 `ResetForEditorReload` 复位，二次 Play 不死锁。

## 3. 所有权模型：作用域树的运行时时间线

静态规则一句话：Root → Account → Match → Scene/UI 五层作用域；取消级联（cascading cancellation——子作用域的取消令牌链接父令牌，父取消必然取消子）、LIFO 释放（栈式展开，stack unwinding——登记逆序释放）、租约归还即卸载。机制细节见 [技术总结 03](../技术总结/03-客户端框架与运行时.md)。这里讲**这些作用域在程序一生中何时建、谁建、拆的时候按什么序**：

| 时刻 | 动作 | 谁 |
|---|---|---|
| 引导期 | Root 作用域 + 根容器（模块产物宿主） | `ClientHost` |
| 进房 | `Account` 作用域 + Account 服务子容器（child container，向父域读 Singleton）+ `BattleClient`（构造即发 Join）；**失败就地回滚**（Dispose 后重抛） | `AccountSessionFactory.Create` |
| 会话建立 | `Match` 作用域（`BattleContext` 构造期创建）；RoomClient 事件订阅以委托释放登记进 Scope（**晚挂先退**） | `BattleContext` ctor |
| 对局中 | Scene（对局场景组）/ UI（页面资源）子作用域按需 | `SceneService` / UIService |
| 离场 | 视图与驱动先拆 → Match 服务域 → Account 作用域——**完整收尾序与宿主关闭豁免的权威在 §8 第 6 步** | 流程 finally 链 |

设计含义：**离开一个域 = 冻结它的一切**——资源租约、事件订阅、会话客户端全部登记进所在作用域，不存在"逐件手工清理清单"。Account/Match 两级各挂一个**子容器**：子域向父域读 Singleton、只持本域实例（scoped lifetime）——登录期服务与局内服务不混居。

## 4. 接入面：UI、内容、配置、Lua

客户端与外部世界（资产/表/脚本）的四个接缝，各自的接缝契约：

### 4.1 UI

- `UINavigationController` 是唯一写者——导航请求队列化（queued navigation）、超时可取消；页面打开必须走导航（禁直调 Show）。
- `UIForm` 七态生命周期（Loading/Active/Covered/Paused/Closing/Recycled/Disposed）；页面按 form 级缓存策略复用（resident/LRU/destroy-on-close）。
- 模态栈（modal stack）最顶优先 Back、射线遮蔽（raycast blocking）；焦点协调以 **EventSystem 当前选择为焦点事实单源**——遮盖时保存并清选择、恢复不抢占；对局内 ESC＝开设置页（暂停菜单，打开即拦游戏输入）。
- 语义层固定四项（Bottom/Window/Top/System），`tbuiform` 表驱动。制作与操作归 08 章。

### 4.2 内容

- `IContentService` 租约是资源访问唯一入口——共享加载（引用计数式共享）、代次校验（generation check）、迟到结果自释放（stale-callback discard）。
- YooAsset 适配编辑器模拟/离线包/真机三态；热更走候选（candidate build）→ 原子激活（atomic activation）事务，失败可回滚。
- 启动期 `AssetsHealthProbe` 报关键资产健康面。

### 4.3 配置

- Luban 产物两端同读同一份 bytes；`ConfigService` 候选构建 → 原子发布（atomic publish），坏表保留空态无半发布（no partial publish）。
- **玩法摘要提供者惰性化**（lazy provider）——工厂在 Preload 前构造、取值点在进房，恒在装载后（装配序约束下的取值时机，配合进房期 `StartGame.ConfigHash` 复算）。
- **地图行键取 JoinAck 权威事实**（`RoomClient.MapId`，0＝首图口径）——本局视觉与判定同图由同一行键保证。

### 4.4 Lua

- 三注册表（UI/内容/策略）装配 + `RegistryFiller` 启动期五步填表；运行期**增量重填**（不重建 env）。
- `Bridge` 只导出 data/ui/content 三个门面——Lua 面的可达面是收敛过的（allowlist 式暴露）；房间会话经 `Bridge.room` 门面装订，收尾必摘。

## 5. 一次帧的三层驱动

把三层的帧序讲清楚，"客户端每帧在干什么"就有完整答案：

**第一层——常驻服务 tick 链**：`GameEntry.Update` 单点把 `Time.unscaledDeltaTime` 喂给容器的可更新链（tick registry）——变速只发生在 `IGameClock` 内部，杜绝"0.2 × 0.2"的双缩放事故。Tick 顺序由装配根显式声明（14 件）：

```text
MainThreadDispatcher → WorldClock → UIClock → DotweenUiClockDriver → EventCenter
→ UIService → LogicScheduler → UIScheduler → TimelineRunner → VfxService
→ DialogService → ToastTicker → CommandCenter → StageMachine（流程机）
```

三个关键排序决策：**Dispatcher 最前**（后台完成先切回主线程，再谈消费）；**时钟先于一切时间消费者**；**命令中心在流程机之前**（排队/延迟命令当帧到期即可被流程应用）。容器 `Seal()` 后只读（注册冻结，registration freeze）——对局期不再注册 tick 件，对局由阶段生命周期驱动，天然随离场停止。

**第二层——流程机**：`StageMachine.OnUpdate` 是 tick 链的末件；当前阶段即帧驱动入口。对局期它就是 `ProcedureBattle.OnUpdate`——**对局的一切每帧工作从这里进**。

**第三层——对局帧序**（`ProcedureBattle.OnUpdate` 的三段，序不可换）：

```text
① 渲染采样前
   rig.TickPreSample()            诊断件先动（自瞄验证件换源——晚了自瞄点落后一帧）
   瞄准世界注入 → 采样            SetAimWorld（设备源用同一 SimRaycast 与预测世界求交，§10）
                                  → SampleOnRenderFrame（上下文门裁决：任一拦截源成立＝本帧输入为空）
② context.Tick(realDelta)        对局唯一驱动入口，内部六步（见下）
③ rig.Tick(realDelta)            视图消费者（动画→准心→HUD→…）——本帧权威已应用后才动
```

`BattleContext.Tick` 内部六步：

```text
网络收泵 TickIncoming（incoming pump）
→ 输入三件：采样入史（input history）→ 同一份上行（uplink）→ 沿用帧预发
   ← 必须【先于本地服步进】——输入前置帧（input lead frames）在此决定
   （viewFrame = 视图当前渲染帧——开火回溯以"玩家看到的过去"为锚）
→ 本地服步进 TickOutgoing（本地测试形态在此步进真房间内核并投递快照）
→ 预测推进 Sim.Tick（固定步长模拟，fixed-timestep；日志帧轴 Log.SetFrame 随之推进——全端日志按帧号关联）
→ 未确认段冗余重发（input redundancy：ResendCarriedFrames）
→ View.Tick（表现视图：网络与 Sim 之后，本帧权威已应用）
```

逻辑帧（simulation tick）与渲染帧（render frame）**解耦（decoupled loops）**：判定走固定步长，表现按显示刷新率走——这是帧率无关（frame-rate independent）手感的结构前提。

**收尾的同步语义**：`Leave()` 在调用栈内同步走完 `Ended` → 流程 finally 收尾（上下文被拆空）——`OnUpdate` 顶门检过后本帧仍可能被拆空，余下驱动面前必须复检空引用。这类"同步收尾 + 复检"是阶段生命周期的固定纪律。

## 6. 流程设计：七个阶段与失败语义

`Launch → Patch → Preload → Main → Match → Battle`（＋`Error` 终态），由一台扁平状态机（flat FSM with explicit transition table）驱动——启动流程不需要抢占/层级状态机（preemptive/hierarchical FSM）的表达力，**显式迁移表**让流程可被静态检查与审计。

| 阶段 | 职责 | 关键设计决策 |
|---|---|---|
| Launch | 引导收尾 | 纯同步落地，不碰 IO |
| Patch | 热更候选 | 薄编排：`PatchRunner` 取候选过信任锚（trust anchor），阶段状态机与激活事务归协调器（十个热更阶段见 08 章） |
| Preload | 配置装载 + Lua 注册表填表 | **放行闸口（release gate）**：五步填表序任一失败即故障停止（fail-fast）阻断进 Main；表驱动（table-driven）的模态登记在此就位（装配期查表必抛——配置还没装载） |
| Main | 启动入口决策 | **不加载对局场景**——只决定登录页/大厅页/不开页；联机入口未配置时页面显性拒绝 |
| Match | 建 Account 会话 | 类型化工厂（typed factory）把动态进房参数变成可移交的 `AccountSession`；传输决策经委托留在流程（工厂不认识测试开关） |
| Battle | 对局全程 | 独占对局场景组的进出场与会话生命周期（见 §8/§9） |
| Error | 终态 | 内建错误 UI；任一阶段失败都进这里 |

**进房参数链**：正式构建走 `MetaJoin`（Meta 签发的 Join Ticket：Host/Port/RoomId/Ticket，服务端验签）——开发与正式构建**同一条链**，测试房只是传输决策的一个分支，不是第二条路径。

## 7. 会话域设计：Account/Match 两半

会话装配是客户端程序最重的一块所有权设计，拆成**两半工厂**：

| 半边 | 形态 | 为什么这样拆 |
|---|---|---|
| `AccountSessionFactory` | **零引擎依赖**（Scope/容器/BattleClient 皆纯 C#），被 dotnet 测试工程源链接（shared-source linking）编译 | 工厂行为（离场/失败/再进房无残留）在 L1 直测，不靠 Unity 才能验证 |
| `MatchSessionFactory` | Unity 面（`BattleContext` 依赖 SimView），从 Account 服务域派生 Match 子域 | 局内服务依赖视图与地图，无法离开引擎；.NET 侧验收归依赖注入专项 DI-4 |

两半都是**类型化工厂**：进房参数（host/port/room/ticket/buildHash/testRoom）经工厂声明进域，流程层不再裸 `new` + 手工拼作用域——作用域与服务域的拼装错误在工厂内就地回滚，不会泄漏半个建好的域到流程里。

`BattleContext` 是一局的**运行态编排内核**，它自己只编排，具体事交给两个协作件：

```text
网络事件 ──→ BattleSnapshotMirror（持久权威镜像（authoritative state mirror）：
              协议单源 Reassembler 重建 + 和解判定 + 视图插值源）
              ↓ AuthorityState（公共事实读源——预测态不回灌公共展示）
        RollbackSim（预测/和解；ConfigHash 复算不等拒局）
              ↓
        SimView（表现镜像/插值/静默门）←── BattleInputPipeline（输入三件顺序与上行——必须先于本地服步进）
```

三个容易忽视的深度点：

- **镜像轮转环容量 16**：本质是环形缓冲（ring buffer），容量必须大于 `SimView` 的抖动缓冲（jitter buffer，8）——只在两份之间轮转（double-buffer）会覆写视图仍持有的旧快照，帧号序被打乱后插值直接跨帧。
- **断线恢复是策略，不是散点**：`SuspectedLost` → 自动重连 `BeginReconnect`（凭 JoinAck 票据）；`Failed`（超时/被拒/版本不符）→ `Ended(SessionFailed)` 交流程回主菜单——**上下文内不静默重建会话**。结束原因四类（`Leave/SessionFailed/Completed/Aborted`）：未开局散场（等待期被中止/排空）无结果可结算，不进结算页。
- **世界重建是预测的前提**：`StartGame` 到达先过**玩法数据身份校验**（`ConfigHash` 与服务端复算比对，不等即拒局），再按服务器 seed 重建同构世界——两端世界构造必须逐位一致（bitwise-identical reconstruction）；该事件幂等（idempotent，重连不重发）。

## 8. 对局编排：`ProcedureBattle` 全序

流程阶段**只做编排**，视图域全部归 `BattleViewRig`——本类保留"取会话 → 等信令 → 每帧驱动 → 收尾"与对局级决策。`RunAsyncCore` 的完整时序（**本局收尾序的权威在此，§3/§9 只引用不复述**）：

| 步 | 动作 | 设计点 |
|---|---|---|
| 1 | 建 `BattleViewRig`（BattleView 作用域 + 视图根）→ `LoadAsync` 八段取件 | 取件与会话建立解耦——资源先备，会话后建 |
| 2 | `MatchSessionFactory.Create` → `BattleContext`（Match Scope 建成）→ `RoomBridge.BindSession` | 页面经 `Bridge.room` 读房主事实/发提前开局；**收尾必摘**（页面订阅不得命中死会话） |
| 3 | **双信号竞速（two-signal race）等开局**：`StartGame` 与 `MatchEnded` 先到先得 | 等待期房间被中止（超时/运维关闭/排空）→ 跳过视图建立立即收尾——不竞速流程会永远停在"等开局"（房间已销毁，信令永不再来）；胜者败者**一并退订** |
| 4a | 散场分支 | 经 `WaitEnded` 的 earlyResult 立即收尾回 Main，房间页替换回大厅 |
| 4b | **开局分支**：加载遮罩 → 场景组 → 相机硬门 → `Attach` → 关房间页 | 详见下文 |
| 4c | **拒局分支**（`ConfigHash` 不符） | 按会话失败收尾——`SimView` 构造要读预测态，无 Sim 进 Attach 必炸；**数据分叉拒局不变成错误态** |
| 5 | `WaitEnded`（单源单事件等待 + earlyResult）→ 冻结 `MatchEnded` 结果 | 结算页数据源；正常结束才 `Completed` |
| 6 | **finally 关闭序（收尾序权威）**：摘会话门面 → 摘对局菜单 Back → 清输入派发状态 → `rig.Dispose` → Match 服务域 → Account 作用域 → 卸场景组 | 顺序即 §3 时间线的展开；**宿主关闭路径不含场景卸载**（见下） |
| 7 | 页面流（finally **之后**） | 正常结束 → 结算页（带结果）；失败/离场 → 回大厅——页面切换不与资源收尾竞争 |

**开局分支的四个设计点**：

1. **对局场景组在 StartGame 之后、本阶段内加载**（Rig ＋ 本局地图，叠加加载（additive loading））——避免"未开局即付费"与跨阶段所有权分叉；全程"正在进入对局…"加载遮罩（loading overlay），**等遮罩真正开面再压加载**（开面在途时收场会产生孤儿加载面（orphan overlay），落地即闪）。
2. **场景行键取 JoinAck 权威事实**（`RoomClient.MapId`，0＝服务器未标注 → 首图口径）→ 查地图表 `scene` 列；注入了场景服务但**缺地图表＝配置缺失 fail-fast**，不给"静默不加载"留口。
3. **相机硬门（hard gate）在场景就位之后**（vcam 随 Rig 场景走）：`requireCamera` 且解析不到虚拟相机 → 显性失败（§10）。
4. **先收 System 加载面、再关 Bottom 房间页**——反序会让房间页卡在被加载面挡住的模态队列里，整局留着全屏阻断（实测事故：Form 直到对局结束才关闭）。

**离场卸载的判据**：卸场景组**只跳过宿主关闭**——判据取**根令牌**而非本阶段令牌：主动离场（房间页「离开」/设置页「退出对局」）也会取消本阶段令牌，但那不是关闭、容器仍在运行，场景必须照卸，否则残留在大厅画面里（换图重进还会累积）。卸载按地图表枚举全部地图场景＋Rig，幂等；失败只记日志不阻塞离场——场景留驻是表现问题，不是会话正确性问题。

## 9. 对局装配：`BattleViewRig` 的四段合同

对局域的表现侧由 `BattleViewRig` 收拢编排；职责按域外提为协作件（一类一文件，公共面不扩）：`BattleViewAssets`（取件/租约/降级）、`BattleViewSceneAssembler`（SimView/移动动画/激光/保护壳）、`BattleHudAssembler`（准心/HUD/排行榜/击杀/网络/阵亡）、`BattleFeedbackAssembler`（命中分发/伤害数字/特效/音效/权威反馈）、`BattleLookController`（视角/瞄准滞回/指针锁定）。Rig 只保留四段合同与相位顺序：

| 段 | 内容 | 设计规则 |
|---|---|---|
| `LoadAsync` | 八段取件（`BattleViewAssets` 承载）：角色 prefab → 激光束 → HUD → 保护壳 → 飘字底件 → 逐档材质 → 片段清单 → 音效 | 逐项独立降级（graceful degradation）；租约全部登记进视图作用域 |
| `Attach` | 建视图与接线（wiring，见下） | 接线序 = 依赖序：先建被依赖者 |
| `Tick` / `TickPreSample` | 按相位驱动：移动动画 → 权威反馈 → HUD 族 → 世界表现件 → 反馈消费者 → 视角/指针；渲染采样前驱动诊断件 | 判定之后表现；自瞄验证件必须在本帧采样前落位 |
| `Dispose` | 按相位逆序：移动动画 → HUD 族 → 世界表现件 → HUD 根件 → 反馈消费者 → 传送/诊断 → 分发器 → 视角/指针 → 上下文/视图根/租约作用域 | **消费者先于生产者、视图先于上下文**——本局完整收尾序（含场景卸载判据）的权威在 §8 第 6 步，此处不重复 |

`Attach` 的实际接线序（依赖序，读代码就按这个序）：`SimView` → 移动动画驱动 → **命中分发**（`SimView.EventSink` 并列订阅）→ HUD 族（准心（crosshair）→ HUD → 排行榜（scoreboard）→ 击杀提示（kill feed）→ 网络质量 → 阵亡面板；准心/阵亡在此注册进分发器）→ 瞄准激光 → 出生保护（spawn protection）→ 视角/指针控制器 → 反馈消费者（伤害数字/枪口火光/命中特效/远端火光/音效/权威命中反馈）→ 输入接线（真对局渲染相机显式换入设备源）→ 传送命令注册进命令中心。

**降级边界是设计出来的**：缺角色 prefab → **无角色视图**（工厂拒绝＝无实体可见，不造占位替身（placeholder））；缺 HUD/激光/飘字/音效 → 该项静默降级（表现增益不当对局失败）；但**相机**这类结构前提缺失 → 显性失败（fail-fast）——"跑得动但看不见"不是可接受态。`requireCamera: true` 就是这条边界的代码化。

## 10. 相机设计：常驻服务、场景构图、端口语义

> 上游权威：[固定斜视角射击方案专项设计](../设计文档/游戏玩法/固定斜视角射击方案专项设计.md)（AimPoint/瞄准端口）；跟随与位姿契约见客户端总设计。

相机是最容易做出"第二事实源"的子系统，本项目的切分：

- **所有权**：`ICameraService`（Cinemachine 适配器（adapter））由装配根创建、**跨场景常驻**、跨对局复用——服务对象恒非 null；但"这一刻有没有接上虚拟相机（Cinemachine Virtual Camera，vcam）"由 `requireCamera` 在开打前判定（§8 相机硬门）。
- **构图事实单源在场景**：相机构图/档位/阻尼全部归 vcam 的场景配置，代码里没有第二处事实源——**单一事实源（Single Source of Truth, SSOT）**；流程每局只做一件事——`Reset`（下一帧重新落位，**不从上局位置飞过来**）。
- **端口语义**：`Follow` 只写相机位姿；`AddLookDelta` 收视角增量；`SetAiming` 收瞄准语义态（迟滞门控（hysteresis gate）——`AimHoldGate` 最小保持 0.3s，短按也走完一次完整混合，连点不重启混合）；`SetAimPoint` 收瞄准点（构图 z 偏移）。
- **ADS 收敛**：机械瞄准（aim-down-sights, ADS）视场收窄（FOV 60→50）下同像素位移对应更大视角变化，灵敏度同比收敛（档位缩放常量）；基础灵敏度是机制常量单源（约 0.0025 弧度/像素），GM 面板可实时覆写（override），实机定档写回常量。
- **AimPoint 单一口径**（射击方案专项 §3）：设备源把准心射线与**预测世界**做射线求交（raycast intersection，实体圆柱 → 地面）解出目标点，朝向与弹道两端自该点派生——"Yaw → 枪口 → 方向 → Yaw"的闭环自激（closed feedback loop）整体消亡。**瞄准世界注入**：世界所有权在流程层，设备源不缓存权威状态（否则是与决策不同帧的陈旧世界（stale world））；本地实体未对齐时按无效槽位注入 → 退化为纯地面点解算（合法退化）。

## 11. 表现域设计规则

> 上游权威：[动画模块专项设计](../设计文档/客户端/动画/动画模块专项设计.md)（驱动层层次状态机）；镜像/插值口径细节归 [技术总结 05](../技术总结/05-确定性Sim与战斗判定.md)。

`Assets/LiteGame/App/Presentation/`（Hud/Fx/Battle/Audio 四组）＋ `Assets/LiteView` 遵守四条规则：

1. **只读判定**：表现驱动只消费预测态与公共快照，**禁回写 Sim**——这是"回滚不闪、和解不抖"的结构前提，不是风格偏好。表现/模拟分离（presentation-simulation separation）。
2. **事件消费制**：`SimView` 的静默门放行帧事件（和解/回滚期间的事件抑制（event suppression））→ `HitFeedbackDispatcher` 并列订阅 → 消费者各自过滤（特效/音效对旁观者同样可见；伤害数字（damage numbers）只显本地造成/承受）。
3. **服务不互调**：动画不认识 VFX、VFX 不认识音频；跨域一律由流程/编排件接线——表现件保持可单测。
4. **预算与句柄制**：VFX 同屏预算（budget：默认 64/低配 32＋跳过重类，溢出按策略回收最旧（recycle-oldest）或拒绝（reject））、句柄制播放、按挂点（attach socket）隔离停止、关闭真取消（真取消 vs 假忽略——关闭面必须可等待）；音频句柄＋优先级抢占（priority preemption）＋分组，**分域时钟**（对局暂停/离场即停）。

主要驱动件速览：

| 驱动 | 消费 | 一句话 |
|---|---|---|
| `CharacterLocomotionDriver` | 视图 Transform 帧间位移 + 瞄准态 | 动画状态决策收进单机双根状态机，速度锁存迟滞（hysteresis）单源 |
| `BattleCrosshairDriver` | 瞄准态/输入拦截 | Hip/ADS 双形态；被模态拦截时藏准心**还系统光标**（光标唯一写者） |
| `BattleHudDriver` / 排行榜 / 击杀提示 / 复活 / 网络质量 | 预测态或权威镜像 | 值变化才写（change-driven write）；件不齐静默降级（旧 prefab 不崩） |
| `BattleDamageNumberDriver` / `BattleImpactFxDriver` / `BattleMuzzleFlashDriver`（含远端） | 帧事件 | 锚定受击点不随实体移动；远端火光走公共开火面，本地不双闪 |
| `BattleLaserDriver` / `BattleProtectionFxDriver` / `BattleAudioDriver` | 射线/快照/帧事件 | 激光端点＝逻辑枪口（muzzle）→瞄准点经 `SimRaycast` 截停（与子弹同终点） |

## 12. 输入设计：三件与唯一消费门

> 上游权威：[角色状态与动作专项设计](../设计文档/游戏玩法/角色状态与动作专项设计.md) §3（输入三件）。

| 件 | 设计角色 |
|---|---|
| 设备源 `IIntentSource` | 键鼠/触屏同面输出**意图（intent）**（Move/Aim/Fire）；Action 资产是**进程级资源**——驻留装配根，不随对局重建；流程只持**本局**设备源挂/摘与清派发状态 |
| 拦截裁决 `IntentGate` | 具名拦截源统一决策并报出**是谁拦的**；生产装配登记 `ui.modal`（模态 UI 开＝拦游戏意图）——流程不持任何"UI 是否拦截"的判断 |
| 协调者 `InputService` | 渲染帧只采样（sample）；逻辑帧经 `TryTakeForPrediction` **唯一消费（single consumption）**；同一份输入经 `TryTakeForSend` 上行 |

对局内的顺序由 `BattleInputPipeline` 收拢：输入帧数组按房间规模定容复用（零分配，zero-allocation），**先于本地服步进**消费——预测、上行、本地服三处吃同一份输入。设计要点：**预测与上行同源**（不存在"预测用了、上行丢了"的裂缝）、**采样与消费分离**（渲染帧率与逻辑帧率解耦后输入不重不漏）。

## 13. 本地联测与开发面

**三种对局传输形态，同一条客户端链**：本地测试模式＝进程内本地服（`LocalServerTransport` 持**真 `RoomRuntime`** ＋ 快照/战斗事件管线——**不复制**票据/多房间/排空/Ops 这些带 IO 的 Application 半边；单连接、热路径（hot path）零分配与服务器宿主同纪律）——客户端除传输外对形态无感知；本地真服与云端测试房走真 KCP。传输决策点在流程的传输工厂（§2.2 委托），**不是第二条代码路径**。

调试能力的边界是**编译期的**：`UNITY_EDITOR || DEVELOPMENT_BUILD || LITEFRAMEWORK_DEBUG`（开发三宏）之内才有 GM 命令、调试内核、弱网预设、自瞄验证件——release 里这些类型整体不存在（条件编译剔除，conditional compilation），不是"藏在 release 里关掉"。

- **一张开关表**：`TestModeOptions`（8 个开关）是面板渲染、运行时快照、`DevStartupConfig` 初值三处的同源描述表——新增开关只改这张表。
- **一条命令链**：玩家操作与 GM 动作都走 `CommandCenter`（权限门 → 拦截器 → 审计踪迹 32 条）。GM 命令的**注册点在装配期**——GM 发现面（command discovery）在 dev 构建恒可用，不依赖场景里的 `DevStartupConfig` 是否挂载；联调工具（弱网预设）也走命令；测试热键（T＝传送到准心）入队命令、帧边界派发（frame-boundary dispatch）、可撤销。
- **一个调试内核**：`DebugKernel` 是调试面的唯一门面，编辑器页/HUD/控制台三投影（read-model projections——CQRS 读侧术语：同一读模型的三个只读投影）只消费它。
- **命令行门控探针（probe）**：内存循环实测（`-memloop`）与模态输入恢复（`-inputmodal`）两类探针**不进 dev 条件块**——靠命令行参数门控（feature flag by CLI），未带参数时一次查找后零开销；这样非 dev Player 也能做这两项实测。
- **诊断读口**：`IModuleStats` 由容器自动发现，DevHUD 跨程序集拉取；对局诊断读口随对局挂接、离场注销（防误注下一局）。

## 15. 常见误解

1. **WorldClock 暂停 ≠ 游戏暂停**：它只冻结走 `IGameClock` 的消费者；流程机与对局推进吃的是 unscaled delta。要"真冻结对局"须在流程/对局侧另行决策。
2. **注册顺序不是风格问题**：它就是依赖图。插入一个模块 = 声明它依赖前面全部、被后面依赖。
3. **容器 Seal 之后对局期零注册**：对局能力来自阶段生命周期与构造注入（constructor injection），不是运行期动态注册。
4. **"已实现" ≠ "已接线"**：读代码要看调用点。反向陷阱同样成立——旧文档说"未接线"的件可能已经接上。
5. **本地测试模式不是"简化版服务端"**：它跑的是与云端同一份房间内核与快照管线，只是传输换成进程内——在本地复现的判定问题在云端同样成立。
6. **角色不见了先查资源包**：缺 prefab 时工厂拒绝＝无实体可见（不造占位替身），Console 有「本局无角色视图」告警——不是渲染 bug。

## 16. 一图回顾（谁认识谁）

```text
Procedure/流程 ──→ BattleContext（会话+Sim+上行）──→ RollbackSim/FrameDriver（判定）
      │                    │                              │
      │                    └──→ RoomClient（KCP 上行）      └──→ SimWorldState（只读镜像）
      ↓                                                          ↓
BattleViewRig（表现装配根）──→ SimView（镜像/插值/静默门）──→ 相机 / 动画 / VFX / 音频（事件消费）
```

判定侧**不认识**表现，表现侧**只读**判定与事件——表现/模拟分离（presentation-simulation separation），这一句就是客户端程序设计的结构前提。
