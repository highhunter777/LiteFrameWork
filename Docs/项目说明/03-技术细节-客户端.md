# 03 · 技术细节：客户端

> 客户端 = 宿主与装配（`Assets/LiteGame/App`）+ 框架（`Assets/LiteFramework`）+ 域层（`Assets/LiteGame/{Runtime,UI,Adapters}`）+ 表现（`Assets/LiteSim/View`）。
> 设计契约以 [客户端总设计](../design/architecture/商业级通用客户端框架总设计.md)、[UI 框架总设计](../design/client/ui/UI框架总设计.md)、[动画模块专项设计](../design/client/animation/动画模块专项设计.md)、[热更与内容发布专项设计](../design/client/content/热更与内容发布专项设计.md) 为准；本文只讲机制怎么落地。

## 1. 装配、容器与作用域

| 件 | 位置 | 机制 |
|---|---|---|
| `ClientHost` | `LiteFramework/Scripts/Core` | 宿主：按序初始化模块、聚合产物、**逆序关闭**、失败只回滚已成功部分 |
| `IClientModule` + `ClientContext` | `LiteGame/App/Bootstrap/*Module.cs` | 模块只经 `Put/Require` 交换产物（同型唯一、编译期可见）——**不用字典做服务定位**，装配错误显性失败 |
| `ServiceContainer` | `LiteFramework/Scripts/Core/DI` | `Seal()` 之后只读；自动发现 `ITickable`（帧驱动）与 `IModuleStats`（DevHUD 诊断面） |
| `AppLifetime` | `LiteFramework/Scripts/Unity/App` | Unity 平台桥：Pause/Focus/LowMemory/Quit + 优雅关闭（刷新钩子 → 逆序模块关闭 → 根 Scope 释放） |
| `ClientScope` | `LiteFramework/Scripts/Core` | 层级所有权：`Account`（登录会话）→ `Match`（一局）→ `BattleView`（视图资源）等；关闭即级联释放租约，**关闭序与创建序相反** |

装配红线：**注册顺序即依赖图**（见 [02 §1.2](02-总体流程.md)）；对局期不再注册 Tickable——对局由**阶段生命周期**（`ProcedureBattle.OnUpdate`）驱动，天然随离场停止。

## 2. 时钟与暂停

| 概念 | 实现 | 谁消费 |
|---|---|---|
| `WorldClock` / `UIClock` / `SystemWallClock` | `LiteFramework/Scripts/Core/Clock/GameClock.cs`，`ClocksModule` 装配 | 逻辑调度（`LogicScheduler`）、时间轴（`TimelineRunner`）、DOTween Manual 轨（`UiAnimationClock.DotweenUiClockDriver`） |
| 暂停 / 变速 | `GameClock.Tick`：`ScaledDelta = Paused ? 0 : realDelta × TimeScale`（单帧 delta 上限钳制） | 同上（**写 `Paused` 的只有开发态 `DebugTuner`**） |
| 全局纪律 | Unity `Time.timeScale` **恒为 1**；`GameEntry.Update` 统一喂 `Time.unscaledDeltaTime` | —— |

**现状约定（重要）**：流程机与对局推进**不消费** `ScaledDelta` —— `StageMachine` 自身是 `ITickable`（被 `GameEntry.Update` 直接喂 unscaled delta），`RollbackSim`/`FrameDriver` 用的是传入的真实帧间隔。因此**把 WorldClock 置暂停只冻结走 `IGameClock` 的消费者，不冻结流程与对局推进**；若要"真冻结对局"，需要在流程/对局侧一并裁决（属设计决策，本文不擅自定义）。

## 3. UI 与 Lua

- **UIService**（`Assets/LiteGame/UI`）：壳件 `UIForm` 生命周期（七态，见 UI 总设计）+ 模态栈（最顶模态优先 Back、射线遮蔽）+ 输入锁职责分离；每个 form 一条**缓存策略**（`DestroyOnClose` / LRU 预算 / `Resident` 不参与淘汰）。
- **导航**：`UINavigationController` 是**单写者**——`GoAsync/ReplaceAsync/BackAsync` 串行执行、队列有上限、排队等待有超时、排队期可取消；UI 页面打开必须走导航（不直调 `ShowAsync`）。
- **Lua 页面**：`Assets/LiteGame/Lua/main.lua` require `UI.UIMain`（真页面），经 `LuaBehaviourAdapter` 挂到 prefab；控件与页面 API 见 [UI控件LuaAPI参考](../design/client/ui/UI控件LuaAPI参考.md)。
- **模板与控件库**：`Assets/UI/Screens`（界面）、`Assets/UI/Widgets`（控件库，收集组 `UIWidgets`）；可用控件含虚拟列表 `VirtualList`（窗口复用/有界节点）、Toast、Dialog、ProgressBar、StarRating 等。
- **本地化/反馈面**：`LText`（语言服务 + 控件/Lua 面，切语言自动刷新已绑定文本）、`DialogService`（合并/互斥组/优先级）、`FeedbackService`（Loading 遮罩/Toast/错误弹窗统一出口，System 层 form，视觉单一来源）。
- **动效**：`UiFx` 原语（DOTween）+ `UiAnimationClock`（Manual 轨接 UIClock，暂停即停）+ 转场策略（`MotionOutcome`/`MotionPlayback`：区分"播完/被取消"，取消必须**先复位再降级**）。
- **生成物**：`LiteCodeGen`（UI/Lua 绑定代码生成），界面行由配置表 `tbuiform` 投影（`Assets/GameData/Config`），模板名与 location 对齐。

> 现状提醒：主流程**当前不打开** `UIMain`（`ProcedureMain` 里的打开调用被注释掉），可玩的 UI 面主要由 PlayMode 用例与冒烟标记覆盖；正式主菜单入口归 U2/G3。

## 4. 内容、配置与热更

| 件 | 机制 |
|---|---|
| `IContentService` / `AssetLease` | 内容访问唯一入口：共享加载（同 location 只加载一次）、**代次校验**、迟到结果自行释放、租约归还即卸载；视图侧另有 `PrefabLeaseCache` 按作用域缓存 |
| YooAsset 适配 | `LiteClient.Content.YooAsset`：编辑器模拟/离线包/真机三态；资源包收集组定义在 `Assets/BundleCollectorSetting.asset`（**经 Pipeline 改，禁手改**） |
| 配置表 | Luban 三份产物：客户端 bin（`Assets/GameData/Config`）、服务端 json（`RoomServer/Data`）、C# 代码（`Assets/GameData/Generated`）；`ConfigService` 走**候选构建 → 原子发布**快照，坏表保留空态无半发布 |
| 热更 | `PatchRunner` 状态机：发布身份 + 签名校验 + 候选校验内核（逐文件摘要复算、空间预检、多源轮转）+ **候选先落盘再激活**的事务 + 激活失败恢复 + 反回退基线；Lua 变更走**受控沙箱**验证 |
| 边界 | 信任锚点 provisioning 未做：**零内置锚点 → 候选一律被拒（fail-closed）**；移动端余量/Android 后端、断点续传与写盘中断矩阵属 G4 真机 |

## 5. 表现层（`Assets/LiteSim/View`）

| 件 | 输入来源 | 职责 |
|---|---|---|
| `SimView` | 只读 Sim 状态 + 帧事件 | 槽位镜像、远端插值（两份快照按视点帧 Lerp/YawLerp）、本地预测跟位 + **和解衰减**（超过阈值硬切）、**事件静默门**（和解/回滚期间不派发视觉事件）、把相机端口与事件出口交给编排方 |
| `EntityViewMap` | SimView 的增删 | 槽位 ↔ 视图实例映射与按 prefab 池化（复用不重建） |
| `CharacterLocomotionDriver`（动画） | **视图 Transform 的帧间位移**（不读 Sim 位置）+ `SimView.IsAiming`（瞄准态） | 速度轴 → `MoveBlend{Idle,Walk,Run}` 混合权重；瞄准+静止 → `AimIdle`；瞄准+移动 → `AimMoveBlend{AimWalk_F/R/B/L}` 四向按夹角插值（限速在 Sim 侧 = 走路档，故只需要 AimWalk）；权重由 Driver 给、**就地更新**（`UpdateBlendWeights`，不换句柄/不重建）；唯一迟滞在"瞄准静止 ↔ 移动"（0.6 进 / 0.3 出）；淡入淡出时长按构造参数显式传入（`0` = 瞬时）；无 Animator 的灰盒视图静默降级 |
| 帧事件接缝（动画，**未接线**） | 同 `VfxService` 的事件来源（`SimView` 静默门放行的帧事件） | `FrameEventAnimationSeam.cs`：`IFrameEventAnimationConsumer`（消费者接口）+ `FrameEventAnimationMap`（FrameEventKind → 语义/通道的**决策表单源**：Fire→UpperBody、Hit/Death→FullBody；Crit/Explosion 不预建）；真实消费、预测/确认合并在 G2 |
| `VfxService` | 编排方消费**静默门放行的帧事件** | 句柄制播放、按挂点隔离 StopAll、预算与回收、关闭面真取消 |
| `AudioService` | 同上（编排方消费事件） | 句柄 + 优先级抢占 + 分组；分域时钟 |
| 相机 | SimView 的本地表现位置 | `ICameraService.Follow` 只写相机；**构图/档位/阻尼归 vcam 的场景配置**，代码里没有第二处事实源（开打前校验相机已接上 vcam，缺则显性失败而非"跑得动但看不见"） |

服务之间**不互调**：动画不认识 VFX，VFX 不认识音频；跨域一律由编排方（流程/表现壳）接线。

## 6. 输入三件（《角色状态与动作专项设计》§3）

| 件 | 位置 | 职责 |
|---|---|---|
| 设备源 `IIntentSource` | `LiteGame/Adapters/Platform.Unity/NewInputIntentSource.cs` | 键鼠/触屏同面采样（Move/Aim/Fire）；Action 资产与订阅是进程级资源，**驻留装配根、不随对局重建** |
| 拦截裁决 `IntentGate` | `LiteGame/Runtime/Input/IntentGate.cs` | 具名拦截源（如 `ui.modal`）统一裁决，并报出是**谁**拦的 |
| 协调者 `InputService` | `LiteGame/Runtime/Input/InputService.cs` | 渲染帧采样（`SampleOnRenderFrame`）、逻辑帧唯一消费门（`TryTakeForPrediction`）、上行开闸（`TryTakeForSend`）；`Reset` 清上一局派发状态 |

## 7. 一图回顾（谁认识谁）

```text
Procedure/流程 ──→ BattleContext（会话+Sim+上行）──→ RollbackSim/FrameDriver（判定）
      │                    │                              │
      │                    └──→ RoomClient（KCP 上行）      └──→ SimWorldState（只读镜像）
      ↓                                                          ↓
SimView（表现镜像/插值/衰减/静默门）──→ EntityViewMap ──→ 相机 / 动画驱动 / VFX / 音频（事件消费）
```

判定侧**不认识**表现，表现侧**只读**判定与事件——这是"回滚不闪、和解不抖"的结构前提。
