# 06 · 环境与协作纪律

> 环境细节以 [环境恢复指南](../环境恢复指南.md) 与 [UNITY-GUIDE.md](../../UNITY-GUIDE.md) 为准；协作者（含 AI Agent）必读约定见 [CODEBUDDY.md](../../CODEBUDDY.md)。本文是它们的"一条线串起来"版本。

## 1. 环境要求与恢复

| 项 | 要求 |
|---|---|
| Unity | **2022.3.55f1c1**（Unity 中国版）；脚本默认编辑器路径 `E:\unity3d\2022.3.55f1c1\Editor\Unity.exe`，可用参数覆盖 |
| .NET | **.NET 8 SDK**（L1/L3 与服务端宿主） |
| Python | `python` + `openpyxl`（`scripts/codegen/gen-build-hash.py` 等） |
| Unity CLI | `unity` 命令在 PATH（Pipeline/门禁/构建脚本都走它）；工具链单源：`scripts/gate/toolchain.json` |
| 一键校验 | `powershell -NoProfile -File scripts/gate/restore-check.ps1`——缺 BLOCKING 项直接 exit 1 |

**随库分发 vs 需自备**：`Packages/`（含 YooAsset、Luban wrapper、`com.unity.pipeline`）、**`ProjectSettings/`（已入库，含 `HIDE_REFLECTION` 等宏）**、`scripts/`、`Tests/` 都在库里；而 **Odin（按席位付费）、部分美术/字体资源、XLua Tools、`MCPForUnity` 等本机工具**需按《环境恢复指南》说明自备（实际检查项以 `scripts/gate/restore-check.ps1` 为准）。第三方素材包（如 `Assets/CombatGirlsCharacterPack`、`Assets/Prefab`）按政策**不入 VCS**——缺包时角色渲染走**程序化灰盒**（可复现降级，不是错误态）。

## 2. 文档体系与权威层级

| 目录/文件 | 角色 | 权威性 |
|---|---|---|
| 代码与测试 | 当前真实行为 | **最高**（与任何文档冲突时以它为准） |
| `Docs/设计文档/**` | 目标架构与专项设计（总设计 > 专项设计 > 规范 > 参考 > 路线图） | 目标形态的权威 |
| `Docs/待办总览.md` | G0～G6 关口、缺口、跨域依赖、下一轮队列 | 进度与优先级权威 |
| `Docs/施工进度/**` | 逐批证据（代码位置、命令、结果、产物、剩余边界） | 已完成事实的权威；**只记可验证证据，不裁决设计** |
| `Docs/开发导航/**` | 代码地图与"改 X 去哪改" | 只答"在哪、去哪改"，不写设计动机 |
| `Docs/项目说明/**`（本文） | 说明/导览层：是什么、怎么跑、怎么流 | 不裁决任何事，冲突以以上为准 |
| `Docs/归档记录/<date>/**` | 被取代的历史稿 | 仅追溯 |

**批次完成后的回写惯例**（"完成定义"的一部分，见 [待办总览](../待办总览.md) 与 [施工进度 README](../施工进度/README.md)）：

1. 本批 `施工进度/<批>.md`：代码位置 + 执行命令 + 实测结果 + 产物 + **剩余边界**；
2. `施工进度/README.md` 索引行；
3. `待办总览.md` 对应关口状态与证据；
4. 相关设计的 `Current`/状态更新节；
5. 结构性改动（新增/搬移目录、新增程序集、改装配序）**当批同步** `开发导航/`。

**不提前造空完成报告**；红的就是红的，失败与跳过都要如实写（含"未跑"）。

## 3. 三条全局红线

| 红线 | 触发 | 动作 |
|---|---|---|
| **BuildHash 源集** | 改 `Assets/LiteSim/Core/{Scripts,Systems}`、`Assets/LiteNet/{Proto,Protocol}`、两端表数据 | 必跑 `python scripts/codegen/gen-build-hash.py`；不跑 → 两端 hash 不等 → Join 被拒进房（设计内红线） |
| **R11 纯化纪律** | 在 `Assets/RoomServer/Runtime/`（及 `MetaServer` 非 Host）写 Console/系统时钟/文件 IO/proto/LiteNet | 被 L1 纪律扫描打红（`DisciplineScannerTests`） |
| **Unity 序列化资产** | 场景 / Prefab / Material / AnimatorController / `.meta` / 工程设置 | **一律走 unity-pipeline CLI**；直接改文件违规（纯文本 `.cs/.json/.md` 可直接编辑） |

## 4. Unity 操作纪律（摘要）

- 与运行中的 Unity 交互统一走 **Unity CLI / Pipeline**；连接命令**必须带** `--project-path "E:\unityProject\Test"`（本机注册表有大小写重复条目，不带会连错实例）。
- 禁止手动创建/修改/删除 `.meta`，不得复用其中的 GUID（历史事故见 [05 §3](05-验证与门禁.md)）。
- 编辑器开着也能跑门禁（`l2-unity-gate.ps1` 的 A 路径），无需关闭工程。
- 改完代码**区分本轮与历史日志**：先 `clear_console` 再观察，避免把上一轮失败编译的残留当成本轮结果。
- 编辑器关闭 Domain Reload 时，静态状态靠 `RuntimeInitializeOnLoadMethod` 复位点清理（如 `GameEntry.ResetForEditorReload`）——新增静态状态时要一并登记。

## 5. 日常命令速查

```powershell
# 打开工程（首次先校验环境）
powershell -NoProfile -File scripts/gate/restore-check.ps1

# 纯逻辑回路（最快，1~2 分钟）
powershell -NoProfile -File scripts/gate/test.ps1 -Lane L1 -Profile PullRequest

# Unity 门禁（meta + 编译 + EditMode + PlayMode；编辑器开着也能跑）
powershell -NoProfile -File scripts/gate/l2-unity-gate.ps1

# 集成/网络回路
powershell -NoProfile -File scripts/gate/test.ps1 -Lane L3 -Profile PullRequest

# 出 Player 并冒烟
powershell -NoProfile -File scripts/build/build-player.ps1
powershell -NoProfile -File scripts/build/player-smoke.ps1

# 改了 Sim / 协议 / 玩法表之后（红线）
python scripts/codegen/gen-build-hash.py
```

## 6. 常见坑（都踩过）

| 坑 | 现象 | 处置 |
|---|---|---|
| 忘了重跑 buildHash | 两端握手失败、拒绝进房 | 跑 `gen-build-hash.py`；出包前 `--check` 会拦下（开发期不设测试守卫） |
| 外部改 `.cs` 后 Unity 没导入 | `recompile_status` 报 up_to_date，用例跑旧程序集（**L2 假绿**） | 用 `l2-unity-gate.ps1`（内含强制 Refresh + 新鲜度守卫），不要只看 `recompile_status` |
| 改动落在点目录 | `Assets/<模块>/.dotnet/obj/**` 的 `.cs` 被误当源码 | 新鲜度守卫已排除点目录；`.dotnet/` 与 `.gitignore` 同源 |
| 拿"启动中"的日志当完成证据 | 冒烟假通过（裸标识符标记） | 只用**完成态标记**（`[Asset] ready` 等），见 05 §4 |
| 判定层混入非确定性 API | 两端行为分叉，握手/重放对不上 | R1～R3 扫描 + L1 的 IEEE/确定性用例 |
| 在 `RoomServer/Runtime` 里打日志 | R11 打红 | 输出只走 `RoomOutput` 事件，宿主侧再落日志 |
| 缺第三方素材包 | 角色/场景资源缺失 | 走灰盒降级（设计内）；正式验收留真机/G2 |
