# 05 · 验证与门禁

> 分层定义与完成标准以 [测试开发框架总设计](../设计文档/测试与性能/测试开发框架总设计.md) 为准；本文是"**怎么跑、跑哪层、结果看哪**"的速查。

## 1. 五层验证（L0～L4）

| 层 | 跑什么 | 命令 | 在哪跑 | 当前 |
|---|---|---|---|---|
| **L0** 静态门禁 | 依赖/秘密扫描：manifest/lock 无个人路径（`file:C:`）、git 依赖固定 commit、vendored 包带 LICENSE、跟踪文本无密钥；追加 `toolchain.py check`（清单/生成索引/CI/hook/计划任务注册面） | `scripts/gate/l0-dep-scan.py` | 任意机器（不需要 Unity/.NET 测试） | 已接入 CI |
| **L1** 纯逻辑单测 | dotnet 侧 6 个测试工程：框架 Core、**Sim 判定与确定性（含 IEEE 逐位基线）**、协议/KCP/房间服务端、测试基础设施、Meta 宿主/票据、Meta 集成（真 Mongo） | `scripts/gate/test.py --lane L1 --profile PullRequest` | win + linux 矩阵 | 用例数以 [施工进度](../施工进度/README.md) 各批实测为准 |
| **L2** Unity 编译与用例 | 非法 `.meta` GUID 扫描 + Unity 编译状态 + 新鲜度守卫 + **EditMode** + **PlayMode** | `scripts/gate/l2-unity-gate.py`（或 `test.py --lane L2`） | 仅 Windows（需编辑器或 batchmode） | EditMode/PlayMode/meta 数以 [施工进度](../施工进度/README.md) 各批实测为准 |
| **L3** 集成/端到端 | 真 IO、真网络、真进程内服务端（多房间/重连/排空等） | `scripts/gate/test.py --lane L3 --profile PullRequest` | dotnet 侧，可双平台 | 已接入 CI（含夜间长跑） |
| **L4** 真机/性能 | 目标真机性能与内存基线、设备矩阵 | ——（**不在 `test.py` 内**） | 真机 | 由《客户端总设计》补齐，属缺口 |

> 注意：`test.py` 的 `--lane` 取值是 **L1 / L2 / L3 / All / Doc**——L0 是独立脚本、L4 尚未纳入脚本。
> 统一入口：`python scripts/toolchain.py verify --lane <L0|L1|L2|L3|Doc|All>` 委托上述脚本；`toolchain.py check` 校验清单/文档/注册面，`toolchain.py docs --check` 校验生成索引。

## 2. 统一入口 `scripts/gate/test.py`

| 项 | 说明 |
|---|---|
| 参数 | `--lane {L1\|L2\|L3\|All}`（默认 L1）、`--profile {PullRequest\|Nightly\|Release}`（默认 PullRequest） |
| L1 过滤 | `Category!=Integration&Category!=EndToEnd&Category!=Performance&Category!=Quarantine&Duration!=LongRunning`；超时 5m；先 `dotnet restore --disable-parallel` → `dotnet build Tests/Tests.slnx`（单 MSBuild 节点）→ 逐工程 `dotnet test` |
| L3 过滤 | `(Category=Integration\|Category=EndToEnd)&Category!=Quarantine`；PR 档再加 `&Duration!=LongRunning`，Nightly 档设 `M10_LONGRUN=1`；超时 12m |
| 产物 | 每个工程一份 TRX + 一份 `TestResults/summary-<lane>.json`（机器可读摘要）；同时导出 `LITETEST_RUN_ID`、`LITETEST_ARTIFACTS`（用例侧写证据用）；`DOTNET_PROCESSOR_COUNT=4` 控并行 |

**机器可读摘要（schema v1）**：`test.py` 写 L1/L3/Doc 的 `summary-<lane>.json`，`l2-unity-gate.py` 写 `summary-l2.json`，`nightly-gate.py` 写 `summary-nightly.json`（`lanes[]` 汇总 L1/L2）。字段：`schemaVersion / lane / profile / status / runId / total / passed / failed / skipped / artifacts[]`，失败附 `error`。CI、夜间日志、人读输出消费同一份，不再各自解析控制台。

## 3. L2 门禁的两条路径（`scripts/gate/l2-unity-gate.py`）

**A. 编辑器在跑**（存在 `Library/Pipeline/.unity-pipeline-port`）——经 Unity Pipeline，不用关编辑器：

1. `set_autotick --enable true`（保证后台编译/测试期间编辑器继续 tick）；
2. **新鲜度守卫**：`eval_file` 强制 `AssetDatabase.Refresh(ForceSynchronousImport)` + `RequestScriptCompilation()` → 轮询到编译收敛。**为什么需要**：外部改 `.cs` 后 Unity 不会自动导入，`recompile_status` 会误报 `up_to_date`，用例跑的是**旧程序集**（L2 假绿）；
3. `recompile_status`（编译失败判红）+ Console 查 `error CS####`（只有 CS 编译错误判红，其它 error 级条目只提示）；
4. `run_tests --mode editor --async_tests true` → 轮询 `test_status`：**EditMode**、**PlayMode** 各判红；`Total=0` 判红（防"测试程序集没编进来"静默通过）。

**B. 编辑器未运行** → batchmode：`unity test <工程> -e <UnityExe> --mode EditMode|PlayMode --output … --timeout 1800`（要求没有 Unity 进程占用同一工程；两段各自独立判定）。

**① meta GUID 扫描**（两模式共有、秒级）：扫 `Assets` + `Packages` 全部 `.meta`，`guid` 必须是 32 位 hex。**历史事故**：非法 GUID 的 `.meta` 被 Unity 拒收 → 资源与类型静默消失，而 L1 全绿。

## 4. 构建与冒烟

| 脚本 | 做什么 |
|---|---|
| `scripts/gate/restore-check.py` | 环境还原校验（缺 BLOCKING 项即 exit 1）：读 `toolchain.json` 校验 Unity 版本/修订、ProjectSettings、manifest/lock、YooAsset/Luban、.NET 8、python+openpyxl+cryptography、git、Odin/DOTween/UniTask/xlua；末尾汇报 `toolchain.py check` |
| `scripts/gate/install-nightly-task.py` | 重注册 `LiteGame-Nightly-Gate`（python + `scripts/gate/nightly-gate.py`；`--dry-run` 干跑，`--what-if` 为兼容别名） |
| `scripts/toolchain.py` | 开发工具链统一 CLI（list/check/docs/open/run/generate/verify/build/doctor）；编辑器 Hub 入口 `LiteGame/工具链` |
| `scripts/build/build-player.py` | 先 `restore-check` → `l0-dep-scan` → 读 `BuildProfiles/windows-x64.json` → 切 target/IL2CPP/场景 → dry-run → `build --confirm` → 轮询 `build_status` → 校验产物 |
| `scripts/build/player-smoke.py` | 清旧实例与 `Player.log` → 启动 exe → 超时内命中**定义态标记**之一即通过：`BootstrapError`（预载失败并显示内建错误 UI）/ `[Asset] ready`（离线包就绪）；其余（早退/无标记）判失败。（旧标记 `[UI] main open` 已随 P0-3 退役删除——`player-smoke.py` 标记集现只有两条） |
| `scripts/codegen/*` | **生成器工具箱**（形态权威见[专项设计](../设计文档/架构/生成器工具箱专项设计.md)）：统一入口 `toolbox.py`（build-hash / proto / luban / sync-code / refresh-hash）；其中 `gen-build-hash.py` 改 Sim/协议/表后**必跑**，否则 Join 被拒 |
| `scripts/content/*` | 内容候选：`gen-candidate.py`（真签名候选）、`publish-candidate.py`、`serve-cdn.py` + `_local_cdn.py`（内部加载器）/`local-cdn.json`（本地 CDN 通道） |

> 标记纪律（历史教训）：**不得用裸标识符当标记**——旧版拿 `AssetService` 当标记，命中的是启动栈帧那一行，等于"还在启动就算过"。只有完成证据可以过。

## 5. 纪律扫描（`Assets/Tools/DisciplineScanner`）

规则集（作用域与豁免以 `Scripts/ScanTargets.cs` 为准；`lint-allow` 可显式豁免）：

| 规则 | 拦什么 |
|---|---|
| R1 | 超越函数（判定层禁用，保确定性） |
| R2 | FMA（融合乘加，两端/跨平台结果可能不同） |
| R3 | float 等值比较 |
| R4 | 非确定性容器/枚举顺序（判定层） |
| R5 | 裸 `UNITY_EDITOR` 条件编译（应走统一宏/适配器） |
| R6 | Unity 原生协程（应走 UniTask） |
| R7 | 非法 `.meta` GUID（仓库级） |
| R8 | `Resources.Load`（资源应走内容服务） |
| R9 | Mod 内容进入 Sim 判定 |
| R10 | UI 服务装配直接发业务包 |
| R11 | **运行时纯化**（`Assets/RoomServer/Runtime`、`Server/MetaServer` 除 `Host/` 外：禁 Console／DateTime.Now／Stopwatch／Thread.Sleep／System.Net/Socket／Kcp*／文件 IO／proto/LiteNet 引用／`new Random()`） |
| R12 | 适配器边界（`YooAsset`／`XLua`／`UnityEngine.InputSystem`／`Cinemachine`／`DG.Tweening` 五个实现只许在各自登记的边界目录内 import；框架侧 `LiteClient.*` 禁反向引 `LiteGame.*`） |
| R13 | **数值读口禁读**（机制面禁读静态可变值：`CombatConfig` 装载面 + `AimMoveSpeed` + `Loaded/Publish`、`MovementConfig` 全类、`WeaponConfig` 的 Default/TryGet/Loaded/Publish——值经 `CombatValues`／`MovementValues`／`WeaponTable` 实例传递；**常量面豁免**。技术债 #1 防复辟线） |

违规即 **L1 红**（命中 `Tests/LiteFramework.Core.Tests/DisciplineScannerTests.cs` 的"真实源码_全部目标_零违规"等用例），不是"建议"。

### 5.1 视觉单一来源扫描（`Assets/LiteGame/Editor/VisualConstructionScanner.cs`，与上表独立）

R1–R13 管的是**机制纪律**；"运行时代码不得构建 UI 视觉结构"这条由本扫描器单独把守，经 EditMode 用例 `VisualSingleSourceEditModeTests`（正/负例）执行。

| 项 | 实际 |
|---|---|
| 判据 | 用户可见视觉必须来自 `Assets/ShareResource/UI/Screens\|Widgets` 模板；命中 `typeof(T)` 参数、`AddComponent<T>`/`GetOrAddComponent<T>` 即违规（**24 个视觉/交互类型名**清单） |
| 例外 | 按**文件名**登记（非路径——目录迁移不使登记失效）：`ProcedureError.cs`（引导期错误界面）、`UiInput.cs`（输入底座）。层容器骨架 `[UIRoot]`/各层节点不带视觉组件参数，按"是否构造视觉组件"判定而非按 `new GameObject` 判定 |
| 扫描面 | `ScanDirectory` 跳过含 `/Editor/` 的目录与自身文件；纯函数 `ScanSource(text)` 便于喂合成负例 |

## 6. 测试基础设施与分类

| 位置 | 内容 |
|---|---|
| `Assets/LiteTesting/Core` | 与 Unity 无关：`TestCategory`/`TestTrait`/`TestDuration`/`TestPriority`、`TestScope`、`Eventually`（轮询等待）、`DeterministicRandom`、`TestRunSettings`；**双轨**（同一份源码出 `LiteTesting.Core.csproj`，dotnet 测试可直接用） |
| `Assets/LiteTesting/Runtime` | PlayMode 用：`PlayModeTicker`、`PlayModeTestScope`（不引 `UnityEditor`） |
| `Assets/LiteTesting/Editor` | EditMode 用：`UnityTestBase`、`UnityTestScope`（对象与 AssetDatabase 的所有权/回收） |

分类标签（`[Category(...)]`）：`Unit`、`Contract`、`Integration`、`Asset`、`Smoke`、`EndToEnd`、`Performance`、`Quarantine`（默认全档排除，**必须关联缺陷且 ≤7 天到期**）；另用 `Duration`（Fast/Medium/LongRunning）与 `Priority`（P0–P3）控档位。

用例规模**随批次推进**——权威以 [施工进度](../施工进度/README.md) 各批实测为准（本文不固化 L1/EditMode/PlayMode 数值，避免多副本分叉）。
