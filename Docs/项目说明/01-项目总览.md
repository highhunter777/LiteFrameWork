# 01 · 项目总览

> 本文回答"项目由哪几块组成、用什么技术、代码怎么分层、现在做到哪"。
> 关口状态与缺口清单以 [待办总览](../待办总览.md) 为准；目录级细节以 [代码地图](../开发导航/代码地图.md) 为准。

## 1. 定位

本仓库同时是两样东西：

1. **自研商业级通用客户端框架**（[客户端总设计](../design/architecture/商业级通用客户端框架总设计.md) C0～C5；
   [服务端总设计](../design/architecture/商业级通用服务端框架总设计.md) R0～R4）——Host/Scope/租约/内容事务/UI/热更/测试门禁这些"与玩法无关"的能力。
2. **一个确定性联机的射击 Demo 游戏**（[框架先行建设与业务接入专项设计](../design/architecture/框架先行建设与业务接入专项设计.md) G0～G6）——
   作为框架的第一个真实业务，用来证明框架不是"接口齐全"，而是"跑得动、验得过"。

判定口径：**框架先行准入未达成**（缺口见 [待办总览](../待办总览.md)），不以"接口与单测齐全"宣布模块完成。

## 2. 五个组成块

| 块 | 代码位置 | 一句话职责 |
|---|---|---|
| 客户端框架 | `Assets/LiteFramework` + `Assets/LiteClient`（框架侧）+ `Assets/LiteGame`（App 装配/UI/Lua 桥） | 宿主生命周期、DI 容器、分域时钟、Scope/租约、事件、日志、池、FSM、内容服务、UI 壳、热更事务 |
| 判定逻辑（Sim） | `Assets/LiteSim/Core` | **确定性**的定长逻辑帧与系统（输入/移动/射击/伤害/清理）——**客户端与服务端共编**，两端行为必须逐位一致 |
| 联机与表现 | `Assets/LiteNet`（协议/传输）+ `Assets/LiteView`（表现）+ `Assets/LiteClient/Runtime`（会话/输入/战斗上下文） | 输入采样与上行、快照差分/AOI、KCP 传输；视图镜像、插值、预测跟位与和解衰减、动画/VFX/音频/相机 |
| 服务端 | `Assets/RoomServer`（权威房间内核，两端共编）+ `Server/RoomServer/`、`Server/MetaServer/`（.NET 8 可执行宿主） | 服务器权威步进、输入闸门、30Hz 快照流水线、回溯补偿、多房间路由与排空；Meta 宿主与票据接缝 |
| 工具与门禁 | `scripts/`、`Assets/Tools/DisciplineScanner`、`Assets/LiteTesting`、`Tests/`、`.github/workflows/ci.yml` | 统一测试入口与 L0～L4 分层、纪律扫描、测试基础设施、CI、构建与冒烟脚本 |

## 5. 程序集分层（依赖方向）

四层单向依赖（**下层不认识上层**）：

```text
[装配层]        LiteGame.App / LiteGame.DevHUD / LiteGame.Editor
                        │  （模块装配、流程机、DevHUD；唯一允许认识全部下层的地方）
[域层/适配器]    LiteClient.Runtime · LiteGame.UI · LiteGame.LuaBridge · LiteGame.DevLocalServer · LiteClient.Adapters(Platform.Unity/Content.YooAsset/Network.Kcp/Scripting.XLua/Serialization.Luban) · LiteCodeGen
                        │
[Unity 基础层]   LiteFramework.Unity · LiteView · LiteClient.Abstractions
                        │
[零引擎层]       LiteFramework.Core · LiteFramework.Async · LiteSim.Core · LiteNet · RoomServer.Runtime · RoomServer.Application.Runtime · LiteTesting.Core · DisciplineScanner
                 （asmdef 显式 noEngineReferences——两端共编、可 dotnet 单测）
```

要点：

- `LiteFramework.Core` / `LiteSim.Core` / `LiteNet` / `RoomServer.Runtime` **零引擎依赖**，所以 L1（dotnet）能直接编它们跑 827 条用例；
- **判定逻辑（`LiteSim.Core`）与服务端房间内核（`RoomServer.Runtime`）是同一份源码被两端引用**——这是"服务器权威 + 客户端预测"能对齐的前提；
- 详尽程序集清单与逐条引用关系见 [代码地图](../开发导航/代码地图.md)。
