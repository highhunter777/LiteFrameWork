# 07-本地联测操作手册

> **本文定位**：回答"我怎么自己开服务器，用编辑器客户端和打好的 exe 联测；改完代码后三端各要做什么"。
> **不做的事**：不解释机制原理（归 [03](03-技术细节-客户端.md)/[04](04-技术细节-Sim与联机.md)）；不列门禁全表（归 [05-验证与门禁](05-验证与门禁.md)）；不覆盖环境安装恢复（归 [06-环境与协作纪律](06-环境与协作纪律.md) 与 [环境恢复指南](../环境恢复指南.md)）。
> **冲突裁决**：与代码不一致以代码为准并顺手修本文。

## 0. 三条联测路径与选择

| 路径 | 开什么 | 适用 | 不适用 |
|---|---|---|---|
| **A 进程内本地服**（最快回路，零服务器） | 只开编辑器 | 表现/玩法手感迭代、动画/HUD/准心、GM 调参 | 真实网络、多客户端、弱网/重连 |
| **B 真 RoomServer 最小联测**（推荐日常） | RoomServer + 编辑器（或 exe） | 真网络链路、快照/和解/重连、多客户端、信封 | 大厅/创房/票据/战绩（不经过 Meta） |
| **C 全链路**（Meta + RoomServer） | Mongo + MetaServer + RoomServer + 客户端 | 大厅/创房/登录/票据/结算全链、exe 正式链路验证 | 日常快速迭代（起链重） |

**两个决定成败的机制**（先记住再操作）：

1. **BuildHash 握手门**：`Assets/LiteSim/Core`、`Assets/LiteNet/{Proto,Protocol,Transport/Security}`、`Assets/RoomServer`、`Assets/GameData/Generated` 是**两端共编共享源**——改动后客户端与服务端编译出的哈希不同，**Join 握手直接拒进房**（这就是"改了共享代码以后 exe 连不上"的原因）。改这些代码必须：跑哈希重生成 → 双端重启/重编译，exe 还要**重新打包**。
2. **安全信封 PSK**：真实 KCP 通道强制 AES-GCM 加密。**服务端没给密钥直接拒绝启动**（fail-closed）；**客户端没给密钥也直接抛错**——不存在"客户端裸连"，因此服务端的 `--allow-insecure-local` 只用于服务器自己单机自测，**没有任何客户端能连上它**。日常联测请始终两端配同一把 PSK。

## 1. 环境前置（一次性）

- Unity 2022.3.55f1c1 + Pipeline（`unity` CLI 可用——[Unity 工程指南](../UNITY-GUIDE.md)）；.NET 8 SDK；打 exe 只支持 Windows。
- 仅路径 C 需要：本机 MongoDB（Meta 的持久层）。
- **生成密钥**（PowerShell，32 字节 → Base64）：

```powershell
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))
```

建议生成三把并自己存好：`信封 PSK`（客户端/RoomServer 共用）、`Lobby 实例键`、`结算键`（后两把仅路径 C）。**密钥不入库、不进文档**。

## 2. 路径 A：进程内本地服（不开任何服务器）

1. Unity 打开工程，`Assets/Scenes/Boot.unity` 起 Play。
2. 二选一：
   - **测试模式**（测试房 `Room-Test`）：进程内服、全房免死、bot 补位、GM 面板全开——调参/验链首选；入口＝**大厅页左上「开发」→ 测试模式**（或 `DebugTuner.DirectToTraining` 直入）；
   - **直连对局**（`Room-A`，真 KCP）：默认走真 KCP；若场景 `DebugTuner` 勾了 **UseLocalServer** 则改走进程内服（无 Socket、无票据）；入口＝**开发页「直连对局」钮**（原 F9 热键已删，能力保留为 UI 入口；`DirectToTraining` 直入只进测试房）。
3. 离开对局 = **ESC → 设置页 → 退出对局（确认弹窗）**（开发热键已删；GM 面板的进入/退出/传送同一条请求桥）。

`DebugTuner`（场景对象，Inspector 编辑随场景保存）：启动项（免死/无限子弹/bot 数/冻结/传送）+ 时钟旋钮；测试模式内的局中开关在 GM 面板（`GmPanel`）。

## 3. 路径 B：真 RoomServer 最小联测（推荐）

### 3.1 开服务器（一个终端）

```powershell
# 密钥建议先设进本机用户环境变量，命令行就不用每次带（两端同名变量）
$env:LITENET_SECURE_ENVELOPE_KEY = "<上面生成的信封PSK>"

dotnet run --project Server/RoomServer -- --port 17777
```

- 表/地图**自动从仓库读**（`Assets/GameData/Config`）——改表后重启服务即生效，无需拷贝。
- **配置文件是必需品**：`--config` 缺省 `Config/roomserver.json`（CWD 相对；**缺失直接拒启**，无内置默认兜底——样例已入库见 §5）。对局端口 = **17777/UDP**（KCP）。配置文件禁注释（严格 JSON）；键位全表见 §5.1。
- 启动横幅确认监听后保持终端开着（Ctrl+C 停服；会走优雅排空——结算日志落盘）。

### 3.2 开编辑器客户端

1. **启动 Unity 前设好环境变量**（Editor 进程继承）：

```powershell
$env:LITENET_SECURE_ENVELOPE_KEY = "<同一把信封PSK>"
# 然后从同一个终端启动 Unity（或先 [Environment]::SetEnvironmentVariable(...) 写用户级再开 Unity）
```

> 嫌每次设 env 烦：在 `Assets/StreamingAssets/deploy.args` 手放一份 `-envelope.key=<PSK>`（一行），编辑器/打包都自动吃（§4.2b 烙入机制；该目录在 gitignore 内不入库）。

2. Boot 场景 Play → 大厅页「开发」→ **直连对局** → 测试身份直连 `127.0.0.1:17777`、房间 `Room-A`（地址是代码常量 `ProcedureMatch.TestHost/TestPort`，本机服天然匹配）。
3. **成功标志**：Editor Console 出现 `[Battle] joined (JoinAck)`；服务端终端出现进房横幅。

> 直连对局的测试身份不经过 Meta/大厅/票据（服务端 dev 形态只校验 token 非空）。要测大厅/创房/登录，走路径 C。

### 3.3 多客户端（可选）

再开一个编辑器实例（同一工程第二个 Unity 进程）或一个 exe（§4），同「开发 → 直连对局」即可拼多客户端；弱网/重连真实性只有这条路径可信（进程内服不真）。

## 4. exe（IL2CPP Player）测试

### 4.1 打包

```powershell
# 前提：Unity 编辑器开着（打包在活编辑器上执行，不需要第二个实例）
powershell -NoProfile -File scripts/build/build-player.ps1
```

- �档 `BuildProfiles/windows-x64.json`（Windows x64 / IL2CPP / **Development 通道**——exe 里「开发页」可用）。
- 门禁链自动跑：restore-check → 依赖扫描 → **BuildHash `--check`**（共享源改了没重跑哈希重生成 → 这里被拦，先 `python scripts/codegen/gen-build-hash.py`）。
- 产物：`Builds/StandaloneWindows64/*.exe`。

### 4.2 启动 exe 连本机服

```powershell
& "Builds\StandaloneWindows64\Test.exe" -envelope.key "<同一把信封PSK>"
```

- exe 是 Development 构建 → 进 Boot 后在大厅页「开发」→ **直连对局**，同编辑器一样连 `127.0.0.1:17777`。
- 也可做成快捷方式带参数；`-envelope.key` 与环境变量 `LITENET_SECURE_ENVELOPE_KEY` 两个注入口任选其一（参数优先）。
- 走全链路（路径 C）时另加 `-meta.url http://127.0.0.1:5000`。

### 4.2b 分发形态：端点烙入（零参数启动）

**正式分发/给别人测试时不用带命令行参数**——把端点写进 `BuildProfile` 的 `endpoints` 字段，打包脚本自动烙进包：

```json
// BuildProfiles/<渠道>.json 的 endpoints 字段（值不可含空格——token 形态）
"endpoints": {
  "meta.url": "http://<你的服务器地址>:5000",
  "envelope.key": "<信封PSK>",
  "content.cdnUrl": "http://<CDN地址>"        // 可选：配了走热更通道
}
```

- 打包时 `build-player.ps1` 把 endpoints 写成 `StreamingAssets/deploy.args`（每行一个 `-key=value`）随包分发；**endpoints 留空/缺省的 profile 打包时自动删残留烙入**——换渠道重打不会带上一个包的密钥。
- 客户端装载合并序：**命令行参数 > 包内烙入 > 环境变量（仅信封）/默认**——玩家双击即玩；运维仍可用命令行临时覆盖（改包内 `deploy.args` 文件也行——改完重启 exe 生效）。
- **编辑器同样吃这个烙入**：在工程 `Assets/StreamingAssets/` 手放一份 `deploy.args`（或跑一次带 endpoints 的打包），Editor 联测就不用每次启动 Unity 前设环境变量了。
- 信任边界不因烙入改变：PSK/基址本来就在客户端二进制可提取（防窃听篡改，不承担客户端身份——身份归 G3 账号体系）；CDN 内容过 RSA 验签。

### 4.3 exe 的三个须知

1. **内容是打包时内置的**（OfflineBundles）：改表/场景/prefab/美术，exe 必须重新打包才生效（编辑器里即时生效 ≠ exe 生效）。
2. **共享源改动必须重打包**：BuildHash 烤进两端程序集——旧 exe 连新服/新编辑器对局会被握手拒（表现：JoinAck 永不到/握手断开）。
3. 冒烟自检：`powershell -NoProfile -File scripts/build/player-smoke.ps1`（起 exe 验启动标记，超时即红）。

## 5. 路径 C：全链路（Meta + RoomServer + 大厅/票据）

### 5.0 一键操作（推荐）

```powershell
powershell -NoProfile -File scripts/local/local-chain.ps1 init    # 生成 deploy/.env（五把密钥）+ 编辑器 deploy.args（一次性）
powershell -NoProfile -File scripts/local/local-chain.ps1 up      # 起 Meta + RoomServer（各开一个日志窗口）
```

**图形界面**：Unity 菜单 `LiteGame/测试/GM 面板` → 「本地联测」页——同一份 `deploy/.env` 驱动的实时 GUI：两端状态（进程/端口/探针）自动刷新、Start/Stop 按钮（输出重定向到 `deploy/logs/*.log` 页内实时尾随）、init/打开 .env。编辑器里不切窗口的常驻联测面。

- 密钥存在 `deploy/.env`（gitignore 内，机器私有）——已存在不覆盖（`-Force` 重生成）。
- `init` 同时写 `Assets/StreamingAssets/deploy.args`（信封 PSK + meta.url）——**编辑器 Play 后直接走登录页/大厅，不需要再设环境变量**；exe 同样零参数启动（烙入进包）。
- 前提只剩一个：**本机 MongoDB 在跑**（`.env` 里 `MONGO_CONNECTION` 可改；两键清空 = 持久化关也能起）。
- 手动控制：`local-chain.ps1 meta` / `room` 分开起；`status` **一屏总览当前环境**（两端 BuildHash / Meta 进程+/live / Mongo 可达性 / RoomServer 进程+UDP 端口 / 信封与票据门禁状态 / 客户端烙入内容 / 密钥脱敏汇总）；`keys` 只看密钥。
- 以下 §5 的手动步骤是脚本的底层语义（排障时对照）。

**先记一个硬事实**：全链服带 `--ticket-key` 后，Join 票据门禁生效——**直连对局的测试身份会被票据拒绝**（`c2-dev-token` 不是合法票据）。全链测试走"登录页 → 大厅 → 创房/进房"的正式链路（本节的路径），不要混用直连对局入口。

手动操作步骤：

1. **MongoDB** 本机可连（Meta 持久层；连接串不填 = 持久化关、能起但账本不落）。
2. **生成四把密钥**（32B Base64，见 §1）：`AuthSigningKey`、`LobbyInstanceKey`、`LobbyTicketKey`、`SettlementKey`。
3. **Meta**：填 `Server/MetaServer/appsettings.json` 的 `Meta` 节——`MongoConnectionString`+`MongoDatabaseName`（**成对**填，只填一半启动即拒）、`AuthSigningKeyBase64`、`LobbyInstanceKeyBase64`、`LobbyTicketKeyBase64`（kid 默认 `l1`、audience 默认 `lobby`）、`SettlementInstanceKeyBase64`。起服：`dotnet run --project Server/MetaServer -- --bind http://127.0.0.1:5000`（ValidateOnStart 一次报齐所有违规；成功横幅含 bind 地址与 `/live /ready /metrics` 端点）。
4. **RoomServer**：`Config/roomserver.json` 已含 lobby/settlement 两段（url 指向 127.0.0.1:5000），起服带三把键：

```powershell
dotnet run --project Server/RoomServer -- `
  --ticket-key l1:<LobbyTicketKey 的 Base64> `
  --lobby-instance-key <LobbyInstanceKey> `
  --settlement-instance-key <SettlementKey>
```

   成功标志：横幅 `Lobby 注册已启用` + `结算提交管道已启用`。**同机开第二个实例**必须换工作目录或换 journal 路径（结算 journal 是 CWD 相对独占文件，双实例同 CWD 会撞文件锁）。

#### 5.1 RoomServer 配置键位全表（`Config/roomserver.json`——严格 JSON，禁注释）

| 键 | 必填 | 语义 |
|---|---|---|
| `port` | ✅ | KCP 监听端口（0 = 系统分配，实际端口从横幅回读） |
| `max_rooms` | ✅ | 房间数上限（满则拒新建房） |
| `rooms.<模板>` | ✅ ≥1 | 房间模板：`expected_players` 必填（1..32——满员开局依赖它）；可选 **`map_id`**（多图批：模板固定地图行键，0/缺省 = 宿主默认图；与票据盖章行键各持非 0 且不等 → 拒绝建房）；可选 `seed`/`match_time_limit_ms`/`waiting_timeout_ms`/`match_duration_frames`/`kill_limit`/`respawn_delay_frames`/`spawn_protection_frames` |
| `default_template` | — | 缺省模板名（懒创建对任意 roomId 生效）；缺省用内置名 |
| `audience` | — | 票据受众比对（空 = 不校验；与 Meta `LobbyTicketAudience` 同值） |
| `worker_count` / `mailbox_capacity` | — | Worker 数（1..256，缺省 1）/ Mailbox 容量（缺省 1024） |
| `settlement_journal` | — | 结算日志路径（**必须 .journal 结尾**——.json/.bytes 进 buildHash 闭包，落错处=握手全拒；缺省 `Outbox/settlements.journal`） |
| `settlement_outbox_capacity` | — | 缺省 10000（1..1000000） |
| `rate_limit` | — | 分层限流：`{ip,entry,account,session}_burst/_per_sec` + `buckets` + `idle_ms`（整段缺省=内置；给了就逐字段校验） |
| `lobby` | — | `url`（注册端点）+ 必随 `instance_id`(≤64B)/`advertise_host`(≤128B)/`heartbeat_interval_ms`——**url 空时不许配其余字段**（半段拒启） |
| `settlement` | — | `submit_url` + 可选 `submit_interval_ms`/`submit_max_backoff_ms`/`submit_timeout_ms`（url 空时不许配其余——同上） |
| `host_tuning` | — | 运维调参（整段可选）：`drain_grace_ms`/`drain_watchdog_extra_ms`/`ops_interval_ms`/`max_inbound_packet_bytes`/`session_cleanup_interval_ticks`/`session_unseated_idle_ttl_ms`/`lobby_request_timeout_ms`/`reconnect_ticket_ttl_ms`/`reconnect_capacity`/`outbox_compact_threshold_marks`（逐字段范围校验） |
| `metrics_port` | — | /metrics 出口（0 = 关；Windows 非管理员绑 `+` 前缀需 urlacl，失败降级不断服务） |
| ~~`combat`~~ | ✗ | **禁**——玩法数值只走 .bytes 表，配了解析直接拒 |

密钥四把**不在文件里**（按设计走环境变量/CLI）：`LITENET_SECURE_ENVELOPE_KEY` / `LITENET_LOBBY_INSTANCE_KEY` / `LITENET_SETTLEMENT_INSTANCE_KEY` / `LITENET_TICKET_KEY`（`<kid>:<base64>`，可多次 `--ticket-key`）。

5. **客户端**（Editor 与 exe 同链）：`-meta.url http://127.0.0.1:5000` + 信封 PSK（`-envelope.key` 或环境变量，见 §4.2b）→ 登录页 → 大厅 → 创房/进房 → 对局（房间地址从 Meta 票据下发）。

## 6. 改完代码后的操作序（核心速查）

先判断**改了哪个面**，再按表执行（`Gen`＝生成物命令，`服`＝停服→重起，`编`＝编辑器重编译，`包`＝exe 重新打包）：

| 改动面 | Gen | 服务器 | 编辑器 | exe |
|---|---|---|---|---|
| 纯表现（`LiteGame` App/UI、`LiteView` 动画、场景/prefab/美术/音效） | — | 不动 | **编**（即改即生效） | **包**才生效 |
| 玩法判定共享源（`LiteSim`、`LiteNet` 协议/信封、`RoomServer` 双端件、`GameData/Generated`） | `python scripts/codegen/gen-build-hash.py` | **停服 → 重起**（dotnet 重新编译） | **编** | **必须包**（旧 exe 握手必拒） |
| 表源（`Luban/Data/*.xlsx`，含文案/准心手感/武器数值） | `Luban/gen.bat` → `gen-build-hash.py` | **停服 → 重起** | **编** | **包** |
| `.proto`（`Assets/LiteNet/Proto/*.proto`） | `gen_proto.py` → `gen-build-hash.py` | **停服 → 重起** | **编** | **包** |
| 服务端宿主（`Server/RoomServer`、`Server/MetaServer` 的 .cs） | — | **停服 → 重起** | 不影响 | 不影响 |
| Lua/文案脚本（`Assets/LiteGame/Lua`） | — | 不动 | Play 重进（Lua 页面脚本随 Preload 装载） | **包** |

**口诀**：改表现=编辑器即改即玩；改判定=两端同步+exe 重打；改数据=Gen+双端；改宿主=只重启服务器。

**易踩坑**：

- **改服务端/共享代码前先停服**——运行中的服务进程锁着 `Server/*/bin` 的 DLL，不停服 L1 门禁与 dotnet 编译都会报文件锁（MSB3027）。
- 编辑器侧改信封/协议后**忘了让编辑器重编译**就开服测试，两端哈希不一致 → Join 被拒；先在编辑器里等编译完再进对局。
- exe 测试用**Development 档**（现唯一档）才有开发页；Release 形态（未建档）没有测试入口。

## 7. 排障速查

| 症状 | 大概率原因 | 处置 |
|---|---|---|
| JoinAck 永不到 / 握手即断 | **BuildHash 两端不一致**（改共享源没双端同步；或 exe 是旧包） | 看服务端日志的哈希比对行 → 跑 `gen-build-hash.py` → 双端重启 → exe 重打包 |
| 对局解不开包 / 信封握手失败断开 | PSK 两端不一致或客户端没拿到 | 核对 `LITENET_SECURE_ENVELOPE_KEY`（服务/编辑器/exe 三处同值） |
| RoomServer 起不来 | 缺信封键（fail-closed 默认拒） | 设 env 或带 `--envelope-key` |
| 编辑器进对局抛信封错 | 启动 Unity 前没设环境变量 | 退出 Unity → 设变量 → 重开 |
| 端口不通 | KCP 是 **UDP**（17777）；防火墙/占用 | `netstat -ano` 查占用；本机回环一般无碍 |
| L1 门禁 / dotnet 编译报 MSB3027 文件锁 | 本机活服进程锁 DLL | 停服再跑门禁 |
| exe 行为与编辑器不一致 | exe 内容是打包内置（表/场景/prefab 旧） | 重打包；对照 §6 表格 |
| Meta 相关（登录/大厅/创房）失败 | Mongo 未起 / 三把键不同值 / 票据键不匹配 | 按 §5 逐项核对键值 |

**成功标志**：客户端日志 `[Battle] joined (JoinAck)`；服务端横幅房间创建/进房行。
