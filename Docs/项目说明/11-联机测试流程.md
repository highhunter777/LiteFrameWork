# 11-联机测试流程（现行：Windows 云主机 + 普通房/云端测试房）

> **本文定位**：把"从改完代码到两个人（或一个人）在云上打完一局"的现行流程收成一条主线，替代在 09/10 两本手册间来回翻。
> **不做的事**：不解释机制（归 [03](03-技术细节-客户端.md)/[04](04-技术细节-服务端.md)）；不重复 Linux/Docker 旧形态（归 [09 §2](09-上云联机测试.md)，备用）；不裁决定义（云侧形态归 [10](10-Windows云主机部署.md)，GM 归《[云端GM通道专项设计](../设计文档/架构/云端GM通道专项设计.md)》）。
> **隐私口径**：公网 IP、账号、GM 密钥、测试者 `.conf` **只落机器私有 `LocalNotes/cloud-host.md` 与 `Dist/out/`**，本文不回显。

## 0. 角色与地址

| 角色 | 地址 / 位置 | 说明 |
|---|---|---|
| 云主机 | `ssh` 别名 **`litegame-cloud-tunnel`**（隧道入口 `10.8.0.1:22`；公网 `22/tcp` 已关，值见 `LocalNotes/cloud-host.md`） | Windows Server 2025 Server Core |
| Meta | 隧道内 `http://10.8.0.1:5000` | 登录 / 大厅 / 票据 / 战绩 |
| Room | 隧道内 UDP `10.8.0.1:17777` | KCP 对局（公网只有 `51820/udp`） |
| 指标 | 隧道内 `10.8.0.1:9100/metrics` | 只读 |
| 运维(GM) | 隧道内 `http://10.8.0.1:9101/gm/*` | 仅 POST + `X-GM-Key`，默认关闭 |
| 客户端配置 | `BuildProfiles/windows-x64-closedtest.local.json` | `meta.url` 已指向隧道地址 + 信封 PSK——**换机器不用改** |

## 1. 房间模板（先分清：模板不是地图）

| 概念 | 是什么 | 现行取值 |
|---|---|---|
| **地图** | 关卡几何 + 出生点（`map_id` / `arena01`） | 由建房选图决定：普通房在大厅选；云端测试房在 GM 页选 |
| **模板** | 规则集：`match_duration_frames` / `kill_limit` / `respawn_delay_frames` / `spawn_protection_frames` | 普通房 `standard`；云端测试房显式 `sandbox` |

- **普通房**（大厅「创建房间」）：默认 `default_template=standard`（20 杀 / 180 s），对局自然结束并产出结算；测试者日常联机用这条。
- **云端测试房**（GM 页显式创建）：`sandbox` = **不限时（`match_duration_frames=0`）+ 无击杀上限（`kill_limit=0`）+ 1 s 复活**，隐藏、不进大厅；代价是**不产出结算**。它**不是地图**，地图由 GM 页下拉选择并随建房票据盖章。

模板/端口改动只需改 `deploy/roomserver.windows.json` 并重启任务（`buildHash` 不变、客户端不用动）。

## 2. 发版（按改动面）

| 改了什么 | 云上 | 客户端 |
|---|---|---|
| 纯表现 / Lua / prefab / 美术 | 不动 | 编辑器重编译；exe 重打包 |
| 服务端宿主 `.cs`（`Server/RoomServer`、`MetaServer`） | 重新发布并上传（见 §3） | 不动 |
| 共享源集（`LiteSim/Core/{Scripts,Systems}`、`LiteNet/{Proto,Protocol,Transport/Security}`、`GameData/Generated`、`SHARED_LINK_FILES` 源链接件） | `python scripts/codegen/gen-build-hash.py` → 重新发布上传 | **必须重打包**（旧包握手拒） |
| 房间内核 `Assets/RoomServer/{Runtime,Application}`（**不在**共享闭包内，改它不动 buildHash） | `dotnet publish` 重新发布上传 | 不动（仅本地服档位用到，编辑器重编译即可） |
| 表源 `Luban/Data/*.xlsx` | `Luban/gen.bat` → 重建产物 | 重编译 + 重打包（摘要同源） |
| 只改 `roomserver.json` | 传配置 → 重启任务 | 不动 |

> 判据永远是两端 `buildHash` 同值；不一致的表现是签票 `409 version-mismatch`，不是"连不上"。

出包前先跑只读 preflight，按本次 diff 拿"内环验证 / 外环交付"两套动作：

```bash
python scripts/build/build-plan.py --base origin/main          # 人读摘要
python scripts/build/build-plan.py --base origin/main --json   # 机器可读
python scripts/build/build-plan.py --changed-file <path>       # 演练/排查
```

它只报告、不阻断；上表是人工速查，工具规则由 `scripts/tests/test_build_plan.py` 的矩阵固定用例与上表逐行对齐。

## 3. 服务端：一键重新部署

```powershell
python scripts/deploy/bootstrap-cloud-python.py       # 首次/换机：云上 embedded Python + remote_runner
python scripts/deploy/deploy-room.py                  # 发布 + 上传 + 停服/解压/起服 + 回读判据
python scripts/deploy/deploy-room.py --skip-publish      # 只上传现有产物（重试/纯配置场景）
python scripts/deploy/deploy-room.py --with-config       # 同时上传 deploy/roomserver.windows.json
```

脚本内已固化两个坑：**先停服再解压**（否则 DLL 被占用 `Can't unlink`）、**停/起分两步 ssh**（合成一次曾"无输出且未生效"）。云上动作由 `remote_runner.py`（Python，stdlib-only）执行；运行时缺失会在停服前 fail-fast，先跑 `bootstrap-cloud-python.py`。

判据：输出 `task=Running` + `buildHash=…`（与客户端包内常量同值）。

## 4. 测试者接入（基包一次 + 每人 conf）

**游戏基包只发一次，不要为每个人重打 491MB；conf 仍一人一份（WireGuard 密钥/隧道地址必须唯一，不能共用）。**

> 测试者包必须用 **release 通道**产物（Development 包只给开发侧测试）：先按 §2 用 `BuildProfiles/windows-x64-release.local.json` 出包（本机档补 endpoints），组包时显式 `-GameBuild Builds/StandaloneWindows64-release`。

```powershell
# ① 一份共享基包（无 conf；游戏 + 启动脚本 + server.txt + WireGuard 安装包）
pwsh -NoProfile -File Dist/New-Package.ps1 -Tester LiteGame-base -Base -Zip -GameBuild Builds/StandaloneWindows64-release

# ② 每个测试者只生成自己的 conf（云上生成密钥 + 追加 peer + 重装隧道服务 → Dist/out/<名字>.conf）
python scripts/deploy/wg-peer.py --name alice
# 'alice','bob','carol' | ForEach-Object { python scripts/deploy/wg-peer.py --name $_ }

# ③ 发放：LiteGame-base.zip 发一次；每人单独发自己的 <名字>.conf
```

批量出包（多个测试者）：

```powershell
# 叠加包（推荐）：基包出一次，每人只出一个「kit + conf」小包
pwsh -NoProfile -File Dist/New-Packages.ps1 -Testers alice,bob,carol -Overlay -Zip -Force

# 全量包：每人一个含游戏的完整包（491MB/人）
pwsh -NoProfile -File Dist/New-Packages.ps1 -Testers alice,bob,carol -Zip -Force

# 省略 -Testers = 扫描 Dist/out/*.conf；--dry-run 只校验；-ContinueOnError 单人失败不停
pwsh -NoProfile -File Dist/New-Packages.ps1 -Overlay -Zip --dry-run
```

测试者侧：解压基包 → 把**自己那份** `.conf` 放到与 `加入联机环境.cmd` 同目录（只能放一份）→ 双击 `加入联机环境.cmd`（装 WireGuard → 装隧道 → `/live` 自检）→ 双击游戏。

> 批量 `wg-peer` 会逐个重装云上隧道服务，期间现有隧道短暂断开；建议在没人测试时批量开号。

注意：
- **一人一份 `.conf`**（内含私钥），不能共用/回传/截图；换机/换公网 IP 时全部作废（只需重生成 `Endpoint` 与 `PublicKey` 两处，游戏包不用换）。
- 基包不含私钥，可安全重复分发；旧的全量单人包（每人一份 491MB）仍可用，但不再推荐。
- 换网络（家宽/热点/办公室）**不用重新加白**——用的是隧道，不是 IP 白名单（模型 B）。

## 5. 开测

### 5.1 客户端从哪起

| 形态 | 启动 | 配置来源 |
|---|---|---|
| 编辑器 | Unity 打开 `Assets/Scenes/Boot.unity` → Play | `Assets/StreamingAssets/deploy.args`（当前 `-meta.url=http://10.8.0.1:5000`） |
| exe | `Builds/StandaloneWindows64/Test.exe`（**零参数**） | 包内 `StreamingAssets/deploy.args`（出包时烙入） |
| 同机第二客户端 | `Test.exe -device.id ed-b` | 命令行覆盖（否则与编辑器落同一游客账号） |

**前提**：本机 WireGuard 隧道已建立——`curl.exe -s http://10.8.0.1:5000/live` 返回 `live`。没隧道时的表现是登录 `/Network` 失败，**不是"服务器没开"**。

**出包**（只有改客户端代码/Lua/prefab/美术、或改共享源集/表源时才需要）：

```powershell
python scripts/build/build-player.py --profile BuildProfiles/windows-x64-closedtest.local.json
```

> 别用默认 profile 出包：`endpoints: {}` 会**删除** `Assets/StreamingAssets/deploy.args`，编辑器下次 Play 变成"未配置服务器"。

### 5.2 操作步骤

| 步 | 操作 | 期望 |
|---|---|---|
| 1 | 编辑器 Play / 双击 exe（零参数） | 登录页版本行 = 云上 `buildHash` |
| 2 | 「游客一键登录」 | 进大厅、显示账号短号 |
| 3 | 选图 + 人数 →「创建房间」 | 房间页，席位 1 人 |
| 4 | **单人**：首个入座者即 owner →「开始对局」 | 开局（`ExecuteStartEarly` 无人数下限） |
| 5 | **双人**：第二人登录 → 大厅列表点房（列表 1 s 自轮询，房间心跳 1 s；仍建议先建房再登录） | 双方 `2/2` |
| 6 | 正常打完（standard：20 杀或 180 s） | 结算页 → 大厅「战绩」有行 |

### 5.3 云端测试房（开发者，非测试者路径）

1. 本机以开发者配置启动（`deploy.args` 或命令行带 `-room.gmkey=<口令>`；模板不用带，GM 页固定用 `sandbox`）；
2. 登录进大厅 → 编辑器 Hub → GM 页「本地测试模式」→「云端测试房（sandbox）」；
3. 选地图 →「创建并进入云端测试房」→ 隐藏房建房成功，房号回填到 GM 规则区；
4. 需要免死/无限弹药时在同页下发 `/gm/rules`；测试房不做结算。

> 云端测试房每次加入都需要 `template=sandbox` + `room.gmkey`，测试者包不带口令 ⇒ 这是开发者专属房间；测试者日常联机走普通房。

卡住时的兜底（GM）：

```powershell
python scripts/deploy/gm.py --action rooms
python scripts/deploy/gm.py --action start --room <房号>
python scripts/deploy/gm.py --action kick  --room <房号> --player 1
```

## 6. 观测

- 服务端：`C:\litegame\room\out.log`（`[GM]` 审计 / 结算 / Lobby 注册横幅）、`/metrics`（房间数、丢包、重连）。
- 本机看 metrics：`ssh -N -L 19100:10.8.0.1:9100 litegame-cloud-tunnel` → `http://127.0.0.1:19100/metrics`（**本机别用 9100/9101 作转发端口**——落在 Windows 排除区间 9014-9113；公网 22 已关，务必用隧道别名）。
- 客户端：release 包无 DevHUD（`developmentBuild: false`），看页内提示/Toast 与 `Player.log`。

## 7. 收尾：验结算

1. 用**普通房**（`standard`）打完一局 → 结算页 → 大厅「战绩」有行；云端测试房（`sandbox`）不结算，不要拿它验结算；
2. 云上若仍是旧配置（横幅 `default=sandbox`），先重新上传 `deploy/roomserver.windows.json` 并重启 `LiteGame-Room`；
3. 也可 `gm.py --action settle-flush` 立即回灌 Outbox。

## 8. 高频坑

| 症状 | 原因 / 处置 |
|---|---|
| 签票 `409 version-mismatch` | 两端 `buildHash` 不同 → 重发产物或重打包 |
| 开局即拒 | 表摘要不同源 → `Luban/gen.bat` + 重建 + 重打包 |
| 登录 `Insecure connection not allowed` | 包不是用当前 profile 出的（HTTP 开关构建期烙定） |
| 同机两客户端同一账号 | 各给不同 `-device.id` |
| 大厅看不到对方的房 | 列表 1 s 自轮询 + 房间心跳 1 s；仍建议先建房再登录 |
| 配置改了但端点/模板没变 | 只重启了任务、没上传新配置；或改的是 C# 却只重启任务 |
| `ssh` 突然 `Connection timed out` | 出口 IP 变了（安全组只放行旧 `/32`）或 sshd 停了 → 控制台核对；`ping` 通不代表 22 通 |
