# 烘焙工具箱专项设计

> **版本**：v2.0（2026-10-31）
> **权威层级**：专项设计（第 3 层）——不得违反《商业级通用客户端框架总设计》。
> **边界**：本文只裁决**工具形态与操作**（入口、执行面、单源、工作流）；判定几何与数值语义的权威在《第三人称越肩射击方案专项设计》（双柱判定/比例单源/逻辑枪口常量的**为什么**），本文只回答**怎么烘、去哪烘、烘出什么**。
> **吸收登记**：本文件吸收了《施工进度/射击单口径.md》三节纯工具操作记录（爆头带调带工具/枪口烘焙/身位烘焙——原文存档于 [归档记录/2026-10-10](../../归档记录/2026-10-10/README.md)）与《开火站姿与换弹动画》中持枪偏移烘焙的代码注释知识（"为什么跟随右手"）。

## 1. 定位

六件编辑器工具分三族：**prefab 采样族**（身位圆柱/枪口偏移/持枪偏移/爆头带调带——共享 `Player(Rifle).prefab` + `Rifle_Controller.controller` 与参考姿态 AimIdle t=0）、**片段采样族**（根位移——共享 `RootMotionBakeConfig.asset` 逐动作登记）与**场景采样族**（地图——来源是地图场景 `Arena01.unity`，产物为 Luban 数据源 JSON）。

产物形态按**消费面**分三类，不再产出生成代码：

| 产物形态 | 落点 | 消费面 |
| --- | --- | --- |
| **表行**（`#combatgeom` 13 列中的 7 列） | `Luban/Data/#combatgeom.xlsx` 单数据行（`id=1`） | 跑 `Luban/gen.bat` 后 `Combat/tbcombatgeom.bytes` 进判定面，两端装载为 `CombatValues.Geometry` |
| **二进制数据文件**（`grip.bin` / `rootmotion.bin`） | `Assets/GameData/Config/runtime/` | 内容包内 `TextAsset`（导入层 Base64 承载），运行时各装载器解析 |
| **Luban 数据源 JSON**（地图） | `Luban/Data/Map/map_<图>.json` | 跑 `Luban/gen.bat` 后 `Map/tbmap.bytes` 进判定面 |

`#combatgeom` 的 13 列里只有 7 列是烘焙产物（`body_radius`/`hitscan_height`、`muzzle_fwd`/`muzzle_right`/`muzzle_height`、`head_ratio`/`head_radius`）；其余 6 列（`hitscan_radius`/`headshot_damage_shift`/`hip_spread_factor`/`corpse_frames`/`hard_max_speed`/`face_turn_rad_per_sec`）是数值裁决值，由表源直接维护（对局内试调走 §3.1 的调参面）。不存在"烘完还要手改生成文件"的中间态。

代码落点：`Assets/LiteGame/Editor/Baking/`（程序集不变，仍 `LiteGame.Editor`）。

| 文件 | 职责 |
|---|---|
| `BakeTargets.cs` | **共享单源**：目标资产路径/参考片段/各产物输出路径（三族分节）+ `FindDeep` + `LoadReferenceClip` + `PrefabEditScope`（Load→Unload 编辑域收口）+ **`WriteArtifact`（文本产物写盘：write-if-changed）**与 **`WriteArtifactBytes`（字节产物写盘：write-if-changed）**——工具内禁再手写裸 `File.WriteAllText`/`WriteAllBytes` |
| `BakingToolbox.cs` | 统一窗口：六页（身位圆柱/枪口偏移/持枪偏移/爆头带调带/根位移/地图），每页＝前提说明 → 执行 → 报告区 |
| `BodyCylinderBaker.cs` / `MuzzleOffsetBaker.cs` / `HeadHitLineTuner.cs` | prefab 采样族：几何烘焙写 `#combatgeom` 表行（经 `CombatGeomTableWriter`），`HeadHitLineTuner` 是交互调带器（`Activate/Deactivate/DrawGUI`，`Export` 同时被 GM 面板复用） |

| `SimParamsExporter.cs` | 判定参数调参面的落表出口：把 `SimParamsOverrides` 的非空列经 `CombatGeomTableWriter` 写回表源（默认 dry-run） |

## 2. 统一形态（红线）

| 面 | 统一后 |
|---|---|
| 入口 | **`LiteGame/工具链` Hub → 烘焙工具箱**（run_script 仍可直调各类 `All()` / `HeadHitLineTuner.Export` / `SimParamsExporter.TryExport`） |
| 执行面 | 静态 `All() → string` 多行报告；**预期失败返回 `ABORT …` 报告，不抛异常** |
| 失败兜底 | 工具箱 `Run()` 内 try/catch 转报告（防御层；工具本体不应再抛） |
| 常量 | 路径/片段/输出路径**只存在于 `BakeTargets`**；工具与报告一律引用常量，不写字面量 |
| 产物写盘 | 文本/字节两类产物**只走 `BakeTargets.WriteArtifact` / `WriteArtifactBytes`**（write-if-changed：同字节不动文件——重烘不产生无意义 diff）；表行产物**只走 `CombatGeomTableWriter`**（进程边界助手 + 备份） |
| 原语 | `FindDeep` 一份；`PrefabEditScope` 统一 Load/Unload 纪律；`LoadReferenceClip` 一份 |
| 报告留痕 | 工具箱执行即 `Debug.Log("[BakingToolbox] …")`，报告区同步显示 |
| 消费面 | 产物只经**表装载**（`CombatValues.Geometry`）或**内容包数据文件**（`grip.bin`/`rootmotion.bin`）进入运行时——不生成 `.g.cs`、不存在"改生成文件"的路径 |

### 3.1 表源读写边界与调参面

`#combatgeom` 是一张**单行表**（表头 3 行 + 数据行 `id=1`），13 列与 `CombatGeometry` 构造参数一一对应：

```text
body_radius  hitscan_height  hitscan_radius  head_ratio  head_radius
muzzle_fwd   muzzle_right    muzzle_height   headshot_damage_shift
hip_spread_factor  corpse_frames  hard_max_speed  face_turn_rad_per_sec
```

- **烘焙写入**（身位/枪口/爆头带三页）只改自己那几列，其余列原样保留；写入经 `CombatGeomTableWriter.TryWrite`（默认 dry-run，`confirm` 才落盘，助手自带 `Temp/combatgeom-backups/` 备份与 diff 回报）。
- **写完不自动跑 Luban**：必须手动 `Luban/gen.bat` → `python scripts/codegen/toolbox.py build-hash`，两端重建后新值才生效。表字节进判定面摘要，因此改表即改联机身份。
- **调参面**（`SimParamsOverrides` / `SimParamsGate` / `SimParamsActivation` / `SimParamsDebugTunables` / `SimParamsExporter`）与烘焙器是**同一条表源的两种写法**：调参面只写内存覆写（13 列可空、零引擎、不落盘、不进摘要），`SimParamsExporter` 负责把非空列经 `CombatGeomTableWriter` 落回表源（默认 dry-run，报告给出逐列 before → after、备份目录与后续命令）。整数列（`headshot_damage_shift`/`corpse_frames`）按无小数点格式化，其余按 `R` 格式逐位往返。
- **生效边界**：覆写只在"本地测试模式 ∧ 本地服传输"的进房时点求值一次（`SimParamsActivation.Resolve` 是唯一求值点，结果同时喂客户端预测读口与本地服房间数值——两端逐字段同值）；联机/云端恒不合并。**对局中改滑杆不生效**，下一局才生效。

### 3.2 数据文件的导入（`bin`）

`.bin` 在本引擎版本被导入为 `UnityEditor.DefaultAsset`：YooAsset 拒绝打包、运行期取不到字节，而 `TextAsset` 无 `byte[]` 构造。故工具箱提供 `BinTextAssetImporter`（`[ScriptedImporter(1, "bin")]`）：**磁盘保持原生二进制**（摘要直接对字节算 SHA-256），资产层以 Base64 `TextAsset` 承载——内容包里它和 `.bytes` 表数据同一通道。

运行时装载点：`BattleViewRig.LoadAsync` 经 `IContentService` 取 `TextAsset` → `Convert.FromBase64String` → `WeaponGripCatalog.Load` / `RootMotionCatalog.Load`。降级口径不同：`grip.bin` 缺失/损坏 = 警告 + 持枪约束退化（片段曲线驱动）；`rootmotion.bin` 缺失/损坏 = **fail-fast**（内容包必备件，对局不可继续）。

## 5. 标准工作流

1. **前提**：`Player(Rifle).prefab` 本地在位（不入 VCS——缺包从派发渠道还原）；缺 prefab 时各页给出警告与 ABORT 报告。
2. **调/烘**：打开 `LiteGame/工具链` → 烘焙工具箱 → 对应页执行；交互页（爆头带）在 Scene 视图拖带后点导出。
3. **收尾**（★ 均为修改指南红线联动）：
   - **表行产物**（`#combatgeom` 的 7 列）→ 手动 `Luban/gen.bat` → `python scripts/codegen/toolbox.py build-hash`；`Combat/tbcombatgeom.bytes` 进判定面摘要 ⇒ 两端必须同批重建，否则握手/准入拒进房；
   - **`.bin` 产物**（`grip.bin`/`rootmotion.bin`）→ 只进内容包，不进 BuildHash 源集；`WriteArtifactBytes` write-if-changed：值未变的重烘不动文件、资产层 Base64 不变；
   - **地图 JSON** → 手动 `Luban/gen.bat` → `gen-build-hash.py`；`Map/tbmap` 入判定面 ⇒ `.bytes` 两端同批发布；改场景重烘后联动更新 `TestMaps.Arena01` 快照锚（L1 会指出）；
   - 身位几何变化 → SimChecksum 基线重录（L1 会指出）；夹具 `BodyCc.json` 同批入库（三方对账与地图出生点校验都读它）。
4. **实机复核**：测试模式 + GM 面板（「判定参数」组 13 滑杆试几何 / 「持枪幅度」/ 爆头带可视化）。

## 6. 扩展约定（新增烘焙工具）

0. **三族归属**：prefab 采样族（来源=PrefabPath+Controller）、片段采样族（来源=配置资产逐动作登记）与**场景采样族**（来源=地图场景）并存。产物写盘红线按**形态**分：表行→`CombatGeomTableWriter`；文本数据→`WriteArtifact`；字节数据→`WriteArtifactBytes`。报告面统一走 `All()→ABORT`。
1. 落 `Baking/`，命名 `<对象>Baker`；目标/输出常量进 `BakeTargets`，禁私有复制。
2. 执行面：静态 `All() → string`，预期失败返回 `ABORT …`，不抛异常；采样 prefab 走 `PrefabEditScope`；**写盘只走 `WriteArtifact`/`WriteArtifactBytes`/`CombatGeomTableWriter`**（禁裸 `File.WriteAllText`/`WriteAllBytes`）。
3. 工具箱加一页（`Tabs` + `DrawXxxPage`：前提说明 → 执行 → 报告）；交互型工具照 `HeadHitLineTuner` 的寄宿件形态（`Activate/Deactivate/DrawGUI`）。
4. 本专项设计 §4 清单加一行；施工进度记录批次证据。
