# 局外背包客户端专项设计

> 状态：草案
> 版本：0.1
> 更新日期：2026-11-02
> 适用范围：`Assets/LiteGame` 客户端侧——局外背包（Profile Inventory）与装备页的页面形态、视图模型、交互、一致性与性能口径
> 维护责任：客户端 UI / 游戏业务架构
>
> **定位**：回答"局外背包在客户端长什么样、数据怎么流、在真实数据规模下为什么不会卡"。
> **不做的事**：不裁决物品/背包/结算的业务规则（归[《游戏业务系统总设计》§7.2](游戏业务系统总设计.md)）；不裁决 UI 运行时、导航、生命周期与通用性能预算（归[《UI 系统总设计》](../客户端/UI系统/UI系统总设计.md)）；不定义 `ProfileService` 的存储形态与 `revision` CAS 语义（归[《Meta 服务专项设计》](../架构/Meta服务专项设计.md)）。
> **冲突裁决**：本条与下列文档冲突时，按"业务规则 → 业务总设计 §7.2；UI 运行时与预算 → UI 系统总设计；持久化与幂等 → Meta 服务专项设计；范围口径 → 玩法策划总设计"取权威，本文只在客户端实现形态上补充，不覆盖任何上游裁决。

## 1. 定位与边界

### 1.1 本文回答什么

局外背包是客户端侧**覆盖面最广的单页业务**：它同时消费配置表、持久化读模型、UI 运行时、虚拟列表、异步资源、输入/拖拽与错误反馈六条链路。把它做成生产级，等于给客户端框架找到第二个真实消费者（第一个是对局 HUD）。

本文只定义四件事：页面结构、数据与视图模型、交互状态机、性能口径。

### 1.2 不做的事

- 不定义物品分类/品质/经济数值——进 Luban 表，见[《玩法数值与Luban配置专项设计》](玩法数值与Luban配置专项设计.md)。
- 不定义 `POST /inventory/command` 的报文与服务端事务——见业务总设计 §7.2。
- 不定义 UI 运行时、导航单写者、模态栈、缓存策略——见 UI 系统总设计 §5。
- 不做交易/拍卖/装备随机词条/耐久/负重——业务总设计 §12 的"首版不做"继续有效。

### 1.3 与玩法范围、模型的关系

[《玩法策划总设计》](玩法策划总设计.md) 的反目标列有"不做复杂背包与负重"，那是**竞技首版灰盒切片**的范围。单人大世界玩法启用后该反目标不再约束物品系统，但正式解除仍需一次范围裁决。

本文只定义**客户端实现形态**。数据结构、容量规则、权威归属与持久化归[《物品与容器系统专项设计》](物品与容器系统专项设计.md)，本文不复制。

规模口径覆盖两档：**背包页**（≤200 实例，一次给全）与**仓库页**（数千实例，分页/索引）。两档判据不同，见 §4.2。

### 1.4 为什么它是客户端首个完整垂直切片

选型判据不是"好不好玩"，而是**能否在单页内把客户端六条链路全部走通并留下可度量证据**：配置表 → 读模型 → 视图模型 → 绑定 → 虚拟化渲染 → 异步资源 → 反馈面。任一条断掉，验收就红。

## 2. 依赖、输入输出与数据流

### 2.1 依赖

| 依赖 | 内容 | 缺失时的退化 |
| --- | --- | --- |
| 配置表 | `#item.xlsx` → `tb_item`（列定义见[物品与容器系统专项设计](物品与容器系统专项设计.md) §3） | 页面不可用（fail-fast），不造占位物品 |
| 读模型 | 服务端下发 `containers[]{revision, kind, slots[]}` + `loadout{revision, ...}` | 空态页 + 重试入口 |
| UI 运行时 | `UINavigationController`（唯一开关写者）、`VirtualList`、`PrefabLeaseCache` | 页面不可打开 |
| 资源 | 图标图集、字体、页面 prefab（走收集目录与租约） | 单格图标缺省占位 + `Log.Warning` |
| 输入 | `UIInput`（设备源 + 上下文门） | 拖拽不可用，键盘导航仍可用 |

### 2.2 输入输出

- **输入**：读模型快照（低频全量）、`revision` 变更通知（低频增量）、用户手势（高频，仅在页面内）。
- **输出**：唯一写口 `POST /inventory/command`（`operationId` + `expectedRevision` + command），以及纯客户端的视图态（筛选/排序/滚动位置，不上行）。
- **必须联网**：断线时页面降级为只读，写入口禁用并给出明确提示；恢复后按 `revision` 重拉，不重放已放弃的乐观态。

### 2.3 数据流

严格按 UI 系统总设计 §5.8 的更新分级（[数据流](../客户端/UI系统/UI系统总设计.md#ch-data-flow)），本页的落点是：

```text
ProfileService 快照/增量
        │
        ▼
InventoryModel (C#)  ── 只读视图模型：id → 行数据，稳定 key = slot
        │  (离散事件，值变才记脏)
        ▼
Page Logic (C# UIBindBase 或 Lua)  ── 命令式 SetList / 局部 SetText
        │
        ▼
VirtualList 行控件（复用池）
```

- **高频物不进 Lua**：滚动与行绑定只在 C# 侧完成；Lua 只做低频编排（页签切换、弹窗）。
- **列表整表替换 + 稳定 key**：禁止每个滚动帧跨语言 `Bind`（UI 系统总设计 §5.8）。
- **同一属性只有一个写者**：绑定与命令式互斥。

## 3. 客户端结构

### 3.1 页面区域

| 区域 | 职责 | 刷新时机 |
| --- | --- | --- |
| 页签/筛选栏 | 类别、品质、搜索 | 用户操作 |
| 物品网格 | 虚拟列表，`slot` 稳定 key | 数据变更 / 筛选结果变更 |
| 详情面板 | 选中物品的属性与可用动作 | 选中变更 |
| 装备栏 | 武器 ×2、动作 ×3、消耗品 ×4 | `loadout.revision` 变更 |
| 操作条 | 使用/装备/卸下/丢弃 | 选中变更 + 可用性重算 |

### 3.2 数据面

结构与容量规则不在此重复，见[《物品与容器系统专项设计》](物品与容器系统专项设计.md) §2～§6。客户端只承担三件事：

- **只读映射**：`ItemDef` 按 `id` 直接下标寻址（禁止热路径字典查表）；`ItemInstance` 原样映射，客户端不推导绑定、有效期或堆叠规则。
- **视图容器**（`BagView`）：把服务端 `Container` 投影成"行数组 + 稳定 key"；容量、堆叠上限、可堆叠判据全部从定义与服务端策略取，客户端不写死数字。
- **本地预判**：拖拽落点合法性用同一套容量规则做**只读预判**，结果只用于即时反馈，不构成权威结论。

### 3.3 视图模型

`InventoryModel` 持有三份数据：全量槽位、当前筛选结果（`int[]` 索引数组）、当前可见窗口。筛选与排序**只在数据或条件变化时重算一次**，结果缓存为索引数组；滚动不触发重算。

排序键在定义里声明为有序元组（如 `rarity desc → type asc → acquireTime desc`），保证同输入同输出——这不是确定性要求，而是**可测性要求**：排序结果可被用例钉死。

### 3.4 交互：拖拽状态机

| 状态 | 进入 | 允许的转移 |
| --- | --- | --- |
| `Idle` | 初始 / 提交结束 | `Dragging` |
| `Dragging` | 按住并越过拖动阈值 | `Commit` / `Cancel` |
| `Commit` | 指针松开且落点合法 | `Idle`（发请求后进入乐观态） |
| `Cancel` | ESC / 指针离开窗口 / 落点非法 | `Idle` |

纪律：

- **拖起不发请求**；只有 `Commit` 才产生一次写命令。
- 落点合法性**本地先判**（容量、可装备槽、绑定状态），非法落点给出即时反馈而不是等服务器拒绝。
- 一次拖拽携带唯一 `operationId`；重试必须复用同一 `operationId`。
- 拖拽中禁止页面切换与列表重排；落点高亮只用已缓存的行矩形，不触发重新布局。

### 3.5 一致性：乐观更新与冲突

| 场景 | 行为 |
| --- | --- |
| 正常提交 | 本地先应用（乐观）→ 收到新 `revision + delta` → 以服务端 delta 覆盖本地占位 |
| `revision` 冲突 | **丢弃本地待提交队列 + 全量重拉 + 提示重试**；禁止客户端自行合并（业务总设计 §7.2 明确） |
| 请求超时 | 保持乐观态但标记"未确认"，超时上限到达后回滚到最近确认快照 |
| 断线 | 立即冻结写入口（页面转只读）→ 恢复后按 `revision` 重拉 → 丢弃全部未确认乐观态，不重放 |
| 重复响应 | 按 `operationId` 去重，重复结果不二次应用 |
| 页面关闭 | 取消展示期异步；迟到结果按 `DisplayGeneration` 丢弃（UI 系统总设计 §5.10） |

## 4. 性能口径

### 4.1 预算来源

通用预算的唯一权威是 [UI 系统总设计 §11](../客户端/UI系统/UI系统总设计.md#ch-quality)（稳定帧 UI CPU、0 B/帧、打开主线程工作、单页 DrawCall、列表节点数随视口容量）。本文**不复制那张表**，只把它落到本页的具体口径与验证手段上。

阈值遵循[《性能工程专项设计》](../测试与性能/性能工程专项设计.md) §1 的"先测后定"：下表为占位初稿，基线产出后回填实测值加余量，并落常量表由测试钉住。

### 4.2 本页判据

| 编号 | 指标 | 口径 | 初稿阈值 |
| --- | --- | --- | --- |
| INV-P1a | 背包页打开耗时 | ≤200 实例、冷缓存 | 单帧主线程 ≤16 ms，记录 p95 |
| INV-P1b | 仓库页打开耗时 | 5000 实例、冷缓存 | **不随规模增长**：首屏只建可容量节点，其余分页/索引；单帧 ≤16 ms |
| INV-P2 | 滚动托管分配 | 稳定滚动，每渲染帧 | 0 B |
| INV-P3 | 滚动帧内 UI CPU | 400 格数据 | ≤0.5 ms 增量（占 §11.1 稳定帧预算的一部分） |
| INV-P4 | 行节点数 | 任意数据规模 | 只随视口容量 + overscan，不随数据量 |
| INV-P5 | Batches / SetPass | 打开态 | 不随数据量线性增长；上限对齐 §11.1 单页口径 |
| INV-P6 | 拖拽命中判定 | 单次指针移动 | ≤0.1 ms，且不触发布局重建 |

**反例判据**：任何一项随"数据量"而非"可视量"增长，即判定为实现缺陷，不是调优空间。

### 4.3 五个热点与手段

| 热点 | 坏形态（可观测） | 手段 | 观测点 |
| --- | --- | --- | --- |
| 合批失效 | Batches/SetPass 随格数增长 | 虚拟化只留可视；动静分层 Canvas；关闭无用 `raycastTarget` | Frame Debugger；`UI.Batch` marker |
| 布局重建 | 打开尖峰随格数增长 | 固定尺寸；禁用嵌套 `LayoutGroup`/`ContentSizeFitter`；避免 `ForceUpdateCanvases` | `UI.Layout` marker |
| 托管分配 | 滚动期 `GC.Alloc` 非 0 | 增量刷新；格式化结果缓存；零闭包；数量文本预分配缓冲 | `ProfilerRecorder(GC.Alloc)` |
| 复用串号 | 快速滚动后图标/数量错位 | 稳定 key + `DisplayGeneration` 代次核对；异步返回先验代次再写 | 快速滚动截图矩阵 |
| 文本重建 | 数量/有效期逐帧 `SetText` | 值真变才写；批量合并写；禁止逐帧写 | `Text` mesh 重建计数 |

### 4.4 度量手法

- **ProfilerMarker 命名对齐 §11.4**：`UI.Show` / `UI.Init` / `UI.Commit` / `UI.Close` / `UI.Bind` / `UI.Scroll`，本页新增 `UI.Bag.Sort`、`UI.Bag.Filter`。
- **计数走 `IModuleStats`**：行节点数、复用命中率、异步图标命中/取消数、待确认写命令数。
- **分配用采样而非均值**：滚动期按 `ProfilerRecorder(GC.Alloc)` 取每帧值，判 `max == 0`。
- **证据口径**：结论必须带构建身份、数据规模、设备档与 Profiler 截图；"感觉顺了"不构成证据。

## 5. 失败语义

沿用 UI 系统总设计 §5.11 的错误契约，本页补充业务级分支：

| 情况 | 分类 | 客户端行为 |
| --- | --- | --- |
| 页面资源加载失败 | `LoadFailed` | 反馈面提示 + 可重试；不留半开页面 |
| 页面初始化失败（表缺失/读模型解析失败） | `InitFailed` | fail-fast 到错误页，不进入降级渲染 |
| 命令被拒绝（不可堆叠/槽位满/绑定） | `Rejected` | 回滚乐观态 + 就地提示，不弹全屏 |
| `revision` 冲突 | `Rejected`（专用码） | 丢弃本地队列 → 全量重拉 → 提示重试 |
| 服务忙碌 | `Busy` | 禁用写入口，保留只读浏览 |
| 操作被新操作取代 | `Canceled` | 静默回滚，不提示 |
| 请求超时 | `Timeout` | 标记未确认 → 到上限回滚 → 提示重试 |

程序员错误（越界槽位、空引用）一律 fail-fast，不做容错吞掉；内容缺失走 `Log.Warning` + 默认占位。

## 6. 交付顺序与退出条件

> 本节只定顺序与判据，不记录完成状态；状态归 `Docs/施工进度/`。

| 批 | 范围 | 退出条件 |
| --- | --- | --- |
| 1 | 数据面：`#item.xlsx` + `ItemDef`/`ItemInstance`/`BagView` 纯逻辑（dotnet L1，零 Unity 依赖） | 堆叠/拆分/容量/可装备判据/排序的边界用例全绿 |
| 2 | 页面骨架：脚手架生成页面 + 契约 + 绑定；静态假数据渲染 | 可开可关；导航只经单写者；契约无漂移；prefab 根契约用例通过 |
| 3 | 虚拟化与预算：`VirtualList` 接入、复用池、代次核对 | INV-P2/P4/P5 达标；节点数不随数据量增长 |
| 4 | 交互：拖拽/双击/右键/键盘；非法落点与中途取消 | 全路径经**真实指针模拟**驱动通过（见 §7 L4） |
| 5 | 一致性：乐观更新 + `revision` 冲突 + 超时 + 重复 `operationId` | 注入冲突/超时/重复响应，视图态不脏、无幽灵物品 |

批 1 不碰 Unity：业务规则在 dotnet 侧测，反馈是秒级，这是规则层最快的循环。

## 7. 测试层级

| 层 | 范围 | 判定 |
| --- | --- | --- |
| L1 纯逻辑 | 堆叠/拆分/容量/排序/可装备判据/乐观态应用与回滚 | 边界用例全绿；同输入同排序结果 |
| L2 EditMode | prefab 根契约、命名、绑定 hash、契约漂移、图集/字体引用 | 正例绿 + 违规负例红，报告可定位节点 |
| L2 PlayMode | 真 `UIService` + 真页面开关复用、虚拟列表滚动、拖拽、语言切换、页面关闭清理 | 可见可点且数据正确；无迟到写入；订阅/对象归零 |
| L4 Player | 400 格真实数据、低内存、前后台、快速滚动、长时操作 | 达到 §4.2 判据且有构建/Profiler/截图证据 |

**真机验证口径**：交互面必须按真实指针/键盘模拟驱动（入口 → 操作 → 副作用断言），先做可点性自检再模拟点击，不以直调 API 冒充"操作过"。
