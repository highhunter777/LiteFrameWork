# 生成器工具箱专项设计

> **版本**：v1.0（2026-10-11）　**权威层级**：专项设计（第 3 层）——不得违反《商业级通用客户端框架总设计》/《商业级通用服务端框架总设计》。
> **边界**：本文只裁决**生成器工具形态与操作**（入口、执行面、单源、失败语义、工作流）；各生成物的**语义权威在位不动**——buildHash 闭包与 Join 握手在《状态同步专项设计》、协议语义在 `battle.proto` 单源、同步分层在《Sim组织专项设计》/《状态同步专项设计》、表链在《玩法数值与Luban配置专项设计》。本文只回答**怎么生成、去哪生成、生成什么、忘了会怎样**。
> **吸收登记**：本文件吸收了 `scripts/README.md` 的 codegen 操作知识（Luban 暂存/发布段与生成链行——原文照录 [归档记录/2026-10-11](../../归档记录/2026-10-11/README.md)）与 `gen-proto.ps1` 中文头注释（protoc 来源/版本对齐约束，正文吸收进 §2/§4）。五件工具头注释保留各自 why，操作面收口本文。

## 1. 定位

五件 CLI 生成器是"两端同源"红线的执行面：buildHash 是 Join 握手版本红线，`gen-sync-code` 根治"加一个字段手抄六处"的静默分叉，`gen-luban` 是表源到双端产物的唯一通道。2026-10-11 前它们形态分散——Python/PowerShell 混用且约定不一、无共享单源（仓库根推导各写一份）、失败口径三套（`throw` 带栈 / `exit 1` / 异常冒泡）、输出无统一前缀、操作知识散落在 scripts/README、修改指南与脚本头注释三处。统一为**一个工具箱入口 + 一份共享单源 + 一种执行形态**。

代码落点：`scripts/codegen/`（工程脚本，不入 Unity 程序集）。

| 文件 | 职责 |
|---|---|
| `_common.ps1` | **共享单源**：仓库根推导（`Get-CodegenRepoRoot`）+ 统一输出三档（`Write-Tool`/`Write-ToolWarn`/`Write-ToolFail`，前缀 `[codegen/<tool>]`）+ 内容哈希（`Get-FileSha256Base64`，发布跳过同字节文件） |
| `toolbox.ps1` | 统一入口：无参列工具索引；`toolbox.ps1 <tool> [args...]` 转发参数与退出码 |
| `gen-build-hash.py` | buildHash 生成 + `--check` 校验（**规则单源**，Python 独立维护——规则只有这一份，无第二清单入口） |
| `gen-proto.ps1` | `battle.proto` → `Proto/Generated/Battle.cs` |
| `gen-luban.ps1` | 表链重生成（C#/binary/lua/LuaKeys；Assets 外暂存 + 只发布变更文件） |
| `gen-sync-code.ps1` | `[StateLayer]` 标注 → `EntitySlot.Sync.g.cs`（checksum 脚手架） |
| `refresh-hash.ps1` | 刷新编排：生成 → RoomServer 重建 → Unity 重编译 → 双端对账 |

## 2. 统一形态（红线）

| 面 | 统一后 | 原状态（已消灭） |
|---|---|---|
| 入口 | **统一入口 `pwsh scripts/codegen/toolbox.ps1 <tool> [args...]`**；单脚本直调保留（`build-player.ps1` 门禁、`Luban/gen.bat` 委托等既有消费面不动） | 五脚本各自为政、无索引，入口只存在于口口相传与文档散落 |
| 执行面 | 每工具一个 `Invoke-<Xxx>` 主函数 + 尾部 `try/catch` 收口；前提缺失（缺 protoc/缺 Luban.exe/缺参数）抛**带用法信息**的错误 | 顶层散装执行；gen-proto 的 `Mandatory` 参数在缺参时触发交互式提示（CI 挂死形态） |
| 失败兜底 | 预期失败＝**一行 `[codegen/<tool>] FAILED: ...` + exit 1**（不冒栈、不静默）；校验/对账类同契约（mismatch 即 exit 1） | 三套并存：`throw`（栈噪声）/ `exit 1` / 异常冒泡 |
| 常量 | 仓库根推导只在 `_common.ps1`；SHA256 内容哈希只在 `_common.ps1`；各工具 I/O 路径仍在各自脚本（各自单源） | 根推导手写 ×4；SHA256 内联在 gen-luban |
| 输出 | 统一前缀 `[codegen/<tool>]`，成功/警告/失败三档 | 无前缀，中英混杂，成功消息三样（`已生成`/`generated`/`BuildHash.g.cs written`） |
| 编码 | **ASCII-only**（PS 5.1 对非 BOM UTF-8 的 GBK 误解析陷阱；scripts/README 约定升为工具箱红线） | gen-proto 中文 BOM 注释（中文知识已吸收进本文与新 ASCII 头） |
| 头注释 | 五段式：用途（why）/ 入口（工具箱 + 直调）/ 输出 / 重跑时机 / 消费点；**why 留在脚本头，操作面收口本文** | 长短不一：三份长头各说各话，两份无完整头 |

**消费面兼容（本批不改）**：`build-player.ps1` 出包门禁仍直调 `gen-build-hash.py --check`（只认 exit code）；`Luban/gen.bat` → `gen-luban.ps1` 委托不变；`refresh-hash.ps1` 内部调 `gen-build-hash.py` 不变；CI（`ci.yml`）不直调任何生成器。工具箱只提供统一入口与索引，不改写任何调用。

## 4. 工具清单

| 工具 | 输入 | 输出 | 重跑时机 | 消费点 | 忘跑后果 |
|---|---|---|---|---|---|
| `build-hash` | Sim/协议/表源文件内容（源集见脚本头注释） | `Assets/LiteNet/Protocol/BuildHash.g.cs`（16 位 hex 常量） | 改 `LiteSim/Core/{Scripts,Systems}`、`LiteNet/{Proto,Protocol,Transport/Security}`、玩法表后 | Join 握手（`JoinRequest.build_hash`）+ 启动期断言 | 两端 hash 不等 → **Join 被拒进房** |
| `build-hash --check` | 同上 + 已生成常量 | 复算比对（exit 0/1） | 出包前（`build-player.ps1` 门禁步强制，不可跳过；开发期不校验） | 出包门禁 | stale 包出厂，实机两端拒进房 |
| `proto` | `Assets/LiteNet/Proto/battle.proto` | `Proto/Generated/Battle.cs`（入库，勿手改） | 改 `.proto` 后（随后 ★ build-hash） | `LiteNet/Protocol` 编解码 | 编译失败（生成物入库，无静默面） |
| `luban` | `Luban/Data/*.xlsx` + schema | `GameData/Generated`、`GameData/Config`、`Lua/Cfg`、`LuaKeys.g.cs` | 改表源/表结构后（随后 ★ build-hash） | 两端 `ConfigService`/`ServerTableLoad` | 表与代码漂移（L1 表守卫会红） |
| `sync-code` | `[StateLayer]` 标注字段（8 结构体） | `EntitySlot.Sync.g.cs`（入库，勿手改） | 同步字段/分型表结构变化后（随后 ★ build-hash） | `SimChecksum` 双口径 | **静默分叉**——漏字段不报编译错，和解假和解（生成器存在的原因，见脚本头注释） |
| `refresh-hash` | 上三者的编排 | 新常量 + 双端对账结论 | 改 Sim/协议/表后的"一键全链"（服务器重建/Unity 重编译可开关跳过，但**跳过≠免除**，Join 前必须补上） | 人工流程 | 漏重建/漏重编译 → Join 超时，症状远离真因（脚本头注释有完整病例） |

"什么改动必跑什么"的**红线权威表**在[修改指南 §2.3/§3.9](../../修改指南.md)——本表只做工具视角对照，不复制红线条目。

## 6. 标准工作流与验证层级

1. 改动涉及共享源集 → 查[修改指南 §2.3](../../修改指南.md)定位必跑工具（红线表权威）。
2. 单工具走 `pwsh scripts/codegen/toolbox.ps1 <tool> [args]`；全链刷新走 `toolbox.ps1 refresh-hash`。
3. 生成物一律入库（`Battle.cs`/`BuildHash.g.cs`/`EntitySlot.Sync.g.cs`/表产物），头注释均带 `DO NOT EDIT`；提交随源一起走。
4. 出包前 `--check` 由 `build-player.ps1` 门禁步强制，无需手工记得。
5. **本工具箱自身的验证层级**：改形态/加工具时——① 全部 `.ps1` 语法解析零错误 + ASCII-only 核验；② `toolbox.ps1` 无参索引、未知工具 exit 1、单工具转发实跑；③ 生成器逻辑改动的批次必须证明"生成物 diff 为零"（对未变源跑生成、产物逐字节不变）或走 BuildHash 重录流程；④ 红线联动照旧归修改指南 §2.3 管。

## 7. 扩展约定（新增第六件 CLI 生成器）

1. 落 `scripts/codegen/`，命名 `gen-<对象>.<py|ps1>`；.ps1 一律 ASCII-only、`[CmdletBinding()]` + **非交互参数**（禁 `Mandatory` 触发提示，缺参走显式校验 + 用法报错）。
2. 共享面只进 `_common.ps1`（根推导/输出/哈希），禁在工具内再手写同型原语；工具自身 I/O 路径在自身脚本常量（各自单源）。
3. 执行面：`Invoke-<Xxx>` 主函数 + 尾部 `try/catch → Write-ToolFail + exit 1`；预期失败一行干净报告，不冒栈。
4. 头注释五段式（§2）；`toolbox.ps1` `$Tools` 注册一行；本文 §4 清单加一行；`toolchain.json` `generators` 节同步；施工进度记录批次证据。
