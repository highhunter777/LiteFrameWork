## 1. Current 与边界

- **Current（2026-10-08）**：`Server/RoomServer/Program.cs` 为手工组合根（top-level statements）：配置装载 → CLI 覆盖 → 信封 fail-closed 判定 → 数值表装载 → 票据验签器 → `FileSettlementOutbox.Open`（续接日志）→ `CreateTransport`（KCP ∨ 信封装饰）→ `new ServerHost(...)`（11 参）→ `new ServerLoop(host)` → 两种运行形态。`ServerHost` 内部另有自建协作对象（SessionManager / ReconnectService / JoinAdmissionGate / RateLimiter / 按配置的 RoomWorkerPool），其中部分已有构造注入口（workerPool / rateLimiter / settlementOutbox / transport 等）。
- MetaServer 已是 MS DI 装配（`MetaHost.cs`：`AddSingleton` 工厂注册端口与用例、`AddHostedService` 启动迁移），RoomServer 与其装配风格不统一——本专项收敛 RoomServer 一侧。
- **范围**：`Server/RoomServer` 宿主装配层——Program/ServerHost 的装配方式、容器接入、释放序、依赖治理。
- **边界**：内核（`Assets/RoomServer/{Runtime,Application}`、`LiteSim.Core`、`LiteNet`）**零容器感知**；双编工程不新增任何 DI 依赖；`ServerHost`/`ServerLoop` 对外行为语义（装载期拒绝、排空 5 步、Worker 执行形态开关、观测计数、节拍）不变。

## 2. 裁决（2026-10-08 用户定案）

| 裁决 | 内容 |
| --- | --- |
| 容器选型 | **MS DI（`Microsoft.Extensions.DependencyInjection`）**——与 MetaServer 同族；纯 .NET 侧无 Unity/AOT 约束 |
| 形态 | **只采用容器（`ServiceCollection`/`BuildServiceProvider`），不引入 Generic Host**：RoomServer 生命周期是自研闭环（60Hz `ServerLoop`＋§12 排空链＋两种运行形态），Host 化＝生命周期重模，收益低、回归面大；二者差异（Web 托管语义 vs 游戏循环）合理保留。触发再评：出现第二宿主级消费者（如 R4 运维统一面）时另裁 |
| 不选 ServiceContainer | 其定位为**客户端统一装配件**（主线程显式单例装配器，面向 Unity 双编 AOT；2026-10-08 客户端 DI 升级新增服务域/生命周期后仍属客户端 Root 装配面）；服务端宿主选 MS DI 与 MetaServer 同族，不把双编侧框架件拖入纯 .NET 宿主 |
| 不选"全量 DI 化" | 内核不得容器化（纯化红线）；`ServerHost` 构造签名不改（嵌入式/测试直接 `new` 是既有契约，`LiteNet.Tests` 直接构造宿主）——容器在**装配层**收敛，不穿透内核 |

## 3. 目标装配形态

组合根＝Program 启动段（一次性）：创建 `ServiceCollection` → 注册（下表）→ `BuildServiceProvider`（`ValidateOnBuild`＋`ValidateScopes` **常开**——启动期一次性成本；批1 实施口径）→ 启动段 Resolve 出 `ServerHost`/`ServerLoop` → **此后不再触碰容器**。

| 装配产物 | 现状（Program.cs） | 目标注册 | 释放 |
| --- | --- | --- | --- |
| `RoomServerConfig` | `RoomServerConfig.Load`＋CLI 覆盖 | `AddSingleton(instance)` | 无 |
| `SecureEnvelopeOptions` | 由密钥装配；缺失即 fail-closed 拒启 | 非空则 `AddSingleton(instance)`；null 语义＝裸 KCP 仅 `--allow-insecure-local` 路径 | 无 |
| `IRoomTransport` | `CreateTransport`（`KcpTransportServer` ∨ `SecureEnvelopeRoomTransport` 装饰） | `AddSingleton<IRoomTransport>(factory)` | **容器**（现状 `using`） |
| `IJoinTicketValidator` | 可无（未装配＝原型告警） | 有则注册；无则由工厂 `GetService` 取可选依赖 | 无 |
| `ISettlementOutbox` | `FileSettlementOutbox.Open`（续接日志/坏行计数） | `AddSingleton<ISettlementOutbox>(factory)` | **容器**（现状 `using`） |
| `ServerHost` | `new`（11 参） | `AddSingleton(factory)`——参数自容器解析 | **容器**（现状 `using`） |
| `ServerLoop` | `new`＋`LoopStats` 接线 | `AddSingleton(factory)`（含 `host.LoopStats = loop.Stats`） | 显式 `loop.Stop()`（不变） |

- **解析序=创建序**（Program 按 `outbox → transport → host` 显式解析——**不得先解析 host**）：MS DI 按创建序**逆序**释放＝现状释放序（host→transport→outbox）；排空链（`loop.Stop()` → `host.FlushSettlementOutbox()` → 释放）仍是显式启动段代码，**不依赖容器释放**（排空第 5 步 2026-10-04 已进程级手验，语义不得变化）。
- **内部协作对象**（SessionManager / ReconnectService / JoinAdmissionGate / RateLimiter / 按配置 RoomWorkerPool）：暂保持 `ServerHost` 构造默认语义（配置形态自动创建，注入口已存在的不变）；装配层如需显式化（观测/测试注入），走既有可选参数，不新增第二套机制。**R3 新增对象一律经容器注册**（不再新增手工装配散点）。
- **运行期零解析红线**：60Hz 循环、Worker 热路径、房间生命周期内零容器调用、零容器分配；per-room 对象（RoomInstance/Runtime/Pipeline）是运行期数据不是服务，**不进容器**。

## 6. 失败语义

- fail-closed 全清单不变：缺信封密钥拒启（`--allow-insecure-local` 仅本机例外）、缺票据 key 告警不拒启、Worker 执行形态三前置装载期拒绝、"票据验证先于建房"等——装配方式变更**不改变任何装载期判定的时点与结果**。
- 装配错误固定在启动期：必填项缺失/循环依赖在 Resolve 当场抛；`ValidateOnBuild` 只覆盖构造注入口，工厂注册靠组合根启动段一次性解析暴露——错误出现在启动，不出现在房间热路径。
- 运行期容器不可达：任何"运行中解析"＝设计违例（评审拒收）。

## 8. 不做（负面清单）

- 容器进内核/双编工程；`ServerHost` 塞 `IServiceProvider`（服务定位器反模式）
- ServiceContainer / MS DI 混用；Generic Host / `IHostedService` 生命周期重模（再评触发见 §2）
- 自动扫描/属性注入/AOP/Transient 滥用；per-room DI scope；运行期解析
- 目录大搬迁；排空链与释放拓扑的任何语义变化
- 本批不涉及 MetaServer（其已是 MS DI；未来若需与 RoomServer 统一宿主形态，另裁）
