## 1. 定位与分工

状态机是框架级**机制件**（Core/Fsm，与 Pool/Event 同层，零引擎依赖、零第三方依赖）：有限状态集合上的"驻留 + 迁移"裁决器——谁在活动、何时能切、切的时候按什么序进出。三机体共用一份阶段契约（`IStage`/`IStageHost`），按场景选型：

| 机体 | 选型场景 | 现状 |
| --- | --- | --- |
| `StageMachine`（平面） | 流程驱动、UI 编排、转场——"状态少而逻辑各异" | 已有；Procedure/`UITransitionRunner` 消费中 |
| `PreemptiveStageMachine`（抢占平面） | 角色动作（格斗/ARPG）：优先级抢占 + 中断规则 + 恢复栈 | 已有；`StageSpec`+`TableStage` 表驱动配套 |
| `HierarchicalStageMachine`（层级） | 复合状态、子页历史、事件冒泡 | 已有；角色动画驱动（LiteSim）消费中 |

与相邻机制的分工（本专项边界即这张表）：

| 机制 | 分工边界 |
| --- | --- |
| 《层次动画机设计》（动画驱动层） | Core/Fsm 只管**机制**（迁移序/事务/历史/抢占）；角色驱动层的**状态树内容**（战斗/移动双根、通道接管）归动画专项，本文不改写其语义 |
| 《角色状态与动作专项设计》（gameplay） | 连段/取消窗/霸体等**玩法判定**归玩法专项；FSM 提供抢占/恢复/帧窗口/表驱动等机制原语 |
| `EventCenter`（事件） | 事件 = 已发生事实的**广播**；`Raise` = 面向当前活动状态的**定向查询**（消费/迁移裁决）。两者互不依赖：事件→迁移是业务语义决策，桥接为订阅侧一行转调（§5），Core 不做自动桥 |
| `CommandCenter`（命令） | 命令可**请求**状态动作（执行方调机器 API）；中心不持有机器 |
| Luban 配置 | Core 不引配置系统；"配置行 → `StageSpec`/迁移边"的适配器归配置/业务层（§5） |
| `ProcedureStageBase` | 异步流程阶段的 CTS/取消纪律归该基类，本专项不改写 |

**输入**：`Request`/`Raise`/`Tick`/`ForceState`/`Capture`/`Restore` + 构造期状态表与迁移表。**输出**：阶段回调序（OnInit/OnEnter/OnUpdate/OnLeave）、`IModuleStats` 与审计/驻留读取面。

红线（继承并加固）：**阶段对象 = 无状态单例**（禁实例字段，可变数据走 payload/宿主）；`TId : struct` 免装箱比较；**两段式迁移**不改（`Request` 只入队、帧末 `Advance` 应用、last-wins）；主线程 only。性能预算：**稳态零 GC**（Request/Tick/Raise/边评估不分配；审计环预分配；`Capture` 仅捕获时一次性分配）；边评估为该帧命中类型的线性扫描；恢复栈深 4（现状）、审计环 32（对齐命令中心）。

## 2. 继承基线（现状契约，本专项不改写）

- **平面机迁移语义七条**：Start 前 Tick 静默、Request 抛；Request 只入队（两段式）；同帧多次 Request = last-wins（payload 同步覆盖）；OnEnter 内 Request 写 pending 下次 Advance 生效（不递归）；重入抛；OnLeave 窗口内抛；未注册 id 抛。一帧最多一变；`StageFrames` 每次 Tick +1、迁移后归零（帧窗口判据）。
- **抢占机**：准入 = 当前阶段允许被它打断 && 来者优先级 ≥ 当前（阶段钩子内"自身推进"一律放行）；被拒返回 false 不抛（`RejectReason`/`LastReject`）；恢复栈深 4、超限丢最老并计数；`TryResume` 绕过准入。
- **层级机**：一次迁移 = 一次事务——LCA 之下先深→浅退出、再浅→深进入，同帧原子（一帧最多一次事务）；OnUpdate 根→叶；降层不重跑祖先 OnEnter；`HistoryMode` None/Shallow/Deep（退出记历史、重进按历史/初始展开，含"子态同父内切换也刷父历史"）；多根允许（跨根 = 全退全进）；事件冒泡最深→根、首个 `IEventSink` 消费即停；事务中断置 `Interrupted` 不回滚（诊断标记）。
- **表驱动**：`StageSpec` 一行 = 一个状态的数据（优先级/恢复模式/中断规则/时长帧/NextId/AutoResumeOnEnd），`TableStage` 零自身状态（驻留读 `host.StageFrames`），同实例可多机共用；时长到点优先恢复栈顶、否则走 NextId。
- **异常策略不在内核**：阶段回调不捕获（平面/层级皆然），由驱动层兜；层级机事务中断留诊断标记。
- **既有测试基线**：`StageMachineTests`/`StageMachineArpgTests`/`HierarchicalStageMachineTests` 共 1,241 行 + `UiTransitionEditModeTests`，全部保持不翻红。

## 3. 高级化契约（新增能力）

**地基完整性优先于"当前无调用方"**——以下能力全部入契约，覆盖的现实场景包括：AI 决策状态机（事件边 + 守卫 + 看门狗，暂无消费者）、帧同步回滚与存档恢复（`Capture`/`Restore`，暂无消费者）、GM 跳态与诊断（`ForceState`/审计/DOT 导出，GM 面板为后续消费端）、复合动作态的抢占恢复（层级机对齐）。**空配置时（不注册边、不挂看门狗、不调用新 API）行为与现状逐位一致——纯加法。**

### 3.1 迁移表与守卫（条件边/事件边/任意态边）

```csharp
public sealed class TransitionTable<TId, TReq> where TId : struct
{
    // 注册（Start 前完成，边 = 配置；Start 后调用抛）。声明序 = 评估序。
    void AddEdge<TEvt>(TId from, TId to, Func<TEvt, TReq> toPayload = null, Func<TEvt, bool> guard = null);
    void AddEdge(TId from, TId to, Func<bool> guard = null);                  // Tick 条件边
    void AddAnyEdge<TEvt>(TId to, Func<TEvt, TReq> toPayload = null, Func<TEvt, bool> guard = null);
    void AddAnyEdge(TId to, Func<bool> guard = null);
    // 评估由机器转调：命中 = From 匹配当前态（或 Any）&& guard 通过；声明序首个命中生效
}
```

- **事件边**：机器 `Raise<TEvt>` **先评估迁移边、后问阶段 sink**——命中即经 `RequestCore` 入队（与手动请求同通道，继承 last-wins/两段式/帧末应用）并视事件为已消费（返回 true，不再冒泡/不问 sink）；未命中维持原语义（平面问当前态、层级冒泡）。未注册事件类型 = 无边 = 零开销短路。
- **条件边**：Tick 在 OnUpdate 之后评估，**仅当本帧无挂起请求**才入队——显式请求永不被自动边覆盖；命中当帧帧末照常 `Advance`。守卫失败 = 边不触发（静默，正常路径，不计数不算拒绝）。
- **任意态边（Any）**：`From` 不限定——层级机上以**最深活动态**参与匹配；"祖先作用域"（任一活动祖先级触发）用 Any 边 + Guard 读 `ActivePath` 表达，不做专用机制（§3.6 非目标）。
- **手动请求不受迁移表约束**：`Request(target)` 目标显式，边只服务自动裁决；两者同入 pending 通道，last-wins 一致。
- **共用件**：平面机/层级机组合挂载同一 `TransitionTable`，三种边语义两机一致；层级机目标路径由树反查（与手动 Request 同管线）。
- 边 To == From（重入）构造即抛；`From`/`To`/Any 边 `To` 未注册构造即抛（§3.4）。

### 3.2 强制迁移与驻留看门狗

- `ForceState(TId, in TReq)`：**绕过准入判定**（优先级/中断规则）入队；守卫语义不涉、重入禁令/未注册抛/Start 前抛/OnLeave 窗口抛**照常生效**（编程错误不豁免）。基础机上与 `Request` 等价（恒接受）；差异在抢占型机体（绕准入）与审计标记 `Forced`。消费端：GM 跳态、看门狗升级。
- **看门狗**（可选接口 `IStageTimeout { int TimeoutFrames; TId TimeoutTarget; }`；`StageSpec` 增列同义字段，`TableStage` 代为实现）：当前阶段驻留帧数超限且无挂起 → `ForceState(TimeoutTarget)`，`TimeoutCount` 计数。定位：**驻留异常升级**（流程卡死、AI 卡态）；`UITransitionRunner` 那类**编排级超时兜底**保持现状，两者正交。机器 Tick 统一裁决（不属 TableStage 私有），在条件边之后评估（同帧边命中则看门狗让位）。

### 3.3 层级机抢占对齐（收敛三机体能力差）

抽取共用件 `PreemptionCore`（准入判定 + 恢复栈 + 拒绝上报），抢占能力三机体共享：

- `PreemptiveStageMachine` 改为转调，**语义逐位不变**（以既有 475 行 ARPG 判例为准）。
- 新增 `PreemptiveHierarchicalStageMachine<TId, TReq>`（层级机 + 抢占层）：抢占裁决问**最深活动态**——优先级（`IPriorityStage`）/中断规则（`IInterruptPolicy`）/恢复意愿（`IResumeStage`）读其可选接口；被抢占阶段按 `ResumeMode` 入恢复栈（栈存 id，`TryResume` 走层级机原生 Request 管线，路径按历史/初始展开，**无需路径快照**）；`TryResume` 绕过准入；`RejectReason` 复用四值。
- 事件冒泡 × 抢占并存：sink 消费不产生迁移；迁移裁决只来自迁移边/显式请求/看门狗。

### 3.4 快照与恢复（Capture/Restore）

```csharp
public enum FsmRestoreMode : byte { Hooks = 0, Silent = 1 }

public sealed class FsmCapture<TId>
{
    // 结构态：当前 id（层级机为活动路径）、复合历史、恢复栈、驻留秒/帧、迁移计数
}

// 平面机/层级机各自实现；层级机含活动路径与历史
FsmCapture<TId> Capture();
void Restore(in FsmCapture<TId> capture, FsmRestoreMode mode);
```

- **Hooks 模式**（默认）：复用迁移事务——分歧尾部深→浅 `OnLeave`、目标尾部浅→深 `OnEnter`（default payload），审计标记 `Restore`。用途：存档恢复、GM/测试跳态。
- **Silent 模式**：纯结构置换、**零回调**、浮点按位捕获——帧同步回滚/确定性重放（重放驱动会重新走回调）。`Restore` 同时清挂起请求（结构性裁决，挂起让位）。
- 约束：Start 前/阶段回调内/OnLeave 窗口内 → 抛；capture 内 id 未注册（机器结构已变）→ 抛——"重建后恢复"由调用方保证结构一致（§3.6 运行期改图非目标）。

### 3.5 图校验

- **构造期 fail-fast**（新增，与既有重复 id/树规则/环检测同批抛）：迁移边 `From`/`To` 未注册抛；Any 边 `To` 未注册抛；边 To == From 抛；委托 null 合法（= 恒真/default 载荷）。
- **Debug 三宏深校验**：Start 时可达性扫描（迁移边 ∪ 复合树 ∪ 时长→NextId 链），不可达阶段 `Log.Warning` 不抛（Error 态常仅边上可达，允许保留）；`DurationFrames > 0` 而无 NextId/AutoResumeOnEnd/超时目标 → 死底告警。

### 3.6 兼容红线与非目标

**兼容红线**：现有公开签名与语义逐位不变——两段式/last-wins/一帧一变（层级一帧一事务）、平面机七条迁移语义、Start 一次、重入/OnLeave 窗口/未注册抛、恢复栈深 4 丢最老、冒泡与历史语义、`IModuleStats` 既有键。空迁移表 + 未挂看门狗 + 不调用新 API = 现状逐位。

**明确不做（非目标登记）**：

- **并行区域/正交态**：无场景——表现分层归动画层通道接管，实体组合归实体分型表；双根互斥已由层级机多根 + 全退全进覆盖。
- **行为树/效用 AI**：不同机制（分支决策 vs 有限状态驻留）；AI 决策若需再立专项。
- **运行期改图**：状态集/边 = 配置，变更重建机器（同"表是配置"纪律）；`Capture`/`Restore` 覆盖"重建后恢复"。
- **祖先作用域事件边**：Any 边 + Guard 读 `ActivePath` 已可表达，不加专用匹配机制。
- **跨线程**：主线程 only（框架泵约定）。
- **编辑器图编辑工具**：`ExportGraph()` 只读导出够用；可视化编辑无场景。
- **协程/UniTask 状态体**：Core 零第三方依赖，异步阶段走 `ProcedureStageBase` 既有形态。

## 4. 统计与诊断面

- **审计环**：最近 32 条迁移（序号/From/To/Kind），预分配零分配；Kind = Manual/Auto(边)/Resume/Forced/Restore；读取面 `GetTransitionAudit()` Debug 三宏。
- **驻留统计**：per-stage `StageInfo`（id/进入次数/累计驻留秒）+ `GetStageInfos()` Debug 三宏（镜像 `EventChannelInfo` 形态；字符串化只在读取面，不进热路径）。
- **计数**：per-`RejectReason` 累计（抢占型机体）、`TimeoutCount`、Auto 边命中数、Resume 成功数——`IModuleStats` 增量追加键，HUD 兼容。
- **`ExportGraph()`** Debug 三宏：DOT 文本（节点 = 阶段、边 = 迁移边 ∪ 时长→NextId 链 ∪ 复合父子）——图审阅与诊断文档生成。

## 5. 接入范式（不改 Core 契约的消费形态）

- **事件→迁移桥**：业务侧 `SubscriptionBag` 订阅 `EventCenter`，处理器一行转调 `machine.Raise(e)`；Core 不做自动桥——事件→迁移是业务语义决策，静默转发会掩盖"谁在听"。
- **配置驱动状态表**：Luban 行 → `StageSpec`/`AddEdge` 适配器归配置/业务层；Core 只认纯数据。
- **嵌套子机**：阶段持有子机、宿主 Tick 内转发（`UITransitionRunner` 由 `UIService` 帧末转发的既有形态合法）；子机不强制注册 `ITickable`。
- **确定性 Sim 接入**：Sim 内机器以固定步长 Tick + `Silent` 快照参与回滚/checksum（与确定性 Sim 纪律对齐）。
