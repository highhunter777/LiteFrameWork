## 1. 范围与裁决

- **用户裁决（2026-10-08）**：网络形态 **B（公网 + IP 白名单封闭测试）**；登录形态 **游客一键**；范围含**房间服闭环**（身份→对局→结算→查询→重启恢复全链）。
- **红线口径**：本部署属**封闭测试例外**——白名单仅测试者可达，非公开暴露；**部署门禁（IL2CPP 真机核证、密钥轮换/批2 随 R4）延续不变**，本环境不得作为"可发布"判据，不得对外宣传/开放（§7）。
- **不做**：大厅/Lobby、账号密码体系、库存/Loadout、Android 真机、真云 CDN、R4 运维套件（OTel/灰度/实例注册/多实例调度）。

## 2. 架构（最小闭环）

```text
客户端(Desktop)
 ├─HTTPS─▶ Meta：POST /auth/guest          → {accountId, accessToken, expiresAtMs}
 │          POST /matches/result（提交管道消费调用，幂等）
 │          GET  /matches?accountId=…      （结果查询）
 └─KCP(UDP·安全信封)─▶ RoomServer：Join(票据验签) → FFA 对局（规则闭环已交付）
                      └─ SettlementReady → 本地 Outbox（持久卷）
                         └─ 后台提交服务（重试/退避）──▶ Meta 幂等落库（Mongo）
```

- **访问令牌与 Join Ticket 分层**：游客登录先由 Meta 以 `AccessTokenFormat` 签发访问令牌；Lobby 阶段再由 Meta 以 `JoinTicketFormat.BuildPrefix/AppendSignature` 签发入场票据，房间服按同格式同 key 验签，物理上不会漂。
- **提交管道 = R3 首段**：后台服务读本地 Outbox（`TryMarkCompleted` 完成语义/压实已有）→ Meta 幂等端点 → Mongo 唯一索引兜底（M0-c 账本原语已有）。
- 房间侧既有能力直接复用：票据验签（`--ticket-key`，fail-closed）、安全信封（`--envelope-key`）、分层限流、排空 5 步、FFA 规则闭环（死亡/复活/计分/终局/MatchEnded）。

## 3. 最小批划分

**批A（纯 .NET，本机可做，随时可开工）**

- Meta：`POST /auth/guest`（HMAC 访问令牌，复用 `AccessTokenFormat`）；`POST /matches/result`（幂等落库）；`GET /matches`（按账号查最近 N 局）
- RoomServer：**提交管道后台服务**（Outbox→Meta：重试/退避/完成标记/重启续投）；**SIGTERM 排空接线**（容器停止信号≠Ctrl+C，现 Program 只捕获 `CancelKeyPress`）
- 结算载荷：见 §4 裁决点 ①（账号映射）
- 本机 L3 闭环保真冒烟：真实 KCP + 两个无头客户端——登录→进房→打完一局→Mongo 可查→杀进程重启→Outbox 重放不丢不重

**批B（部署）**

- 云主机编排（最小 compose/systemd 或单容器）、UDP 安全组 + **IP 白名单**、HTTPS（云 LB 证书或 Caddy 反代）
- Mongo 副本集（事务依赖；单节点以副本集模式起亦可）；持久卷：Outbox `.journal` + Mongo 数据
- Release 构建；密钥经环境变量/Secret（严禁命令行明文）；`--allow-insecure-local` 严禁上云

**批C（客户端，Unity 环境）**

- 一键游客入口（点按 → 调 Meta 获取访问令牌 → Lobby 获取 Join Ticket → 走现有 Join）；服务器地址/端口与 PSK 可配（构建期注入）
- 结果页（最小：最近成绩列表）
- 页面集与层级图：[上云测试页面层级设计](../client/ui/上云测试页面层级设计.md)（登录/大厅/房间/结算/设置，命名按《制作规范》§9）
- **重编译对齐 buildHash**（当前 `07dbe182f67d0e69`；两端未对齐联机必被拒）

## 5. 部署侧注意清单

- **SIGTERM**：容器 stop/K8s 默认发 SIGTERM；批A 修 Program（捕获 SIGTERM→同排空路径），或编排 stop-signal 配 SIGINT（临时）
- **密钥**：`--envelope-key`/`--ticket-key` 均环境变量注入；客户端 PSK 同值（构建期注入）
- **持久**：Outbox `.journal` 挂卷；Mongo 数据卷 + 备份（最小：定时 dump）
- **探针**：Meta `/live` `/ready`；RoomServer 进程守护（restart=always）
- **§14 完整清单**（多阶段 Dockerfile/非 root/只读根/资源限额）——测试形态**最小满足**，逐项在部署记录中注明"测试豁免"，不冒充生产达标

## 6. 端到端验收（封闭测试达成定义）

1. 白名单外**连不上**（UDP 与 HTTPS 均不可达）
2. 一键游客 → 拿访问令牌 → 分配后拿 Join Ticket → 进房成功；无票/错票/过期被拒
3. 打完一整局（击杀上限或帧时限）→ MatchEnded 可靠到达客户端
4. 结果在 Meta **可查**（按账号）；同一结果重复提交 100 次只落一条（幂等）
5. 杀 RoomServer 重启 → Outbox 待提交**重放**：不丢、不重
6. 重启窗口 Mongo 不可用 → 提交重试；Mongo 恢复后收敛
7. 容器 stop → 走完**排空 5 步**（SIGTERM 修好后）

## 7. 红线与边界（必须遵守）

- **不得公开**：白名单 = 测试名单管理，不是公网运营；不发布地址、不开放注册、不做宣发。
- **门禁未闭合**：IL2CPP 真机核证、密钥轮换（批2 随 R4）仍挂账——本环境只能作为封闭测试，不能作为可发布判据。
- 数据最小化：游客随机账号，不采集个人数据；测试期日志与控制台按最小必要保留。
- 本专项 ≠ R4/G5：容量、长稳（24h）、灰度回滚等验收不做承诺。
