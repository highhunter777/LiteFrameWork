# 对象池专项设计

> 状态：现行专项设计（目标契约层；实现进度见 Docs/施工进度/对象池高级化.md）
> 版本：1.0
> 更新日期：2026-10-02
> 适用范围：`LiteFramework/Core/Pool`（内核与静态门面）、`LiteFramework/Unity/Pool`（GameObject 池）、表现层与 UI 层的池消费者（`LiteSim/View`、`LiteGame/UI`、`LiteClient` 实体服务）
> Owner：客户端框架；表现层消费 Owner 负责收编面的行为等价
> 依赖：`IModuleStats`（HUD 统计面）、`IPoolable`/`IPoolLifecycle`（两层生命周期接口）、Unity Object 生命周期（EditMode/Play mode 销毁口径）
> 工程结构、接口命名为设计契约；实现进度见 Docs/施工进度/对象池高级化.md，不在此重复。

## 1. 定位与分工

对象池是框架级**机制件**：消灭高频借还路径上的分配尖峰（实体生灭、特效、飘字/提示、集合临时对象）。分工三条线、各管一域、不做第二套：

| 件 | 位置 | 管什么 |
| --- | --- | --- |
| `ObjectPool<T>` | `LiteFramework/Core/Pool` | **内核**：带创建/借还/销毁回调与生命周期的 C# 实例池（所有权移交制） |
| `ReferencePool` | `LiteFramework/Core/Pool` | **静态按类型池**：纯数据对象（实现 `IReference.Clear()` 自清），静态门面按类型分桶 |
| `GameObjectPool` | `LiteFramework/Unity/Pool` | **Unity 包装**：按 prefab key 分桶的 GameObject 池，逐桶委托内核，不自研第二套池逻辑 |

红线：**池机制只有这一套内核**。任何新的池化需求先走 `ObjectPool<T>` 组合（回调表达策略），不得再手写 `Stack<T>` 分桶池；Unity 域生命周期差异（池根、销毁口径、归属标记）由包装层表达，不进内核。

与并存机制的关系：定容环家族（`PendingInputRing`/`InputHistory`/`SnapshotRing`）是"槽位复用存储"——槽号即寻址、无借还所有权语义，不属对象池、不收编；`UIService` 表单缓存是带 LRU 淘汰的**实例缓存策略层**（Recycled 原位停用、租约语义），保持自有；kcp2k vendor `Pool<T>` 隔离在 Vendor；`GameFramework` 第三方池套件为无引用死资产，不在本专项范围（清理另行）。

## 2. 继承基线（现状契约，本专项不改写）

`ObjectPool<T>` 既有语义全部保留，作为高级化的不变基线：

- **所有权移交制**：`Acquire` 所得状态未定义须先初始化；`Release` 即移交，归还后禁止再持引用；重复归还 UB（Debug 三宏并集下抛）。
- **回调分层**：`Acquire` = onGet（池策略）→ `IPoolable.OnSpawn`（对象自初始化）；`Release` = `OnDespawn`（对象自清理）→ onRelease（池策略）→ 空闲满则销毁。`Trim`/`Clear` 只销毁空闲件（已 OnDespawn），只走 onDestroy，不二次 OnDespawn。
- **回调异常隔离**：OnSpawn/OnDespawn/onRelease 抛异常 → 销毁该件并回滚账目，异常传播或吞掉按既有口径。
- **容量**：`MaxIdle` 空闲上限；`Preload(count)` 预热并自动上调上限；`Trim(keep)`/`Clear()` 手动裁剪。
- **统计**：`IModuleStats` 无条件实现（Created/Acquired/Released/Unused/Using/PeakUnused/Dropped/MaxIdle）。
- **线程模型**：主线程 only（框架约定，不加锁）。

## 3. 高级化契约（新增能力）

### 3.1 淘汰策略 `PoolEviction`

```
enum PoolEviction { DropNewest = 0, EvictOldest }
```

`Release` 时空闲数已达 `MaxIdle`：`DropNewest`（默认）= 销毁**新归还件**（现状）；`EvictOldest` = 销毁**队首最旧空闲件**、新归还件入池——热点对象（刚归还大概率马上再借）不再被反复重建。淘汰走 onDestroy 并计 `EvictedCount`；`DroppedCount` 专属 DropNewest 路径，两计数不混用。

### 3.2 空闲过期收缩 `TrimExpired(long nowMs, long maxIdleMs)`

入池时刻记录（与空闲队列平行的时刻队列，同进出序），`TrimExpired` 从队首（最旧）销毁空闲时长超 `maxIdleMs` 的件，返回裁剪数。**消费方驱动**——内核零时钟纪律（时钟只从调用方进入，同 `FrameDriver` 模式）；不自动跑、无后台 Tick。定位：消灭"峰值后池常驻"，与手动 `Trim(keep)` 互补（一个按龄、一个按量）。

### 3.3 借出验证 `Func<T,bool> validateOnAcquire = null`

`Acquire` 从池取件先过验证；失败即销毁（计 `InvalidatedCount`）并继续取下一件，池空再 create。**Unity fake-null 防御的通用解**：池中 GameObject 被外部 `Destroy` 后引用非托管 null，纯 C# 内核无从察觉——验证回调由 Unity 侧消费者提供（如 `obj == null` 判定）。验证发生在 onGet/OnSpawn **之前**（验证的是空闲件，被销毁件只走 onDestroy，与 Trim 同口径）。

### 3.4 统计面追加

`PoolHits`（池中直取数；Misses = Acquired − PoolHits，不另建键）、`EvictedCount`、`InvalidatedCount` 进 `IModuleStats`（键追加，HUD 消费方兼容）。复用率 = PoolHits / Acquired。

### 3.5 兼容红线

默认构造参数下，行为与现状**逐位一致**：淘汰默认 `DropNewest`、过期收缩不自动跑、验证回调默认 null。所有权移交制、回调顺序、异常回滚、重复归还检测、主线程 only 全部不变。

## 4. 集合池家族

高频临时集合（每帧/每广播的 List/Dictionary/HashSet）此前只有"调用方持实例 Clear 复用"的约定，无机制件。新增：

- `CollectionPool<TCollection, TItem>`：组合 `ObjectPool<TCollection>` 内核（onRelease = `Clear()`），不新写池逻辑。
- 静态门面：`ListPool<T>` / `DictionaryPool<K,V>` / `HashSetPool<T>`——`Get()` / `Release(collection)`，maxIdle 默认 8（集合池典型小容量；借用方须 Release 同一实例，所有权移交制同内核）。
- 定位：机制件交付。既有"调用方复用"点（如 `RoomRuntime.Execute` 的 outputs 列表）**不强制迁移**，新代码优先走池。

## 5. 收编清单（自建栈池并轨内核）

| 消费点 | 现状 | 收编后 |
| --- | --- | --- |
| `EntityViewMap`（实体视图） | `Dictionary<string, Stack<GameObject>>` 按 location 分桶；无上限、无统计、无生命周期接口、无外部销毁防御 | 每 location 一个 `ObjectPool<GameObject>`：validateOnAcquire 做 Unity 销毁防御；onGet = 激活 + 挂指定父，onRelease = 隐藏 + 挂池根；maxIdle 可配（默认 32），`statsName = EntityViewMap.{location}`；**recycler 两态语义不变**（外部回收方接管时不入本地池，避免两份池重复记账） |
| `FlyTextPool`（飘字） | `Stack<TMP_Text>`，PoolDepth=16 归还侧满则销毁；复位逻辑手写在归还路径 | `ObjectPool<TMP_Text>`（maxIdle=16 语义保留；复位 alpha/隐藏进 onRelease 回调；模板 CanvasGroup 随 prefab 序列化的红线不变） |
| `Toast`（提示条） | `Stack<RectTransform>` 池侧无上限（靠 MaxVisible=4 限活跃） | `ObjectPool<RectTransform>`（maxIdle=MaxVisible——池侧装得下活跃峰值，语义不变；Retire 复位进回调） |

**收编红线**：行为等价优先——原复位动作、隐藏口径、（Play 延迟 / 编辑 Immediate 的）销毁口径逐项映射到回调，不借收编改行为。

### 5.1 缺陷修复（随批3）

`EntityService.ShowAsync` 首建路径双 `OnSpawn`：`_pool.Get(...)` 已由池驱动 `IPoolLifecycle.OnSpawn`，随后又手动调用一次（池命中路径只一次）——删除手动调用，两路径对齐为各恰一次。

### 5.2 为什么 EntityViewMap 不用 GameObjectPool

`GameObjectPool` 的池根是全局隐藏根 + `DontDestroyOnLoad`（跨场景常驻），而实体视图的池根是**战斗域 root**（随 Match Scope 销毁）——生命周期不符；且全局 prefab 桶会让跨对局视图互相污染。战斗域根即 `SimView` 根，Dispose 随 Scope 走，故 EntityViewMap 组合内核、自持池根。

## 6. 验收口径

- **L1 直测补缺**：内核（淘汰两策略、过期收缩、验证回调含全失效转 create、统计口径、回调顺序、异常回滚、重复归还 Debug 抛、Preload/Trim）与集合池家族此前零直测，本专项补 `LiteFramework.Core.Tests` 直测。
- **EditMode 回归**：实体视图复用/泄漏断言（SimView/ShellLifecycle 面）、飘字与 Toast 行为等价断言（FeedbackService 面）不翻红；新增容量与统计断言。
- **兼容断言**：默认参数下 DropNewest/不收缩/无验证——与现状逐位一致（L1 用例钉死）。
- 门禁：L1 全量 + Unity 编译；EditMode 实跑随编辑器窗口期。
