## 0. 定位与边界

- **一个面、一次升级**：Loading 语义已由 `FeedbackService`（统一入口）+ 系统面 202（视觉载体）承担（U2-⑥c 已交付）；本页**不新开第二条 Loading 实现**（§6.1"同一反馈语义不得存在第二条并行实现"）。"通用"指同一载体覆盖操作阻断与流程加载两类窗口，形态从"遮罩+文案"升级为"遮罩+进度+阶段文案"。
- **与 2xx 系统面的关系不变**：layer=3（System）、full_screen=false（与 Toast 同组并行不互斥——全屏会触发同组 Replace 语义互相顶掉）、lua_path 空（纯 C# 驱动）。tbuiform **不新增行**：202 原位升级。
- **范围边界（重要）**：本页覆盖**内容初始化之后**的加载窗口；**冷启动内容事务（Patch ①）不覆盖**——该窗口 YooAsset 未初始化（`InitializeAsync` 在事务之后才执行，2026-10-10 核对），任何包内 prefab 都不可加载；且加载页不是"资源不可用时仍要能显示"的兜底（[总设计 §7](UI框架总设计.md#7-渲染适配与制作边界) 代码构建例外仅限 `ProcedureError`、绑定 `BootstrapError` 冒烟标记）——不得援引该例外。覆盖该窗口需两段初始化，见 §8 裁决点②。
- **驱动面**：C# 流程/业务入口经 `FeedbackService` 驱动；本批不加 Lua 门面（§8 裁决点④）。系统面不内嵌：五页页面层级中不出现 Loading 节点（[上云测试页面层级设计 §0](上云测试页面层级设计.md) 既有裁决）。
- 既有语义保持：嵌套计数（最后一个结束才解除）、Back 首位拦截取消（`TryCancelLoading`/`LoadingToken`）、失败不吞被门控操作——本页只做**载体升级**，不改变这些契约。

## 2. 形态与结构

两个 prefab：`Widgets/Loading.prefab`（模板本体——视觉主体升级，手工制作）+ `Screens/Loading.prefab`（202 系统面壳——外包结构不变，根 `Loading` = Canvas + CanvasGroup）。

目标层级（`Widgets/Loading.prefab`；现结构 = Blocker + Message 两件）：

```
Tmp_Loading                     ← 模板本体（现根名 Loading，随模板批次整形为 Tmp_<控件类型>）
├─ Bg_Blocker                  全屏阻断底（现 Blocker：黑 a=0.55、raycastTarget=1——吃射线 = 阻断下层）
└─ Cot_Content                 居中内容容器
   ├─ AnimatedImage_Spin       转圈装饰（帧动画自播；帧资源未就绪时静态占位——挂账）
   ├─ ProgressBar_Load         进度条（确定态显示；不定态隐藏）
   └─ Txt_Status               状态文案（现 Message；模板默认"加载中…"）
```

- **暴露面 = 组件序列化引用**（`LoadingMask.Blocker/Message/Progress`），不设 `BindName`——系统面由 C# 驱动、无 Lua/受控 API 消费（现行同款；与"模板不预设非空 BindName"规则一致）。
- 组件 `LoadingMask`（`Assets/LiteGame/UI/Widgets/LoadingMask.cs`）：保持"只暴露状态驱动、不自己创建视觉"的既有模式；新增进度字段与 Set 面（§3）。
- 存量差异登记（制作规范 §9.6 表增行，随本批一次整形）：`Blocker`→`Bg_Blocker`、`Message`→`Txt_Status`、widget 根 `Loading`→`Tmp_Loading`（随模板批次）、`Screens/Loading` 内嵌实例名 `Loading`→`Loading_Block`（出处定段）。`Bg_Blocker`/`Spin`/`Load` 为词表外语义——按 §1 例外表登记词条。
- 系统面壳根名维持 `Loading`（不带 `Page_` 前缀——`Page_<语义>` 批次仅指业务页面，§9.6 口径；系统面非导航页）。

## 3. 驱动契约（目标；API 名待实现批定案）

`LoadingScope`（`FeedbackService`）扩展——**唯一驱动面**：

```csharp
public LoadingScope BeginLoading(string message = null);   // 既有：嵌套安全；返回作用域；Dispose 收尾
// 目标新增（名称为设计建议）：
scope.Report(string message = null, float? progress01 = null);
```

行为约定（必须）：

- **写全量状态**：每次打开（含缓存复用）由服务写全量（文案 + 进度有无）——不留上次残留（总设计 §4.2 复位纪律；进度条显隐随本次状态）。
- **首写不丢**：`Report` 早于表单打开完成（首帧异步打开）→ 服务侧缓存最新值，打开完成后写入（对齐现有"打开时写 message"的时序，避免首条进度丢失）。
- **嵌套**：计数 >0 期间各作用域写同一面，**后写胜出**（"最后调用者定内容"，登记为本语义）；解除仍按计数归零。
- **确定/不定**：传入 `progress01` → 显示进度条（0..1 夹取）；`null` → 保持当前。开场默认不定态。不提供"确定→不定"回落（随真实消费者再补）。
- **Back 取消**：既有链不变（`UIService`/`UINavigationController.BackInterceptor` → `LoadingToken`；被门控操作自行响应）。本页不设取消按钮（默认，裁决点⑤）。
- **失败**：调用方（流程）收场后经 `ShowErrorAsync` 走错误弹窗；本页不内建错误态。
- **装配可观测**：模板缺 `Txt_Status`/`ProgressBar_Load` 组件 → 显性日志（对齐"缺 LoadingMask 即报装配错误"的现有口径），不静默。
- **线程/驱动**：主线程推送式（服务不建每帧泵；场景进度由消费方在既有 `OnUpdate` 轮询后 Report）。
