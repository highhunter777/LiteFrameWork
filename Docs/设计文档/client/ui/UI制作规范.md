# UI 制作规范

> 状态：现行规范
> 版本：2.1
> 更新日期：2026-10-10
> 适用范围：UI Prefab、命名、布局、渲染、动效、文本、资源与提交验收
> Owner：客户端 UI / TA
> 上位设计：[UI框架总设计](UI框架总设计.md)；实施状态与预算只在总设计维护

## 1. 规则等级与适用方式

本文定义目标制作规则，不表示既有资产全部符合。标为“必须”的新资产规则应由校验器或运行验证保障；既有资产按总设计 U0～U3 分批整改，并在报告中列出差异。建议项允许按页面需求选择，不能被工具误判成硬错误。

例外写入版本化的资产/规则例外表，包含资产、规则、原因、替代验证和失效条件；不依赖口头约定，也不因一个例外新增通用审批流程。校验器尚未实现的规则标为人工验收，不能冒称已有自动门禁。

## 2. 目录、Prefab 与绑定

| 内容 | 位置/约定 |
| --- | --- |
| 页面 | `Assets/UI/Screens/`；YooAsset 独立页面打包按依赖分析配置 |
| 控件模板 | `Assets/UI/Widgets/`；同族可用 Prefab Variant |
| 调试属性补丁 | `Assets/UI/Patches/`；只在 Editor/dev 使用，生产包排除 |
| 字体 | `Assets/Fonts/`；字体族与 fallback 受统一配置管理 |
| 运行时 | `Assets/LiteGame/UI/`；Lua 桥在 `Assets/LiteGame/LuaBridge/`；内容等适配在 `Assets/LiteClient/Adapters/` |
| 编辑器 | `Assets/LiteGame/Editor/`，样式在 `Style/` |

必须：

- 页面根具有 Canvas、CanvasGroup；Raycaster 按交互需要配置。页面嵌套于统一根 Canvas 时继承根缩放，独立根模式有自己的缩放配置，不能重复缩放。
- Screens/Widgets 收集路径不互相包含，tag `ui`；打包规则使用 YooAsset 工具/API维护。Editor 模拟加载通过不代替真实包验收。
- 可序列化 MonoBehaviour 使用同名独立 `.cs` 文件；Prefab 保存后无缺失脚本和丢失引用。
- 模板不预设非空 BindName、不放界面级 BindRoot；界面作者命名暴露控件。内部接线用序列化引用。
- 同一页面绑定命名空间内唯一、类型匹配。列表项/子页面作为独立绑定作用域时由生成器显式区分，不能依赖偶然的层级遍历顺序。
- 修改绑定后重新生成并验证索引；生成结果与运行时扫描结果一致。模板、生成代码与页面三者不能各维护一套名字。
- 控件模板不直接依赖具体玩法、Transport 或 Sim。业务通过 ViewModel/受控 API 驱动。
- **运行时代码不得构建用户可见视觉效果**：不 `new GameObject` 造 Canvas/Graphic/Text/Button，不 `AddComponent` 挂视觉组件；一律引用本目录模板。唯一例外是引导期错误界面（判据见[总设计第 7 节](UI框架总设计.md#7-渲染适配与制作边界)）——它是"资源不可用时仍要能显示"的兜底，不是可援引的先例。层容器节点（`UIRoot` 与各层节点）是骨架不是视觉，不在此限。**测试夹具同受此约束**：从测试专用 prefab 加载，不进 Screens/Widgets 收集路径，见[UI 测试开发专项设计 §7.2](../../quality/UI测试开发专项设计.md)。
- 反馈面（Loading/Toast/错误重试）落在 System 语义层并经统一排序器分配 order；不得自建 Canvas 或私有 sortingOrder 跨层。
- Prefab/asset/meta 变更经 Unity 编辑器或项目 Pipeline，遵循根目录 `UNITY-GUIDE.md`；工具保留 Undo 和差异预览，不手改序列化文本。

建议：模板采用清晰层级结构；命名（业务层 `<前缀>_<语义>`、模板层 `Tmp_<控件类型>`）、类别前缀词表与内部节点 `_` 前缀规则统见第 9 节（命名单源）。层级尽量浅，但不以统一“最多五层”阻止合法组合。图标选择 Simple；需要九宫格拉伸的背景才选 Sliced；进度按需要选 Filled。

## 3. 布局、缩放与安全区

- 横屏初始参考 1920×1080、Match=0.5；产品配置可覆盖。必须用实际比例、安全区和窗口尺寸验证，不能只检查存在 CanvasScaler。
- 安全区应用于内容/交互容器；全屏背景可延伸至边缘。方向变化和安全区变化应刷新。
- 小规模、低频变化、自适应文案可用 LayoutGroup/ContentSizeFitter；避免循环依赖和重复强制布局。高频 HUD、虚拟列表窗口位置由明确的布局算法控制，不能每帧全量重排。
- 文案区域声明单行截断、换行、伸展或滚动策略；关键按钮、错误原因、确认结果不能仅靠截断通过验收。
- 确定性模板可预排锚点与尺寸，但不可牺牲本地化、字体缩放和输入框自适应。

建议阶梯：字号 12/14/16/20/24/32/40；间距优先 8 的倍数；图标 24/32/48/64/96；安全边距初始 32。这些是风格默认值，语言/可访问性适配允许经样式档声明覆盖。

## 4. 层序、Canvas 与输入

层和页内排序由运行时排序器统一分配，页面不得私自占用其他层区间；不使用固定特效 order，也不使用组内槽位回卷。模板仅声明所需相对层级，不能把实例的绝对顺序写死。

默认 Overlay；Camera/世界特效夹层按实际消费者启用。Overlay 页面可用 RenderTexture 显示 3D 预览；不要求每个页面配置专用相机。

必须：

- 非交互 Graphic 默认 `raycastTarget=false`；只在必要 Canvas 上挂 Raycaster。
- 模态背景有真实射线阻断；页面 `blocksRaycasts=false` 不能当作防穿透实现。
- 自定义点击控件尊重页面输入锁；焦点、键盘/手柄提交和取消通过统一输入能力接入。
- 转场/缓存复用恢复到视觉基线；不能保存 alpha=0 或偏移残留作为下一次显示状态。

Canvas 按刷新频率和同时可见区域组织。高频与静态内容可以分层，但不要求每个动效节点独立 Canvas。验证分层前后的 CPU rebuild、批次数和 GPU 代价，不能仅按组件数量断言优化完成。

图集按复用关系与资源卸载边界分组；同页资源可以共享图集，但不强制全工程单一大图集。packingTag 不是图集与可发布资源正确性的唯一证据。

## 5. 动效、粒子与材质

- UI 动效/粒子/音效走统一播放入口（现行 UiFx/转场策略；效果系统落地后为其播放契约，见 [UI 效果系统专项设计](UI效果系统专项设计.md)），走 UIClock 语义；异步使用 UniTask。每个动效具有所属展示作用域、取消和视觉复位路径。音效经 AudioService 的 UI 组接入，页面/控件不得直挂 AudioSource。
- 禁用/关闭/超时须停止对应 Tween；SetLink 是兜底，不能代替操作取消和关闭清理。
- 文本/整组连续淡入淡出优先用 CanvasGroup.alpha；避免每帧改 TMP 顶点颜色或重新写文本。位移/缩放仍需观察 Canvas 重建，不能宣称改 Transform 永远没有重建代价。
- 现有 `UiFx.Pulse/Flash` 修改 Graphic 颜色；连续文本淡入淡出不要直接使用这两个入口，需补专用 CanvasGroup 路径。Image 的颜色动效也计入测量。
- 装饰优先考虑图片/帧动画；确需粒子时验证遮罩、裁剪、排序与预算，RectMask2D 不能被假定为自动裁剪任意粒子。
- 世界 VFX 归表现服务；UI 内动效/粒子/音效的播放契约归 [UI 效果系统专项设计](UI效果系统专项设计.md)。任何表现不得决定命中、伤害或业务完成。
- 材质优先共享；需要独立实例时必须显式持有、销毁并计入预算。不要通过读取 `fontMaterial` 无意制造实例。
- Shader 需通过目标管线的 alpha、Stencil、RectMask2D 和裁剪用例；TMP 使用项目批准的字体 shader/共享预设。不要求不存在于 ShaderLab 语义中的通用“继承 UI/Default”。
- Outline/Shadow 不作全工程绝对禁令；高频或长文本优先使用合适的字体材质/美术资源，采用额外网格效果时记录顶点与重建成本。

建议时长：0.15s 快反馈、0.25s 标准、0.35s 全屏；缓动按表现选择。减少动效模式应替换策略或立即完成，不能改变页面操作的结果。帧动画引用按名册检查，不能自动重排帧序。

## 6. 文本、本地化与样式

- 正式本地化组件保存 key/参数，不把产品文案写进 Prefab。尚未接本地化的灰盒内容明确为占位并登记待整改；表格、Lua 和 Prefab 不得分别维护同一文案。
- key、语言切换与缺失回退遵循总设计第 9 节；语言切换不得重跑 OnShow。
- 字体配置允许主字体和 fallback；按所支持语言检查缺字。统一字体族不等于只准一个字体资产。
- 字号、换行、对齐和溢出来自样式档；自动缩放仅在声明 min/max、支持语言与验证样例的样式档中启用，避免任意组件各自缩字。
- 颜色 token 与文字角色档各自单源。字距/行距和垂直对齐有默认值，可按语言或语义档显式覆盖，不能用全局硬置零破坏排版。
- 作者富文本允许 color/b/i/u/s、受限 size、已登记 sprite 和 link；禁止任意 material/font/style/quad/gradient 以及未知标签。link 需受控处理器。
- 玩家/外部字符串默认关闭富文本，或使用经过 TMP 实际渲染测试的转义路径再插入；不假定任意 HTML 转义方案对 TMP 都成立。
- TMP Sprite Asset 与 SpriteAtlas 是不同资产；使用 `<sprite name=...>` 前校验名册，不能用不稳定 index 表示内容语义。
- 中英真实文本与伪本地化都要验证；不把固定长度膨胀比例作为充分验收。

样式编辑器只写盘上基准；运行时按状态改实例合法。对账报告不得把运行时状态判成资产漂移。

## 7. 列表、异步资源与业务绑定

- 大列表采用窗口复用，节点数量受视口容量控制；滚动不按数据总数创建节点，不反复添加监听。
- 行绑定包括稳定 key 与绑定代次；条目复用先解绑旧回调并释放旧图标租约，迟到资源不能覆盖新条目。
- 小列表可用 SimpleListView；变高/Grid 支持以运行时能力为准，不靠模板假装已支持。
- 同一控件属性只有一个数据写入所有者；命令式与绑定式不能争写。组件禁用/销毁/页面退出时清理自己的订阅。
- 页面资源在实例销毁前保持有效租约；临时资源绑定展示作用域。不能把关闭和释放全部 Prefab 依赖等同。

## 8. 提交与验证

| 阶段 | 必须检查 | 验证载体 |
| --- | --- | --- |
| 资产静态检查 | 丢脚本、绑定唯一/类型、资源引用、本地化 key、字体/样式、图集引用、Raycast 配置；**运行时视觉构建反例扫描**（服务/页面代码中的 `new GameObject` 与视觉 `AddComponent`——违规负例须落在 EditMode 用例，例外须能指向总设计第 7 节判据） | L2 EditMode 校验器；未实现项列人工报告 |
| 页面行为 | 首开/关闭/复用、层序/模态、焦点、语言切换、异步资源取消 | L2 PlayMode，实际生命周期和 Lua |
| 列表 | 首尾往返、重复刷新、增删到 0、异步图标乱序、窗口缩放 | L2 PlayMode |
| 发布表现 | 真资源包、SafeArea、长文本、内存清理、CPU/GPU/GC、前后台 | L4 Player/目标设备 |

EditMode 结构检查不能替代依赖 Awake/OnEnable 的行为测试。已有模板菜单可继续使用，但菜单报告应逐步转成可自动失败的用例。性能目标和数据记录方式只维护在 [总设计第 12 节](UI框架总设计.md#12-验收预算与观测)，不在本文件复制一份数字。

新规则必须有定位信息和至少一个违规负例；测试数量不固定为永久门槛。

## 9. 层级与节点命名

本章为**业务命名规范**：管页面业务节点与预制体模板原型的业务变体（使用处）。预制体模板本体没有业务语义，不适用业务语义命名——本体按 `Tmp_` 命名（9.3）、内部交互件按角色文法（9.4）。节点名同时承担四种消费——层级阅读、LiteCodeGen 生成成员名（= 节点名直出，须过 C# 标识符校验）、受控 API/Lua 的引用键（经 `BindName`）、工具校验的定位信息——一个名字必须一次满足，不允许各消费面各维护一套（§2“三者不能各维护一套名字”的命名侧展开）。

节点名不是本地化 key（key 规则见[总设计 §9](UI框架总设计.md#9-本地化文本与可访问性)，`UI.<页面>.<语义>`），也不是颜色 token 或样式档名；三者是不同命名空间，互不替代。

### 9.1 名字模型

| 名 | 载体 | 消费者 | 规则 |
| --- | --- | --- | --- |
| 节点名（层级名） | `GameObject.name` | 人 / LiteCodeGen 成员名 / 工具定位 | 9.2 文法：`<前缀>_<语义>` |
| 类别前缀 | 节点名首段 | 校验器 / Inspector 预设 | 9.3：词表前缀或控件类型段（必须取自其一） |
| 绑定名 `BindName` | `BindNode.BindName` | 受控 API（路径 A/B）、Lua（`self.ui:OnButton("Button_Close")`）、Designer 登记 | 非空 = 本页面暴露该控件；与节点名同文（必须）；页面作用域内唯一；`_` 私有件不得设置 |

同文后实际只需起一个名字：起名在 `BindNode` Inspector（选前缀 + 填语义名，9.5）或层级里直接改名，两处殊途同归。

### 9.2 文法（必须）

- 结构 `<前缀>_<语义>`（前缀段 = 词表前缀或控件类型段，见 9.3）：前缀 PascalCase；语义 PascalCase（多词连写，如 `Button_CloseAll`）；全名恰一个下划线；ASCII 字母/数字且语义不以数字开头：`^[A-Za-z]+_[A-Za-z][A-Za-z0-9]*$`；禁空格/连字符/点/中文/全角。例：`Page_Inventory`、`Button_Close`、`Bg_Shop`、`Cot_TradePanel`。
- C# 直出兼容：成员名 = 节点名（`public Button Button_Close;`）；绑定节点不满足文法时 LiteCodeGen 拒绝生成（`IsValidIdentifier`）。全量节点名只允许两种形态——`<前缀>_<语义>`（前缀段 = 词表前缀或控件类型段）或 `_` 私有件（9.4）——不等到“要暴露时才改名”；关键字风险由文法排除（前缀段 + 大驼峰语义不构成 C# 关键字）。
- 编号族：编号紧贴语义尾部、0 起、连续、升序——`Button_Tab0`、`Button_Tab1`（既有 `Tab0`/`Nav0`/`Star0` 属存量）。
- 根节点名：页面根 = Prefab 文件名（`Page_<语义>`，文件 `Page_<语义>.prefab`）；模板原型的业务变体/使用处 = `<控件类型名>_<语义>`——`Dialog_Trade`（交易弹窗）、`Toast_Warning`（警示吐司），类型段取现役控件类型名、语义段表用途；文件与根同名。模板本体不适用本条——原型 `Tmp_<控件类型>`、特化 `Tmp_<控件类型>_<语义>`（9.3）。`BindRoot.ScriptName` 留空时生成类名取根名，两者不允许分叉；页面名同时是流程/表格的引用键。
- 改名联动：节点名改动必须同批同步 `BindName`、Lua 引用字符串、C# 受控 API 字符串与重新生成产物（§2 重新生成与对账要求）。

### 9.3 前缀词表、类型段与模板命名（Inspector 预设同表）

| 前缀 | 类别 | 例 |
| --- | --- | --- |
| `Page_` | 页面根 | `Page_Inventory` |
| `Cot_` | 容器/分组（含列表容器、SafeArea） | `Cot_TradePanel`、`Cot_List` |
| `Bg_` | 背景/底板 | `Bg_Shop` |
| `Txt_` | 文本 | `Txt_Title` |
| `Image_` | 图像 | `Image_Portrait` |
| `Icon_` | 图标 | `Icon_Coin` |
| `Clone_` | 克隆条目模板 | `Clone_Item` |

**控件类业务节点（类型段）**：判据——交互控件（UGUI）与控件模板 → 类型段；展示/结构角色词 → 词表；控件名一律写全称。交互控件如 `Button`/`Toggle`/`Slider`/`Dropdown`/`InputField`/`ScrollRect`/`Scrollbar`；模板名即 `Assets/UI/Widgets` 去 `Tmp_` 清单——判据即成集，不另建登记。出处定段：节点由模板实例化/变体而来 → 模板段（`StateButton_Ok`——StateButton 模板做出来的按钮）；直接使用的 UGUI 控件 → 控件段（`Button_Ok`）。例：`Dialog_Trade`、`Toggle_Sound`、`StateButton_Close`、`Button_Close`。

**模板命名（模板层）**：预制体模板本体不用业务语义、不占词表——原型按 `Tmp_<控件类型>`（`Tmp_Dialog`、`Tmp_Toast`）；特化语义模板按 `Tmp_<控件类型>_<语义>`——大量页面复用同一语义件时抽出（如 `Tmp_Button_HeroLevelUp`），建议阈值：同一语义件被 ≥2 个页面使用（或已明确跨模块复用）即抽并登记，单页专用不抽；跨页面复用入模板层，单业务用途的变体留业务层。使用处（业务层）命名 = 去掉 `Tmp_` 前缀的 `<控件类型>_<语义>`（与上段控件类口径一致：`Dialog_Trade`、`Button_HeroLevelUp`）。`Tmp_` 仅供模板资产，业务节点不得使用；`Clone_`（9.4）是节点级克隆模板，与 `Tmp_` 模板资产区分。

**语义词条（高频参考）**：动作——`Close`、`Confirm`、`Cancel`、`Back`、`Submit`、`Save`、`Reset`、`Retry`、`Refresh`、`Buy`、`Equip`、`Use`；角色——`Title`、`Message`、`Name`、`Value`、`Count`、`Level`、`Time`、`Desc`。规则：同页面同语义同词（`Close` 不混 `Quit`/`Exit`）；词条重复出现即补录本表（§1）。

词表与词条数据化单源（Inspector 预设与校验器共读，见[工具专项 §2](UI编辑器工具专项设计.md)）；词表外新类别先登记（§1 例外表）再使用；规范与工具同批更新，不即兴造同义词（如再出 `Lst_`/`Pnl_`）。完整枚举（角色词 / 交互控件段 / 全部 27 件模板，与选段指引）见[UI 命名词表与控件清单](UI命名词表与控件清单.md)。

### 9.4 私有件与克隆模板（必须）

- `_` 前缀 = 私有实现细节：Unity 复合控件内部件（`_Viewport`/`_Content`/`_Placeholder`）、装饰底（`_Bg`）。不设 `BindName`、不进运行期索引、不被页面与 Lua 引用；要暴露时改用词表前缀/类型段并按 9.2 起名。页面业务节点不得以 `_` 开头（不暴露 ≠ 私有）。
- 模板内部交互件按角色文法命名（同 9.2——它们会随暴露进入业务面）：如 `Tmp_Dialog` 内 `Button_Ok`、`Txt_Title`；其余内部件（纯实现）走 `_` 私有。
- 克隆条目模板 = `Clone_<语义>`（如 `Clone_Item`）：保持非激活、子树不设 `BindName`、由容器组件的序列化引用接线（C# 面为 `Template` 字段）。
- 模板 prefab 不预设非空 `BindName`、不放界面级 `BindRoot`（§2 已定，此处为命名侧重申）。

### 9.5 绑定命名作者面：前缀预设

- `BindNode` Inspector 命名面提供**类别前缀预设**：下拉选前缀（9.3 词表）+ 只填语义名 → 组合为 `前缀_语义`，一次写入 `BindName` 并同步重命名节点（同文由工具构造性保证，不存在只改一处的手工路径）；已带前缀的节点回显解析为「前缀下拉 + 语义输入」两控件。
- 起名动作收敛为“选前缀、填名字”；层级手工改名仍合法，暴露与改名以后一次经 Inspector 写入为准。
- 工具现状：现 Inspector 为自由文本索引名，预设未实现——实现进[工具专项 §2](UI编辑器工具专项设计.md)；未实现前按 9.2 手工命名并自查。
