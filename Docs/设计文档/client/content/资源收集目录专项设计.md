# 资源收集目录专项设计

> **版本**：v3.0（2026-10-11）　**权威层级**：专项设计（第 3 层）。
> **定位**：裁决 **YooAsset 资源收集目录**的规划——目录三层模型、哪些目录进包、按什么粒度分包、热更怎么定位资产（"管理资源＋打资源包热更"）；并给出本工程热更实装流程与分包分组方法论。热更事务/候选/签名/回退细节以《[热更与内容发布专项设计](热更与内容发布专项设计.md)》为权威。
> **不在范围**：版本管理（git / 是否上传 GitHub）。入库状态按 `AGENTS.md` 资源规范与 `.gitignore` 既有裁决执行；收集规划不改变任何入库状态。

## 1. 概念分层与四个旋钮

```
收集器（Collector＝收集目录＋四旋钮） → 组（Group＝收集器集合＋激活开关＋组tag）
  → 包（Bundle＝构建输出的物理单元，粒度由 PackRule 决定）
    → 清单/版本（Manifest+Version，YooAsset 的发布与寻址单元）
```

| 旋钮 | 现值 | 热更语义 |
|---|---|---|
| AddressRule | AddressByFileName（全组统一） | 运行时按文件名寻址：场景名 / Lua 名 / 页面名 / 特效 id / 表名直接当资源地址 |
| PackRule | PackDirectory / PackSeparately | **分包粒度**：Directory＝整目录一包（改一件发整包）；Separately＝每件一包（改哪件发哪件） |
| FilterRule | CollectAll | 收集过滤；"只收实际用到的"类声明要靠它或目录拆分落实 |
| AssetTags | lua / ui（其余空） | **候选定位面**：`lua` 已接线（`ContainerModule.cs:141` 产候选 Lua 清单）；`ui` 已标注，消费面随 UI 热更批接线 |

**与 BuildHash 的关系**：BuildHash 只锁代码/协议/表源集（Join 握手身份）；收集目录及其产物走 bundle 清单与版本摘要。改收集目录不需要重跑 BuildHash，反之亦然。

## 2. 目录三层模型（2026-10-11 裁决）

> **裁决原文**：Assets 顶层只放原始资源；收集目录用**模块内使用的资源**和**共享资源目录**；共享的资源放 `ShareResource` 目录，该目录下再自建顶层目录。

| 层 | 位置 | 放什么 | 进包方式 | 现状样板 |
|---|---|---|---|---|
| **L1 原始资源层** | Assets 顶层 | 原始美术素材（Art/Model/Sound/Animation/Animator/Map…）——只被引用、不被直接寻址 | 依赖闭包随引用者进包，或纯编辑器期不进包 | `Art/`、`Model/`、`Sound/`（现状已合） |
| **L2 模块资源层** | 模块目录内的资源子目录（模块聚合：代码与相关资源同模块） | **仅本模块使用**的资源 | 直接寻址→登记为收集路径；被引用→依赖闭包 | `LiteGame/Lua`（代码即热更资源，目录即收集组 tag lua——**样板**） |
| **L3 共享资源层** | `Assets/ShareResource/`，**其下自建顶层子目录**（虚拟顶层：`ShareResource/{类别}/`，每类可独立成收集路径/组） | 跨模块共享、需进包的资源 | 各子目录独立登记收集路径，PackRule 按类定粒度 | `ShareResource/SampleContent`（首个子目录样板） |

推论：**现有按"类型"集中且被收集的顶层目录（UI/Fonts/Prefab/FX）不符合本模型**——它们要么归 L3（跨模块共享），要么归 L2（确属单模块专用），迁移映射见 §5。Scenes 与 GameData/Config 为两类例外（§5 登记裁决建议）。

## 3. 热更流程（本工程实装）

### 3.1 两条内容线

| 线 | 载体 | 打包 | 分发 | 生效 |
|---|---|---|---|---|
| **资源线（YooAsset bundle）** | 收集目录 → bundle（依赖闭包自动补齐被引用资源） | `BuiltinBundleBuildInvoker`（菜单 `LiteGame/Resource/构建内置 Bundle 包`）：SBP 构建 DefaultPackage → 产物清空复制 `StreamingAssets/yoo` 随 Player 分发；版本号 `1.0-yyyyMMddHHmmss` 唯一化 | 首版内置；候选 rel 可携带 `bundle/` 段 | OfflinePlayMode **包根可变**——激活事务把包根指向候选 release 即生效（NextLaunch） |
| **轻内容线（自研候选/激活事务）** | Lua/配置/bundle 段按 ReleaseLayout 前缀（`lua`/`config`/`bundle`）圈选 | `gen-candidate.ps1` → `publish-candidate.ps1`（信封 `candidate.json` + `LocalCDN/rel-xxx/{bundle,config,lua}/`） | 配置 `-content.cdnUrl` 走 HTTP；未配置＝本地信封通道 | ProcedurePatch 事务（§3.2） |

### 3.2 Patch 事务与 PlayMode 三态

```
读信封 → 下载候选（前缀圈选、摘要复算）→ 候选验证（Lua 导出/Prefab 绑定/schema/Bridge 兼容）
  → PendingActivation 落盘 → 激活（包根/内容代次切换）→ 健康确认 → Confirmed 提交｜失败回退 Confirmed
```

- PlayMode 三态：EditorSimulate（编辑器）✅；Offline（Player 内置/指定包根）✅；HostPlayMode（网络下载）⏳ 未实现，契约在《热更专项》§7 立案——接通时收集规划与 Patch 事务零改动。
- 生效策略首版 `NextLaunch/SafeWindow/NextMatch`：对局中可下载但不替换在用内容（ContentGeneration 代次隔离）。

## 4. 分包分组方法论

**分组看四个问题**：热更频率 / 生效窗口 / 下载优先级 / 平台差异——一类答案相同的资产进一组。**分包看粒度账**：bundle 是下载/校验/加载的最小单元，越细热更流量越小但请求数越多。

| PackRule | 行为 | 适用 | 本工程用例 |
|---|---|---|---|
| PackDirectory | 整目录合并一包 | 低频、大体量、总是一起用 | 现有 Directory 组 |
| PackSeparately | 每资产一包 | 高频单件改动、件级热更 | UIScreens（单页热更）、ShareResource |
| PackTopDirectory | 按一级子目录各一包 | 目录内再分族（**L3 自建顶层子目录正是此形态**——ShareResource 迁移完成后可整组改用） | 备选 |
| PackCollector | 整收集器一包 | 极低频恒定集合 | 暂无用例 |
| PackRawFile | 原生文件直发（RawFile 管线） | 文本/二进制直读 | 备选：Lua 转直读时 |

**规划规则 G1～G5**：G1 收集目录职责单一；G2 打包粒度跟随热更频率；G3 **直接寻址资源必须在收集目录**（被引用不直接寻址的素材不必进——依赖闭包进包，位置按 §2 三层模型）；G4 第三方素材不进收集目录（FX 组描述原规定；登记落差：FilterRule=CollectAll 未落实排除，归后续收集批）；G5 新增/搬动收集目录＝collector＋[修改指南 §3.9](../../修改指南.md)＋本文档三面同批，改后重跑资源包构建核对清单。

## 5. 现状 → 目标迁移映射（9 组）

> **迁移不随本批执行**：物理移动序列化资产必须走 unity-pipeline CLI，且每类牵动代码常量与收集配置——按下表**逐类点单**，一次一类，三面同批。本文只锁模型与映射。

| 现收集组 | 现路径 | 目标层/路径 | 同步面（动收集必过） | 成本 |
|---|---|---|---|---|
| Lua | `Assets/LiteGame/Lua` | **不动**——L2 样板 | — | — |
| UIScreens | `Assets/UI/Screens` | L3 `ShareResource/UI/Screens` | collector + `VisualConstructionScanner`/`UiStyleTool` 路径常量 + 修改指南 §3.6/§3.10 + 构建器登记 | 中 |
| UIWidgets | `Assets/UI/Widgets` | L3 `ShareResource/UI/Widgets` | 同上 | 中 |
| Fonts | `Assets/Fonts` | L3 `ShareResource/Fonts` | collector（单条） | 低 |
| Characters | `Assets/Prefab` | L3 `ShareResource/Characters` | collector + 代码常量四处：`BakeTargets.PrefabPath`、`SimView.DefaultEntityPrefab`、`CombatGirlsAnimationProfile.ViewPrefabPath`（审计登记的双写对）+ `AgentScripts/BuildClipManifestAssets` | 中高 |
| FX | `Assets/FX` | L3 `ShareResource/FX` | collector + 代码常量 `VfxCatalog.DefaultRoot="Assets/FX/"` + 修改指南 §3.10 | 中 |
| ShareResource | `Assets/ShareResource` | **不动**——L3 本体；随迁移逐步形成自建顶层（`{UI,Fonts,Characters,FX,…}`） | 迁移项落位时该子目录登记为收集路径 | — |
| Scenes | `Assets/Scenes` | **例外，建议维持顶层**：场景是流程编排资产（直接寻址、跨模块），"原始资源顶层"放不下它；迁移涉及 `ProcedureMain.cs:30` 场景路径、BuildProfiles 场景清单、多场景构建配置——高成本低收益 | 待用户裁决（如未来归入流程模块再议） | 高 |
| Config | `Assets/GameData/Config` | **例外，建议维持**：表产物（构建输出）而非素材，Luban/gen 脚本、服务端 `CombatNumbers` 仓库根定位、双端同读路径均钉在此 | 待用户裁决 | 高 |

> 目录名说明：共享目录现名 `ShareResource`（收集组同名）；如需更名 `SharedResource` 属一次 G5 三面同步＋代码/文档全量改名，未执行。
