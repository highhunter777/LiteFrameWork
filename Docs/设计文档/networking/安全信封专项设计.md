## 1. 定位与分工

安全信封是 R2 的第四件（前 three：重连票据 CSPRNG、规范化远端地址、分层限流——见[服务端R2安全](../../施工进度/服务端R2安全.md)）：给 KCP 裸 UDP 上的业务载荷补**机密性、完整性、序号、重放窗口**四项，形态为**传输装饰器**（`IRoomTransport`/`IClientTransport` 的套壳实现）——上层协议（PacketCodec/RoomCommand/RoomOutput）与会话/房间逻辑零改动、零感知。

| 邻居 | 分工边界 |
| --- | --- |
| KCP/kcp2k | 只提供可靠/不可靠 UDP 信道与 cookie 探测；cookie **不等同**业务身份或加密（总设计 §P0-6 红线）——信封在其载荷之上 |
| `HmacJoinTicketValidator`/`ReconnectService` | **身份与会话准入**（谁进来）；信封只管**信道侧**（进来之后听什么说什么） |
| `CombatConfigDigest`/buildHash | 玩法与协议**版本身份**（进房前）；信封源码目录进 buildHash 源集——密文帧形状两端不一致即握手拒绝 |
| LiteSim/RoomRuntime | 零接触：装饰器在 `Server/RoomServer` 宿主装配层挂载，Runtime/Application 保持零 IO 零加密 |

红线：不自创密码算法；信封完成前服务不得直接暴露公网（本专项即为解除该红线的交付）；密钥不得入库、不得写日志。

## 2. 核心契约

**PSK 握手**（防"无凭据连接"即得会话；三步，全部走 KCP 可靠信道）：

```text
Client ── ClientHello(clientNonce 32B) ──────────► Server   （CSPRNG nonce）
Client ◄─ ServerHello(clientNonce 回显, serverNonce, serverProof) ── Server
         serverProof = HMAC(PSK, "…/server" + clientHello + serverNonce)
Client ── ClientFinish(clientProof) ─────────────► Server
         clientProof = HMAC(PSK, "…/client" + clientHello + transcript)
双向证明验过 → 双端 HKDF 派生会话密钥（client/server 方向各 32B + 4B nonce 前缀）
```

- **数据帧**：`Magic"LSE1" + version + kind + channel(可靠/不可靠) + sequence(64b) + 密文长度 + AES-256-GCM 密文 + 16B tag`；**帧头作为 AAD 参与 GCM 认证**——篡改即解密失败。
- **防重放**：每方向单调 sequence + 64 位滑动窗口（位图），窗口内重复/未见过老帧拒收；**解密成功才推进窗口**（先认证后状态）。
- **载荷上限**：`MaxPayloadBytes`（默认 64KB，≤1MB）——解析前按头内长度拒绝（对齐 §5 P0-3"包体在解析前限制长度"）。
- **fail-closed 处置**：垃圾首包/不可靠信道握手/证明不符/解密失败/再握手重放 → **直接断开**，不回包不等待（无放大面）。
- **版本协商**：version 字节单值（v1），魔法数+版本不符 = 非信封流量直接断开；不支持降级。

## 3. 装配与密钥（fail-closed 两侧对称）

- **RoomServer**：`--envelope-key <base64>` 或环境变量 `LITENET_SECURE_ENVELOPE_KEY`；**未提供即拒绝启动**——仅本机联调可显式 `--allow-insecure-local`（裸 KCP，启动横幅警告"不得暴露公网"）。
- **客户端**：`BattleClient` 真实 KCP 路径必须装配 `SecureEnvelopeOptions`（缺失即抛，与服务器对称）；注入传输（测试假件/`LocalServerTransport` 进程内本地服）不受影响。
- 密钥是**进程级 PSK**（32 字节高熵，会话密钥经 HKDF 派生）——分发/轮换归部署侧（G4 Secret Provider 接缝），本专项不建 KDH/证书体系。

## 4. 明确不做（非目标登记）

- **前向保密/身份双向认证体系**（KDH、证书链）：PSK 模型下服务器证明即 PSK 持有证明；公钥体系待真实账号体系（G3 Auth）有签发方后评估。
- **会话内重钥（rekey）**：对局时长（分钟级）内 GCM 单密钥帧量在安全余量内；超长对局重钥随 G4 运维批评估。
- **握手超时清理**：宿主连接生命周期（KCP 断线判定）兜住僵尸半握手；独立超时器随 R4 运维批。
- **跨线程加密会话**：装饰器内锁只护顺序号/窗口一致性，不改变"单线程泵"宿主纪律。

## 5. 验收口径

- **L1**（`SecureEnvelopeTransportTests`，假传输）：双向握手与密文互通、篡改拒收+断开、重放拒收+断开、错钥不建立会话、垃圾首包/不可靠握手/伪造 ClientFinish/建立后再握手全部 fail-closed 断开、伪服务器 ServerHello 客户端自断、载荷边界（64KB 通过/越界加密口抛）。
- **真实传输**（`SecureEnvelopeRealTransportTests`）：信封套真 KCP 两端，127.0.0.1 回环完成握手 + Join→JoinAck 全链。
- **buildHash**：`Assets/LiteNet/Transport/Security` 进源集——信封改动即两端哈希同变，错配在 Join 握手被拒。
- 门禁：L1 全量 + Unity 编译；**IL2CPP Player 的 AesGcm 可用性**随真机矩阵核证（Windows Player RSA 先例同路径）。
