# 生成器工具箱专项设计

> **版本**：v1.1（2026-10-11）
> **执行语言**：五件工具统一为 **Python**（裁决理由见 §2“执行语言”行）；参数约定 `--protoc`/`--python`/`--skip-*`。　**权威层级**：专项设计（第 3 层）——不得违反《商业级通用客户端框架总设计》/《商业级通用服务端框架总设计》。
> **边界**：本文只裁决**生成器工具形态与操作**（入口、执行面、单源、失败语义、工作流）；各生成物的**语义权威在位不动**——buildHash 闭包与 Join 握手在《状态同步专项设计》、协议语义在 `battle.proto` 单源、同步分层在《Sim组织专项设计》/《状态同步专项设计》、表链在《玩法数值与Luban配置专项设计》。本文只回答**怎么生成、去哪生成、生成什么、忘了会怎样**。
> **吸收登记**：本文件吸收了 `scripts/README.md` 的 codegen 操作知识（Luban 暂存/发布段与生成链行——原文照录 [归档记录/2026-10-11](../../归档记录/2026-10-11/README.md)）与 `gen-proto.ps1` 中文头注释（protoc 来源/版本对齐约束，正文吸收进 §2/§4）。五件工具头注释保留各自 why，操作面收口本文。

## 1. 定位

六件 CLI 生成器是“两端同源”红线的执行面：buildHash 是 Join 握手版本红线，`gen-sync-code` 根治“加一个字段手抄六处”的静默分叉，`gen-luban` 是表源到双端产物的唯一通道。统一形态＝**一个工具箱入口 + 一份共享单源 + 一种执行形态 + 全 Python 实现**（选 py 的理由见 §2“执行语言”行）。

代码落点：`scripts/codegen/`（工程脚本，不入 Unity 程序集；全部 Python，`python` 3.10+ 为 toolchain 既定项）。

| 文件 | 职责 |
|---|---|
| `_codegen.py` | **共享单源**：仓库根推导（`repo_root()`）+ 统一输出三档（`info`/`warn`/`fail`，前缀 `[codegen/<tool>]`）+ 统一执行面（`run_tool`：异常 → 一行 FAILED + exit 1） |
| `toolbox.py` | 统一入口：无参列工具索引；`toolbox.py <tool> [args...]` 以**同一解释器**转发参数与退出码 |
| `gen-build-hash.py` | buildHash 生成 + `--check` 校验（**规则单源**——规则只有这一份，无第二清单入口） |
| `gen_proto.py` | `battle.proto` → `Proto/Generated/Battle.cs`（`--protoc`） |
| `gen_luban.py` | 表链重生成（C#/binary/lua/LuaKeys；Assets 外暂存 + 只发布变更文件） |
| `gen_sync_code.py` | `[StateLayer]` 标注 → `EntitySlot.Sync.g.cs`（checksum 脚手架；逐字节等价移植自 ps1 原版） |
| `gen-ui-page.py` | `#uiform` + `UiPageManifest` + `UiPageContract` → `UiPageCatalog.g.cs`（`PageDefinition` 单制品；`--check` 确定性） |
| `gen-ui-api.py` | `UiApiSpec.json` → `UIBindIndex.Api.g.cs`（partial 声明）/ `UIBindBase.Api.g.cs` / `UiApiManifest.g.cs` / `UiApiShim.g.cs` / `LuaBehaviourAdapter.Dispatch.g.cs` / `UI逻辑API参考.md` §3 生成区（`--check` 确定性） |
| `refresh-hash.py` | 刷新编排：生成 → RoomServer 重建 → Unity 重编译 → 双端对账 |

## 2. 统一形态（红线）

| 面 | 统一后 |
|---|---|
| 入口 | **统一入口 `python scripts/codegen/toolbox.py <tool> [args...]`**；单脚本直调保留（`build-player.py` 门禁、`Luban/gen.bat` 委托等既有消费面不动） |
| 执行面 | 每工具一个 `main()` + `run_tool` 收口（异常 → 一行 FAILED + exit 1）；前提缺失（缺 protoc/缺 Luban.exe/缺参数）抛**带用法信息**的错误 |
| 失败兜底 | 预期失败＝**一行 `[codegen/<tool>] FAILED: ...` + exit 1**（不冒栈、不静默）；校验/对账类同契约（mismatch 即 exit 1） |
| 常量 | 仓库根推导只在 `_codegen.py`；SHA256 内容哈希只在 `gen_luban.py` 内联（唯一消费者，收口单处）；各工具 I/O 路径仍在各自脚本（各自单源） |
| 输出 | 统一前缀 `[codegen/<tool>]`，成功/警告/失败三档 |
| **执行语言** | **全 Python**：BuildHash 规则单源本就是 py 且字节确定性要求最高、PS 文本语义（GBK/BOM/CRLF）是本仓文档化陷阱源、py 可单测、toolchain 已含 python——不为“统一”而把最不该动的规则单源迁去更脆的语言 |
| 编码 | 产物/脚本 UTF-8；`.g.cs` 产物行尾各自保持与入库件一致（`EntitySlot.Sync.g.cs` CRLF） |
| 生成物署名 | 统一为 `// <auto-generated: <生成器路径> —— DO NOT EDIT。源：<单源>；重跑 <命令>。>`（≤3 行，闭合于 `>`）：`gen-build-hash` 两处、`gen_sync_code`、`gen-ui-page`、`gen-ui-api`、`Luban/gen_lua_keys` 同形；Luban 自身模板产物（`Assets/GameData/Generated/*.cs`）与随机化签名信封不在内 |
| 头注释 | 五段式：用途（why）/ 入口（工具箱 + 直调）/ 输出 / 重跑时机 / 消费点；**why 留在脚本头，操作面收口本文** |

**消费面兼容**：`build-player.py` 出包门禁仍直调 `gen-build-hash.py --check`（只认 exit code）；`Luban/gen.bat` → `gen_luban.py` 委托（v1.1 换指）；`refresh-hash.py` 内部调 `gen-build-hash.py`（同解释器）；`Luban/gen.sh` 已删除（死遗留——指向不存在的 Luban 可执行体路径）；CI（`ci.yml`）不直调任何生成器。工具箱只提供统一入口与索引，不改写任何调用。

## 3. 单源与同步面

| 常量/规则 | 唯一出处 | 备注 |
|---|---|---|
| 仓库根推导 | `repo_root()`（`_codegen.py`） | scripts/README"脚本自身位置推导"约定的机制化——移动脚本位置时只改这一处 |
| 输出/失败契约 | `info`/`warn`/`fail`/`run_tool`（`_codegen.py`） | 前缀与三档语义；新工具禁再裸 `print`/裸异常 |
| buildHash 规则（源集/排序/行尾归一化/算法） | `gen-build-hash.py` **单源** | `--check` 复算与生成同规则（2026-10-07 起 `BuildHashSourceSet.g.cs`/`BuildHashTests` 已退役，无第二清单入口） |
| 同步脚手架规则 | `gen_sync_code.py` 解析 `[StateLayer]` | 字段声明处标注＝唯一真相；生成器只做机械半部 |
| 表链 schema/表源 | `Luban/`（权威见《玩法数值与Luban配置专项设计》） | `gen_luban.py` 只是执行面 |
| 工具链登记 | `scripts/gate/toolchain.json` `tools` 节（`kind: cli/docs`） | 新增生成器须同步该节 + 本文 §4/§5 两处清单；CLI 入口见 `python scripts/toolchain.py generate <tool>` |

## 4. 工具清单

| 工具 | 输入 | 输出 | 重跑时机 | 消费点 | 忘跑后果 |
|---|---|---|---|---|---|
| `build-hash` | Sim/协议/生成读码面/源链接共编件的内容（源集见脚本头注释；**表数值 `.bytes` 不在内**——数据面走运行期摘要） | `Assets/LiteNet/Core/Protocol/BuildHash.g.cs`（16 位 hex 常量） | 改 `LiteSim/{Scripts,Systems}`、`LiteNet/{Proto,Protocol,Transport/Security}`、`GameData/Generated`、`SHARED_LINK_FILES` 登记件后 | Join 握手（`JoinRequest.build_hash`）+ 启动期断言 | 两端 hash 不等 → **Join 被拒进房** |
| `build-hash --check` | 同上 + 已生成常量 | 复算比对（exit 0/1） | 出包前（`build-player.py` 门禁步强制，不可跳过；开发期不校验） | 出包门禁 | stale 包出厂，实机两端拒进房 |
| `proto`（`--protoc <protoc.exe>`） | `Assets/LiteNet/Core/Proto/battle.proto` | `Proto/Generated/Battle.cs`（入库，勿手改） | 改 `.proto` 后（随后 ★ build-hash） | `LiteNet/Core/Protocol` 编解码 | 编译失败（生成物入库，无静默面） |
| `luban` | `Luban/Data/*.xlsx` + schema | `GameData/Generated`、`GameData/Config`、`Lua/Cfg`、`LuaKeys.g.cs` | 改表源/表结构后（随后 ★ build-hash） | 两端 `ConfigService`/`ServerTableLoad` | 表与代码漂移（L1 表守卫会红） |
| `sync-code` | `[StateLayer]` 标注字段（8 结构体） | `EntitySlot.Sync.g.cs`（入库，勿手改） | 同步字段/分型表结构变化后（随后 ★ build-hash） | `SimChecksum` 双口径 | **静默分叉**——漏字段不报编译错，和解假和解（生成器存在的原因，见脚本头注释） |
| `refresh-hash` | 上三者的编排 | 新常量 + 双端对账结论 | 改 Sim/协议/表后的"一键全链"（服务器重建/Unity 重编译可开关跳过，但**跳过≠免除**，Join 前必须补上） | 人工流程 | 漏重建/漏重编译 → Join 超时，症状远离真因（脚本头注释有完整病例） |

"什么改动必跑什么"的**红线权威表**在[修改指南 §2.3/§3.9](../../规范/02-代码与修改规范.md)——本表只做工具视角对照，不复制红线条目。

## 6. 标准工作流与验证层级

1. 改动涉及共享源集 → 查[修改指南 §2.3](../../规范/02-代码与修改规范.md)定位必跑工具（红线表权威）。
2. 单工具走 `python scripts/codegen/toolbox.py <tool> [args]`；全链刷新走 `toolbox.py refresh-hash`。
3. 生成物一律入库（`Battle.cs`/`BuildHash.g.cs`/`EntitySlot.Sync.g.cs`/表产物），头注释均带 `DO NOT EDIT`；提交随源一起走。
4. 出包前 `--check` 由 `build-player.py` 门禁步强制，无需手工记得。
5. **本工具箱自身的验证层级**：改形态/加工具时——① 全件 `py_compile` 零错误；② `toolbox.py` 无参索引、未知工具 exit 1、单工具转发实跑；③ 生成器逻辑改动的批次必须证明"生成物 diff 为零"（对未变源跑生成、产物逐字节不变）或走 BuildHash 重录流程；④ 红线联动照旧归修改指南 §2.3 管。

## 7. 扩展约定（新增第六件 CLI 生成器）

1. 落 `scripts/codegen/`，命名 `gen_<对象>.py`（snake_case）；**只用 Python**（v1.1 裁决，不再新增 ps1/py 混用）；`import _codegen` 取共享面。
2. 共享面只进 `_codegen.py`（根推导/输出/run_tool/执行面收口），禁在工具内再手写同型原语；工具自身 I/O 路径在自身脚本常量（各自单源）。
3. 执行面：`main()` + `run_tool(TOOL, main)` 收口；预期失败 `raise ValueError("usage: ...")` → 一行干净报告 + exit 1，不冒栈。
4. 头注释五段式（§2）；`toolbox.py` `TOOLS` 注册一行；本文 §4 清单加一行；`toolchain.json` `tools` 节登记；施工进度记录批次证据。
5. 生成逻辑改动的批次必须证明"生成物 diff 为零"（对未变源跑生成、产物逐字节不变）——`gen_sync_code.py` 移植批即按此验收（唯一 diff＝署名行）。
