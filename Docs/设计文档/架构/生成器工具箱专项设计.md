# 生成器工具箱专项设计

> **版本**：v1.2（2026-11-01）
> **执行语言**：工具统一为 **Python**（裁决理由见 §2“执行语言”行）；参数约定 `--protoc`/`--python`/`--check`/`--skip-*`。　**权威层级**：专项设计（第 3 层）——不得违反《商业级通用客户端框架总设计》/《商业级通用服务端框架总设计》。
> **v1.2 变更**：统一入口由“保留直调”改为“门禁/CI/脚本内部只走 toolbox，人工直调 deprecated”；新增 `all`/`doctor`/`trig`、`--check` 补齐、输入指纹、路径单源、调用点分类守卫与 `codegen-check` 门禁；`Luban/gen.bat` 仅保留为兼容别名。
> **边界**：本文只裁决**生成器工具形态与操作**（入口、执行面、单源、失败语义、工作流）；各生成物的**语义权威在位不动**——buildHash 闭包与 Join 握手在《状态同步专项设计》、协议语义在 `battle.proto` 单源、同步分层在《Sim组织专项设计》/《状态同步专项设计》、表链在《玩法数值与Luban配置专项设计》。本文只回答**怎么生成、去哪生成、生成什么、忘了会怎样**。
> **吸收登记**：本文件吸收了 `scripts/README.md` 的 codegen 操作知识（Luban 暂存/发布段与生成链行——原文照录 归档记录/2026-10-11）与 `gen-proto.ps1` 中文头注释（protoc 来源/版本对齐约束，正文吸收进 §2/§4）。五件工具头注释保留各自 why，操作面收口本文。

## 1. 定位

七件 CLI 生成器是“两端同源”红线的执行面：buildHash 是 Join 握手版本红线，`sync-code` 根治“加一个字段手抄六处”的静默分叉，`luban` 是表源到双端产物的唯一通道。统一形态＝**一个工具箱入口（含 all/doctor/trig）+ 一份共享单源 + 一种执行形态 + 全 Python 实现**（选 py 的理由见 §2“执行语言”行）。

代码落点：`scripts/codegen/`（工程脚本，不入 Unity 程序集；全部 Python，`python` 3.10+ 为 toolchain 既定项）。

| 文件 | 职责 |
|---|---|
| `_codegen.py` | **共享单源**：仓库根推导（`repo_root()`）+ 统一输出三档（`info`/`warn`/`fail`，前缀 `[codegen/<tool>]`）+ 统一执行面（`run_tool`：异常 → 一行 FAILED + exit 1；直调 deprecated）+ `normalize_eol`/`input_digest`/`load_module` |
| `toolbox.py` | 统一入口：无参列索引；`toolbox.py <tool> [args...]` 同解释器转发；`all`（严格序 + 生成/检查）、`doctor`（路径体检 + 调用点清单）、`trig`（Unity eval → ToolWriteScope） |
| `gen-build-hash.py` | buildHash 生成 + `--check` 校验（**规则单源**——规则只有这一份，无第二清单入口） |
| `gen_proto.py` | `battle.proto` → `Proto/Generated/Battle.cs`（`--protoc`） |
| `gen_luban.py` | 表链重生成（C#/binary；Assets 外暂存 + 只发布变更文件） |
| `gen_sync_code.py` | `[StateLayer]` 标注 → `EntitySlot.Sync.g.cs`（checksum 脚手架；逐字节等价移植自 ps1 原版） |
| `gen-ui-page.py` | `#uiform` + 页面 prefab（组件映射 `ui_builtin_component_types.json`）→ `UIPageCatalog.g.cs` / `PageIds.g.cs`（`PageDefinition` 单制品；`--check` 确定性） |
| `gen-ui-api.py` | `UIApiSpec.json` → `UIBindIndex.Api.g.cs`（partial 声明）/ `UIBindBase.Api.g.cs` / `UIApiManifest.g.cs`（`--check` 确定性） |
| `refresh-hash.py` | 刷新编排：生成 → RoomServer 重建 → Unity 重编译 → 双端对账 |

## 2. 统一形态（红线）

| 面 | 统一后 |
|---|---|
| 入口 | **唯一入口 `python scripts/codegen/toolbox.py <tool> [args...]`**：门禁/CI/脚本内部只走这里；人工直调保留但打印 `[deprecated]`（`CODEGEN_VIA_TOOLBOX=1` 时不打印）；`Luban/gen.bat` 仅兼容别名 |
| 执行面 | 每工具一个 `main()` + `run_tool` 收口（异常 → 一行 FAILED + exit 1）；前提缺失（缺 protoc/缺 Luban.exe/缺参数）抛**带用法信息**的错误；`all` 缺 `--protoc` 在开跑前 fail-fast |
| 失败兜底 | 预期失败＝**一行 `[codegen/<tool>] FAILED: ...` + exit 1**（不冒栈、不静默）；`--check` 过期＝非零并给 toolbox 重跑提示；`all` 首个失败即中止、退出码归一 1（用法 2） |
| 常量 | 仓库根推导只在 `_codegen.py`；输入指纹/行尾归一/模块加载只在 `_codegen.py`；客户端 BuildHash 路径只在 `gen-build-hash.SHARED_OUT_REL`+`shared_out_file(root)`；各工具 I/O 路径仍在各自脚本（各自单源） |
| 输出 | 统一前缀 `[codegen/<tool>]`，成功/警告/失败三档；`all`/`doctor` 额外打印步骤/路径/调用点清单 |
| **执行语言** | **全 Python**：BuildHash 规则单源本就是 py 且字节确定性要求最高、PS 文本语义（GBK/BOM/CRLF）是本仓文档化陷阱源、py 可单测、toolchain 已含 python——不为“统一”而把最不该动的规则单源迁去更脆的语言 |
| 编码 | 产物/脚本 UTF-8；`.g.cs` 产物行尾各自保持与入库件一致（`EntitySlot.Sync.g.cs` CRLF；`SimTrigTables.cs` 保持既有 CRLF/`git` 归一） |
| 生成物署名 | 统一 3 行：`// <auto-generated: toolbox/<tool> — DO NOT EDIT` + `// input: <相对路径\|N sources\|shared/meta source set> sha256:<8>` + `// regen: python scripts/codegen/toolbox.py <tool>[ args]>`（`>` 收口、无时间戳）：BuildHash×2、EntitySlot.Sync、UIPageCatalog、PageIds、3 个 UI API 产物共 8 个；**豁免**：`Battle.cs`（protoc 产物，sidecar 戳 `Generated/Battle.cs.input`）、`SimTrigTables.cs`（在 BuildHash 闭包内，改头=换号）、`.bytes`、Luban 模板 `.cs`、随机化签名信封 |
| 头注释 | 五段式：用途（why）/ 入口（toolbox；直调 deprecated）/ 输出 / 重跑时机 / 消费点；**why 留在脚本头，操作面收口本文** |

**消费面兼容**：`build-player.py` 出包门禁经 `toolbox.py build-hash --check-shared`（只认 exit code）；`sync-and-sim-e2e.py` 同走 toolbox；`toolbox all --check` 由 `.workflow/config.json` 的 `codegen-check` 承接（shared+meta 两常量）；`refresh-hash.py` 内部 build-hash 步经 toolbox；`Luban/gen.bat` → `gen_luban.py` 兼容别名（打印 deprecated）；CI（`ci.yml`）不直调任何生成器。直调不再作为门禁/CI 的事实入口。

## 3. 单源与同步面

| 常量/规则 | 唯一出处 | 备注 |
|---|---|---|
| 仓库根推导 | `repo_root()`（`_codegen.py`） | scripts/README"脚本自身位置推导"约定的机制化——移动脚本位置时只改这一处 |
| 输出/失败契约 | `info`/`warn`/`fail`/`run_tool`（`_codegen.py`） | 前缀与三档语义；新工具禁再裸 `print`/裸异常；直调 deprecated 也在此 |
| 输入指纹/行尾归一/模块加载 | `normalize_eol()`/`input_digest()`/`load_module()`（`_codegen.py`） | 指纹 = 排序相对路径 + NUL + 行尾归一后的 SHA-256 前 8 位；生成器与 doctor 不另写 |
| 生成物签名 | `signature()`（`_codegen.py`） | 3 行头（`toolbox/<tool>` + `input sha256:<8>` + `regen`），末行 `>` 收口；10 个产物同源 |
| 客户端 BuildHash 路径 | `gen-build-hash.SHARED_OUT_REL` + `shared_out_file(root)` | `refresh-hash`/`local-chain`/doctor 只调函数，禁止手抄 `Packages/com.litegame.net/...` |
| `all` 顺序 | `toolbox.ALL_ORDER` | `luban → ui-page → ui-api → sync-code → proto → build-hash`；不含 trig/refresh-hash |
| 调用点分类 | `scripts/tests/fixtures/codegen-call-sites.json`（`(file,line,literal)`） | 守卫逐字面量分类；`invocation` 只能指 toolbox；`contract-test`/`compat` 为例外 |
| buildHash 规则（源集/排序/行尾归一化/算法） | `gen-build-hash.py` **单源** | `--check` 复算与生成同规则（2026-10-07 起 `BuildHashSourceSet.g.cs`/`BuildHashTests` 已退役，无第二清单入口） |
| 同步脚手架规则 | `gen_sync_code.py` 解析 `[StateLayer]` | 字段声明处标注＝唯一真相；生成器只做机械半部；头指纹只随解析后的字段模型 |
| 表链 schema/表源 | `Luban/`（权威见《玩法数值与Luban配置专项设计》） | `gen_luban.py` 只是执行面；头指纹只随表源 xlsx 与 schema 变化 |
| 工具链登记/索引 | `scripts/gate/toolchain.json` `tools` 节 + `python scripts/toolchain.py docs` | 新增生成器须同步该节 + 本文 §4/§5；CLI 入口见 `python scripts/toolchain.py generate <tool>`；改 command 后必须再生 `Docs/说明/工具索引.md` |

## 6. 标准工作流与验证层级

1. 改动涉及共享源集 → 查[修改指南 §2.3](../../规范/02-代码与修改规范.md)定位必跑工具（红线表权威）。
2. 单工具走 `python scripts/codegen/toolbox.py <tool> [args]`；全链生成走 `toolbox.py all --protoc <protoc.exe>`；全链新鲜度检查走 `toolbox.py all --check`；路径体检走 `toolbox.py doctor`；三角表走 `toolbox.py trig`（需 Editor）；全链刷新走 `toolbox.py refresh-hash`。
3. 生成物一律入库（`Battle.cs`/`BuildHash.g.cs`/`EntitySlot.Sync.g.cs`/表产物），头注释均带 `DO NOT EDIT`；提交随源一起走。
4. 出包前 `--check` 由 `build-player.py` 门禁步强制；PR/`wf verify` 的 `codegen-check` 走 `toolbox.py all --check`（shared+meta 两常量）。
5. **本工具箱自身的验证层级**：改形态/加工具时——① 全件 `py_compile` 零错误；② `toolbox.py` 无参索引、未知工具 exit 2、单工具转发实跑、`doctor` 健康树 exit 0；③ 生成器逻辑改动的批次必须证明"生成物 diff 为零"（对未变源跑生成、产物逐字节不变）或走 BuildHash 重录流程；④ `codegen-call-sites.json` 分类守卫 0 未分类/0 非法 invocation；⑤ 红线联动照旧归修改指南 §2.3 管。

## 7. 扩展约定（新增 CLI 生成器）

1. 落 `scripts/codegen/`，命名 `gen_<对象>.py`（snake_case）；**只用 Python**（v1.1 裁决，不再新增 ps1/py 混用）；`import _codegen` 取共享面。
2. 共享面只进 `_codegen.py`（根推导/输出/run_tool/指纹/签名/模块加载），禁在工具内再手写同型原语；工具自身 I/O 路径在自身脚本常量（各自单源），并暴露 `path_report()`。
3. 执行面：`main()` + `run_tool(TOOL, main)` 收口；预期失败 `raise ValueError("usage: ...")` → 一行干净报告 + exit 1，不冒栈；直调提示由 `run_tool` 统一。
4. 头注释五段式（§2）；`toolbox.py` `TOOLS` 注册一行、`ALL_ORDER` 插入位置（若进 `all`）、`--check` 实现；本文 §4 清单加一行；`toolchain.json` `tools` 节登记并跑 `toolchain.py docs`；施工进度记录批次证据。
5. 生成物头走 `_codegen.signature()`；输入指纹走 `_codegen.input_digest()`（解析模型优先，避免非输入改动噪音）；新增调用点同批更新 `codegen-call-sites.json`。
6. 生成逻辑改动的批次必须证明"生成物 diff 为零"（对未变源跑生成、产物逐字节不变）——`gen_sync_code.py` 移植批即按此验收（唯一 diff＝署名行）。
