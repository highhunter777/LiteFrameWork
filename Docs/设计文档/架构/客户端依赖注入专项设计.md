# 客户端依赖注入专项设计

日期：2026-11-09。范围：LiteFramework.Core 的 `ServiceContainer` 与 LiteGame.App 客户端装配。施工状态见 [客户端DI升级](../../施工进度/客户端构建与契约线.md#ch4-客户端DI升级)。

## 1. 目标与选型

客户端容器只做一件事：**装配期把已构造的实例按类型登记，运行期按类型取件**，并把释放责任讲清楚。Core 保持零 Unity、零第三方；不引入 MS DI。

明确不做（2026-11-09 精简裁决）：类型注册与反射构造、工厂注册、Singleton/Scoped/Transient 生命周期、父子容器、声明图预检、`IServiceContainer` 抽象。理由：生产装配全部是 `RegisterInstance`（实例由组合根直造），上述能力在客户端没有消费者；保留它们只会增加概念与故障面。

验收口径：每个服务唯一实例来源；依赖在组合根显式构造并登记；缺失在装配期 `Require` 即暴露；容器拥有的对象退出必定释放；帧驱动顺序独立于登记/解析顺序。

## 2. 统一装配

`ClientHost` 建立 RootScope 与 `ClientContext`；Context 持有唯一 Root `ServiceContainer`。模块的 `Put/Get/Require` 直接写入/读取该容器，不再维护第二份类型字典。

`Put` 同类型、同引用可重复暴露，换引用当场拒绝；`Seal` 后拒绝一切写入。具体类型与能力接口可以映射到同一实例（同一引用登记两次）。`Host.Product<T>`、Context 与容器查询必须获得同一对象。

UI 导航控制器、FeedbackService、DialogService/ToastTicker 等容器产物同时进入统一来源（见 §6.3）。

## 3. 登记与解析

- 唯一入口 `RegisterInstance<T>(instance, ownership)`；同类型重复登记当场抛。
- `Resolve<T>` 缺失即抛（消息指向装配点）；`TryResolve<T>` 缺失返回 false，不构造、不抛。
- 依赖由组合根显式构造后登记；容器不做构造注入，因此没有构造函数选择/歧义/循环依赖问题。
- `Seal()` 只冻结注册；失败/未冻结前可继续登记。帧计划覆盖校验在装配末段显式调用 `FrameSchedule.Validate()`（见 §5）。
- 运行期参数、配置快照、委托由实例登记或域工厂显式传入；构造器不负责异步初始化。

## 4. 所有权与关闭

`RegisterInstance` 默认 `Borrowed`：模块继续执行异步 Shutdown，容器只引用该实例。显式 `ContainerOwned` 表示把 IDisposable 释放责任交给容器。

容器用独立服务资源子 `ClientScope` 承担 LIFO 释放；父 RootScope 登记容器，宿主逆序关闭模块后再释放根。多接口别名按引用去重；重复 Dispose 幂等；单项失败继续释放并聚合到 `DisposeFailures`。关闭后拒绝注册/解析，并清除实例缓存、登记观察订阅与统计引用。

拥有异步关闭面或模块 Shutdown 已处理的对象保持 Borrowed，禁止再以 ContainerOwned 登记。

## 5. 帧驱动

`FrameSchedule` 独立承担帧计划、覆盖校验、别名去重、稳定快照与逐帧执行。容器只提供 `RegistrationsChanged` 通知与只读登记快照，不包含 `ITickable`、帧排序或逐帧入口。

`ClientContext` 创建唯一 Root `FrameSchedule` 并以 `ContainerOwned` 登记。组合根在装配末尾 `SetOrder(...)` → `Validate()` → `ServiceContainer.Seal()`；`Validate` 失败时容器仍未密封，可诊断修正。`GameEntry.Update` 持有调度器并 `Tick(Time.unscaledDeltaTime)`，不在每帧解析服务。

帧计划契约：

- 类型必须已登记、不得重复、必须实现 `ITickable`；已登记 Tickable 必须全部覆盖，多接口别名按实例引用去重。
- 校验不构造服务；无效计划保留原计划；未设置显式计划时按登记序发现已登记实例。
- 容器密封后帧序不可修改；关闭/回滚释放调度器并解除订阅。
- 每帧按索引遍历稳定快照；帧内解析不使当前迭代失效，稳态执行不分配托管内存；驱动异常 fail-fast，不吞掉后继续驱动。
- 产品保持 11 项既有顺序：Dispatcher → WorldClock → UIClock → DOTween UI轨 → UIService → TimelineRunner → VfxService → DialogService → ToastTicker → CommandBus → 流程机。EventBus 无延迟队列，不在帧表内。

## 6. 服务域与动态对象

> **作用域表权威＝[商业级通用客户端框架总设计 §6.2](商业级通用客户端框架总设计.md)**（Scope 生命周期/允许持有/退出动作）；下表仅作服务域视角补充，域划分与持有物以 §6.2 为准。

| 服务域 | 目标所有权 | 服务内容 |
| --- | --- | --- |
| Root | Host | 内容、平台、设置、时钟、输入能力、UI 运行时、日志、遥测 |
| Account | 登录到登出 | Token、Profile、RemoteConfig、Meta 会话（同总设计 §6.2） |
| Match | 匹配到结算退出 | `IMatchRuntime`（Battle 侧端口，提供 BattleClient/BattleContext 材料与 Match 子域入口）、输入历史、对局配置快照 |
| Scene/UI | 场景或界面实例/展示域 | 按消费者需要建立服务域，资源租约仍走 ClientScope |

服务域是**彼此独立的容器**，不做父子查找：每个域由域工厂 `new ServiceContainer()` 创建，登记本域实例，`Seal` 后交给消费者；跨域依赖由组合根/域工厂显式传入，不经容器向上查找。域容器登记进对应 `ClientScope`（或由域对象显式 Dispose），释放顺序由登记顺序决定。

`AccountDomain` 在登录时创建独立 Account 容器并登记 `IMetaAccountSession`；`MatchSessionFactory` 创建 Match 容器并登记 `IBattleClient`；`BattleDomainFactory` 从 `IMatchRuntime.CreateMatchServices()` 取未 Seal 的 Match 服务域，直接构造 `BattleContext` 与 `EventBus` 并登记（`ContainerOwned`），`Seal` 后返回 `BattleDomain`。`BattleContext` 不再经工厂解析。

流程负责迁移和调用工厂；逐帧 Sim、输入与渲染循环只消费已注入对象。ClientScope 继续持有取消、订阅、租约；服务释放者必须唯一（容器 `ContainerOwned` 或域对象显式 Dispose，二者幂等）。

### 6.1 操作作用域（OperationScope）

- `OperationScope` 是**调用方拥有**的一次操作上下文，不由容器注册：同时持有 `CancellationToken`、超时、合并键、所有者与状态，`Dispose` 释放链接令牌/计时器。现役实现：`Packages/com.litegame.framework/Runtime/Core/Operations/OperationScope.cs`（`Start(owner, mergeKey, timeout, parent)`；`OperationState` 五态；令牌取消——含超时/父令牌——回写状态）。
- 使用面：UI 排队与转场、内容下载/校验、场景加载、会话重连。四类操作共用同一套取消、超时、合并与拒绝语义，不再各自持有 `CancellationTokenSource` + 超时字段。
- 取消只约束“还没开始的步骤”；已开始的清理必须执行（与 `ClientHost.ShutdownAsync` 同口径）。

### 6.2 错误恢复（ErrorKind）

- 错误分类统一为 `ErrorKind`：`Transient` / `Recoverable` / `Compatibility` / `Security` / `Fatal`；分类在抛出点声明，不在 catch 点猜测。
- `ErrorRecoveryService` 由 Root 域注册，提供“分类 → 动作”的**执行器**（有界重试、清缓存、回登录、导出诊断、退出），并接入引导失败、内容失败、会话失败与错误页；只做映射、没有执行器的静态骨架不保留。
- 错误页/诊断只消费 `ErrorKind` 与恢复结果，不自行拼错误码或第二套枚举。
- 现役实现：`ErrorKind`/`ClientErrorException`（`Packages/com.litegame.framework/Runtime/Core/Errors/ErrorKind.cs`）、`ErrorRecoveryService`/`RecoveryPolicy`/`IRecoveryActions`（`Packages/com.litegame.framework/Runtime/Hosting/Recovery/`）、生产动作 `AppRecoveryActions`（`Assets/LiteGame/Modules/Recovery/`）、受控内容缓存清理 `IContentCacheMaintenance`（`Packages/com.litegame.framework/Runtime/Services/Content/Activation/ContentCacheMaintenance.cs`）、账号重入单点 `AccountReentry`（`Assets/LiteGame/Modules/Procedure/Flow/AccountReentry.cs`，端口 `IAccountLoginControl`/`ILoginSurface` 住 `Modules/Meta/Abstractions`）。
- 动作映射：Transient→有界重试；**Recoverable→有界重试，重试耗尽或调用点无法重试时清受控内容缓存（删候选产物 + 激活记录回退 builtin）后阻断**；Compatibility→阻断；Security→导出后阻断；Fatal→导出并安全退出（编辑器不退出）。房间侧 JoinAck 拒绝/超时与准备失败属本次房间操作的恢复结果：先释放本次会话并完成必要卸载，再由 `IRoomFlow` 的唯一观察者经 `FeedbackService` 展示不可重试错误确认，确认后回大厅重新取票，不直接送入只支持重启的错误阶段。
- “重新登录”不是启动错误动作：启动失败语境没有登录态；凭证失效（Meta 401 / `auth.unauthorized`）由 `MetaSessionFacade`（`IMetaSession` 实现）统一收口转 `AccountReentry`（登出 → 离场 → 回登录页），页面不各自处理 401。
- 离线模式按“产品允许时”执行：本作在线对局不提供离线恢复，不造空动作（单机训练属 `LiteGame.Adapters.Dev` 装配层，不属恢复链）。

### 6.3 跨程序集接缝与页面服务装配

- **开发装配接缝单点**：产品侧只认 `IDevAssembly`（`DevHooks.Current`）；本地传输工厂经 `IDevAssembly.LocalTransport` 取件，不再另设静态注册表。端口 `ILocalTransportFactory` 住 `LiteGame.Modules.Dev`（消费方 `LiteGame.Modules.Session` 已引用 Dev，无环）；发布形态返回 null，测试房分支由 `DevBuildFacts.IsDevelopment` 把守。
- **页面服务装配（2026-11-06 裁决）**：`IPageContext` 由 `AppComposition.BindPageServices` 一次产出、按页面注入，页面逻辑件只持有注入引用；UI 段不自建服务定位器，`Modules/UI` 也不引用任何 `LiteGame.Adapters.*`。
- **设置页端口装配**：`ISettingsPagePort`（UI 域自持契约）由组合根在 `ProductSettings` 实例登记之后包成 `ProductSettingsAdapter`（`App/PageServices`）；`PageContext` 构造注入 `Func<ISettingsPagePort>` 惰性取，不在 `BindPageServices` 当场 `Require<ProductSettings>`（`BindPageServices` 早于 `BindProductSettings`，当场取会抛）。
- **房间入场装配**：Meta 只出票据事实（`MetaLoginService : IRoomTicketSource/IMetaConfigFacts`），入场/离场由 `ProcedureFlow : IRoomFlow/IAccountLoginControl` 统一持有；`ProcedureSegment` 在同一初始化窗口构造 `RoomFlowLifetime`、阶段机与 `ProcedureFlow`，同实例登记 `IRoomFlow`/`IAccountLoginControl` 并注入 `AccountReentry`；`AppComposition.BindPageServices` 直接 `Require<IRoomFlow>` 构造 `MetaSessionFacade`，不再有 `BindMetaEntry` 后装订。
