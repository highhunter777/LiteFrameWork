# 客户端依赖注入专项设计

日期：2026-10-08。范围：LiteFramework.Core/Async 与 LiteGame.App 客户端装配。施工状态见 [客户端DI升级](../../施工进度/客户端构建与契约线.md#ch4-客户端DI升级)。

## 1. 目标与选型

客户端沿用显式注册的 `ServiceContainer`，按批次补齐统一装配、依赖图预检、所有权与服务作用域。Core 保持零 Unity、零第三方实现依赖；不引入服务端 MS DI 包。业务通过构造参数消费依赖，模块和类型化工厂承担装配。MonoBehaviour 经明确绑定入口接线，Sim 经参数/配置快照接线，Lua 经能力门面接线。

完整 DI 的验收包含：每个服务唯一实例来源、生命周期可解释、依赖在启动/建域时校验、退出必定释放、动态对象有类型化工厂、帧驱动顺序独立于对象解析顺序。接口仅用于 IO/平台/所有权边界或真实替代实现，不为所有类机械增加接口。

## 2. 统一装配

`ClientHost` 建立 RootScope 和 `ClientContext`；Context 持有唯一 Root `ServiceContainer`。模块的 `Put/Get/Require` 直接写入/读取该容器，不再维护第二份类型字典。Context 是启动装配面；运行期业务只持显式注入的依赖。

`Put` 同类型、同引用可重复暴露，换引用当场拒绝；注册冻结后拒绝全部写入。具体类型与能力接口可以映射到同一实例。`Host.Product<T>`、Context 与容器查询必须获得同一对象，真实构造只发生一次。

UI 导航控制器由 UiServiceModule 创建；流程导航委托、FeedbackService 和容器注册共享该实例。DialogService/FeedbackService/ToastTicker 等容器模块产物同时进入统一来源。

## 3. 依赖声明与预检

- 类型注册使用唯一最长公共构造函数；缺失、歧义、抽象实现与循环依赖给出可定位诊断。
- 工厂以 `RegisterFactory<T>(factory, params Type[] dependencies)` 显式声明需要解析的服务。无依赖工厂传空列表；运行期拒绝工厂解析未声明依赖。
- `Validate()` 遍历声明图，检查构造和工厂依赖；不调用构造函数、不执行工厂、不触发 IO。已传入的实例作为外部构造完成的叶节点，实例内部依赖不属于反射预检范围。
- `Seal()` 先预检，再冻结注册；失败保留未密封状态以便诊断和修正。构造函数与工厂实际执行中的异常仍在 Resolve 时报告；静态预检不能证明任意工厂函数正确。
- 裸配置、运行期参数由实例注册或类型化工厂明确传入；构造器不负责异步初始化。

## 4. 所有权与关闭

`RegisterInstance` 默认为 `ServiceOwnership.Borrowed`：模块继续执行异步 Shutdown，容器只引用该实例。显式 `ContainerOwned` 表示将 IDisposable 释放责任交给容器；构造/工厂注册生成的 IDisposable 默认归容器。

容器用独立服务资源子 Scope 承担 LIFO 释放；父 RootScope 登记容器，宿主逆序关闭模块后再释放根。容器模块在自身关闭或装配失败时提前释放其同步产物，保证消费者早于 UI/内容等模块设施关闭。多接口别名按引用去重；重复 Dispose 幂等；单项失败继续释放并保留诊断。关闭后拒绝注册/解析，并清除缓存、帧驱动与统计引用。

拥有异步关闭面或模块 Shutdown 已处理的对象保持 Borrowed，禁止再以 ContainerOwned 登记。外部已实例化对象的登记顺序必须表达其依赖关系；容器构造的对象按真实构造顺序逆序释放。

## 5. 帧驱动

`SetTickOrder(params Type[] services)` 在启动装配末尾显式声明驱动顺序；类型必须已注册，已知 Tickable 必须覆盖，别名按实例引用去重。后续解析只能填入已声明的驱动位置，不能在驱动中追加未声明的 Tickable。注册和 Resolve 顺序不改变显式驱动序。

当前产品保留代码实际驱动序：Dispatcher → WorldClock → UIClock → DOTween UI轨 → EventBus → UIService → LogicScheduler → UIScheduler → TimelineRunner → VfxService → DialogService → ToastTicker → **CommandCenter**（排队/延迟命令到期派发，先于流程机——命令对机器的 Request 当帧可被 Advance 应用） → ProcedureMachine。AudioService/EntityService 为统计服务，不进入驱动表。驱动列表按快照发布，解析新服务不修改正在遍历的列表。初始化/关闭顺序继续由模块清单明确表达。

## 6. 服务作用域与动态对象

> **作用域表权威＝[商业级通用客户端框架总设计 §6.2](商业级通用客户端框架总设计.md)**（Scope 生命周期/允许持有/退出动作）；下表仅作服务域视角补充，域划分与持有物以 §6.2 为准。

| 服务域 | 目标所有权 | 服务内容 |
| --- | --- | --- |
| Root | Host | 内容、平台、设置、时钟、输入能力、UI 运行时、日志、遥测 |
| Account | 登录到登出 | Token、Profile、RemoteConfig、Meta 会话（同总设计 §6.2） |
| Match | 匹配到结算退出 | BattleClient、BattleContext、输入历史、对局配置快照 |
| Scene/UI | 场景或界面实例/展示域 | 按消费者需要建立服务域，资源租约仍走 ClientScope |

作用域容器允许向父域查找能力；子域不得覆盖父域已有服务，父域不能反向解析子域服务。Root 禁止注册 Scoped，可注册 Singleton/Transient；Account/Match 子域可注册 Scoped/Transient。Singleton 不能捕获同域 Scoped；Transient 不得成为 Tickable。`Seal()` 在各域分别执行声明图、缺失依赖、循环和生命周期预检，失败时保留未密封状态。Scoped 每域一份，Transient 每次解析一份，二者均由当前域资源面释放。

`CreateScope("Account"/"Match")` 返回父域只读可见的子容器；进房/对局经**类型化工厂**建域：`AccountSessionFactory`（零引擎依赖，**L1 源链接直测**——进房参数变 `AccountSession`，传输选择经注入委托由产品装配根裁决）与 `MatchSessionFactory`（从 Account 会话建 Match 域，`BattleContext` 为工厂产物由容器承担释放——Unity 面验收）。流程负责迁移和调用工厂；逐帧 Sim、输入与渲染循环只消费已注入对象。ClientScope 继续持有取消、订阅、租约；服务作用域必须明确服务释放者，避免与资源域重复登记。

### 6.1 操作作用域（OperationScope）

- `OperationScope` 是**调用方拥有**的一次操作上下文，不由容器注册：同时持有 `CancellationToken`、超时、合并键、所有者与状态，`Dispose` 释放链接令牌/计时器。现役实现：`Assets/LiteFramework/Runtime/Core/Operations/OperationScope.cs`（`Start(owner, mergeKey, timeout, parent)`；`OperationState` 五态；令牌取消——含超时/父令牌——回写状态）。
- 使用面：UI 排队与转场、内容下载/校验、场景加载、会话重连。四类操作共用同一套取消、超时、合并与拒绝语义，不再各自持有 `CancellationTokenSource` + 超时字段。
- 取消只约束“还没开始的步骤”；已开始的清理必须执行（与 `ClientHost.ShutdownAsync` 同口径）。

### 6.2 错误恢复（ErrorKind）

- 错误分类统一为 `ErrorKind`：`Transient` / `Recoverable` / `Compatibility` / `Security` / `Fatal`；分类在抛出点声明，不在 catch 点猜测。
- `ErrorRecoveryService` 由 Root 域注册，提供“分类 → 动作”的**执行器**（有界重试、清缓存、回登录、导出诊断、退出），并接入引导失败、内容失败、会话失败与错误页；只做映射、没有执行器的静态骨架不保留。
- 错误页/诊断只消费 `ErrorKind` 与恢复结果，不自行拼错误码或第二套枚举。
- 现役实现：`ErrorKind`/`ClientErrorException`（`Assets/LiteFramework/Runtime/Core/Errors/ErrorKind.cs`）、`ErrorRecoveryService`/`RecoveryPolicy`/`IRecoveryActions`（`Assets/LiteFramework/Runtime/Modules/Hosting/Recovery/`）、生产动作 `AppRecoveryActions`（`Assets/LiteGame/App/Recovery/`）、受控内容缓存清理 `IContentCacheMaintenance`（`Assets/LiteFramework/Runtime/Modules/Content/ContentCacheMaintenance.cs`）、账号重入单点 `AccountReentry`（`Assets/LiteGame/App/Meta/AccountReentry.cs`）。
- 动作映射：Transient→有界重试；**Recoverable→有界重试，重试耗尽或调用点无法重试时清受控内容缓存（删候选产物 + 激活记录回退 builtin）后阻断**；Compatibility→阻断；Security→导出后阻断；Fatal→导出并安全退出（编辑器不退出）。
- “重新登录”不是启动错误动作：启动失败语境没有登录态；凭证失效（Meta 401 / `auth.unauthorized`）由 `MetaBridge` 统一收口转 `AccountReentry`（登出 → 离场 → 回登录页），页面不各自处理 401。
- 离线模式按“产品允许时”执行：本作在线对局不提供离线恢复，不造空动作（单机训练属 `LiteGame.Dev` 装配层，不属恢复链）。
