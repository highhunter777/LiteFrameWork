# 客户端依赖注入专项设计

日期：2026-11-08。范围：LiteFramework.Core/Async 与 LiteGame.App 客户端装配。施工状态见 [客户端DI升级](../../施工进度/客户端构建与契约线.md#ch4-客户端DI升级)。

## 1. 目标与选型

客户端沿用显式注册的 `ServiceContainer`，按批次补齐统一装配、依赖图预检、所有权与服务作用域。Core 保持零 Unity、零第三方实现依赖；不引入服务端 MS DI 包。业务通过构造参数消费依赖，模块和类型化工厂承担装配。MonoBehaviour 经明确绑定入口接线，Sim 经参数/配置快照接线，页面逻辑件经 `IPageContext` 注入的服务接线。

完整 DI 的验收包含：每个服务唯一实例来源、生命周期可解释、依赖在启动/建域时校验、退出必定释放、动态对象有类型化工厂、帧驱动顺序独立于对象解析顺序。接口仅用于 IO/平台/所有权边界或真实替代实现，不为所有类机械增加接口。

## 2. 统一装配

`ClientHost` 建立 RootScope 和 `ClientContext`；Context 持有唯一 Root `ServiceContainer`。模块的 `Put/Get/Require` 直接写入/读取该容器，不再维护第二份类型字典。Context 是启动装配面；运行期业务只持显式注入的依赖。

`Put` 同类型、同引用可重复暴露，换引用当场拒绝；注册冻结后拒绝全部写入。具体类型与能力接口可以映射到同一实例。`Host.Product<T>`、Context 与容器查询必须获得同一对象，真实构造只发生一次。

UI 导航控制器由 UI 段（`Modules/UI/UISegment.cs`）创建；流程导航委托、FeedbackService 和容器注册共享该实例。DialogService/FeedbackService/ToastTicker 等容器模块产物同时进入统一来源。

适配器只由组合根 `AppComposition` 产出、模块只经端口消费：UI 段的页面服务经 `AppComposition.BindPageServices` 装配成 `IPageContext`（`Meta`/`Room`/`Maps`/`Nav`）注入页面逻辑件，逻辑件由 prefab 根挂载、`UIPageLogicScanner` 按名解析；各域程序集（`LiteGame.Modules.*`）不出现任何 `LiteGame.Adapters.*` 引用。

## 3. 依赖声明与预检

- 类型注册使用唯一最长公共构造函数；缺失、歧义、抽象实现与循环依赖给出可定位诊断。
- 工厂以 `RegisterFactory<T>(factory, params Type[] dependencies)` 显式声明需要解析的服务。无依赖工厂传空列表；运行期拒绝工厂解析未声明依赖。
- `Validate()` 遍历声明图，检查构造和工厂依赖；不调用构造函数、不执行工厂、不触发 IO。已传入的实例作为外部构造完成的叶节点，实例内部依赖不属于反射预检范围。
- `Seal()` 先预检，再冻结注册；失败保留未密封状态以便诊断和修正。构造函数与工厂实际执行中的异常仍在 Resolve 时报告；静态预检不能证明任意工厂函数正确。
- 裸配置、运行期参数由实例注册或类型化工厂明确传入；构造器不负责异步初始化。

## 4. 所有权与关闭

`RegisterInstance` 默认为 `ServiceOwnership.Borrowed`：模块继续执行异步 Shutdown，容器只引用该实例。显式 `ContainerOwned` 表示将 IDisposable 释放责任交给容器；构造/工厂注册生成的 IDisposable 默认归容器。

容器用独立服务资源子 Scope 承担 LIFO 释放；父 RootScope 登记容器，宿主逆序关闭模块后再释放根。容器模块在自身关闭或装配失败时提前释放其同步产物，保证消费者早于 UI/内容等模块设施关闭。多接口别名按引用去重；重复 Dispose 幂等；单项失败继续释放并保留诊断。关闭后拒绝注册/解析，并清除实例缓存、登记观察订阅与统计引用；容器持有的帧调度器同步释放其驱动引用。

拥有异步关闭面或模块 Shutdown 已处理的对象保持 Borrowed，禁止再以 ContainerOwned 登记。外部已实例化对象的登记顺序必须表达其依赖关系；容器构造的对象按真实构造顺序逆序释放。

## 5. 帧驱动

`FrameSchedule` 独立承担帧计划、覆盖校验、别名去重、稳定快照与逐帧执行。`ServiceContainer` / `IServiceContainer` 不包含 `ITickable`、帧排序或逐帧入口；容器只向同程序集观察者提供只读 `ServiceRegistration` 快照、发布前校验和登记变更通知，不把帧调度策略写回 DI。

`ClientContext` 创建唯一 Root `FrameSchedule` 并以 `ContainerOwned` 登记。组合根在装配末尾调用 `FrameSchedule.SetOrder(params Type[] services)`，再密封容器；密封前校验同时覆盖依赖图与帧计划。`GameEntry.Update` 持有该帧调度器并调用 `Tick(Time.unscaledDeltaTime)`，不在每帧解析服务。

帧计划契约：

- 类型必须在本域登记、不得重复且必须可驱动；已知 Tickable 必须覆盖，多接口别名按实例引用去重。父域服务不重复进入子域帧计划。
- 计划校验不构造服务、不执行工厂；无效计划保留原计划。未设置显式计划时，按服务登记序发现已构造实例；显式顺序不受注册或解析先后影响。
- 惰性解析只填入计划中的位置；工厂隐藏的未编排 Tickable 在发布前拒绝，构造产生的 IDisposable 仍归原容器，失败回滚可回收。
- Transient 不允许进入已附着的帧调度器。纯容器不按 `ITickable` 类型施加帧规则；创建帧调度器时先检查存量登记，后续登记/实例发布继续检查。
- 容器密封后帧序不可修改；关闭/回滚释放调度器并解除观察订阅。帧驱动数由 `FrameSchedule` 的 `Frames` 统计输出，容器仅报告 DI 自身统计。
- 每帧按索引遍历一次稳定快照；帧内解析不使当前迭代失效，稳态执行不分配托管内存。驱动异常保持 fail-fast，不吞掉后继续驱动。

产品保持 11 项既有顺序：Dispatcher → WorldClock → UIClock → DOTween UI轨 → UIService → TimelineRunner → VfxService → DialogService → ToastTicker → CommandCenter → 流程机。EventBus 无延迟队列，不在帧表内。

## 6. 服务作用域与动态对象

> **作用域表权威＝[商业级通用客户端框架总设计 §6.2](商业级通用客户端框架总设计.md)**（Scope 生命周期/允许持有/退出动作）；下表仅作服务域视角补充，域划分与持有物以 §6.2 为准。

| 服务域 | 目标所有权 | 服务内容 |
| --- | --- | --- |
| Root | Host | 内容、平台、设置、时钟、输入能力、UI 运行时、日志、遥测 |
| Account | 登录到登出 | Token、Profile、RemoteConfig、Meta 会话（同总设计 §6.2） |
| Match | 匹配到结算退出 | `IMatchRuntime`（Battle 侧端口，提供 BattleClient/BattleContext 材料与 Match 子域入口）、输入历史、对局配置快照 |
| Scene/UI | 场景或界面实例/展示域 | 按消费者需要建立服务域，资源租约仍走 ClientScope |

作用域容器允许向父域查找能力；子域不得覆盖父域已有服务，父域不能反向解析子域服务。Root 禁止注册 Scoped，可注册 Singleton/Transient；Account/Match 子域可注册 Scoped/Transient。Singleton 不能捕获同域 Scoped；Transient 不得成为 Tickable。`Seal()` 在各域分别执行声明图、缺失依赖、循环和生命周期预检，失败时保留未密封状态。Scoped 每域一份，Transient 每次解析一份，二者均由当前域资源面释放。

`CreateScope("Account"/"Match")` 返回父域只读可见的子容器；进房/对局经**类型化工厂**建域：`AccountSessionFactory` 归 `Modules/Session`（零引擎依赖，**L1 源链接直测**——进房参数变 `MatchSession`，传输选择经注入委托由产品装配根裁决）；`MatchSessionFactory`/`BattleRunFactory` 归 `Modules/Battle/SubModules/SessionSubModule`（由 `BattleSegment` 装配，Battle 经 `IMatchRuntime.CreateMatchServices()` 从 Account 会话派生 Match 子域，`BattleContext` 为工厂产物由容器承担释放）。流程负责迁移和调用工厂；逐帧 Sim、输入与渲染循环只消费已注入对象。ClientScope 继续持有取消、订阅、租约；服务作用域必须明确服务释放者，避免与资源域重复登记。

### 6.1 操作作用域（OperationScope）

- `OperationScope` 是**调用方拥有**的一次操作上下文，不由容器注册：同时持有 `CancellationToken`、超时、合并键、所有者与状态，`Dispose` 释放链接令牌/计时器。现役实现：`Packages/com.litegame.framework/Runtime/Core/Operations/OperationScope.cs`（`Start(owner, mergeKey, timeout, parent)`；`OperationState` 五态；令牌取消——含超时/父令牌——回写状态）。
- 使用面：UI 排队与转场、内容下载/校验、场景加载、会话重连。四类操作共用同一套取消、超时、合并与拒绝语义，不再各自持有 `CancellationTokenSource` + 超时字段。
- 取消只约束“还没开始的步骤”；已开始的清理必须执行（与 `ClientHost.ShutdownAsync` 同口径）。

### 6.2 错误恢复（ErrorKind）

- 错误分类统一为 `ErrorKind`：`Transient` / `Recoverable` / `Compatibility` / `Security` / `Fatal`；分类在抛出点声明，不在 catch 点猜测。
- `ErrorRecoveryService` 由 Root 域注册，提供“分类 → 动作”的**执行器**（有界重试、清缓存、回登录、导出诊断、退出），并接入引导失败、内容失败、会话失败与错误页；只做映射、没有执行器的静态骨架不保留。
- 错误页/诊断只消费 `ErrorKind` 与恢复结果，不自行拼错误码或第二套枚举。
- 现役实现：`ErrorKind`/`ClientErrorException`（`Packages/com.litegame.framework/Runtime/Core/Errors/ErrorKind.cs`）、`ErrorRecoveryService`/`RecoveryPolicy`/`IRecoveryActions`（`Packages/com.litegame.framework/Runtime/Hosting/Recovery/`）、生产动作 `AppRecoveryActions`（`Assets/LiteGame/Modules/Recovery/`）、受控内容缓存清理 `IContentCacheMaintenance`（`Packages/com.litegame.framework/Runtime/Services/Content/Activation/ContentCacheMaintenance.cs`）、账号重入单点 `AccountReentry`（`Assets/LiteGame/Modules/Procedure/Flow/AccountReentry.cs`，端口 `IAccountLoginControl`/`ILoginSurface` 住 `Modules/Meta/Abstractions`）。
- 动作映射：Transient→有界重试；**Recoverable→有界重试，重试耗尽或调用点无法重试时清受控内容缓存（删候选产物 + 激活记录回退 builtin）后阻断**；Compatibility→阻断；Security→导出后阻断；Fatal→导出并安全退出（编辑器不退出）。房间侧 JoinAck 拒绝/超时与准备失败属本次房间操作的恢复结果：先释放本次会话并完成必要卸载，再由 `IRoomFlow` 的唯一观察者经 `FeedbackService` 展示不可重试错误确认，确认后回大厅重新取票，不直接送入只支持重启的错误阶段。
- “重新登录”不是启动错误动作：启动失败语境没有登录态；凭证失效（Meta 401 / `auth.unauthorized`）由 `MetaSessionFacade`（`IMetaSession` 实现）统一收口转 `AccountReentry`（登出 → 离场 → 回登录页），页面不各自处理 401。
- 离线模式按“产品允许时”执行：本作在线对局不提供离线恢复，不造空动作（单机训练属 `LiteGame.Adapters.Dev` 装配层，不属恢复链）。

### 6.3 跨程序集接缝与页面服务装配

- **开发装配接缝单点**：产品侧只认 `IDevAssembly`（`DevHooks.Current`）；本地传输工厂经 `IDevAssembly.LocalTransport` 取件，不再另设静态注册表。端口 `ILocalTransportFactory` 住 `LiteGame.Modules.Dev`（消费方 `LiteGame.Modules.Session` 已引用 Dev，无环）；发布形态返回 null，测试房分支由 `DevBuildFacts.IsDevelopment` 把守。
- **页面服务装配（2026-11-06 裁决）**：`IPageContext` 由 `AppComposition.BindPageServices` 一次产出、按页面注入，页面逻辑件只持有注入引用；UI 段不自建服务定位器，`Modules/UI` 也不引用任何 `LiteGame.Adapters.*`。
- **房间入场装配**：Meta 只出票据事实（`MetaLoginService : IRoomTicketSource/IMetaConfigFacts`），入场/离场由 `ProcedureFlow : IRoomFlow/IAccountLoginControl` 统一持有；`ProcedureSegment` 在同一初始化窗口构造 `RoomFlowLifetime`、阶段机与 `ProcedureFlow`，同实例登记 `IRoomFlow`/`IAccountLoginControl` 并注入 `AccountReentry`；`AppComposition.BindPageServices` 直接 `Require<IRoomFlow>` 构造 `MetaSessionFacade`，不再有 `BindMetaEntry` 后装订。

> 设计与进度分离：本表只定义批次范围与**退出条件**，**完成状态与证据不记于此**，见 [施工进度/客户端DI升级](../../施工进度/客户端构建与契约线.md#ch4-客户端DI升级)。

| 批次 | 工作 | 退出条件 |
| --- | --- | --- |
| DI-1 | 唯一 Root 来源、导航修复、声明图预检、所有权、显式 Tick 序 | .NET 容器/Context/Host 故障路径和框架回归通过；Unity 接线静态检查 |
| DI-2 | Scoped/Transient、父域查找、生命周期校验 | 域内复用、域间隔离、越域捕获拒绝、嵌套释放与 Transient 驱动禁用通过 |
