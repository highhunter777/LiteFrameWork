# 脚本形态统一专项设计

> **版本**：0.2（2026-10-21）
> **定位**：裁决 `scripts/` 下工程脚本的**角色分层、入口与登记、调用契约、文件与配置形态、全量 Python 迁移顺序**；回答“脚本最终该长什么样、现有脚本按什么批次转 Python”。
> **语言裁决（2026-10-21）**：`scripts/` 最终**全量 Python**，不保留 PowerShell 长期例外；Windows 原生能力通过 Python `subprocess` / `ctypes` / `winreg` 等调用，不再构成“必须用 PS”的理由。
> **不做的事**：不裁各工具的业务算法与产物语义；不重复清单 schema 与 `ToolWriteScope` 细则；不改 CI 车道、测试分层与发布流程；不把工程脚本放进 Unity 程序集；不要求迁移一次完成——按 §6 的 P0–P5 分批，但最终状态必须是零 `.ps1`。
> **冲突裁决**：入口/清单/CLI 形态以[开发工具链平台专项设计](开发工具链平台专项设计.md)为准；执行/写盘以[工具执行与写盘契约专项设计](工具执行与写盘契约专项设计.md)为准；生成器形态以[生成器工具箱专项设计](生成器工具箱专项设计.md)为准（其全 Python 裁决并入本文目标）；L2-D 的 CLI 参数与 dry-run 批次以[开发工具链平台分层设计](开发工具链平台分层设计.md) §6 为准。本文只裁“脚本作者面”，不另立第二套清单或执行契约。
> **关联**：[scripts/README](../../../scripts/README.md)、[技术支持](../../工具链/技术支持.md)、[工具索引](../../工具链/工具索引.md)、[修改指南](../../修改指南.md)、[directory-move-sync](../../../.agents/skills/directory-move-sync/SKILL.md)。

## 1. 原则

脚本形态统一的目标不是“所有脚本写成一样”，而是让维护者与 Agent 在**任意一个脚本前**都能回答四个问题：

1. 它是不是入口？入口叫什么？
2. 它怎么被调用、怎么失败、失败码是什么？
3. 它由谁登记、被谁消费、移动后要同步哪些面？
4. 它处在全量 Python 迁移的哪一批（P0–P5）？

四条原则：

| 原则 | 含义 |
|---|---|
| **单一 canonical 入口** | 每个用户面能力只有一个权威调用方式，写在清单 `command`；直调脚本保留兼容，但不得在文档里成为第二入口 |
| **按角色分层** | 全局入口、域入口、叶子工具、内部库、测试、一次性运维各有明确形态，禁止“既能直调又像库”的灰色地带 |
| **契约一致** | 参数、帮助、退出码、输出前缀、dry-run 的**语义**一致；迁移期 PS 壳只转发，不承载第二套契约 |
| **全量 Python、按风险分批** | 最终零 `.ps1`；按 P0–P5 迁移，每批行为等价、可独立回滚，不用“一次大重写”推倒 Windows/Unity 链路 |

## 2. 现行形态（统一基线）

规模基线（v0.2 盘点）：`scripts/` 下 18 个 `.ps1`（约 2715 行）与 15 个 `.py`（约 2536 行）；目标是 `.ps1` 归零。当前同时存在以下差异：

| 面 | 现行形态 | 造成的实际后果 |
|---|---|---|
| 语言 | 生成器已全 Python；门禁/构建/部署/本地联测/内容发布仍有 18 个 `.ps1` | 这是迁移对象，不再是长期保留面；最终统一 Python |
| 入口 | 存在“脚本直调 / `toolbox.py` / `toolchain.py`”三种路径；`gen-build-hash.py` 三者都可到达 | canonical 不唯一，文档与 CI 各写一套 |
| 登记 | 清单覆盖 18 条命令，但 `deploy/gm.ps1`、`deploy/deploy-room.ps1`、`deploy/wg-peer.ps1`、`local/local-chain.ps1` 等用户面脚本未登记；`toolchain_*.py`、`_codegen.py` 等内部模块与入口混放 | 用户找不到、注册面漏检、移动脚本后引用漂移 |
| 参数 | PS 用 `-Lane L1` 这类 PascalCase 参数；Python 混用 argparse、`sys.argv` 与位置参数 | 同一能力在 CLI 清单与脚本两处各写一份参数说明 |
| 帮助 | argparse 脚本有 `--help`；deploy 三件已有 comment-based help，gate/build/content/local 多数只有头注释或 `param()` | 不好发现用法，Agent 只能读源码 |
| 退出码 | 多数本地入口为 0/1；`local-chain`/`serve-cdn`/`nightly-gate` 会透传子进程任意退出码；argparse 返回 2；`toolchain.py` 另有 4/5。`wg-peer.ps1` 的 2/3/4 是**远端脚本**哨兵，不是本地退出码 | 调用方无法用统一规则判断“用法错误”还是“执行失败” |
| 输出 | 生成器 `[codegen/<tool>]`；CLI `[toolchain]`；内容脚本 `[FAIL]`；其余裸 `Write-Host` | 人读尚可，机器解析与日志检索困难 |
| 文件 | EOL 混用（部分 PS/Py 为 CRLF，其余 LF）；`l2-unity-gate.ps1` 带 BOM；多个 PS 含中文但无 BOM | PS 5.1 下中文误解析风险，diff 噪声 |
| 根路径 | PS 约 15 处重复 `$PSScriptRoot` 推导；Python 只有 codegen 收口到 `repo_root()` | 移动脚本时漏改一处即从错误 CWD 解析 |
| 配置 | 数据已是 JSON（`local-cdn.json`）；加载器必须是 `_` 前缀内部库，不得命名成 `*.config.ps1` 或可执行入口 | 容易被误当成可配置脚本直调 |

**结论**：差异集中在“作者面”，不是业务实现。统一先从登记与契约入手；语言按**全量 Python**目标迁移，PowerShell 只作为迁移期的兼容壳，不作为最终形态。

## 3. 角色分层与入口

### 3.1 六类角色

| 角色 | 判据 | 命名 | 是否进清单 | 例子 |
|---|---|---|---|---|
| 全局入口 | 面向所有工具的发现/执行入口 | `toolchain.py` | 是 | `python scripts/toolchain.py` |
| 域入口 | 一个域一个稳定入口，负责分发子工具 | `<域>/<动词>-<对象>.py` 或既有工具箱名 | 是 | `codegen/toolbox.py`、`gate/nightly-gate.py`、`local/local-chain.py` |
| 叶子工具 | 单一职责、可独立执行 | 动词开头 kebab-case，`.py` | 用户面/CI 面必进；仅被域入口注册的可豁免 | `gate/test.py`、`content/publish-candidate.py` |
| 内部库 | 被其他脚本 import，不独立执行 | `_` 前缀，`.py` | 否 | `_codegen.py`、`_ssh_host.py` |
| 测试 | 脚本层契约测试 | `tests/test_*.py` | 否 | `tests/test_toolchain.py` |
| 一次性运维 | 历史补丁/一次性扫描，不进入日常流程 | 原目录保留，文件头 `@oneshot` | 否（仅告警） | `pipeline/patch_p1_plugin_metas.py` |

**生成器例外**：`codegen/` 继续遵守[生成器工具箱专项设计](生成器工具箱专项设计.md) §7——新生成器 `gen_<对象>.py`（snake_case）、全 Python、由 `toolbox.py` 注册。该域不与“kebab-case 入口”规则冲突，因为它的权威入口是工具箱，不是单脚本文件名。

**迁移期命名**：表中 `.py` 是目标名；当前仍是 `.ps1` 的存量脚本在所属 P 批切换时改名。旧名只允许保留 `@ps-shim` 兼容壳（仅转发到新 Python 入口并透传退出码），窗口结束后删除。

### 3.2 入口规则

1. **canonical 入口 = 清单 `command`**。文档、CI、Agent 指令、计划任务都只写这一种；单脚本直调保留给既有消费面（迁移后 `build-player.py` 门禁、`Luban/gen.bat`、`test.py` 内部调用；迁移期旧名由 `@ps-shim` 兼容），不在操作文档里作为首选。
2. **域入口只做转发**：解析子命令、校验参数、透传参数与子进程退出码；不承载业务算法，不复制叶子脚本的默认值。
3. **叶子工具不反向依赖域入口**；域入口可调用叶子脚本，叶子脚本不得调用域入口。
4. **内部库不可执行**：`_` 前缀文件不得包含 `main()` 或可独立运行的 `param()` 入口；只提供函数/类型。
5. **一次性运维脚本**：文件头第一行后加 `@oneshot` 标记与用途/执行日期；不要求清单登记，`toolchain.py check` 只告警不阻断。需要反复使用的，必须升级为叶子工具并登记。

### 3.3 登记判据（可机械检查）

一个可执行脚本（含 `main()` 或 `param()`）必须满足以下之一：

- 出现在清单某条 `command` 中；
- 被某个已登记入口的注册表引用（如 `codegen/toolbox.py` 的 `TOOLS`、`gate/nightly-gate.py` 的步骤表）；
- `_` 前缀内部库、`scripts/tests/` 下测试、或文件头带 `@oneshot`；
- 确属未登记的新入口 → 补清单，而不是加豁免。

`toolchain.py check` 增加“孤儿可执行脚本”检查：扫描 `scripts/**/*.{py,ps1}`，按上述判据归类；未覆盖项默认告警，`--strict` 升级为错误。检查只做静态路径/引用匹配，不执行脚本。

## 4. 调用契约

### 4.1 参数

- **清单 `args` 是参数 schema 的唯一来源**（字段与 `toolchain.py run` 的校验归 L2-D1）；脚本自身用 `argparse` 解析，不另抄一份参数表。
- Python 入口用 `argparse`，长参数 kebab-case（`--project-path`、`--dry-run`）；只有域入口的子命令位置参数允许省略 `--`（如 `toolbox.py luban`）。
- 迁移期 `.ps1` 兼容壳只做转发：把 `-ProjectPath` 等 PascalCase 参数映射到 Python 的 kebab-case 参数，并原样透传退出码；壳内不得承载业务逻辑或第二套默认值。
- 必填参数缺失、类型错误、枚举非法 → **调用前 fail-fast**，打印一行 usage，退出码 2；不得落到子进程才报错。
- 默认值只在一个地方声明：Python 参数或清单 `args.default` 二选一，清单声明后脚本不得再写一份不同的默认值。

### 4.2 帮助

- 每个入口必须支持 Python `--help`；迁移期 `.ps1` 兼容壳把 `-?` / `Get-Help` 转发到对应 Python 入口的帮助，不维护第二份 help 文本。
- `toolchain.py run <id> --help` 渲染清单 `args` 与默认值，不启动子进程（L2-D1）。
- 域入口无参时打印索引/用法并退出 0；未知子命令打印已知列表并退出 2。
- 帮助文本只描述当前行为，不复述业务规则；业务规则留在对应专项设计。

### 4.3 退出码

| 码 | 语义 | 适用范围 |
|---|---|---|
| `0` | 成功（允许零变更） | 所有脚本 |
| `1` | 预期失败（校验不过、对账不一致、执行失败） | 所有脚本 |
| `2` | 用法/参数错误 | 所有脚本 |
| `4` | 工具不存在 | 仅 `toolchain.py` |
| `5` | 编辑器未运行/不可达 | 仅 `toolchain.py` |

- 叶子脚本与域入口**本地**只使用 0/1/2；不得自造 3/4/7 等业务码。`wg-peer.py` 的远端 2/3/4 是哨兵，不构成本地契约；本地按预期失败→1 或显式用法错误→2。
- 域入口对子进程的 2/3/4/7 等退出码归一为 1（原始码与摘要写 stderr）；`local-chain`/`serve-cdn`/`nightly-gate` 的透传面按此收口。
- Python 用返回值/受控异常收口；迁移期 PS 壳的 `throw`/`exit` 只做透传映射，不新增业务码。
- 子进程退出码优先透传：域入口不得把子进程失败吞成 0。

### 4.4 输出

- 状态行统一前缀 `[<域>/<工具>]`（如 `[gate/l1]`、`[content/publish]`、`[toolchain]`）；一行摘要说明结果与关键计数。
- 正常状态/摘要写 stdout；错误与修复提示写 stderr。退出码是权威结果，不以“最后一行文本”判断成功。
- 迁移期 `.ps1` 兼容壳不产生业务输出；所有状态/错误由被转发的 Python 入口输出。
- `--json` 为**可选**能力：需要结构化消费的脚本可提供，启用时 stdout 必须是纯 JSON（诊断走 stderr）；本层不强制所有脚本实现。
- 热路径/批量循环不得逐行刷屏；进度输出按阶段汇总，失败时给出可复现命令。

### 4.5 dry-run 与 check

- **`--check` = 只校验，不写盘**（对账/门禁用）；**`--dry-run` = 预览将要发生的写盘**（动作工具用）。两者不得混用。
- 清单 `safety.dryRun=supported` 的工具，脚本必须提供对应的 `--dry-run`（或 L2-D 映射的既有 `--check`）；不支持的脚本必须明确拒绝，不得静默执行。
- dry-run/check 的退出码仍按 0/1/2；预览有变更但未写盘不等于失败（返回 0），除非该工具契约定义为对账失败（如 buildHash `--check`）。
- CLI 侧映射与 `run --dry-run` 的开放条件归 L2-D2；本文只要求脚本侧存在可调用的对应形态。

### 4.6 非交互与根路径

- CI、Agent、计划任务路径不得等待键盘输入；破坏性动作需要显式开关（如 `-Force`、`--yes`），不得用交互确认代替。
- 工程根一律由**脚本自身位置**推导，禁止依赖当前工作目录；允许显式 `--project-path` 覆盖。迁移期 PS 壳接受 `-ProjectPath` 并映射过去。
- 最终只保留一个共享根推导实现：`scripts/_common.py` 的 `repo_root()`。叶子脚本不得再复制推导片段；`_codegen.py` 的 codegen 专用输出/执行面保留，根推导委托 `_common`。迁移期存量 PS 的 `$PSScriptRoot` 随所属批次删除，不新增 `_common.ps1`。

## 5. 文件与配置形态

### 5.1 编码与行尾

| 类型 | 规则 |
|---|---|
| Python（最终唯一形态） | UTF-8 无 BOM；只允许 LF |
| 迁移期 `.ps1` 兼容壳 | 只允许 `@ps-shim` 标记的薄壳；**ASCII-only**；只转发到 Python 并透传退出码 |
| 迁移期存量 `.ps1` | 在所属 P 批切换前保留；改动时按 UTF-8 BOM 或去中文处理；**禁止新增非 shim 的 `.ps1`** |
| 所有 `scripts/**` 文本 | LF；在 `.gitattributes` 声明 `*.py text eol=lf`、`*.ps1 text eol=lf`，避免 `core.autocrlf` 造成工作区混用 |

行尾统一不改变任何逻辑；按文件触碰批次归一，不做一次性全仓格式化。编码/行尾由 `toolchain.py check` 扫描告警；P5 收口后，`scripts/**/*.ps1` 本身即为错误（除显式 `@ps-shim` 且未过窗口的壳）。

### 5.2 命名

| 类型 | 规则 |
|---|---|
| 入口 | `<域>/<动词>-<对象>.py`（kebab-case），如 `publish-candidate.py`、`doc-lint.py` |
| 生成器 | `gen_<对象>.py`（snake_case，生成器专项例外） |
| 内部库 | `_<name>.py` |
| 测试 | `tests/test_<主题>.py` |
| 配置数据 | `<name>.json`；加载器必须是内部库，不得命名为 `*.config.py` / `*.config.ps1` 或可执行入口 |
| 一次性运维 | 原目录 + 文件头 `@oneshot`；不新增 `ops/` 目录 |

### 5.3 文件头

入口脚本使用四段式头注释（生成器继续五段式）：

1. **用途**：它做什么、何时用；
2. **入口**：canonical 命令 + 直调兼容说明；
3. **契约**：退出码、输出前缀、是否 dry-run/check；
4. **消费点/重跑时机**：谁调用、改了什么之后必须跑。

内部库使用两段式：用途 + 公开函数/类型。头注释只写当前设计与约束，不写“已修复/已迁移”等状态。

### 5.4 配置与密钥

- 配置数据一律 JSON/YAML 等声明式格式；**禁止可执行配置**（`.py` / 迁移期 `.ps1` 配置只允许作为内部加载器）。
- 配置加载器目标命名为 `_local_cdn.py` 这类内部库；数据继续留在 `local-cdn.json`，加载器只做解析与默认值。当前 `_local-cdn.ps1` 随 P1 迁移删除。
- 密钥、口令、测试者 `.conf` 继续按 AGENTS.md 红线与 `LocalNotes/` 管理；脚本不得内置密钥或在工作区打印明文。
- 配置路径与数据路径由脚本常量或 JSON 单源声明，不在多处硬编码同一路径。

## 6. 语言裁决：全量 Python

### 6.1 目标与边界

- `scripts/` 最终 **0 个 `.ps1`**：入口、域入口、叶子工具、内部库、测试、hook 全部为 Python 3.10+。
- Windows 原生能力**不构成 PS 例外**：计划任务/进程宿主/SSH/WireGuard/注册表通过 `subprocess`、`ctypes`、`winreg` 调用；Unity Pipeline 通过 HTTP/CLI；RSA 签名通过 `cryptography` 或 `openssl`（二选一固定）。
- 迁移红线：**行为等价**——退出码、关键 stdout、产物字节、参数/default、错误路径与确认语义不变；不顺手重构业务算法。
- 范围只到 `scripts/`；`Luban/gen.bat` 等既有入口 shim、Unity/Server C# 不在本迁移内。

### 6.2 迁移原则

1. **行为基线先行**：迁移前记录旧脚本的 `--help`、退出码、关键输出、产物 hash 与调用命令；Python 版逐项对照。
2. **兼容壳窗口**：高风险入口保留 `@ps-shim` 薄壳（只转发到 Python、透传退出码），所有外部调用面切换后删除。
3. **波次顺序**：P0 地基 → P1 低风险 → P2 内容/环境 → P3 门禁/CI → P4 构建/Unity → P5 云侧/本地联测 + 清壳。
4. **注册面同批**：CI、hook 配置、计划任务、`toolchain.json`、`AGENTS.md`/`scripts/README`/docs/skills、GM/编辑器里的启动面必须同批更新；`toolchain.py check` 必须绿。
5. **每批独立可回滚**：该批验收通过前保留旧 PS 与旧任务 action；不把旧债滚到下一批。

### 6.3 运行环境与依赖

- Python 3.10+；RSA 签名使用 `cryptography`（PKCS#1 v1.5 + SHA-256，与 C# 验证器对齐）；HTTP 用标准库 `urllib`，不强制 `requests`；进程查询不引入 `psutil`（`tasklist`/`ctypes`）。
- UTF-8：入口设置 stdout/stderr 为 UTF-8；Windows 控制台与重定向都按 UTF-8 输出。
- `restore-check`、CI 与开发机环境检查增加 Python 依赖校验；计划任务 runner 从 `pwsh` 改 `python`，夜间任务需重注册。
- 安全语义不变：密钥仍走环境变量/`LocalNotes`；Python 不打印私钥；deploy 的破坏性动作确认/显式开关不放宽。

### 6.6 完成判据

- `scripts/**/*.ps1` 数量为 **0**；`toolchain.py check` 对任何新增 `.ps1` 直接报错（`@ps-shim` 仅允许在迁移窗口内且带批次号）。
- 清单 `command`、CI workflow、`.zcode`/`.claude` hook、计划任务 action、`AGENTS.md`、`scripts/README`、项目说明/云侧速查/skills 全部指向 Python。
- `restore-check` 校验 Python 依赖；夜间任务 `schtasks` 回读为 `python .../nightly-gate.py`。
- L1/L3/Doc 绿；涉及 Unity 的 P3/P4 跑 L2；无 PS 入口残留、无旧命令残留（历史施工卷除外）。

### 6.7 非目标与迁移期例外

- 不改业务算法、协议、表、Unity/Server C# 行为；不把 `.ps1` 迁移当作顺手重构的机会。
- 迁移期只允许 `@ps-shim` 薄壳；**禁止新增**非 shim 的 `.ps1`。
- `Luban/gen.bat` 保持既有 shim 形态，不属于 `.ps1` 清零点。

## 8. 风险与回滚

| 风险 | 处理 |
|---|---|
| 改名/移动脚本导致 CI、hook、计划任务、文档引用漂移 | 按 `directory-move-sync` 六面同步；`toolchain.py check` 的注册面检查必须绿；一次只搬一个域 |
| 行尾归一产生大 diff、掩盖逻辑改动 | EOL/编码批次只做字节级转换，不夹带逻辑；单独提交，评审看文件数而非内容 |
| 退出码变化破坏调用方 | 先 grep 消费面；对既有非 0/1 码保留一个批次的兼容映射，再收口；CI/Agent 只依赖 0/非 0 |
| 登记检查误报 | 孤儿检查先告警后严格；`@oneshot`/内部库/测试三类豁免明确；新增入口优先补登记而不是加豁免 |
| 全量迁移改变行为 | P0 先定行为基线；每批要求退出码、stdout 关键行、产物字节、参数/default 等价；高风险入口保留 `@ps-shim`；不做“顺手重构” |
| CI/hook/计划任务漏切 | 每批同改注册面；`toolchain.py check` 校验 surface；计划任务 `schtasks` 回读；hook 双客户端各跑一次 |
| Windows 进程/窗口语义差异 | P5 用 `subprocess` + `CREATE_NEW_CONSOLE` 复现控制台窗口；本地联测页/日志窗口人工冒烟；不达等价就不删旧壳 |
| Python 依赖/环境漂移 | `cryptography` 等依赖进 `restore-check` 与 CI 安装；锁定版本；不引入非必要第三方包 |
| 迁移期双入口漂移 | `@ps-shim` 带批次号且只转发；窗口结束删除；`toolchain.py check` 对新增非 shim `.ps1` 报错 |
| 与 L2-D 重复定义 | 清单 `args`/dry-run 映射只引用 L2-D，不在本文复制 schema；本文只要求脚本侧能力存在 |

**回滚**：清单/命名/入口可单文件回退；`.gitattributes` 可整体撤销（不涉及数据迁移）；脚本改名按 git rename 回退；退出码兼容映射保留到消费面确认后再删除。工程脚本不在 BuildHash 闭包内，本设计不触发共享源重生成。

## 9. 验收与检查面

- **结构**：`toolchain.py check` 覆盖清单、注册面、孤儿脚本、编码/EOL；P5 后 `scripts/**/*.ps1` 非零即失败。
- **契约**：Python 契约测试覆盖帮助、退出码、未知子命令、参数缺失、输出前缀；迁移期额外校验 `@ps-shim` 转发与退出码透传。
- **依赖**：`restore-check`/CI 校验 Python 版本与 `cryptography` 等实际依赖；不靠开发机偶然安装。
- **文档**：`scripts/README` 只保留目录职责与 canonical 入口，不复制每个工具的参数表；工具索引由清单生成；迁移每批更新 AGENTS/项目说明/云侧速查/skills。
- **门禁**：L1 + Doc；P3/P4 附带 L2；涉及计划任务的改名按 `directory-move-sync` 核对六面并回读任务 action。
- **证据**：批次完成后由施工进度记录命令、输出、旧/新对照与文件清单；本文不记完成状态。
