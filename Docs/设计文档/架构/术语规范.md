## 1. 使用规则

- **三档处置**：每个词归入 A（换用业界词，§3）/ B（已是业界词，保留，§2）/ C（中文保留，英文语境按此译，§4）之一。
- **A 档增量收敛**：新写的文档与代码一律用业界词；存量不批量替换，随自然修改换词。带 ⚙ 注记的属**结构名**（目录名、卷名、CLI 参数、文档类型后缀），其改名是结构变更须挂批次；行文面即可开始换词。
- **首次出现写法**：中文词（English）——如「门禁（Quality Gate）」；B 档词鼓励括注英译，C 档词在英文语境按 §4 译法。
- **新自造词先入表**：任何新隐喻词/新缩写先登记进本表（词义、档位、英译）再使用（见 §7）。
- 频次列为本表落定批的检索量级（Docs/＋根 AGENTS.md，含合理子串），仅用于排优先级，不随修改刷新。

## 5. 一词多义消解

### 5.1 Lane——测试档位 vs UI 角色分层

**现状**：同词两义——①测试门禁档位：`scripts/gate/test.py --suite` 参数（L1/L2/L3/Doc，行文数十处）；②UI 工作台角色分层：`UiLanePolicy`/`UiWorkbenchLane`，定义为「UX 分层与默认动作集，不是权限系统」（[UI 编辑器工具链专项设计](../客户端/UI系统/UI编辑器工具链专项设计.md) §2.3）。两义互不相关，检索与沟通都会串线。

**业界对应**：①测试语境＝Test Suite / Tier（仓库 `--profile` 是正交的运行档参数，不与测试层混义）；②角色语境＝Role Mode / Persona——工作台已有的「透视（Perspective）」表达的是窗口布局，与角色分层是两个概念，不得混用。

**裁决**：

1. **立即生效（行文纪律）**：禁止单写「Lane」，必须写全称（「测试档位」「角色分层」）。
2. **目标词（新写即用）**：测试面用**套件/档位（Suite/Tier）**；UI 面用**角色模式（Role Mode）**。若未来需要表达泳道式视觉布局，再回归 Lane 本义（swimlane）。
3. **CLI 与摘要契约（现行形态）**：门禁测试层参数名为 `--suite`（L0/L1/L2/L3/Doc/All）；`--profile`（PullRequest/Nightly/Release）是正交的运行档参数，二者不合并。摘要文件 `summary-<suite 小写>.json`，schema v2 键 `suite`/`suites`。`UiLanePolicy` 等类名随自然重构改名，专项改名须挂批次并走 `directory-move-sync`。

### 5.2 登记——注册表行 vs 债登记 vs 索引登记

**现状**：「登记」覆盖三件事——①UI 工具链把页面写入 `#uiform.xlsx` 表行（UI 编辑器工具链专项设计 §3.6）；②把债记入质量登记表（审计/代码质量审计-*.md）；③把新文档补进 README 索引（doc-authoring）。

**裁决**：「登记」保留为泛动词，靠**限定搭配**消歧；无上下文的单写「登记」默认按②理解：

1. 页面/控件/服务写入表或容器 → **注册（Register）**；
2. 债/事实记入登记表 → **登记**（表本身＝债务登记表，Debt Register）；
3. 文档补进索引 → **索引登记**。

### 5.3 允许的同形复用

同一概念族的两个用法不算双义，不消解：

- **快照**：网络同步快照 / 批次 checkpoint——同为 Snapshot；
- **摘要（Digest）**：BuildHash 源集摘要 / `CombatConfigDigest` 运行期摘要——同为 Message Digest。

### 5.4 其他同形「lane」（登记待消解）

服务端域还有一组与测试套件无关的 lane 同形词——传输/限流的 **`Control lane`/`Outbound lane`**（队列语义，业界对应 queue / channel）与**限流 lane**（限流键维度，业界对应 dimension / scope）。消解与否随服务端批次另裁，本表先行登记，防止与 §5.1 的套义串线。

## 6. 代码标识符用词规约

### 6.1 大小写（.NET 设计准则）

- **两字母缩写全大写**：`UI`（如 `UIFocusCoordinator`）、`IO`；
- **三字母及以上帕斯卡**：`Hud`（如 `DevHudFilter`）、`Kcp`、`Aoi`。

现行存量类名前缀 `Ui`（150+ 处）与 `UI`（26 处）并存、`DevHud*` 与 `DevHUD` 并存，属历史不一致；**新标识符按本规约**，存量随自然重构收敛，新增文件不得再引入第二种拼法（机械拦截可挂纪律扫描词表，属工具演进另批）。

### 6.2 动词语义

| 动词 | 语义 | 业界对应 |
| --- | --- | --- |
| `Take*` | 消费性获取：读即清或接管所有权，不可重复取 | `BlockingCollection<T>.Take`、channel receive |
| `Get*` / `Resolve*` | 幂等纯读，不改变状态 | DI Resolve / accessor |

二者禁止对同一资源混用。`GameEntry.TakeContainer`、`TakeSnapshot`、`TakeExitRequest` 均为消费语义，属正确用法；反之不得用 `Get` 命名读清语义的方法。

### 6.3 隐喻词

| 标识符 | 处置 | 说明 |
| --- | --- | --- |
| `*FeelBook` | 用 `*FeelProfile` / `*FeelPreset` | feel/juice 是业界词；「Book」不是参数集量词（现行：`CrosshairFeelProfile`） |
| `*ViewRig`（`BattleViewRig`） | 用 `*ViewGroup` / `*HudView` | rig 在游戏业特指绑定/动画装配；不用 `*ViewBundle`——与 YooAsset 资产包 bundle 术语冲突 |
| `*Pump`（`FramePump`） | 允许 | Windows Message Pump 同构；新代码亦可用 `*Ticker`/`*Driver` |
| `*Doc`（`AccountDoc`/`LedgerDoc`/`OutboxDoc`） | 允许 | Mongo document；求显式可写 `*Document`；Outbox 是标准模式名 |
| `*Kernel`、Shim、`Workbench` | 允许 | 业界既有词 |

存量改名随自然重构进行；专项改名须挂批次并走 `directory-move-sync`。

### 6.4 模块名映射（登记，不裁决改名）

| 现名 | 业界对应 | 备注 |
| --- | --- | --- |
| MetaServer | Master Server / GameBackend | 承载 Auth/Lobby/Profile 与房间编排；游戏业经典叫法是 Master Server |
| ShareResource | SharedAssets | Unity 惯例 |
| RoomServer / GameData / `Lite*` 前缀家族 | 保留 | RoomServer 是标准词；`Lite*` 家族属品牌一致性选择 |

## 7. 维护规则

- **先入表再用**：新自造词/新缩写先登记进本表（词义、档位、英译）再进入文档与代码；未登记新词按违反本规范处理（机械拦截属 doc-lint 词表扩展，另批）。
- **档位调整即裁决变更**：升版本号并在元数据记录落定日期；正文不写调整过程（设计↔进度分离）。
- **频次列不刷新**：仅落定批快照，用于排优先级。
- 本表只登记**工程与文档方法论**用词；纯领域业务词（角色/武器/房间模板等）不入表。
