# 开发工具链平台分层设计

> **版本**：0.1（2026-10-21）
> **定位**：裁决开发工具链平台的三层边界、层间不变量、后续批次（L2-C/L2-D/L3）的契约缺口与退出条件；作为“总体方案”的索引层，不重复 L1 与 L2-A/B 的细则。
> **不做的事**：不裁决各工具的业务算法；不重复清单 schema、CLI 命令面、ToolWriteScope 细则；不登记施工状态与批次证据（归 `Docs/施工进度/资源与工具链线.md`）。
> **冲突裁决**：L1 细则以[开发工具链平台专项设计](开发工具链平台专项设计.md)为准；L2-A/B 细则以[工具执行与写盘契约专项设计](工具执行与写盘契约专项设计.md)为准；能力优先级以[调试与开发工具链演进路线图](../测试与性能/调试与开发工具链演进路线图.md)为准。
> **关联**：[开发工具链平台专项设计](开发工具链平台专项设计.md)、[工具执行与写盘契约专项设计](工具执行与写盘契约专项设计.md)、[技术支持](../../工具链/技术支持.md)、[修改指南](../../修改指南.md)。

## 1. 分层模型

| 层 | 名称 | 解决什么 | 权威细则 |
|---|---|---|---|
| **L1** | 入口与登记 | 工具在哪、怎么被找到、怎么被调用、文档与外部注册面怎么不漂移 | [平台专项设计](开发工具链平台专项设计.md) |
| **L2** | 执行与写盘 | 一次性动作执行前可预览、执行中写入可追踪、执行后可回滚、结果统一 | [执行与写盘契约专项设计](工具执行与写盘契约专项设计.md)（L2-A/B）；本文 §5/§6（L2-C/D） |
| **L3** | 交互与 UI | 交互式窗口/页件如何统一入口、生命周期与安全边界，而不重写业务 UI | 本文 §7 |

**分层原则**：先有 L1 的单一清单与入口，才有 L2 的统一执行；L2 不做完整之前，L3 不强行把所有窗口塞进 Hub，否则只是把分散从菜单搬进一个更大的窗口。

## 2. 层间不变量

1. **单一清单**：`scripts/gate/toolchain.json` 是工具/分类/入口/outputs/safety 的唯一元数据源；Hub、CLI、生成索引、注册面检查共用。
2. **行为唯一**：C# handler 与清单 1:1，由 `EditorToolCatalogEditModeTests` 对账；禁止“清单有、行为无”或“行为有、清单无”。
3. **写盘可控**：一次性动作只能经 `ToolWriteScope` 写声明产物；交互式工具必须声明自己的预览/确认/Undo 边界，不得冒充 one-shot dry-run。
4. **不碰共享源集**：工具写盘不得写入 `LiteSim/Core/{Scripts,Systems}`、`LiteNet/{Proto,Protocol,Transport/Security}`、`GameData/Generated` 等 BuildHash 闭包，除非该工具本身就是生成器且按生成链收尾。
5. **不新增静态可变状态**：工具平台不引入新的全局开关；执行请求/scope 显式传递。
6. **交互例外必须显式**：GM 页、绑定/编排/回写窗口等交互面不受 one-shot dry-run 约束，但必须在清单 `kind/safety` 中如实声明，且不能绕过确认/备份。
7. **不在文档里记状态**：层设计只写契约与批次；完成/未完成由施工进度卷承担。

## 3. L1 现行形态（引用）

- 一个根菜单 `LiteGame/工具链`（叶子项；Unity 菜单不允许父路径同时是子菜单）。
- 一个 CLI `python scripts/toolchain.py`：`list/check/docs/open/run/generate/verify/build/doctor`。
- 一份清单 `scripts/gate/toolchain.json`；一份生成索引 `Docs/工具链/工具索引.md`。
- 外部注册面：CI / hook / 计划任务 / 可选路径。

本层不在本文重复细则；新增工具/分类/注册面按平台专项设计 §8 执行。

## 4. L2-A/B 现行形态（引用）

- `ToolRequest/ToolResult/ToolChange/ToolWriteScope`；动作页支持 dry-run、计划变更、写入变更、回滚。
- 清单 v3 `outputs/safety`；烘焙五动作、SimTrig 接 scope；BindGenerator 主文件只创建不覆盖。
- 写盘边界：工程根内、outputs allowlist、拒绝 `..`、write-if-changed、失败/ABORT 的部分写入保留 Undo。

本层不在本文重复细则；资产写盘与 CLI 参数层分别见 §5/§6。

## 5. L2-C：资产写盘契约

### 5.1 目标

把 UI 样式刷新/文字档应用、绑定生成物 hash 记录、样例内容生成等**资产写入动作**接入与生成物相同的预览/追踪/回滚边界。

### 5.2 契约扩展

- `ToolWriteScope` 增加资产写模式：
  - `WriteAsset(assetPath, Action<SerializedObject> mutate)` 或 `WritePrefab(prefabPath, Action<GameObject> mutate)`；
  - 写入前校验 `ProjectRoot` + 清单 `outputs`（资产路径/目录前缀）；
  - dry-run 只生成资产差异计划（路径 + 属性/节点 + before/after 摘要），不调用 `SaveAssets`；
  - 实际写入前把资产备份到 `Temp/ToolWriteScope/asset-backup/<run>/`（`AssetDatabase.CopyAsset`），Undo 时恢复并 `ImportAsset`；
  - 不使用裸 YAML 文件改写绕过 Unity 序列化管线。
- `ToolChange` 资产变更增加 `Detail`（属性/节点/旧值→新值摘要）；仍以路径为键。
- 清单 `safety.undo=asset` 表示支持资产回滚；不支持的工具必须 `undo=none` 且 `confirmation=required`。

### 5.3 迁移范围

| 工具 | 写面 | 目标 |
|---|---|---|
| `ui.style.colors-refresh` / `ui.style.text-apply` | prefab 的 Graphic/TMP 属性 | dry-run 差异清单；应用到源 prefab；资产 Undo |
| `ui.binding-hash-all` / `selected` | `UiBindManifest.json` 资产文本 | dry-run 列出增删条目；应用后 Undo |
| `content.sample` | 样例素材/收集组资产 | dry-run 列出将创建资产；应用后 Undo/清理 |
| `ui.writeback`（窗口） | 实例→源 prefab | 保留窗口内预览/勾选；接 `ToolInteractionSession` 结果摘要，不做 one-shot dry-run |

### 5.4 非目标

- 不重写 UI 窗口的交互；不自动保存场景；不把 `PrefabWriteBackWindow` 的逐属性选择改成全量应用。
- 不做任意 `SerializedObject` 写入的通用 UI；L2-C 只服务已登记工具。
- 不改运行时资产/内容打包链路。

### 5.5 验收

- 任一迁移动作 dry-run：`AssetDatabase` 无脏标记、无 `SaveAssets`、资产文件 mtime/内容不变。
- 应用只改声明资产；Undo 恢复原资产（prefab/manifest/样例）并通过 `AssetDatabase.ImportAsset` 收敛。
- 不支持资产 Undo 的工具在 Hub 明示 `undo:none` 并要求确认。
- 定向 EditMode（临时资产夹具）+ L1/Doc；全量 L2 夜间。

## 6. L2-D：CLI 执行面

### 6.1 目标

让 Agent 侧与 Hub 共享同一份参数/安全元数据，而不是靠记忆拼命令行。

### 6.2 清单 `args`（v3 可选字段）

```jsonc
"args": [
  { "name": "protoc", "type": "path", "required": true, "description": "protoc.exe（与运行时 Google.Protobuf 对齐）" },
  { "name": "skip-server-build", "type": "bool", "required": false, "default": false }
]
```

- `type`：`path/file/bool/int/string/enum`；`enum` 给 `values[]`。
- `toolchain.py run <id>` 在启动前校验必填/类型/枚举；缺参不再落到子进程才报错。
- `toolchain.py run <id> --help` 展示清单参数与默认值。
- 不为单个工具写专用 argparse switch；参数透传仍以 `-- args` 为准。

### 6.3 `run --dry-run`

- 只对 `safety.dryRun=supported` 且声明了 CLI dry-run 形态的工具开放：
  - 已有 `--check` / `--dry-run` 的脚本：映射并透传；
  - 没有 dry-run 形态的脚本：明确返回“不支持预览”，不得静默执行。
- 编辑器动作的 dry-run 仍走 Hub（`open <id>` + 动作页开关）；CLI 不模拟编辑器 UI。
- `refresh_hash.py` 读不到 server hash 时改为非 0（或默认 strict + `--allow-incomplete` 显式降级），与“对账不能静默成功”一致。

### 6.4 结果与退出码

- CLI 的权威结果仍是子进程退出码；`run` 统一打印 `[toolchain] <id> exit=<code>` 和可选的子进程尾部。
- 不在 L2-D 强行要求所有脚本输出 JSON；需要结构化结果的脚本走独立 `--json` 约定，后续再收编。
- `toolchain.py check` 校验 args/outputs/safety 与生成索引新鲜度；L0/Doc 继续复用。

### 6.5 验收

- 缺必填参数/类型错误在 CLI 层 fail-fast，不启动子进程。
- 不支持 dry-run 的 `run --dry-run` 返回非 0 + 明确提示。
- `refresh_hash` 在 server hash 不可读时返回非 0；`--check` 与出包门禁语义不变。
- 清单/文档/索引通过；L1/Doc；出包门禁不受影响。

## 7. L3：交互与 UI 收编

### 7.1 目标

在不重写业务 UI 的前提下，让交互式窗口也具备统一入口、生命周期与安全边界；**入口统一不等于所有内容必须塞进一个窗口**。

### 7.2 两种合法形态

| 形态 | 适用 | 契约 |
|---|---|---|
| `page`（内嵌） | GM 六页、动作页、轻量工具 | `IEditorToolPage`；Hub 驱动 OnShow/OnHide/Draw/Poll；写盘走 ToolWriteScope 或页面自己的安全边界 |
| `window`（外部窗口） | UI 绑定/编排/回写、烘焙工具箱 | Hub 只负责打开；窗口必须声明 `safety`（interactive/dry-run:unsupported/undo:none 或 asset），并提供结果摘要/关闭回调；禁止裸写资产 |

- `UiComposeWindow`（Odin）保持外部窗口；不为了统一重写 Odin。
- `PrefabWriteBackWindow` 保留“取选择→扫描→勾选→回写”交互，接入 `ToolInteractionSession` 记录本次变更，供 Hub 显示/回滚（能接则接，不强制 one-shot）。
- GM 页已经是 `page`；其 `GmLocalChainPage` 编辑态自管心跳作为既有例外，后续若 Hub 增加编辑态节拍再迁移。

### 7.3 `ToolInteractionSession`（交互面边界）

- 打开窗口时创建；记录窗口内的资产/文件变更（路径/操作/摘要），不要求事先 dry-run；
- Hub 在窗口关闭后显示“本次变更摘要 + 可回滚项”；不支持回滚的变更明确标注；
- 交互窗口不得在无确认的情况下保存场景；不得绕过 Unity 序列化管线。

### 7.4 收编顺序

1. 给所有 `window` 工具补 `safety`/docs/结果边界；不改内部。
2. 把绑定/回写窗口接入 `ToolInteractionSession`；Odin 编排保持外窗。
3. 评估烘焙工具箱是否改页件；若其内部多页交互收益不足，保留外窗。

### 7.5 验收

- 顶层菜单仍只有 `LiteGame/工具链`；所有窗口可从 Hub 打开并显示安全标签。
- `window` 工具关闭后 Hub 能显示变更摘要（有变更时）；无确认不自动保存场景。
- 无 UI 业务重写；定向 EditMode/人工冒烟；全量 L2 夜间。

## 8. 批次、依赖与退出条件

| 批次 | 内容 | 依赖 | 退出条件 |
|---|---|---|---|
| L2-C1 | `ToolWriteScope` 资产快照/备份/Undo + 临时资产测试夹具 | L2-A/B | dry-run 不改资产；Undo 恢复；测试覆盖新建/更新/取消 |
| L2-C2 | UI 样式颜色/文字档接入 | L2-C1 | 两动作预览/应用/回滚；只改声明 prefab |
| L2-C3 | 绑定 hash/样例内容接入 | L2-C1 | 预览条目 diff；应用/回滚；样例资产清理 |
| L2-D1 | 清单 `args` + CLI 校验/`--help` | L1 | 缺参 fail-fast；文档/索引更新 |
| L2-D2 | `run --dry-run` + `refresh_hash` 严格失败 | L2-D1 | 不支持显式拒绝；对账不可读非 0 |
| L3-A | 所有 `window` 声明 safety/结果边界 | L2-C | 顶层菜单唯一；窗口安全标签齐全 |
| L3-B | 绑定/回写接 `ToolInteractionSession` | L3-A | 关闭后变更摘要；无自动存场景 |
| L3-C | 烘焙/Odin 窗口评估 | L3-B | 保留外窗或改页件有明确理由；无业务重写 |

**并行性**：L2-C 与 L2-D 可并行；L3 依赖 L2-C 的资产安全边界。每批独立可验收，不要求一次性完成三层。

## 9. 风险与回滚

- **Unity 资产快照/Undo 复杂**：只用 `AssetDatabase.CopyAsset` + `ImportAsset` 的受控路径，不手写 YAML；测试用临时资产夹具，不碰真实 UI 资产。回滚 = 删除临时备份/恢复旧资产。
- **Odin/IMGUI 双栈**：L3 不统一绘制框架，只统一入口与结果边界；Odin 编排保留外窗。
- **CLI 参数 schema 与现有脚本漂移**：清单 args 只描述，真正执行仍由脚本解析；先用 `check` 对账，再逐步给脚本加校验。
- **交互面误用 one-shot 契约**：`safety` 明确 `interactive/unsupported`，Hub 不显示 dry-run/回滚按钮。
- **批次范围膨胀**：每批只迁已登记工具；新增工具必须按当前层契约接入，不借机重构业务。
