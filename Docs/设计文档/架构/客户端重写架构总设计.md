> 状态：现行总设计
> 版本：1.0

## 1. 决策摘要

新客户端只有四个概念：

1. **ClientApp**：组合根 + 顶层 async 流程 + 帧驱动 + 关闭。
2. **Feature**：一个能说出口的功能；一个目录、一个公开入口 `<Name>Feature.cs`；自带页面、资源、状态、测试。
3. **Page**：`PageBase` + prefab；页面元数据是页面类上的 `PageSpec`；没有全局页面目录、页面 ID、生成目录。
4. **PlatformService**：内容、配置、UI 运行时、音频、输入、本地化、Meta HTTP、日志；由 `ClientApp` 显式构造并传给需要的功能。

**不再是概念**：`IClientSegment`、`ClientHost`、`ServiceContainer`、`ClientScope` 五层树、`StageMachine<ProcedureId>`、`PageServices`、`PageIds`、`UIPageCatalog`、`UIBindIndex`、`BindGenerator`、`SubModules`、`Abstractions`、`EventBus`/`CommandBus`、`FrameSchedule` 全局 12 项帧序、AR1/AR2。

**保留的外部事实**：AOT/hot、HybridCLR、YooAsset、Luban、BuildHash、`LiteSim`/`LiteNet`/`LiteSync`、RoomServer/MetaServer 协议、资源入库与 Unity 资产管线、`Log` 门面、`CancellationToken` 纪律。

## 2. 目标与非目标

### 2.1 目标（可观察）

| 目标 | 判据 |
|---|---|
| 功能内聚 | 一个功能 = 一个目录；代码、页面 prefab、页面数据、测试都在内；对外只有一个 `<Name>Feature.cs` |
| 短链路 | 新增页面：1 个代码文件 + 1 个 prefab，0 生成、0 中央登记；改按钮：1 个代码文件；新增功能：功能目录外 ≤1 行；新增设置：≤2 个代码文件 + 1 个 prefab |
| 低心智负担 | 只读 4 个概念；新上下文拿到功能目录 + 一句需求，打开入口文件即可改；冷启动子代理 ≤2 文件、0 反问 |
| 不保留旧设计 | 旧 17 段/容器/五层 Scope/流程机/PageServices/生成目录/绑定生成/SubModules/Abstractions/双总线/AR1-AR2 全部不在新路径出现 |
| 可运行迁移 | 旧客户端在切换前保持可编译可跑；原地 strangler（`Assets/LiteGame/Next` 子树）逐功能验收；切换后旧目录删除、可回滚 |

### 2.2 非目标

- 不改 `LiteSim` 判定、`LiteNet` 协议、`LiteSync` 重组、RoomServer/MetaServer、Luban 表结构、BuildHash 源集。
- 不重做美术、动画、特效、地图、UI 视觉；保留 uGUI + TMP。
- 不新增玩法/商业化功能；背包当前不存在，不纳入本重写。
- 不迁移旧 UI 工作台/契约/预览矩阵/24 条校验规则/`UIApiSpec`/`BindGenerator`。
- 不在第一阶段覆盖 Dev/GM 全部能力；先保证发布路径，Dev 面随 P3a 收口。
- 不追求“代码行数下降”；只以触碰面与冷启动可发现性判定。

## 3. 旧设计废除清单

| 旧机制 | 处置 | 理由 |
|---|---|---|
| `IClientSegment`/`ClientHost`/`SegmentContext`/`DependsOn` 拓扑/`ComposeAfter` | 删除 | 17 段装配把“依赖序、生命周期、服务注册、帧序”拆成四份；新增能力要穿 4 处 |
| `ServiceContainer`/`ClientContext`/`Put/Require/Get` | 删除 | 显式构造注入即可；容器只登记不构造，仍制造“解析点”与隐式依赖 |
| `ClientScope` 五层树 + `AssetLease` 组合 | 删除；保留 `Lifetime` 小工具与 `AssetHandle<T>` | 原语（CTS+LIFO+异常聚合）有用，但“每段一 Scope + 域内再建”叠出 6 类生命周期 |
| `StageMachine<ProcedureId>`/7 阶段/`ProcedureArgs` | 删除 | 顶层流程是线性 async 调用栈；阶段机把 await 顺序变成全局状态与观察者 |
| `RoomFlowOperation`/`RoomFlowLifetime`/清理观察者 | 删除 | `await` 清理完成再返回；不需要跨阶段句柄与代次观察 |
| `UIService`/`UINavigationController`/`UIForm`/`UIModalStack` 公共契约 | 删除；行为语义移植到新 `UiRuntime` | 7k 行/112 文件的公开面把页面、层、缓存、转场、焦点、对话框、反馈拆成 6 个目录；新运行时对外一个门面 |
| `PageLogicBase`/`PageServices`/`IUIFormLogic` | 删除 | 页面依赖 7 个域端口，等于服务定位器；新页面按需 `Bind` 1–3 个依赖 |
| `#uiform`/`PageIds`/`UIPageCatalog`/`UIPageManifest`/`ui-page` | 删除 | 页面元数据放页面类 `PageSpec`；新增页面 0 生成 |
| `UIBindIndex`/`BindRoot`/`BindGenerator`/`UIApiSpec`/`*.Designer.cs` | 删除 | 当前无生产页面走 Designer 路径；`BindName` 运行时扫描足够，且无全局生成 |
| 产品侧 20 个运行时 asmdef/`LiteGame.*` 模块件 | 合并为 1 个 hot `LiteGame` | 功能边界由目录+约定+架构测试保证，不由 asmdef 数量表达 |
| `Abstractions/`/`SubModules/`/`Services/`/`Impl/` 技术层目录 | 禁止 | 同一功能被声明/实现/装配切开 |
| `EventBus`/`CommandBus` 双通道 | 删除 | 跨功能通知用 C# event/回调；GM 命令用 Dev 功能内字典；请求-响应用直接方法 |
| `FrameSchedule` 12 项全局帧序 | 删除 | `ClientApp.Tick` 显式调用 `UiRuntime.Tick` 与活动功能 Tick；顺序在一个方法里 |
| AR1（路径=命名空间）/AR2（≤5 文件/≤600 行）/0 跨单元接口 | 废除 | 规则条数与文件数量不是目标；改为“功能目录 + 入口唯一 + 禁止技术层目录”三条 |
| `LiteFramework` 四件程序集 | 目标 1 个 AOT `LiteFramework` | 旧四件是历史分层；目标按 AOT/hot 与平台/产品分工 |
| 旧 UI 工作台/工具链 95 文件/1 万行 | 不迁移 | 只保留轻量资产校验；工具不作为运行期依赖 |

**不废除**：`LiteSim`/`LiteNet`/`LiteSync`、BuildHash、R11/R13、YooAsset/HybridCLR/Luban 接入、资源入库与 unity-pipeline、`Log` 门面、错误契约、`CancellationToken`、Unity 序列化资产规则。

### 3.1 “复用实现 / 不复用契约”的定界

| 类别 | 对象 | 处置 |
|---|---|---|
| 复用实现、换新契约 | YooAsset 适配、Log、时间/池、Audio、Input、Settings 存储、Animation Backend、Camera 适配 | 代码可复制/裁剪进新 `LiteFramework`/`LiteGame`；公共类型/命名空间按新设计重写 |

| 不复用、随旧目录删除 | `IClientSegment`/`ClientHost`/`SegmentContext`、`ServiceContainer`、`ClientScope`、`EventBus`/`CommandBus`、`UIService`/`UIForm`/`UINavigationController`、`PageLogicBase`/`PageServices`/`UIBindBase`/`UIBindIndex`、`BindNode`/`BindRoot`、`IContentService`/`IFileStore` 旧公共契约 | 旧目录删除时一并删除；`Next` 不引用 |

## 4. 总体架构

```text
Boot.unity
 └─ GameEntry（AOT MonoBehaviour）
      ├─ PlatformBoot（AOT）
      │    ├─ Log / FileStore / 启动错误面
      │    ├─ HotUpdateLoader（HybridCLR 槽位）
      │    └─ ContentService（YooAsset）/ Audio / Input / 平台桥
      └─ ClientApp（hot）
           ├─ AppFlow（线性 async）
           ├─ Features
           │    Account / Matchmaking / Battle / Result / Settings / Records / Dev
           └─ Platform
                UiRuntime / Config / Localization / MetaClient / NetSession
```

| AOT | `LiteGame.Bootstrap`（迁移期 `LiteGameNext.Bootstrap`） | `GameEntry`、入口装载、AOT 错误页 |

- 产品层不再按功能拆 asmdef；功能边界由目录、`internal` 约定与 L1 架构测试保证。
- 迁移期 `Next` 后缀避免与旧目录同名；切换时统一提升/改名，旧程序集删除。

## 5. 启动与生命周期

### 5.1 Boot 序列

```text
BootNext.unity
  → GameEntry.Awake
  → PlatformBoot.InitializeAsync()
       日志/文件/平台桥 → HotUpdateLoader.TryEnsureLoaded() → ContentService.InitializeAsync()
  → EntryLoader.Load("LiteGameNext.ClientApp, LiteGameNext")
  → ClientApp.CreateAsync(platform, ct)
       new ConfigService / Localization / UiRuntime / MetaClient
       new features（显式构造）
  → ClientApp.RunAsync(ct)   // 不阻塞 Awake；由 UniTask 驱动
  → GameEntry.Update → ClientApp.Tick(unscaledDeltaTime)
  → GameEntry.OnDestroy/Quit → ClientApp.ShutdownAsync()
```

- `GameEntry` 是唯一 MonoBehaviour，`[DefaultExecutionOrder(-1000)]`，`DontDestroyOnLoad`；重复引导守卫保留。
- `PlatformBoot` 负责“与 hot 无关”的平台初始化；hot 程序集装载失败 → AOT 错误页（prefab）。
- `ClientApp.CreateAsync` 只做构造与初始化，不打开页面；`RunAsync` 才进流程。
- 关闭：`ClientApp.ShutdownAsync` 取消 App lifetime → 逆序 `Feature.ShutdownAsync` → `UiRuntime.ShutdownAsync`（全关页面/归还租约）→ `PlatformBoot.ShutdownAsync`（内容/音频/输入/热更）。
- Domain Reload Off：`GameEntry.ResetForEditorReload` 只复位 `s_booted` 与 `UiRuntime.ResetStatics`；其余状态由实例持有。

### 5.2 Lifetime

```csharp
public sealed class Lifetime : IDisposable
{
    public CancellationToken Token { get; }
    public bool IsDisposed { get; }
    public void Add(IDisposable disposable);
    public void Cancel();
    public void Dispose();   // Cancel → 逆序 Dispose → 聚合异常
}
```

- `ClientApp`、每个 `Feature`、每个 `PageHandle`、每个 `BattleSession` 各持一个 `Lifetime`。
- 异步任务统一 `token`；页面关闭/功能关闭/战斗结束都会取消。
- 没有父子作用域解析；需要组合时，子 `Lifetime` 链接父 token（`CancellationTokenSource.CreateLinkedTokenSource`）。
- 错误契约：已关闭的 `Lifetime.Add` 立即 `Dispose` 并抛 `ObjectDisposedException`。

## 6. AppFlow

```csharp
public sealed class AppFlow
{
    public async UniTask RunAsync(CancellationToken ct)
    {
        await _platform.Content.InitializeAsync(ct);
        await _platform.Config.LoadAsync(ct);

        await _account.RestoreOrLoginAsync(ct);

        while (!ct.IsCancellationRequested)
        {
            MatchInfo match = await _matchmaking.WaitForMatchAsync(ct);
            BattleResult result = await _battle.RunAsync(match, ct);
            await _result.ShowAsync(result, ct);
        }
    }
}
```

- **没有全局阶段枚举/阶段机**；当前流程就是当前 await 的调用栈。
- 每个功能方法负责自己的页面、资源、会话与清理；返回时资源已释放。
- 取消：`OperationCanceledException` 在顶层静默；各功能 `finally` 清理。
- 失败：功能返回 `Result<T>` 或抛 `ClientException`（分类：`Recoverable`/`Fatal`/`Compatibility`/`Auth`/`Network`）；顶层捕获后打开 `ErrorPage`，提供重试/回登录/退出。
- 用户主动退出对局：`BattleFeature.RunAsync` 走 `Leave` 分支返回 `LeftByUser`，不打开结算页；`AppFlow` 回大厅。
- 设置/战绩等“旁路页面”不打断 AppFlow；由页面所属功能打开，`UiRuntime` 负责模态与输入阻断。
- **终态处理**：

| `BattleResult.Outcome` / 异常 | AppFlow 动作 |
|---|---|
| `Completed` | 打开 `ResultPage`；确认后回 `Matchmaking` |
| `LeftByUser` | 不打开结算，直接回 `Matchmaking` |
| `Aborted` | 回 `Matchmaking`，Toast 提示 |
| `SessionFailed` | 回 `Matchmaking`，可重试错误确认；不进入错误终态 |
| `OperationCanceledException`（App token） | 静默关闭 |
| `OperationCanceledException`（页面/操作） | 回 `Matchmaking` |
| `ClientException.Auth` | 登出 → `LoginPage` |
| `ClientException.Fatal` | `ErrorPage`（不可重试） |
| `ClientException.Recoverable` | `ErrorPage`（可重试）→ 重试或回大厅 |

- **Tick 所有权**：`ClientApp.Tick` 固定 `UiRuntime.Tick → BattleFeature.Tick（活动对局）→ DevFeature.Tick`；`BattleFeature.RunAsync` 只等待内部 TCS，不自己驱动帧。暂停/失焦由 `GameEntry` 转发 `ClientApp.OnPause(bool)`；暂停时停止输入采样，网络泵策略在 P2 时序契约中钉死。

## 7. Feature 规则

```csharp
public abstract class Feature : IAsyncDisposable
{
    protected Feature(string name);
    public string Name { get; }
    public Lifetime Lifetime { get; }
    public virtual UniTask InitializeAsync(CancellationToken ct) => default;
    public virtual void Tick(float deltaTime) { }
    public virtual UniTask ShutdownAsync() => default;
}
```

- 功能构造参数是它真正需要的平台服务/其他功能入口；不传 `ClientApp`/全局容器。
- 功能对外方法返回强类型结果；事件（`event Action<T>`）只用于广播，不用于请求-响应。
- 功能不读 `public static` 可变状态；不持有跨功能内部类型。
- 功能内部可自由分层（Battle 内部 `Session/World/View/Hud/Input`），但入口文件封住复杂度。
- 新增功能：
  1. 建 `Features/<Name>/` 目录与 `<Name>Feature.cs`；
  2. 在 `ClientApp` 构造一行；
  3. 若参与 AppFlow，在 `AppFlow` 加一次调用。
  功能目录外最多 1–2 行；不修改其他功能。
- 删除功能：删目录 + 删构造/流程行；其他功能不改。

### 7.1 已规划功能

| 功能 | 职责 | 对外入口 |
|---|---|---|
| `AccountFeature` | 游客登录/登出/令牌/Profile/历史；`LoginPage` | `RestoreOrLoginAsync`、`LoginAsync`、`LogoutAsync`、`Profile`、`HistoryAsync` |

## 8. Page 与 UiRuntime

### 8.1 PageSpec

```csharp
public sealed record PageSpec(
    string Address,          // prefab 地址（YooAsset location）
    PageLayer Layer,         // Screen / Modal / Overlay / System
    bool FullScreen,
    PageCachePolicy Cache);  // Lru / Resident / DestroyOnClose

public sealed class LoginPage : PageBase
{
    public static readonly PageSpec Spec = new("Page_Login", PageLayer.Screen, true, PageCachePolicy.Lru);
    private AccountFeature _account;
    public void Bind(AccountFeature account) => _account = account;

    protected override void OnShow()
    {
        SetText("Txt_Title", "UI.Login.Title");
        OnClick("Btn_GuestLogin", () => _account.LoginAsync());
    }
}
```

- `PageSpec` 是页面类的静态事实；**没有全局页面目录、表行、页面 ID、生成物**。
- 页面地址是 YooAsset location；页面 prefab 在其功能 `Content/` 下，收集组按目录通配。
- 新增页面 = 新页面类（+ 可选数据类）+ prefab；由所属功能打开；不改 AppFlow/其他功能。
- 页面数据是页面目录内的强类型 record/class；跨功能数据由功能入口方法传递。
- 页面依赖：`UiRuntime.OpenAsync<TPage>(spec, data, page => page.Bind(...))`；页面只拿自己需要的依赖。
- `PageBase` 生命周期：实例化时保持非激活 → `Bind`（注入依赖）→ 激活 → `OnShow` → `OnHide` → `OnDispose`。**先构造后激活**，避免 `OnEnable` 先于依赖注入。页面异步任务用 `PageHandle.Lifetime.Token`。
- 控件绑定：`PageBase` 在 `OnCreate` 扫描自身子树一次，建立 `BindName → Component` 字典；`Bind<T>(name)`、`OnClick(name, handler)`、`SetText/SetVisible/SetInteractable`。`BindName` 重名/缺控件抛异常；关闭时解绑按钮。
- 没有 `UIBindIndex`、没有 `BindGenerator`、没有 `UIApiSpec`、没有 `*.Designer.cs`。prefab 的 `BindName` 命名约定保留，作为美术/工程交接面；新页面用新 `BindName` 组件，旧 prefab 的 `BindNode/BindRoot` 在复制时剥离。
- **系统页**：`ErrorPage`/`LoadingPage`/`Toast`/`Confirm` 属 `Platform/Ui/Content`，由 `UiRuntime` 直接管理，不属于任何 Feature；`ErrorPage` 是启动/顶层失败的兜底，必须 prefab 化。
- **P1 parity 清单**：列表复用/滚动、LText 打字机与语言切换、UI 动效中断复位、CanvasScaler 多端、InputSystem 导航、SafeArea 设备差异、缓存/关闭原因、模态遮挡/Back 链。P0 只做最小栈。

### 8.2 UiRuntime 职责

| 能力 | 行为 |
|---|---|
| 层 | `Screen`（0）/`Modal`（1）/`Overlay`（2）/`System`（3）；固定 Canvas 根，不新建视觉 |
| 页面栈 | `OpenAsync`/`CloseAsync`/`ReplaceAsync`/`BackAsync`；同页在途请求合流或拒绝，防重复 |
| 模态 | Modal 栈；射线遮蔽、拦截输入计数、Back 优先关闭最顶模态 |
| 缓存 | `Lru`/`Resident`/`DestroyOnClose`；预算默认 16；关闭归还 prefab 租约，销毁释放依赖 |
| 转场 | 默认淡入/滑动；由 `UiRuntime.Tick` 驱动，不依赖全局时钟；超时兜底 |
| 焦点 | 保存/恢复 EventSystem 选中项；模态打开时聚焦；关闭恢复 |
| 反馈 | `Toast`/`ConfirmAsync`/`Loading`/`ErrorPage`；全部来自 `Platform/Ui/Content` 的 prefab |
| SafeArea | `SafeAreaFitter` 组件挂在页面容器；运行时按 `Screen.safeArea` 调整 |
| 输入阻断 | `IsInputBlocked` 由模态/全屏页面计数；`InputService` 读取 |
| 平台返回 | ESC/Android Back → `BackAsync`；Loading 可阻断 |

- 对外只有一个 `UiRuntime` 门面；内部按层/栈/缓存/转场/焦点拆 4–8 个文件，不暴露 `UIForm` 状态机。
- 页面缓存与展示代次：每次 `OnShow` 递增 `DisplayGeneration`；异步回调必须检查 `handle.IsCurrent(generation)`，防止旧页面回调覆盖新页面。
- 关闭原因：`User`/`Back`/`Replace`/`ScopeExit`/`Reload`/`Shutdown`；系统关闭跳过未保存拦截。
- `UiRuntime` 不构建视觉；缺 prefab/根组件 fail-fast，不静默造替身。

## 10. BattleFeature

### 10.1 对外契约

```csharp
public sealed class BattleFeature : Feature
{
    public async UniTask<BattleResult> RunAsync(MatchInfo match, CancellationToken ct);
}

public sealed record BattleResult(
    BattleOutcome Outcome,          // Completed / SessionFailed / Aborted / LeftByUser
    int LocalPlayerId,
    MatchEnded? MatchEnded,         // 冻结的权威结束数据
    ISettlementSummary Settlement,  // 结算页行表
    string? FailureReason);
```

- 调用方只传 `MatchInfo`（host/port/roomId/ticket/buildHash/mapId/玩家身份），只拿 `BattleResult`。
- 不暴露 `BattleContext`、`SimWorldState`、`RoomClient`、`BattleViewRig`、`ClientScope`。
- 场景加载/卸载、RoomPage 等待、HUD、输入、相机、VFX/音频全部在功能内部。

### 10.2 内部顺序

```text
RunAsync
  → 打开 RoomPage（显示房号/席位/房主开局）
  → NetSession.ConnectAsync(ticket)
  → JoinAck → 等 StartGame / MatchEnded
  → 校验 StartGame.ConfigHash（不等 → SessionFailed）
  → 加载本局 owned 场景（Rig + 地图）→ 建 BattleWorld（RollbackSim resolveCombat:false）
  → 建 BattleView（场景/Rig/角色/相机）→ HUD
  → 关闭 RoomPage
  → 每帧 Tick（固定序）：
        TickPreSample（诊断）
        → 输入采样/上下文门
        → 同一份输入上行（InputLeadFrames=3）
        → NetSession 收泵
        → Sim.Tick
        → 追帧补发
        → View.Tick（插值/和解/动画/相机/HUD/反馈）
  → 等 MatchEnded → 冻结 BattleResult
  → finally（逆序）：
        解绑输入/会话门面 → View.Dispose（消费者→视图→租约）
        → World.Dispose（BattleContext 退订/Sim）
        → NetSession.Dispose
        → 归还 prefab/资源租约
        → await 卸载 owned 场景（失败 → 保留占用/错误页，不假完成）
        → 恢复进场前活动场景
```

### 10.3 必须保留的隐式契约

1. `BattleContext.Tick` 五段顺序不可换；输入必须先于 Sim 步进；视图后于权威应用。
2. `InputLeadFrames = 3`；`viewFrame = SimView.RenderFrame`（不是最后快照帧）；追帧多出的逻辑帧逐帧补发。
3. `StartGame.ConfigHash` 必须等于本端 `IMatchIdentity.Compute`（含 noDeath/infiniteAmmo 规则位）；不等不建世界，直接 `SessionFailed`。
4. `JoinAck.reconnect_token` 一次性、绑 `(playerId, roomId)`、服务端 TTL 300s；`MatchEnded` 后作废；`RestoreComplete` 不发则服务端抑制增量。
5. 只卸本局 `_ownedScenes`；卸载前恢复进场前 active 场景；卸载完成才释放占用；卸载失败 = 停机态（保留占用、不自动回大厅）。
6. 释放序：解绑会话 → 关对局菜单 Back → 输入 Reset → View 消费者/视图/租约 → World/BattleContext → NetSession → 场景卸载。
7. 快照幂等：`RoomInbound` 严格单调；CombatEvents 首批只标已见；回滚/和解段事件静默；快照环 16 > 视图缓冲 8。
8. 断线：`BattleSession` 内部 `SuspectedLost → Reconnecting → Restoring`；失败返回 `SessionFailed`，不把错误状态泄漏到全局。

## 11. 取消、错误与恢复

- **取消**：每个功能/页面/会话一个 `Lifetime`；App 关闭取消根 token；页面关闭取消页面 token；战斗结束取消战斗 token。所有 `await` 传 token。
- **错误分类**：`Result<T>` 用于可预期失败（网络、票据、房满、版本不符）；`ClientException` 用于需要顶层处理的失败。分类：`Recoverable`（可重试）、`Fatal`（停机/错误页）、`Compatibility`（版本/内容不符）、`Auth`（回登录）、`Network`（重试/回大厅）。
- **重试**：只对幂等操作自动重试（房间列表、登录态恢复、内容健康检查）；进入对局/结算提交不自动重试，返回明确结果。
- **错误页**：`UiRuntime.ShowErrorAsync(title, message, retry, backToLogin)`；prefab 化，不运行时拼 UI。
- **启动失败**：AOT `BootstrapErrorPage`（prefab）显示；hot 装载失败也走它。
- **离场失败**：BattleFeature 返回 `Fatal` + 保留场景/占用；`AppFlow` 显示不可重试错误页；不自动回大厅，避免在旧场景上入场。
- **恢复**：登录态恢复、断线重连、内容候选恢复沿用现有协议语义；不恢复旧的 `ProcedureId.Error` 态。

public sealed class ClientApp

    private readonly PlatformServices _platform;

    public static async UniTask<ClientApp> CreateAsync(Platform platform, CancellationToken ct)
    {
        var account = new AccountFeature(platform.Meta, platform.Settings);
        var matchmaking = new MatchmakingFeature(platform.Meta, platform.Ui, account);
        var battle = new BattleFeature(platform.Content, platform.Config, platform.Input,
            platform.Audio, platform.Ui, platform.Settings, account);

        var records = new RecordsFeature(platform.Ui, account);
        var dev = DevFeature.CreateIfEnabled(platform);
        var app = new ClientApp(platform, account, matchmaking, battle, result, settings, records, dev);
        await app.InitializeAsync(ct);
        return app;
    }

    public UniTask RunAsync(CancellationToken ct) => _flow.RunAsync(ct);

    public void Tick(float dt)
    {
        _platform.Ui.Tick(dt);
        _battle.Tick(dt);       // 仅活动对局；非活动 no-op

    }

    {

        await _account.ShutdownAsync();
        await _settings.ShutdownAsync();
        await _records.ShutdownAsync();
        await _result.ShutdownAsync();
        await _platform.Ui.ShutdownAsync();

    }

### 17.2 UiRuntime 打开

```csharp
public async UniTask<PageHandle> OpenAsync<TPage>(
    PageSpec spec, object data, Action<TPage> bind, CancellationToken ct)
    where TPage : PageBase
{
    ct.ThrowIfCancellationRequested();
    PageHandle handle = AcquireOrCreate(spec);          // 缓存/实例化/租约
    try
    {
        TPage page = handle.Page as TPage
            ?? throw new InvalidOperationException($"{spec.Address} 根组件不是 {typeof(TPage).Name}");
        bind(page);                                     // 功能注入依赖
        await PushAsync(handle, spec, data, ct);        // 入栈/转场/OnShow
        return handle;
    }
    catch
    {
        await ReleaseAsync(handle, CloseReason.ScopeExit);
        throw;
    }
}
```
