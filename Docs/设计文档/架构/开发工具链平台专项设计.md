# 开发工具链平台专项设计

> **版本**：0.1（2026-10-21）
> **定位**：裁决开发工具链的统一入口、机器可读清单、编辑器页件契约、单一 CLI、生成文档与外部注册面检查。
> **不做的事**：不裁决测试分层、构建产物、GM 能力、热更发布与性能预算；不重写各工具的业务算法；不登记施工批次与完成状态。
> **冲突裁决**：能力优先级以[《调试与开发工具链演进路线图》](../测试与性能/调试与开发工具链演进路线图.md)为准；生成器形态以[《生成器工具箱专项设计》](生成器工具箱专项设计.md)为准；烘焙与 GM 页件分别以对应专项设计为准；本文件只裁决“入口、清单、发现、校验、文档”这一层。
> **关联**：[AGENTS.md](../../../AGENTS.md)、[修改指南](../../修改指南.md)、[技术支持](../../工具链/技术支持.md)、[生成器工具箱专项设计](生成器工具箱专项设计.md)、[烘焙工具箱专项设计](../游戏玩法/烘焙工具箱专项设计.md)、[GM 与调试工具分层专项设计](GM与调试工具分层专项设计.md)、[开发工具链平台分层设计](开发工具链平台分层设计.md)（总体分层与后续批次）。

## 1. 定位与原则

工具链的专业度不取决于工具数量，而取决于**发现成本、登记成本与失败可信度**。平台的统一对象是“工具如何被找到、如何被执行、如何被登记、如何被验证”，不是工具内部实现。

四条原则：

1. **一处登记，多处消费**：工具元数据只有 `scripts/gate/toolchain.json` 一份；Hub、CLI、生成文档、注册面检查都从它读取。
2. **薄适配，不重写**：现有窗口、页件、动作保留实现；平台通过 `page / window / action` 三种适配接入。
3. **失败可见**：清单缺失、handler 缺失、路径漂移、生成物过期都必须显式失败或告警，禁止静默空目录与静默跳过。
4. **上下文入口不强行收编**：Inspector/资源右键等上下文菜单依赖当前选择，保留在原工具；包级可复用入口（如 LiteCodeGen）保留独立形态。

## 2. 统一模型

```text
scripts/gate/toolchain.json
  ├─ categories[]        分类与排序
  ├─ tools[]             工具元数据 + 入口 + 写入面 + 文档
  └─ surfaces[]          外部注册面（CI / hook / 计划任务 / 可选路径）
          │
          ├─ LiteGame/工具链 → LiteGameToolboxWindow
          │      ├─ page   → IEditorToolPage（GM 六页、动作页、状态页）
          │      ├─ window → 现有 EditorWindow（烘焙/UI 绑定/编排/回写）
          │      ├─ action → 公开静态入口（Lua/扫描/SimTrig/资源构建等）
          │      └─ cli    → 只读命令展示/复制
          │
          └─ python scripts/toolchain.py
                 ├─ list / check / docs
                 ├─ open <editor-id>（Unity Pipeline 深链）
                 ├─ run <tool-id>（清单 command）
                 ├─ generate / verify / build（委托既有脚本）
                 └─ doctor（环境 + 注册面）
```

清单位于 `scripts/gate/`，不进入 Assets；编辑器通过工程根路径读取。这样不触发资源导入，也不把编辑器工具带进 Player 构建。

## 3. 清单契约

### 3.1 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `schemaVersion` | 是 | 当前为 `3`；结构变更时递增 |
| `categories` | 是 | `{id,title,order}`；Hub 与生成文档的分类顺序 |
| `tools` | 是 | 工具条目数组，见 §3.2 |
| `surfaces` | 是 | 外部注册面数组，见 §3.3 |
| 既有环境字段 | 否 | `unity/dotnet/python/packages/...` 保留；环境校验读取其中的版本与包信息 |

### 3.2 工具条目

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定标识，`<域>.<工具>`，全局唯一 |
| `title` | 是 | 人类可读名称 |
| `category` | 是 | 必须存在于 `categories` |
| `kind` | 是 | `page / window / action / cli / gate / build / content / docs` |
| `summary` | 是 | 一句话说明“它做什么/何时用” |
| `docs` | 是 | 仓库相对路径，必须存在 |
| `handler` | `page/window/action` 必填 | C# 行为键，全局唯一；由 `EditorToolRegistry` 注册 |
| `command` | `cli/gate/build/content` 必填 | 默认命令数组；`run` 在其后追加参数 |
| `menu` | 否 | 旧菜单路径，仅用于迁移说明与生成文档；不得制造第二份入口实现 |
| `writes` | 否 | `source/generated/asset/distribution` 子集；Hub 用于提示与确认 |
| `destructive` | 否 | 可能覆盖/删除资产时为 `true`；Hub 执行前确认 |
| `order` | 否 | 分类内排序；缺省按 `title` |
| `outputs` | 否 | v3：`{path,kind}` 数组；动作允许写入的文件/目录前缀；dry-run 动作必填 |
| `safety` | 否 | v3：`{dryRun,undo,confirmation}`；Hub 据此显示预览/回滚/确认 |

`kind` 语义：

- `page`：Hub 内嵌绘制，实现 `IEditorToolPage`。
- `window`：Hub 只显示摘要与“打开窗口”，实际内容留在现有 EditorWindow。
- `action`：Hub 内执行一次公开静态入口，结果进统一报告区。
- `cli/gate/build/content`：由单一 CLI 执行；Hub 只显示命令与复制按钮，不在编辑器主线程阻塞。
- `docs`：说明型条目，只提供摘要与文档链接。

### 3.3 外部注册面

| 字段 | 说明 |
|---|---|
| `id` | 注册面标识 |
| `kind` | `ci-workflow / hook-config / scheduled-task / path` |
| `path` | 文件或目录路径（`ci-workflow/hook-config/path`） |
| `name/script/runner` | 计划任务名与期望脚本/启动器 |
| `required` | 缺少时是否阻断；计划任务默认 `false`，因为并非每台机器都需要本地夜间任务 |

## 4. 编辑器 Hub 与页件契约

### 4.1 入口与布局

- 唯一顶层游戏菜单：`LiteGame/工具链`。**该路径必须是叶子项**——Unity 不允许同一路径既是可点击项又是子菜单父节点；快捷键与跨程序集桥放 `LiteGame/快捷/`（Prefab 回写、Lua Reload/Refill），LiteCodeGen 包级入口用 `LiteCodeGen/BindRoot/`，上下文菜单保留。
- 左侧：搜索框 + 分类列表；右侧：选中工具的标题、摘要、文档、写入面标签、内容区。动作型工具的“执行 + 统一报告区”在动作页内（报告随动作/页面走，Hub 不另设全局报告）。
- 顶部状态：清单路径与“重新加载清单”入口；环境版本与门禁结果归 `toolchain doctor` 与施工记录，不塞进 Hub。
- `Open()` / `Open(string id)` 为公开静态入口；CLI 深链与菜单都走它。

### 4.2 页件契约

```csharp
public interface IEditorToolPage
{
    GUIContent Title { get; }
    void OnShow();
    void OnHide();
    void Draw();
    void Poll();
}
```

- `EditorToolPageBase` 提供空实现。
- `IGmPage` 改为继承 `IEditorToolPage`；GM 六页不改业务即可被 Hub 宿主。原 `GmPanel` 壳退役（由 Hub 接管生命周期、轮询与选中记忆）。
- 生命周期由 Hub 壳统一驱动：翻页/关窗调 `OnShow/OnHide`；仅活动页按 0.5s 节拍 `Poll`。
- 页面不得自行订阅 `EditorApplication.update`；需要心跳的页面用 `Poll`。这条与 GM 页件的既有分层一致。
  - **既有例外**：`GmLocalChainPage` 需要编辑态（非 Play）1s 刷新，仍自管 `EditorApplication.update`，由 `OnShow/OnHide` 订阅/摘除；它的 `Poll` 为空。后续若 Hub 增加编辑态节拍，再迁移并由 Hub 统一驱动。

### 4.3 三类适配

| 适配 | 适用 | 行为 |
|---|---|---|
| `PageTool` | GM 页、动作页、状态页 | 直接 `Draw()`；报告进 Hub 底部 |
| `WindowTool` | 烘焙工具箱、UI 绑定/编排/回写 | 摘要 + “打开原窗口”；窗口内部实现不动 |
| `ActionTool` | Lua Reload/Refill、SimTrig、IEEE、纪律扫描、Resource、样式 | 按钮触发公开静态入口；按 `destructive/writes` 确认；报告/Console 提示 |

上下文型入口（BindRoot Inspector、资源右键、LiteCodeGen 包级菜单）不进入 `action` 注册；Hub 只提供说明与文档链接，避免“没有选择对象也能点”的假入口。

### 4.4 失败与边界

- 清单不可读/非法：显示 `ManifestErrorPage`（路径、错误列表、重新加载），不显示空目录。
- handler 未注册：该工具显示错误行；目录对账测试失败。
- 旧窗口类型被删/改名：打开动作显示可操作错误，不抛裸异常。
- 清单变更：Hub 提供“重新加载清单”；域重载后自然重读。

## 5. 单一 CLI

命令面以 `python scripts/toolchain.py` 为唯一文档入口；既有脚本直调保留（CI/构建/工具箱内部消费不动）。

| 命令 | 行为 |
|---|---|
| `list [--json]` | 按分类列出清单工具；标记编辑器/CLI/门禁/构建 |
| `check [--json] [--strict] [--manifest PATH]` | 清单 schema/唯一性/分类/路径、CI 与 hook 引用、生成文档新鲜度；可选 surface 缺失默认 warning |
| `docs [--check]` | 生成/校验 `Docs/工具链/工具索引.md` |
| `open <editor-id>` | 经 Unity Pipeline `eval_file --file` 打开 Hub 并选中 |
| `run <tool-id> [-- args]` | 执行清单 `command`；编辑器类工具引导到 `open` |
| `generate <tool>` | 委托 `scripts/codegen/toolbox.py` |
| `verify --lane <L0|L1|L2|L3|Doc|All>` | 委托门禁脚本 |
| `build [--profile]` | 委托 `build-player.ps1` |
| `doctor [--strict] [--fix-nightly]` | `check` + `restore-check` + 计划任务/pipeline 状态 |

退出码：0 成功；1 校验/执行失败；2 参数错误；4 工具不存在；5 编辑器未运行。子进程退出码优先透传。

`open` 必须使用 `eval_file --file`（Pipeline 命令 schema 的必填参数），不依赖内联代码字符串。

## 6. 生成文档

- 目标：`Docs/工具链/工具索引.md`。
- 头部声明 `AUTO-GENERATED by scripts/toolchain.py docs`；固定格式、LF、write-if-changed。
- 内容：分类 → 工具表（ID、标题、类型、入口/命令、写入面、文档）＋ surfaces 表。
- `docs --check` 比较生成内容与落盘内容；Doc 车道执行该检查。
- 手工排障叙事保留在 `Docs/工具链/技术支持.md`，不复制完整工具清单；生成页是清单的投影。

## 7. 外部注册面

工具链不仅被代码引用，还被外部注册面引用；这些面不会随文件移动自动更新。

| 面 | 检查 | 失败级别 |
|---|---|---|
| CI workflow | 扫描 `scripts/**.ps1|py` 字面量，逐一检查存在 | required → error |
| hook 配置 | 解析 `.zcode/config.json` / `.claude/settings.json`，检查 `scripts/hooks/*` | required → error |
| Windows 计划任务 | `schtasks /query /tn <name> /xml`；校验启动器为 `pwsh`、参数含清单脚本路径 | 可选 → warning；`--strict` → error |
| pipeline 包 | 可选路径存在性；不校验本地补丁内容 | 可选 → warning |

`install-nightly-task.ps1` 从清单读取任务名/脚本/runner，重新注册任务并打印 action/下次运行时间；不在构建或 CI 中自动执行。`restore-check.ps1` 从清单读取 `unity.version/revision` 并比对 `m_EditorVersionWithRevision`；L0 追加 `toolchain.py check`，使同一份清单在 CI 与本地都得到校验。

## 8. 扩展约定

**新增编辑器工具**：

1. 清单加 `tools` 条目，选择 `page/window/action`。
2. 在 `EditorToolRegistry` 注册同名 `handler`；`page` 返回 `IEditorToolPage`，`window` 提供打开委托，`action` 提供执行委托。
3. 不新增顶层菜单；需要快捷键的放在 `LiteGame/快捷/` 下（不要挂在 `LiteGame/工具链/` 下，否则 Hub 父项会失去可点击性）。
4. 在 `EditorToolCatalogEditModeTests` 的覆盖范围内自动对账，无需新增测试。

**新增 CLI 工具**：

1. 清单加 `kind: cli` 条目与 `command`；`toolchain.py run <id>` 自动支持。
2. 需要复杂参数的，仍通过 `run <id> -- ...` 追加；不要在 CLI 里为新工具写专用 switch。

**新增注册面**：

1. 清单加 `surfaces` 条目。
2. 在 `toolchain.py` 的 surface 检查器加对应 `kind` 的检查；不在多个脚本里各写一份。
3. 同步《directory-move-sync》与《修改指南》§2.3 的注册面清单。

**分类**：只改清单 `categories`；Hub 与生成文档自动跟随，不在 C# 写死分类。

## 9. 非目标与后续

- 不把 UI 绑定/编排/回写窗口重写为页件；它们是 `window` 目标，后续可逐个迁移。
- 不重构 L2 执行链；只修 `eval_file --file` 与注册面。
- 不修与本层无关的存量债：`BindGenerator` 覆盖手写主文件、`SimTrigTableGenerator` 无条件写盘、`refresh_hash` 探测失败返回 0、`GmLocalChainPage` 后台同步；这些继续由各自批次处理。
- 不校验 `Packages/com.unity.pipeline` 的 9 处本地补丁内容；后续加 checksum/apply 校验。
