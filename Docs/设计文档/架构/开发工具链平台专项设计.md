# 开发工具链平台专项设计

> **版本**：0.3（2026-10-22）
> **定位**：裁决开发工具链的统一入口、机器可读清单、编辑器页件契约、单一 CLI、生成文档与外部注册面检查，以及 `scripts/` 脚本作者面与 L1/L2/L3 分层。
> **不做的事**：不裁决测试分层、构建产物、GM 能力、热更发布与性能预算；不重写各工具的业务算法；不登记施工批次与完成状态。
> **冲突裁决**：能力优先级以[《调试与开发工具链演进路线图》](../测试与性能/调试与开发工具链演进路线图.md)为准；生成器形态以[《生成器工具箱专项设计》](生成器工具箱专项设计.md)为准；烘焙与 GM 页件分别以对应专项设计为准；本文件只裁决“入口、清单、发现、校验、文档”这一层。
> **关联**：[AGENTS.md](../../../AGENTS.md)、[修改指南](../../规范/02-代码与修改规范.md)、[技术支持](../../说明/15-工具链手册.md)、[生成器工具箱专项设计](生成器工具箱专项设计.md)、[烘焙工具箱专项设计](../游戏玩法/烘焙工具箱专项设计.md)、[GM 与调试工具分层专项设计](GM与调试工具分层专项设计.md)、[工具执行与写盘契约专项设计](工具执行与写盘契约专项设计.md)（L2 执行/写盘）、[调试与开发工具链演进路线图](../测试与性能/调试与开发工具链演进路线图.md)（能力优先级）。

## 1. 定位与原则

工具链的专业度不取决于工具数量，而取决于**发现成本、登记成本与失败可信度**。平台的统一对象是“工具如何被找到、如何被执行、如何被登记、如何被验证”，不是工具内部实现。

四条原则：

1. **一处登记，多处消费**：工具元数据只有 `scripts/gate/toolchain.json` 一份；Hub、CLI、生成文档、注册面检查都从它读取。
2. **薄适配，不重写**：现有窗口、页件、动作保留实现；平台通过 `page / window / action` 三种适配接入（`hud` 是运行内载体，平台只做说明，不做适配）。
3. **失败可见**：清单缺失、handler 缺失、路径漂移、生成物过期都必须显式失败或告警，禁止静默空目录与静默跳过。
4. **上下文入口不强行收编**：Inspector/资源右键等上下文菜单依赖当前选择，保留在原工具；包级可复用入口（如 LiteCodeGen）保留独立形态。

### 1.1 目标形态与收敛判据

**目标形态：一个声明式平台 + 三条能力线 + 一条证据链。** 工具只是清单里的一行数据；平台负责发现、执行、写盘、回滚与文档投影；能力线回答“这次改动用哪条环验证”。§2 展开清单驱动的数据流，本图只给全景。

```text
入口      LiteGame/工具链 Hub │ python scripts/toolchain.py
          page / window / action │ run / open / generate / verify / build / doctor
                    │ 唯一元数据 scripts/gate/toolchain.json + 生成索引
分类      category（域：维护与文档归属） × plane（生效面） × purpose（能力线）
                    │
执行      ToolRequest → ToolResult → ToolChange
          ToolWriteScope：dry-run / 备份 / Undo / outputs allowlist
                    │
能力线    调试（现场/回放/操控） │ 开发（内环/中环/构建计划） │ 交付（出包/部署/回归）
                    │
证据      BuildHash + CombatConfigDigest + 现场件信封 + 门禁结果 +（T3）度量趋势
```

三条能力线的问题、度量与红线各不相同（见[路线图 §3/§5](../测试与性能/调试与开发工具链演进路线图.md)与[GM 分层](GM与调试工具分层专项设计.md)）；平台只统一“工具怎么被找到、执行、写盘、回滚”，不统一能力目标。能力优先级归路线图，本节只裁决形态收敛。

**六条收敛判据**（全部满足即达目标形态；以门禁/测试为判据，不以文档描述为判据）：

| # | 判据 | 目标 | 验证面 |
|---|---|---|---|
| 1 | 单一清单与入口 | 工具/分类/入口/写面/安全等级只存在于 `toolchain.json`；Hub、CLI、生成索引、注册面检查共用；handler 与行为 1:1 | `toolchain.py check` 零告警；`docs --check` 无 stale；`EditorToolCatalogEditModeTests` |
| 2 | 声明完整 | 每个会写盘的工具声明 `outputs`（产物形态与路径）与 `safety`（dryRun/undo/confirmation）；Hub 的预览/回滚/确认只从声明推导，不在 C# 写死 | `check` 对“写盘但未登记产物”报错；Hub 动作页按声明渲染 |
| 3 | 单一执行/写盘 | 一次性动作只经 `ToolWriteScope`；资产写盘走 L2-C（备份/Undo/ImportAsset）；工具内无裸 `File.WriteAllText`/`SaveAssets` 旁路 | `ToolWriteScopeEditModeTests`；定向 EditMode；全量 L2 |
| 4 | 单一交互边界 | 只有 `page`/`window` 两种交互形态（`hud` 是运行内载体，不占 Hub 交互面）；生命周期由 Hub 驱动；window 声明 `safety` 并在关闭时给出变更摘要 | `EditorToolCatalogEditModeTests`；窗口冒烟 |
| 5 | 证据链闭环 | 失败自带现场：`BuildHash` + `CombatConfigDigest` + 现场件信封；房间记录可离线重放到首分歧 | 路线图 T0 退出条件；`ReplayTool`；现场包用例 |
| 6 | 平台可度量 | 构建/测试耗时、flaky 率、`change-to-verified`、回放采集率有趋势出口 | 路线图 T3；CI 报告 |

六条判据只判“形态是否收敛”，不判能力完成度；其中 5/6 的能力目标归[路线图](../测试与性能/调试与开发工具链演进路线图.md)，本节只要求平台为其提供入口与单一读口。

**新增工具达到收敛的动作**（细则见 §8）：清单一行 + 对应 handler/脚本 + 经单一入口可达 + 写盘/交互声明完整 + `check` 与对账测试通过。**不需要**新增顶层菜单、第二份索引或第二套写盘代码。

**非目标**：

- 不做第二个 Hub/CLI，不把工具放进 `Assets/`；
- 不要求所有窗口同构——入口统一不等于内容重写；
- 不替路线图排能力优先级，不登记完成状态；
- 不做 release 可调试，不做全量遥测平台。

## 2. 统一模型

```text
scripts/gate/toolchain.json
  ├─ categories[]        分类与排序
  ├─ tools[]             工具元数据 + 入口 + 写入面 + 文档 + plane/requires
  └─ surfaces[]          外部注册面（CI / hook / 计划任务 / 可选路径）
          │
          ├─ LiteGame/工具链 → LiteGameToolboxWindow
          │      ├─ page   → IEditorToolPage（GM 六页、动作页、状态页）
          │      ├─ window → 现有 EditorWindow（烘焙/UI 绑定/编排/回写）
          │      ├─ action → 公开静态入口（Lua/扫描/SimTrig/资源构建等）
          │      ├─ cli    → 只读命令展示/复制
          │      └─ hud    → 运行内载体，只做说明（DevHUD）
          │
          └─ python scripts/toolchain.py
                 ├─ list / check / docs
                 ├─ open <editor-id>（Unity Pipeline 深链）
                 ├─ run <tool-id>（清单 command）
                 ├─ generate / verify / build（委托既有脚本）
                 └─ doctor（环境 + 注册面）
```

清单位于 `scripts/gate/`，不进入 Assets；编辑器通过工程根路径读取。这样不触发资源导入，也不把编辑器工具带进 Player 构建。

## 3. 清单契约

### 3.1 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `schemaVersion` | 是 | 当前为 `6`；结构变更时递增 |
| `categories` | 是 | `{id,title,order,docs,allowDocs}`；`docs`＝域权威文档，`allowDocs`＝允许偏离权威的文档白名单（域内形态规则见[域形态基线](工具链域形态基线专项设计.md)） |
| `tools` | 是 | 工具条目数组，见 §3.2 |
| `surfaces` | 是 | 外部注册面数组，见 §3.3 |
| 既有环境字段 | 否 | `unity/dotnet/python/packages/...` 保留；环境校验读取其中的版本与包信息 |

### 3.2 工具条目

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定标识，`<域>.<工具>`，全局唯一 |
| `title` | 是 | 人类可读名称 |
| `category` | 是 | 必须存在于 `categories` |
| `kind` | 是 | `page / window / action / hud / cli / gate / build / content / docs`；宿主与执行形态 |
| `plane` | 是 | `editor / runtime / external / none`；工具生效时哪一侧必须活着（语义与校验见 §3.2.1） |
| `requires` | 否 | `play / player / unity-batch` 子集；执行前置，满足其一即可，空＝无额外前置 |
| `purpose` | 是 | `debug / dev / delivery`；工具服务哪条能力线（语义与校验见 §3.2.2） |
| `summary` | 是 | 一句话说明“它做什么/何时用” |
| `docs` | 是 | 仓库相对路径，必须存在 |
| `handler` | `page/window/action` 必填 | C# 行为键，全局唯一；由 `EditorToolRegistry` 注册 |
| `command` | `cli/gate/build/content` 必填 | 默认命令数组；`run` 在其后追加参数 |
| `menu` | 否 | 旧菜单路径，仅用于迁移说明与生成文档；不得制造第二份入口实现 |
| `writes` | 否 | `source/generated/asset/distribution` 子集；**只表达动不动工程资产/分发物**（Hub 确认提示用），证据/报告类产物不进此列 |
| `destructive` | 否 | 可能覆盖/删除资产时为 `true`；Hub 执行前确认 |
| `order` | 否 | 分类内排序；缺省按 `title` |
| `outputs` | 否 | v6：产物登记 `{path,kind}` 数组；有产物就登记（语义与枚举见 §3.2.3）；dry-run 动作必填 |
| `safety` | 否 | v3：`{dryRun,undo,confirmation}`；Hub 据此显示预览/回滚/确认 |

`kind` 语义：

- `page`：Hub 内嵌绘制，实现 `IEditorToolPage`。
- `window`：Hub 只显示摘要与“打开窗口”，实际内容留在现有 EditorWindow。
- `action`：Hub 内执行一次公开静态入口，结果进统一报告区。
- `cli/gate/build/content`：由单一 CLI 执行；Hub 只显示命令与复制按钮，不在编辑器主线程阻塞。
- `hud`：运行内载体（DevHUD）——由游戏进程自创建，Hub/CLI 只显示说明与前置提示，不执行、不打开。
- `docs`：说明型条目，只提供摘要与文档链接。

### 3.2.1 平面与前置

`plane` 回答“工具生效时哪一侧必须活着”，与 `kind`（宿主与执行形态）正交——同一个 `kind` 可以落在不同平面（`debug.local-chain` 是 `page` 但 `plane=external`），同一平面也允许不同宿主形态：

| plane | 生效条件 | 典型条目 |
|---|---|---|
| `editor` | Unity 编辑器开着、编辑态 | 烘焙、UI 绑定、编辑器内生成器与扫描动作 |
| `runtime` | 一个游戏实例在跑（编辑器 Play 或 Player） | GM 页件、Lua 热更动作、DevHUD |
| `external` | 宿主 shell 或云端独立完成，不要求编辑器与游戏实例 | 门禁/构建/部署/内容 CLI、本地联测页件 |
| `none` | 无执行，只做说明 | `docs` 条目 |

`requires` 是执行前置清单，取值 `play`（编辑器 Play 模式）、`player`（可运行的 Player 产物/进程）、`unity-batch`（Unity 批处理，不需要开编辑器 UI）；**列表内满足其一即可**，空表示无额外前置。

判定规则（`toolchain.py check` 与 `EditorToolCatalog.Load` 同口径，两侧都报错）：

| # | 规则 |
|---|---|
| 1 | `plane` 必填且 ∈ 四值；`requires` ⊆ 三值 |
| 2 | `plane=none` ⇔ `kind=docs` |
| 3 | `plane=editor` ⇒ `requires` 为空 |
| 4 | `plane=runtime` ⇒ `requires` 非空且 ⊆ `{play, player}` |
| 5 | `plane=external` ⇒ 有 `command`，或 `kind=page`（宿主在编辑器、操作外部环境的页件，如本地联测） |
| 6 | `kind=hud` ⇒ `plane=runtime` 且 `requires` 含 `play`/`player` |

### 3.2.2 用途（能力线）

`purpose` 回答“这工具服务哪条能力线”，词汇直接沿用[路线图 §3/§5](../测试与性能/调试与开发工具链演进路线图.md)已裁决的三条线，不另造第三套词：

| purpose | 能力线 | 判据（它回答什么问题） | 典型条目 |
|---|---|---|---|
| `debug` | 调试（现场/回放/操控） | 对着一个**在跑或已录下**的游戏实例看/动 | 调试页件六条（GM 面板）、DevHUD、日志检索、房间回放、本地联测、Lua 热更 |
| `dev` | 开发（内环/中环/构建计划） | 造东西：内容、资产、代码、配置 | 烘焙、UI 工具、生成器、Bundle 构建、纪律/基线自查 |
| `delivery` | 交付（出包/部署/回归） | 把东西**发出去或验回来** | 门禁 L0–L3、出包与冒烟、部署与云端运维、内容发布、环境恢复与夜间 |

判定与 `plane` 正交，两者可以任意组合（`debug.test-mode` 是 `runtime`+`debug`，`env.room-replay` 是 `external`+`debug`，`quality.l1` 是 `external`+`delivery`）。与 `category`（域）**不重合**：域是维护与文档归属，用途是消费者意图——`codegen` 域同时含 `dev`（生成器）与 `debug`（Lua 热更），`quality` 域同时含 `dev`（纪律扫描）与 `delivery`（门禁）。

判定规则：

| # | 规则 |
|---|---|
| 1 | `purpose` 必填且 ∈ 三值；Hub 与 `list --purpose` 据此筛选 |
| 2 | 判定看“**它服务谁**”，不看宿主与平面：同一域内允许三条线并存 |
| 3 | 说明型（`docs`）条目按**主题**归线（如 Unity Pipeline 运维归 `dev`），不因“不执行”而免填 |

### 3.2.3 产物形态

`outputs` 回答“这工具产出什么、落在哪”，是**产物登记**（不只是写盘 allowlist）：有产物就登记，交互式窗口除外。

| kind | 形态 | 典型产物 |
|---|---|---|
| `generated` | 生成代码/读码 | `BuildHash.g.cs`、`GameData/Generated/`、烘焙产物 |
| `source` | 手写源 | 由工具生成的源码文件（非生成器产物） |
| `data` | 表/配置数据 | `GameData/Config/*.bytes`、`UiBindManifest.json`、`deploy/.env` |
| `asset` | Unity 资产 | prefab、场景、材质、SO |
| `binary` | 包体/可执行 | `Builds/`、`Bundles/`、`Builds/win-server/` |
| `report` | 证据/报告/日志 | `TestResults/`、`TestResults/nightly/` |
| `distribution` | 分发物/投放面 | `LocalCDN/`、`Dist/out/` |

**`writes` 与 `outputs` 的分工**：`writes` 只表达“动不动工程资产/分发物”（Hub 确认提示用）；`outputs` 表达“产物是什么形态、在哪”。因此**证据/报告类产物（`report`）不写进 `writes`**——门禁类工具仍是 `writes: none`，但产物可见。

判定规则：

| # | 规则 |
|---|---|
| 1 | `outputs[].path` 必须是仓库相对路径（文件或目录前缀，以 `/` 结尾）；`kind` ∈ 七值 |
| 2 | 支持 `safety.dryRun=supported` 的动作必须有 `outputs`（既有规则） |
| 3 | **非交互式写入者**（`kind ∉ {page, window}` 且 `writes` 含非 `none` 写面）必须登记 `outputs` |
| 4 | 交互式窗口（`page/window`）不要求固定产物：产物随选择走，由 `writes` 与 `ToolInteractionSession` 表达 |
| 5 | 新增清单字段的门槛：必须同时给出「校验规则 + 检索/展示面 + 至少一个消费者」，否则不加 |

### 3.3 外部注册面

| 字段 | 说明 |
|---|---|
| `id` | 注册面标识 |
| `kind` | `ci-workflow / hook-config / scheduled-task / path` |
| `path` | 文件或目录路径（`ci-workflow/hook-config/path`） |
| `name/script/runner` | 计划任务名与期望脚本/启动器 |
| `required` | 缺少时是否阻断；计划任务默认 `false`，因为并非每台机器都需要本地夜间任务 |

## 4. 编辑器 Hub 与页件契约

### 4.1 入口与布局

- 唯一顶层游戏菜单：`LiteGame/工具链`。**该路径必须是叶子项**——Unity 不允许同一路径既是可点击项又是子菜单父节点；快捷键放 `LiteGame/快捷/`（Lua Reload/Refill），LiteCodeGen 包级入口用 `LiteCodeGen/BindRoot/`，上下文菜单保留。
- 左侧：搜索框 + 分类列表；右侧：选中工具的标题、摘要、文档、写入面标签、内容区。动作型工具的“执行 + 统一报告区”在动作页内（报告随动作/页面走，Hub 不另设全局报告）。
- 顶部状态：清单路径与“重新加载清单”入口；环境版本与门禁结果归 `toolchain doctor` 与施工记录，不塞进 Hub。
- `Open()` / `Open(string id)` 为公开静态入口；CLI 深链与菜单都走它。

### 4.2 页件契约

```csharp
public interface IEditorToolPage
{
    GUIContent Title { get; }
    void OnShow();
    void OnHide();
    void Draw();
    void Poll();
}
```

- `EditorToolPageBase` 提供空实现。
- `IGmPage` 改为继承 `IEditorToolPage`；GM 六页不改业务即可被 Hub 宿主。原 `GmPanel` 壳退役（由 Hub 接管生命周期、轮询与选中记忆）。
- 生命周期由 Hub 壳统一驱动：翻页/关窗调 `OnShow/OnHide`；仅活动页按 0.5s 节拍 `Poll`。
- 页面不得自行订阅 `EditorApplication.update`；需要心跳的页面用 `Poll`。这条与 GM 页件的既有分层一致。
  - **既有例外**：`GmLocalChainPage` 需要编辑态（非 Play）1s 刷新，仍自管 `EditorApplication.update`，由 `OnShow/OnHide` 订阅/摘除；它的 `Poll` 为空。后续若 Hub 增加编辑态节拍，再迁移并由 Hub 统一驱动。

### 4.3 三类适配

| 适配 | 适用 | 行为 |
|---|---|---|
| `PageTool` | GM 页、动作页、状态页 | 直接 `Draw()`；报告进 Hub 底部 |
| `WindowTool` | 烘焙工具箱、UI 绑定/编排/回写 | 摘要 + “打开原窗口”；窗口内部实现不动 |
| `ActionTool` | Lua Reload/Refill、SimTrig、IEEE、纪律扫描、Resource、样式 | 按钮触发公开静态入口；按 `destructive/writes` 确认；报告/Console 提示 |

上下文型入口（BindRoot Inspector、资源右键、LiteCodeGen 包级菜单）不进入 `action` 注册；Hub 只提供说明与文档链接，避免“没有选择对象也能点”的假入口。

### 4.4 失败与边界

- 清单不可读/非法：显示 `ManifestErrorPage`（路径、错误列表、重新加载），不显示空目录。
- handler 未注册：该工具显示错误行；目录对账测试失败。
- 旧窗口类型被删/改名：打开动作显示可操作错误，不抛裸异常。
- 清单变更：Hub 提供“重新加载清单”；域重载后自然重读。

## 5. 单一 CLI

命令面以 `python scripts/toolchain.py` 为唯一文档入口；既有脚本直调保留（CI/构建/工具箱内部消费不动）。

| 命令 | 行为 |
|---|---|
| `list [--json]` | 按分类列出清单工具；标记编辑器/CLI/门禁/构建 |
| `check [--json] [--strict] [--manifest PATH]` | 清单 schema/唯一性/分类/路径、CI 与 hook 引用、生成文档新鲜度、域形态三条规则（见[域基线](工具链域形态基线专项设计.md) §4）；可选 surface 缺失默认 warning |
| `docs [--check]` | 生成/校验 `Docs/工具链/工具索引.md` |
| `open <editor-id>` | 经 Unity Pipeline `eval_file --file` 打开 Hub 并选中 |
| `run <tool-id> [-- args]` | 执行清单 `command`；编辑器类工具引导到 `open` |
| `generate <tool>` | 委托 `scripts/codegen/toolbox.py` |
| `verify --suite <L0|L1|L2|L3|Doc|All>` | 委托门禁脚本 |
| `build [--profile]` | 委托 `build-player.py` |
| `doctor [--strict] [--fix-nightly]` | `check` + `restore-check` + 计划任务/pipeline 状态 |

退出码：0 成功；1 校验/执行失败；2 参数错误；4 工具不存在；5 编辑器未运行。子进程退出码优先透传。

`open` 必须使用 `eval_file --file`（Pipeline 命令 schema 的必填参数），不依赖内联代码字符串。

## 6. 生成文档

- 目标：`Docs/工具链/工具索引.md`。
- 头部声明 `AUTO-GENERATED by scripts/toolchain.py docs`；固定格式、LF、write-if-changed。
- 内容：分类 → 工具表（ID、标题、类型、入口/命令、写入面、文档）＋ surfaces 表。
- `docs --check` 比较生成内容与落盘内容；Doc 车道执行该检查。
- 手工排障叙事保留在 `Docs/工具链/技术支持.md`，不复制完整工具清单；生成页是清单的投影。

## 7. 外部注册面

工具链不仅被代码引用，还被外部注册面引用；这些面不会随文件移动自动更新。

| 面 | 检查 | 失败级别 |
|---|---|---|
| CI workflow | 扫描 `scripts/**.ps1|py` 字面量，逐一检查存在 | required → error |
| hook 配置 | 解析 `.zcode/config.json` / `.claude/settings.json`，检查 `scripts/hooks/*` | required → error |
| Windows 计划任务 | `schtasks /query /tn <name> /xml`；校验启动器为 `pwsh`、参数含清单脚本路径 | 可选 → warning；`--strict` → error |
| pipeline 包 | 可选路径存在性；不校验本地补丁内容 | 可选 → warning |

`install-nightly-task.py` 从清单读取任务名/脚本/runner，重新注册任务并打印 action/下次运行时间；不在构建或 CI 中自动执行。`restore-check.py` 从清单读取 `unity.version/revision` 并比对 `m_EditorVersionWithRevision`；L0 追加 `toolchain.py check`，使同一份清单在 CI 与本地都得到校验。

## 8. 扩展约定

**新增编辑器工具**：

1. 清单加 `tools` 条目，选择 `page/window/action`，并如实声明 `plane`（生效面）、`purpose`（能力线）与 `requires`（执行前置，如 Play/Player）。
2. 在 `EditorToolRegistry` 注册同名 `handler`；`page` 返回 `IEditorToolPage`，`window` 提供打开委托，`action` 提供执行委托。
3. 不新增顶层菜单；需要快捷键的放在 `LiteGame/快捷/` 下（不要挂在 `LiteGame/工具链/` 下，否则 Hub 父项会失去可点击性）。
4. 在 `EditorToolCatalogEditModeTests` 的覆盖范围内自动对账，无需新增测试。

**新增 CLI 工具**：

1. 清单加 `kind: cli` 条目与 `command`；`toolchain.py run <id>` 自动支持。
2. 需要复杂参数的，仍通过 `run <id> -- ...` 追加；不要在 CLI 里为新工具写专用 switch。

**新增注册面**：

1. 清单加 `surfaces` 条目。
2. 在 `toolchain.py` 的 surface 检查器加对应 `kind` 的检查；不在多个脚本里各写一份。
3. 同步《directory-move-sync》与《修改指南》§2.3 的注册面清单。

**分类**：只改清单 `categories`；Hub 与生成文档自动跟随，不在 C# 写死分类。

## 9. 脚本作者面（`scripts/`）

> 平台不只管编辑器工具：`scripts/` 下的工程脚本与工具同属一个入口面（清单 `command`）。本节裁决脚本角色、入口、调用契约与文件形态；迁移批次与证据归 `Docs/施工进度/资源与工具链线.md`，本节只写现行形态。

### 9.1 角色分层

| 角色 | 判据 | 命名 | 进清单 | 例 |
|---|---|---|---|---|
| 全局入口 | 面向所有工具的发现/执行入口 | `toolchain.py` | 是 | `python scripts/toolchain.py` |
| 域入口 | 一个域一个稳定入口，负责分发子工具 | `<域>/<动词>-<对象>.py` 或既有工具箱名 | 是 | `codegen/toolbox.py`、`gate/nightly-gate.py` |
| 叶子工具 | 单一职责、可独立执行 | 动词开头 kebab-case | 用户面/CI 面必进 | `gate/test.py`、`content/publish-candidate.py` |
| 内部库 | 被其他脚本 import，不独立执行 | `_` 前缀 | 否 | `_common.py`、`_codegen.py` |
| 测试 | 脚本层契约测试 | `tests/test_*.py` | 否 | `test_toolchain.py` |
| 一次性运维 | 历史补丁/一次性扫描 | 原目录 + 文件头 `@oneshot` | 否（仅告警） | `pipeline/patch_*.py` |

**生成器例外**：`codegen/` 遵守[生成器工具箱专项设计](生成器工具箱专项设计.md) §7（`gen_<对象>.py`，由 `toolbox.py` 注册）。

### 9.2 入口与登记

1. **canonical 入口 = 清单 `command`**：文档、CI、Agent、计划任务只写这一种；单脚本直调保留给既有消费面，不作为首选。
2. **域入口只做转发**：解析子命令、校验参数、透传参数与子进程退出码；不承载业务算法，不复制叶子脚本默认值。
3. **叶子工具不反向依赖域入口**；域入口可调用叶子，叶子不得调用域入口。
4. **内部库不可执行**：`_` 前缀不得包含 `main()` 或可独立入口，只提供函数/类型。
5. **登记判据**（满足其一）：清单 `command`；被已登记入口的注册表引用；`_` 内部库/测试/`@oneshot`；否则补清单，不加豁免。
6. `toolchain.py check` 扫描孤儿可执行脚本、编码/EOL；未覆盖项默认告警，`--strict` 升为错误。

### 9.3 调用契约

- **参数**：清单 `args` 是 schema 单源；脚本用 `argparse` 解析，长参数 kebab-case；缺参/类型/枚举错 → 调用前 fail-fast、exit 2；默认值只在清单或脚本一处声明。
- **帮助**：每个入口支持 `--help`；`toolchain.py run <id> --help` 渲染清单参数与默认值，不启动子进程。
- **退出码**：`0` 成功、`1` 预期失败、`2` 用法错误；`toolchain.py` 另有 `4`（工具不存在）/`5`（编辑器未运行）。叶子与域入口本地只用 0/1/2；域入口把子进程的 3/4/7 等业务码归一为 1（原始码与摘要写 stderr），不得把失败吞成 0。
- **输出**：状态行前缀 `[<域>/<工具>]`；正常/摘要写 stdout，错误与修复提示写 stderr；退出码是权威结果；`--json` 为可选能力（启用时 stdout 纯 JSON）。
- **dry-run 与 check**：`--check` 只校验不写盘；`--dry-run` 预览写盘；清单 `safety.dryRun` 声明，未声明或 `unsupported` 必须显式拒绝。
- **根路径**：一律由脚本自身位置推导（`_common.repo_root()`），禁止依赖 CWD；允许 `--project-path` 显式覆盖。
- **非交互**：CI/Agent/计划任务路径不得等待键盘；破坏性动作需显式开关（`--yes`/`-Force`）。

### 9.4 文件与配置形态

| 面 | 规则 |
|---|---|
| 语言 | **全 Python**（3.10+）；`scripts/**/*.ps1` 恒为 0，兼容壳只允许存在于迁移窗口且不得新增 |
| 编码/EOL | UTF-8 无 BOM、LF；`.gitattributes` 声明 `*.py text eol=lf` |
| 命名 | 入口 `<域>/<动词>-<对象>.py`（kebab）；生成器 `gen_<对象>.py`；内部库 `_<name>.py`；配置 `<name>.json` |
| 头注释 | 入口四段式：用途/入口/契约/消费点与重跑时机；生成器五段式；内部库两段式 |
| 配置 | 声明式 JSON/YAML；加载器必须是 `_` 内部库；禁止可执行配置 |
| 密钥 | 环境变量/`LocalNotes/`；不入库、不回显、不写进工作区输出 |

### 9.5 机械判据

- `toolchain.py check` 覆盖清单、注册面、孤儿脚本、编码/EOL；
- 所有登记入口有原生 `--help`，未知参数/子命令 exit 2；
- 脚本契约测试（帮助/退出码/参数缺失/输出前缀）随 L1 跑。

## 10. 分层与不变量

| 层 | 名称 | 解决什么 | 权威 |
|---|---|---|---|
| **L1** | 入口与登记 | 工具在哪、怎么被发现与调用、文档与外部注册面不漂移 | 本文件 §2–§9 |
| **L2** | 执行与写盘 | 执行前可预览、写入可追踪、可回滚、结果统一 | [工具执行与写盘契约专项设计](工具执行与写盘契约专项设计.md) |
| **L3** | 交互与 UI | 交互窗口/页件的统一入口、生命周期与安全边界 | 本文件 §11 |

**层间不变量**：

1. **单一清单**：`scripts/gate/toolchain.json` 是工具/分类/入口/outputs/safety 的唯一元数据源，Hub/CLI/生成索引/注册面检查共用。
2. **行为唯一**：清单 handler 与 C# 行为 1:1，由 `EditorToolCatalogEditModeTests` 对账。
3. **写盘可控**：一次性动作只能经 `ToolWriteScope` 写声明产物；交互式工具必须声明自己的预览/确认/Undo 边界。
4. **不碰共享源集**：工具写盘不得写入 BuildHash 闭包，除非该工具本身就是生成器且按生成链收尾。
5. **不新增静态可变状态**：执行请求/scope 显式传递。
6. **交互例外必须显式**：GM 页、绑定/编排/回写窗口不受 one-shot dry-run 约束，但必须在清单 `kind/safety` 如实声明，且不能绕过确认/备份。
7. **不在文档里记状态**：层设计只写契约；完成/未完成由 `Docs/施工进度/` 承担。

**未闭合面**（只列缺口，不排批次）：L2-C 资产写盘 → [写盘契约 §8](工具执行与写盘契约专项设计.md)；L3 窗口收编 → 本文件 §11。

## 11. 交互面（L3）

### 11.1 两种合法形态

| 形态 | 适用 | 契约 |
|---|---|---|
| `page`（内嵌） | GM 六页、动作页、轻量工具 | `IEditorToolPage`；Hub 驱动 OnShow/OnHide/Draw/Poll；写盘走 ToolWriteScope 或页面自己的安全边界 |
| `window`（外部窗口） | UI 工作台、烘焙工具箱 | Hub 只负责打开；窗口必须声明 `safety`（interactive/dry-run:unsupported/undo:none 或 asset），并提供结果摘要/关闭回调；禁止裸写资产 |

- UI 工作台宿主 `UiWorkbenchWindow` 为纯 IMGUI（零 Sirenix）；控件库/受控属性分区仍用 Odin（存量，不为统一重写 Odin）。
- 专用 prefab 回写窗口已退役；Play 内调参走 Prefab Stage/Unity 原生 Overrides，真实消费者出现再恢复。
- GM 页已是 `page`；`GmLocalChainPage` 编辑态自管心跳作为既有例外，后续若 Hub 增加编辑态节拍再迁移。

### 11.2 `ToolInteractionSession`（交互面边界）

- 打开窗口时创建；记录窗口内的资产/文件变更（路径/操作/摘要），不要求事先 dry-run；
- Hub 在窗口关闭后显示"本次变更摘要 + 可回滚项"；不支持回滚的变更明确标注；
- 交互窗口不得在无确认的情况下保存场景，不得绕过 Unity 序列化管线。

### 11.3 收编顺序与验收

1. 所有 `window` 工具补 `safety`/docs/结果边界，不改内部。
2. 绑定/回写窗口接入 `ToolInteractionSession`；Odin 编排保持外窗。
3. 评估烘焙工具箱是否改页件；内部多页交互收益不足时保留外窗。

验收：顶层菜单仍只有 `LiteGame/工具链`；所有窗口可从 Hub 打开并显示安全标签；有变更时关闭后显示摘要；无确认不自动保存场景；无 UI 业务重写；定向 EditMode/人工冒烟，全量 L2 夜间。

## 12. 非目标与后续

- 不把 UI 绑定/编排/回写窗口重写为页件；它们是 `window` 目标，后续可逐个迁移。
- 不重构 L2 执行链；只修 `eval_file --file` 与注册面。
- 不修与本层无关的存量债：`GmLocalChainPage` 编辑态自管心跳（§11.1 既有例外）。
- 不校验 `Packages/com.unity.pipeline` 的 9 处本地补丁内容；后续加 checksum/apply 校验。
