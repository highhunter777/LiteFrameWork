## 1. 目标

写一个 Unity Editor 烘焙器（`SimMapBaker`，落**烘焙工具箱第六页**），把**地图场景**（首图＝`Assets/Scenes/Arena01.unity`，纯地图形态）里**判定用碰撞代理几何 + 出生点**烘焙成 **Luban 地图数据**（烘器写 JSON 数据源 `Luban/Data/map.json`；`Luban/gen.bat` 产 `.bytes`——D6），供**服务端权威 Sim 与客户端预测**共用同一份 `SimMapData`（移动碰撞 + 射击遮挡）。

一句话：**判定地图从"硬编码 C# 常量"升级为"可烘焙、可数据驱动、两端单源"的 Luban 表**；多图＝多行，换图不换代码。

## 4. 架构与数据流

```
Boot.unity（常驻：GameEntry ＋ Main Camera/Brain）
 ├─ BattleRig.unity（加性·幂等——仅装配：Player Camera / Aim Camera 两台 vcam）
 └─ Arena01.unity（首图，加性·幂等——纯地图：Environment ＋ Directional Light
        ＋ MapCollision 代理 ＋ spawn_00..15 ＋ map_bounds；TrainingGround 保留为游戏内训练场，同形态）
        │  [烘焙工具箱第六页] SimMapBaker：采集→校验(fail-fast)→排序→毫米量化→digest→写 JSON
        ▼
Luban/Data/map.json ──Luban/gen.bat──▶ Assets/GameData/Config/Map/tbmap.bytes（域=Map，入判定面摘要）
        │
   ┌────┴──────────── 客户端装配 ─────────────┐   └──────────── 服务端装配 ─────────────┐
   │ ConfigService 装载 Map/tbmap             │   │ ServerTableLoader 直读同一 .bytes    │
   │ → IMapProvider（map_id 选行）            │   │ → ServerMapLoader → RoomConfig.Map   │
   │ → MapTableProjection.Project(row)  ◀─同一 .bytes ＋ 同一投影源码（源链接共编）─▶ 同 │
   │ → SimMapData → BattleContext(map)        │   │ → RoomRuntime.Map                    │
   ▼                                          ▼   ▼                                      ▼
RollbackSim(_map) / SimView            SimStep.Step(AuthSim, Map, …)
        └─ MovementSystem 去穿插 ＋ ShootingSystem LOS（SimRaycast）＋ 激光截停 ＋ 视野 A1（后置消费）─┘
```

**不变量**：两端从同一 `tbmap.bytes`，经**同一份** `MapTableProjection` 投影出 `SimMapData`；行内 `content_digest` 自证投影零漂移；`Map` 域入判定面 ⇒ 两端字节不一致被 `StartGame.ConfigHash` 拒局。

## 5. Luban 表设计

- **单表 `TbMap`（一图一行）＋ 嵌套 bean 列表**（不拆多表、不用联合键）：

| 类型 | 字段 |
|---|---|
| bean `MapObstacle` | `kind:int(0圆/1盒)`、`x:float`、`y:float`(底)、`z:float`、`radius:float`、`half_x:float`、`half_z:float`、`height:float`、**`surface:int`** |
| bean `MapSpawn` | `x:float`、`y:float`、`z:float` |
| 行 `Map`（表 `TbMap`） | `map_id:int`、`name:string`、`content_digest:string`、`ground_y:float`、`half_width:float`、`half_depth:float`、`obstacles:list<MapObstacle>`、`spawns:list<MapSpawn>` |

- **数据源＝Luban JSON**（`Luban/Data/map.json`——**文件名不带 `#`**：`#` 前缀触发按文件名自动注册，而 json 无法自描述模式；文本可 diff、嵌套数组天然、确定性由烘焙器掌握）。**单文件＝一条记录，内容为单对象**；多图时 input 改指目录（每图一文件）。
- **注册（批2 实证）**：经 `Luban/Defines/map.xml` 的 `<table name="Tbmap" value="map" input="map.json" mode="map" index="map_id" group="c,s"/>` ＋ 同文件 bean 定义（`map`/`mapobstacle`/`mapspawn`）。**本工程 Luban 4.11 的既有 10 表全部靠 `#` 前缀文件名自动注册**（表名＝`Tb`＋文件名词干，如 `#ltext.xlsx`→`Tbltext`）；`Data/__tables__.xlsx` 行在本版**不参与注册**（实证：改行名不影响生成、非 `#` 文件经行注册无效）——新表落法以本条为准，勿依赖元表行。
- **域布局**：`TableLayout.Files += "Map/tbmap"`（`gen_luban.py` 按 `TableLayout` 分域归位；装载路径同源）；`JudgmentDomains += "Map"`（域内表自动进运行期摘要——不依赖第二份人工清单）。
- **`tbmap.json` 形态（示例）**

## 6. 关键组件与契约

```csharp
// S0：Assets/LiteSim/Core/Scripts（零依赖，两端共编）
public static class SimMapBuilder {
  public static SimMapData Build(float groundY, float halfWidth, float halfDepth,
      SimObstacle[] obstacles, int obstacleCount, SimVector3[] spawns, int spawnCount); // 定长填充 + 越界/NaN fail-fast
}

  public static string CanonicalText(SimMapData map);  // InvariantCulture 固定字段序 + '\n'
  public static string Compute(SimMapData map);        // SHA-256 前 16 hex（同 RootMotion/CombatConfigDigest）
}

// 表面类型枚举（单源；1–10 对齐 KriptoFX Impacts 十档字母序——批D 表面分流取值参考）
public enum SimObstacleSurface : byte {
    Default = 0, Brick = 1, Concrete = 2, Dirt = 3, Foliage = 4, Glass = 5,
    Metal = 6, Plaster = 7, Rock = 8, Water = 9, Wood = 10,
}

// 地图场景标注件（Assets/LiteGame/App/MapBoundsMarker.cs）：挂场景对象 map_bounds——
// 烘焙器读 GroundY/HalfWidth/HalfDepth 单源；运行时零消费者（随地图场景入库）。

// 共享投影：Assets/LiteClient/Adapters/Serialization.Luban/MapTableProjection.cs

public static class MapTableProjection {
  public static SimMapData Project(cfg.map row);              // kind 0→Circle/1→Box；surface 0..10；越界 fail-fast
  public static SimMapData Project(cfg.Tables tables, int mapId);
  // 校验：数量 ≤ 上限、全 finite、Compute(map) == row.content_digest（不等→抛）
}

// 服务端：Server/RoomServer/ServerMapLoader.cs（仿 ServerTableLoader）
public static class ServerMapLoader {

  public static SimMapData LoadTableBytes(string configDir, int mapId);
```

**数量上限**：`MaxObstacles` 64 → **256**（D4）；`SimObstacle + Surface` 字段随 S0 批落地。

**烘焙器规则**（`Assets/LiteGame/Editor/Baking/SimMapBaker.cs`，工具箱第六页）：
- 采集根 `MapCollision`（缺失 fail-fast）；`BoxCollider→Box`、`SphereCollider→Circle`、`CapsuleCollider` 按方向定形；**`MeshCollider → 默认 fail**（策略可切 ReportOnly）
- `map_bounds` 对象必读（GroundY/HalfWidth/HalfDepth 数据化；缺失 ABORT——禁硬编码）
- 旋转仅接受 yaw∈{0,90,180,270}（90/270 交换 HalfX/HalfZ）；pitch/roll≠0 或非均匀缩放 → fail
- surface：代理名前缀 `surf_<surface>_`（如 `surf_concrete_box_01`）；无前缀＝Default；前缀后未知名＝ABORT
- 出生点：前缀 `spawn_`，按名 Ordinal 排序定 index；0 个 → fail；>16 → fail
- 确定性：固定 key 排序 ＋ 毫米量化（`Round(v*1000, AwayFromZero)/1000`）＋ `InvariantCulture` ＋ LF → **重复烘焙逐字节一致**
- 超上限：面积降序取前 256 ＋ **报告丢弃清单**（禁止静默截断）
- 产物：写 `Luban/Data/map.json`（单对象＝单记录；含 `content_digest`）**write-if-changed**（同字节不动文件）；**不手写 `.bytes`**；不自动跑 `gen.bat`（D6）；执行面 `All()→ABORT` 报告（工具箱统一纪律；JSON 走非 `.g.cs` 通道——`BakeTargets.WriteArtifact`，见《烘焙工具箱专项设计》§6）

**实施注（批3 落地口径）**：① 非均匀缩放＝**箱体尺寸机制**（场景代理以 transform 缩放定尺寸——箱体接受任意正缩放；球/胶囊因截面须为圆而要求均匀缩放，否则拒载）；② 超上限＝占位面积降序取前 256、**产物条目定序＝名 Ordinal**（选择序与输出序分离；丢弃清单点名进报告）；③ JSON 文本布局＝单对象、障碍/出生一条一行、数值 `"0.###"`（`SimMapDigest.Fmt` 提为 public 单源——规范文本与 JSON 共用一个格式化函数）；④ MeshCollider 策略 `MeshColliderPolicy{Fail=默认, ReportOnly}`（ReportOnly＝网格局部包围盒 8 角变换取世界 AABB＋逐件过近似报告）；⑤ 场景有未保存改动时报报告警示（烘焙含未保存状态，建议先存后烘）；⑥ 直调面＝`SimMapBaker.All()`（工具箱页）与 `Collect(root, out map, out json)`（不落盘——测试/对账用）；⑦ 首图实烘产物冻结为快照夹具 `TestMaps.Arena01()`（L1 `TestMapsTests` 锚定——改场景重烘须联动更新）。
