# 俯视角三维命中与爆头判定专项设计

> 状态：现行专项设计（批A Sim 三维化/批B 输入与协议/批C 表现与样式 分期；均未实施）
> 版本：0.1
> 更新日期：2026-10-06
> 适用范围：hitscan 由 2.5D 水平射线升级为三维射线、部位（HitBox）判定、爆头结算、爆头飘字
> Owner：玩法数值与战斗结算（Sim 侧）；客户端表现负责爆头档样式
> 依赖：[游戏业务系统总设计](游戏业务系统总设计.md) §1 射击行、[角色状态与动作专项设计](角色状态与动作专项设计.md) §7（瞄准口径）、[命中反馈与伤害数字专项设计](命中反馈与伤害数字专项设计.md) §2 事件源与§4 分层契约、[状态同步专项设计](../networking/状态同步专项设计.md)（输入面与回滚重放）
> 输入：鼠标屏幕点（准心位）＋相机射线；输出：三维瞄准向量、部位化命中事件、爆头档飘字

## 1. Current 与问题

- **Current（2026-10-06）**：命中判定为**严格 2.5D**——`SimRaycast` 只有 XZ 平面射线＋y 区间闸（`SimRaycast.cs`类注释「水平射线（2.5D：方向 XZ、原点带眼高 oy）」）；`ShootingSystem` 的出射线高度恒为 `CombatConfig.MuzzleOffsetHeight = 1.0f`（逻辑枪口高度）；爆头判据 `hitPos.Y >= hit.Pos.Y + CombatConfig.HeadHitLine(1.7f)`。
- **问题（用户裁决「平地也能爆头」）**：平地对枪时射线高度恒为 `射手Pos.Y + 1.0`，命中点Y 恒为 1.0，**与爆头线 1.7 差 0.7m，判据数学上恒不成立** ⇒ 平地永远打不出爆头。`CombatConfig.HeadHitLine` 注释已自记该限制（「同地平面对枪……永不达线，高差位才有爆头；俯仰轴归输入面扩展（AimY 未实现）」）。
- **根因不在判据，在瞄准向量丢掉了 Y 分量**：输入侧 `NewInputIntentSource` 把「屏幕点 → 相机射线 → ∩地面(y=0) 平面交点」的结果**只取 XZ 归一化**（`_groundPlane = new Plane(Vector3.up, 0f)`，`NewInputIntentSource.cs`）⇒ `SimInputFrame.AimX/AimZ` 恒为水平向量，射线方向无 Y 分量。
- **参考口径（外部对标）**：《逃离鸭科夫》为俯视角，其爆头**按命中部位（HitBox）判定而非随机概率**——玩家实证「只要准星大概在敌人头上左键开火就能爆头，不管有没有右键开镜」，伤害机制 wiki（引源码 `Health.cs`）记「**暴击时为头部护甲，未暴击时为身体护甲**」，即命中部位决定结算分支。**本设计借鉴其「准心位置直接决定是否爆头」的可控性**，不引入俯仰输入轴。

## 2. 口径裁决（2026-10-06 用户定案）

| 口径 | 裁决 | 影响 |
|---|---|---|
| 触发方式 | **准心位置决定**（借鉴 Duckov 部位判定），**不新增俯仰输入轴** | 玩家把准心移到目标头部即爆头；可控、可复现 |
| 部位模型 | **单一圆柱按 Y 分带**（沿用 `HitscanHeight` 身位，头部带为顶部子区间） | 不引双 HitBox/不引骨骼；身位常量仍唯一 |
| 爆头带| 命中点 Y ∈ `[HeadHitLine, HitscanHeight]`（**带判据**，非 `>=` 单边） | 修「高于身高段不算任何部位」的漏洞 |
| 飘字样式 | **敌我方统一**：普通白字、爆头红字 | 不按造成/承受染色（偏离 `DamageNumberStyleResolver` 现有 4 档，见 §6） |
| 协议 | `SimInputFrame` 加 `AimY` ⇒ **进 checksum ⇒ 重录基线** | ★ 触发 `scripts/codegen/gen-build-hash.py` |
| 分期 | 分 3 批（Sim / 输入与协议 / 表现） | 批A 纯逻辑、L1 可完整覆盖，不碰玩家可见项 |

## 3. 三维瞄准向量（批B：输入与协议）

### 3.1 采集侧口径

**从「地面交点 XZ」改为「相机射线 3D 方向」**——这是本设计的核心改动，单点即通：

```
现状：屏幕点 →相机射线 → ∩地面(y=0) → p → Aim = normalize(p.xz - muzzle.xz)   // Y 恒 0
改为：屏幕点 → 相机射线 → normalize(ray.direction)                             // Y 保留
```

- 玩家可控性来源：屏幕点上下移动 ⇒ 相机射线仰角变化 ⇒ 远距离目标处射线抬高 ⇒ 可命中头部带（俯视角下准心抬高即射线抬高，与 Duckov「准心在头上就爆头」同构）。
- **不新增输入面**：仍只读`Mouse.current.position`；`MouseScreenPosition`（准心/HUD 消费面）语义不变。
- **零瞄准方向退化**：射线与地面无交点（相机近水平且准心在屏幕上方）时沿用**上一次有效 3D 方向**，并置「本帧无解算」标志（与现有 `_hasAimPoint` 口径一致）——不取零向量（零向量会让 `InputSystem` 不派生 Yaw，破坏既有语义）。

### 3.2 输入帧与协议

- `SimInputFrame` 加 `public float AimY;`（**长度 ≤ 1 由采集侧保证**，与 AimX/AimZ 同约束）。
- **进 `SimChecksum`**：瞄准向量参与命中判定 ⇒ 属确定性状态（同 `FireStanceFrames` 先例），故进公共 checksum ⇒ **两端基线须重录**。
- `InputPacker` / proto `Input` 消息同步加字段（**两端同帧同值**——《状态同步专项设计》§输入面纪律）；`InputGate` 的有限性校验纳入 `AimY`（`float.IsFinite`）。
- `InputHistory` / 回滚重放：瞄准向量逐帧记录（既有 `AimX/AimZ` 机制扩展，无新增结构）。

### 3.3 与相机/准心的关系

- 准心仍贴鼠标（`BattleCrosshairDriver` 读 `MouseScreenPosition`），**不锁屏心**（ADS 锁屏心裁决不变——瞄准相机同轴仍未接）。
- 相机 `AimOffsetCurve`（构图 z 偏移随瞄准点）与 ADS 混合**不因AimY 改动**；俯仰化后若构图观感异常，另立观感批（不在本设计范围）。

## 4. 部位化命中（批A：Sim侧）

### 4.1 `SimRaycast` 三维化

- 射线方向由 `(dx, dz)` 扩为 `(dx, dy, dz)`（单位向量）；原点仍带 `oy`（逻辑枪口高度 `MuzzleOffsetHeight`）。
- **实体圆柱求交改为三维**：与竖直圆柱（半径 `HitscanRadius`、高`HitscanHeight`）求交，**返回命中点 3D 坐标**（现返回 `t`，本批扩为 `t` + 命中点）。
- **确定性纪律**：全程 `SimMath`（融合安全累积＋软件 sqrt）——**跨运行时逐位确定是硬约束**（`SimRaycast` 类注释既有纪律），新增的 `dy` 项运算必须同样走 `SimMath`，不得用 `Mathf`/`Math`。
- **障碍求交**：2.5D 障碍（圆/盒 + y 区间闸）**口径不变**——关卡障碍均为地面级盒体，三维化收益为零而破坏面大（`SimMapData` 语义与 `MovementSystem` 碰撞共用同一图）。**仅实体圆柱三维化**。

### 4.2 部位判定与爆头

- 部位带（沿用身位常量，**头部线是唯一新数值**）：
  - 身体：`y ∈ [目标Pos.Y, 目标Pos.Y + HeadHitLine)`
  - 头部：`y ∈ [目标Pos.Y + HeadHitLine, 目标Pos.Y + HitscanHeight]`
  - 命中点高于 `+HitscanHeight` ⇒ 掠过（不入部位，见 §4.3 修订记录）
- 爆头判据：命中点 Y 落在**头部带内** ⇒ `dmg <<= CombatConfig.HeadshotDamageShift`（**位级精确不变**），且事件写`FrameEventKind.Crit`。
- **事件**：`FrameEventKind.Crit`（枚举已预留、`ShootingSystem` 从不写；**不进 checksum、不进快照**，回滚重放天然正确——§2 已核实 `SimWorldState` 事件缓冲同属非校验面）。下游**链路已通**：`HitFeedbackDispatcher.Resolve` 传 `Kind` → `BattleDamageNumberDriver` 吃 Crit → `DamageNumberAggregator` 已有 `e.Crit |= crit` 粘滞。**View 侧零改动**。
- **`HeadHitLine` 语义收紧**：由「≥ 1.7 判爆头」改为「头部带下沿」，需同步复核其注释与既有 `HeadshotTests` 口径（§7 批A 红线）。

### 4.3 与既有 2.5D 判定的并存

- **移动/障碍碰撞不动**：`MovementSystem` 复用 `HitscanRadius/HitscanHeight` 作身体圆柱（`MovementSystem` 类注释「一套身体两种用途」），三维化**只改 hitscan 命中**，不动移动解算——避免同一身位常量在两条链路分叉。
- **俯仰轴仍缺**：`AimY` 由采集侧从相机射线派生，**不是玩家可控的独立俯仰轴**（不存在"抬头/低头"按键）——俯视角下的部位瞄准由**准心位置**表达（§2）。若后续要独立俯仰玩法（如狙击镜抬高），另立专项。

## 5. 相机距离缩放与观感

- 飘字 `CameraReferenceDistance` 距离缩放口径**不变**（爆头红字仍走同一缩放）——观感批再调。
- **爆头档视觉加强**（批C）：红字＋字号放大＋可选描边；具体档值走 `IDamageNumberStyleResolver`（§6），**表现参数禁入 `CombatConfig`**（digest 源集纪律）。

## 6. 样式面（批C）与现有 4 档的偏离

现有 `DamageNumberStyleResolver` 为 4 档（造成白/造成暴击橙/承受红/承受暴击深红），**按造成/承受染色**。本设计裁决**敌我方统一**（普通白、爆头红），故：

- `DamageNumberStyleResolver.Resolve(value, role, crit)` **忽略 `role`**（保留参数以维持接口不变——样式编辑器批落地后换 token 来源，见[命中反馈与伤害数字专项设计](命中反馈与伤害数字专项设计.md) §4.2）。
- `CausedWhite/ReceivedRed` 等 4 个常量**收敛为 2 档**（普通/爆头）；`HitLocalRole` **仍进合并键**（`(TargetId, Role)`）——敌我方**样式**统一不意味**合并**统一（我方承受与造成是两笔账，见 §4.2 引用文档 §3）。
- **既有 EditMode 用例需同步**：`BattleDamageNumberEditModeTests` 中断言「承受染红」的用例将失效（该口径本设计裁决推翻）——按§7 批C 红线改。

## 7. 批次与验收

| 批 | 内容 | 验收 | 红线联动 |
|---|---|---|---|
| **A Sim 三维化** | `SimRaycast` 实体三维求交＋`SimInputFrame.AimY`＋`ShootingSystem` 用 3D 方向＋爆头发 `Crit`＋部位带判据 | **L1**：`HeadshotTests` 扩平地远距爆头/近距不爆头/高差位回归；`SimChecksumBaselineSpec` 重录 | ★ **动 `LiteSim/Core` ⇒ `python scripts/codegen/gen-build-hash.py`**；确定性逐位；`SimMath` 纪律 |
| **B 输入与协议** | `NewInputIntentSource` 3D 方向＋`InputPacker`/proto 加 `AimY`＋`InputGate` 有限性校验 | L1（输入面往返/确定性）＋ 两端同帧同值 | ★ **协议变更 ⇒ 两端重录基线**；`PredictedButtons` 不含连续位 |
| **C 表现与样式` | `DamageNumberStyleResolver` 2 档（敌我方统一、爆头红）＋爆头飘字观感 | EditMode 同步＋ 手测（爆头红/普通白） | 样式参数**禁入 `CombatConfig`**；`BattleDamageNumberEditModeTests` 染红用例按裁决改 |

**分期依赖**：批A 独立可交付（纯 Sim + L1）；批B 使批A 的 3D 方向在真实对局可达；批C 依赖批A 的 `Crit` 事件。**批A 完成后 L1 即能验证「平地爆头」是否成立**，是本设计的最小验证闭环。

## 8. 总验收口径

- **平地可爆头**：同地平面对枪、准心置于目标头部带 ⇒ `Crit` 事件＋爆头倍率（批A L1 锁）。
- **可控性**：爆头与否**仅由准心位置决定**（无随机、无俯仰输入轴）——借鉴 Duckov 部位判定，玩家可复现。
- **协议/身份**：`AimY` 两端同帧同值；基线重录后 BuildHash 一致。
- **表现**：普通白字、爆头红字（敌我方统一）；爆头档放大。
- **无回归**：移动/障碍碰撞 2.5D 口径不动；`SimMath` 逐位确定；既有 `HeadshotTests` 高差位/死亡守卫用例绿。
