# 命中反馈与伤害数字专项设计

> 状态：现行专项设计（设计先行，未施工）
> 版本：0.1
> 更新日期：2026-10-06
> 适用范围：命中分发（帧事件表现路由）、自研伤害数字、DNP 技巧炼化口径、渲染件升级路径
> 维护责任：客户端表现
> 依赖：[战斗美术资源参考](战斗美术资源参考.md)（三包裁决）、[角色状态与动作专项设计](角色状态与动作专项设计.md) §5（事件口径）、《动作与特效专项设计》§2.3（服务间不互相调用）、[动画模块专项设计](../client/animation/动画模块专项设计.md) §8（帧事件接缝）

## 1. Current 与边界

- **Current（2026-10-06）**：`FrameEventKind` 产出 `Fire/Hit/Death`（`Crit/Explosion` 枚举预留未产出）；`SimView` 静默门 + `EventSink` 已就位（回滚重放/和解段丢弃一次性副作用）；动画消费者已接 `Fire`（`CharacterLocomotionDriver` 构造自订阅）；命中特效/音效/受击死亡动画/伤害数字均未接。**本文全部未施工**——批次见 §7。
- **范围**：命中分发器（表现层事件路由）＋伤害数字系统（纯件＋驱动＋样式面）。
- **边界**：命中判定归 `LiteSim`（`SimRaycast` 单源）；特效/音效本体归 `VfxService`/`AudioService`（选择逻辑经分发器，服务契约归《动作与特效专项设计》）；动画迁移细节归动画专项。伤害数字属高频事件——**永不过 Lua**（归档《UI性能优化规划》事件过桥硬规则）。表现层只读 Sim 事件，禁回写。

## 2. 事件源与数据（零 Sim 改动起步）

`FrameEvent { Kind, EntityId=主体, OtherId=对象, Value=数值, Pos=位置 }`——伤害数字所需字段当前已齐备：

| Kind | 产出 | 释义（主体/对象/数值/位置） | 消费现状 |
|---|---|---|---|
| Hit | `ShootingSystem` | 命中目标/射手/伤害量/命中点 | **未接**（本文首个消费者） |
| Death | `ShootingSystem` | 死者/击杀者/—/死亡位置 | 未接（受击/死亡动画归动画批） |
| Fire | `ShootingSystem` | 开火者/0/—/射线原点 | 已接（枪口特效/开火动画） |
| Crit | 预留未产出 | 暴击目标/射手/伤害量/命中点 | 暴击**档位样式先行**，数据源随 P1 武器战斗批就位 |
| ObstacleHit | 枚举不存在 | — | 扩展批（§7 批D：弹孔/着墙） |

- **静默门**：`SimView.OnFrameEvents` 在回滚重放/和解段丢弃事件（"一次命中只响一次"是结构性保证）——伤害数字**不自行防重**，实现者不得在消费者内再加去重。
- 命中点 `Pos` 为 Sim 空间，消费侧经 Sim→世界换算（与 `SimView` 同式）。

| 口径 | 裁决 | 影响 |

## 4. 分层契约

### 4.1 命中分发器 `HitFeedbackDispatcher`（App/Presentation；装配 `ProcedureBattle`）

- **唯一持有** `SimView.EventSink`（单一路径、转发序确定）；逻辑帧边界批量转发（静默门之后）。
- 事件前解析进上下文 `HitFeedbackContext`：`kind / 槽位（实体 Id 解析）/ 对方槽位 / 命中点世界位 / 数值 / 本地角色（造成/承受/旁观）`。
- 消费者面（表现扩展点）：
  - 向既有动画缝 `IFrameEventAnimationConsumer` 转发——**接缝接口不变**，`CharacterLocomotionDriver` 的直订阅收编为分发器转发（批A 一处装配改动，帧事件开火全链 EditMode 用例回归把守）；
  - 新增 `IHitFeedbackConsumer`（消费 `HitFeedbackContext`）——**伤害数字为首个消费者**；命中特效/音效/受击死亡动画随各自批注册，注册面即扩展点（框架件零改动）。
- 分发器不持业务状态、不做消费者裁决（本地过滤在伤害数字消费者内做——特效/音效对旁观事件同样可见，过滤不是分发器职责）。

### 4.2 伤害数字核心纯件（`Assets/LiteSim/View/DamageNumbers/`，**文件零引擎引用** → L1 经源链接直测，`InputService` 先例）

- **聚合器**：同目标合并窗口（窗口内命中累加＋重置淡出——连击合并语义，即 DNP `CombinationSettings` 的自研对应物）。窗口/初速/淡出等**表现参数落纯件常量或样式档位**，**禁入 `CombatConfig`**（BuildHash/digest 源集，表现参数不得搅联机身份）。
- **轨道数学**：初速/推挤/插值/淡出/按值缩放/抖动 → 每渲染帧输出 `(pos, alpha, scale)`；参数表驱动、可确定性测试。
- **样式解析 `IDamageNumberStyleResolver`**：值/暴击/承受 → 档位（颜色/字号/格式化/缩放）；**初版常量表实现**，样式编辑器批（《UI编辑器工具专项设计》§3）落地后换 token 来源——**接口不变，消费者零改动**。
- **格式化**：位数/缩写（千/K 简写语义自研）。

### 4.3 渲染驱动 `BattleDamageNumberDriver`（App/Presentation；`BattleLaserDriver` 同款纪律：sealed/IDisposable/只读）

- 首版渲染件＝**池化世界空间 TMP**（`GameObjectPool` 先例）；静态文本不逐帧 layout；淡出走 TMP 顶点色标准技巧（`UpdateVertexData`），零 DNP 代码。
- 跟随：目标槽位视图位置；实体 despawn/视图回收**降级到最后位置不悬挂**（Entity 关闭面先例）。
- 预算：同屏上限常量（起始 24）；超限淘汰最旧并**记日志不静默丢**（UiFx 先例）。
- 相机距离缩放：驱动读主相机参数换算（本工程相机，适配精确——DNP 是给 FPS 猜的）。

### 4.4 样式面

- 颜色/字号档位唯一来源＝`IDamageNumberStyleResolver`；样式编辑器落地前为常量表、后换 token（§4.2）。
- DNP 炼化资源沿[战斗美术资源参考](战斗美术资源参考.md) §7.3：`Sprite Overlay.shader` 为 `ZTest Always`（HUD 叠加口——世界空间飘字走正常深度，该 shader 仅归置参考不直用）＋克制选风格字体；归置动作归观感批（批C），走 pipeline CLI。

## 5. 渲染件三级升级路径（留作扩展，不预建）

| 级 | 形态 | 触发判据 |
|---|---|---|
| 首版 | 池化世界空间 TMP 直渲 | 默认——8 人对局＋同屏预算下 Profiler 无压力即止 |
| 升级1 | **TMP 网格提取**：`ForceMeshUpdate → textInfo.meshInfo → 裸 Mesh + MeshRenderer + 顶点色淡出`（DNP 同款技巧，§6） | Profile 证据：TMP 对象/layout 开销或 GC 显著 |
| 升级2 | **真合批**：自研 MeshBuilder＋数字图集（0-9/+/%），N 个活跃数字拼单 Mesh 单材质 **1 draw call**（超越 DNP——DNP 无跨数字合批） | Profile 证据：draw call/SetPass 成瓶颈（100+ 同屏需求） |

架构保证：驱动只消费轨道数学输出 `(pos, alpha, scale)`——渲染件是**可替换实现**，升级不动纯件/分发器/样式面。

## 6. DNP 技巧炼化口径（读码实证 2026-10-06，`DamageNumber.cs`/`DNPUpdater.cs`）

- **弃用裁决不变**：运行时不引入、不拷源码（DNP 是 MonoBehaviour＋Inspector Settings 形态，硬搬破坏驱动/纯件结构）。
- **可炼技巧**（Unity 公开 API 标准用法，非 DNP 专利）：

| 技巧 | 源码事实 | 炼化落点 |
|---|---|---|
| TMP 作"文本→网格"后端 | `textMeshPro.ForceMeshUpdate → textInfo.meshInfo → CopyMeshInfo` 裸 Mesh，随即停用 TMP | 升级1 |
| 顶点色驱动淡出 | `mesh.GetColors` 逐顶点 alpha，不动物料属性 | 不破 SRP Batcher/不产材质实例；升级1/2 通用 |
| 双渲染器交叉淡入 | `meshFilterA/B` 同 mesh 双材质，淡入完关 B | 仅描边/发光双层需要（观感批评估） |
| 共享 tick 向量 | `DNPUpdater` 80Hz 分桶＋billboard 向量一帧一算全数字共享 | 驱动 Tick 内共享相机基向量 |
| 连击合并语义 | `CombinationSettings`（逻辑合并，非渲染合批） | §4.2 聚合器 |

- **纠偏记录**：DNP **无跨数字渲染合批**——每数字独立 `MeshRenderer` 独立 draw call（淡入期双渲染器＝2 个）；其 "Combination"＝逻辑合并。真合批是本项目升级2 的超越点。

## 7. 批次与验收

| 批 | 内容 | 验收 | 红线联动 |

## 8. 总验收口径

- 功能对齐 DNP §4.4 清单（**碰撞项除外**——俯视角垂直上浮＋合并窗口已消解叠字，不复刻 2D 物理碰撞）。
- 口径生效：本地造成/承受过滤＋承受染红；世界空间；一次命中一次飘字（静默门结构性回归）；despawn 不悬挂；预算超限有日志。
- 观感定档以 DNP demo 对照为准（差距是调参时间，不是能力差距——§5 首版止步判据由 Profiler 说话）。
