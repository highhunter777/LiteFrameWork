## 1. 现行链路病灶（重规划的理由）

| 病灶 | 事实 | 后果 |
|---|---|---|
| **瞄准双口径并存** | 协议同载 `AimX/Y/Z`（方向 3 float）+ `AimPointX/Y/Z`（目标点 3 float）；采集侧两套都产、判定侧主路（点）+ 回退路（方向）两个分支 | 同一件事两份事实，"方向与点同源产出不会不一致"靠纪律维持而非结构保证 |
| **锚点分叉** | 采集侧不敢用 `MuzzleOrigin`（Yaw 反推闭环自激，原地摆头真缺陷），改用"本体 XZ + 枪口高度"；服务器用真枪口 | 两侧锚点差 ≤0.4m 平行差，靠 AimPoint 口径糊住 |
| **相机轨道补丁链** | `CinemachineInputProvider` 鼠标直驱轨道 ⇒ 腰射冻结三笔提交（SimView 锁存 → 回退 → 轨道输入门控）+ `AimHoldGate` 滞回 | 相机语义散落在 ProcedureBattle/SimView/适配器三处，每次修正都前一笔的补丁 |
| **文档漂移** | 旧爆头专项 v0.2 记"批B 未实施/HeadHitLine=1.7"，其后又记 1.55、1.395（比例 0.775） | 文档不再是可信事实源；头部带下沿现为**比例派生**（`HeadBake.Ratio`，导出值 0.805 ⇒ 1.449 m），重调走 `HeadHitLineTuner` |

## 2. 目标链路（单口径、单向无环）

```text
鼠标屏幕点 → 相机射线（固定俯视 ⇒ 必交世界）
  → SimRaycast.RaycastEntities（本地预测世界，跳过自己）──命中──► P = 交点（带高度）
  → 未命中 → 地面 y=0 平面 ──────────────────────────────────► P = 地面点
  （障碍刻意不入采集侧：截停是权威判定的事——准心对着墙后敌人，解出的仍是打敌人的弹道）
  ⇒ AimPoint（唯一瞄准表示，3 float 上行）

服务器/预测同式派生：
  Yaw（射击语境）= Atan2(P − 本体XZ)；水平距离 < ε 不派生（保持上帧）
  弹道 d = normalize(P − MuzzleOrigin(Pos, Yaw))；|P − muzzle| < ε ⇒ 无效开火（只写 Fire，无命中）
  命中 = SimRaycast 实体三维圆柱 + 障碍 2.5D 折算取近（不变）
  爆头 = AimPoint.Y 落头部带（归属校验后，§5）

表现同源：
  激光端点 = 同一弹道被 SimRaycast 截停点（与子弹同终点）
  准心 = 鼠标屏幕点（零网络面）
  相机 = 固定视角维持现状（无旋转；§7），移动输入按相机 yaw 恒等映射
```

**单向无环不变式**：P 由"屏幕射线 ∩ 世界"产生，**不读 Yaw** ⇒ `P → Yaw → 枪口 → d` 是单向链，不存在 `Yaw → 枪口 → 瞄准向量 → Yaw` 的正反馈（历史摆头缺陷的结构性根除，不再靠"采集侧换锚点"规避）。

## 3. 瞄准单口径：AimPoint

- **零值约定**：`(0,0,0)` = 无点（沿用现行 `ShootingSystem.hasPoint` 判据）。固定俯视下恒有点；唯一无点路径是相机未就绪/数值边缘——沿用上次有效点。
- **采集侧不产方向**：`NewInputIntentSource` 只解算并缓存 AimPoint；删除 `_aimX/_aimY/_aimZ` 方向缓存与三维长度闸（方向不上行，闸随之消亡）；`IntentVectorLimit` 三维重载退役。
- **AI/沙盒/测试**：直接构造 AimPoint（目标位置 + 期望高度），不再构造方向——比方向口径更直白。
- **朝向派生**：`InputSystem` 射击语境（瞄准 ∨ 开火帧 ∨ 开火驻留窗内）下 `Yaw = Atan2(P.Z − Pos.Z, P.X − Pos.X)`；`P` 水平距本体 < ε 或为零值 ⇒ 不派生（保持上帧，与现行"零向量不派生"同语义）。

## 5. 判定链（接管旧爆头专项，口径不变登记）

以下口径**已交付并 L1 覆盖**（`Tests/LiteSim.Core.Tests/HeadshotTests.cs`），本方案不改数学、只改输入面：

- **命中谁**：子弹射线 `muzzle → P` 经 `SimRaycast`——实体三维圆柱最近者 + 障碍 2.5D 折算（`RaycastObstacles3D`）取近；障碍更近截停（子弹不穿墙）；并列实体优先。
- **爆头判谁**：判定高度 = `AimPoint.Y`（"准心指哪按哪判"），非子弹近弧交点高度。**归属校验**：P 水平距命中目标 ≤ `HitscanRadius` 才用 `P.Y`，否则回退子弹交点高度。
- **双柱判定几何（2026-10-07"爆头柱/非爆头柱"裁决）**：实体命中形状 = **竖直堆叠的两根圆柱**——身体柱 `[0, HeadHitLine) × HitscanRadius(0.45)`（普通命中）＋ 爆头柱 `[HeadHitLine, HitscanHeight] × HeadshotRadius`（Crit）。分界线 `HeadHitLine = HitscanHeight × HeadBake.Ratio`（比例单源随烘焙身高缩放）；**命中爆头柱即 Crit**（`ShootingSystem` 按命中高度 ≥ 分界判定，无事后水平闸）。**为什么几何化**：AimPoint = 相机射线 ∩ 命中形状的表面点——单柱下瞄头的射线在宽柱面取点（水平距恒 ≈柱径），任何事后水平闸都会拒掉合法瞄头点（实测"准心瞄头打中却是白字"；单柱时代视差还把胸腹判定高度抬进带内——"爆头区过大"的结构性根源）；几何化后瞄头的射线穿透肩侧空隙在爆头柱面取点，所见即所判。上段 `[HeadshotRadius, HitscanRadius)` 环状空隙按裁决不可命中（装饰性肩沿/发侧放过）。爆头 `dmg <<= 1`（×2）。**重调 = 调带工具**：`HeadHitLineTuner`（菜单 `LiteGame/调整爆头带`——编辑器 Scene 拖黄圈/锚点对照/半径滑杆，导出 `HeadBake.g.cs` 双值）＋**测试模式实时预调**（GM 面板双滑杆写 `HeadHitLineDevOverride`/`HeadshotRadiusDevOverride` 开发三宏覆写——`SimRaycast` 求交与身位可视化同读 `HeadHitLineLive`/`HeadshotRadiusLive`，对局内实弹试 Crit 档后导出；release 恒 = 导出值）。
- **事件**：爆头发 `FrameEventKind.Crit`、普通发 `Hit`；帧内瞬态，不进 checksum/快照。
- **回溯契约**：`ShootingSystem` 不改时序、只读输入写 Cmds/Events/RngState/开火窗；回溯用静态地图 + 历史帧位；回调方还原 RngState。
- **接触容差**：命中圆闸的垂距含 `SimRaycast.TouchEpsilon`（**`1e-5f` m ＝ 0.01 mm**；垂距改为直接分量计算、去 |m|²−b² 消减）——AimPoint 是相机射线与同一圆柱的交点、**落在表面上**，命中线数学上必经表面；无容差时擦边（c2−R²≈0）会被 float32 舍入随机翻成"超半径"整发拒掉（实测 18–24m 处虚假差值 1.7e-5~7.8e-5 ⇒ 12/1566 例"瞄着柱轮廓边打不中"）。回归钉子 `AimParallaxHitTests.可见面全采样_弹道必命中`。
- **确定性**：全部走 `SimMath`；RngState 仅真实命中消费。
- **身位双半径（判定宽容 / 物理体宽解耦）**：**命中柱半径 = 判定宽容裁决常量 0.45**（战斗姿态视觉轮廓实测：下半身 0.27~0.43 / 上半身 0.6~0.8（手臂/持枪/长发）——0.45 覆盖肢体与站姿、放过枪尖与长发尾）；**物理半径 = 烘焙值**（`BodyBake.g.cs`，采样 prefab `CharacterController`；重烘 = `BodyCylinderBaker`），供移动去穿插/视图 CC；`HitscanHeight` = 烘焙身高（站姿与判定体上沿一致），头部带下沿 = `× HeadBake.Ratio` 比例单源（**当前导出值 `Ratio = 0.805` ⇒ 下沿 = 1.8 × 0.805 = 1.449 m**，随重烘自动缩放）。表列（tb_combat_num 的 hitscan_radius/height）已退役——命中宽容度恢复表化时回归该列。EditMode 对账用例卡"改 CC 忘重烘"。
- **逻辑枪口常量 = 烘焙值**（`MuzzleBake.g.cs`：采样 prefab `Weapon_Rifle/Muzzle` 锚点 @ 参考姿态 AimIdle t=0——射弹时刻视觉姿态单族（瞄准=AimIdle；腰射开火窗 FireIdle 亦以 AimIdle 填窗）；重烘 = Editor 工具 `MuzzleOffsetBaker`，美术调锚点/换枪后重跑）。三常量进 `CombatConfigDigest`；tb_weapon 落表时转 per-weapon 列（表化后仍为静态常量——动画枪口不进判定）。
