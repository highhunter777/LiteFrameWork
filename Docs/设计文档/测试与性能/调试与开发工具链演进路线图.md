## 1. 评估框架

工具链的专业度不看工具数量，看四条闭环是否闭合，以及低成本通路是否可信。

| 判据 | 核心问题 | 专业级表现 |
| --- | --- | --- |
| **可复现** | 线上/测试中的问题能否离线重现？ | 种子、输入、配置、构建身份可记录；一条命令重放；首分歧帧可定位 |
| **可观测** | 是否不用猜就能知道发生了什么？ | 结构化日志 + 关联 ID；崩溃/错误有现场；关键路径有指标；性能有基线 |
| **可操控** | 能否不改代码就验证分支？ | 开发包控制台/GM/远程配置；弱网、时间、状态可注入；开关可运行时切换 |
| **可回归** | 修过的问题会不会回来？ | 用例、回放、黄金基线覆盖；CI 能挡住回退；flaky 可隔离 |
| **低成本通路可信** | 便宜的验证方式是否可靠？ | 内环/中环工具稳定、可诊断；失败不靠“再打一次包”绕行 |

### 1.1 三层反馈环

| 环 | 形态 | 目标反馈时间 | 适用改动 |
| --- | --- | --- | --- |
| 内环 | Editor Play + 进程内服/本地 Room + 热重载 | 秒级～1 分钟 | 表现、手感、UI、纯逻辑 |
| 中环 | 可调试 Player + 远端内容 + 本地/云端 Room | 小于 5 分钟 | 联机行为、内容/配置、Lua、网络路径 |
| 外环 | release IL2CPP + 云部署 + 真人对局验收 | 按批次，不按 micro-fix | AOT/IL2CPP 差异、真网络、跨机、发布验收 |

工具链的核心度量是 `change-to-verified`（改完到拿到可信结论的时间）与 `rebuild-to-change`（每个改动触发的重建次数）。专业级不是把外环压到最快，而是**让改动落在正确的环**：能用内环/中环回答的问题，不进入外环。

## 2. 现状判断

### 2.1 可复用的地基

- **确定性诊断内核**：`SimRunRecord` 定义完整复现数据（种子、初始世界、逐帧输入、逐帧 checksum），`SimReplayRunner` 能重跑并定位首个分歧帧、产出字段级 diff（[SimRunRecord.cs:7](../../../Assets/LiteSim/Core/Diagnostics/SimRunRecord.cs)、[SimReplayRunner.cs:129](../../../Assets/LiteSim/Core/Diagnostics/SimReplayRunner.cs)）。这是回放、desync 报告与自动复现的地基。
- **联测路径分层**：A 进程内本地服、B 真 RoomServer、C 全链路、D 云主机，各自写明适用与不适用（[07-本地联测.md:13](../../项目说明/07-本地联测.md)）。
- **测试资产**：L1/L3 规模过千；`HeadlessRunTests` 以真实 UDP/KCP 起内嵌 RoomServer + 双无头客户端对跑，覆盖短跑与长跑门控（[HeadlessRunTests.cs:18](../../../Tests/LiteNet.Tests/HeadlessRunTests.cs)）；IEEE 黄金基线与 CI 防篡改校验（[ci.yml:40](../../../.github/workflows/ci.yml)）。
- **纪律与生成物**：DisciplineScanner、BuildHash、Luban/proto、生成器工具箱构成“单源 + 门禁”的骨架；共享源不一致由 Join 握手拒绝（[JoinAdmissionGate.cs:141](../../../Server/RoomServer/Application/JoinAdmissionGate.cs)）。
- **调试面**：`Log` 门面 + `LogTag` + `ErrorCount`、DevHUD、`CommandCenter`、GM HTTP 端点、`DiagTrace` 已有统一入口与审计口径。
- **CI**：GitHub Actions 覆盖 L0 + L1 双平台、基线防篡改与 L3，L2 走夜间/自托管（[ci.yml:82](../../../.github/workflows/ci.yml)）。

### 2.2 结构性低效的根因

1. **内容内嵌**：Player 走 OfflinePlayMode，读 StreamingAssets/yoo 内置包；Host/Web 下载与网络更新路径未实现（[AssetService.cs:15](../../../Assets/LiteClient/Adapters/Content.YooAsset/AssetService.cs)、`:76`）。因此表值、Lua、场景、Prefab、美术的改动全部落到 Player 重打。签名候选的发布→接受→激活→回滚链路尚无端到端证据（[热更与内容发布专项设计.md:31](../客户端/内容/热更与内容发布专项设计.md)）。
2. **AOT 无脚本层**：纯客户端 C# 走 IL2CPP；测试 exe 也是 IL2CPP，`reload_file` 仅 Mono + `[CodeReload]` 可用。日常验证被放在迭代最慢的载体上。开发通道只传 `Development + DetailedBuildReport`，未传 `AllowDebugging`（[build-player.py](../../../scripts/build/build-player.py)），Player 不能 attach 脚本调试器，也没有控制台。
3. **建包单体化**：`build-player.py` 把 L0 门禁、BuildHash 复算、`deploy.args` 烘焙、内置 bundle（轮询上限 20 分钟）、dry run、IL2CPP（脚本按 10-30 分钟估算）与产物校验串成一条链（[build-player.py](../../../scripts/build/build-player.py)、`:271`）。没有“改动类型 → 最小重建集”的预检，改一个 Prefab 和改共享源走同一条重链。
4. **验证走错环**：文档把 A/B 定为日常（[07-本地联测.md:13](../../项目说明/07-本地联测.md)），但发版矩阵仍把纯表现/Lua/Prefab/美术归为 exe 重打包（[11-联机测试流程.md:35](../../项目说明/11-联机测试流程.md)）。外环验证有正当理由（真网络、AOT 差异），但不应按 micro-fix 频率触发。
5. **低成本通路可信度不足**：L0 被本机绝对路径依赖卡红（[manifest.json:26](../../../Packages/manifest.json)）；`run_tests --mode playmode` 同步模式返回 0 例、`editor_status` 超时、CLI 实例发现失效等工具面摩擦需要 HTTP 直连或异步轮询绕行。便宜路径不可靠，人就会默认走贵而可信的路径。

### 2.3 一句话判断

**确定性内核的专业度高于交付与观测外围**：难的部分（确定性、重放数据模型、无头对跑、黄金基线）在，接线与产品化不在。当前不是“工具不够多”，而是“已有能力没有接到生产链路，缺失的能力没有按环补齐”。

## 3. 调试工具链目标形态

### 3.1 回放与 desync 诊断

- **目标**：每局可记录、错误/分歧自动落盘、一条命令离线重放、直接给出首个分歧帧与字段 diff；回放文件带构建身份与配置摘要，能跨运行时对账。
- **现行缺口**：`SimRunRecord`/`SimReplayRunner` 无序列化与自动采集面，生产与测试均无调用方（[13-调试手册.md:386](../../项目说明/13-调试手册.md)）；`SimWorldDiff` 同样未接入常规排障路径。
- **退出条件**：任一 desync、断言失败或 fatal error 都能产出一个可复现的回放件；离线重放在另一运行时能定位首分歧帧并输出字段差异；回放件进入 bug 单附件与回归语料库。

### 3.2 崩溃与现场采集

- **目标**：崩溃捕获、minidump/堆栈、每构建归档 IL2CPP 符号、最近 N 秒日志与面包屑、自动聚合去重；开发/测试包支持一键现场包。
- **现行缺口**：无 crash handler、无 minidump、无错误上报与聚合；`Log` 只有 32 条环形缓冲（[Log.cs:8](../../../Assets/LiteFramework/Scripts/Core/Logging/Log.cs)）；IL2CPP 符号有产出但分发侧不归档，现场与符号脱节。
- **退出条件**：每个构建产物带内部符号归档；fatal error 自动生成“日志尾 + 最近日志环 + 回放/快照 + buildHash + configDigest + 系统信息”的现场包；同类崩溃可聚合计数。

### 3.3 结构化可观测

- **目标**：日志带 session/match/frame/player 关联字段；按类别、级别、标签过滤；采样与统一限频；文件 sink 与轮转；服务端 tick、队列深度、丢包等指标可查；错误有趋势。
- **现行缺口**：`LogEntry` 只有 Level/Tick/Tag/Message，全局 min level，无关联 ID；`DiagTrace` 有结构化字段但消费面很小；服务端日志以散字符串为主。
- **退出条件**：任一错误可用 match/frame/player 过滤出前后文；错误现场自动附带最近 N 条日志；服务端关键指标有稳定导出面；热路径日志有统一限频/采样策略。

### 3.4 网络调试

- **目标**：传输层可注入延迟、抖动、丢包、重复、乱序，固定种子可复现；RTT/丢包曲线、回滚次数、输入领先、快照年龄可视化；场景化网络测试可脚本化。
- **现行缺口**：通用损伤注入面不存在；现有丢包模拟只在 L3 对跑里跳发（[HeadlessRunTests.cs:95](../../../Tests/LiteNet.Tests/HeadlessRunTests.cs)）；RTT/丢包是 1Hz 文本读数（[DevHUD.cs:69](../../../Assets/LiteGame/DevTool/DevHUD.cs) 的帧样本窗同样只有 240 帧）；KCP 自带 RTT 未接入；`InputLeadFrames` 不可视化。
- **退出条件**：固定种子的弱网场景（如基线 RTT、抖动、丢包组合）可在本地/云端复现；HUD 显示 RTT/丢包曲线、回滚/追帧/输入领先；弱网场景进入夜间回归。

### 3.5 性能

- **目标**：ProfilerMarker 覆盖 View/网络/宿主关键段，Sim Core 零埋点；帧预算、GC 分配、服务端 tick p50/p95/p99、队列深度；夜间性能回归带阈值。
- **现行缺口**：全框架尚无 ProfilerMarker/FrameTiming 埋点、BenchmarkDotNet 与性能基线（[性能工程专项设计.md:28](性能工程专项设计.md)）；DevHUD 只有 240 帧环形样本；服务端只有 debt/abandoned/pumpFail 等计数；门禁排除 `Performance`。
- **退出条件**：关键路径有可读 marker；服务端 tick/队列指标进 `/metrics` 或等价导出；夜间性能对比在超预算时变红，且基线重录有声明流程。

### 3.6 运行时操控与状态检查

- **目标**：开发包内置控制台/命令注册表（刷怪、传送、时间缩放、规则、回放），复用 `CommandCenter` 的权限门与审计；世界/实体查看器、快照 dump/diff、变量 watch；release 剥离。
- **现行缺口**：DevHUD 只读；GM 面板 Editor-only；`CommandCenter` 有命令与审计但 Player 无控制台；`DebugTuner` 是启动配置而非运行期调参；无世界查看器与快照 dump。
- **退出条件**：开发 Player 可经控制台完成常用状态注入与规则调整；世界/实体状态可导出并 diff；release 包不含调试命令面。

## 4. 开发与交付工具链目标形态

### 4.1 内环

- **目标**：Editor + 本地服 + 热重载 + 脚本化场景，`change-to-verified` 控制在分钟以内。
- **现行形态**：A/B 路径与 Lua 开发重载可用；纯客户端 C# 在 Editor 内重编译即可验证。
- **退出条件**：常见表现/玩法分支有可重复的本地场景脚本，失败有种子与日志；不需要为内环问题出 Player。

### 4.2 中环（内容、配置、Lua）

- **目标**：内容/配置/Lua 的改动在可调试 Player 上验证，不触发 IL2CPP 重打；中环 `change-to-verified` 小于 5 分钟。
- **现行形态**：Player 走内置内容包，远端候选链的签名发布/激活/回滚无端到端证据；Lua 在 IL2CPP 包里同样内置。
- **退出条件**：表值、Lua、Prefab/场景/美术任一类改动可在开发 Player 上完成“发布候选 → 接受 → 激活 → 回滚”的验证，且不重打 Player；中环不通时工具明确提示“本次必须外环”。

### 4.3 变更驱动构建

- **目标**：preflight 根据 diff 输出最小重建集；纯内容、纯客户端 C#、共享源三条路径分开；构建缓存可复用；不需要出的包由工具明确说“不需要”。
- **现行形态**：单体构建脚本；BuildHash 只在出包时复算，CI 不跑；BuildHash 只收集 `*.cs`，`.proto`/Luban 表源/同步代码的生成物漂移没有 CI 校验（[gen-build-hash.py:99](../../../scripts/codegen/gen-build-hash.py)）。
- **退出条件**：任一改动的构建计划可解释（改了哪些面、必须重建哪些产物、可跳过哪些）；生成物漂移在 CI 变红；`--skip-bundles` 一类逃生口不再需要人工判断。

### 4.4 可调试开发 Player

- **目标**：存在与发布包分离的开发载体，可 attach、可读控制台、可加载远端内容；发布包仍走 IL2CPP。
- **现行形态**：全 IL2CPP；development 通道只传 `Development + DetailedBuildReport`，不传 `AllowDebugging`（[build-player.py](../../../scripts/build/build-player.py)）；无 `[CodeReload]` 消费面。
- **退出条件**：开发 Player 能 attach 脚本调试器、使用控制台与运行时调参；release 包不携带调试面；开发包与发布包的能力差异有清单。Mono/Development 与 IL2CPP+HybridCLR 是候选路径，具体形态在 T1 决策点裁决，本文件不预先锁定。

### 4.5 CI 作为唯一真相

- **目标**：PR 门禁可信；生成物漂移、构建身份、测试报告、flaky 隔离、夜间矩阵与产物符号归档都在 CI 有稳定出口。
- **现行形态**：GitHub Actions 有 L0+L1 双平台、基线防篡改与 L3；L2 夜间/自托管；无 JUnit/覆盖率，L2 不上传报告，无重试，生成物漂移无校验；L0 被 ParrelSync 绝对路径卡红（[manifest.json:26](../../../Packages/manifest.json)）。
- **退出条件**：L0/L1 稳定绿；生成物漂移与基线变更都有显式门禁；测试报告可检索；flaky 用例进入 `Quarantine` 且有到期日；CI 结论与本地一致。

### 4.6 环境与工具链度量

- **目标**：一键 bootstrap 能装能修；工具链版本钉死；构建/测试耗时、flaky 率、`change-to-verified`、`rebuild-to-change` 有趋势。
- **现行形态**：`restore-check` 只校验不安装，Odin/DOTween 仍需手装；CI `cache:false`；无工具链度量。
- **退出条件**：新机器按一键流程恢复到可测试状态；关键耗时与失败率有周/批趋势；工具链自身的退化能被看见。

## 5. 演进路线

阶段用 T0～T3 标记，避免与业务/测试优先级编号混用。每一阶段以“能力闭环”而不是“工具数量”验收。

### T0 可复现现场（最高杠杆）

**目标**：让每一次失败自带现场，先把“可复现”闭环。

- 在线回放：房间命令日志（`RoomRunRecord`）按到达序记录命令、每个权威步进的 checksum、测试规则变更；重放构造同配置 `RoomRuntime` 按序喂命令，输出首分歧帧、checksum 与命令序号。纯输入回放不作为在线方案（`viewFrame`/延迟补偿/席位上下文不在 `SimInputFrame` 内）；`SimRunRecord`/`SimReplayRunner` 保留给离线纯 Sim/批跑。
- 现场包：服务端房间终态写“记录信封”（构建/配置/地图身份 + 地图快照 + 日志尾 + mismatch 摘要）；客户端在 checksum 或配置身份不符时写本地日志包。字段级 world-ring diff、崩溃捕获与符号归档、上传/下载通道归 T0 后续。
- 符号：构建产物按版本归档 IL2CPP 符号，分发包不带符号；符号查找有固定路径。
- 低成本通路可信：消除 L0 的本机绝对路径依赖；修 `run_tests` 同步模式/实例发现等阻塞日常验证的工具面问题。

**依赖**：`RoomRuntime` 单一权威执行链（不在重放器复制 Step 编排）；其余无外部系统阻塞。
**退出条件**：房间终态可产出记录并离线重放到首分歧；客户端 mismatch/配置身份不符有本地现场包；字段级 diff、崩溃捕获、符号归档与上传/下载作为 T0 的后续退出项。

### T1 可操控与中环

**目标**：让“改设置/小逻辑”在中环闭环，不再默认外环。

- 日志关联 ID：session/match/frame/player 环境上下文；热路径零分配；错误现场自动附带最近日志。
- 弱网注入：传输层延迟/抖动/丢包/重复/乱序，固定种子；网络 HUD 显示 RTT/丢包、回滚、输入领先、快照年龄。
- 可调试开发 Player：attach、控制台、运行时调参；具体载体在 T1 决策点裁决（Mono/Development 或 IL2CPP+HybridCLR）。
- 中环内容通路：签名候选的发布→接受→激活→回滚端到端；契约以[《热更与内容发布专项设计》](../客户端/内容/热更与内容发布专项设计.md)为准。
- 构建 preflight：按 diff 输出最小重建集；内容、纯客户端 C#、共享源三条路径分开；不需要出包时明确提示。

**依赖**：T0 的回放/现场包；热更专项的签名发布链；构建脚本的 profile/channel 面。
**退出条件**：内容/配置/Lua 改动可在开发 Player 完成验证且不重打 IL2CPP；固定种子弱网场景可复现并有可视化；任一改动的构建计划可解释。

### T2 可回归与性能

**目标**：让修复可回归、性能可守住。

- ProfilerMarker + 服务端 tick/队列指标；夜间性能回归带阈值；`Performance` 分类进入夜间门禁。
- CI 生成物漂移检查：`.proto`/Luban 表源/同步代码“重生成后 diff 为空”，不改变 BuildHash 闭包口径；测试报告上传、flaky 隔离与到期日。
- 完整对局 E2E：PlayMode/无头链路覆盖“起服→进房→对局→结算”主路径；30 分钟 soak 与基础 chaos（断线、重连、弱网）进入夜间。
- 世界/实体查看器与快照 dump/diff；开发包控制台覆盖常用状态注入。

**依赖**：T1 的开发 Player 与弱网面；性能专项的基线回填；测试框架的 `Category`/`Quarantine` 契约。
**退出条件**：性能回归会让夜间变红；生成物漂移会让 CI 变红；完整对局 E2E 与 soak/chaos 有稳定通过率；世界状态可导出并 diff。

### T3 度量与常态化

**目标**：工具链自身可度量、可优化。

- 看板：构建/测试耗时、flaky 率、`change-to-verified`、`rebuild-to-change`、回放采集率、现场包覆盖率。
- 回放语料库：按缺陷/场景归档，作为回归与性能样本；定期演练“从现场包到首分歧”的排障链。
- 工具链复盘：按季度检查 T0～T2 的退出条件是否仍成立，防止能力退化。

**依赖**：T0～T2 的埋点与流程。
**退出条件**：关键指标有趋势；工具链退化能被数据发现；排障演练有记录。

## 6. 退出条件与度量

### 6.1 完成定义

- 每个 bug 单都带构建身份、配置摘要与回放件（或明确说明为何无法采集）。
- 每个 fatal error 自动产出可离线分析的现场包；每个构建有内部符号归档。
- 每个改动都能回答“它属于内环、中环还是外环”，且验证证据与所属环一致。
- CI 的 L0/L1 稳定绿；生成物漂移、基线变更与 flaky 都有明确门禁与出口。
- 性能、弱网、完整对局、soak/chaos 至少各有一条夜间回归。

### 6.2 度量指标

| 指标 | 含义 | 目标方向 |
| --- | --- | --- |
| `change-to-verified`（内环） | 改完到本地可信结论 | 分钟以内 |
| `change-to-verified`（中环） | 改完到开发 Player 可信结论 | 小于 5 分钟 |
| `rebuild-to-change` | 每个改动触发的 Player/服务端重建次数 | 趋近于“只有硬边界才重建” |
| 回放采集率 | 可复现的失败中带 replay 的比例 | 趋近 100% |
| 现场包覆盖率 | fatal/desync 自动产出 bundle 的比例 | 趋近 100% |
| 符号归档覆盖率 | 构建产物有可查符号的比例 | 100% |
| flaky 率 | 非确定性失败占比 | 可解释、可隔离、趋零 |
| 性能回归捕获率 | 夜间性能门禁发现的回归 | 关键路径全覆盖 |

### 6.3 红线（不得为效率让步）

- **确定性不变**：不放松 BuildHash/共享源契约；不为“少出包”热更 Sim 判定逻辑。热更只覆盖表现、配置、Lua 与非权威流程，范围以热更专项为准。
- **测量不污染判定**：Profiler/日志/采样不进入 Sim 判定路径；Core 维持零埋点纪律。
- **调试面不进发布包**：控制台、GM、feature flag 的发布形态必须有剥离/门禁；密钥不入库。
- **单一权威**：不复制热更、测试分层、性能预算、GM 分层的第二套契约；本文件只排优先级与退出条件。

## 7. 非目标

- 不在近期建设分布式构建集群/远程缓存；先做 change-driven preflight 与本地增量。
- 不建设全量遥测平台；先做现场包、关联日志与关键指标。
- 不重写网络/Sim 架构；弱网注入与回放是诊断设施，不改变同步策略。
- 不让 release 包可调试；开发载体与发布包分离。
- 不替代既有测试框架、性能预算、GM 分层与热更发布契约。
