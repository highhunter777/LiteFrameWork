# 状态同步专项设计

> 当前联机主路线：3D 俯视角、float、服务器权威、客户端移动预测、快照和解、远端插值、服务器回溯命中。帧同步只是独立预案，见《帧同步备选方案》。
> 状态：现行专项设计
> 版本：1.2
> 更新日期：2026-10-18
> 适用范围：客户端预测、服务器权威、快照、和解、插值和回溯
> 维护责任：网络同步

## 1. 不可让步的原则

1. `LiteSim.Core` 不引用 Unity、LiteFramework、Lua、网络或 IO。
2. `Step(state, input)` 是可重放的固定顺序函数；不得依赖 Dictionary 遍历、动态订阅、隐藏静态状态或可变 dt。
3. `View → Sim` 只有输入和读取；View 不回写位置、血量、伤害、库存或技能判定。
4. 服务器是战斗事实唯一来源；客户端预测只为手感，权威快照负责纠正。
5. 协议单源为 protobuf；框架网络层只提供字节管道，不认识帧号和房间语义。

## 2. 程序集和拓扑

```text
LiteSim.Core  ── 纯 C# Sim、固定布局、系统、快照、回滚
LiteNet       ── protobuf、KCP 双通道、RoomClient、协议纯函数
LiteView  ── Unity 镜像/插值/输入/相机/VFX
LiteGame      ── 流程、Bridge、UI、Lua、BattleService
RoomServer    ── .NET 权威 Sim、广播、回溯、重连、归档
```

客户端战斗链路：`Input → LiteNet → RoomServer AuthSim → StateSnapshot → Rollback/SimView`。

## 3. 数值与布局

- 逻辑帧率 60Hz，`dt = 1/60`；快照初始 30Hz。
- 状态同步使用 float；超越函数通过生成查表，基础算术遵守 IEEE 纪律。
- `SimWorldState` 使用固定容量数组：`EntitySlot[]`、`AliveBitmap`、`Globals`、`CustomData` 和明确的 Weapon/Action/Status/Match 状态数组。
- 快照、checksum、回滚、重连必须覆盖所有影响判定的字段；帧内命令和帧事件不进快照，消费后清空。
- 实体 Id = 版本 + 槽位，禁止 swap-remove；遍历顺序固定。

## 4. Sim 系统顺序

> **权威＝代码 `Assets/LiteSim/Core/Scripts/Pipeline/SimStep.cs`**（顺序即确定性契约；本节曾列 CharacterState/Action/Skill/Status/Loot 等未落地系统，2026-10-13 按代码回正）。

```text
Respawn
→ Input
→ Movement
→ Weapon（懒装备/换弹/切枪推进/半自动重臂）
→ Shooting（hitscan + 障碍遮挡 + 散布/多弹丸）
→ Flush（伤害/计分命令轮次，固定最多 3 轮）
→ Cleanup
→ Frame++
→ Match（advanceMatch）
```

同帧请求按 `EntityId` 升序。系统不使用通用事件中心，使用固定 `CommandBuffer` 和 `FrameEventBuffer`。

## 5. 协议

### 5.1 输入

`InputFrame` 包含 `EntityId/MoveX/MoveZ/AimX/AimZ/Buttons`，追加 `selected_weapon_slot/target_entity_id/action_seq`。按钮位覆盖 Fire、Reload、Switch、Skill1–3、Pickup、UseItem。

- Move/Aim/Fire/Skill：不可靠包 + 未确认段冗余（最近快照帧+1 起，容量 16 帧；锚快照——预测领先不会甩掉服务器所需帧号）。
- 一次性 Pickup/Use/Drop：可靠命令，带 commandId。
- 服务端覆盖 EntityId，校验帧号、按钮、向量长度、频率和 seq 窗口。

### 5.2 快照分层

快照分四层：

- `PublicStateSnapshot`→`SlotDelta`：可见实体的位置、速度、朝向、HP、护盾、公开状态、动作摘要。
- `MatchStateSnapshot`→`StateSnapshot.match`：阶段、倒计时、比分、回合和胜者。
- `PrivateStateSnapshot`→`PrivateStateDelta`：仅本人可见的弹药、技能 CD、资源、局内背包、私有状态（只发本人）。
- `CombatEvent`（公共面，**独立包 `PacketType.CombatEvents`**——与快照同节拍、窗口全量重发，自带丢包收敛）：kind 判别的通用记录（`CombatEventEntry`：kind/双方/帧/数值/位置——字段按 kind 释义，Death 的数值＝击杀帧武器槽）。房间侧窗口（`CombatEventWindow`：1s 时间老化＋容量有界＋同键聚合/Crit 升档）经映射单源 `CombatEventCodec` 打批、在 `WireBudget` 预算内**留新弃旧**；客户端按 (kind,双方,帧) 去重消费（`PublicCombatFeed`），首份/重连只标记已见、不重播历史。**事件面不进快照**——快照尺寸只随实体数变，状态面与事件面各有载荷预算、互不挤占（合包会顶爆 KCP 不可靠上限导致整份快照被丢）。

和解口径：线上 `StateSnapshot.checksum` 为**公共可重建口径**（`SimChecksum.ComputePublicChecksum`），私有面不进比对。

重连顺序：公共全量 → 比赛状态 → 本人私有状态 → 输入历史。新增状态必须同步修改 `SnapshotCodec/Differ/Reassembler`、`CopyTo`、checksum 和协议测试——该纪律由布局/校验/往返用例把守（施工证据见 [同步契约 P0 施工记录](../../施工进度/输入与同步链线.md#ch1-同步契约P0)）。

## 6. 预测、和解和插值

### 6.1 客户端预测

- 预测移动和朝向（**含开火资源账/开火窗/Fire 事件**，用于本地手感与动画语境）；**命中、伤害、击杀、死亡不预测**。
- 客户端本地 `ShootingSystem` 以预测模式运行：散布/伤害随机流按与服务端前向步进同序推进，但不写 Damage 命令、不产 Hit/Crit/Death 事件；命中/伤害/死亡只由权威快照与公共战斗事件面（`PublicCombatFeed` 的命中/阵亡队列）驱动。
- `InputHistory` 保存最近输入；权威快照到达后在对应帧校验，差异触发回滚重放。
- 回滚重放清空帧事件；`silenceUntilFrame` 防止特效、音效、震屏重复。

### 6.2 View

- 本地玩家跟预测位置；远端按**快照帧号**在 jitter buffer 中插值：渲染帧以 tick 频率匀速推进、落后最新快照 `InterpFrames`（66ms），丢包时按真实帧差铺满间隔，不冻结再跳；旧帧/重复帧在入口丢弃。
- 和解时本地误差衰减，远端必要时 snap；**复活/传送＝语义硬切**：本地生命更替（`LifeStartFrame` 变化）或表现硬切阈值触发时，表现位置**无条件**瞬移到权威位、物理代理（`CharacterController`）关停后直写——落位不经带扫掠的 `cc.Move`（否则中途/落点有障碍就会被拦在墙外永久滞后）；远端同语义（前后快照的 `LifeStartFrame` 不同 ⇒ 直接对齐后帧，不按 alpha 插值）。判据是语义而非距离，**新图不依赖"复活点离死亡点多远、中间有没有掩体"**；距离阈值只兜底异常单帧跳变。
- 远端离散事实（瞄准/开火窗/死亡/生命起始帧）取**渲染帧对应快照**，与画面同拍；快照驱动的远端移动测速做低通/硬切抑制，避免锁存抖动。
- 开火反馈由本地 Fire 事件立即播放；**命中/受击/死亡反馈只由公共战斗事件面或快照状态触发**。死亡是每帧权威状态（本地经和解、远端取渲染快照），事件不置不可逆锁存；复活（Hp 回满）即退出死亡叶。

## 7. 命中和延迟补偿

- hitscan 使用服务器快照环回溯到开火者在**客户端实际渲染的帧**（`viewFrame` 直接取 `SimView.RenderFrame`，服务器不再做 ±插值帧抵消）；回溯窗口 clamp 到 `[当前帧-LagCompHistory, 当前帧]`。
- 回溯时**目标取历史帧位置，射手取当前权威位/朝向/武器**（客户端从当前预测位开枪）；同帧互杀按各射手开火时的生命/武器结算，不被同帧先结算的死亡取消。
- 回溯只读目标位置，不推进世界、不消费权威随机数；命中结论回写当前帧命令缓冲。
- 投射物作为 Sim 实体随快照推进，不走 hitscan 回溯。
- 客户端不自行决定命中和伤害。

## 8. RoomServer

- 每房间单线程 AuthSim，MVP 单循环；缺席输入使用空输入。
- 60Hz Step，30Hz 增量快照，AOI 只影响广播不影响判定。客户端只接收严格新于已应用帧的快照（旧包/重复包丢弃）。
- Hp/击杀/死亡/复活/保护等关键状态变化在变化后 1s 内重复下发（粘滞窗），丢包不依赖全量兜底；活体位图变化必须转全量（只比数量会漏“一死一生”）。
- 每连接有发送队列上限；超限按降快照率、收缩 AOI、丢低优先级实体降级。
- Join 目标校验身份票据、房间 Protocol/Sim/Gameplay 契约和签名的 MatchStartSnapshot；RoomServer 不查 Profile 数据库。版本维度切换前保留 buildHash 严格检查；新增维度按[热更专项](../客户端/内容/热更与内容发布专项设计.md)补协议、准入和双端测试。
- 结算只输出签名 `RewardDelta`，交给 ProfileService 幂等落库。

## 9. 重连和归档

- 重连票据一次性、短时有效；服务端返回公共/私有快照和输入历史。
- 归档至少包含 matchId、seed、Build/Protocol/Sim 身份、可找回原 ConfigSnapshot 的 ID 与完整 GameplayDigest、最终 checksum、输入历史和结算摘要；版本维度切换前继续保留 buildHash。
- 对局固定配置和版本依赖，重连必须恢复原房间版本；发布新数据不能替换局中快照。新旧房间并存与内容准入遵循热更专项。
- 归档用于复查和反作弊，不作为客户端权威数据源。

## 11. 红线和验收

- 不把玩法判定放 View/Lua；不让 UI 直接发战斗包。
- 不把局外库存、聊天、公会完整状态放进战斗快照。
- 8 人 3 分钟稳定；150ms RTT、10% 丢包可收敛；重连 5 秒内恢复；重复输入不得重复伤害或奖励。
