# 11 · 现状边界与演进方向

> **本章回答**：哪些能力是真正兑现的、哪些只是"代码写了但没接线"、下一阶段的关口与主要风险是什么。
> **口径**：2026-10-22 工作区；状态判断以**代码调用点**为第一证据、施工进度卷为第二证据；文档状态行与代码冲突时以代码为准并标注。
> **不做什么**：本章不是验收裁决，也不维护完整任务清单——完整关口与队列见 [待办总览](../待办总览.md)。

## 1. 先把四个词分清

| 词 | 判据 | 读文档时的陷阱 |
|---|---|---|
| **已交付** | 有施工记录 + 门禁结果 + 代码路径 | 交付的是"当时范围"，不等于后续没改坏 |
| **已接线** | 生产装配/调用链上有真实调用点 | 有测试调用不算生产接线 |
| **已实现未接线** | 类型完整、能编译、L1 通过，但全 `Assets/` 无生产调用点 | 文档常把它写成"已具备/已支持" |
| **目标** | 设计文档定义、代码尚未兑现 | 不要当现状引用 |

本项目的特殊性在于：**框架能力先行**，所以"已实现未接线"的比例天然偏高；读技术文档时必须区分"能力存在"与"业务在用"。

## 3. 已兑现的核心能力（按域）

### 3.1 客户端框架

- Host/模块/作用域/统一取消/逆序关闭/编辑器重载复位（C1）。
- 容器构造注入 + 声明图预检 + Seal + Tickable/Stats 发现。
- 事件中心高级化（优先级/延迟/有界队列/拦截链）、命令中心（类型化/权限门/审计/撤销）、对象池高级化、三机体状态机。
- 内容事务：`IContentService` + `AssetLease` + 代次校验 + 共享加载；`ConfigService` 候选构建/原子发布。
- 会话与重连：`BattleClient` 状态机、Account/Match Scope、断线恢复 ACK。
- 表现域生命周期：Scene 迟到加载代次检查、Entity 作用域/重复归还幂等、Audio 分域时钟、VFX 关闭真取消。

### 3.2 Sim 与联机

- 定长 60Hz 逻辑帧、9 系统固定顺序、输入就地排序、命令轮次（≤3）。
- 确定性保障：`SimMath`（整数 sqrt）、`SimRng`（Xorshift64*）、FNV-1a checksum 双口径、槽位版本化、IEEE 逐位基线。
- 预测/回滚/和解：输入历史 32 帧、快照环 8 帧、`MaxRollbacksPerFrame=2`、公共 checksum 比对、`SimView` 插值/衰减/静默门。
- 协议：`battle.proto` 单源、1B PacketType 信封、输入位打包单源、快照差分/重组/AOI、KCP 双通道（可靠信令 + 不可靠快照/事件）。
- 上行冗余（未确认段 16 帧）与 `viewFrame` 延迟补偿；BuildHash 两端握手。

### 3.3 服务端

- 房间内核纯化（R11）、`RoomRuntime` 权威步进、`InputGate` 四类校验、30Hz 快照流水线（差分/AOI/背压）、`LagCompensator` 回溯、`MatchStateMachine` 全表。
- 宿主：组合根、60Hz `ServerLoop`、多房路由、Worker/Mailbox、Owner 切换、终态销毁、排空 5 步（进程级手验）。
- 安全：票据 CSPRNG、分层限流、AES-256-GCM 安全信封、64 位重放窗口。
- Meta：Auth/Lobby/Profile 模块化单体、HMAC 票据、房间注册与 BuildHash 准入、Mongo 持久化（账本/Outbox/迁移/幂等）、`/live` `/ready` `/metrics`。
- 云侧：Windows Server Core 原生托管、WireGuard 隧道、任务计划、GM 通道、自包含发布。

### 3.4 内容、UI、工具链

- 热更批(一)~(九)：签名/候选校验/激活事务/Lua 沙箱/反回退/真实下载/可信公钥/健康探针/IL2CPP 密码学验证。
- UI：导航单写者、模态栈、七态生命周期、缓存策略（部分不可达）、绑定代码生成、Lua 三注册表、UI 工具链（在途重构）。
- 工具链：60 工具单清单、Hub/CLI/生成索引/注册面校验；生成器工具箱（BuildHash/proto/Luban/sync-code）。
- 测试：L0/L1/L2/L3 可跑；8 个双轨共编程序集 + 52 个 asmdef 的编译面，6 个 dotnet 测试工程。

## 5. 明确缺口与风险

### 5.1 质量与验证

- **L4 缺失**：无真机性能/内存基线、无设备矩阵；`test.py` 不含 L4。
- **L2 仅自托管 Windows**：需要完整工程 + 中国版编辑器授权 + `L2_ENABLED`；CI 的 L2 与本机夜间任务二选一。
- **Doc 门禁不在 CI**：文档索引/链接/命名只在本地/手动跑。
- **Quarantine 未机械化**：没有到期日/缺陷关联校验，容易变成永久豁免。
- **CI 基线防篡改可绕过**：浅历史取不到 BASE 时直接跳过。

### 5.2 服务端与部署

- **Meta 单实例**：房间注册表/出号保留集驻进程内存，不支持多实例。
- **容量硬限**：`max_rooms=8`；席位上限 32；`Running` 后不可中途加入；观战/回放无实现。
- **公网门禁未闭合**：当前是封闭测试环境，不得作为"可发布"判据；公网只开 `51820/udp`。
- **真云 CDN / Android 真机 / 断点续传 / 写盘中断矩阵**未验。
- **部署无自动回滚**：无产物快照、Mongo 无定时备份；覆盖配置只留 `.bak`。
- **Room UDP 绑定差异**：配置没有对局 bind 字段，实测 `0.0.0.0:17777`，与"只绑隧道"的表述不一致（已登记）。

### 5.3 客户端与表现

- **Android 热更真机矩阵**阻塞于无设备（随 G4）。
- **UI 正式页面仍缺**：登录/大厅/房间/结算/设置五页已接 Meta 演示链，但背包/错误恢复/完整 HUD（技能栏/CD/比分/延迟/对局中退场）仍归 U3/G3。
- **动画余部**：Hit/Death 整身接管、真对局动作对齐/打断/重连去重、8 人基线。
- **UIMain 已退役（2026-10-23）**：样例页的 tbuiform 行/启动锚/main.lua require 均已移除；prefab/Lua 改为测试载体 `Tmp_UiTestPage`/`Tests.UiTestPage`。产品入口是登录/大厅；正式主菜单归 U2/G3。

### 5.4 文档与代码漂移

## 6. 质量债：三类系统性问题

[审计流程](../审计/README.md)的总评比单条缺陷更值得记住：

**客户端**：
1. **"单源"承诺靠人肉同步**：FSM 双内核互抄、checksum 字段清单两份、动效默认值三份、SimTrig 表长双写——守卫测试钉不住"改一处漏一处"。
2. **能力先行、接线缺位**：KcpNetworkService/AudioService/CommandCenter 部分功能/主流程不开 UI，编译器与测试都不拦。
3. **临时手段沉淀成常态**：`[Diag]` 哨位、反射取容器、静态可变全局进判定路径。

**服务端**：
1. **跨线程边界只防了一半**：结算 Outbox 的 60Hz→后台线程边界曾全类无锁（P0，已修并验证）。
2. **"同口径"映射靠人肉第四份**：真服/本地服/worker 对同一段协议映射各手抄，AimPoint 六字段真实漂移过一次（已抽 `InputPacker` 单源）。
3. **错误吸收不对称**：Worker 有异常隔离，`ServerLoop` 的 60Hz 权威循环曾无 try/catch（P0，已修）；配置边界与内核容量曾失配。

**当前最值得盯的技术债**：技术债 #1（静态数值读口）已用 `CombatValues`/`WeaponTable` 实例化 + R13 扫描治住大半，但 `MovementValues` 的 17 个字段仍是"装载了没人读"；技术债 #2（checksum 字段清单）仍是手抄；技术债 #3（诊断工具链）仍未接线。

## 8. 本卷的维护约定

1. **每完成一个 G 关口或一批结构性改动**，回写对应章节的"机制"段落 + 本章的"已兑现/未接线/缺口"三张清单。
