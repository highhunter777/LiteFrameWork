# 框架实施手册（精简版）

> 本文件只保留里程碑、依赖和验收；逐件施工图已归档到 `Docs/Archive/2026-09-20/`。

## 1. 实施顺序

当前采用“先联机地基，再内容闭环”的顺序：

```text
M0–M4 框架底座
→ M7 数值/确定性
→ M8 Sim
→ M9 快照/回滚
→ M10 网络/RoomServer
→ M11 表现/Demo
→ M12 工具/归档
→ M13–M16 账号、库存、房间、社交、运营
```

M5/M6 单机内容和热更闭环不阻塞 M7–M12；在联机 Demo 稳定后补齐。

## 3. 每个里程碑的通用门

1. 先冻结接口/表/协议，再写实现。
2. 纯 C# 规则进入 L1；Unity 资源和 View 进入 L2；多人行为进入无头联测。
3. 任何新增状态必须同时更新快照、checksum、重连和测试。
4. 任何新增 Bridge API 必须登记白名单和 Lua 用法。
5. 预算超出或出现第二套真相时，停止扩展，先回到边界审查。
