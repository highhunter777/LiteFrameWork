# 自研框架设计方案（精简版）

> 这份文档只保留长期有效的边界和决策。逐件施工记录在 `Docs/Archive/2026-09-20/`，玩法系统见《六大系统具体方案》。

## 1. 目标和红线

框架负责生命周期、资源、UI 壳、事件、时钟、配置和桥接；玩法负责规则；Lua 负责内容与界面编排。

不可违反的边界：

1. `LiteSim.Core`、`LiteNet` 不依赖 Unity、Lua、框架和热更运行时。
2. Sim 判定只读/写固定数据，不能访问 `Transform`、`Time`、`Animator`、数据库或网络 IO。
3. 业务 UI 不直接拿 `INetworkService` 发包，必须经过 `Bridge.*` 或 `IBattleService` 等玩法门面。
4. 资源只经 `AssetService/YooAsset`；配置只经 `ConfigService/Luban`；日志只经 `Log`。
5. 所有跨帧引用使用稳定 Id，不保存 Unity 对象或短生命周期对象引用。

## 2. 程序集和依赖

```text
LiteFramework.Core      纯 C# 机制：事件、时钟、DI、StageMachine、池、FileSys
LiteFramework.Unity     Unity 绑定：GameEntry、UniTask、资源/场景适配
LiteSim.Core             纯 C# 战斗判定：SimWorld、Systems、快照、回滚
LiteNet                  纯 C# 传输协议：protobuf、KCP 适配、RoomClient
LiteGame.Runtime         流程、Bridge、UI 壳、Lua、表现编排
LiteSim.View             Unity 表现：镜像、插值、相机、VFX、输入采集
RoomServer               .NET 权威房间：AuthSim、广播、回溯、结算
```

依赖只向下：`LiteGame/View → LiteSim/LiteNet`；`RoomServer → LiteSim/LiteNet`。`LiteSim.Core` 不反向引用 View 或框架。

## 3. 框架机制

### 3.1 装配和 DI

- `GameEntry` 创建根容器并按顺序注册服务。
- 注册完成后 `Seal()`；业务阶段只允许解析，不允许临时注册。
- 容器只做单例构造和显式依赖解析，不做自动扫描、属性注入、作用域容器或第二个 Service Locator。
- 战斗 `BattleContext` 由流程创建和销毁，不放入全局容器。

### 3.2 流程和状态机

- 流程使用 `StageMachine/IStageHost/ProcedureArgs`。
- 需要层级、历史和事件冒泡时使用 `HierarchicalStageMachine`。
- 角色联机判定不使用框架状态机，使用 Sim 数据 + 表；框架状态机只服务流程、UI 和单机表现。

### 3.3 事件、时钟和池

- 事件中心用于框架/UI桥；Sim 内使用固定 `CommandBuffer/FrameEventBuffer`。
- `WorldClock`、`UIClock`、墙钟分域；网络逻辑由 `FrameDriver` 60Hz 驱动，不依赖可变游戏时钟。
- 对象池由工程自有 `ObjectPool<T>`/实体池负责，不引入 `UnityEngine.Pool` 作为框架依赖。
- 订阅统一进入 `SubscriptionBag`，生命周期结束一次性注销。

## 4. Lua、Bridge 和 UI

- Lua 可调用的只有白名单门面：`Bridge.data/ui/content/combat/inventory/chat/guild`。
- Luban 类型、Sim 状态、网络包和服务容器不直接导出给 Lua。
- UI 逻辑在 Lua，C# 提供生命周期、控件访问、批量刷新和安全调用。
- 高频 HUD（血条、弹药、技能 CD、击杀提示）由 C# `HudModel` 聚合脏位后直驱；Lua 不逐帧调用。
- UI 只能读 ViewModel，不能写权威战斗或持久化状态。

## 5. 配置和热更

- `ConfigService` 在 Preload 阶段一次性加载 Luban binary；缺文件、坏表、缺关键行直接失败。
- 客户端 binary、服务端 JSON、Lua 产物和战斗表进入 buildHash。
- `LiteSim.Core`、`LiteNet` 和战斗规则不热更；Lua 内容、UI、表现资源按 YooAsset 规则热更。
- 对局内禁止重载武器、动作、数值和 Timeline 产物。

## 6. 玩法接入规则

| 能力 | 规则归属 | 表现归属 |
|---|---|---|
| 战斗/武器/技能/状态/局内包 | `LiteSim.Core` + RoomServer | `LiteSim.View` |
| 局外背包/装备/结算 | ProfileService | LiteGame UI |
| 聊天/公会 | Chat/Guild Service | LiteGame UI + WebSocket |
| 剧情/引导/活动 | C# 机制 + Lua 内容 | UI/Timeline |

跨系统操作必须经过 UseCase/服务门面，不拼装多次底层请求。详见《六大系统具体方案》和《商业级通用服务端框架重构总设计》。

## 7. 启动主线

`GameEntry → ProcedureLaunch → 资源/配置/Lua 预载 → 生成注册表 → Seal DI → ProcedureMain → Match/Battle/Result`。

任何关键配置或桥接失败都进入明确错误流程，不静默使用默认值。编辑器重载只重建 Lua/注册表/表现缓存，不重建 Sim 或网络程序集。
