# 编辑器设计规划（UI 编辑器 + 时间轴编辑器）

> 定案 2026-09-14（用户）：**规划 UI 编辑器与时间轴编辑器设计**；UI 编辑器走 **标记工具 + 编排器两阶段**；时间轴编辑器走 **Unity 内时间轴编辑**、**技能与动画/表现共用**（取代编排层 + 属性轨；骨骼曲线仍归 Animator）。
> 总则：编辑器服务**内容与界面生产**，不替运行时做决定；**产物必须过运行时纪律**——绑定索引可生成、时序为整数帧、模板/表内无裸引用、不引业务依赖。

---

## 1. 定位与边界

| 编辑器 | 解决的问题 | 产物 | 明确不做 |
| --- | --- | --- | --- |
| UI 编辑器（阶段一：标记工具） | prefab 绑定标记的可视化编辑、校验、一键生成 | 标记（BindRoot/BindNode）+ 绑定索引/绑定类 | 不做界面搭建 |
| UI 编辑器（阶段二：编排器） | 快速搭建界面骨架（拖控件出 prefab） | 标准 prefab（可继续用 Unity 原生编辑） | 不生成界面逻辑代码（逻辑在 Lua）；不做运行时联动预览（列远期） |
| **时间轴编辑器**（技能 + 动画/表现共用） | 动作序列的可视化编辑——**采用 Unity Timeline（内置 1.7.6），不自研画布**；自研仅三件：自定义轨 + 导出器 + 校验 | **TimelineAsset（时序真相）** → 导出 `tb_timeline`（产物）+ `tb_action_num`（数值真相，策划面）→ binary → Sim + 表现双消费者 | 不自研画布/轨道交互；不取代 Animator（骨骼与属性动画走 Animation Track / AnimationClip）；不做 SO 中间态；**对局中不允许热重载**（确定性） |

**实现技术栈**：UI 编辑器四面板 = **Odin**（授权已有，附录 B）；**时间轴编辑器 = Unity Timeline 包**（内置，零自研画布）——**原"IMGUI 自绘时间轴 + Odin 宿主"方案已作废（2026-09-14 二次修订）**，理由与成本对照见 §3.0/§3.1。

## 2. UI 编辑器

> **实现技术栈定案（2026-09-14，用户：已有 Odin 授权，直接用）**：面板实现走 **Odin Inspector**——控件库面板 = `OdinMenuEditorWindow`（菜单树 + 对象预览）；标记组件 Inspector = Odin 属性绘制（`[ValueDropdown]` 类型下拉 / `[Required]` / 分组 / 联动）；受控属性面板 = `OdinEditor` + 属性树过滤（白名单 attribute）；校验展示 = **Odin Validator**（另购项，未购则该面板自研）。
> **硬纪律**：**Odin 只进 `LiteGame.Editor`**，运行时组件零 Odin 依赖（受控面白名单用我们自己的 attribute 表达，Editor 侧写 Odin drawer 认它）。摘除 Odin 只换绘制层，不倒架构。详见附录 B。

### 2.1 阶段一：标记工具（随控件模板落地实施）

**能力**：
1. **树形视图**：选中 prefab → 展示 BindRoot/BindNode 结构（节点名 / 绑定名 / 组件类型 / 是否缺失）
2. **Inspector 增强**：BindNode 的名字与类型选择（下拉控件类型）、批量改名、复制标记
3. **场景视图叠加**：标记节点可视化（图标/描边），一眼看出哪些节点已暴露
4. **一键校验**（可批量扫全目录）：重名绑定 / 缺失组件 / 重复标记 / 类型不匹配 / 未标注的疑似控件（启发式提示）
5. **一键生成**：绑定索引（`UIBindIndex`）+（路径 B）绑定类；多 prefab 批量生成 + 全局绑定名冲突检查
6. **CI 前置位**：校验作为提交前检查项（与 TemplateEngine/link.xml 同类纪律）

**落点**：`LiteGame.Editor`（在现有 `BindIndexBuilder`/`UIBindBase` 之上扩展，不新增 asmdef）。

**验收**：对控件库 20 余件模板全量校验通过；生成物与运行时索引一致（Play 断言）；改名/删除标记后一键重生成无残留。

### 2.2 阶段二：编排器（控件模板库就绪后实施）

**分工会说清（为什么画布用原生、面板自研）**：Unity 原生擅长**几何与层级**（拖拽/锚点/吸附/多选/撤销，全部免费）；本项目的痛点不在几何，而在四件原生没有的事——**控件从哪来**（库）、**哪些节点要暴露**（标记）、**暴露的边界**（受控属性）、**改完能否生成正确索引**（校验+生成）。

| 环节 | 原生 | 自研面板 |
| --- | --- | --- |
| 拖拽/锚点/吸附/撤销 | ✅ Prefab Stage 内全有 | — |
| 控件从哪来 | ❌ 翻 Project 找 `UI/Widgets/` | ① 控件库面板（缩略图素材架） |
| 哪些节点暴露给 Lua | ❌ 手动加标记组件 + 手填字段（易漏、命名乱、无全局视图） | ② 标记面板（一键标记 + 暴露清单树） |
| 暴露的边界 | ❌ Inspector 暴露控件内部字段，可被改坏 | ③ 属性面板（只显示壳允许的面——把纪律变成物理边界） |
| 索引/绑定类生成 | ❌ 不存在 | ④ 校验与生成面板（校验结果可点击跳转 + 一键生成） |

**内容作者工作流**：打开界面 prefab（Prefab Stage）→ 控件库面板拖入控件 → 原生调布局 → 标记面板设 BindNode 并命名 → 属性面板调壳允许的面 → 校验面板一键校验 + 生成索引/绑定类 → Play 经 Lua 逻辑表验证。

**价值不均衡提示（范围可收缩）**：③④（纪律边界 + 校验生成）是本项目独有价值；①（素材架）在控件数 20+ 时才明显。**阶段二范围允许按落地体感收缩**——若"标记面板 + 校验生成"已够用，编排器即到此为止，不凑齐四件。

**能力**（画布形态已定案 = Prefab Stage 原生编辑，见附录 A）：
1. **控件面板**：控件库 prefab 列表（带缩略预览），拖入 = 在 Prefab Stage 实例化模板
2. **画布 = Prefab Stage**：编排在 prefab 编辑模式下进行——**锚点/边距/吸附/对齐/多选/撤销全部复用 Unity 原生**（不自研）；面板侧只做"控件库拖入 + 安全区/绑定标记叠加显示"
3. **层级面板**：复用 Unity Hierarchy（命名自动套用绑定约定；`_` 前缀标记非暴露节点由标记面板负责）
4. **属性面板**：受控 API 子集（尺寸/锚点/文本占位/样式开关/多态视觉配置）——**只暴露壳允许的面**（不暴露控件内部实现）
5. **标记面板**：一键设为 BindNode / 设为 BindRoot（类名/命名空间/输出目录）+ 批量改名
6. **产物 = 标准 prefab**：保存即原生保存（存入 `Assets/LiteGame/UI/` 约定目录）——**不需要"生成 prefab"这一步**（这是选 D/H 的核心红利）
7. **缩略预览（可选增量）**：RenderTexture 渲染 prefab 缩略图列在控件面板中（选型 E）；真实数据预览走 Play

**落点**：独立 `EditorWindow` + 画布——**画布技术选型见附录 A（全选型清单 + 推荐）**；实施第一步定案。

**验收**：用编排器搭出联机 HUD 界面（《联机Demo设计》§4）→ 生成 prefab → 标记工具校验通过 → Play 中经 Lua 逻辑表正常驱动（冷却环/血条/比分）。

### 2.3 两阶段关系

阶段一（标记/校验/生成）是阶段二的**基础设施**：编排器生成的 prefab 必须能被标记工具校验、索引可生成。控件模板库（《UI控件库Prefab落地规划》）是阶段二的**素材**。顺序不可颠倒。

## 3. 时间轴编辑器（技能 + 动画/表现共用）—— **采用 Unity Timeline，不自研画布**

> **定位定案（2026-09-14 二次修订，用户：用 Timeline 好了，不自研）**：**编排层直接采用 Unity Timeline 包**（工程已内置 `com.unity.timeline 1.7.6` + `modules.director`，零引入成本），**不自研时间轴画布**；曲线层/状态机层保留 Animator。**自研部分收窄为三件**：自定义轨（承载判定/表现语义）≈300-500 行 + 导出器（TimelineAsset → 表）≈200-300 行 + 导出校验 ≈150 行（合计 ≈650-950 行，一次性）。

### 3.0 三层边界（修订后）

| 层 | Unity 原生 | 本项目 | 采用/不采用 |
| --- | --- | --- | --- |
| **曲线层**（AnimationClip） | Animation 窗口 | 美术资产，走 Animator（《动效设计方案》§1） | **保留**（骨骼动画） |
| **状态机层**（AnimatorController） | Animator 窗口 | 同上，参数单向驱动 | **保留** |
| **编排层**（何时播什么） | **Unity Timeline** | M4b 序列执行器（ITimelineRunner，运行时） | ✅ **采用 Timeline 作为创作工具**（§3.1） |
| **属性动画**（非骨骼：位移/缩放/透明度/材质） | Animation 窗口 / Timeline Animation Track | — | ✅ **采用 Timeline 的 Animation Track**（编辑 AnimationClip）——**原"自研属性轨"作废**；属性动画随 YooAsset 热更（《动效设计方案》§2 已定），不落表 |

**不自研画布的成本对照**：自研 ≈800-1200 行 + **长期维护**（拖拽/吸附/框选/缩放/播放头/曲线全自写）；Timeline 路线自研 ≈650-950 行且**一次性**，编辑体验（吸附/预览/曲线/多轨对齐/动画编辑）直接白拿。

### 3.1 Timeline 轨道映射（自研部分只剩这里）

| 需求 | Timeline 承载 | 自研内容 |
| --- | --- | --- |
| **判定轨**（前摇/判定窗/位移/冷却起点，**Sim 消费**） | **自定义 Track + Clip**（Clip 字段：判定类型/半径/伤害系数/时长帧） | TrackAsset + PlayableBehaviour + ClipEditor（≈300-500 行，与表现轨共用一套框架） |
| **表现轨**（特效/音效/震屏/飘字） | **自定义 Track + Clip**（引用名从下拉选，禁手填） | 同上 |
| **动画轨**（骨骼动画） | **内置 Animation Track**（直接引用/编辑 AnimationClip；Animator 参数单向驱动） | 无（白拿） |
| **属性动画** | **内置 Animation Track**（AnimationClip 曲线） | 无（白拿） |
| **事件轨**（回调点/演出切换） | **内置 Signal Track** | 少量（Signal 接线） |

**秒 → 帧硬规则（导出器必须实现）**：Timeline 以**秒（double）**记录 clip 位置；导出时 `帧 = round(秒 × 60)`，并校验 `|秒 × 60 − 帧| < 1e-4`，不满足即报"关键帧未对齐整帧"（拖到 0.2s 实际可能是 12.0000001 帧——取整歧义必须在导出时拦下，否则判定帧在两端可能不一致）。

### 3.2 数据流（真相方向：**Timeline 管时序，表管数值**）

```
Unity Timeline（TimelineAsset，时序真相；程序/TA 编辑）
   ＋ Luban 表（数值真相：伤害/半径/冷却帧数；策划编辑，可 diff/可热更）
   ↓ [一键导出]（TimelineAsset → 时序列；保存时自动触发，§3.5）
   CSV：tb_timeline（id | 总帧长 | tracks 时序列 ← 产物，标注"勿手改"）
   CSV：tb_action_num（数值参数 ← 手改，策划面）
   ↓ gen.bat → binary
   → Sim 读判定轨 + 数值表；表现层读表现轨（序列执行器 + UiFx / Animator）
```

- **双源分层（各取所长）**：**时序结构**（哪帧出判定、哪帧特效/动画）住 TimelineAsset——程序/TA 用成熟编辑器改；**数值参数**住表——策划可改、可 diff、可热更
- **代价（明确接受）**：①改时序要开 Unity（不能手改表）②TimelineAsset 的 git diff 不可读（YAML）③`tb_timeline` 的 tracks 列是**产物**，导出时覆盖（需提示到位）
- **红利**：零自研画布；吸附/预览/曲线/多轨对齐/动画与属性编辑全部白拿（连 Animation 窗口的工作流都并入 Timeline）
- **与原"CSV 唯一真相"原则的关系（修订说明）**：该原则的本意是"**不要影子真相**——两侧都能改同一份数据"。现在真相是**分层的**（时序只来自 TimelineAsset、数值只来自数值表），**不存在同一份数据的两个可写副本**——这与被否掉的旧 SO 方案有实质区别（旧方案 SO 与表写的是同一份完整数据）
- **手工编辑通道**：数值表可直接手工改（CSV，可 diff）；时序列手改会被下次导出覆盖（明确标注）

### 3.3 运行时形态：表现侧要不要直接跑 PlayableDirector

| 场景 | 建议 | 理由 |
| --- | --- | --- |
| **联机技能表现（对局内）** | **走导出数据 + 我们的序列执行器**（M4b），**不直接跑 PlayableDirector** | 状态同步下表现要"快照驱动 + 和解重对齐 + `silenceUntilFrame` 防重播"，Timeline 的"播放一段演出"模型与之摩擦；时钟分轨（UIClock/WorldClock/时停）也需额外桥接 |
| **非对局演出**（剧情/加载/结算/单机 demo） | **可直接跑 PlayableDirector** | 无回滚/重对齐问题，白拿 Timeline 播放能力 |
| **骨骼 / 属性动画** | 由 **Animator / Animation**（或 Timeline 的 Animation Track 驱动）执行 | 与《动效设计方案》§1 一致；资产随 YooAsset 热更 |

**表结构与序列化（定案）**：
```
tb_timeline: id | name | frames(总帧长) | consumer(skill/view/both) | tracks(时序列紧凑串)
   → Sim 只读「判定轨」动作点（consumer 含 skill）
   → 表现层只读「表现轨」动作点（序列执行器 + UiFx 消费）
tb_action_num: id | 冷却帧 | 前摇帧 | 伤害系数 | 半径 | …   ← 数值真相（策划面，可手改）
```
- **时序列紧凑串 schema**（导出器产出，`tb_timeline.tracks` 列）：`帧:轨类型:参数;帧:轨类型:参数…`
  例：`0:judge:r=2.5;12:fx:hit_a;18:anim:attack_a`
- **单表的意义**：判定与表现在**同一条时间轴**上对齐（不会"判定 12 帧、表现 18 帧"错位）
- **数值与时序分离**：数值改动只碰 `tb_action_num`（不必开 Unity）；时序改动只碰 TimelineAsset（不必碰数值表）——两边的编辑者互不干扰
- **原"取消 SO 中间态"的理由仍然成立**：SO 与表写**同一份完整数据** = 影子真相；现在时序与数值是**两类数据两个家**，各自单一可写来源，不构成分叉

### 3.4 导出时校验（每条配负例用例）

1. **秒 → 帧对齐**（§3.1 硬规则：`|秒×60 − round(秒×60)| < 1e-4`；不满足即拒并给出实际秒值）
2. 判定点必须落在整数帧且 ≤ 总帧长（总帧长 = Timeline 时长取整）
3. 引用完整性：特效名 / 音效名 / AnimationClip 名 / Animator 状态名 / 表 id 存在
4. 必填参数缺失（冷却、前摇、判定半径）
5. 语义规则（阈值可配）：冷却 ≥ 前摇 + 最短判定窗口
6. 同类判定同一帧冲突 / 动画轨状态同帧重复写入
7. **引用对账**：Timeline 引用的数值键必须在 `tb_action_num` 存在（防孤儿数值 / 防数值键写错）

### 3.5 一键导出与"改完立马生效"（2026-09-14 需求落点）

**一键导出**（菜单按钮 + **TimelineAsset 保存时自动触发**，`AssetPostprocessor` 监听变更）：

```
[一键导出]
 ① 全部校验通过（§3.4 七类；不过则不落盘、不导出）
 ② TimelineAsset → tb_timeline.tracks 时序列（覆盖写，标注"勿手改"）
 ③ 调 Luban 生成（同 gen.bat 的 client+bytes 两步；编辑器内以进程调用）
 ④ AssetDatabase.Refresh（.bytes 变更被 YooAsset 编辑器文件系统直读）
 ⑤ 热生效：非对局态 → 立即重载；对局中 → 提示"下一局生效"
```

**"改完立马生效"的两条通道与一条硬约束**：

| 场景 | 生效方式 |
| --- | --- |
| **非对局态**（编辑器 / 主菜单 / 未开始对局） | **立即生效**：`IConfigService.ReloadAsync()`（清缓存重建 Tables）→ 技能系统重取表 → 表现层刷新；若 Lua 侧有消费（技能描述/UI 图标）→ 顺带触发 DevReload（Ctrl+Alt+R，M3 已交付） |
| **对局中** | ⚠️ **不允许热重载**——技能表参与 Sim 判定，对局中换表会破坏**确定性**与两端一致（客户端与服务器读的表不再是同一份）。提示"已导出，**下一局生效**" |
| **骨骼/属性动画改动** | 随 YooAsset 热更链路（AnimationClip/Controller 资产），与本导出管线无关 |
| **真机** | 走 M6 热更闭环（Luban 表本就是 binary 热更链路的内容）——本条只覆盖编辑器内迭代 |

**必须落到 M8 的纪律（否则热重载会埋雷）**：
1. **技能表消费点不缓存 `Tables` 引用跨对局**——统一经 `IConfigService.Tables` 取（对局开始时可快照到对局上下文，对局结束后丢弃）
2. **`ReloadAsync()` 需与 DevReload 同款"清理顺序钉死"**：清配置缓存 → 重建 Tables → 通知消费点（技能系统/表现层）→ 再放行新对局
3. **对局态守卫**：热重载入口检查当前流程状态，非对局态才放行（对局中点击只提示，不静默生效）
4. 与 M3 的 DevReload 分工：DevReload 管 **Lua 侧**，本文的导出后重载管 **C# 表侧**；两者可串联（技能描述在 Lua、判定在 C#）

### 3.6 预览

- **Timeline 窗口自带预览**（拖时间轴即时看角色动画/属性动画/事件）——**采用 Timeline 的最大体验红利，无需自研**
- **判定范围/命中窗可视化叠加（可选增量）**：`OnSceneGUI` 在场景视图叠加判定框（灰盒），复用 Scene View 而非自绘窗口
- **Play 内编辑回写**：M12 可选（工具期），限非对局态（与 §3.5 硬约束一致）

### 3.7 验收

1. 用 Timeline 产出《联机Demo设计》§5 的三个技能：**判定轨（自定义）+ 表现轨（自定义）+ Animation Track（骨骼）+ Signal** 各至少用一次
2. **一键导出**跑通（含保存自动触发）：TimelineAsset 改动 → 导出 → `tb_timeline` 更新 → gen.bat → binary；非对局态**立即生效**、对局中提示"下一局生效"
3. **秒→帧拦截有效**：把 clip 拖到非整帧位置 → 导出被拒并给出实际秒值
4. 七类校验各有负例用例（含引用对账：孤儿数值键被抓出）
5. 同一份时序同时驱动 Sim 判定与表现序列（帧对齐无错位）
6. **联机技能表现不依赖 PlayableDirector**（走序列执行器）；非对局演出可直接跑 Timeline（抽查一条）
7. 产物边界清晰：手改 `tracks` 列会在下次导出被覆盖（提示到位）；数值表手改不受导出影响（不被覆盖）
8. **不自研的收益可核**：整个过程无需自研时间轴画布（拖拽/吸附/预览/曲线全部来自 Timeline）

## 4. 排期与共性纪律

| 编辑器 | 排期 | 前置 |
| --- | --- | --- |
| UI 标记工具（阶段一） | 随《UI控件库Prefab落地规划》同步实施 | 控件模板落地启动 |
| **时间轴编辑器（Timeline 方案）** | **M11 demo 前必须就绪**；启动点 = M8/M9 技能进 Sim 前后。**工作量：自研仅自定义轨（≈300-500）×＋导出器（≈200-300）＋校验（≈150）≈650-950 行，一次性**（无画布维护） | `tb_timeline`/`tb_action_num` schema 定案（《联机Demo设计》§5）；表现侧消费者 = M4b 序列执行器（已交付） |
| UI 编排器（阶段二） | M11 前后 | 标记工具 + 控件模板库就绪 |

**消费者全景**（共用编辑器的正当性）：①**Sim**（技能判定轨，M8）；②**表现层**（技能特效/音效/属性轨，M11）；③**剧情演出**（事件轨 + 属性轨，M5′ 纵向切片）；④**UI 动效**（属性轨，可替代部分手写 DOTween 编排）——四处共用同一份时间轴数据与同一套运行时执行器。

**共性纪律**：
- 编辑器产物**全部走既有生成链**（Luban / gen.bat / 绑定索引），不做编辑器私有运行时格式
- 编辑器不得成为纪律的例外通道：产物与手工产物受同样校验（索引可生成、整数帧、无裸引用）
- 编辑器不引入新运行时依赖（纯 Editor 程序集）；**Odin 只在 Editor 侧**（附录 B）

## 附录 B：UI 面板技术栈——Odin 选型定案（2026-09-14）

> 决策：**使用 Odin Inspector 实现 UI 编辑器四面板**（用户：已有授权，直接用）。Odin **不提供画布**，故画布决策不变（Prefab Stage 原生，附录 A）；Odin 只加速面板层。

**逐件落法**：

| 面板 | Odin 承载 | 自研部分 |
| --- | --- | --- |
| ① 控件库面板 | `OdinMenuEditorWindow`（菜单树 + 右侧对象预览）+ 动作按钮 | 控件清单来源（扫 `UI/Widgets/` + 校验）、实例化到 Prefab Stage 的动作 |
| ② 标记面板 | 标记组件 Inspector 用 Odin 绘制（`[ValueDropdown]` 类型下拉 / `[Required]` / 分组 / 联动 / 批量改名） | 标记组件本体（运行时，零 Odin）、prefab 级"暴露清单树"扫描 |
| ③ 受控属性面板 | `OdinEditor` + 属性树过滤，只画白名单成员 | 白名单 attribute（**运行时零依赖**）+ 过滤逻辑 |
| ④ 校验与生成面板 | **Odin Validator**（全工程扫描 + 问题列表 + 点击跳转）——**独立付费项**；未购则该面板自研（~200 行） | 校验规则（六类 + 索引/命名规则）、索引与绑定类生成（BindIndexBuilder） |

**硬纪律（隔离）**：
1. **Odin 属性/特性不上运行时组件**——运行时程序集零 Sirenix 依赖（否则 Sirenix 程序集进玩家包，破"运行时零编辑器依赖"）。受控面用**我们自己的 attribute**（如 `[ControlledSurface]`）表达，Editor 侧写 Odin drawer 认它。
2. Odin 只进 `LiteGame.Editor` 的 asmdef 引用（Editor-only）。
3. 校验规则与生成逻辑住我们自己的代码——**摘除 Odin 只换绘制层，不倒架构**。

**依赖登记**：`Odin Inspector`（付费，按席位）→ 团队 + CI/构建机需覆盖；可选 `Odin Validator`（独立付费项，决定 ④ 是否自研）。两者均不进运行时依赖清单。

## 附录 A：UI 编排器画布——全选型清单（2026-09-14）

> 前置约束（决定选型的三个硬条件）：①运行时是 **UGUI + prefab 模板**，画布产物必须是**标准 prefab**且能被 Unity 原生继续编辑；②不引入第二套 UI 运行时；③编排的复杂度主要在"拖入控件模板 + 层级/锚点 + 标记"，**不在通用图形编辑**（锚点/吸附/撤销/多选是 Unity 二十年积累，自研即重造轮子）。

| # | 选型 | 技术要点 | 渲染真实性 | 拖拽/锚点/吸附 | 产物 | 自研成本 | 风险/代价 | 判定 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| A | **UI Toolkit（EditorWindow + UIDocument）** | Unity 官方新 UI；UI Builder 可视化；Editor 内原生支持 | 中（UIToolkit 渲染 ≠ UGUI，需自行保证视觉一致或仅作面板） | 需自研 | 需自研生成 | 中 | 与 UGUI 视觉差异；画布能力要从零写 | 面板层可用，画布层不推荐 |
| B | **IMGUI 自绘**（EditorGUI/Handles） | 手绘矩形 + Handle 拖拽；无依赖 | 中（可画灰盒） | 需自研（吸附/多选/撤销全自己写） | 需自研生成 | 高 | 交互体验难达原生；维护成本高 | 仅适合极小面板，不推荐画布 |
| C | **Scene View 叠加**（`[CustomEditor]` + `OnSceneGUI`） | 在场景视图叠加可视框/锚点/拖拽 handle | **高**（真实 UGUI 渲染） | 复用原生（RectTransform 工具） | 直接改场景/prefab | 中 | 仅做"增强"（如安全区/锚点可视化），不做完整编排 | 可作增强项 |
| D | **Prefab Stage 原生编辑 + EditorWindow 面板**（最小自研） | `PrefabStageUtility` 打开 prefab 独立场景；原生拖拽/锚点/吸附/撤销/多选**全部免费**；EditorWindow 只做控件库面板/属性/标记/校验/生成 | **最高**（100% 真实） | **免费复用** | 标准 prefab | **低** | 拖拽体验是 Unity 原生（非"图形化编辑器"观感）；控件库需以 prefab 素材形式提供 | ★ **推荐（画布层）** |
| E | **RenderTexture 预览**（编辑态渲染真实 prefab 到窗口） | 临时实例化 prefab → RT → EditorWindow 显示 | 高（真实渲染截图级） | 交互映射需自研 | 辅助预览 | 中 | 只读预览，编辑仍回 Unity | 可作编排器内缩略预览 |
| F | **运行时内嵌编辑器**（UGUI 自绘，Play 内） | 编辑器本身用 UGUI 画；所见即所得 100% | 最高 | 需自研 | 回写复杂（Play→编辑态） | 高 | 需打包剥离；数据回写与撤销链路重 | 远期可选（M12 调参类） |
| G | **第三方/外挂 UI 系统**（FairyGUI / DoozyUI / UI Toolkit 运行时 UIDocument） | 引入外部 UI 管线 | 取决于方案 | 免费（各方案自带编辑器） | 外部格式 → 需转换 | 低（买现成） | **与既有 UI 壳/绑定面/控件库纪律冲突**（第二套 UI 运行时）；FairyGUI 尤其会替换整条 UI 栈 | **否决**（与 §1.3 归属纪律冲突） |
| H | **D + A 混合**：Prefab Stage 画布 + UI Toolkit 面板 | 画布用原生（D），控件库/属性/标记面板用 UIToolkit（A） | 最高 | 免费复用 | 标准 prefab | 低-中 | 面板技术栈多一点学习量 | ★ **推荐（组合形态）** |

### 推荐与理由

**选 H（画布 = Prefab Stage 原生编辑；面板 = UI Toolkit 或 IMGUI，实施首步定）；D 是其退化形态（面板用 IMGUI）。**

1. **产物对**：约束②要求标准 prefab，D/H 天然满足；A/B 要自研"画布 → prefab 生成"，等于用自研代码模拟 RectTransform——纯亏。
2. **免费能力**：锚点/边距/吸附/多选/撤销/对齐/像素级预览，全部是 Unity 原生能力，自研无法在合理成本内企及。
3. **我们真正要自研的只有四件**（价值集中处）：控件库面板（拖入模板）、标记面板（BindNode/BindRoot）、属性面板（受控 API 子集）、校验与一键生成——**这四件才是本项目独有的**。
4. **体验诚实说明**：H/D 的观感是"Unity 原生编辑 + 专用面板"，**不是** FairyGUI 式的全屏图形化编辑器——这是刻意的取舍（少造轮子、产物标准）。
5. **E 作为辅助**：编排器内做缩略预览（RT）成本低、体验好，列为可选增量。
6. **F/G 否决理由**：F 的回写/撤销链路重且需打包剥离；G 引入第二套 UI 运行时，与 UI 壳/绑定面/控件库三处纪律正面冲突。
