## 1. 目标终态

**一个机制**：`StageMachine<TId, TReq>`（四个正交维度全部参数化）。

| 退场 | 接任 |
|---|---|
| `Fsm<TOwner>` | `StageMachine<TId, TReq>` |
| `FsmState<TOwner>` | `IStage<TId, TReq>` |
| `ChangeState<TState>()` | `Request(TId, in TReq)` + `Advance()`（两段式） |
| `CurrentState` / `CurrentStateTime` | `Current` / `StageTime` |
| `IProcedureOwner` + `ProcedureOwner`（owner 承载业务状态） | **`TReq` payload**（每次迁移随参数带，见 §5 决策记录） |
| `ProcedureBase<TOwner>` | `ProcedureStageBase<TId, TReq>` |

## 2. 核心 API（Core 新增两文件）

```csharp
// Core/Fsm/IStageHost.cs（2026-09-17 追加：钩子只认这个窄接口，见《层级状态机施工图》§实施记录"契约抽窄"）
public interface IStageHost<TId, TReq> where TId : struct, Enum
{
    bool Started { get; }  TId Current { get; }  float StageTime { get; }
    void Request(TId nextId, in TReq req);   void Request(TId nextId);
}

// Core/Fsm/StageMachine.cs
public interface IStage<TId, TReq> where TId : struct, Enum
{
    void OnInit(IStageHost<TId, TReq> m);
    void OnEnter(IStageHost<TId, TReq> m, in TReq req);     // ★ payload 走参数：不进 owner、不用字典
    void OnUpdate(IStageHost<TId, TReq> m, float elapseSeconds);
    void OnLeave(IStageHost<TId, TReq> m);
}

public sealed class StageMachine<TId, TReq> : ITickable, IModuleStats, IStageHost<TId, TReq>
    where TId : struct, Enum
{
    public StageMachine(string name, params (TId id, IStage<TId, TReq> stage)[] stages);

    public TId Current { get; }
    public bool HasPending { get; }
    public TId PendingId { get; }
    public float StageTime { get; }
    public long TransitionCount { get; }

    public void Start(TId initialId);                        // 一次；全部 stage 先 OnInit
    public void Request(TId nextId, in TReq req);            // 只入队（last-wins，payload 同时覆盖）
    public void Request(TId nextId);                         // = Request(nextId, default)
    public void Advance();                                   // 应用队首：OnLeave → OnEnter(in req)
    public void Tick(float realDelta);                       // OnUpdate + 有挂起 → Advance
}
```

```csharp
// Core/Fsm/ProcedureStage.cs（流程基类：保留"可取消 RunAsync"语义）
public abstract class ProcedureStageBase<TId, TReq> : IStage<TId, TReq> where TId : struct, Enum
{
    public virtual void OnInit(StageMachine<TId, TReq> m) { }
    public void OnEnter(StageMachine<TId, TReq> m, in TReq req)   // sealed：进流程即建 CTS + RunAsync
        => RunAsync(m, req, StartCts());
    public void OnLeave(StageMachine<TId, TReq> m)                // sealed：离场即 Cancel + Dispose
        => CancelCts();
    public virtual void OnUpdate(StageMachine<TId, TReq> m, float dt) { }
    protected abstract void RunAsync(IStageHost<TId, TReq> m, in TReq req, CancellationToken ct);
    protected void Fail(StageMachine<TId, TReq> m, Exception ex, string where);  // Log.Fatal + 由业务 Request(Error, args)
}
```

## 3. 语义契约（**7 条既有语义逐条保住** —— 迁移的红线）

| # | 既有语义（`FsmTests` 用例） | `StageMachine` 如何保 |
|---|---|---|
| 1 | `Start` 触发 OnEnter；**未 Start 时 Tick 静默** | 同：`_current == null` → Tick 直接 return |
| 2 | 迁移在 **OnUpdate 之后**、帧末应用；`StageTime` 归零 | 同：`Tick` = `OnUpdate` → 若有挂起则 `Advance`；`Advance` 末尾 `_stageTime = 0` |
| 3 | 同帧多次请求 **last-wins** | 同：`_pendingId`/`_pendingReq` 覆盖式写入 |
| 4 | `OnEnter` 内请求 → **挂到下次 Advance**（期间收到一次 OnUpdate） | 同：`Advance` 内 `OnEnter` 里再 `Request` 写 pending，不递归 |
| 5 | **重入禁止**（请求 = 当前）→ 抛 | 同 |
| 6 | **`OnLeave` 期间改道 → 抛** | 同：`_inLeave` 窗口内 `Request` 抛 |
| 7 | **未注册 id → 调用时当场抛**（不等帧末） | 同：`Request` 内查表 |
| +8 | （新增）**payload 随迁移传递**：`OnEnter` 收到的是 `Request` 时给的 `req` | `_pendingReq` 字段随 `_pendingId` 一起交接 |
| +9 | （新增）**两段式**：`Request` 后不迁移，`Advance()` 才迁移（SignalDriver 就是"调用方自己调 Advance"） | — |
| +10 | （新增）payload 也 **last-wins** | 同 #3 |

**异常策略内核不管**（保持旧 `Fsm` 的"回调不 try/catch"）：流程侧靠 `ProcedureStageBase` 的 `RunAsync` 内部 try/catch；转场侧将来由驱动层捕获 + 超时。这是设计里的"策略注入点"，本图不动。

## 5. 决策记录（本轮定案）

1. **状态标识用枚举（`TId : struct, Enum`）而非类型**：类型作状态标识无法携带 payload（只能靠 owner 字段或字符串键字典，后者**你们已删**）。改枚举后 `ChangeState<T>()` → `Request(TId, in TReq)`。**状态逻辑仍写成类**（`IStage` 注册表，键从 `Type` 变 `TId`），现有 4 个流程类**保留类形态**，改动只是注册键 + 钩子签名。
2. **`IProcedureOwner` + `ProcedureOwner` 退休**：owner 的原始用途是"框架不承载业务状态、业务字段放业务 owner"（2026-09-10 泛型化决策）。**payload 参数更彻底地实现了同一意图**——每次迁移的数据随参数走，且是**编译期强类型**（不是 owner 上一堆可能为 null 的字段）。`LastError` 的职责由 `ProcedureArgs.Error` 承接。
3. **`Request`/`Advance` 两段式**：请求只入队、迁移点独立。这一条是让"队列推进"绕开 `OnLeave` 禁改道窗口的关键（旧 `Fsm` 的队列推进无处安放），也为将来的 `SignalDriver` 留好口——**它不需要新类，`Advance()` 已是公开入口**。
4. **异常策略留内核外**：内核不 try/catch（保旧语义），流程侧由 `ProcedureStageBase.RunAsync` 自己兜，转场侧将来由驱动层兜 + 超时。

## 10. 能力分层（2026-09-17 追加：状态机家族现在的形状）

**背景**：ARPG 形态扩展初版把抢占/恢复直接塞进 `StageMachine`，使其承载两套关注点。用户质疑"是不是太复杂了，
要不要抽内核做流程机 API 与有限机 API"——评估后**不抽内核**，改做**能力分层**（判据见下）。

### 10.1 家族三件（选型一句话）

| 类型 | 装什么 | 用在哪 |
|---|---|---|
| `StageMachine<TId,TReq>` **基础机** | 状态表 / 迁移 / 守卫 / 计数 / `StageFrames` / 表驱动配套。**4 个入口**：`Start` / `Request` / `Tick` / `IStage` | 流程 / UI / 转场 / 界面外流程 |
| `PreemptiveStageMachine` **抢占机**（子类） | + 优先级抢占 / 中断规则 / 恢复栈 / `priorityOverride` | 角色 / 动作（格斗、ARPG） |
| `HierarchicalStageMachine` **层级机**（独立） | 层级 / 历史 / 冒泡（迁移 = **LCA 事务**） | 界面内多段流程、压制-恢复类表现 |

配套件：`StageSpec` + `TableStage`（表驱动，"状态多而规则同构"时用）、`IStageHost`（钩子只认它）、`IEventSink<T>`（冒泡）。

### 10.2 为什么不抽"同一份内核 + 两套 API"（判据）

| 能抽的 | 抽不动的 |
|---|---|
| 骨架：阶段表注册与校验、pending/last-wins、`Advance` 应用、四条守卫、`StageTime`/`StageFrames`/计数（**约 60–80 行重复**） | **算法**：基础机迁移 = 一次退一次进；层级机迁移 = LCA 事务（N 退 M 进、可中断）；抢占机还要过准入判定 |

**判据：当两件的差异在"算法"而非"骨架"时，抽内核收益低** —— 省 80 行，代价是"策略间接层 + 全量重跑 190+ 用例 + 两份语义文档合并"，而 flat/HSM 现在各自语义清晰、测试独立。

**替代做法（已落地）**：① **能力分层**（抢占/恢复抽子类；基础机只多 3 个扩展点：`CanAccept`/`OnStagePreempted`/`EnqueueRequest`）；② **文档按"基础 API / 扩展 API"分级**（本表即入口）；③ 若将来只需要"两套 API **名字**"，用**薄门面**（编译期转发，零重复、零间接），而不是抽内核。

### 10.3 重新评估内核抽取的触发点（写下来，现在不做）

- 基础机能力再涨 30% 以上（继续堆），或
- 层级机也要抢占/恢复（那时两者算法开始趋同），或
- 出现**第三个**需要第三套语义的消费者。

### 10.4 能力登记（2026-09-17 缺口盘点后的结论）

**已补（本轮）**：
| 能力 | 落点 | 语义 |
|---|---|---|
| **`Reset()`**（基础机虚方法 / 抢占机清栈 override / 层级机深→浅收尾） | 三件都有 | 停止并回到**未启动态**（可再次 `Start`）：对当前阶段调 `OnLeave`（与 `Start` 的 `OnEnter` **对称**，让阶段收尾），清挂起/计时/计数；**钩子抛异常也保证复位**（`finally` 清理，异常继续传播） |
| **`LastReject` + `RejectReason`** | 基类字段（谁都可读）＋抢占机上报 | **只描述"正常路径的拒绝"**（编程错误仍抛）：`Priority` / `InterruptDisallowed` / `ResumeStackEmpty` / `ResumeAlreadyCurrent`；被接受则回 `None`（恒反映最近一次）。用途：ARPG 调"技能为什么放不出来" |

| 3 | **标签查询 `Tags`**（"是否属于某类状态"） | AI/表现层高频问"是不是在攻击/受控类状态" |
| 4 | **机器组**（统一 tick 顺序 + 仲裁） | 一个实体挂多台机器（正交轴的正解）时 |
| 5 | **迁移历史**（最近 N 次，Debug 三宏下启用） | 状态机出 bug 时"它怎么跳过来的" |

**明确不做（别当缺口补）**：
| 不加 | 理由 |
|---|---|
| **并行状态 / 正交区域** | 用**多机器 + 机器组**替代（即待补 #4）；并行区域会把 tick/仲裁/快照全复杂化 |
| **黑板 / 字符串键数据字典** | 项目**已删过一次**（零编译期检查 + 装箱 + 静默 cast）；跨阶段数据走 payload 或宿主字段 |
| **线程安全** | 主线程 only 是项目纪律 |
| **可视化状态图** | 属编辑器范畴（《编辑器设计规划》） |
| **HSM 上的抢占/恢复** | 刻意不组合 —— 跨层事务 × 抢占栈 × 历史 × 冒泡会爆炸（§3 判据）；真出现"分层流程被中断后要恢复"的需求时再单独评估 |
