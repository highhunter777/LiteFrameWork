### 2.1 vendor 与工程骨架（~0 代码，纯装配）

`Assets/LiteNet/Vendor/{kcp2k, Google.Protobuf}`；`LiteNet.asmdef`（`noEngineReferences: true`）；`Assets/LiteNet/LiteNet.csproj`（双轨，`Directory.Build.props` 重定向 `.dotnet/`）；`RoomServer/RoomServer.csproj` + `Tests/LiteNet.Tests/LiteNet.Tests.csproj`；`.gitignore` 白名单三行；HybridCLR 排除清单登记 `LiteNet`。

### 2.2 协议定义与生成（`Proto/`，~120 行 .proto + 生成物）

消息面按 §4.5 协议矩阵；`Input(frameNo, wire[≤4 帧冗余], ackSnapshot, viewFrame)`；`StateSnapshot(frameNo, slotDeltas[] 或 fullState, checksum, ackInput, isFull)`。`scripts/gen-proto.ps1` 固定 protoc 版本；生成物入库。

### 2.3 `Protocol/`（~250 行）：打包解包纯函数

InputWire 打包（最近 4 帧冗余）、快照解包、信令序列化——零 IO 零状态零 kcp2k 依赖（决策 #4）。**用例**：往返序列化逐字节一致；冗余解包取最新有效帧；坏包丢弃不抛。

### 2.4 `Transport/` + 契约（~350 行）

kcp2k `KcpPeer` 收发、双通道分流、冗余发送、Session（心跳/超时）；`INetworkService`（§7.1 原文 ~30 行，接口在 `LiteFramework.Unity`，枚举 `NetState/NetChannel` 在 Core）。

### 2.5 RoomServer 会话与房间（~300 行）

Acceptor（握手→cookie→token/buildHash 校验→Session）、SessionManager（心跳/超时踢除/断线标记）、RoomManager + Room（成员表 playerId↔session）。E3 加固 + E1 队列上限骨架。
**批内必做（2026-09-17 盘点登记）**：①**假传输/假会话测试驱动**（无头客户端在第四批，本批用例必须靠 `IRoomTransport` 的测试实现 + 脚本输入注入，否则"60Hz 权威局"无从验收）；②**E1 数值落定**（队列上限、三档降级阈值——§10-E1 只给了顺序）+ **Ops 指标输出形式**（控制台周期打印？频率？指标集？）。

### 2.6 权威循环（~200 行）

`FrameAggregator`（`PeriodicTimer` 60Hz）：聚合（缺席沿用空输入）→ `SimStep.Step` → 服务端快照环 `Capture`（`LagCompHistory`）→ SnapshotDiffer → Broadcast。输入传输层校验（每帧≤1 条/玩家、ackSnapshot 单调且 ≤ 已广播帧号、非法帧号丢弃）——**Clamp 口径**：非法只丢弃不改写（拒绝会引发预测分叉，见《角色状态与动作实现设计》§4.2⑤）。Ops 控制台指标（帧号/房间数/快照均长/丢包率/和解率汇总，输出形式见 §2.5 登记）。
**广播用 `ISnapshotSource`**（本批注入 `FullSnapshotSource` 全量占位；第三批换 `SnapshotDiffer` 增量，循环零改动）；**`SimConfig.SnapshotHz=30`** 控制抽帧节拍。

### 2.7 SnapshotDiffer + AOI（~300 行）

上一广播帧副本对比 → 变化槽位 → 量化 zigzag；全量兜底（每 60 帧或 ack 落后）；AOI 网格过滤（旋钮）。**用例**：增量→全量往返一致；静止场景增量趋零；AOI 开/关判定结果一致。

### 2.8 回溯判定（~150 行）

开火输入带 `viewFrame` → 环回溯 → `ShootingSystem.Run` 单系统执行（历史态）→ 命令与帧事件**丢弃**（回溯只判命中，不结算当帧——结算在权威当前帧消费该判定）→ 恢复当前态。**用例**：150ms 模拟下"命中开火者所见位置"（§9 验收用例）；`LagCompHistory=0` 退化。

### 2.9 客户端接缝（~400 行）

`RoomClient`（连接/收发/冗余/ack 上报）；`RollbackSim.OnAuthoritativeSnapshot`（~120 行：环内同帧 checksum 比对 → 不符 → Restore 权威 → 重放本地历史 → `OnReconcile` 计数）；`MismatchReport` 上报；`KcpNetworkService : INetworkService`（LiteGame 桥接，本批只求编译通过）。**用例**：注入快照不一致 → 和解后与真值一致；快照超前（halt 态）→ 直接覆盖续跑。

### 2.10 损伤模拟与无头对跑（~250 行 harness + 验收组）

`LoopbackDamageSim`（延迟/丢包/乱序注入）；无头客户端（脚本输入 + RollbackSim）；验收组见 §3。

## 3. 测试与自测策略

| 组 | 用例 |
| --- | --- |

## 7. 边界与风险

- **不越界**：不做 Unity 视觉装配（M11：`SimView`/插值接线/`PlayerController`/场景）、不做重连客户端流程与断线重进体验（M11，服务器能力已备）、不做 MatchMaker（MVP 固定房间号/好友码）、不做 E2 快照优先级（M10 后调优）、不做 Gate/Sim 拆分与 I/O 线程（触发条件未命中）、不做帧同步预案（判据未触发）
- **风险 1：和解率底噪**——M8 实测 Mono/.NET 1-ULP 差异意味着 Unity 客户端预测与 .NET 服务器**必然周期性和解**；无头验收（全 .NET）无此底噪，M11 demo 需重新观测并记基线。**对策**：和解率是质量指标非正确性前提（快照覆盖兜底）；预期写进 Ops 文档，勿在 M11 把底噪当 bug 排查
- **风险 2：kcp2k 版本漂移**——vendor 版本锁定并记录；升级按 vendor 目录整体替换 + 回归对跑
- **风险 3：protoc 工具链依赖**——生成物入库后运行期零依赖；生成脚本注明 protoc 版本，避免本机环境差异
- **风险 4：双轨 csproj 维护**——`RoomServer`/`LiteNet.Tests` 的 `Compile Include` 随新文件漂移。**对策**：按既有模式用通配 Include + 纪律测试钉死（缺文件即编译失败）
- **风险 5：`PeriodicTimer` 节拍漂移**——60Hz 长跑累积误差。**对策**：绝对时间锚定（nextTick = start + n×dt，不 tick+=interval）；对跑验收 5 分钟帧号线性度即检验
- **风险 6：回溯判定与当前帧结算的双路径**——回溯只出命中结论，结算必须回到当前帧，两路径不一致会产生"幽灵命中/漏判"。**对策**：回溯产物只进当前帧的命令缓冲，用例钉死（150ms 用例 + 0ms 等价用例）
- **风险 7：协议单源红线回潮**——任何"服务器侧另写一个消息结构"的诱惑即违规。**对策**：RoomServer csproj 直接 Compile Include `LiteNet/Protocol`，物理上双写不可能

1. **`FrameDriver` 不能用于网络对跑**——它是渲染帧驱动（按真实 dt 追帧/丢帧），无头客户端与服务器用它会帧号漂移（实测：服务器第 k 帧用的输入，客户端是第 k+1 帧用的）。**修**：新增 `FramePump`（定次 1:1），服务器/无头客户端一律用它。
2. **AOI 网格静态缓存串味**——只按帧号失效 → 多房间/多测试世界在同一帧号互相污染（实测：并发用例可见集合混入别的世界的实体）。**修**：网格归 `AoiFilter` 实例所有（每房间一份），键 = (世界实例, 帧号)。
3. **多客户端共用一个差分器**——每客户端各调一次 `Build` 会推进金标，第二个客户端恒发空增量（实测 116/144 次退化为全量）。**修**：两段式 API（`BeginFrame` 每帧一次 / `BuildFor` 每客户端纯读）。
4. **"全局状态变了吗"不能用 checksum 直接比**——checksum 含 **Frame**，帧号每步都变 → 每帧都判"变了"（实测表现：永远全量）。**修**：探针改比 `RngState` + Globals + CustomData（摘要外的量），且基准**每帧**推进（含全量帧，否则首帧后基准停在初始值，次帧必误报）。
5. **`viewFrame` 语义**——按《状态实施方案》§3.4.1 原文 = **客户端所见的权威帧号**（ackSnapshot 对应权威帧 + 插值帧，已是服务器帧轴的值）。服务器只做两件事：减插值量、clamp 到 `[当前帧 − LagCompHistory, 当前帧]`。曾实现为"用服务器当前帧 − ack 作偏移再对齐"，多减了一层（实测回溯帧恒等于当前帧 → 全部退化）。
6. **测试辅助函数的 EntityId 缺省 0** —— `SimInputFrame.EntityId` 缺省 0 会被 `TryResolve` 判失效实体**静默丢弃**，导致多条用例空转（"位移 0 也判过"）。**修**：所有合成输入一律显式带 `EntityId`，并在 helper 注释里写明。
7. **`gen-build-hash.py` 收录了 Editor 目录**——`Scripts/Editor/**` 不在双端共同编译源集（csproj 显式 Exclude），喂进 hash 会让"给菜单加一行注释 = 全体握手被拒"。**修**：生成器与 `BuildHashTests` 的跳过列表加 `Editor`。
8. **`.gitignore` 缺 `__pycache__/`**（跑生成器产生）——已补规则。
9. **`ServerLoop` 常驻模式缺追赶上限**（复盘发现）——`LoopBody` 落后时无界连跑 = 过载即持续满核。**修**：两形态统一"**有界追赶 + 丢债记账**"（超 <see cref="MaxCatchUp"/> 即把债从锚点时间轴上减去，计入 `DroppedTimeMs`/`CatchUpAbandoned`，Ops 行可见），并加注入点让"过载 → 有界"可被用例驱动（`ServerLoopTests.过载时_追赶有上界并记账丢债_不会无界满核`）。
10. **锚点换算走 double**（同批复盘）——`tick * 1000.0 / 60` 每帧一次浮点乘法，长期运行（数天）后 tick 很大时有累积舍入风险。**修**：整数锚点 `TickPeriodMs = 1000/60 = 16`（锚点纯整数运算），丢掉的 0.67ms/帧由**有界追上**补回——帧率长期精确、代价可观测。

**已知项（批④/M11 处理，非遗漏）**：
- **AOI 移出补发**：槽位移出可见集时客户端保留旧值 → 残影/陈旧位置，由 1s 周期性全量兜底纠正。批④ 对跑可观测（如需精确，加"移出即补发一次"）。
- **全量帧是整帧属性**：某客户端触发全量（重连/ack 落后）时，本帧对房间内所有客户端都发全量（差分金标需一义）。1s 周期兜底本就会发生，代价可接受。
- **客户端→服务器的 `ack_input`** 用"最近接受的输入帧号"（`InputGate.LastAcceptedFrame`）——语义是"你的输入到了"，不是"已消费帧"；回滚判定以真实输入帧号为准。

| **S2** | **`ackInput` 语义与校验自相矛盾（真 bug）** | 服务器下发 `ackInput = LastAcceptedFrame`，而 inputDelay=1 下它通常 = **服务端帧+1**；客户端原样回传后，收包校验 `AckSnapshot > serverFrame → 丢整条输入` → **合法输入被自己的 ack 丢掉**（服务器只能用空输入推进该帧）。与 §3.4.1「ackSnapshot ≤ 服务器已广播帧号」也不符 | ①下发口径改为 `min(LastAcceptedFrame, 快照帧)`；②收包越界 ack **只计数 + 钳位，不再丢输入**（ack 是元数据：判定不消费它，回溯窗口由 `LagCompensator` 自行 clamp）→ 新增 `LastClampedAckSnapshot` 供审计 |

| **S4** | **已消费帧被接受 → 永久滞留（内存有界性）** | `Store` 的向下搜索可接受 `frame ≤ serverFrame` 的帧（已步进、永不再 `TryConsume`）→ 存进 `_pending` 就再也不出来 | 收紧为只接受 `frame > serverFrame`，新增计数 `DroppedStaleFrame` |

### 2026-09-19 — 传输窄端口收口（IRoomTransport 从"装饰"变"真在用"）

**背景（审查发现）**：设计 §4.6 的"可替换性第二刀"写了 `IRoomTransport` 窄端口，但实测**它只出现在注释里**——
`ServerHost( KcpTransportServer transport, … )` 吃的是**具体类**，接口没有任何实现者之外的使用者 ✗。
于是"换传输 = 只写适配器"这句是**名不副实**的。

**处置**（纯类型替换，零逻辑改动）：
- `ServerHost` 字段与构造参数 → `IRoomTransport`；实测它只用到窄端口的 **3 个事件 + Start / TickIncoming / TickOutgoing / SendTo / Dispose**（`Broadcast/Disconnect` 未用），端口**够用、无需扩**。
- 类注释写明**所有权**：宿主**接管**传输（构造即 `Start`、`Dispose` 即释放）——与 `RoomClient`（不接管、退订即走）刻意不同，因为服务端的装配者是 `Program`/测试，谁创建谁交给宿主。
- 调用点**零改动**（具体类 → 接口是隐式转换）✓。

**可替换性自证（用例 3 条，`ServerHostTransportTests`）**：
1. **假传输换实现跑通全链路**：装配（`Start(port)` 被调用）→ 两个连接 → 两次 Join（JoinAck/票据/成员表）→ **满员自动 StartGame 并广播给两人** ✓
2. 版本红线与输入路由不因换传输而失效：buildHash 不符 → 无 JoinAck + `Ops.Rejects=1`；正确 hash → 放行 + `Pump()` 不抛 ✓
3. 所有权：`ServerHost.Dispose()` → 假传输 `Disposed=true` ✓
> 关键点：假件**只实现窄端口**——若 `ServerHost` 用到端口外的任何东西，这个假件根本编译不过。**解耦度自证**，不靠人读代码。
