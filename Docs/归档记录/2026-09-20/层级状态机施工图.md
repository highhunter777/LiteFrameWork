# 层级状态机（HSM）施工图

> 2026-09-17。**用户拍板三决策**：① 场景 = **流程线 + UI 都要**（框架层给"复合态"能力）② 语义 = **完整 HSM**（浅/深历史 + 事件冒泡）③ 跨层迁移 = **路径式自动降升**（框架算共同祖先，调用方只给目标 id）。
> 前置：通用阶段状态机（`StageMachine`，同日 A 路线交付，见《通用流程状态机施工图》）——HSM **共享同一份 `IStage` 契约与语义**，不是第二套概念。

---

## 0. 定位：扩展而非替换

| | 平面机 `StageMachine<TId, TReq>`（已有） | 层级机 `HierarchicalStageMachine<TId, TReq>`（新增） |
|---|---|---|
| 状态空间 | 平铺，一层 | **树**（复合态可含子层，任意层） |
| 一次迁移 | 一进一出（一帧最多一变） | **一次迁移事务**（LCA 之下 N 次 exit + M 次 enter，同帧原子） |
| 历史 | 无 | 复合态可选 `None / Shallow / Deep` |
| 事件 | 无 | `Raise<TEvt>` 从最深活动态向根冒泡，首个 `IEventSink<TEvt>.TryHandle` 返回 true 即停 |
| 关系 | **flat = HSM 的退化形态**（无复合态时行为应一致，有对拍用例证明） | 超集 |

**为什么不把 flat 直接删掉改成只剩 HSM**：flat 已验收（11 用例绿）且写法最简；HSM 的"树/历史/冒泡"对单层用户是纯负担。两者是**同一契约的两个配置**（类似 `List` 与 `Dictionary`），不是两个机制。**将来统一判据**：若流程线/UI 全部迁到 HSM 后 flat 无消费者 → 再让 flat 退场（那时它的 11 条语义已被 HSM 的对拍用例覆盖）。

## 1. 对外形态

```csharp
// 复合态声明（纯描述，与"谁实现钩子"解耦）
public enum HistoryMode { None, Shallow, Deep }
public sealed class CompositeSpec<TId> where TId : struct, Enum
{
    public CompositeSpec(TId id, TId initialChild, HistoryMode history, params TId[] children);
    // 只读：Id / InitialChild / History / Children
}

// 事件接收位（可选实现；不实现 = 不处理事件，现有阶段零改动）
public interface IEventSink<TEvt> { bool TryHandle(in TEvt e); }

public sealed class HierarchicalStageMachine<TId, TReq> : ITickable, IModuleStats
    where TId : struct, Enum
{
    public HierarchicalStageMachine(string name,
        (TId id, IStage<TId, TReq> stage)[] stages,   // 全部阶段（含复合态自身的钩子实现）
        CompositeSpec<TId>[] composites);             // 树的形状（几个复合态、各自子集/初始子态/历史模式）

    public bool Started { get; }
    public TId Current { get; }                       // 最深活动态
    public IReadOnlyList<TId> ActivePath { get; }     // 根 → 最深活动态
    public bool HasPending { get; }
    public TId PendingId { get; }
    public float StageTime { get; }
    public long TransitionCount { get; }              // 迁移事务计数（不是层数）

    public void Start(TId root);
    public void Request(TId target, in TReq req);     // 只入队（last-wins）
    public void Request(TId target);
    public void Advance();                            // 应用挂起 → LCA 事务
    public void Tick(float realDelta);                // OnUpdate 根→叶 + 有挂起则 Advance
    public bool Raise<TEvt>(in TEvt e);               // 叶→根冒泡
}
```

**建树校验（ctor 内当场抛）**：children 必须在 `stages` 里；每个非根阶段至多一个父（无环）；`InitialChild` 必须是自己 children 之一。
**允许多根**（实施期调整）：流程线的 `Launch/Preload/Main/Error` 是**平级根**，强制单根会逼它们外面包一层虚拟根（多余仪式）。多根下的**跨根迁移 = 全退全进**（LCA = 0），语义与"两个独立子树的切换"一致；`Start(任意根)` 均可，`Roots` 可读。

## 2. 语义钉死（HSM 的十条）

| # | 语义 | 说明 |
|---|---|---|
| H1 | **enter 顺序：浅 → 深**（父先子后） | `Start`/事务进入都如此 |
| H2 | **exit 顺序：深 → 浅**（子先父后） | 事务退出如此 |
| H3 | **OnUpdate 顺序：根 → 叶** | 父先子后，每帧对活动路径逐层调用 |
| H4 | **跨层迁移 = 一次事务**：`Request` 后由 `Advance` 应用，同帧原子完成 LCA 之下的全部 exit/enter | 对应 flat 的"帧末应用"；**flat 的"一帧最多一变"在 HSM 改写为"一帧最多一次事务"** |
| H5 | **LCA 自动降升**：`target` 的路径由树反查；旧路径与新路径的共同前缀即 LCA，LCA 之下先退后进 | 调用方只给目标 id，不给路径。**跨根**（两个平级根之间）LCA=0 → 全退全进 |
| H6 | **降层不重跑祖先**：`target` 若已在活动路径上（祖先或当前）→ 只 exit 到它（不重跑它的 `OnEnter`）；`target == Current` 仍按重入抛 | 重跑祖先 `OnEnter` 会重复初始化（如 Main 的常驻壳） |
| H7 | **显式目标优先于历史**：`target` 明确给出的层级一律按显式路径；**只有进入复合态后未指定的更深层**才用历史/初始子态 | 例：`Request(Result)` 不会因为 Battle 有历史就改道 |
| H8 | **历史**：复合态在**退出时**记录子路径（`Shallow` 只记直接子态，`Deep` 记整条子链）；重进时优先按历史展开，历史已被显式路径覆盖的层级不再回放 | 深历史在浅层之后继续用历史链、穷尽后退回 `InitialChild` |
| H9 | **冒泡**：`Raise<TEvt>` 从最深活动态向根逐层问 `IEventSink<TEvt>.TryHandle`，首个 true 即停并返回 true；全 false 返回 false | 未实现该接口的阶段自动跳过（零改动） |
| H10 | **7 条传统语义全部保留**：未 Start 时 Tick 静默 / 未 Start 时 Request 抛 / 未注册抛 / 重入抛 / `OnLeave` 期间 `Request` 抛 / 同帧 last-wins / `OnEnter` 内 `Request` 挂到下次 `Advance` | 与 flat 逐条对齐，**有对拍用例** |

**payload 语义**：一次事务内**每一层 enter 都收到同一个 `req`**（简化：不为每层单独造 payload；需要分层数据时由阶段自己从 `req` 取所需字段）。

## 3. 异常与中断（不引入回滚）

- 钩子异常**内核不捕获**（沿 flat 与旧 Fsm 的"脊柱炸响"纪律）。
- `exit`/`enter` 链中某步抛 → **立即中止**，`ActivePath` 保留**已完成部分**（已退出的层已移除、已进入的层已加入），并置 `InterruptedDuring`（诊断字段：记录中断时的目标 id 与阶段），异常向外传播。
- **不做回滚**（回滚要 undo 语义，属过度设计）；调用方（流程/UI）看到异常即为"需要人工介入"的信号。文档与 HUD 如实反映 `InterruptedDuring`。

| 批 | 内容 | 验收 |

**测试清单（`HierarchicalStageMachineTests`，≈20 用例）**：
建树校验（子未注册抛 / 重复父抛 / 根不唯一抛 / InitialChild 非法抛）；enter 浅→深 / exit 深→浅 / OnUpdate 根→叶；**LCA 跨层降升**（`Main.Battle.Result → Main.Lobby`）；降层不重跑祖先；浅历史恢复直接子态、深历史恢复整条链；历史被显式路径覆盖时不回放；`InitialChild` 兜底；冒泡命中最近者 / 未处理返回 false / 中间层处理即停；H10 对拍（帧末应用、last-wins、重入抛、未注册抛、OnLeave 禁改道、未 Start 静默/抛）；异常中断留下部分退出路径；payload 逐层传递同一 req。

## 5. 落地场景（本轮只交能力，不改流程线）

| 场景 | 形态 | 时机 |
|---|---|---|
| **流程线** | `Boot(Launch/Preload)` / `Main(Lobby/Match/Battle(Ongoing/Result))` / `Error`——`Main`、`Battle` 是复合态 | 与 **M10 四批 / M11** 的 `Match/Battle/Result` 同期落地（那批本就要动这 4 个文件） |
| **UI** | 界面内子页/子流程（结算页 统计→翻牌→奖励→确认），界面退出后子态随界面销毁（历史无意义） | 随具体界面落地 |
| **转场** | **不用 HSM**（已定案：事务对象 + `TransitionPhase`） | — |

## 6. 不做（判据留档）

| 不做 | 判据 |
|---|---|
| 状态回滚 / undo | 出现"迁移失败必须原子回退"的真实需求 |
| 并行状态（正交区域） | 出现"两个子层需同时活动且都要 tick"的需求（转场 Replace 用阶段内编排已够） |
| 事件冒泡的"捕获/预处理"（自上而下先过父） | 出现"父层要先拦截子层事件"的需求 |
| 自动迁移表 / 事件→迁移声明映射 | 出现"事件直接驱动迁移"的需求（现在是显式 `Request`） |
| HSM 与 flat 的合并 | flat 失去全部消费者时（见 §0 判据） |

**契约抽窄（实施期决策，务必知道）**：HSM 与平面机的钩子**参数类型天然不同**（`StageMachine<...>` vs `HierarchicalStageMachine<...>`），若直接各写一套 `IStage` 就变成"两份契约、阶段不能复用"——与"flat 是 HSM 的退化形态"直接矛盾。故抽 `IStageHost<TId,TReq>` 让两台机器都实现它，`IStage` 钩子只认宿主；**流程因此可以零改动地在 flat/HSM 之间迁移**（`ProcedureStageBase.RunAsync(IStageHost<...> m, ...)`，四流程只改签名）。机器专属能力（`ActivePath`/`Raise`/`Interrupted`）不进宿主接口（宁窄勿宽），阶段需要时 `m is HierarchicalStageMachine<..> hsm` 显式取用。

**验收数据**：

- **L1 = 250 绿**：LiteFramework **171**（= 上轮 145 + 26 HSM 用例）/ LiteSim 68 / LiteNet 11，0 失败。
- **Unity 编译 0 错误**（completed / failed=false / errors=[]）。
- **Play 冒烟（Test.unity）**：`current=Main`、`switches=2`、`assetInit=True`、`luaMain=True`、**启动后 error 0**。（照上轮教训先跑 `editor_focus`，一次通过。）

**实施期发现的两个真问题（已修 + 进用例）**：

1. **`_inLeave` 窗口过宽**：初版把整段事务（退出 + 进入）都罩在"离场禁改道"窗口里 → **`OnEnter` 内 `Request` 被自己拦掉**（而平面机的语义是允许，因为它的窗口只包 `OnLeave`）。修正：窗口只包**退出循环**。用例 `HSM_OnEnter内请求_挂下次Advance` 钉住。
2. **历史刷新漏了"同父内换子"**：初版只在复合态**被退出**时记历史 → 在 `Main(Lobby)` 与 `Main(Match)` 之间来回切时 `Main` 从不退出，历史不更新，"降层到 Main"会回到**更早**的旧子页。修正：事务末尾对**活动路径上的复合态统一刷新历史**。用例 `HSM_降层到父态_按历史回到上次子页` 钉住。

**中断语义（与初版施工图的差异）**：`OnLeave` 抛异常的那一层**视为"未完成退出"而保留在活动路径**（可重试），已成功退出的层才移除 —— 初稿写的是"已退出的层已移除"，但没说清"正在退出而抛出的层"怎么算。现在钉死为**保留**（保守、可重试），用例 `HSM_事务中途抛_保留已完成部分并标记中断` 覆盖（含"摘掉毒钩子后可继续推进"）。

**多根（与初稿的差异）**：初稿要求唯一根；实施时发现流程线的 `Launch/Preload/Main/Error` 是**平级根**，强制单根会逼它们外包一层虚拟根（多余仪式）→ 改为**允许多根**，跨根迁移即全退全进（LCA=0）。已在 §1 记录。

**未做**：流程线/UI 的 HSM 化落地（见 §5 排期）；§6 的"不做"清单原样保留。
