## 一、必修（M11 开工前）

### 1. `RollbackSim.OnAuthoritativeSnapshot` 和解重放丢失 `_lastInputs` 基线 —— ✅ 已修
- **位置**：`RollbackSim.cs` 和解重放段
- **问题**：Restore 权威 + 重放本地历史后，`_tickInputs`（下帧预测基线）未按重放后的输入链刷新——下一渲染帧 PrepareNext 的"沿用上一帧"取到的是**重放前**的陈旧值（预测与权威基线错位一帧）。
- **影响**：和解后第一帧预测错位（有界、下一快照纠回）——对跑测试未暴露是因为重放输入 ≈ 沿用链。
- **修法（已落）**：两条路径都在状态重立后调用 `PrepareNext(_state.Frame + 1)`——重放路径（与 `ExecuteRollback` 对称）+ 超前/太老覆盖路径（同款对称补全）。
- **修法复核（如实记录）**：核对调用图后确认，**`Tick` 在每渲染帧开头也会 `PrepareNext`**，故该缺口的即时症状被它掩盖（`PrepareNext` 在历史未变时幂等）——因此**该项属"路径对称性 + 未来安全"的防御性修复**（若将来新增 mid-tick 调用点、或 `Tick` 结构改变，缺它即成真 bug），**无法用黑盒用例区分**（公开 API 下两条路径结果相同），故未强行造测试；改为在代码内注释对称性理由。
- **成本**：5 分钟（实际 ~10 分钟含复核）。

## 五、本轮附带发现并修复：L2 门禁的"假绿"口子（2026-09-19）

- **现象**：改完 `RollbackSim.cs` 后 L2 仍报 `recompile_status: up_to_date` + 全部 PASS，但 `Library/ScriptAssemblies/LiteSim.Core.dll`（20:33）**旧于**源码（21:09）——EditMode 用例跑的是**旧程序集**。
- **根因**：外部改 `.cs` 后 Unity 需要 `AssetDatabase.Refresh()` 才会导入；未刷新时 `recompile_status` 报 `up_to_date`，门禁据此判绿 = **假绿**。
- **修法**（`scripts/l2-unity-gate.ps1` 新增第 ③ 步）：跑 EditMode 用例前**无条件** `Refresh(ForceSynchronousImport)` + `RequestScriptCompilation` 并轮询 `isCompiling` 收敛；随后断言 `最新源码 ≤ 最新程序集`，不满足即 FAIL。
- **注意**：`unity command eval` 的代码里**不要出现双引号**（PowerShell 5.1 传 native 参数会弄坏内层引号）→ 全用无字符串写法（如 `? 1 : 0`）。
