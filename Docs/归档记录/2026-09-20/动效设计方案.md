# 动效设计方案

> 制订日期：2026-09-13。定位：**表现层运动设计的统一规范**——动效分类与归属、技术选型纪律、框架接法（谁触发/谁承载）、性能红线与里程碑挂接。
> 前置：《自研框架设计方案》§1.3（转场策略归属）/§4.7（命令式控件类型）、《M4实施指导》§2.2/§2.4（ITransitionStrategy / 受控 API）、《M5 纵向切片》红线（表现与判定分离）、《状态同步实施方案》§6.2（动效不回滚）。
> 一句话定位：**动效是判定的可见投影，不是判定的组成部分——它可以在任何时刻被打断、跳过、重播，而游戏事实（血量/经济/命中）毫发无损。**

---

## 0. 四条原则（不可让步）

1. **动效永不携带判定**——表现与判定分离（M5 红线提前生效于此）：DOTween / Animator / 粒子只写 Transform / 组件表现，禁止回写任何逻辑状态；"动效播完"不是任何逻辑事件的触发条件。
2. **时钟分轨**：UI 动效挂 `IUIClock`（时停不停转场），世界动效挂 `IWorldClock`（时停冻结）——动效实现不自读 `Time`（M4 §1e 决策的推论）。
3. **热更边界**：动效**实现资产**（Animator Controller / 粒子 prefab / 材质）随 YooAsset 增量下发（M6 闭环）；动效**触发与编排**进 Lua（经受控 API / 序列执行器）或 Luban 表（时长 / 曲线 / 目标控件名可热更调参）——**动效的 C# 实现代码出包**。
4. **每帧动效白名单**：持续运行的动效（呼吸 / 脉冲 / 待机飘动）必须 `SetLoops` 复用单 tween + 纳入数量预算；一次性动效（弹窗 / 飘字）低频不限。禁止"每帧 new 一个 tween"的写法。

## 1. 分类与归属（五类动效，各归各家）

| 类 | 内容 | 技术 | 归属 / 触发 | 驱动时钟 |
| --- | --- | --- | --- | --- |
| **UI 转场** | 界面打开/关闭/切换的位移、缩放、淡入出 | DOTween（壳内通用转场组件） | `ITransitionStrategy`（M4a 策略三件之一）——Lua 可经 Strategies 注册表换风格 | UIClock |
| **界面内反馈** | 按钮按压、数值滚动（CountUp）、飘字、红点脉冲、引导高亮 | DOTween + 受控 API 动效口（§3） | Lua 经绑定面受控 API 触发（§4.7 命令式——动效本就是命令式控件类型） | UIClock |
| **角色动画** | 移动/攻击/受击 state machine | Animator Controller，**参数单向驱动**：C# 玩法系统（联机 = SimView 观察状态）写参数；Animator 事件只触发表现（脚印/音效），绝不回写逻辑 | 玩法系统 / View 镜像层 | WorldClock |
| **特效** | 命中、技能、拾取 | 粒子（Shuriken）+ DOTween 组合 | 联机：FrameEventBuffer 观察 + `silenceUntilFrame` 防重播（状态同步 §6.1/6.2 已定）；单机：事件桥 | WorldClock |
| **相机动效** | 震屏、推拉、聚焦 | Cinemachine Impulse + DOTween | 事件桥 / 序列执行器 | WorldClock |

## 2. 技术选型纪律（DOTween 为全项目唯一 tween 库）

- **唯一性**：DOTween 已 vendor（Plugins/Demigiant）；禁再引入 iTween / LeanTween / Prime31 等第二 tween 库；禁 DOTween Pro（非必须的外部资产）。
- **防泄漏（§7.3 内存红线同款）**：所有 tween **`SetLink(target.gameObject)`**——目标销毁自动杀；`SetAutoKill(true)` 为默认；循环 tween 显式保存句柄可杀；界面进入 Recycled 态时壳统一 Kill 该界面全部关联 tween。
- **防 GC**：高频件（飘字 / 数值滚动）用对象池 + tween 复用（`SetTarget` 定向 Kill 后重用）；规格在 M5 Profiler 作业实测后定（记入实施记录）。
- **Animator 纪律**：Controller 资产随 YooAsset 热更；运行期**参数驱动单向**（Set/SetFloat/Trigger），Animator 状态机不反向调用业务方法。
- **联机补充**：动效不进回滚、不参与确定性（Sim 层禁 Animator/Transform——状态同步 §0 红线 1）；本地预测表现 0 延迟（开火反馈），命中特效等权威确认（§6.2 已定，此处归拢）。

## 3. 框架接法（谁触发、谁承载）

1. **转场动效** = `ITransitionStrategy` 实现内容（M4a 交付默认实现：淡入淡出 + 位移灰盒版）——壳在七态切换点调用，策略自行编排 tween。
2. **界面内动效口** = 绑定面受控 API 的最小扩展（M4a 定集）：`Pulse / Flash / Slide` 三件起步（**YAGNI——不预作完整动效词汇表**，需求来了按此模式加）；Lua 经 `OnButton` + 动效口组合覆盖绝大多数界面反馈。
3. **演出级动效**（技能时间轴 / 剧情演出）= **时序执行器**编排（M4b 交付、M5 消费）：动作序列数据进 Luban 表可热更调参；DOTween 挂在执行器步骤的**表现位**，与判定的推进互不等待——执行器冻，动效可继续播完但不产生事实。**编排的创作工具 = Unity Timeline 包**（《编辑器设计规划》§3，2026-09-14 定案：**不自研画布**；自研仅自定义轨 + 导出器 + 校验；骨骼与属性动画走 Timeline 的 Animation Track / AnimationClip，随 YooAsset 热更——与本节 §1/§2 一致；联机技能表现不直接跑 PlayableDirector，走本文的序列执行器）。
4. **Lua 不直持 DOTween API**：桥面最小纪律——一切动效经受控 API / 策略 / 执行器三口进。

---

## 4. 性能红线（移动端）

- **Canvas 拆分**：每界面独立 Canvas；**动效中的元素再拆子 Canvas**（防整页 rebatch）——写入 M4a prefab 规范。
- **overdraw 预算**：全屏 UI 动效叠加 ≤ 2 层；全屏转场用单全屏 Image 淡入出，禁多层渐变叠。
- **目标**：动效播放不掉帧（Profiler 实测记档，M5 作业）；低端机降级 = 策略换短时长/直切，不是砍功能。
- **泄漏即红线**：界面关了 tween 还在跑 = bug；DevHUD 后续可加"活跃 tween 计数"位（挂在 UI 壳 IModuleStats）。

## 附 A. 动效代码形态（2026-09-13 补，规划形态示意——签名 M4a 开工定稿）

组织原则：**一个原语库 + 三个触发口**——DOTween 只出现在 C# 原语库里，Lua 永远隔着三个口。

### A.1 原语库（单源，唯一碰 DOTween 的地方）

```csharp
// Shell/UI/Anim/UiFx.cs —— 全部动效原语收口在此；两个特性写死在原语里：
//   SetUpdate(true)  → UIClock 轨（unscaled，时停不停）；世界动效省略此行 = 走 scaled，时停冻结
//   SetLink(go, KillOnDisable) → 池化界面回收（SetActive(false)）即杀，tween 泄漏在机制上不可能
internal static class UiFx
{
    public static Tweener Pulse(Graphic g, float strength) =>
        g.DOFade(strength, 0.08f).SetLoops(2, LoopType.Yoyo)
         .SetUpdate(true).SetLink(g.gameObject, LinkBehaviour.KillOnDisable);

    public static Tweener Flash(Graphic g, float duration) => /* 闪一下，同款后缀 */;

    public static Tweener Slide(RectTransform rt, Vector2 offset, float duration) => /* */;

    public static Tweener CountUp(TMPro.TMP_Text label, float from, float to, float duration) => /* 数值滚动 */;
}
```

### A.2 策略口（转场——壳在七态切换点调用，壳不认识 DOTween）

```csharp
public interface ITransitionStrategy {
    UniTask PlayShow(UIForm form);
    UniTask PlayClose(UIForm form);
}

public sealed class FadeSlideTransition : ITransitionStrategy   // 默认实现（灰盒）
{
    public UniTask PlayShow(UIForm form)
    {
        var cg = form.CanvasGroup;
        cg.blocksRaycasts = false;
        return DOTween.Sequence()
            .Join(form.Root.DOAnchorPosY(40f).From().SetEase(Ease.OutQuad))
            .Join(cg.DOFade(1f, 0.25f).From(0f))
            .SetUpdate(true)
            .SetLink(form.gameObject, LinkBehaviour.KillOnDisable)
            .OnComplete(() => cg.blocksRaycasts = true)
            .ToUniTask();
    }
}
```

### A.3 受控 API 口（Lua 唯一的界面内动效面，M4a 定集）

```lua
function M:OnShow(data)
    self.ui:Pulse("ImgIcon", 1.2)              -- 控件名经索引解析，Lua 拿不到 GameObject
    self.ui:OnButton("BtnStart", function()
        self.ui:Flash("ImgBg", 0.3)
    end)
end
```

```csharp
// 适配器装配期：动效口做成 LuaTable 挂给逻辑表（self.ui）——延续 M3 手法：
// 白名单委托 + Lua 闭包 shim，零 LuaCallCSharp 生成（避开 asmdef 循环）
var api = env.NewTable();
api.Set("Pulse", new Func<string, float, bool>((name, s) =>
    UiFx.Pulse(_index.Resolve<Graphic>(name), s) != null));   // 索引未命中 → 记日志返回 false，不抛穿
```

生命周期自动化重点：Lua **不管理 tween 句柄**——`KillOnDisable` 让动效随界面隐藏自动消亡；需主动停的只有 OnButton 回调（返回注销委托，已定语义）。

### A.4 执行器口（演出时间轴，M4b 交付、M5 消费）

```csharp
// Luban 表驱动（可热更调参）：tb_timeline 每行 = 一步 { id, step, fx, target, duration, delay, curve }
public sealed class SequenceExecutor
{
    public void Play(string timelineId, object context);   // 等待模型 = 回调注册（M4 §1e 已定）
    public void Cancel(string timelineId);
}
```

执行器推进到表现步骤时调**同一个 UiFx 原语库**——三个口是三种触发方式，不是三套实现；执行器冻结（时停/暂停）时判定停，已播的表现 tween 播完但不产生事实。

### A.5 横切边界（写在原语库与适配器里，不是约定）

- SafeCall 边界：Lua→C# 回调（OnButton 等）逐个隔离；动效原语同步返回、不抛穿 Lua。
- 联机：特效由 FrameEventBuffer 观察 + `silenceUntilFrame` 防重播，动效不进回滚（状态同步 §6 已定）。
