# 13-调试手册（现行调试面全景与排障手册）

> **本文定位**：回答"这个项目里能怎么调试、每个调试件在哪、看到什么数字算正常、出了症状先看哪一处"。
> **不做的事**：不裁决调试面的分层设计（归 [GM 与调试工具分层专项设计](../../../设计文档/架构/GM与调试工具分层专项设计.md)）；不记批次与交付状态（归 [施工进度](README.md)）；不写联测怎么开服（归 [07-本地联测](../../../说明/11-构建与本地联测.md) / [11-联机测试流程](../../../说明/12-云侧部署与联机测试.md)）；不解释同步机制（归 [04-技术细节-服务端](../../../说明/04-服务端与房间内核.md) / [12-联机全栈参考](../../../说明/07-联机全栈参考.md)）。
> **冲突裁决**：与代码不一致以代码为准并顺手修本文。行号以文件当前 Editor 总行为准（含空行）。
> **三条前置事实**（先记住，能省掉一半误判）：
> 1. **GM 页是编辑器工具**（`LiteGame/工具链` Hub 内嵌，`IEditorToolPage`），**不进包**——开发包 Player 里唯一的运行时调试面是 **DevHUD（F1）**。
> 2. 调试件几乎全部**随开发三宏剥离**：`UNITY_EDITOR || DEVELOPMENT_BUILD || LITEFRAMEWORK_DEBUG`。release 包里这些类型**不存在**（不是"关着"，是编译不进）。
> 3. **判定路径禁读静态可变值（含 dev 宏内）**，所以所有 GM 开关都是"显式注入的规则实例"，不是"全局开关被判定读到"。

## 2. DevHUD（只读运行时 Overlay）

### 2.1 形态

| 项 | 事实 |

| 刷新 | 0.25s 节流渲染；**帧采样逐帧、与可见性解耦**（隐藏期间性能窗不冻结） |
| 绘制 | UITK：顶部状态行（可拖动面板）+ 七段（段标题 `[-]/[+]` 点击折叠），每行一个 `Label` 按色调着色（白=正常、灰=次要、黄=警告、红=错误）；半透明底板 + 滚轮滚动 + 字号/缩放；IMGUI 回退：`OnGUI` 整串白字、自动换行/滚动/字号 |

### 2.2 七个段（可折叠）

| 段 | 内容 | 什么时候看它 |
|---|---|---|
| **Errors** | 仅 `Log.ErrorCount > 0` 时出 `⚠ 错误计数: N`（红色） | 一进来先看有没有 |
| **联机诊断** | `相位 / RTT / 丢包` + `和解 N 次` + `回滚 N（延后 M）/输入领先/快照年龄`；RTT/丢包 **60s sparkline**（min/avg/max）；无对局整段不显示 | 对局内网络手感异常、回滚/追帧排查 |
| **性能** | `FPS / p50 / p95 / p99 / 最差 / 长帧`；`GC alloc/帧`、`Draw/Batches`（`ProfilerRecorder`，不可用显示 `n/a`）、`HUD: x ms` 自报聚合耗时（指数平滑）；p95>16.6ms 黄、p99>33ms 红 | 卡顿归因（本机帧样本，非对局数据） |
| **Stats** | 按模块分段：`MainThreadDispatcher` / `Clock.World` / `Clock.UI` / `EventCenter` / `Game` / `Lua`（可 Inspector 关单段；模块名灰色、键值白色） | 找哪个模块在涨/在卡 |
| **Log Recent** | 最近 N 条 `Log` 环（默认 10，范围 1..32；`✗/⚠/·` 前缀 + `[Tag]` + `[m/f/p]` 上下文；按级别着色；F3 级别过滤、F4 仅本局） | 页内提示不够用时 |

### 2.5 结构化日志文件（JSONL）与检索

| 项 | 事实 |
|---|---|
| 安装 | dev 三宏内由 `PlatformInfrastructureModule` 调 `StructuredLogInstaller.Install()`；release 不装（`Log.SetSink` 保持 null） |
| 位置 | `persistentDataPath/logs/log-<session>-<yyyyMMdd-HHmmss>-p<n>.jsonl`（Windows：`%USERPROFILE%\AppData\LocalLow\DefaultCompany\Test\logs`） |
| 格式 | 一行一个 JSON：`ts/lvl/tag/sid/mid/f/p/msg`（`sid`=会话 8 位、`mid`=对局、`f`=逻辑帧、`p`=席位；消息内换行/引号已转义） |
| 写入 | 调用线程只入队（容量 1024，满则丢最旧并计数）；后台线程格式化/落盘；单文件 8MB 轮转、目录保留 8 个文件 |
| 计数 | `StructuredLogSink.Written/Dropped/LastError/CurrentPath`（`Dropped>0` = 写盘跟不上，日志有丢失） |
| 检索 | `python scripts/logs/query.py <文件或目录> [过滤] [--limit N] [--json\|--stats]`；目录默认读最新文件，`--all` 合并全部；支持 `--match/--player/--tag/--level/--frame-min/--frame-max/--contains/--since` |
| 与现场包的区别 | 现场包（`diagnostics/`）是**一次事件**的信封（身份 + Player.log 尾 + 最近日志）；JSONL 是**连续日志流**；两者都带 `mid/f/p`，可交叉对账 |
| 已知边界 | 服务端 `HostLog` 未接同一 sink（归 T1 后续）；JSONL 只在本机，取回靠文件拷贝或现场包 |

示例：

```powershell
# 目录默认读最新文件；对局 + 级别 + 帧窗口过滤
python scripts/logs/query.py "$env:USERPROFILE\AppData\LocalLow\DefaultCompany\Test\logs" `
  --match Room-Test --level warning --frame-min 100 --limit 20

# 只出汇总（全量命中，不受 --limit 影响）
python scripts/logs/query.py <file> --stats
```

> 日志文件以 `FileShare.Read` 打开、`Flush` 每秒/错误时触发——**游戏运行中也能读**（`query.py` 直接读最新文件即可）。

## 4. 测试模式的真实边界（最容易误判的一段）

**测试模式恒为本地服形态**：客户端预测与权威 Sim **同进程、同实例、同规则对象**。这条决定了谁能生效：

| 形态 | 现场开关（Live） | 云端 GM 下发 | 权威侧是否知情 |
|---|---|---|---|
| 测试房 / 本地服（`Room-Test`） | ✅ 即时生效 | 不需要 | 同进程同实例 ⇒ **知情** |
| 真 KCP 对局 | ⚠️ **只改本进程预测** | ✅ 必须用 | 只有下发后才知情（快照 `gm_flags` 同值下发） |

本地服"假"的部分（`LocalServerTransport.cs:24-30` 明确列出）：**无 Socket**（无丢包/乱序/延迟/MTU）、**无票据验签**（token 只做非空）、**单房间**、**自动补位**（剩余席位由假连接补满并按缺席空输入站桩）、**代房主开局**。⇒ 弱网、断线重连真实性、多房间隔离**必须在真服务器验**。

其他边界：

- **测试房（带模板建、不进大厅）不产结算**——`ServerHost.cs:1244-1250`；客户端仍收 `MatchEnded`，结算页按"无结果"展示。**"打了半天没战绩"可能不是 bug。**
- **`MatchTestRules` 链路依赖"同进程同实例"**——真 KCP 不提供测试房，在线房间级规则下发当前只覆盖 `gm_flags`（免死/无限弹药），爆头带覆写等**没有**在线下发。
- **覆写面统一口径**：仅开发三宏内、不落盘、复位即回烘焙/导出值、判定路径读注入实例；定型值经导出工具进 `*.g.cs`（进 digest 的只有导出常量）。

## 6. 云端 GM（运维端点）

**与上面 GM 面板不是一回事**：GM 面板是**编辑器 + 客户端预测面**；云端 GM 是**房间服进程内的写面 HTTP 端点**，动作在权威循环执行。

| 动作 | 路径 | 语义 |
|---|---|---|
| `rooms`（读面） | `POST /gm/rooms` | 列出在册房间（含隐藏测试房）：`room/phase/players/expected/map` |
| `start` | `POST /gm/start` | 强制开局（**取真实 owner 代发**，不旁路 owner 校验） |
| `abort` | `POST /gm/abort` | 运维终止（走完 Finishing/Settling） |
| `kick` | `POST /gm/kick` | 踢席位（需 `player`） |
| `rules` | `POST /gm/rules` | 规则位：`1`=免死 / `2`=无限弹药 / `0`=关闭；也可 `{noDeath:true, infiniteAmmo:true}`。**只对测试房生效**，普通房 409 |
| `settle-flush` | `POST /gm/settle-flush` | 立刻回灌结算 Outbox |

门禁（三条，缺一不开）：**仅 POST**（其余 404）、头 `X-GM-Key` **恒定时间比对**、body ≤ 4096 B；密钥取环境变量 `LITENET_GM_KEY`，**空则端点不创建**；`gm_bind` **不得为通配地址**（装载期拒）。细节见 [12 §5.10](../../../说明/07-联机全栈参考.md)。

**本机调用（已封装好全部坑）**

```powershell
python scripts/deploy/gm.py --action rooms
python scripts/deploy/gm.py --action start  --room <房号>
python scripts/deploy/gm.py --action kick   --room <房号> --player 1
python scripts/deploy/gm.py --action rules  --room <房号> --flags 3
```

脚本内固化的两个坑：**本机转发端口默认 19101**（9101 落在 Windows 排除区间 9014-9113，直接绑会 `Permission denied`）；**POST 必须带 body**（无 `Content-Length` 会被 `HttpListener` 回 411）。密钥来源：`LITEGAME_GM_KEY` 环境变量，缺失则回落解析 `LocalNotes/cloud-host.md`（不入库、不回显）。

> ⚠️ GM 审计行走的是**裸 `Console.WriteLine`**（`[GM] 入队/拒绝/执行/跳过`），未经 `HostLog` 门面——这是登记在案的偏差，读日志时按前缀 `[GM]` 抓即可。

### 7.3 Ops 周期行（服务端"体检表"）

缺省 **5s 一行、每房一行**（`host_tuning.ops_interval_ms`），格式单源 `Ops.Format`（`Server/RoomServer/Application/Ops.cs:403-473`）。分段读法：

| 段 | 字段 | 看什么 |
|---|---|---|
| 房间 | `rooms room frame steps sessions players` | `steps` 应随 wall time 稳定增长（60/s）；停涨 = 权威循环卡住/异常被吸收 |
| 快照 | `snap: sent full deltaSlots` | `full` 增长过快 = 有人 ack 落后或频繁重锚；`deltaSlots` 长期为 0 = 没变化（正常）或裁剪过度 |
| 输入 | `in: pkts acc drop(dup/range/stale/ack/btn)` | **`acc` 不涨 = 输入链断**；`range/stale` 暴涨 = 帧号窗口错位；`btn` 涨 = 按键白名单拒绝 |
| 和解 | `reconcile: reports` | > 0 且持续增长 = 客户端在与权威反复分叉（查 checksum 口径/输入链） |
| 回溯 | `lagcomp: fire comp degr` | `degr` 占比高 = 回溯常走退化路径（`view_frame` 越窗/补偿关闭） |
| 背压 | `bp: throttled outRej` | 只影响单个慢客户端；`throttled` 涨说明有人跟不上 |
| 比赛 | `match: phase transitions settled obx(ok/dup/rej/fail) restored` | `obx` = 结算入盒四态；`rej` 涨 = Outbox 满 |
| 边缘 | `edge: rejects sessRej sessClean pktBad pktBig roomsFull roomsBad roomsDown drainRej drainTimeout tickCoalesced ackBad(stale/future/evict) tktBad(bad/exp/rply/kid)` | 进房拒绝/包拒绝/票据拒绝分类全在这；`pumpFail` 在 `loop` 段 |
| 限流 | `rl: ipConn ipEntry acct sess tblFull purged buckets` | `tblFull` > 0 = 限流表容量与来源规模不匹配 |
| 循环 | `loop: ticks debt abandoned pumpFail` | **`pumpFail` > 0 = 权威帧体在抛且已被吸收**——必须查 `LastPumpError` |

> **`pumpFail` 是最容易被忽略的一行**：帧体异常一律被吸收（循环不能死），所以日志可能只有"首败 + 每 100 次一次"，而 Ops 行会一直记账。

| Code 词表 | `JoinRejectedBuildHash` / `JoinRejectedTicket` / `JoinRejectedAdmission` / `JoinRejectedRoom` / `JoinAttempt` / `JoinNoAckDisconnected` / `ActivationFailed` / `ActivationRecovered` | `:58-72` |

## 8. 确定性 / 回归调试

### 8.1 分层跑法（先选最小够用的一层）

| 层 | 命令 | 什么时候跑 |
|---|---|---|
| L0 静态 | `python scripts/gate/l0-dep-scan.py` | 依赖/秘密扫描（不需要 Unity/.NET 测试） |
| L1 纯逻辑 | `python scripts/gate/test.py --lane L1 --profile PullRequest` | 改逻辑/协议/房间内核后的底线（含纪律扫描/表守卫/BuildHash 守卫） |
| L2 Unity | `python scripts/gate/l2-unity-gate.py` | 改场景/prefab/UI/动画/序列化面 |
| L3 集成 | `python scripts/gate/test.py --lane L3 --profile PullRequest` | 改网络/进程/多房间/重连/结算 |
| Doc | `python scripts/gate/test.py --lane Doc` | 改 `Docs/**` 或审计表 |

完整分层与过滤条件见 [05-验证与门禁](../../../说明/10-测试与门禁.md)。

### 8.2 确定性对账三件

| 工具 | 用途 | 现状 |
|---|---|---|
| **IEEE 基线对账** | Unity 侧与 .NET 侧同一份样本逐位比较（不等 = 浮点路径分叉） | Hub `LiteGame/工具链` → 质量门禁 → IEEE 基线对账（`IeeeBaselineChecker.cs`）；CI 入口 `RunCli`（一致 exit 0 / 否则 exit 1）；EditMode 用例直调 `Verify` |
| **`SimWorldDiff`** | 把"checksum 不符"翻译成"哪个槽位哪个字段从什么变成什么"（float 附位型十六进制，**不做容差**） | 已有实现 + 扰动法覆盖守卫（`SimWorldDiffCoverageTests`）；**生产零调用** |
| **`SimReplayRunner`** | 把一局的 `SimRunRecord` 在另一运行时重跑，给出**首个分歧帧** + 字段级报告 | 已有实现；**生产与测试均零调用**（跨运行时对账链未接线） |

> 这三件的意义：checksum 不可逆，只能回答"是否相同"；1-ulp 分歧下两个世界可能只差一个 float 的最低位。**"有工具"≠"链已通"**——`SimWorldDiff`/`SimReplayRunner` 要自己接线才能在 Play 里用（在 EditMode/L1 用例里直调是当前可用形态）。

### 8.5 房间回放与现场包（v2 第一刀）

**服务端记录**（配置 `diagnostics` 分区启用后，房间终态自动落盘）：

```json
"diagnostics": {
  "enabled": true,
  "directory": "C:/litegame/room/diagnostics",
  "max_files": 100,
  "max_total_mb": 512,
  "max_commands": 400000,
  "max_steps": 100000,
  "log_tail_lines": 200
}
```

- 目录必须是**绝对路径**；`enabled=false` 或缺省 = 不写盘、零行为变化。
- 产物：`room-<roomId>-<matchId>-<utc>.json.gz`，内含构建/配置/地图身份、地图快照、有序命令、逐帧 checksum、测试规则事件、`HostLog` 尾与最近一次 mismatch 摘要。
- 记录只在房间终态**静默后**取走并写盘；mismatch 当场不写（避免跨线程读半截记录），其帧号随终态记录落盘。

**离线重放**：

```powershell
dotnet run --project Server/ReplayTool -- replay <record.json.gz> [--json] [--defaults]
```

- 默认加载仓库真实表并复算 `fixedConfigDigest`；`--defaults` 仅用于默认表/离线测试记录。
- 退出码：`0` 一致；`2` 首分歧（输出帧号/事件序号/命令序号/双边 checksum）；`3` 身份或格式不符；`4` IO；`5` 记录截断。
- 身份三项（`buildHash`/`fixedConfigDigest`/`mapDigest`）任一不符会拒绝重放，不给“假分歧”。

**客户端现场包**（checksum mismatch 或 `StartGame.ConfigHash` 不符时）：

- 路径：`Application.persistentDataPath/diagnostics/diag-*-<reason>-*`。
- 内容：`manifest.json`（buildHash/configDigest/matchId/frame/localEntityId/reconcileCount/平台/版本）、`log-recent.txt`（`Log.Recent`）、`player-log-tail.txt`（Player.log 尾 64KB）。
- 同局最多 3 份、默认间隔 30s；本地 only，不上传；写入失败只 `Log.Warning`，不影响对局。

**已知边界**：服务端记录目前只覆盖房间终态；客户端包不含完整重放（权威重放以服务端记录为准）；字段级 world-ring diff、崩溃捕获/符号归档、产物上传/下载通道归 T0 后续。

## 9. 症状 → 分层判断 → 处置

> 判断顺序永远是：**先确认"哪一段断"，再看具体原因**。断点分段见 [12 §0.3 五个交接点](../../../说明/07-联机全栈参考.md)。

| 症状 | 先看哪一处 | 大概率原因 / 处置 |
|---|---|---|
| 编辑器里什么都没出现（无 HUD、无开发页） | Console 是否有 `BootstrapError` | 引导期失败；看 `ProcedureError` 页与 `Log` 错误行 |
| 按 F1 没反应 | 是否在 release 形态 | release 无 DevHUD（三宏剥离）；只有编辑器/`development` 通道包才有 |
| 开发页「开发」钮不见 | `DevStartupConfig.DevMenu` 是否勾；是否编辑器形态 | `DevMenu` 默认 true；dev 预制体不在收集组 ⇒ **仅编辑器形态**（`DevMenuLauncher.cs` 的 `EnsureDevMenu`） |
| GM 面板读数是空的 | 是否 Play；容器是否就绪 | 页件经 `GameEntry.TakeContainer()` 取件，未装配按空态显示 |
| 登录失败 | Meta 是否在跑（`/live`）；`deploy.args` 的 `meta.url` | 没隧道/没起 Meta/Mongo 未起（持久化开时 Meta 起不来） |
| 大厅看不到对方的房 | 房间是否注册成功（实例心跳）；列表 1s 自轮询 | 先建房再登录；`sandbox` 房不进大厅（隐藏房） |
| 签票 `409 version-mismatch` | 两端 `buildHash` | 共享源集改了没重跑 `gen-build-hash.py` / 客户端旧包 |
| 签票 `403 forbidden` | 测试房口令 | `LITEGAME_GM_ROOM_KEY` 为空 ⇒ 测试房功能关闭（一律 403） |
| 签票 `503 no-capacity` | 实例是否上报 `players < maxPlayers` 且未 drain | 实例心跳超时被摘；或房间已满 |
| Join 发出后**没有 Ack** | 客户端是否 `JoinNoAckDisconnected`（DiagTrace）；服务端 `rejects`/`tktBad` | 准入链某一环拒绝（频率/字段/token/buildHash/票据）；服务端拒因不回明文（P0-3），要靠 Ops 计数分流 |
| 连上就断、无任何报文 | 信封 PSK 是否两端一致 | 握手形状不符即断且**无回执**（`SecureEnvelopeRoomTransport.cs:151-169`） |
| 进局了但角色**站着不动** | 服务端 Ops `in: acc` 是否增长；`drop(range/stale/btn)` | 输入全被判非法：AimPoint 全零、帧号越窗、seq 违纪、按键白名单 |
| 每份快照都在和解（橡皮筋） | DevHUD「和解 N 次」+ 服务端 `reconcile: reports` | 输入链锁死，或公共 checksum 口径问题（AOI × 全图，登记为 P2 残差） |
| RTT/丢包显示 `无样本` / `—` | 探针是否在 Connected 相位 | 探针仅 Connected/Restoring 发（1Hz）；刚进房要等一轮 |
| 命中/伤害数字不出现 | 是否只在本地预测里"打中" | 命中/伤害只信权威（`recent_hits`）；本地预测不产命中（`resolveCombat:false`） |
| 爆头永远不出 | 开 `DrawHeadshotDebug` 看黄/红圈；开 `AutoHeadshot` 验链 | 判定柱几何（灰=命中柱、黄红之间=爆头窄柱）；AimPoint 高度落点决定 Crit |
| 死了不播死亡动画 | 远端取的是**渲染帧对应快照** | 死亡是每帧权威状态；检查 jitter buffer 与 `corpse_frames` 公共面 |
| HUD 面板整块不见 | Console 是否 `hud-attached` / 降级 Warning | HUD 走场景对象解析，缺失静默降级（`BattleViewRig.cs:595-609`） |
| 退出对局卡住 | ESC → 设置页 →「退出对局」确认弹窗 | 直接断进程会跳过收尾；正常路径 `Leave → Ended(Leave) → 回 Main` |
| 打完没有战绩 | 是否 `sandbox` 模板；是否测试房 | `sandbox` 永不结束；测试房额外不产结算 |
| 结算提交一直重试 | 服务端 `obx(fail/rej)` + `deploy/logs/room.log` | Meta 不可达/凭据不匹配（跑的是错误分级：可重试保持待提交，确定性 4xx 弃置） |
| 服务端 `steps` 不涨 | Ops `loop: pumpFail` | 帧体异常被吸收；查 `LastPumpError`（首次与每 100 次上报） |
| L1/编译报 **MSB3027 文件锁** | 是否有活服进程 | 先停服（GM 面板「本地联测」Stop 或 Ctrl+C 排空） |
| 对局中点「导出爆头区」就断线 | domain reload | 面板已提示：**先记数值，出对局后再导** |
