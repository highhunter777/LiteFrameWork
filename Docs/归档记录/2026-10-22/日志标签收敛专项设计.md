## 2. 选型：候选对比与冻结

| 候选 | 形态 | 机制强度 |
| --- | --- | --- |
| A 字符串常量类 | `LogTag.UI`（string const）+ L1 扫描"tag 位禁裸字面量" | 集中登记 + 扫描双件套；tag 位类型仍是 string——经变量／参数转传的未登记值无法静态拦截 |
| **B 枚举强类型（冻结）** | `LogTag` 枚举 + 门面签名改 `LogTag`、删 string 重载 | 编译期封闭：裸字面量／未登记值**无入口**；词表集中登记 |

### 冻结 B 的四条论证

1. **编译期即守卫**：B 删除 string 重载后，"未登记 tag"在语言层面不存在；A 的扫描规则弱于编译期（转传拦不住），且扫描规则本身是一处需长期维护的机制件。
2. **"小而稳定"的机制化**：tag 契约本就要求封闭集合；枚举＝把该意图钉进类型系统——新增 tag＝加一行枚举＝显式一次评审。
3. **词表归属**：词表含业务模块名（UI／Battle／Lua……）仍放 `LiteFramework` 与 Log 同域——tag 是**日志系统的全局分类词表**，不是行为契约；与 `LogLevel` 同级先例。LiteFramework 是客户端框架（S2 档；服务端不引用其 Log，服务端有独立 HostLog），无跨端共享面问题。
4. **未来身份**：DevHUD 按模块过滤／开关（未点单）需要 tag 的稳定身份；枚举天然具备。本稿不预置过滤功能，只冻结形态。

### 被否备选（记录）

- `readonly struct LogTag`（可挂元数据如默认级别）：当前零元数据需求；枚举＋旁挂表可在有需求时平滑升级。
- 保留 string 重载过渡期：封闭性即被放弃（B 的全部价值）；不设过渡期，类型变更强制全量同批。

## 3. 目标形态

1. **枚举 `LogTag`**（新文件 `Assets/LiteFramework/Scripts/Core/Logging/LogTag.cs`）：
   - `None = 0`（缺省值，显示面不出前缀——与现 `tag = null` 语义一致）+ 32 项词表（§4：设计期 31 项＋实施期补 `Vfx`）。
   - 显示名＝枚举名（与现值一致；实施期 `VFX` 归一为 `Vfx`，见 §4 备注）；若将来出现显示名≠枚举名的需求，在 TagName 单源内解决，不散落。
2. **门面 API**（Log.cs）：
   - `Info/Warning/Error/Fatal(string message, LogTag tag = LogTag.None)`；
   - `Error/Fatal(Exception ex, string context = null, LogTag tag = LogTag.None)`；
   - string tag 全部重载删除（同批）。
3. **`LogEntry.Tag`**：string → `LogTag`；契约注释（Log.cs:70）重写为：词表＝枚举单源；动态信息（实例名／路径）仍进 message；新增 tag 流程＝加枚举项（集中登记）。
4. **显示名转换单源 `Log.TagName(LogTag)`**（LogTag.cs 内，switch 表达式，不设默认臂——`None => ""` 为显式臂，全项覆盖免 CS8509）＋**穷尽守卫测试**：遍历 `Enum.GetValues<LogTag>()` 全量调用 TagName 断言非 None 项映射有效——加枚举忘加名字即被拦。
5. **零变化面**：级别过滤（`_minOutput`）、环缓冲容量与行为、`ILogHelper` 接口、`ErrorCount`、输出拼接格式（`[tag] message`）。
