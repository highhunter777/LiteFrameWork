## 2. 问题（用户裁决「平地也能爆头」）与根因

- **问题**：平地对枪时射线高度恒为 `射手Pos.Y + 1.0`，命中点 Y 恒为 1.0，与爆头线 1.7 差 0.7m ⇒ 判据数学上恒不成立，**平地永远打不出爆头**。
- **根因不在判据，在瞄准向量丢掉 Y 分量**：v0.1 §3.1 把采集口径写成"屏幕点 → 相机射线 → 只取 XZ 归一化"（`_groundPlane = new Plane(Vector3.up, 0f)`）⇒ 射线方向无 Y 分量。
- **参考口径（外部对标）**：《逃离鸭科夫》为俯视角，爆头**按命中部位判定而非随机概率**——「准心在敌人头上开火就爆头」；伤害机制按命中部位选择护甲分支。本设计借鉴其**可控性**，不引入俯仰输入轴。

## 4. 瞄准向量解算（批B 核心，C2/C3/C4）

### 4.1 为什么否决 `normalize(ray.direction)`

俯视角相机（Cinemachine 跟随，本工程 `/Aim Camera` 形态）位于角色**上方**并向下看，`ScreenPointToRay(准心).direction.y` **恒为负**。拿它当弹道方向有三重错误：

1. **弹道恒向下**：枪口 y=1.0 + 负 Y 分量 ⇒ 命中点恒 < 1.0 ⇒ **永远进不了头部带 [1.7, 2.0]**——与"平地不能爆头"同一个病，只是换了个理由。
2. **与世界朝向脱钩**：相机射线方向几乎只由屏幕位置在**相机局空间**决定，相机随玩家转动时弹道不随之旋转 ⇒ 准心左右移动与世界射击方向不一致。
3. **与逻辑枪口脱节**：射线原点是相机（高处、身后），而子弹出射点是逻辑枪口。

### 4.2 定案解算流程

```
准心屏幕点 → 相机射线 ray
  ① 实体求交：SimRaycast.RaycastEntities(本地预测世界, skipSlot=本地玩家槽位,
              o=相机位置, dir=ray.direction, maxT=足够大)
     命中 ⇒ P = 相机位置 + ray.direction × t          （P.y 即准心真正点到的部位高度）
  ② 未命中 ⇒ 地面平面 y=0 求交 ⇒ P = (x, 0, z)           （打空/打远）
  ③ 无交点（相机近水平且准心在屏幕上方）⇒ 沿用上次有效方向 + _hasAimPoint=false
            （不取零向量：零向量会让 InputSystem 不派生 Yaw）

弹道方向 = normalize(P − 逻辑枪口) ⇒ frame.AimX / AimY / AimZ（单位向量）
长度闸：IntentVectorLimit 三维重载（EnsureWithinLengthLimit(ref,ref,ref)）
```

**为什么这样就"准心在头上就爆头"**（可验证的因果链）：
- 俯视角下，敌人**头部在屏幕上比脚部高**；准心上移 ⇒ 相机射线打到更高处 ⇒ `P.y` 升高。
- 弹道从枪口（y=1.0）指向 `P` ⇒ 命中点高度随之上抬 ⇒ 落入头部带 ⇒ `Crit`。
- 准心在敌人**头顶上方** ⇒ ① 不命中该实体 ⇒ P 落到其后方地面 ⇒ 弹道指向远处 ⇒ 打空或打远 —— 与俯视角射击直觉一致。

### 4.3 接缝面（不扩核心接口，沿 `SetAimCamera` 既有范式）

- `NewInputIntentSource` 新增 `SetAimWorld(SimWorldState world, int localSlot)`；`_groundPlane` 保留作②的兜底。
- `IIntentSource.Sample(in SimVector3 localPos)` **签名不变**；`IInputService` 增加 `SetAimWorld(...)`，内部转发给实现了该接口的源（`IAimWorldSink`）。理由同 `SetAimCamera`：不让流程层认 `NewInputIntentSource` 具体类型（`ProcedureBattle.AimPointOf` 已破过一次 R12，不再新增同类破口）。
- 装配：`ProcedureBattle` 每渲染帧在 `SampleOnRenderFrame` 前注入 `RollbackSim.State` + 本地槽位（`State.TryResolve(localEntityId, out slot)`）。
- 相机射线与三维弹道**都从逻辑枪口算**：`CombatConfig.MuzzleOrigin` 是常量偏移，客户端侧同式复刻（已有先例——表现层复刻逻辑枪口）；不得改用视图枪口位（服务器无模型、服务器用的是逻辑枪口）。

### 4.4 已知精度边界（登记为口径，不在本批解决）

- 客户端用**预测/插值态**求交、服务器用**回溯历史态**判定 ⇒ 目标移动时爆头判定存在误差（打头/打身之别）。这是 lag compensation 的固有性质（Duckov/CS 同构），**接受**。误差量级 ≈ 目标速度 × RTT/2。
- 量化把握：20m 外平地，命中头部的弹道仰角 ≈ `(1.8 − 1.0) / 20 ≈ 0.04`，命中点 Y ≈ 1.8 ⇒ 仍在头部带内 ⇒ 远距可爆头成立（列入实机验证矩阵第 3 项）。
- `h ≈ 0`（相机射线近乎水平）时弹道水平投影退化 ⇒ `AimX/AimZ ≈ 0`、`InputSystem` 不派生 Yaw（朝向保持）。俯视角下几乎不可达（准心恒在屏幕中下部），登记为边缘情形，不做特殊处理。

## 5. 部位判定与爆头（批A 已交付，本节为口径复核）

- **爆头判据**：`relY = hitPos.Y − hit.Pos.Y >= HeadHitLine`。
- **上界由 `SimRaycast` 的 Y 带闸承担**（`yHit > Pos.Y + HitscanHeight` ⇒ 未命中）⇒ 判据侧只需 `>=` 下沿。**此口径与 Y 带闸一致，勿单方面收紧**（既有用例「高差位命中头部带」依赖闭区间含端点语义）。
- **爆头发 `Crit`、普通发 `Hit`**；两者**不进 checksum、不进快照**（帧内瞬态），故协议与 checksum 基线零改动，回滚重放天然正确。
- **下游链路已通**（已核实）：`HitFeedbackDispatcher.Resolve` 直传 `Kind` → `BattleDamageNumberDriver.OnHitFeedback` 吃 `Hit/Crit` → `snap.Crit` → `DamageNumberStyleResolver.Resolve(value, role, crit)`。View 侧零改动。
- **确定性纪律**：新增运算全部走 `SimMath`（融合安全累积 + 软件 sqrt），不得用 `Mathf`/`Math`。

## 6. 样式面（批C）与 v0.1 §6 的偏离（**推翻**）

v0.1 裁决"敌我方统一（普通白、爆头红）"，本版**否决**，理由三条：

1. **敌我色差是 PvP 核心可读性信息，不是装饰**——玩家必须一眼分清"我造成的伤害"与"我承受的伤害"。统一后只剩红/白两档，暴击与敌我两个维度挤在同一维度上互相遮蔽。
2. **推翻它必须改既有锁定断言**（`BattleDamageNumberEditModeTests:96-97` 断言"造成档白色 / 承受档染红"）——改测试去迁就一个被推翻的口径，方向可疑、收益不划算。
3. 外部对标（Duckov / CS 系）均有敌我色差。

**批C 缩编为"爆头档观感加强"**（不改 `Resolve` 的 `role` 分支、不改合并键）：
- 爆头档字号 6.5 → 7.5；爆击抖动/缩放加强（`DamageNumberMotion` 已有 crit 通道）。
- 表现参数**禁入 `CombatConfig`**（digest 源集纪律），继续走 `IDamageNumberStyleResolver`。
- `HitLocalRole` 仍进合并键（`(TargetId, Role)`）——样式统一与账目统一是两件事。

|---|---|---|
| 1 | `RaycastObstacles3D` 把三维 `maxT` 直接当**水平**距离上界（严格应为 `maxT × h`，当前偏宽松） | **不改**——折回后 `obstacleT` 可能 > `maxT`，但截断条件是 `hitSlot ≥ 0 && obstacleT < hitT ≤ maxT`，故**无法产生误判**。改动只会扰动既有逐位结果 |
| 2 | `SimRaycast` 障碍仍 2.5D（XZ + y 闸） | **不改**——关卡障碍均为地面级圆/盒，三维化零收益、破坏面大（与 `MovementSystem` 共用 `SimMapData` 语义） |
| 3 | `HeadHitLine` / `HeadshotDamageShift` 表化 | **不改**——现为代码常量、不进 digest，调参零副作用（改表才触发两端 buildHash 不一致）；表化随 `tb_weapon` 批 |
| 4 | AI/沙盒的三维弹道构造 | 登记后续——`ButtonFireFlag` 是服务器内部构造输入，AI 射击方向需自建口径，本批不预埋 |
| 5 | `h ≈ 0`（射线近水平）时朝向保持 | 登记边缘情形——俯视角下几乎不可达，不做特殊处理 |

## 10. 总验收口径

- **平地可爆头**：同地平面对枪、准心置于目标头部带 ⇒ `Crit` + 爆头倍率（L1 + 实机第 2/3 项双锁）。
- **可控性**：爆头与否**仅由准心位置决定**（无随机、无俯仰输入轴），玩家可复现。
- **全链一致**：客户端上报方向 = 服务器回溯重演方向 = 激光端点方向（同源同向）。
- **身份**：`AimY` 两端同帧同值；触及源集则 buildHash 重录后一致（**不重录 `SimChecksum` 基线**——输入面不进 checksum）。
- **无回归**：移动/障碍碰撞 2.5D 口径不动；`SimMath` 逐位确定；既有 `HeadshotTests` 全绿。
