## §1 代码实现规范（红线）

> 每条红线都有审计实锤反例（条目编号指向 [代码质量审计-客户端](代码质量审计-客户端.md) / [服务端](代码质量审计-服务端.md) 对应节）。写新代码触碰同型问题 = 直接违反本节，评审可打回。

### 1.1 常量与硬编码

- **逻辑中禁魔法数字/魔法字符串**：数值参数进 Luban 表或带名常量；资源路径、场景对象名、协议词表、Lua 注册 key 收口到所在系统的常量类。〔反例：客户端硬编码节 ProcedureMatch 的 `127.0.0.1:17777` 与 DebugTuner 文案双写——已收口（2026-10-11 P2 批：文案改引 `ProcedureMatch` 常量）〕
- **跨层共享的"同一常量"必须单源，C# 侧是权威**：Lua shim、编辑器工具、Lua 页面引用同一份（经桥接导出或生成），不允许两份字面量并存。〔反例：Pulse/Flash/Slide/Bubble 默认值在 `UiFx.cs`、`LuaBehaviourAdapter` shim、`UIMain.lua` 三份副本，`UIWidget.cs:42` 的 0.08 即漏网产物——已收口（2026-10-11 P2 批：单源表 `UiFxDefaults`，shim 经占位符注入）〕
- **生成器与运行时共享常量，生成器必须引用运行时定义**（同工程源链接或代码生成），禁"注释对齐"。〔反例：`SimTrigTableGenerator.TableSize` 与 `SimTrig.TableSize` 各写一份〕
- **按名解析场景对象必须常量化 + 失败可见**：`GameObject.Find`/`transform.Find` 的路径字面量收口常量，解析失败必须留下诊断（静默 no-op 视为 bug）。〔反例：`ProcedureBattle` 6 条场景路径 + `"Aim Camera"` 字符串约定〕
- **新路径字面量禁含中文**（跨平台打包风险）。〔反例：曾用 `"训练场.unity"`——2026-10-11 P2 批已迁 `Assets/Scenes/TrainingGround.unity`；新增路径字面量仍一律禁中文〕

### 1.2 单源与同步面

- **任何"A 与 B 必须一致"的关系必须机制化**：单源引用 / 代码生成 / 守卫测试，三选一。只靠注释或"记得同步"即违规——评审见到"必须与 X 保持一致"的新注释应要求改成机制。〔反例：SimChecksum 分型表字段清单手抄两份、SimWorldDiff 覆盖面漂移导致"checksum 报警但 diff 报不出原因"〕
- **float 位级比较只走 `BitUtil.Equal`**（Sim 确定性唯一入口）；数学只走 SimMath/SimTrig。
- **新增实体状态字段 = 同步链四处一起动**（`CopyTo`/`SimChecksum` 双口径/`SnapshotDiffer`/`SnapshotReassembler`），且优先推动进 StateLayer 生成器而非继续手抄。〔反例：Item/Projectile/Zone 分型表未进生成器〕

### 1.3 静态状态与依赖获取

- **禁新增 public static 可变字段/属性**。名义豁免名单：Log / FileSys / ReferencePool（封闭，扩名单须设计文档登记）；静态只读配置快照须走 ConfigSnapshotService 式的"版本化发布"，禁裸 volatile 直赋值双轨。〔反例：AnimationProfileConfig 静态快照绕过配置服务；CollectionPool 静态池族出了豁免名单〕
- **确定性判定路径（伤害/弹药/移动/命中/checksum）禁读任何静态可变状态——包括 `#if UNITY_EDITOR` 内的**。GM 开关一律显式注入参数对象，不进 checksum 的可变全局 = 静默分叉源。〔反例：SimTestRules 六个静态布尔直读〕
- **服务获取统一构造注入 / 容器 Resolve**；禁反射取私有成员取服务（改名即静默断链）；禁新增静态服务定位器。〔反例：GmPanel 反射 `"s_container"` 六区静默失效；Bridge.Data 静态定位器是受控存量债〕

### 1.4 错误与日志契约

- **已关闭服务再调用：统一抛 `ObjectDisposedException`**。同一层级的姊妹服务必须同契约——不许一个抛、一个警告降级、一个裸奔 KeyNotFound。〔反例：EntityService/SceneService 抛、VfxService 警告、AudioService 无守卫〕
- **程序员错误 fail-fast**（构造期校验、参数越界直接抛）；**内容降级**走 `Log.Warning + 显式默认值`；禁吞异常静默继续。
- **生产日志统一 `Log.*` 门面**；禁在非编辑器生产路径直落 `Debug.Log/LogWarning`。临时诊断必须带 `[Diag]` 前缀 + 摘除批次号，批次收口时必须清——热路径禁放周期性 Warning。〔反例：BattleContext 七个 [Diag] 哨位进 Tick〕
- **`IModuleStats.Snapshot` 实现统一约定：调用方负责 `into.Clear()`**（现状分裂，新实现必须遵守调用方 Clear 约定）；统计键用英文词表。

### 1.5 并发与异步

- **锁粒度一致性**：同一对象的状态读写要么全在锁内、要么有单一属主线程，禁混用。〔反例：SecureEnvelopeRoomTransport 锁外读改连接状态、锁内 Dispose〕
- **延迟一拍（UI 反馈）走 `EventCenter.PublishQueued`；按秒延迟走 `GameScheduler`**——按域选择，不混用。
- **UniTask 延迟/续帧统一经 `UnityAsync` 封装入口**（LiteNet 禁 UniTask 的纪律维持不变）。
- **传输层所有权约定写进接口注释并全项目一致**（谁 Dispose 内层——现状装饰器与 RoomClient 两种约定是登记债，新适配器禁止再加第三种）。

### 1.6 类与接口设计

- **单一职责**；单类 >400 行且多职责，动手前先给拆分方案（现役 god class 清单见审计 §5——ProcedureBattle/UIService/BattleContext/HierarchicalStageMachine；改动这些文件时应顺手收敛自己那一域，禁止继续加职责）。
- **禁 public 可变字段状态袋**：上下文/实例对象用只读属性或 internal setter + 明确属主；上下文类不得反向引用宿主形成双向耦合。〔反例：SlotAnimContext 14 个 public 可变字段 + Root 反向引用；VfxInstance 10 字段〕
- **禁把 GetHashCode 公式当身份键**（哈希相撞=静默吞通知）。〔反例：AnimationPlayer._terminals〕
- **一类一文件；接口与实现分文件**（同文件需注释豁免理由，如 ISceneService 先例）。
- **事件/回调必须上接口端口**，禁 `is 具体类` 突破抽象订阅实现。〔反例：装饰器 `is KcpTransportClient` 订阅 OnError〕
- **同一接口的多实现行为契约一致**（返回 Clone 与暴露内部引用不许混用）。〔反例：RoomClient.MatchResult Clone vs StartGame 裸引用〕

### 1.7 UI 通路纪律

- **产品 UI 打开/关闭唯一写者是 `UINavigationController`**：流程层、服务类（Feedback/Dialog）、Lua 桥一律经单写者队列，禁直调 `UIService.ShowAsync`。〔存量三通道是登记债；新代码必须走单写者〕
- **UI 控件计时统一走 `UiAnimationClock`**（时停/变速联动），禁自驱 `Update` 用 `Time.unscaledDeltaTime`。〔反例：Countdown〕
- **动效参数一律走 `UiFx` 默认值或表**，页面转场参数收口到同一处，禁内联第三份。〔反例：FadeSlideTransition 内联 0.25s/0.2s/40f〕
- **UI 页面接入不动框架**：走 UIFormCatalog/构建器扩展点（见 §3.10）。

### 1.8 确定性 Sim 纪律

- **改 Sim 内核（`LiteSim/Core/{Scripts,Systems}`）= ★ BuildHash 重跑 + L1 全量**，顺序即确定性契约（Input→Movement→Shooting→Damage→Cleanup）。
- **地图/出生点唯一构造**：`SimMapData.StandardBattleMap()` 两端共用，禁另写第二份地图。
- **客户端与服务端同读同一份 `.bytes` 表**，表值与代码默认值必须一致（L1 表守卫钉住）。

### 1.9 接线纪律（禁静默半成品）

- **注册进容器的服务必须有生产消费者**，否则不得注册；发现无消费者的功能面：接线或退役，二选一，不许静默留着养 god class。〔反例：KcpNetworkService 整文件零引用、AudioService 空转、CommandCenter 批3 约 200 行无消费者〕
- **"待接线"半成品必须挂施工进度批次号**（可被追踪），注释只写"待"不算登记。
- **反射访问私有成员取服务 = 违规**，一律走 `GameEntry.TakeContainer()` 等公开面。〔反例：GmPanel〕
- **预埋结构（数据先行机制缺席）必须在设计文档声明预期消费批次**，否则不进 checksum/快照这类有对账语义的面。〔反例：EntityKindTables〕

## §2 修改规范（流程）

### 2.1 动手前

1. **查 §3 领域表**定位改动文件与"改完必跑"；查不到的领域先补表再动手（本指南是活文档）。
2. **查对应专项设计**（[设计文档中心](设计文档/README.md)）：领域设计裁决目标架构，本指南不替代它。
3. **查质量登记表**（[客户端](代码质量审计-客户端.md)/[服务端](代码质量审计-服务端.md)）：要改的文件里有没有已登记债——顺手修同文件小债（记入批次），**禁止新增同型问题**（§1 红线）。
4. **查 §3.10"扩展成本"表**：确认这次变体的多点同步面（BuildHash 源集、ScanTargets、两端装载、C#/Lua shim……），漏一处即静默漂移。

### 2.2 改动中

- **一个改动一个关注点**：流程接线、数值调参、结构拆分分开提交。
- **同步面清单逐项过**：改了共享源（Sim/协议/表）→ BuildHash；改了目录 → ScanTargets.cs/收集组/csproj；改了 Lua shim 对面 → C# Dispatch 同步（反之亦然）。
- **写代码时自我检查**：要写"必须与 X 一致"的注释 → 停下，改成机制（§1.2）；要加 static 可变字段 → 停下，走注入（§1.3）；要 `Debug.Log` 临时排查 → 带 `[Diag]` + 批次号，当天登记摘除批次（§1.4）。

### 2.3 收尾必跑

| 情况 | 必跑 |
|---|---|
| 一切改动的基线 | Unity recompile 0 错误 + `scripts/gate/test.ps1 -Lane L1 -Profile PullRequest` |
| ★ 改了 `LiteSim/Core/{Scripts,Systems}`、`LiteNet/{Proto,Protocol,Transport/Security}`、表数据 | `python scripts/codegen/gen-build-hash.py`（漏跑＝出包门禁被拦、两端常量不同步时握手拒进房） |
| ★ 改了 `.proto` | `scripts/codegen/gen-proto.ps1` + ★ BuildHash 重跑 |
| ★ 改了表源 | `Luban/gen.bat` + ★ BuildHash 重跑 |
| 目录搬动 | 同步 `ScanTargets.cs`、YooAsset 收集组、`Tests.slnx`/csproj 引用、`.gitignore` 白名单、构建器路径 |
| 出包前 | `gen-build-hash.py --check`（`build-player.ps1` 门禁步复算比对） |

> 生成器的工具形态/失败语义/新增约定的权威见 [生成器工具箱专项设计](设计文档/architecture/生成器工具箱专项设计.md)（2026-10-11）；统一入口 `pwsh scripts/codegen/toolbox.ps1 <tool> [args...]`（与单脚本直调等价），上表保持红线最小命令形态。

### 2.4 文档回写与登记

- **代码完成后回写文档**（AGENTS.md 文档规范）：设计变更回写对应专项设计；批次证据记入[施工进度](施工进度/README.md)。
- **修了质量登记表的条目** → 回写该审计文档的"修复登记"表（状态 + 提交号），不删除条目。
- **新发现的质量问题** → 按审计文档的格式追加登记（严重度 + file:line + 一句话），让债可见。
